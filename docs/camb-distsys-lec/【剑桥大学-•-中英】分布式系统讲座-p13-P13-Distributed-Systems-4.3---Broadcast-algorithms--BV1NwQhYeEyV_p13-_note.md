## 从尽力而为广播到可靠广播

![](img/9d588e5642b5f59258924d0c1c1b3c75_4.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_5.png)

上一节我们介绍了广播的不同模型，本节中我们来看看如何实现可靠广播。

最直观的想法是：希望广播消息的节点通过点对点链路，将消息单独发送给其他每个节点，并确保这些链路是可靠的。如果消息在传输过程中丢失，发送方会重传。通过重传，消息最终会到达所有其他节点。

然而，这种方法存在缺陷。

![](img/9d588e5642b5f59258924d0c1c1b3c75_7.png)

假设节点A尝试向节点B和C广播消息M1。消息成功到达C，但在前往B的途中丢失。因此，A需要向B重传消息。但如果A在完成重传前崩溃了，那么将没有人会再次尝试向B发送消息M1。结果，C交付了一个B永远不会收到的消息，导致系统状态不一致。

因此，我们必须设计一个健壮的算法，即使消息的发送方崩溃，所有剩余节点仍能就哪些消息被实际交付达成一致。

![](img/9d588e5642b5f59258924d0c1c1b3c75_9.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_11.png)

## 积极可靠广播算法

![](img/9d588e5642b5f59258924d0c1c1b3c75_13.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_14.png)

我们可以使用一种称为**积极可靠广播**的技术。其核心思想是让每个收到消息的节点都向其他所有节点转发该消息。

具体过程如下：
1.  节点A希望向节点B和C广播消息M1。
2.  当节点B首次收到M1时，它通过点对点链路将同一消息**再次广播**给其他所有节点。
3.  同样，当节点C首次收到M1时，它也将消息**再次广播**给其他所有节点。

![](img/9d588e5642b5f59258924d0c1c1b3c75_16.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_17.png)

这个算法确实能确保可靠性，即使节点崩溃，所有未崩溃的节点也能收到消息。但是，它的代价很高。

以下是该算法的核心流程描述：
```
当节点 i 收到来自节点 s 的消息 m 时：
    如果这是首次收到 m：
        将 m 交付给应用层
        向除 i 和 s 外的所有其他节点发送 m
```

每个收到消息的节点都会将该消息再次发送给其他 `n-1` 个节点。因此，对于节点想要广播的每一条消息，总共会产生大约 `n²` 数量级的消息发送量。我们获得了可靠性，但代价是相当高的网络带宽消耗。

## 流言协议

![](img/9d588e5642b5f59258924d0c1c1b3c75_23.png)

许多算法被设计用来优化上述过程，其中一类特别有趣的算法称为**流言协议**。它们模仿了流言在人群中传播的方式：一个人从某人那里听到流言，然后告诉另外几个人，最终信息通过群体传播开来。它们有时也被称为**流行病协议**，因为其传播方式类似于传染病在人群中的扩散。

在这个例子中，每个小点代表系统中的一个节点。该算法的参数设定为每个节点将消息发送给**三个**随机选择的其他节点。

1.  红色节点将消息发送给三个其他节点。
2.  这三个节点各自收到消息后，又分别将消息**再次广播**给三个随机选择的其他节点。
3.  这些消息的接收者再次将消息进一步传播出去。

![](img/9d588e5642b5f59258924d0c1c1b3c75_25.png)

可以看到，有时消息会发送给之前已经收到过消息的节点，有时消息甚至会发回给过去某个时刻曾持有该消息的节点。但最终，经过几轮协议后，消息**极有可能**传播到所有节点。

![](img/9d588e5642b5f59258924d0c1c1b3c75_26.png)

在这个包含30个节点的例子中，经过大约六轮通信，所有节点都收到了消息。

![](img/9d588e5642b5f59258924d0c1c1b3c75_28.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_29.png)

流言协议有许多可调的细节，例如如何决定何时发送消息、何时停止发送等。但其基本原理是：它们是实现可靠广播的一种方式，并且非常健壮。即使某些节点崩溃或某些消息在网络中丢失，我们仍然有很高的概率保证所有消息都能到达所有节点。

## 实现顺序广播

上一节我们获得了可靠性，接下来看看如何实现顺序广播。

![](img/9d588e5642b5f59258924d0c1c1b3c75_31.png)

### FIFO广播算法 🧾

![](img/9d588e5642b5f59258924d0c1c1b3c75_32.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_33.png)

如果我们想实现FIFO广播，就必须确保来自同一发送者的所有消息都按正确顺序交付。

以下是实现FIFO广播的一种算法，每个节点维护三个变量：

*   **`sender_seq`**：一个整数，该节点每广播一条消息就递增一次。
*   **`delivered[]`**：一个整数向量，记录我们从每个特定发送者那里已经交付了多少条消息。
*   **`buffer`**：一个**暂存队列**，用于存放尚未准备好交付的消息。

以下是算法的核心步骤：

**广播消息时（在节点 `i`）：**
```
seq = sender_seq[i]
将消息 (i, seq, m) 通过可靠广播发送给所有节点
sender_seq[i] = sender_seq[i] + 1
```

**接收消息时（在节点 `j`）：**
```
将消息 (s, seq, m) 放入 buffer
while buffer 中存在消息 (s, seq, m) 使得 seq == delivered[s] + 1：
    将消息 m 交付给应用层
    delivered[s] = delivered[s] + 1
    从 buffer 中移除该消息
```

该算法确保了来自同一发送者的消息按发送顺序交付，从而实现了FIFO广播。

### 因果广播算法 ⛓️

因果广播算法的结构与FIFO广播非常相似。我们同样从三个变量开始：`sender_seq`、`delivered`向量和暂存`buffer`。

![](img/9d588e5642b5f59258924d0c1c1b3c75_39.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_41.png)

**广播消息时（在节点 `i`）：**
```
dependencies = copy(delivered)      // 捕获此消息的因果依赖
dependencies[i] = sender_seq[i]     // 更新自身条目为当前序列号
将消息 (i, dependencies, m) 通过可靠广播发送给所有节点
sender_seq[i] = sender_seq[i] + 1
```

**接收消息时（在节点 `j`）：**
```
将消息 (s, deps, m) 放入 buffer
while buffer 中存在消息 (s, deps, m) 使得 deps <= delivered：
    将消息 m 交付给应用层
    delivered[s] = delivered[s] + 1
    从 buffer 中移除该消息
```

这里的关键是 `deps <= delivered` 这个比较操作。它使用了我们之前定义的向量时钟“小于等于”比较，来判断此消息的所有因果依赖（即`deps`向量中指定的消息）是否都已被本地交付。如果满足，则该消息的因果顺序条件已满足，可以交付。

![](img/9d588e5642b5f59258924d0c1c1b3c75_43.png)

这确保了因果广播的正确性。

### 全序广播算法 🏆

全序广播更具挑战性，因为我们需要就消息交付的总顺序达成一致。

![](img/9d588e5642b5f59258924d0c1c1b3c75_45.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_46.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_47.png)

**1. 基于领导者的方法**
一种简单的方法是选择一个节点作为**领导者**（或称为定序器），由它负责决定消息的交付顺序。
*   当任何节点想要广播消息时，它不直接广播，而是将消息发送给领导者。
*   领导者通过**FIFO广播**将消息广播给整个组。
*   由于所有消息都经过领导者，领导者广播消息的顺序就是所有其他节点交付消息的顺序。

这种方法的问题在于，如果领导者崩溃，就无法再交付新消息。我们需要一种在领导者崩溃时安全切换领导者的方法，但这在保证全序的前提下比较困难。我们将在后续关于共识的讲座中探讨安全实现领导者变更的方法。

![](img/9d588e5642b5f59258924d0c1c1b3c75_49.png)

**2. 基于Lamport时间戳的方法**
另一种实现全序广播的方法不依赖于领导者，而是利用**Lamport时间戳**。
*   每条消息都附加一个Lamport时间戳。
*   消息通过某种可靠广播进行传播。
*   每个节点确保按照Lamport时间戳**递增的顺序**交付消息。

![](img/9d588e5642b5f59258924d0c1c1b3c75_50.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_52.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_53.png)

但这依赖于一个关键知识：节点在交付一条消息时，必须**确信**将来不会有时间戳比当前消息更小的消息到达。因为如果它现在交付了时间戳为 `t` 的消息，之后又来了一个时间戳为 `t-1` 的消息，交付顺序就错了。

我们可以利用FIFO链路的特性来获得这种确信：如果我们在FIFO链路上从每个其他节点都收到了消息，并且知道每个节点发送的消息其Lamport时间戳是递增的，那么当我们从每个节点都收到至少一条时间戳大于某个值 `T` 的消息后，我们就可以确信将来不会再有时间戳小于等于 `T` 的消息出现，从而可以安全交付时间戳为 `T` 的消息。

遗憾的是，这种方法也不是容错的。如果有一个节点崩溃，它将不再发送消息，时间戳就无法继续推进，可能导致整个系统无法交付新消息。

![](img/9d588e5642b5f59258924d0c1c1b3c75_55.png)

![](img/9d588e5642b5f59258924d0c1c1b3c75_56.png)

综上所述，这两种算法都能工作，但都不是完全容错的。在后续课程中，我们将看到实现容错的全序广播的方法。

## 总结

本节课中我们一起学习了实现各类广播模型的具体算法：
1.  我们首先探讨了如何通过**积极可靠广播**和**流言协议**在不可靠网络上实现**可靠广播**。
2.  接着，我们在可靠广播的基础上，通过为消息附加序列号和向量依赖，并利用暂存缓冲区，分别实现了**FIFO广播**和**因果广播**。
3.  最后，我们分析了两种**全序广播**的实现思路：基于领导者定序和基于Lamport时间戳排序，并指出了它们在容错性方面的当前局限。

![](img/9d588e5642b5f59258924d0c1c1b3c75_63.png)

这些算法是构建更复杂分布式协议的基础模块。
