## 概述：什么是搜索问题？

![](img/6fe1efefa343c94f8ab4c61cf78bf594_12.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_13.png)

搜索问题可以描述为：一个**智能体**处于某个**初始状态**，它可以通过执行一系列**动作**来改变状态，目标是到达一个或多个**目标状态**。在这个过程中，我们希望找到一条最优（例如成本最低）的路径。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_15.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_17.png)

为了形式化地描述一个搜索问题，我们需要定义以下几个核心组件：

![](img/6fe1efefa343c94f8ab4c61cf78bf594_19.png)

*   **智能体**：感知环境并执行动作的实体。
*   **状态**：智能体及其环境在某一时刻的配置。
*   **初始状态**：搜索开始的起点。
*   **动作**：在给定状态下可以做出的选择。我们可以用一个函数 `actions(s)` 来描述，它接收一个状态 `s`，返回在该状态下所有可执行的动作集合。
*   **转移模型**：描述执行某个动作后状态如何变化。可以用函数 `result(s, a)` 表示，它接收状态 `s` 和动作 `a`，返回执行动作后得到的新状态。
*   **目标测试**：判断一个给定状态是否是目标状态的函数。
*   **路径成本函数**：为每条路径（即动作序列）分配一个数值成本，用于衡量解决方案的优劣。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_21.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_22.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_24.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_25.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_27.png)

搜索问题的**解决方案**是一个能够将我们从初始状态带到目标状态的动作序列。**最优解**则是所有可能解决方案中路径成本最低的那个。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_29.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_31.png)

上一节我们定义了搜索问题的基本框架，本节中我们来看看计算机如何表示和解决这类问题。

## 节点与前沿

为了在计算机中实现搜索算法，我们需要一种数据结构来封装搜索过程中的信息，这种结构称为**节点**。

一个节点通常包含以下信息：
*   **状态**：节点所代表的状态。
*   **父节点**：导致当前状态的上一节点。
*   **动作**：从父节点状态转移到当前状态所采取的动作。
*   **路径成本**：从初始状态到达当前节点的累积成本。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_33.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_34.png)

在搜索过程中，我们会维护一个称为**前沿**的数据结构，它包含了所有我们已发现但尚未探索的节点。搜索算法本质上就是不断从前沿中取出节点、检查目标、扩展新节点并加入前沿的循环过程。

一个朴素的搜索算法框架如下：
1.  初始化前沿，使其仅包含初始状态对应的节点。
2.  初始化一个空的**已探索集合**，用于记录已访问过的状态，避免重复探索。
3.  循环执行以下步骤：
    *   如果前沿为空，则问题无解。
    *   从前沿中移除一个节点。
    *   检查该节点是否为目标状态。如果是，则回溯构建解决方案。
    *   将该节点加入已探索集合。
    *   扩展该节点：考虑所有可从该节点状态执行的动作，对于每个动作产生的新状态，如果它既不在前沿中也不在已探索集合中，则将其作为一个新节点加入前沿。

这个框架的关键在于**如何从前沿中移除节点**，不同的移除策略导致了不同的搜索算法。

## 无信息搜索算法

![](img/6fe1efefa343c94f8ab4c61cf78bf594_39.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_41.png)

无信息搜索算法在探索时不利用问题本身的任何特定知识。以下是两种基本的无信息搜索算法。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_43.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_45.png)

### 深度优先搜索

![](img/6fe1efefa343c94f8ab4c61cf78bf594_47.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_48.png)

**深度优先搜索** 总是优先探索搜索树中最深的节点。在实现上，它使用**栈**作为前沿数据结构，遵循“后进先出”的原则。

以下是DFS的特点：
*   **优点**：在内存使用上可能比较节省，因为它不需要同时存储大量浅层节点。
*   **缺点**：找到的解不一定是最优解（路径成本最低的）。在最坏情况下，它可能探索整个状态空间才能找到解。

### 广度优先搜索

![](img/6fe1efefa343c94f8ab4c61cf78bf594_50.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_52.png)

**广度优先搜索** 总是优先探索搜索树中最浅的节点。在实现上，它使用**队列**作为前沿数据结构，遵循“先进先出”的原则。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_53.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_55.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_57.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_58.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_60.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_61.png)

以下是BFS的特点：
*   **优点**：只要路径成本是节点深度的非递减函数（例如每步成本相同），BFS找到的解一定是最优解。
*   **缺点**：需要存储大量节点，内存消耗大。对于状态空间庞大的问题，可能不切实际。

## 有信息搜索算法

![](img/6fe1efefa343c94f8ab4c61cf78bf594_81.png)

有信息搜索算法利用**启发式函数**来估计当前状态到目标的距离，从而更智能地选择探索哪个节点。

### 贪婪最佳优先搜索

![](img/6fe1efefa343c94f8ab4c61cf78bf594_83.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_85.png)

**贪婪最佳优先搜索** 在每一步都扩展它认为最接近目标的节点，即启发式函数 `h(n)` 值最小的节点。`h(n)` 是对从节点 `n` 到目标的剩余成本的**估计**。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_87.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_89.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_90.png)

例如，在迷宫问题中，一个常用的启发式函数是**曼哈顿距离**，它计算当前单元格到目标单元格在水平和垂直方向上的格子数之和（忽略墙壁）。

以下是贪婪最佳优先搜索的特点：
*   **优点**：通常比BFS探索的节点少，能找到解的速度更快。
*   **缺点**：它仍然是“贪婪”的，只考虑当前最优，不保证找到全局最优解。它可能被误导进死胡同。

### A*搜索

![](img/6fe1efefa343c94f8ab4c61cf78bf594_92.png)

**A*搜索** 结合了到达当前节点的实际成本和对剩余成本的估计，是贪婪最佳优先搜索的优化版本。它选择扩展 `f(n) = g(n) + h(n)` 值最小的节点，其中：
*   `g(n)` 是从初始状态到节点 `n` 的实际路径成本。
*   `h(n)` 是从节点 `n` 到目标状态的估计成本（启发式函数）。

为了使A*搜索能够保证找到最优解，启发式函数 `h(n)` 必须满足以下条件：
1.  **可采纳性**：`h(n)` 永远不会高估到达目标的真实成本。即对于所有节点 `n`，有 `h(n) ≤ h*(n)`，其中 `h*(n)` 是真实成本。
2.  **一致性**：对于每个节点 `n` 及其后继节点 `n’`，有 `h(n) ≤ cost(n, a, n’) + h(n’)`。这意味着启发式估计是“连贯”的，不会出现矛盾。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_94.png)

当使用可采纳且一致的启发式函数时，A*搜索是**完备且最优**的。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_96.png)

到目前为止，我们讨论的搜索都是单个智能体在静态环境中寻找解决方案。接下来，我们将目光转向一种更动态、更具对抗性的场景。

## 对抗性搜索

![](img/6fe1efefa343c94f8ab4c61cf78bf594_98.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_100.png)

在对抗性搜索中，我们的智能体（如游戏玩家）需要与一个具有相反目标的对手竞争。典型的例子是棋类游戏，如井字棋。

### Minimax算法

**Minimax算法** 用于在零和、确定性、完全信息的双人游戏中做出最优决策。它将游戏结果量化为效用值（例如，赢=1，输=-1，平=0）。游戏中包含两类玩家：
*   **MAX玩家**：试图最大化最终效用值。
*   **MIN玩家**：试图最小化最终效用值。

算法通过递归地模拟游戏进行：
*   在MAX的回合，选择能带来最大最小值的动作。
*   在MIN的回合，选择能带来最小最大值的动作。
*   递归直到终端状态（游戏结束），然后回溯效用值。

伪代码描述如下：
```
function MAX-VALUE(state):
    if TERMINAL(state): return UTILITY(state)
    v = -∞
    for action in ACTIONS(state):
        v = max(v, MIN-VALUE(RESULT(state, action)))
    return v

function MIN-VALUE(state):
    if TERMINAL(state): return UTILITY(state)
    v = ∞
    for action in ACTIONS(state):
        v = min(v, MAX-VALUE(RESULT(state, action)))
    return v
```
最优决策由 `MAX-VALUE(initial_state)` 产生。

### Alpha-Beta剪枝

![](img/6fe1efefa343c94f8ab4c61cf78bf594_102.png)

Minimax需要探索整个游戏树，对于复杂游戏（如国际象棋）这是不可行的。**Alpha-Beta剪枝** 是对Minimax的优化，它通过跟踪两个值来剪除不必要的分支：
*   **α**：MAX玩家当前能保证的最佳值（下界）。
*   **β**：MIN玩家当前能保证的最佳值（上界）。

![](img/6fe1efefa343c94f8ab4c61cf78bf594_104.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_106.png)

![](img/6fe1efefa343c94f8ab4c61cf78bf594_108.png)

在搜索过程中，如果发现某个分支的值对于当前玩家来说已经不可能优于已知的最佳选择，则停止探索该分支的其余部分，从而大幅减少需要评估的节点数。

### 深度限制与评估函数

对于状态空间极其庞大的游戏，即使使用剪枝，也无法搜索到终端状态。解决方案是采用**深度限制Minimax**：只向前看固定的步数（如10步）。

在深度限制处，游戏尚未结束，我们需要一个**评估函数**来估计非终端状态的期望效用。评估函数的质量直接决定了AI的强弱。例如，在国际象棋中，评估函数可能会考虑棋子价值、棋盘控制、王的安全等因素。
