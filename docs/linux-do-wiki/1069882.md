所以整体过程大概是这样：

- 内网机器：docker跑服务（选一个不常用宿主端口，比如 33033），再跑 xray bridge，把 33033 端口反向打到小鸡。

- VPS公网机器：搭一个xray portal，用vless+reality，与内网机器上的bridge连上，接受内网打过来的；然后再开一个dokodemo-door端口，作为反向出口。配置caddy，监听80/443，把域名的流量反代到dokodemo-door端口

- cloudflare处理域名和证书

# 具体步骤

## 0. 域名配置与端口放行

- 添加DNS记录：在cloudflare控制台 → DNS → 新增A记录



名称：你的子域名。例如`crs`.

IPV4：你的小鸡的ipv4地址

代理：建议开，之后配置origin证书。

- cloudflare SSL/TLS: 控制台 → SSL/TLS → 建议选择Full(strict)

- 放行22、80、443、8443（本文中的xray portal端口）

## 1. 在内网机器部署服务（以CRS为例）

> mac安装docker：

> `brew install colima docker colima start brew install docker-compose mkdir -p ~/.docker/cli-plugins ln -sfn $(brew --prefix)/opt/docker-compose/bin/docker-compose ~/.docker/cli-plugins/docker-compose `

1）准备服务目录、`docker-compose.yml`与`.env`文件



创建一个文件夹`~/crs`，然后按照教程中写的方式获得`docker-compose.yml`文件：

```
curl -fsSL https://pincc.ai/crs-compose.sh -o crs-compose.sh && chmod +x crs-compose.sh && ./crs-compose.sh
```

然后在目录下应该会出现`docker-compose.yml`文件。



并且这个脚本应该会为你输出随机生成的`JWT_SECRET`以及`ENCRYPTION_KEY`，你可以直接用上。

接下来，在其下创建`.env`文件，设定一些必需的变量：

```
PORT=33033 #host的端口，crs将可以在内网机器的localhost:33033访问。也可以改别的。
BIND_HOST=0.0.0.0
ADMIN_USERNAME= #你设定的管理员用户名
ADMIN_PASSWORD= #你设定的管理员密码
JWT_SECRET= #这次用刚刚输出的；或者自行生成
ENCRYPTION_KEY= #同上
```

其他都不需要更改。

**2）启动并检查**

在服务的目录下（`~/crs`）启动服务并检查一下是否安装成功：

```
docker compose up -d
```

访问`http://localhost:33033/web`看看服务是否正常启动。

如果服务没有正常启动，检查上述步骤；如果正常启动进入下一步。

> [!check] 如果没有正常启动服务，检查步骤

>

> 首先执行`docker ps -a`，看一下容器是否健康运行；

> 然后确认端口，应该看到类似这样的 `0.0.0.0:33033->3000/tcp`

## 2. 在VPS上配置xray

**1）使用官方脚本安装xray**

```
sudo bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install
```

安装后可执行文件在 `/usr/local/bin/xray`，配置目录 `/usr/local/etc/xray/`，并有 systemd 服务。

**2）生成凭据（UUID和reality密钥）**

```
# 生成 UUID
xray uuid
# 生成 REALITY x25519 公私钥
xray x25519
```

记录下以下信息：

- UUID

- PrivateKey：私钥，放在服务端portal的`realitySettings.privateKey`

- Password：密码（其实就是原本的公钥，避免大家误以为可以随便公开，所以在新版改名了），给客户端bridge用在`realitySettings.publicKey`

- Hash32：用于 vless encryption 中转，本次reality反代用不到，不过还是存一下吧

另外reality还需要一个`shortId`（2-16位十六进制）。上面的命令不会生成，我们再生成一个即可，也记录一下：

```
openssl rand -hex 8     # 生成16位hex，够用
```

**3）portal配置**

> [!note]

>

> 思路：VPS 上开一个 **vless+reality** 入站（`8443`）接受 bridge 注册；再开一个本地 **dokodemo-door** 入站（`10080`）作为反向出口；通过 `reverse.portals` 将它们关联起来。

>

> 注意：caddy 会占用 80/443，这里把 xray 的reality放在 **8443**，内网机器bridge直连vps的ip:8443

编辑`/usr/local/etc/xray/config.json`，替换上一步生成的凭据：

```
{
  "log": { "loglevel": "info" },
  "inbounds": [
    {
      "tag": "reality-in", // 给这个入站起个名字，路由里会用到
      "listen": "0.0.0.0", // 监听所有网卡
      "port": 8443,  // 给bridge连接进来的端口（避开 443 给 Caddy）
      "protocol": "vless",  // 使用 vless 协议（配合 reality）
      "settings": {
        "decryption": "none",  // vless必须为"none"
        "clients": [
          { "id": "<UUID>", "flow": "xtls-rprx-vision" }
        ]
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "show": false,
          "dest": "www.cloudflare.com:443",  // 伪装要“握手”的目标网站（仅用于握手/伪装）
          "serverNames": ["www.cloudflare.com"],  // 接受的 SNI 名称（证书里会出现的域名）
          "privateKey": "<REALITY_PRIVATE_KEY>",  // 服务器私钥（用 `xray x25519` 生成）
          "shortIds": ["<SHORT_ID>"] // 短 ID（客户端要匹配）
        }
      }
    },
    {
      "tag": "dock",  // 本地接caddy反代的口
      "listen": "127.0.0.1",
      "port": 10080,  // caddy反代的目标端口
      "protocol": "dokodemo-door",  // 任意门入站：做端口映射/接驳
      "settings": {
        "address": "127.0.0.1",
        "network": "tcp"
      }
    }
  ],
  "outbounds": [
    { "tag": "direct", "protocol": "freedom" },
    { "tag": "block", "protocol": "blackhole" }
  ],
  "reverse": {
    "portals": [
      { "tag": "portal-crs", "domain": "crs" } // 定义一个“Portal”：tag名叫portal-crs，内部通讯域名叫crs（不需要是真实的域名，Bridge↔Portal内部识别用）。bridge会用domain=crs来注册，路由只要把流量发到outboundTag=portal-crs就会走这条反向通道
    ]
  },
  "routing": {
  	"rules": [
    	{ "type": "field", "inboundTag": ["dock"],       "outboundTag": "portal-crs" },  // 来自caddy→dock的公网请求 → 发到portal(tag=portal-crs)
    	{ "type": "field", "inboundTag": ["reality-in"], "outboundTag": "portal-crs" } // 来自bridge的注册连接 → 也发到portal
   ]
  }

}
```

**4）重启并查看日志**

```
sudo systemctl restart xray
sudo journalctl -u xray -e --no-pager
```

## 3. 在内网机器上配置xray

这里用docker运行xray。



1）我们先创建一个目录，就叫做`xray-bridge`吧；然后在目录下创建`bridge.json`，其中的值一样替换为之前获得的凭证：

```
{
  "log": { "loglevel": "info" },
  "inbounds": [],  // bridge不对外开端口（由portal负责对公网）
  "outbounds": [
    {
      "tag": "to-portal",  // 到VPS的出站连接
      "protocol": "vless",
      "settings": {
        "vnext": [
          {
            "address": "<VPS_IP>",
            "port": 8443,  // 与上面portal的reality-in端口一致
            "users": [
              { "id": "<UUID>", "encryption": "none", "flow": "xtls-rprx-vision" } // 和小鸡那边一致
            ]
          }
        ]
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",  // 以下设置都要与vps一致
        "realitySettings": {
          "serverName": "www.cloudflare.com",
          "publicKey": "<REALITY_PASSWORD>",
          "shortId": "<SHORT_ID>",
          "spiderX": "/"
        }
      }
    },
    {
      "tag": "to-local-crs", // 把连接接到本地crs
      "protocol": "freedom",
      "settings": {
        "redirect": "host.docker.internal:33033" // 访问host的专用域名+你的服务的host端口
      }
    }
  ],
  "reverse": {
    "bridges": [
      { "tag": "to-portal", "domain": "crs" }  // 向portal注册的bridge，domain必须与portal那边一致
    ]
  },
  "routing": {
    "rules": [
      { "type": "field", "inboundTag": ["to-portal"], "domain": ["full:crs"], "outboundTag": "to-portal" },  // 带目标域名的流量 → 继续送回portal
      { "type": "field", "inboundTag": ["to-portal"], "outboundTag": "to-local-crs" }  // 从portal过来的公网请求 → 到达本机的crs服务
    ]
  }
}
```

> [!tip]

>

> 因为在mac上docker不支持 `--network host`，**从容器访问宿主机服务**应使用特殊主机名 `host.docker.internal`，将portal转来的流量打到 `host.docker.internal:33033`，也就是内网机器CRS的host端口。

**2）启动xray bridge服务：**

```
docker run -d --name xray-bridge --restart unless-stopped \
  -v "$PWD/bridge.json:/usr/local/etc/xray/config.json:ro" \
  ghcr.io/xtls/xray-core:latest
```

这一步成功后，bridge会与外网小鸡的portal建立长连接并注册反向隧道。

> [!note]在macos上可以直接原生运行xray，效果会比docker更好

>

> 如果你的内网机器是mac，在macos上，这一步可以通过直接使用 `brew install xray`、`xray run -c bridge.json`来运行；如果想放后台，可以直接：

> `cp ~/xray-bridge/bridge.json "$(brew --prefix)/etc/xray/config.json" brew services start xray `

> 记得 1)中的 `bridge.json` 里面的`host.docker.internal:33033`要改为`localhost:33033`。

>

> 这样的好处是可以使用macos的原生网络，如果使用ipv6服务，可以避免colima docker的ipv4限制。

**3）检查服务**

使用以下命令测试一下能否从小鸡直接打到内网机器上的服务：

```
curl -sS -o /dev/null -w "HTTP %{http_code} in %{time_total}s\n" http://127.0.0.1:10080/web
```

- 如果立即返回200/302/401等，说明外网xray portal ↔ 内网xray bridge ↔ 内网CRS服务已经通了，可以进行下一步。

- 如果卡住超时，检查一下xray的链路，这段出问题了。

## 4. 在小鸡上安装caddy并反代到xray portal的dock

**1）安装caddy**

```
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
chmod o+r /usr/share/keyrings/caddy-stable-archive-keyring.gpg
chmod o+r /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install caddy
```

**2）配置证书**

GPT在这里给我了两个方案，我选择了第一个，如果有需要也可以参考另外一个。

> [!example]+ 方案1：使用 Cloudflare Origin CA

>

> Cloudflare 控制台 → SSL/TLS → Origin Server → Create certificate，生成证书与私钥（PEM）。

> 编辑caddy文件`/etc/caddy/Caddyfile`：`<你的域名xx.xx.xx> {     reverse_proxy 127.0.0.1:10080     tls /etc/caddy/certs/origin.crt /etc/caddy/certs/origin.key } `

>

> 把证书放到外网VPS：`sudo mkdir -p /etc/caddy/certs `

> 保存证书为`/etc/caddy/certs/origin.crt`与`/etc/caddy/certs/origin.key`

> 重启caddy服务：`sudo systemctl reload caddy`

> [!example]- 方案2：用 DNS-01 自动签发（Let’s Encrypt + Cloudflare API）

>

> 如果你更想要公共 CA 证书，可使用 **Caddy 的 Cloudflare DNS 插件**进行 DNS-01 验证（需带插件的 Caddy 构建或镜像），Caddyfile 里写 `tls { dns cloudflare {env.CLOUDFLARE_API_TOKEN} }`，并把 `CLOUDFLARE_API_TOKEN` 设为环境变量。（没试过，GPT这么说的我就抄过来了。 ![:tieba_001:](https://cdn3.ldstatic.com/original/3X/9/a/9ac368cc8eafad165bbcf61b0263803d3b2dc2a7.png?v=15)）
