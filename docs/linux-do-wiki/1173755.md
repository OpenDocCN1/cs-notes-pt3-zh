# [笔记]DDC/CI

DDC/CI（Display Data Channel/Command Interface）定义 显示器 和 主机 之间进行通信的协议，允许主机通过显示接口（如VGA、DVI、HDMI等）传递与显示器进行双向通信。
不同显示接口对DDC/CI的支持
- DP协议 通过其 **AUX (辅助) 通道** 完美支持 DDC/CI
- HDMI 标准 本身 包含 DDC/CI
- 雷电 / USB-C (DP Alt Mode)，本质上是“隧道化”的 DisplayPort 信号，所以它们**完全继承了 DP 的 AUX 通道**，因此也完美支持 DDC/CI
需要注意的是 DDC/CI 是否可用有多个影响因素
- 显示器固件（fireware）对DDC/CI的支持，通常表现为不完全支持，包括两层含义，一是协议的部分支持，二是部分接口支持，比如DP支持但HDMI不支持
- 传输路径是否支持，如通过转换器、转接器、扩展坞等方式，容易造成信号丢失。可能场景列举如下：

HDMI to DP，一般内部芯片主要做视频信号转换，而忽略DDC/CI信号的传递
扩展坞（USB-C to HDMI），取决于内部芯片
在本贴撰写时，有搜索到之前佬留的一个贴——[分享显示器输入源快捷切换 (kvm) 的方法](https://linux.do/t/topic/321291)，作为参考和补充。
本人的使用场景主要是两台mac mini（M1、M4）设备共用一个显示器（Dell 2720QM），在Github开源库的基础上，结合Vibe Coding，结合个人需求：切换输入源和调节亮度/对比度，以减少侵入的方式做了一个[菜单栏应用](https://github.com/depressi0n/SwiftDDC)，当前仅在本人的设备环境下进行过测试，状态仅可用，未细细打磨。
中间有遇到一个很有意思的问题使用 HDMI to HDMI 线缆竟然会切换失败，暂时定位到的是显示接口协议用了 HDMI to DP，猜测可能的原因包括固件、线缆，换线缆（USB-C to DP）后正常可用。
