# 由Gemini 3 的 thoughtSignature引发的一些观察与结论

自从 Gemini 新版本发布后，我第一时间注意到了谷歌最新的 `thoughtSignature` 字段。其实早在前几个版本（Gemini 2.5时期）就有这个字段了，但当时不返回思考签名也不会报错，所以我一直没太在意。
** 发现一个严重缺陷：** 如果不返回该签名，模型可能会**重复调用工具（死循环）**。 如果大家使用的是**非 SDK 的 OpenAI 格式**进行调用，或者上游完全没有提供原生格式支持，大概率会遇到这个问题。（注：NewAPI 似乎已在最新的 PR 中修复了此问题）。
** 关于 Vertex 和 Studio 的兼容性测试：** 最近测试发现，`thoughtSignature` 似乎不能在 Vertex 和 AI Studio 之间随意混用：
- **Vertex** 不承认 Studio 生成的签名 ![:cross_mark:](https://linux.do/images/emoji/twemoji/cross_mark.png?v=15)
- **Studio** 却可以兼容 Vertex 的签名 ![:white_check_mark:](https://linux.do/images/emoji/twemoji/white_check_mark.png?v=15)
- 另外，CLI 和 Vertex 的签名看起来是兼容的，两者似乎属于同一平台。
大家对接的时候注意一下环境区分。
