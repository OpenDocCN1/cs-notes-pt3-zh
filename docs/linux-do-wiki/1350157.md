# 关于 SSH 远程连接 VPS 卡顿的解决方案



# Mosh

Mosh 是一款远程终端应用程序，支持漫游、间歇性连接，并提供智能本地回显和用户按键行编辑功能。

Mosh 是交互式 SSH 终端的替代方案。它更加稳定可靠，响应速度更快，尤其是在 Wi-Fi、蜂窝网络和长途连接下。

Mosh 是一款自由软件，适用于 GNU/Linux、BSD、macOS、Solaris、Android、Chrome 和 iOS 系统。

```
https://mosh.org/
```

对于远程的外网服务器为什么选择 Mosh，而不选择其他大众的 SSH 工具？

SSH 协议在默认情况下，每当你输入一个字符（比如 ‘a’），这个字符必须先发送到服务器，服务器处理后，再把这个字符“回显”（Echo）发回给你的客户端，显示在屏幕上。

如果输入 ‘a’ 需要 3 秒才显示，说明数据包在你和服务器之间往返一次需要 3 秒。

**可能的原因有：**

A. 物理距离与线路质量 (最常见)

情况：你的服务器可能位于海外（如美国、欧洲），而你在国内。

原因：数据包需要跨越海底光缆，且可能经过了拥堵的路由节点（特别是晚高峰期间）。如果没有走优质线路（如 CN2 GIA），延迟和丢包会非常严重。

B. 严重的丢包 (Packet Loss)

情况：网络不稳定，数据包在半路丢失了。

原因：TCP 协议（SSH 基于 TCP）在丢包时会尝试重传。你感觉到的“3秒延迟”，其实是系统在后台默默等待重传成功的耗时。

**解决方案**

针对网络导致的 SSH 卡顿，提供以下解决思路：

更换 SSH 工具 (推荐：Mosh)

SSH 基于 TCP，对延迟非常敏感。Mosh (Mobile Shell) 是基于 UDP 的协议，专门为高延迟和不稳定网络设计。

效果：使用 Mosh，你在本地输入的字符会立即显示在屏幕上（本地回显），不需要等待服务器确认（延迟降低）。

做法：在服务器安装 mosh，客户端也使用支持 mosh 的软件（如 Termius, MobaXterm 等）连接。

**从 TCP 换到 UDP 会不会不安全？**

这确实是一个值得思考的问题因为 TCP 有三次握手互相确认身份，而 UDP 协议对方只要是可以访问的能建立成功不管身份是否正确都传输数据。从表面上看确实 UDP 可能不如 TCP 安全但在技术层面上，Mosh 使用 UDP 并不代表它比 TCP（SSH）不安全。

简单来说：Mosh 的安全性是建立在 SSH 之上的，且数据传输经过了高强度的加密。

我们需要先区分“传输协议（TCP/UDP）”和“加密协议（Encryption）”的区别。以下是详细的安全分析：

为什么说 Mosh 是安全的？

它依赖 SSH 进行“握手”

Mosh 并不会像 Telnet 那样直接裸奔，也没有发明一套新的登录系统。

启动流程：当你输入 mosh root@ip 时，Mosh 实际上会先建立一个标准的 SSH 连接（使用 TCP 22 端口）。

身份验证：所有的密码输入、密钥验证，全部都是通过 SSH 完成的。如果你现在的 SSH 是安全的，那么 Mosh 的登录过程就是一样安全的。

密钥交换：在 SSH 连接建立后，Mosh 会生成一个随机的加密密钥（Session Key），并通过这条安全的 SSH 通道发送给客户端（这一步类似 SSL/TLS 协议使用 ECC 算法时的工作交互）。

切换协议：只有拿到这个密钥后，Mosh 才会断开 SSH（TCP），切换到 UDP 协议进行数据传输。

结论：只要你的 SSH 没被攻破，Mosh 的“大门”就是锁死的。UDP 只是“卡车”，加密才是“保险箱”，UDP 不安全，通常是指 UDP 协议本身没有“状态确认”，容易被伪造源 IP（DDoS 攻击常见手段）。

但在 Mosh 中：Mosh 使用 AES-128-OCB 模式进行加密。这是一种认证加密（Authenticated Encryption）方式。这意味着每一个 UDP 数据包不仅是被加密的，而且带有“校验”。如果黑客在中间截获了数据包并试图修改（比如注入恶意命令），服务器解密时会发现校验失败，直接丢弃该包。Mosh 会给每个包编号，防止黑客录制你的操作包然后重放。

Mosh 真正的“安全隐患”在哪里？

虽然协议本身很安全，但它在运维层面确实带来了一些必须要考虑的风险：

风险一：需要开放大量 UDP 端口 (最主要的顾虑)

SSH 只需要开放一个 TCP 22 端口。但 Mosh 为了支持多用户并发，通常要求防火墙开放 UDP 60000-61000 这一大段端口。

为什么这是个问题？在企业级防火墙策略中，开放几千个端口是很难通过安全审查的，虽然这些端口只有在有连接时才会被占用，但看着很吓人（或者适当减少些端口的开放）。

解决：个人 VPS 无所谓；如果是公司服务器，这是个阻碍。

风险二：漫游功能的双刃剑

Mosh 的核心优势是“漫游”（Roaming）：你从家里的 Wi-Fi 切换到手机热点，IP 变了，连接不会断（但其实就是联网后自动尝试连接）。

原理：Mosh 不认 IP，只认那个加密的 Session Key。

极端风险： 如果（我是说如果）有黑客攻破了你的客户端电脑，偷走了内存里的 Session Key，那么他可以在世界任何地方接管你正在运行的这个终端会话，而不需要知道你的 SSH 密码。

对比 SSH：SSH 是绑定 TCP 连接的，IP 一变连接就断，黑客偷了 Key 也没法接管旧会话。

现实评估：如果黑客已经能读取你本地电脑的内存了，你无论用 SSH 还是 Mosh 都已经完蛋了。

前面认识了 Mosh 的存在下面我们就可以开始对 Mosh 进行配置了。

**服务器配置**

先决条件：本身对 Linux 存在基础的认识，了解 ssh，已经能远程登录到远程的 vps，服务商的安全组开放 UDP 60000-60010（如果存在安全组）。
