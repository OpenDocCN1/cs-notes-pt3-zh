### 共建说明
现对于 **建设性** 或 **重要** 的 Issue/PR，在成功采纳后 将在 LINUX DO - WIKI - 共建荣誉榜 中标明，并发放 **专属动态卡片** 以表示感谢！
#### [LINUX DO - WIKI - 共建荣誉榜](https://wiki.linux.do/honor)
- 由于 Wiki 站刚起步，因此共建荣誉榜可能会有一定问题，如有遗漏或BUG请及时私信[@chenyme](https://github.com/Chenyme/Linux-Do-Wiki)
- 试运行期间，会对参与 issue/PR的 前 6 位 共建者（放宽限制，不要求 建设性 或 重要，只要求 有效 ）直接发放 专属卡片，以感谢支持！
- 人数已满，期待大家更多的 **建设性** 或 **重要** 的 Issue / PR，来获取你的专属卡片叭！
> 试运行活动的卡片人数已满！要求也随之变更为 **建设性** 或 **重要**，若 未采纳 或 未达要求 还望请不要气馁！此类后期会在 GitHub 上标明感谢！
> 期待大家更多的 Issue / PR，来一起共建 wiki 站，获取你的专属卡片叭！

### 反馈格式和说明
为了方便更好的管理和维护 Wiki 站，希望大家在提交 Issue/PR 时可以遵循一定的格式。
- PR 时请遵循项目框架 Nextra 的编写规范
- Issue/PR 提交时的格式和说明 ：
| 标题格式 | Issue/PR 内容 |
| --- | --- |
| 【建议】xxx页面的xxx内容 | 想要建议的内容 + 理由 +  社区个人主页链接 |
| 【错误】xxx页面的xxxBUG | 报告xxx页面内的BUG + 具体情况 + 社区个人主页链接 |
| 【修复】xxx页面的xxxBUG | xxx页面内的 xxx BUG + 社区个人主页链接 |
| 【更正】xxx页面的xxx内容 | xxx页面内需要更新的内容 + 社区个人主页链接 |
| 【新增】xxx页面的xxx内容 | xxx页面内需要新增的内容 + 理由 + 社区个人主页链接 |
| 【改进】xxx页面的xxx内容 | xxx页面内需要改进的内容 + 理由 + 社区个人主页链接 |
