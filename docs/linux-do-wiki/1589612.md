# Docker 容器无法出网问题解决

## 排查
> **tips**: 下方的命令并不是需要挨个执行的, 需要具体情况具体处理, 下方是我遇到出网故障反馈时的处理排查思路记录, 可能不太全面, 佬友们多多担待, 欢迎补充~~
### NAT (MASQUERADE) 规则丢失
一般不咋会出现该问题
```
iptables -t nat -L -n

# 应当观察到类似如下 docker 网络放行规则
POSTROUTING
MASQUERADE  all  --  172.17.0.0/16  !172.17.0.0/16
```
### FORWARD 链被 DROP
遇到过的大部分出网问题均是该问题, 特别是各类国产化信创系统, 无特殊防护要求一般我都是直接全放了
```
iptables -L FORWARD -n -v

# 如观察到类似如下规则则说明规则链被 DROP
Chain FORWARD (policy DROP)

# 全放行 如果没有
iptables -P FORWARD ACCEPT

# 指定段放行精确放行 policy DROP
iptables -P FORWARD ACCEPT
iptables -I FORWARD -s 172.17.0.0/16 -j ACCEPT
iptables -I FORWARD -s 172.18.0.0/16 -j ACCEPT
iptables -I FORWARD -d 172.17.0.0/16 -j ACCEPT
iptables -I FORWARD -d 172.18.0.0/16 -j ACCEPT

# 明确放行 Docker bridge docker 0
iptables -I FORWARD -i docker0 -j ACCEPT
iptables -I FORWARD -o docker0 -j ACCEPT

# 网桥
iptables -I FORWARD -i br-4f2da0e6a02f -j ACCEPT
iptables -I FORWARD -o br-4f2da0e6a02f -j ACCEPT
```
### Docker iptables 被禁用
```
cat /etc/docker/daemon.json

# 如观察到如下规则
{
  "iptables": false
}

# 修复 删除对应规则或者直接移除这个配置文件
rm -f /etc/docker/daemon.json
systemctl restart docker
```
### 路由表异常或 DNS 异常
大型企业内网使用的 cidr 范围较大, 概率性网段与 docker 网段重复也会导致该问题, 表现为可以发起请求但等不到响应, 因为响应被 docker 网段吞了, 该类问题一般都是修改容器网段即可
```
# 检查 ip 默认路由 default via <10.10.16.1>
ip route

# DNS 检查
cat /etc/resolv.conf

# Generated by NetworkManager
search 172
nameserver 61.139.2.69
nameserver 2400:3200::1
```
