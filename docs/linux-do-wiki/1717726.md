# 【木子狸的openclaw】 00 谈谈Openclaw

这个是 openclaw 的系列的开篇。但开始之前，我觉得有必要讨论和分析一下 openclaw 的价值，解构一下爆火的原因，同时还有各方得利。
# 是什么？
Openclaw 指的是由 Peter Steinberger 于2025年11月开发的开源自主智能体（最初名为Clawdbot或Moltbot，后于2026年1月27日正式更名）。
# 与 LLM 的不同？
传统的大语言模型（LLM）主要作为被动响应的对话工具存在，其核心价值在于文本生成与信息检索。
而 OpenClaw 通过接入操作系统、电子邮件、日历乃至Shell，为这个工具赋予了一个很好的期许——24小时不间断运行的**数字员工**或**个人AI操作系统**。
> 事实上 Cursor，CC，CodeX 这些都可以做到。
从“人类下达指令、AI生成文本”向“AI自主规划、跨应用执行”转移。
这个转变让我们好像发现了“银弹”，但事实上“没有银弹”。
截至2026年3月初，OpenClaw在GitHub上迅速斩获超过24.7万Star及4.77万次Fork，其受开发者[[1]](#footnote-14754400-1)追捧的程度一举超越了Linux等历史悠久的底层基石项目。
笔者认为，这个数据本质上是硬件公司，算力提供商，大模型公司，自媒体共同推波助澜的流量狂欢。
# 技术架构简述
在2023年至2024年间，自主智能体主要依赖于无边界的推理循环（Agent Loops），其核心逻辑是设定宏大目标后，由模型自主拆解子任务并不断递归试错。这种架构在研究和探索未知问题时表现出极高的自由度，但在企业级生产环境中却暴露出不可靠、容易陷入死循环以及执行不可预测等致命缺陷。
而OpenClaw采取的是结构化的工作流编排与本地优先（Local-First）的网关控制。OpenClaw作为一个本地网关运行在用户的计算机或服务器上，通过安全[[2]](#footnote-14754400-2)的沙盒环境为外部大语言模型提供读写文件、运行脚本和控制浏览器的权限。
通过技能 （Skill）和模型上下文协议（Model Context Protocol, MCP），将AI的能力严格约束在预定义的操作逻辑、重试规则和权限治理框架内。
还有一个关键点是——整合进用户现有的即时通讯软件（如WhatsApp、Telegram、Discord、Slack、Google Chat、Signal及iMessage等）。系统将配置数据和交互历史作为本地Markdown文档持久化存储，使得智能体能够跨会话/平台保持上下文，并通过其内置的机制自动唤醒，主动检查收件箱、日历或项目进度，从而真正实现了全天候的自动化接管[[3]](#footnote-14754400-3)。
在此基础架构之上，OpenClaw构建了一个庞大的技能生态系统（Skill Ecosystem），允许社区开发者编写并分享名为Agent Skills的预配置功能模块。
这个功能则是赋予了普通用户更多可以复用的自动化操作，软件连接。降低了技术门槛[[4]](#footnote-14754400-4)。
# 流量
Moltbook[[5]](#footnote-14754400-5)这个全新社交网络平台的诞生，是流量爆发的关键点。
在这个平台上，人类退居幕后，而运行在各个设备上的OpenClaw代理则在这里发帖、点赞、交流执行任务的心得，甚至互相抱怨它们的人类雇主。
人都是喜欢看热闹的，在平台上发生的各种失控事件，极大的刺激了公众的好奇心和传播欲。这时雪崩就开始了，人们越发想要了解这个平台，而泼天的流量便给到了 Openclaw。
在这一过程中，“错失恐惧症（FOMO）”成为了最强大的营销工具。大量的自媒体和技术顾问[[6]](#footnote-14754400-6)开始兜售“如何通过AI智能体实现被动收入”的焦虑型课程，进一步推高了系统的安装量。
最近这种炒作更是达到了白热化的程度。2026年3月初，微博上甚至出现了一个名为“OpenClaw 官方微博”的伪造账号，短时间内吸引了包括智谱等国内多家主流AI大模型厂商官方账号的积极互动[[7]](#footnote-14754400-7)。
同样我们可以发现OpenClaw现象的繁荣在很大程度上是由**供给侧**而非**需求侧**驱动的。在2026年的AI市场，大模型公司急需天文数字的Token消耗量来向投资者证明其商业价值，云服务商需要海量的服务器租赁合同，而硬件制造商则迫切希望销售搭载高算力芯片的终端设备。
OpenClaw作为一个能够24小时无休止运行、自主发起请求的“Token黑洞”，完美契合了上述所有利益相关方的核心诉求，从而获得了一股几乎无法阻挡的隐形推力。
# 谁得利？
首先是 Clawdbot 被 Anthropic 公司要求更名，于此同时OpenAI为该项目提供了巨额资金赞助，同时将创始人招致麾下。这个给 OpenAI 或者说以 Open 命名的项目带来了很好的技术声誉。
OpenClaw的开源属性、极高的可塑性以及本地化部署能力，为企业提供了一个绝佳的应用外壳[[8]](#footnote-14754400-8)。同时一些国内模型公司为其提供了针对性的 Token 套餐，并针对微信、企业微信、飞书以及QQ等即时通讯和办公生态进行了深度的逆向适配/原生适配。
在硬件和云基础设施层面，OpenClaw同样催生了一个围绕“部署与算力托管”的暴利产业链。由于该系统要求极高的系统权限且配置环境极其复杂，市场上迅速出现了大量安装 OpenClaw 的专业[[9]](#footnote-14754400-9)安装服务。
既然 Openclaw 已经成为热点，那么自媒体肯定不会错过这一风口。于是愈加卖力的进行宣传，想尽千方百计告诉人们这个东西多有用。
最终各方的共同努力下，Openclaw 出圈，爆火。
# 问题？
不可否认，Openclaw 确实可以带来一些工作上的帮助。但是个人用户，特别是跟风的那些用户，完全没有意识到 Token 的消耗和一些无意义的损失。
同时安全也是重要威胁。现在的宣传，几乎没有关注过用户的使用风险。不管是 ClawJacked 漏洞，还是 Skill 投毒，提示词注入。都反映了我们不应该将电脑权限完全交给现在的 Openclaw。
如果不了解边界而盲目使用，用户终将会付出沉重的代价。
# 最后
说了这么多，也不是说不要用 Openclaw。我们需要权衡利弊，明确问题，才能在后续使用时不被牵着鼻子走，尽可能保障自己的数据隐私安全。了解边界和缺陷，才能让我们更好的使用工具。
