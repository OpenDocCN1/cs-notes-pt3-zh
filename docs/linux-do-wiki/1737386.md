# 目前一些 AI 工具的 Agent 并行化功能(例如Multi-agents)测试



测试对象: Antigravity, Codex CLI, Gemini CLI (手头上的订阅能用的就这几个, 所以 Claude Code 的 subagents 和 Agent teams 功能测不了)

测试场景: 多 Agent 并行 review 一个软件项目(例如 Agent 1 review 后端代码, Agent 2 review 前端代码, Agent 3 review 文档一致性, Agent 4 review 项目中的 AI Rules 和 MCP/Skills), 最后集中汇报.

结论

1. Codex CLI 对 Agent 并行的支持最好.

它目前不支持 `codex exec` 多开(我在一个系统里开两个以上的 codex 会提前退出). 但可以打开 /experimental 实验性功能里的 Multi-agents, 由 prompt 触发在单个会话中 spawn 多 Agent 来并行 review 项目的不同部分 (就是执行开头的测试场景).

不过这样的话额度消耗特别快, 我实测是 19 分钟消耗 ChatGPT Team 账号的 20% 周限额度.

2. Gemini CLI 只能使用 Gemini 系模型, 不支持通过 prompt 明确指示调用多 Agent.

它的多 Agent 局限在单个会话中, 主模型只会其他低级模型干点简单的杂活, 例如写文件什么的, 没法完成测试场景中 spawn 多个子 Agent 并行 review 的需求.

优点是它的 gemini-3.1-pro-preview 额度和 Antigravity 里的 Gemini 3.1 pro 独立, 有 Pro/Ultra 订阅相当于白送的额度. 不过经常遇到 429 限流, 需要慢点发送请求, 而且输出结果的速度比 Antigravity 中的 Gemini 3.1 Pro 要慢.

3. Antigravity 对 Agent 并行的支持最差, 那个 Agent Manager 完全就是毛坯房功能.

Agent 不能自动触发, 需要用户手动打开并输入任务, 无法自动化, 只适合执行只读任务.

最离谱的是, 我主窗口使用 wsl 连接到 wsl Ubuntu 虚拟机, 打开  Agent Manager 在相同仓库执行review 时, 生成的报告文件竟然是保存到 windows 主机的, 而且没有应用修改的选项, 需要用户手动把文件复制到虚拟机目录里.

不过 Ultra 订阅能爽用 Opus 4.6, 也只能先忍了.
