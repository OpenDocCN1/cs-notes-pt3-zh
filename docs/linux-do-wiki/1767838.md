# 【IDE系列5】Antigravity全部auto-accept插件评测【260320更新Antigravity Better】



### 什么是auto-accept类插件

因为Antigravity自带的自动按键功能很不好用，总是暂停等审批，非常耽误事，所以auto-accept类插件几乎是编程必备的

原理（选读）：



VSCode的插件API并不支持插件直接控制Chat窗口，所以要用以下两种方式



Ⓐ绝大多数用cdp方式



Antigravity的Chat窗口类似chrome网页，用cdp可以查询和点击，



特征是：第一次安装插件后会自动运行cmd，把Antigravity启动快捷方式后面加port参数，这样插件才能通过port控制Antigravity



Ⓑ少量用自定义workbench.html+内置js替换原版，例如Antigravity better

### ![:white_check_mark:](img/5f8bd971c8b10260a24c5e6f5de2737f.png)[⊚Antigravity better⁵@GH142](https://github.com/016/Antigravity-Better)

#### 优点

这是现阶段唯一一个接近完美的方案



唯一不使用cdp原理的方案，特别适合多开Antigravity，其他方案多开每个Antigravity需要使用不同的auto-accept插件，才能连接不同的cdp端口



可以限定auto-accept次数，避免无人值守时一直retry

#### 缺点

对文件修改的accept-all无法自动accept，需要手动点，但是也完全可以不管他，因为实际上这些文件早已经自动改完了，你只要不点reject(相当于undo)，是否点accept都没有实际影响



一些比较深的滚动可能点击不到



每次启动Antigravity提示损坏，估计是因为检查到替换了文件，办法：关掉提示即可



每次升级Antigravity要重覆盖workbench.html

#### 复制功能(与auto-accept无关)

效果与选区 → 复制差不多，不支持md，而chat右上角三点 → export有md格式

#### 自定义回车功能(与auto-accept无关)

开启后回车=换行，发送=Ctrl+enter等



但有个bug，导致这个功能基本没法用，因为原版里ai思考过程是可以继续输入内容并按回车发送的(进入排队状态)，开启了自定义回车，思考时就不能发送排队了

#### 安装方法

不是传统意义上的插件，无法通过插件市场安装



①[下载](https://github.com/016/Antigravity-Better/releases/)最新版本的assets里的source code zip文件



②解压 → 复制\app_root\workbench.html，只有这一个文件有用，其他一大堆文件都没用



③打开 \AppData\Local\Programs\Antigravity\resources\app\out\vs\code\electron-browser\workbench\ 粘贴覆盖原版workbench.html



④重启Antigravity → chat栏右侧应该多出一个蓝色齿轮图标 → 功能 → 启用自动操作 → 勾选全部按钮类型

### Auto-accept类插件常见问题

因为这些插件原理都差不多，很多插件就是互相fork或抄袭的，所以毛病也差不多，至今没有完美的

#### 绝大多数不支持双开Antigravity

办法：安装两个插件，两个Antigravity同时开时，但分别使用两个不同的插件，Antigravity1关掉插件2，Antigravity2关掉插件1，



具体见：[【IDE系列2】Antigravity双开，双账号同时登录，gemini/opus/codex三窗口一起开](https://linux.do/t/topic/1576410)

#### 超出页面就点击不到的问题，各插件都少都有这个问题，有的轻一些，有的重一些

#### 干扰打字问题，绝大部分插件都有，

办法：Ⓐ打字时把右边栏临时关掉



Ⓑ一个Antigravity打字，另一个Antigravity跑任务基本不打字

#### 不能点击全部按钮问题，停更的插件多数都有这个问题，对于最近Antigravity版本新出的按钮不识别
