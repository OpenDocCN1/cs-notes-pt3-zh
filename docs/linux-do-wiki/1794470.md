1. 历史记录界面和收藏界面功能不全

`2.x`版本的历史记录和收藏的逻辑没有`1.x`系列的要好一些。`1.x`支持单个删除，`2.x`只支持全部删除。收藏界面甚至连删除按钮好像都没做（也可能做了，可能是我没找到 ![:bili_040:](https://cdn3.ldstatic.com/original/3X/3/3/3339b15ea7c025039809fab82a3b3e4d31f80b80.png?v=15)）

以下是`1.x`和`2.x`的历史和收藏界面的区别,可以看出鼠标移动到图片上面`2.x`界面是没有显示播放和删除控件图标的。如果有无法接受的用户建议先不着急升`2.x`版本，目前`2.x`才刚出没多久，还有很多不成熟的地方，期待等之后慢慢增加吧。饭要一口一口吃，代码要一行一行写。码农彼此之间还是要互相理解。 ![:bili_040:](https://cdn3.ldstatic.com/original/3X/3/3/3339b15ea7c025039809fab82a3b3e4d31f80b80.png?v=15)

1. Pansou搜索界面和正片播放界面缺失跳转网盘源链接的按钮

`2.x`版本相比于`1.x`，缺失了pansou搜索界面识别网盘源链接的功能，并且这个功能在`1.x`版本中的播放器界面也是显示的，`2.x`版本却是移除了的，这个功能很好用，可以点一下去看网盘内容有没有缺失。以及`1.x`的pansou搜索界面是显示网盘视频是来自哪个插件的，`2.x`则不显示。

另外，PanCheck可以检测到网盘链接失效还是没失效，但是对网盘缺失内容的支持却不是很好。有些时候还是需要点一下这个`访问`按钮来手动检查的。这时候有些佬友要问了，每次手动点击一下进去看一看不就可以了吗？ ![:bili_040:](https://cdn3.ldstatic.com/original/3X/3/3/3339b15ea7c025039809fab82a3b3e4d31f80b80.png?v=15)是的，这又回到第一个问题了，由于没有跳转访问，点进去就是播放，很多网盘链接并不全，你会得到几个甚至十几个不全的观看历史列表。最后终于找到一个能看的全集之后，你只能点击收藏，不然会由于观看历史界面只有一个删除所有的按钮。所以，bro，现在你不能逐一删除，只能选择删除全部观看记录来实现清理杂乱的播放记录列表。如果之前你没有点击收藏的话，这时候恭喜你又可以重新操作一遍`搜索`-`逐个点击`-`播放`-`收藏`-`清非完整全集链接`的步骤了 ![:face_savoring_food:](https://cdn.ldstatic.com/images/emoji/twemoji/face_savoring_food.png?v=15)

> 事先声明，如果是小白玩家的话，某个服务的compose.yaml文件在哪，那个配置的`.env`就在它相同的目录，还有`.data/`目录也是。每个服务需要自己手动新建一个文件夹放置。
> 比如假设一台主机上的docker目录被新建为`/docker/`，那么假设我就需要再`/docker/`目录下新建一个文件夹存放compose.yaml文件，当然名字可以随意起，只要是`yaml`或者`yml`格式就可以了。
```
/docker/
├── omnibox
│   ├── docker-compose.yml
│   └── .env
├── pancheck
│   ├── .data
│   ├── docker-compose.yml
│   └── .env
└── pansou
    ├── docker-compose.yml
    └── .env
```
## 1.配置omnibox容器
关于`2.x`怎么部署我相信佬友们玩docker的肯定是会docker-compose的，不过还是以防万一，给小白玩家贴一个compose.yaml文件 ![:face_savoring_food:](https://cdn.ldstatic.com/images/emoji/twemoji/face_savoring_food.png?v=15)
`latest`版本是最新主分支版本，`lite`版本是最新的轻量版本。

二者具体有什么区别可以看omnibox作者@dragoncoder的原话
[2026_03_21_17_51_19985×295 74.9 KB](https://cdn3.ldstatic.com/original/4X/0/6/a/06acf777fccef6607b0d0dd143ca48fa43d7e819.jpeg)
> image: lampon/omnibox:v1.4.4
以下是compose文件
```
services:
  omnibox:
    image: lampon/omnibox:lite #这里可以把lite改为latest，lite是轻量版本
    container_name: omnibox #容器名，随便改
    ports:
      - "7023:7023" #端口号，冒号左边是物理主机端口，右边是容器内部端口。左边物理主机端口随便改一个未被占用的端口。改好之后如果需要外部访问权限记得防火墙放行下端口
    restart: unless-stopped #重启规则，未手动停止则一直重启。如果有不论什么情况下都需要重启的需求，可改为always
    #env_file:
    #  - .env #如果有环境变量需求，可手动取消注释，在compose文件同目录下新建.env文件
    networks:
      - omnibox #使用的容器网络。如果不喜欢用这种方式可以使用network_mode: 'bridge'这种来使用docker默认桥接网络，但是不建议使用默认网络，对代理配置不友好。
    volumes:
      - /dockerdata/omnibox/data:/app/data #这里是挂载本机目录映射，可修改为自己存放docker内部文件路径，也可以使用挂载卷的方式，二选一，挂载为本机目录的方式比较容易备份和修改
    #mem_limit: 2g #内存限制
    #cpus: 1 #CPU核心数限制
networks:
  omnibox:
    external: true #这里就是上面的容器网络，允许外部访问，后续可对接数据库或者pansou/pancheck服务
```
再贴一个omnibox的`.env`文件，如果有外置数据库需求或者容器代理需求可以取消`.env`的注释，~建议不要使用`postgresql`，因为作者还没修，不能用~（又看了一眼，最新版修好了） ![:bili_040:](https://cdn3.ldstatic.com/original/3X/3/3/3339b15ea7c025039809fab82a3b3e4d31f80b80.png?v=15)
```
DATABASE_TYPE="mysql" #数据库类型，可以是mysql或者postgres
DATABASE_HOST="mysql" #数据库主机地址，如果是容器搭建的数据库，就填写启动的数据库容器名，如果是其他主机，就填写内网ip地址
DATABASE_PORT="3306" #数据库端口，mysql默认是3306，postgresql默认是5432
DATABASE_DATABASE="omnibox" #数据库名，自定义
DATABASE_USERNAME="omnibox" #数据库用户名，自定义
DATABASE_PASSWORD="" #数据库密码，自定义
TZ=Asia/Shanghai#时区
#HTTP_PROXY=http://192.168.1.1:7890 ##这三条可以不设置，omnibox界面自带，其他docker容器若需要代理可以参考此配置以供容器内部走代理。http代理，改为自己的代理主机ip和端口
#HTTPS_PROXY=http://192.168.1.1:7890 ##同上，https代理
#NO_PROXY=localhost,127.0.0.1,docker-internal.net ##排除不需要代理的地址
```
我这里用的是1panel面板，如果是NAS的话，也是一样的步骤，只需要改一下存放docker容器内部文件的位置就可以了。如果是和compose.yaml在同一路径，那就直接设置为如下。而`.`代表当前目录，指的是compose.yaml存在的目录。`.env`文件同理，指的是有一个环境变量配置`.env`文件存放在和compose.yaml文件存在的同一目录下。可以手动改为绝对路径。
```
volumes:
  - ./data:/app/data
```

## 3.配置pancheck容器
> 由于pancheck依赖redis和mysql数据库，所以先安装两个数据库，Lampon提供的compose文件是整合到一起的，我个人是倾向于将数据库容器分配置来管理，因为不只是这个容器会用到数据库，其他容器可能也会使用到。如果你没有其他场景可以使用到数据库，可以直接使用Lampon老哥的版本，另外，这个容器对postgresql支持也不好 ![:bili_040:](https://cdn3.ldstatic.com/original/3X/3/3/3339b15ea7c025039809fab82a3b3e4d31f80b80.png?v=15)如果有需求可以自己拉取源码改一改编译一个。不过很多佬友可能没有postgresql数据库的需求，下面我就用mysql来展示了。 ![:bili_040:](https://cdn3.ldstatic.com/original/3X/3/3/3339b15ea7c025039809fab82a3b3e4d31f80b80.png?v=15)（postgresql修好了，有需求的可以自己改，把mysql的type类型和port端口的行注释掉，取消注释postgresql的type类型和port端口的行就可以了）
> 首先提供一个pancheck的仓库地址，如果对整洁度单容器管理无需求的话，可以直接用Lampon老哥的整合版[Lampon/PanCheck](https://github.com/Lampon/PanCheck)
```
services:
    mysql:
        container_name: mysql
        image: mysql:8.0
        network_mode: "omnibox"
        ports:
            - "3306:3306"
        restart: unless-stopped
        environment:
            MYSQL_ROOT_PASSWORD=""#mysql的root管理密码
        volumes:
            - ./data/:/var/lib/mysql
            - ./conf/my.cnf:/etc/my.cnf
            - ./log:/var/log/mysql
            - /etc/timezone:/etc/timezone:ro
            - /etc/localtime:/etc/localtime:ro
```
```
services:
    redis:
        container_name: redis
        image: redis:latest
        network_mode: "omnibox"
        ports:
            - "6379:6379"
        restart: unless-stopped
        command: redis-server --appendonly yes
        volumes:
            - ./data:/data
            - ./conf/redis.conf:/etc/redis/redis.conf
            - ./logs:/logs
```
```
services:
  pancheck:
    image: lampon/pancheck:latest
    container_name: pancheck
    ports:
      - "6080:6080"
    env_file:
      - .env
    volumes:
      - ./data:/app/data

    network_mode: "omnibox"
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:6080/api/v1/health"]

```
