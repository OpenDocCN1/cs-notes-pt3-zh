## Rules 和 Skills

### Skill 通用

名称与 `SKILL.md` 里的 name 要一致，需要下划线，不能用空格

项目级 skill 会覆盖同名的全局 skill

### Rules 通用

@ 任何 rules 都是进上下文的 user 部分，上下文用满后，压缩上下文时可能被压缩或删除

只有自动加载的 rules 才会写进上下文的 system prompt 部分，不会压缩或删除

### Antigravity

**全局 rules**：`C:/Users/用户名/.gemini/GEMINI.md`

**项目全局 rules**：没有

**项目 rules**：`{workspace}/.agent/rules/*.md`，可设强制/手动/ AI 决定/匹配文件名

**执行规则，YAML**：trigger: `always_on` / `model_decision` / `manual` / `glob`

**子目录 rules**：没有

**skills**：`.agent/skills/名称/SKILL.md`

### Cursor

**全局 rules**：没有 `.md` 文件，写在数据库里

**项目全局 rules**：`.cursor/rules/*.md`

**项目 rules**：

**执行规则**：执行规则不是写在 rules 文件里，没有 YAML，而是写在 UI 里，存数据库：`Auto` / `Manual` / `Glob` / `AI match`

**skills**：`.cursor/skills/名称/SKILL.md`

可在 `config.toml` 用 `skills.config[ ].path` 指向任意目录

### Trae

**全局 rules**：在 `Users/用户名/.trae-cn/user_rules.md`

**项目全局 rules**：在 `{workspace}/.trae/rules/*.md`

**项目 rules**：执行规则仅在 `.trae/rules` 下生效

**Trae.trae/skills**：`/名称/SKILL.md`

没有单独的由 AI 决定选项，可以按下面写法触发：

```
alwaysApply: false
description: "AI决定匹配的触发关键词"
globs: [...] # 如果想结合文件匹配，可以留空或加通配符
```

**同步提示词**：

把 `Users/用户名/.gemini/GEMINI.md` 映射到 `Users/用户名/.trae-cn/*.md`

把 `.agent/rules/` 映射到 `.trae/rules/`

### Codex

**全局 rules**：`{workspace}/AGENTS.md`

`AGENTS.md`（注意有 S），`AGENTS.override.md`（覆盖同级），可以放 workspace 根目录或子目录（仅对子目录里文件有效），新建聊天才会生效

**skills**：`.agent/skills/名称/SKILL.md`

### Claude Code

**全局 rules**：`Users/用户名/.claude/CLAUDE.md`

**项目全局 rules**：`{workspace}/CLAUDE.md`，强制执行

**项目 rules**：`{workspace}/.claude/rules/*.md`

**项目 rules**：执行规则只能设 glob，其他不能设置，规则文件总是加载，由模型决定何时用哪段

**子目录 rules**：`{workspace}/子目录/CLAUDE.md`，只在处理该子目录文件时生效

**YAML**：`paths: ["*文件夹关键词*/**", "*文件名关键词*.md"]`

**description**: 测试文件规范，*是给人看的，无其他作用，可以不写*

**skills**：`.claude/skills/名称/SKILL.md`

没有单独“改默认根目录”开关，但可用 `--add-dir` 加载额外目录中的 `.claude/skills`

**映射提示词**：

把 `C:/Users/用户名/.gemini/GEMINI.md` 映射为 `C:/Users/用户名/.gemini/.claude/CLAUDE.md`

把 `{workspace}/.agent/` 映射为 `{workspace}/.claude/`

注意要把所有 `.agent/rules/*.md` 里面加一行 `paths`，不知道加啥的就先用`paths: ["禁用"]`占位，否则会全部加载

### Kilo Code

**全局 rules**：`Users/用户名/.kilocode/rules/*.md`

**项目 rules**：`{workspace}/.kilocode/rules/*.md`

**项目 rules**：执行规则没有 YAML，没有 `alwaysApply` / `manual` / `glob` / `AI决定`

**全局skills**：`~/.kilocode/skills/名称/SKILL.md`

**项目skills**：`{workspace}/.kilocode/skills/名称/SKILL.md`

## 同步

### 相同 IDE，不同 workspace 之间的 rules：同步

### Antigravity 除 `GEMINI.md` 以外的 rules：只能映射

提示词：把 `{workspace1}/.agent`，映射到 `{workspace2}/.agent`

### 不同 IDE，相同 workspace，从一个 IDE 映射到其他 IDE

提示词：把 `{workspace}/.agent`，映射到 `{workspace}/.cursor`

### 文件夹映射 vs 单文件映射

**文件夹优点**：一次性映射所有文件，管理方便

**文件夹缺点**：两个文件夹内容会完全相同，没有私密 rules 或 skills

**单文件优点**：文件夹内只有映射了哪些文件相同，可以有私密 rules 或 skills 不参与映射

**单文件缺点**：要每个 rule 都映射一次，量大比较难管理

### 内容不同，但文件名不同的映射

例如： Antigravity 的 `GEMINI.md  映射到 Codex 的 `AGENTS.md`

不只是编辑文件，还包括执行任意 bash 命令、删除文件、安装依赖、访问网络等所有操作，统统不问直接干

## 聊天记录和Artifact

### VSCode通用

#### `/annotations/id.pbtxt` 聊天记录索引

每个文件里只有一行：`last_user_view_time:{seconds:1773403375 nanos:592000000}`

Chat History UI 很可能就是靠读取 annotations 目录来排序和展示 “Recent” 列表的。370 个 annotation 文件对应 370 次对话记录（远多于 conversations 里的 7 个 `.pb`文件），这说明 annotations 保留了比 conversations 更完整的历史索引

annotation 里只有一个时间戳，没有 workspace 信息

#### `/conversations/id.pb` 聊天记录文件

`.pb` 是Protocol Buffers 的缩写，谷歌自家的二进制序列化格式 相比 JSON 或纯文本，它体积更小、解析更快，但人类无法直接阅读

聊天名字是自动起的，只能英文，不能修改

#### /brain

多个 profile 共享 brain

存的是 AI 在对话过程中生成的 artifact 文件，按对话 ID 分文件夹 每个文件夹里可能有：

`task.md` — 任务清单（带勾选状态）

`implementation_plan.md` — 实施方案

`walkthrough.md` — 完成报告

`media_*.png` — 截图

`*.metadata.json` — 元数据

这些是从对话中提炼出来的结构化文档，人类可以直接阅读

conversations 是“录像”，brain 是“剪辑后的精华片段”

一次对话可能有 100 轮来回，但最终沉淀到 brain 里的可能只有一份 `task.md` 和一份`walkthrough.md`

conversations 是完整但冗余的（包含所有试错、返工、废弃的思路），brain 是精炼但不完整的（只保留最终结论）

#### /knowledge

knowledge 是跨对话的知识提炼——系统后台会分析多次对话，把重复出现的主题合并成知识条目

三者的层次：conversations（原始流水）→ brain（单次提炼）→ knowledge（跨对话沉淀）

#### /implicit 隐式对话

存的是隐式对话——就是你没有主动发起聊天，但 Antigravity 在后台自动触发的 AI 交互 典型场景包括：

内联代码补全（你打字时跳出的灰色建议）

代码操作（Quick Fix、重构建议等 Gemini 驱动的功能）

自动解释/诊断（悬停时弹出的 AI 解释、错误诊断等）

后台索引和上下文理解（Antigravity 在后台分析你的代码库时产生的请求）

这些交互不在 Chat History 和 Agent Manager 里展示，因为它们不是用户发起的“对话”，而是编辑器自动产生的 API 调用记录

#### 丢聊天记录问题

Reddit 上也有人反映丢聊天记录问题

关于为什么聊天历史里找不到凌晨 0~6 点的内容

这是核心问题。从你的两张截图来看：

Profile2（图1）：当前是 “Dream Analysis Rules”（即我们这次对话），Recent 里最近的是 “Explorer & TreeView Enhancements”（2 days ago）

Profile1（图2）：当前是 “AI Product Development Strategy”（1 day ago），Recent里最近的是 “我写了大量关于Antigravity的笔记…”（3 days ago）

但磁盘上确实存在两个 `.pb` 文件的修改时间落在今天凌晨：

“eea89266”（AI IDE Customization Options）修改时间 = 今天04:34

“1c75a612”（Antigravity Chat Integration）修改时间 = 今天06:07

**id 在 conversations 里存在，在 annotations 里丢失**

这也解释了你的丢记录问题——如果一个对话的 `.pb` 文件在 conversations 里丢了，但 annotation 还在，UI 可能会跳过它（有索引但找不到数据文件） 反过来，如果 `.pb` 文件在但 annotation 丢了，UI 也不会显示它

你那两个凌晨的对话（eea89266 和 1c75a612），`.pb` 文件在 conversations 里存在，但它们在 annotations 里是否存在才是决定 UI 是否显示的关键

**id 在 annotations 里存在，在 conversations 里丢失**

不会显示id名字

无法恢复，因为

**通过 /implicit/.pb 时间，确定是否丢记录**

所以 implicit 和你的聊天记录丢失问题无关——你丢的是 conversations 目录下的显式对话，implicit 里的隐式对话从来就不会出现在聊天列表里

无法通过 `/implicit.pb` 恢复 `/conversations/.pb`

## `settings.json` 和 `keybindings.json`同步 /*260224*/

### `settings.json` 原理

VSCode 系有三个 `settings.json`，格式内容可以一样

一个是 default `settings.json`，不能修改

一个是 user `settings.json`，不同 profile 独立

### 映射法

**Cursor提示词**：把 `/AppData/Roaming/Antigravity/User/settings.json` 和 `keybindings.json` 映射到 `/AppData/Roaming/Cursor/User/`

**VSCode提示词**：把 `/AppData/Roaming/Antigravity/User/settings.json` 和 `keybindings.json` 映射到 `/AppData/Roaming/Code/User/`

**Trae提示词**：把 `/AppData/Roaming/Antigravity/User/settings.json` 和 `keybindings.json` 映射到 `/AppData/Roaming/Trae CN/User/`

中途可能会提示需要管理员模式，点确定即可

### 分叉专有设置问题

VSCode：不存在这个问题

Antigravity：专有设置基本在 `~/.antigravity/settings.json` 或 `~/.gemini/antigravity/`

Cursor：90% 在 `settings.json`，10% 在`用户名/Cursor/User/globalStorage/state.vscdb`

Trae：主要写在 `settings.json`

VSCode 与 Antigravity 最安全，Cursor 和 Trae 可能有专有设置被 VSCode 或 Antigravity 覆盖问题

### 映射后专有设置是否会互相干扰？

一般不会，因为名称并不相同，等于一个总 `settings.json` 里包括了所有 IDE 的专有设置，互不影响

### `workspace/settings.json` 同步

缺点：但换个 `workspace` 就失效，不推荐

各 IDE 在同一 workspace 下，`settings.json` 位置也不同，还是要映射
