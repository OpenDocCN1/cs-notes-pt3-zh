# 授课讲义二：集群架构；ssh config；nfs；rsunc

## 课程目标
- 理解超算集群的架构设置
- 了解ssh免密，config文件作用
- 了解NFS并能使用NFS挂载共享目录
- 了解rsync并使用其进行数据同步与备份
- 能独立搭建一超算集群雏形，并完成基本配置（如共享目录，节点间免密等）
## 超算集群
### 超算集群是什么
超算集群是计算资源，存储资源，网络资源，调度资源的整合
用于平衡有限的资源与近乎无限的任务
### 超算集群基本架构
一个成熟的超算集群通常分为以下部分
```
用户层 -> 接入层 -> 调度层 -> 计算层 -> 存储层
  ↑         ↑        ↑         ↑        ↑
  ----------------网络层-----------------
```
#### 用户层&接入层
用户层即为使用集群的用户，接入层的作用就是为用户提供稳定且唯一的集群入口
特点：禁止用户运行计算任务/高并行大规模编译任务等占用大量系统资源的任务，IO高，ssh并发高
#### 调度层
超算集群的核心，常用的调度系统有slurm，lsf，tbs等
职责：分配集群所有资源（CPU/GPU/内存等），任务调度，队列管理
调度器的作用就是对用户明确展示：谁在什么时候使用了什么资源，运行了多长时间；谁可以在什么时间范围内使用什么资源
#### 计算层
为用户提供计算资源
特点：多为无状态设计，即通过网络启动，重启时会覆盖所有更改；禁止用户ssh直连；多以NFS挂载共享目录
#### 存储层
为用户提供存储空间
常见为NFS；并行文件系统等
特点：多节点共享，高吞吐
#### 网络层
连接其他五大层
成熟的集群通常拥有两套网络系统，其一为计算网络，其二为管理网络
计算网络为保障普通用户使用，如ssh，NFS等，管理网络为运维专用
常见技术：InfiniBand；RDMA over Ethernet
是MPI等多节点并行计算性能的上限
#### 用户任务流程
```
用户通过ssh登录login节点 -> 通过调度器提交任务 -> 调度器进行资源匹配与调度 -有空余节点-> 任务启动 -> 计算节点共享读取任务所需存储数据 -> 计算 -> 得到结果并写入结果文件 -> 任务结束 -> 通知用户(若配置)
                                                   |                      ↑
                                                 无空余节点                |
                                                   ↓                      |
                                                 排队等待 -----------------|
```
最小集群配置需要两台机器，具体任务分配如下
节点1：登录节点，兼存储节点，兼调度节点
节点2：计算节点
### 超算性能瓶颈
网络延迟与传输带宽上限；存储IO限制
## ssh免密登录，config配置
### ssh免密登录
#### 认证流程
```
ssh客户端以公钥指纹向节点发起连接 -> 节点侧查找authorized_keys中是否存在该公钥 -存在-> 节点侧发送随机数据进行挑战验证 -> 客户端使用私钥对该随机数据进行签名 ->节点侧以公钥验证签名 -验证通过-> 登录成功
                                                                                                                                                          |
                                                                                                                                                       验证失败
                                                                                                                                                          ↓
                                                                                                                                                 回退到密码登录/登录失败
```
#### 配置流程
1. 在需要配置免密登录的节点（通常为login节点）生成密钥对 `ssh-keygen -t ed25519`
2. 分发公钥 `ssh-copy-id user@node01`
常见问题：权限问题：.ssh目录权限必须为700；.ssh/authorized_keys文件权限必须为600；home目录权限必须为755；否则ssh会认为公钥不安全，可被篡改而拒绝使用公钥验证登录
### ssh config
在管理多节点过程中，ssh config可以帮助我们以别名的形式连接节点，而不必每次都写 `ssh username@ip`
#### 配置写法
```
Host node01
  HostName 127.0.0.1
  User username （可选，默认当前系统登录用户）
  Port 2222 （可选，默认22）
  IdentityFile ~/.ssh/id_ed25519 （可选，默认会尝试 ~/.ssh 下常见私钥（如 id_rsa、id_ed25519））
  IdentitiesOnly yes （可选，默认值为no，只使用 IdentityFile 指定的密钥）
  ProxyJump hostname （可选，默认关闭，指定跳板主机（别名或user@ip））
  更多配置可查询文档(man ssh_config)，此处不做展示
```
配置成功后即可通过 `ssh node01` 来连接127.0.0.1
#### 跳板机配置
```
Host login
  HostName 127.0.0.1
  User username
Host node01
  ProxyJump login
  User username
```
配置完成后可通过 `ssh node01` 连接，实际连接路径： `本机 -> login -> node01` 若login可被公网访问，但node01不可被公网访问，此配置可保证在公网连接node01
前提条件：login可访问node01 username对应用户拥有login和node01的访问权限
#### 性能优化
链接复用
```
Host * （通配符，对所有已配置主机生效）
  ControlMaster auto （自动启用主链接，后续重复连接复用该主链接）
  ControlPath ~/.ssh/cm-%r@%h:%p （指定复用的socket文件路径，%r->user；%h->host；%p->port；例：~/.ssh/cm-username@node01:22）
  ControlPersist 10m （主链接在最后一个session关闭后保留时间，此处为10分钟）
```
该配置可保证第二次及后续未超过主链接关闭时间的连接速度大幅提升，HPC中常用语rsync提速，git/scp等均可提速
可能存在问题：socket残留，可通过rm删除；多用户不可共享socket
## NFS共享存储
### NFS是什么
Network File System 本质上是将远程目录进行挂载以作为本地目录使用
在超算中用于统一存储管理，将用户文件在多个计算节点间共享
### 拓扑结构
```
                  NFS 服务端
                       |
               -------------------
               ↓       ↓         ↓
            node01   node02     login
```
### 配置流程
服务端：安装：`sudo apt install nfs-kernel-server` ，以配置`/shared` 目录为例，编辑`/etc/exports` `/shared  10.0.0.0/24(rw,sync,no_root_squash)`，`exportfs -ra` `sudo systemctl restart nfs-kernel-server`启用配置
客户端：挂载 `mount -t nfs serverip:/shared /path/shared`，`df -h`验证
参数详解：
- rw/ro：rw（read&write）读写；ro（readonly）只读
- sync/async：sync数据先写入磁盘后返回结果，安全性高；async：数据存入缓存后即刻返回，性能高但遇断电等情况时可能丢数据
- root_squash/no_root_squash：用于防止客户端root修改服务端文件，前者是nfs的默认行为，此时，客户端的root被映射为nobody；而后者则不做映射；视对客户端root权限所有者的信任情况开启/关闭
- subtree_check/no_subtree_check：路径一致性检查，超算上一般关闭，开启后每次访问都会校验路径是否属于导出目录，进而导致性能下降（例：客户端访问`/home/user1/file` 开启时，nfs会检查file文件是否真实存在于`/home/user1`目录下；路径是否被修改；是否存在越界访问等，任何一个环节出问题，nfs都会拒绝访问，关闭后则不做检查）
### 常见问题
权限问题：在NFS中，文件所属及权限管理均以UID/GID形式进行，而不是用户名，此时，假设同一个用户在node01上的UID为10001，node02上的UID为10002，此时就会导致这个用户的文件权限混乱，进而导致一些奇奇怪怪的问题，可通过LDAP；修改用户UID等方法解决
性能问题：在进行小文件读写或网络不稳定时，NFS有极大地可能卡在内核态，从而导致slurm无法判断任务结束状态，进而导致该计算节点停止工作
## Rsync数据同步
### rsync是什么
高效文件同步工具
### 与scp；cp的区别
最大的区别就是rsync是增量同步，而scp和cp是全量同步，这一特点使得rsync在备份与同步方面性能极高
### 原理
rsync在传输时会进行滚动校验，会将文件按照规则切分成块，rsync只会传输发生变化的块
### 使用
`rsync -av file /path/data` 同步某个文件，其中-a表示保留权限，时间等信息，-v表示展示传输过程
`rsync -av dir/ /path/data/` 同步整个目录，注意：dir后的`/`是否存在将对应两种不同行为：若带`/`，最终传输后则不会传输dir这个目录本身，不带`/`则会传输，例如：原本目录结构为`/home/dir/file` 带上`/`最终目录结构为`/path/data/file` 不带`/`最终目录结构为 `/path/data/dir/file`
### 参数
–delete：多余的文件将被删除，多用于镜像同步
-z：压缩，网络条件差时可启用
–progress：显示进度
–exclude：忽略文件
–partial：开启断点续传
