# 讨论一下怎么整理笔记

佬们好，想和大家讨论一下笔记整理方案，先讲讲我的方案，抛砖引玉一下。

## 为什么整理笔记

首先我个人开始写笔记的动机是**沉淀相对高质量的离线笔记（能够快速反复查询）**

具体一点：

1. 购买产品时，了解学习相关参数，每次重新购买时都补充回顾

2. 了解新技术、知识时，记录回顾；比如配置 pve、routerOS 系统，还有备份操作都记录下来，否则容易忘记自己做过什么操作、备份在哪里，怎么恢复。到时候都得重新上网搜集资料

总之，应该是融入工作流，遇到哪个就回顾。它本质上是大脑的延伸。

## 整理成什么样

首先就是要方便查询，每次需要的时候应该能快速定位。



其次，很多其他知识点，并不应该每个都在同一个笔记中重复地讲，应该能够复用，有点组件化的感觉。

所以，这个笔记应该是需要原子化，并且能够方便地查询。

总而言之，笔记系统的目标，不是“看起来整齐”，而是让知识能被持续找回、串联、复用和扩展。



如果只是记下来但几个月后找不到，那其实等于没记。

所以我现在对笔记系统的要求只有四个：

- 可导航

- 可复用

- 可复习

- 可扩展

## 使用过的旧方案

之前我最开始的笔记的话可能是，首先是按照文件夹来建立结构，进行分类。然后在单篇笔记中，可能直接就记录所有的相关内容。

但后面就发现存在一些问题。首先，文件夹的分类存在问题。遇到某些知识点的时候，往往可能就不知道应该放在哪个文件夹下。然后，如果全放在一起的话，也不方便组合复用。

笔记承载的是知识，本质上是**知识**+**知识展现形式**。

知识是复杂的，难以精确分类的，比如 xxx开发 的笔记，它可能包含 electron、vue、frontend、backend、typescript 等多种技术，或者是 dev 领域 或者是 project 属性。



**对于每个人，甚至每个人的不同时间，都会有不同的想法**。



所以任意的 tags 或者 文件夹结构在我看来都是不优雅的。

还有如果把所有相关内容都放在一篇笔记里更是灾难，它的维度会更多（concept、howto），也不方便复用 链接。



所以应该使用 **原子笔记**，能够做到笔记之间相互链接复用。

## 我现在用的方案

我现在采用的记笔记的方案是原子笔记加多维标签体系。然后，我抛弃了传统的文件夹架构，把所有的笔记都放在同一个文件夹下。然后是利用标签来筛选查找，利用 Obsidian 中的双向链接，还有 MOC 笔记来进行笔记之间的联系。

### 1. 原子笔记

一篇只讲一个概念、一个功能、一个操作。

比如：

- 什么是样式

- 什么是分节符

- 怎么插入题注

- 怎么设置页码

这种写法的好处是：

- 每篇都能独立读

- 后面可以自由重组

- 不会一篇里塞太多内容



我的原则很简单：



**一篇只讲一个东西。**

### 2. 关系笔记

有些内容不是单个概念，而是几个概念之间的关系。



比如：

- 分页符 vs 分节符

- 题注 vs 交叉引用

- 标题样式 vs 目录

- 脚注 vs 尾注

这类内容单独做成关系笔记更合适，因为真正有价值的地方不是定义本身，而是：

- 它们为什么经常一起出现

- 它们有什么区别

- 先后顺序是什么

- 最容易混淆的点在哪里



我的理解是：



**链接负责关系，正文负责解释。**

### 3. MOC

MOC 就是地图，不是正文。



它的作用只有三个：

- 给入口

- 给路径

- 给分组



MOC 不应该再把概念重新讲一遍，不然它就会退化成另一篇长文。



我的原则是：



**MOC 负责导航，不负责讲课。**

### 4. 多维标签

我现在不用“一套标签管所有事”，而是分维度来打标签。



大致是这些：

- `type/*`：这篇笔记是什么类型

- `status/*`：这篇笔记处于什么阶段

- 领域标签：属于哪个大领域

- `resource/*`：直接讲什么对象

- `purpose/*`：这个对象主要拿来做什么

- `platform/*`：适用什么平台

- `media/*`：资源形态是什么



比如：

```
type/concept
status/growing
resource/word
或者：
type/howto
status/evergreen
resource/zotero
```

核心原则只有一句：



标签负责分类和筛选，链接负责关系，正文负责解释。



我实际是怎么整理的



我一般会按这个顺序做：

1. 先查重，看看是不是已经有同主题笔记

2. 再判断角色，它是概念、关系、地图，还是操作指南

3. 再打标签，至少有 type/*、status/* 和一个领域标签

4. 再补 related notes，把前置、并列、易混淆概念串起来

5. 如果这篇是入口页，就顺手更新对应 MOC

一个实际例子



以 Word 这类主题为例，我会这样拆：

- Word 是 MOC

- Word 文档结构 是概念笔记

- Word 本科论文工作流 是 howto

- Word 题注与交叉引用 是关系笔记

它们不是互相替代，而是分工不同。



这套拆法的好处是：以后你想补内容、换顺序、重做入口页，都不会把整坨东西打乱。

我现在的经验整理笔记这件事，我现在越来越不追求“分得很细”，而是追求“边界清楚”。



我的经验是：

- 能独立成立的内容，做成原子笔记

- 需要讲联系的内容，做成关系笔记

- 需要组织全局的内容，做成 MOC

- 需要长期筛选的内容，用多维标签

如果一套系统只能写一次，那它只是草稿。

真正好用的系统，是你几个月后再回来，仍然知道：

- 每篇笔记是什么角色

- 应该去哪里找

- 应该怎么串联

- 应该怎么扩展

## 补充

还有现在的话，有了 AI 之后，完全可以添加一些 skills，来让 AI 去帮我们更好地联系各个笔记。



比如直接把自己刚学过的知识，或者说是问到的一大段文字，给它交给 AI，让 AI 帮我们去进行拆分，融入到原有的知识库中。



这样可以让笔记更清晰，拆分得更优雅。
