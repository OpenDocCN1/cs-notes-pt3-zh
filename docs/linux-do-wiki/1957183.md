> v0.0.11

> Features

>

> **模型选择器下拉浏览** — API Model 输入框右侧新增下拉按钮，点击即可浏览最新模型目录，不再只能靠打字触发搜索

> **图片文件识别** — Agent 读取图片文件时，内容会作为图片发送给 LLM，模型可以真正"看到"图片并描述内容

> **Explore SubAgent 模型选择** — 可在面板中为 SubAgent/Task (Explore) 配置独立的模型，不再强制继承主对话模型

> **Context Window 用量分类** — 上下文窗口占用现在按 Conversation / System / Rules 等类别分别显示

> **Shell/SubAgent 后台执行** — 长时间运行的 Shell 命令和 SubAgent 任务支持后台执行，不再阻塞对话

> **Canvas 导出** — Canvas 发布功能改为本地单文件 HTML 导出，无需联网

> **Skills 支持** — Canvas 和 View Report 等官方 Managed Skills 现在可正常使用

> **端口冲突检测** — 启动时自动检测端口占用，提供清晰的状态提示而非静默失败 9960 → 39831

> **Windows 兼容提示** — 缺少 MSVC Runtime 时给出安装引导，而非报不可理解的加载错误

> **Gemini Thinking** — 支持 Gemini 2.5 系列的 Level 和 Budget 两种思考模式

> **QuickSwitch 增强** — Fast 模式、Thinking 档位、1M 上下文等 Edit 面板开关现在与实际运行行为一致

> **跟进 Cursor 3.7.27**，消除启动时的重试风暴

>

> Bug Fixes

>

> **队列消息丢失** — 在 Agent 忙碌时发送的排队消息偶尔会变成空内容发送给 LLM，现已修复

> **读取二进制文件崩溃** — Agent 读取图片/PDF 等非文本文件时报 “invalid uint32: undefined” 错误

> **模型选择器点选不生效** — 从搜索结果中点击选择模型后，输入框仍显示之前输入的部分文字而非完整模型 ID

> **Fork Chat 失败** — 修复分支对话时 blob 编码不匹配导致历史记录丢失 功能无效的问题

> **SSE 流中断** — 长对话尾部偶发的流关闭竞态导致响应被截断

> **OpenAI 跨模型切换** — 从支持 thinking 的模型切换到不支持的模型后，thinking 参数未正确降级

> **Gemini 图片上传** — 发送图片给 Gemini 模型时请求被错误拦截

> **Gemini 工具调用** — 多工具并发时 functionResponse 数量不匹配导致报错

> **Max Output Tokens OFF** — 关闭开关后实际仍在发送 max_tokens 参数 （for Sub2api）

> **自动压缩只触发一次** — 修复 长对话中上下文压缩只能执行一次，后续超阈值不再触发的问题

> **SubAgent 权限** — SubAgent 默认 readonly 导致无法执行写入操作

> **工具路径错误** — Remote-SSH/WSL 跨平台场景下工具的工作目录被服务端错误解释

> **Task 后台状态序列化** — backgroundReason 字段偶发 NaN 导致 protobuf 编码崩溃

> **服务启动失败残留** — 端口被占用时 Fastify 实例和数据库连接未正确清理

>

> Features

>

> **Agent Window 独立运行** — 无需打开 Editor 窗口即可直接使用 Agent Window，侧边栏底部显示 BYOK 状态按钮，点击切换 ON/OFF

> **Server 自动接续** — 关闭运行 Server 的窗口后，其他窗口（含 Agent Window）数秒内自动接管，无需手动重启

> **模型参数面板** — 模型选择器点击 Edit 可调节 Thinking 开关、Effort 等级、Context 窗口大小，不同参数变体直接在列表切换

> **Fast Mode** — 支持 OpenAI / Anthropic 优先推理通道

> **网页搜索** — Web Search 工具支持 6 引擎（DuckDuckGo / Exa / Tavily / Brave / Jina / Firecrawl），可并行聚合

> **网页抓取** — Web Fetch 工具支持 3 种方式（内置 / Jina Reader / Firecrawl），HTML 自动转 Markdown

> **Web Tools 配置面板** — 侧边栏中配置搜索/抓取的 API Key、启用状态、并行模式

> **模型列表手动刷新** — 模型选择器搜索框右侧 ↻ 按钮，替代不稳定的自动刷新时序

> **Provider 排序** — 上下箭头调整 Provider 显示顺序

> **远端模型拉取** — Fetch Models 从 API 拉取可用模型列表，一键填入

> **Provider 独立保存** — 单个 Provider 独立保存，不影响其他未保存草稿，脏数据检测更精确

# 正文

虽然说是尽力做的简单好理解 傻瓜一些



但可能仍有一些基础的知识 可能我认为都不算知识 而只是通识 确实是有不了解的佬



所以在这里简单的列举和标注一些使用问题及其详情

---

1. 安装Cursor v3最新版 （虽然是废话 但真的有佬直接就开始++了）

2. 安装扩展 `npx @cometix/ccursor@latest install`

- 卸载扩展 `npx @cometix/ccursor@latest uninstall`

1. 打开检查网络模式处于 ![image](https://cdn3.ldstatic.com/original/4X/6/4/9/64980ea03aa7f81685eb7408e414f658d1e47d36.png) 下 然后确认![image](https://cdn3.ldstatic.com/original/4X/0/8/c/08c38e96ad82c02e840e034614f2bbcacd32abb6.png)处于正确工作的状态

2. 配置供应商

- **Anthropic** 直接写 除了 `/v1/messages` 之外的那部分

- **OpenAI** 通常要加 `/v1`

- **Gemini** 查无此资源 没有测试 按官网要求填写

1. 登录账号点一下开关就可以正常登了 ![image](https://cdn3.ldstatic.com/original/4X/8/3/8/838cd3786b687160d52219bd00ddb3fdefd1b594.png) 这就是 OFF 态

2. 单纯更新Cursor++就是 先uninstall恢复未Patch状态 再install到新版本

直接输模型id 然后模糊匹配会发力 直接点选一个 看起来相近的 （上下文窗口值很重要）



能力部分基本会自己填上



思考等级自己选 会赋予到 模型选择列表显示
