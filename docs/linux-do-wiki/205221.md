# 【科普】Linux下的权限

# 用户、用户组和权限
前两个顾名思义；用户大家都理解是什么，用户组就是把具备相同职能的多个用户划分到相同的用户组里，一个用户可以同时在多个用户组里。
Linux下文件或目录的权限有两个维度：
- 第一个维度分三项，可以为每一项单独设置权限，这三项分别是：

目录或文件所属的`用户（user，用u表示）`，
目录或文件所属的`用户组（group，用g表示）`，
还有一个`其他用户（other，用o表示）`。
- 第二个维度也分三项，分别是对文件或目录的：

`读（read，用r表示）`权限，
`写（write，用w表示）`权限，
`执行（execute，用x表示）`权限。
两个维度进行组合，就可以定义：
- 文件或目录所属的用户的读、写、执行权限，
- 文件或目录所属用户组的读、写、执行权限，
- 其他用户的读、写、执行权限。
针对目录，有两点特殊说明：
- 访问目录内容，是一种执行操作；所以像是cd进一个目录遭遇无权限的错误的情况，通常是因为当前使用的用户或用户组没有这个目录的执行权限。
- 在目录中添加或删除子文件或子目录，属于对目录本身的写操作；可以类比为图书馆要新增或处理一些图书，这时候要在图书馆的图书目录上进行修改。
还有一点需要说明的是，执行文件内容，并不需要读文件内容的权限。
# 如何查看权限信息
通常使用`ls -l`来查看权限，输出如下：
```
-rw-r--r--  1 libook libook    0 Sep 13 10:56 c
drwxr-xr-x  2 libook libook   40 Sep 13 10:56 d
```
我们主要看第1列、第3列、第4列。
**第1列，就是权限信息，每一位代表一个信息，一共10位。**
[权限说明.drawio400×477 7.01 KB](https://cdn3.ldstatic.com/original/3X/c/8/c8b9c74d8821bd431421a4dfc048af32dedfbf65.png)
第1位代表类型：
- `-`代表普通文件；
- `d`代表目录；
- `l`代表链接；
- `b`和`c`不常用，分别代表块设备和字符设备。
后面9位分为三组，每一组分别代表文件或目录所属用户、文件或目录所属用户组、其他用户；每一组内的3位分别代表读、写、执行权限，每一位上如果有字母就说明有权限，如果是`-`就说明没权限：
1. `r`代表读权限；
2. `w`代表写权限；
3. `x`代表执行权限。
比如`-rw-r--r--`从左到右这10位字符就分别表示：
1. `-`代表这是普通文件；
2. `r`代表文件所属**用户**有**读**权限；
3. `w`代表文件所属**用户**有**写**权限；
4. `-`代表文件所属**用户**没有**执行**权限；
5. `r`代表文件所属**用户组**有**读**权限；
6. `-`代表文件所属**用户组**没有**写**权限；
7. `-`代表文件所属**用户组**没有**执行**权限；
8. `r`代表**其他用户**有读权限；
9. `-`代表**其他用户**没有写权限；
10. `-`代表**其他用户**没有执行权限；
**第3列和第4列，是文件或目录所属用户和用户组**
比如`-rw-r--r--  1 libook libook    0 Sep 13 10:56 c`这里所示的就是这个文件属于libook用户，同时属于一个叫做libook的用户组。
# 如何修改权限信息
修改权限通常使用`chmod`指令，这个指令只能修改当前文件或目录本身，如果需要递归修改目录下的子文件或子目录需要添加`-R`参数。更多用法可以查看chmod的帮助或手册。
只有文件或目录的所有者和root用户可以修改这个文件或目录的权限，两者之外的任何用户都不可以，包括属于文件或目录的用户组的用户。
## 修改权限
### 符号法
在`chmod`指令后面，使用符号形式的权限描述。符号形式的权限描述主要分三部分：
- 权限主体，如用户（u）、用户组（g）、其他用户（o），此外还有一个包含前三者的所有用户（a）；
- 操作符，添加权限用`+`，去除权限用`-`，覆盖权限用`=`,覆盖的时候未写的权限则为要去除的权限；
- 权限组合，读（r）、写（w）、执行（x）。
需要同时操作多个权限主体就使用逗号分割。
举例：
```
# 给用户组添加写权限
## 当前权限为 -rw-r--r--
chmod g+w file.txt
## 新权限变为 -rw-rw-r--

# 给所有用户去除读权限
## 当前权限为 -rwxr-xr--
chmod a-r file.txt
## 新权限变为 --wx--x---

# 同时为用户和用户组添加执行权限
## 当前权限为 -rw-rw-r--
chmod u+x,g+x file.txt
## 新权限变为 -rwxrwxr--

#直接覆盖组权限为只读
## 当前权限为 -rwxrwxr--
chmod g=r file.txt
## 新权限变为 -rwxr--r--
```
用户可以剥夺自己对一个属于自己的文件的的写权限，当然也可以随时自己给自己赋予，这个功能实际上就相当于其他系统下存在的给文件设置“只读”的功能，避免用户自己对文件进行了误写入操作。
### 数字法
在`chmod`指令后面使用三位数字的形式来表示权限，这三位数字每一位分别代表：
1. 文件所属用户的权限；
2. 文件所属用户组的权限；
3. 其他用户的权限。
每一位数字是根据当前授权主体的读、写、执行权限的授予情况计算出来的分数，每种权限的分值如下：
- 读权限：4；
- 写权限：2；
- 执行权限：1。
看一个授权主体同时具备哪几项权限，将它们的分值累加就可以得出最终得分。
比如令一个文件的：
- 所属用户具备读权限、写权限、执行权限，即4+2+1=7；
- 所属用户组具备读权限、执行权限，即4+1=5；
- 其他用户具备读权限，即4
最终使用754为这个文件设置权限：
```
chmod 754 file.txt
```
## 修改文件或目录所属的用户、用户组
使用`chown`指令来修改，像`chmod`一样默认只会修改当前文件或目录本身，如果需要递归修改目录下的子文件或子目录需要添加`-R`参数。更多用法可以查看chown的帮助或手册。
只有文件或目录的所有者和root用户可以修改这个文件或目录的所属用户和用户组，两者之外的任何用户都不可以，包括属于文件或目录的用户组的用户。
直接举例：
```
# 修改为属于nobody用户
chown nobody file.txt

# 修改为属于nobody用户、users用户组
chown nobody:users file.txt

# 仅修改属于users用户组
chown :users file.txt
```
也可以使用`用户ID（UID）`和`用户组ID（GID）`来修改，系统的UID列表和GID列表可以使用如下方式查看：
- 从`/etc/passwd`文件查看UID，存储格式为`用户名:x:UID:所属主用户组的GID:备注:home目录路径:shell`；
- 从`/etc/group`文件查看GID，存储格式为`用户组名:x:GID:用户1,用户2`。
具体的使用例子：
```
# 假设当前系统上nobody的UID是99，users的GID是100
chown 99:100 file.txt
```
使用数字甚至可以设置为当前系统不存在的UID和GID。需要注意的是不同系统中，用户名和UID的对应，以及用户组与GID的对应不一定都是一致的，使用ID来操作有助于解决不同操作系统共享相同的文件系统（如网络文件系统，或容器与宿主机存储卷的映射）情况下名称与ID对应不同的问题，可以更精确地操作。
## 查看和修改用户所属的用户组
### 查看
在 Linux 下，用户可以同时属于多个用户组。这是通过用户的主组和附加组来实现的：
- 主组：用户默认所属的组，用户创建的文件默认归属于该组；
- 附加组：用户除了主组之外，还可以属于其他组，附加组为用户提供了额外的权限。
查看用户所属的用户组可以使用如下方式：
```
groups 用户名
# 或者下面这种可以同时输出GID和用户组名，并区分主组和附加组
id 用户名
```
### 修改/附加
只有root有权限修改用户的组。
修改用户的组使用`usermod`指令，具体使用例子：
```
# 修改用户libook的主组为hero
sudo usermod -g hero libook

# 将用户libook附加到users和staff组中
sudo usermod -aG users,staff libook
```
### 从附加组中移出
将用户从附加组中移出可以使用`gpasswd`指令：
```
# 将用户libook从staff组中移出
sudo gpasswd -d libook staff
```
或者可以使用`usermod`重新覆盖完整的附加组列表：
```
# libook用户当前属于users、staff、goodguy三个附加组，现重新覆盖为仅属于users、staff附加组
sudo usermod -G users,staff libook
```
也可以手动修改`/etc/group`的内容，这里就不赘述。
# umask是什么
本部分仅作为了解，暂不涉及实操。
`umask`是Linux系统中的一个命令和环境变量，用于控制新创建的文件和目录的默认权限设置。
在Linux系统中，新创建的文件的默认权限通常是`666（4+2即读+写权限）`，这意味着所有者、组用户和其他用户都可以读写文件。

新创建的目录的默认权限通常是`777（4+2+1即读+写+执行权限）`，这意味着所有者、组用户和其他用户都可以读写和进入目录。
`umask`通过**屏蔽**权限中的某些位，限制文件和目录的默认权限。
比如如果希望程序新创建的目录的权限为755（drwxr-xr-x），那么就需要将默认的777权限减去022，这时候就将umask设置为022即可。

同理，如果希望程序创建的文件的权限为640，那么就需要将默认的666权限减去026，这时候umask设置为026即可。
设置一次umask会同时影响创建目录和文件的权限，如设置umask为022，那么对新创建目录来说就是777-022=755，对新创建文件来说就是666-022=644。
