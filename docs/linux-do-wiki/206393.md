# 【科普】模拟器、虚拟机、容器有什么区别？

本文仅以科普为目的，旨在粗略、通俗地帮助人们了解相关知识原理，如果有兴趣深入了解请阅读专业的文献资料。
经常看到鼓捣NAS的大佬们分享各种关于PVE、EXSI、Docker、K8s等技术的实践经验，有的人说虚拟机功能很强大，也有人说容器管理超方便。
那么究竟什么是虚拟机，什么是容器；它们有什么区别；分别适合什么场景？
介绍它们之前我想先介绍模拟器。
# 模拟器（Emulator）
模拟器这个概念相信大部分人都曾经听说或，或使用过，比如在手机上玩FC、GBA、PSP游戏，或者在电脑上玩手游、NS游戏，都会使用到模拟器。之所以要用到模拟器就是因为这些游戏和软件没法直接运行在我们希望它们运行的硬件上。由于硬件设计不同，导致软件运行的机制、调用设备的方式不同；进而导致了为一种硬件平台编写的软件程序，尝试在另一个软件平台上运行的时候，会因为没有自己运行所需要的机制和设备而无法运行。
模拟器就是在硬件平台A上，使用平台A的软件的方式模拟出一个以假乱真的硬件平台B，来在这个硬件环境B里，按照平台B运行程序的方式来运行程序，并提供平台B所提供的设备调用功能。
关键特征就是模拟器模拟了一个完整或近乎完整的硬件环境。
模拟器解决的是在一个硬件平台上运行另一个完全不同硬件平台的程序的问题。
除了常见的模拟器，企业经常使用QEMU满足诸如在x86平台上运行ARM平台应用程序的需求。
# 虚拟机（Virtual Machine）
玩Linux的人可能大多都接触过虚拟机，比如在Windows中跑个虚拟机来安装Linux玩一玩，或者在Linux中跑个虚拟机来安装Windows使用一些Windows下才有的软件。虽然两个操作系统支持的硬件平台是一样的，但两个操作系统都要求独占硬件，所以通常不能同时运行。
而虚拟机就是在一个操作系统中，以软硬件结合的方式，欺骗另一个（或多个）操作系统以为自己独占了硬件。
因为宿主机和虚拟机上运行的操作系统都是面向相同的硬件平台而开发的，所以虚拟机并不需要像模拟器那样再费很大劲用软件来模拟设备，而是做好资源的分配和欺骗虚拟机里的系统就行了。
像极了脚踏多条船的“时间管理大师”，总能够隐瞒其他男/女朋友的存在。
虚拟机解决的是把一套硬件掰成很多份来用的问题。
常见的虚拟机软件有KVM（PVE的虚拟机也是基于KVM）、VMware（包括ESXI等产品）、Virtualbox、Hyper-V、Parallels等。
# 容器（Container）
曾经很长一段时间里，企业都是使用虚拟机来进行服务的部署，虚拟机有很多好处：
- 隔离：同一台服务器上部署多个服务不会导致运行环境互相冲突，也不会导致互相污染。
- 可复制性、可移植性：同一个服务部署在多个服务器上，可以直接部署虚拟机镜像，不需要重新搭建运行环境。
- 部署一致性：使用虚拟机镜像可以在多个服务器上部署完全一致的服务，不会因为手工部署而产生差异从而导致服务的运行不符合测试预期。
后来人们发现绝大部分企业应用场景下，使用虚拟机存在一些痛点：
- 硬件资源利用率不高：同一台服务器上部署多个服务的场景，绝大部分情况都可以使用相同的操作系统和系统配置，而每个服务虚拟机都运行一套独立的操作系统显然太浪费硬件资源了。
- 启动速度慢：因为每个虚拟机的启动都是经过引导-操作系统启动-应用程序启动的完整过程，所以往往需要数分钟才能完成启动提供服务。
- 分发成本较高：虽然可以使用虚拟机镜像来分发服务到多个服务器上，但是通常镜像体积比较大，即便开发者进行轻微的修改，也需要重新打一个全量大小的镜像，而且服务有bug需要回滚上一个版本就需要重新加载上一个版本的完整镜像。
- 资源分配的灵活性不高：设备、存储等资源可能是定量分配的，所以可能一部分服务用了80%的资源配额而有20%的资源闲置，但同时另一部分服务已经用完所有资源配额了，不能更弹性地分配资源。
是不是可以不把硬件掰成很多份，而是把操作系统环境掰成很多份，并确保每一份相互隔离？
容器：“我来助你！”
我们知道计算机操作系统中管理和分配资源的基本单位是进程。容器就是操作系统中的虚拟空间，欺骗容器内的进程以为这个虚拟空间就是整个操作系统环境。
所以实际上，同一个操作系统上运行的多个容器都共用宿主机的操作系统内核（Kernel），或者说都被同一个宿主机的内核管理，内核利用一个叫做cgroups的功能来创建出一个个虚拟的容器空间来运行进程以及给这些进程分配资源。
你可以运行一些容器，然后在宿主机和容器内分别执行`ps -ef`，就可以看到宿主机返回的进程列表包含所有容器的进程，但在容器内就只能看到当前容器内的进程列表；这说明容器内的进程和当前操作系统内的其他进程是一样被统一管理的，只不过就是一个容器内的进程无法觉察到自己是在容器内，也无法觉察到其他容器进程的存在。
那么疑问来了，我构建容器镜像的时候使用的是不同Linux发行版作为基础镜像，它们都可以在同一个Linux发行版上运行吗？

当然可以，因为Linux发行版都是使用Linux内核代码构建的系统内核，它们绝大部分的接口都是一样的，它们只是包管理器、文件结构、默认的软件包组合有区别而已，而绝大部分应用程序都只使用这些通用的内核接口。除非一个容器内的程序依赖某一个发行版内核特有的接口，那么这个容器就只能在支持这个接口的内核系统上运行。
容器是如何解决分发和部署痛点的呢？容器技术使用了一种分层文件系统的机制，构建镜像的每一步骤都会创建一个新的文件系统分层并进行操作，如果一个镜像有10层，我只修改了第7步的文件，那么前6步的文件系统层级可以直接复用，然后从第7步骤开始构建，分发的时候如果服务器上已经有前6层，我也只需要传输新构建的4层。
当然不是说容器技术可以完全替代虚拟机技术了，在需要对硬件资源进行严格隔离使用以及同时运行不同系统内核的情况，虚拟机往往依然是最佳方案。
常见的容器技术有Docker（containerd）、Podman、LXC、CRI-O等，过去很多VPS使用的OpenVZ实际上也是容器技术（貌似不维护了）。
# 兼容层（Compatibility layer）
游戏玩家应该都知道Steamdeck，默认配备的是Linux系统，但借助一个叫做Proton的技术可以玩大部分Windows游戏。Proton是一个提供了Windows兼容层的软件，它是基于Wine项目的，事实上有不少基于Wine的项目，都旨在于在Linux上运行Windows程序。
兼容层相当于是一个同声传译，Windows应用程序在兼容层上运行，应用程序调用兼容层的Windows接口，兼容层就去调用宿主系统的相同功能的Linux接口。
兼容层与模拟器的区别在于它通常是在操作系统之上使用，且不模拟设备而是提供系统接口的转换调用，所以通常它运行的程序可以以近乎原生性能的效率运行。
# 二进制转译（Binary translation）
苹果曾经在两次更换电脑产品的硬件平台，一次是从Power PC转到了x86，另一次是从x86转到了ARM，为了兼容旧平台的程序分别推出了Rosetta和Rosetta 2，这两代Rosetta工具就是二进制转译工具。
二进制转译工具就是在不需要修改软件代码的情况下，将已经编译成为二进制文件的软件程序进行转换生成新的程序文件，以支持不同的系统平台。
如果说兼容层相当于是同声传译，那么二进制转译就相当于将书籍或稿件进行一次性的翻译并发行译制版。
