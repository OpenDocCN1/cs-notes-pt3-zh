# :fire:【省钱系列15】还在用opus4.6吗，Claude Code里4.6消耗速度是4.7的4倍



下图我自己做的VSCode插件，来拟合按价格算出的用量曲线(蓝色)与Claude Code内/usage返回的百分比曲线(灰色)



价格如果填不对，两条曲线不可能拟合上

[image850×788 67.3 KB](https://cdn3.ldstatic.com/original/4X/8/4/8/8481c2097e59a478e0fb850c2bb6b8876230c694.png)

max算法与api算法完全无关，不要管api怎么算的，A社从来就没说过Max走API的算法

而且A社根据算力紧张程度，经常调整max额度的算法，少数时候会公开宣布，大多数时候黑箱子偷偷改

我推导Claude Code max算法，拟合官方百分比曲线得到

opus4.6 = 输入$5 + 输出$25 + **写缓存$15** + 读缓存免费

opus4.7 = 输入$5 + 输出$25 + **写缓存$3.125** + 读缓存免费

而写缓存一般占到了成本的80%，输入占0.1%，输出占20%左右

4.6价格并不是一直这么贵，在4.7出之前，4.6写缓存价格应该在$5-$6.25之间



是4.7出之后上调4.6的价格

我现在编程是用4.7便宜，但我写作还是喜欢用4.6，

虽然4.6很贵，消耗很快，写作任务一个多小时就用光5x的5h额度

4.7写作极简/抽象的风格，作为编程没问题，但作为写作经常不说人话，感觉不好

4.7写作用cluade web或app时，不说人话的问题会好一些，因为web/app系统提示词与Claude Code不同，4.7模型本来就有简洁倾向，再叠加Claude Code系统提示词里多处要求简洁，叠两层buff就更简洁抽象

### 动机

动机我猜测是，4.7是一个参数比4.6小很多的模型，成本更低，他们的价格差，可能一定程度就是他们的成本差或者参数差(四倍)

A社最近一个季度收入（即用户数）增加了了1.1倍，但算力怎么可能一季度增加1.1倍，造数据中心，建房子，排队等老黄和台积电造显卡，建电网，建电站都要时间，所以A社只能先给4.6降智，再砍4.7的参数来节省算力，或者也可能用sonnet4.7改名顶包opus4.7，

所以为什么sonnet没有4.7，之前泄露的Claude Code源代码里，sonnet的预留模型是sonnet4.6直接跳到sonnet4.8

另外mythos开发完了为什么迟迟不上线，安全问题可能都是扯淡，mythos api价格是opus五倍，说明需要的成本的算力也是五倍级别，A社维持opus运作算力都捉襟见肘要跟马斯克借算力，哪有几倍的余富算力支持mythos，所以真正原因可能是，A社现有算力根本不够支撑mythos大规模上线，只能提供给小部分公司试用

另外4.7的1m上下文分数比4.6下降一半，也是较小参数模型的特征

还有4.7的写作分数不如4.6，可能也是参数不够，写作和编程只能保一样，只能先保编程，放弃写作



这种保编程，弃写作，简洁抽象不说人话的策略，在gpt5.2-5.4时代，OpenAI为了追opus的编程，也使用过，对写作的残化也很明显，直到5.5参数上来了(价格翻倍，通常意味着成本翻倍，参数翻倍），才有所好转

### LiveBench和LMArena的写作/语言分，4.7都低于4.6

LiveBench里，4.7的语言分，甚至低于4.5和deepseek4
