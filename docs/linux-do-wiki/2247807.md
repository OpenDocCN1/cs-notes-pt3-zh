# 关于cc-switch



[CC Switch 官方网站 - AI 编程工具统一管理平台](https://www.ccswitch.io/zh/) 目的就是为了一键热切换。



详细图文教程：[搭建CPA配合CC-Switch畅快使用Codex的标准姿势 - 开发调优 / 开发调优, Lv1 - LINUX DO](https://linux.do/t/topic/2123253)

## 路由

路由就是指的是类似于[cpa](https://linux.do/t/topic/1914404)，把所有的模型url换成cc-switch的本地端口。让请求都经过cc-switch，因为在codex等agent端，他们的配置一直没变，都是cc-switch的端口，所以不需要重启agent，达到热切换的目的。



打开路由功能后，ccswitch会同步修改agent的配置。所以打开之前一定要确认当前的配置能通过测试，不然会破坏可用的ai配置，导致无法询问ai解决问题。

## 在kelivo中配置cc-switch

手动填写cc-switch的url和api



url："[http://127.0.0.1:15721/v1"](http://127.0.0.1:15721/v1%22)



api key可空白或随意填写



kelivo无法一键获取cc-switch的模型，所以需要**手动**填写模型名称。

## 报错

如果出现

- 503 Service Unavailable: Unknown error



可能是网络问题，关闭或者打开代理尝试。(在mac中用shadowrocket比[Clash Verge Rev](Clash Verge Rev.md)出的bug更多，而且不熟悉也不好改)

- Not found (404) 接口地址不存在，请检查 Base URL 和 API 路径。可能是CC Switch 的 SQLite 数据库里面 provider_health 表健康状态坏了，要重置一下。具体怎么改可以让ai改。

```
update provider_health
set
  is_healthy = 1,
  consecutive_failures = 0,
  last_error = NULL,
  last_failure_at = NULL
where app_type = 'codex';
```
