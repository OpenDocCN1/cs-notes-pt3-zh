# AI处理聊天记录数据思路共建汇总贴



最近想搞个AI智能查询聊天记录，然后对聊天记录进行分析、处理、总结的工具。

目前没有找到一个很高效的查询处理的方案，于是开帖，请求各位大佬开源一下自己的宝贵思路。

目前尝试过的方案：



1、传统RAG平台进行分段式向量处理，再关联大模型根据关键字查询。



存在的问题：前后记录无法关联；时间序列几乎没有；无法按照时间查询处理；无法从多个聊天中查询数据。



2、使用GraphRAG进行处理查询。



存在的问题：资源消耗大；时间序列不敏感；效率和经济属性极低。



3、目前在测试的方法，直接连接聊天记录的数据库，生成一些查询模板，然后以提示词的方式告诉他什么时候调用什么模板。



存在的问题：尚未测试成功；感觉通用性有点差。

感谢各位大佬赐教。

> 注：因考虑到聊天记录属于比较私密的内容，测试一般采用本地模型，考虑到可迁移，目前用的测试环境是ollama+qwen2.5_1.5B(纯cpu 0.5B)。使用联网大模型请注意消息记录脱敏处理。
