# 【保姆级教程】通过CCswtich兼容Cluade Cli和桌面版，接入第三方API热切换模型



# 前言

最近在折腾Claude中转站，因为佬友们的公益站太香了，本来以为只是填个 base url 和 key 的小事，结果CLI的不知道填到哪，桌面版的进去傻眼了，进去登陆之后，连配置入口都找不到，切到code还只能用订阅的默认免费模型发信息，踩了不少坑：

- 不知道怎么接入第三方API

- Claude Code CLI 能用，但是不知道怎么用桌面版

- 同一个中转站，sonnet 能用，opus/haiku 不一定能用

- ccswitch 切了 provider，但还像没切换一样

- 有的模型不是配置错了，而是上游根本没权限

- 开启本地代理之后 ccswitch 用的是一家中转站，结果另一家中转站收到请求

这篇不是“权威教程”，更像是我自己的排查记录。主要是用ccswitch 实现 Claude Code 桌面端和 CLI 端同时使用，而且可以在ccswitch里无感切换中转站，不用退出重进，真正意义上实现中转站的无缝切换，同时和codex也可以借用此管理方法。

- Gateway API key 使用 PROXY_MANAGED
- Auth scheme 使用 bearer

#### 手动注入注册表

```
New-Item -Path $path -Force | Out-Null

New-ItemProperty -Path $path -Name inferenceProvider -PropertyType String -Value 'gateway' -Force | Out-Null
New-ItemProperty -Path $path -Name inferenceGatewayBaseUrl -PropertyType String -Value 'http://127.0.0.1:15721' -Force | Out-Null
New-ItemProperty -Path $path -Name inferenceGatewayApiKey -PropertyType String -Value 'PROXY_MANAGED' -Force | Out-Null
New-ItemProperty -Path $path -Name inferenceGatewayAuthScheme -PropertyType String -Value 'bearer' -Force | Out-Null
New-ItemProperty -Path $path -Name inferenceModels -PropertyType String -Value '["claude-opus-4-8","claude-sonnet-4-6","claude-haiku-4-5"]' -Force | Out-Null
New-ItemProperty -Path $path -Name isClaudeCodeForDesktopEnabled -PropertyType DWord -Value 1 -Force | Out-Null
New-ItemProperty -Path $path -Name skipLoginModeChooser -PropertyType DWord -Value 1 -Force | Out-Null```

```
`$path = 'HKCU:\Software\Policies\Claude'`

这一行定义了一个变量 $path，里面保存注册表路径。

HKCU 是 HKEY_CURRENT_USER 的缩写，表示当前 Windows 用户。

Software 表示软件配置区域。

Policies 表示策略配置区域。这个区域通常优先级更高，软件会把它当成“强制配置”来读取。

Claude 是 Claude Desktop 对应的配置项。
`New-Item -Path $path -Force | Out-Null`

这一行用于创建注册表路径。

New-Item 表示新建一个项目。这里新建的不是文件夹，而是注册表项。

-Path $path 表示要创建的位置就是前面定义的 $path。

-Force 表示如果路径已经存在，就直接沿用；如果不存在，就创建。

| Out-Null 表示不显示命令输出，让执行结果更干净。
`New-ItemProperty -Path $path -Name inferenceProvider -PropertyType String -Value 'gateway' -Force | Out-Null`

这一行设置推理提供方。

inferenceProvider 表示 Claude Desktop 使用哪个推理提供方。

gateway 表示使用 Gateway 模式，也就是让 Claude Desktop 通过第三方网关转发请求，而不是直接使用默认官方入口。
`New-ItemProperty -Path $path -Name inferenceGatewayBaseUrl -PropertyType String -Value 'http://127.0.0.1:15721' -Force | Out-Null`

这一行设置 Gateway 的基础地址。

inferenceGatewayBaseUrl 表示 Gateway 的 base URL。

[http://127.0.0.1:15721](http://127.0.0.1:15721) 表示请求会发到本机的 15721 端口。

127.0.0.1 是本机地址，也叫 localhost。
`New-ItemProperty -Path $path -Name inferenceGatewayApiKey -PropertyType String -Value 'PROXY_MANAGED' -Force | Out-Null`

这一行设置 Gateway API key。

inferenceGatewayApiKey 表示 Claude Desktop 请求 Gateway 时使用的 API key。

PROXY_MANAGED 通常表示真实 API key 由代理或网关管理，Claude Desktop 这里不直接保存真实 key。
`New-ItemProperty -Path $path -Name inferenceGatewayAuthScheme -PropertyType String -Value 'bearer' -Force | Out-Null`

这一行设置认证方式。

inferenceGatewayAuthScheme 表示认证方案。

bearer 表示使用 Bearer Token 认证，请求头通常类似：

Authorization: Bearer PROXY_MANAGED
`New-ItemProperty -Path $path -Name inferenceModels -PropertyType String -Value '["claude-opus-4-8","claude-sonnet-4-6","claude-haiku-4-5"]' -Force | Out-Null`

这一行设置模型列表。

inferenceModels 表示告诉 Claude Desktop 当前 Gateway 暴露了哪些模型。

这里的值是一个 JSON 数组字符串：

[“claude-opus-4-8”,“claude-sonnet-4-6”,“claude-haiku-4-5”]

也就是说，模型列表包含：

claude-opus-4-8

claude-sonnet-4-6

claude-haiku-4-5
`New-ItemProperty -Path $path -Name isClaudeCodeForDesktopEnabled -PropertyType DWord -Value 1 -Force | Out-Null`

这一行启用 Claude Code for Desktop。

isClaudeCodeForDesktopEnabled 是一个开关。

-PropertyType DWord 表示这是一个数字类型的注册表值。

-Value 1 表示开启。

如果改成：

-Value 0

就是关闭。
`New-ItemProperty -Path $path -Name skipLoginModeChooser -PropertyType DWord -Value 1 -Force | Out-Null`

这一行开启跳过登录模式选择器。

skipLoginModeChooser 也是一个开关。

1 表示跳过登录模式选择器。

0 表示不跳过，也就是重新显示登录模式选择页面。
检查当前配置是否写入成功，可以运行：

`reg query HKCU\Software\Policies\Claude`
恢复正常原版 Claude Desktop，可以删除整组策略配置：

`Remove-Item -Path 'HKCU:\Software\Policies\Claude' -Recurse`

这条命令会删除：

HKCU\Software\Policies\Claude

以及它下面的所有 Claude 策略值。

删除后，Claude Desktop 启动时就读不到这组 Gateway policy，会回到默认登录和默认配置逻辑。
删除前如果想备份，可以运行：

`reg export HKCU\Software\Policies\Claude "$env:USERPROFILE\Desktop\claude-policy-backup.reg"`

这会把当前配置导出到桌面。以后如果想恢复，可以双击这个 .reg 文件重新导入。

## 原理和分析

至此，已经完成了所有设置，佬友们可以尝试重启后回到Claude桌面端，会变成这个样子，可以开心的蹬啦 ![:innocent:](https://cdn.ldstatic.com/images/emoji/twemoji/innocent.png?v=15)

### 同时解释一下为什么要这样配置，说清楚原理：

#### 1.为什么要配置ccswitch的本地代理

因为可以直接热切换多个中转站，不用退出重进Cluade，不用再重复教程配置

#### 2.什么是模型映射

配置中转站的可能会出现，大概意思是，你想用claude opus 4.8，但是他在中转站的名字叫别的名字，这个时候开启就可以让中转站得知请求，或者你只想用claude这个工具，但是接入别的模型，比如deepseek，这个时候就是把claude opus 4.8翻译成deepseek，能够成功使用。如果中转站原生支持所谓的官方模型，或者名字就和官方模型一样，那你开不开启都是无所谓的

#### 3.同时配置了cli和桌面版的中转站，并开启了本地代理，究竟走哪个

走cli的，即使中转站不同

#### 4.codex用不用开本地代理

我个人觉得没必要，因为codex集成了cli和桌面端，所以相比claude要走两个配置，直连每次切换需要重复配置非常麻烦，codex直接每次切换退出重进一下就好了，非常方便
