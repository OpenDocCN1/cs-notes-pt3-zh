shell不仅仅是命令解释器，也是一个脚本语言

shell脚本是一个文件

指定脚本解释器 `#!/bin/bash`，表示命令交给bash shell执行

注释用来描述程序代码的作用，不会被脚本执行

单行注释使用 `#` 多行注释使用 `<<EOF EOF`，后期补充明确，Bash原生并不支持多行注释，此写法是Bash的Here Document模拟出来的多行注释，这更像常见技巧，而不是标准的注释语法

```
<<EOF
我是注释
我是第二行注释
EOF
```

**后期发现，该多行注释的方法能作为注释工作，但Bash官方将其定义为Here Document，并不是专用的注释语法，如果 Here Document 的定界词未被引用，例如 <<EOF，其中的内容会进行参数展开、命令替换和算术展开**

GNU Bash官方文档 3.1.3 Comments：[Comments (Bash Reference Manual)](https://www.gnu.org/software/bash/manual/html_node/Comments.html)

其中写明 **a word beginning with ‘#’ introduces a comment.** 译为 **使用 # 引入注释**

GNU Bash官方文档3.6.6 Here Documents：[Redirections (Bash Reference Manual)](https://www.gnu.org/software/bash/manual/html_node/Redirections.html#Here-Documents)

其中写明 **all lines of the here-document are subjected to parameter expansion, command substitution, and arithmetic expansion** 译为 **here-document 中的所有行都将进行参数扩展、命令替换和算术扩展**

命令替换实例展示

```
$(date)
`date`
```

更明确更安全的写法如下

```
: <<'EOF'
这里作为伪多行注释
$USER 和 $(date) 都不会展开
EOF
```

Bash 原生使用 `#` 进行单行注释；脚本中常用 Here Document 模拟多行注释。推荐使用 `: <<'EOF'`，避免所写的内容发生变量展开和命令替换。

## Shell 脚本自动生成注释头

此方法来自誉天教育的孙老师（全名我确实不知道，所以只能这样写了）

```
autocmd BufNewFile *.py,*.cc,*.sh,*.java exec ":call SetTitle()"

func SetTitle()
    if expand("%:e") == 'sh'
        call setline(1, "#!/bin/bash")
        call setline(2, "##################################################")
        call setline(3, "# File Name: ".expand("%"))
        call setline(4, "# Version: V1.0")
        call setline(5, "# Author: xxx")
        call setline(6, "# Email: xxxg@xxx.com")
        call setline(7, "# Created Time: ".strftime("%F %T"))
        call setline(8, "# Description:")
        call setline(9, "##################################################")
        call setline(10, "")
    endif
endfunc
```

将以上代码写入 `~/.vimrc`，使用 Vim 新建 `.sh` 文件时会自动生成脚本注释头。

## 执行脚本的方式

相对路径执行 `./test.sh` 需要x执行权限

绝对路径执行 `/opt/test.sh` 需要x执行权限

bash shell执行 `bash test.sh` bash不看执行权限，但依旧要有读权限

source 执行 `source test.sh`或 `. test.sh` 不看执行权限，但依旧要有读权限

bash执行脚本时会创建一个子shell执行，使用脚本定义变量无法使用

source在当前shell执行脚本，定义的变量可以直接使用

## 位置化参数（位置变量）

在执行shell脚本时，可以在终端传入变量给脚本（在脚本后面接参数

$1 $2 $3 …

10及以上使用 `${10}`，这个参数是在脚本后接入的参数的第几个

使用 `$0` 可以获取第0个位置参数，也就是文件位置

课程里教了一种用后自焚的写法，`rm -rf $0`，但我研究了一下，实际操作下来可能因为启动命令的差异导致用后自焚的无效

```
./test.sh       # $0 = ./test.sh
bash test.sh    # $0 = test.sh
bash /tmp/test.sh  # $0 = /tmp/test.sh
source test.sh  # $0 不是 test.sh，可能是 bash 或父脚本
bash < test.sh  # $0 通常是 bash，也无法定位原脚本
```

综上，除非能限定用户的启动方式，不然是无法做到100%用后即焚的效果的

如果确需使用此方法，建议写成 `rm -f -- "$0"` ，此方法可以在减少递归误删的可能时，确保文件名中有空格时依旧可以做到删除

`$$`代表当前执行脚本的PID，使用 `echo $$` 可以在shell脚本运行时获取到当前脚本运行的进程PID

同样拥有扩展写法，使用 `ps -aux | grep $$ > /tmp/shell_log`将运行时的占用写入此文件，但我能想到的问题就是只能写入一次，或使用时间戳和追加+循环的方式持续写入，以做到脚本运行结束后debug查看占用的能力

我和chatgpt研究了一下，这种模型是可行的，且可以进行持续写入

```
#!/bin/bash

script_pid=$$                          # 保存当前脚本的PID
log="/tmp/shell_log.$script_pid"       # 使用PID区分不同脚本的日志

(
    # 脚本进程存在时，每秒记录一次资源占用
    while kill -0 "$script_pid" 2>/dev/null; do
        echo "===== $(date '+%F %T') ====="  # 写入采样时间

        # 记录PID、CPU、内存、运行时间和命令等信息
        ps -p "$script_pid" \
           -o pid,ppid,%cpu,%mem,rss,vsz,etime,cmd

        sleep 1                               # 每隔1秒采样一次
    done
) >> "$log" &                                # 后台运行并追加到日志

monitor_pid=$!                                # 获取监控进程PID

# 脚本结束时关闭后台监控进程
trap 'kill "$monitor_pid" 2>/dev/null' EXIT

# 此处以后编写脚本的主体任务
sleep 10
```

**注意：ps 显示的 %CPU 是进程启动以来的平均值，不是这一秒的瞬时占用。**

### 从命令行中接受用户的输入信息

`read` 从命令行中接受用户信息，可以指定变量名

`-p` 提示信息

`-s`秘文输入，静默输入/不回显输入

`-t`超时时间，单位是秒

```
read -p "输入你的提示词：" [变量]

read -p "输入你的提示词：" informathion #这样就为用户输入的信息传入变量$informathion

read -t 3 -s -p "输入你的提示词：" informathion #用户输入时秘文输入，三秒不操作超时
```

**注意：read的参数传递有很明确的层级，-t后面跟秒，-p后面写提示信息**

```
read -p -s "输入你的提示词：" informathion #经过后期校对，此处更改-s被识别成了-p的字符串
```

**如果你没有明确变量，则会使用read的默认变量 $REPLY，此变量只有一个，如果有多个read则会相互覆盖**

## exit退出码

当满足某一种条件后，执行退出，个人认为常用于各种if判断

exit可以携带退出码，成功是0，如果是1-255则为失败，也可以人为定义

exit的退出码是帮助判断问题的

```
#!/bin/bash
useradd $1
exit 2
```

这是的意思携带为2的退出码退出，我可以在手册中定义退出码2为创建成功

**但尽量不要学习这种逻辑，1-255应该是各种各样的报错，一般默认0为成功，如果使用后期的条件执行运算，会导致"逻辑与"失效，逻辑与使用退出码来判断成功，成功退出码为0**

```
#!/bin/bash
useradd $1
exit 0
```

**上面的示例则是携带成功退出码退出（也就是退出码为0）**

**后期修正：如果使用 exit命令直接退出，他不会默认为0，而会继承上一条命令的退出码**

在运行结束后使用`echo $?`命令即可查看退出码

## 条件执行运算符

使用逻辑条件执行多条命令

`&&` 逻辑与，当命令1执行成功（返回值为0的时候），则执行命令2；如果命令1执行失败，则命令2不执行

```
echo a && echo b && echo c
```

`||`逻辑或，命令1执行失败则执行命令2（也是通过返回值进行判断）

个人理解这个东西就像是备用路线，来一个实例看一下

```
pgrep nginx || ps aux | grep nginx || echo "执行失败啦"
```

这条命令的逻辑就是，先执行 `pgrep` 命令搜索 `nginx` 进程，如果执行失败，则启用备用方案 使用 `ps aux | grep nginx` 来搜索 `nginx` 进程，如果还是失败，则输出 `执行失败啦！`



如果第一条就成功了，则后面的命令都不执行

**前一个命令返回非 0 才走备用路线；任意一个返回 0，后面就停止**

刚跟GPT又掰扯了一下，`ps aux | grep nginx`这条命令确实会把grep自己也搜出来（前面学习进程管理的时候深有体会），所以可以使用正则表达式

```
pgrep nginx || ps aux | grep '[n]ginx' || echo "执行失败啦"
```

算是一种取巧的写法，可以匹配普通文本`nginx`但无法匹配`[n]ginx`，防止匹配到grep命令导致的误判为执行成功

`!` 逻辑非，对命令的结果进行取反，这块感觉有点抽象，但貌似理解了？

## 复合指令

将多条命令变成一条集合，这里涉及到shell和子shell

`{}`执行括号内的命令，在当前shell运行，开头必须加空格，结尾必须是分号，命令分割使用分号或换行

```
{ pwd;cd /root;}
```

`()`执行括号内的命令，在子shell中运行，命令分割使用分号或换行

```
(pwd;cd /root) #使用此命令不会进入root目录
```

这里会有一些疑问，那既然实在子shell中运行，那我删文件不是删不掉？（这是课程上有人问的，所以写出来）

答案：会删，虽然操作的不是一个shell，但操作的是同一个用户同一个系统。

可以把子shell理解为多开了一个终端控制台

### 文件测试运算符

`-f`判断文件是否存在，存在返回0

`-d`判断是否为目录，是返回0

`-e`判断目录是否存在，是返回0

`-s`判断文件是否存在且是否为空，不存在或为空返回1，存在且有内容范围0（他讲的时候只说了判断是否为空，但我感觉怪怪的就去查了一下）感觉此参数在应用层面更多是判断一个文件是否有内容，有内容则返回0，没内容则返回1

```
test -f /etc/passwd

[ -f /etc/passwd ]

[[ -f /etc/passwd ]]
```

`-b`是否为块设备

`-r -w -x` 判断是否有相应的权限

**后期经过激烈讨论在此处补充关于-e -f -d -s的官方解释，以免引起歧义**

`-e` 路径对应的对象存在

`-f` 路径对应的对象存在，并且是普通文件

`-d` 路径对应的对象存在，并且是目录

`-s` 路径对应的对象存在，并且大小大于0

GNU Bash官方文档 6.4 Bash Conditional Expressions：[Bash Conditional Expressions (Bash Reference Manual)](https://www.gnu.org/software/bash/manual/html_node/Bash-Conditional-Expressions.html)

### 布尔运算符

`-a` 与运算，等价 `&&` 只有两个表达式同时成立结果才为真

`-o` 或运算，等价 `||`两个表达式只要有一个真即为真

`!` 非运算，对整个表达式取反，同逻辑表达式里的 `!`逻辑非

后期与GPT查证，`-a -o`为test的旧语法，复杂条件可能容易引起歧义，建议使用以下写法

```
[ 条件1 ] && [ 条件2 ]
[ 条件1 ] || [ 条件2 ]

或

[[ 条件1 && 条件2 ]]
[[ 条件1 || 条件2 ]]
```

**关于 -a 和 -o 为旧语法的争论**

GNU Bash官方文档 4.1 Bourne Shell Builtins 中的test描述章节 ：[Bourne Shell Builtins (Bash Reference Manual)](https://www.gnu.org/software/bash/manual/html_node/Bourne-Shell-Builtins.html#index-test)

原文写道：The historical operator-precedence parsing with 4 or more arguments can lead to ambiguities when it encounters strings that look like primaries. The POSIX standard has deprecated the -a and -o primaries and enclosing expressions within parentheses. Scripts should no longer use them. It’s much more reliable to restrict test invocations to a single primary, and to replace uses of -a and -o with the shell’s `&&` and `||` list operators.

可译为：历史上的四参数及以上优先级解析可能产生歧义；POSIX 已弃用 `-a`、`-o`，脚本不应继续使用，应改成 Shell 的 `&&`、`||` 列表运算符。

官方推荐写法如下：

```
test -n string1 && test -n string2

test "$1" && test "$2"
```

## break和continue

视频课里说很多人大学里学了可能分不清这俩的区别是什么，而我就不一样了，我压根忘了这俩是啥东西了![:face_savoring_food:](img/68e985d3b4eaeedd21711931dc3ba7a2.png)

`continue`是跳过本次循环

`break`是跳出当前整个循环

一个小实验就可以很明确的看出来了，这里是编写了一个脚本，意思是遇到5就运行continue命令，即跳出本次循环

```
root@SH-Debian-Tencent:~# cat continue
#!/bin/bash

for i in {1..10}
do
	if [ $i -eq 5 ]
	then
		continue
	fi
	echo $i
done
echo End

root@SH-Debian-Tencent:~# bash continue
1
2
3
4
6
7
8
9
10
End
```

而 `break`是跳出整段循环，通过以下实验可以看出

```
root@SH-Debian-Tencent:~# cat break
#!/bin/bash

for i in {1..10}
do
	if [ $i -eq 5 ]
	then
		break
	fi
	echo $i
done
echo End

root@SH-Debian-Tencent:~# bash break
1
2
3
4
End
```

## trap技巧

trap 是 Bash 的信号处理机制，让你在脚本被中断时仍能执行清理逻辑。



trap … EXIT 是最安全的——不论脚本因 exit、Ctrl+C、kill 或错误结束，都会执行清理。比手动在每个 exit 前写清理程式码可靠得多。

### 基本语法

```
trap 'commands' SIGNAL
```

### 常见用法

1. 清理临时档

```
TMPFILE=$(mktemp)
trap 'rm -f "$TMPFILE"' EXIT # EXIT 不论正常结束或被中断都会触发
```

1. 忽略 Ctrl+C

```
trap '' SIGINT # 脚本执行期间 Ctrl+C 无效
```

1. 禁用/重启信号

```
trap - SIGINT   # 重新启用 Ctrl+C
```
