# 【面向小白】分享使用cc-swtich的经验--配置路由

本人小白，在使用cc-switch的过程中发现路由是一个非常重要的配置项，在此分享一些对cc-switch配置路由的一些学习和了解。
## 简单介绍一下cc-switch：
我理解的cc-switch是一个AI工具配置管理中心。能一次性将你的api-key配置到你的codex、claude等AI工具中，并且在多个账号的情况下能够快速切换配置。
更多内容可以在[cc-switch官网](https://www.ccswitch.io/zh/)进一步了解。
- 需要注意的一点是，正常登录使用AI工具，都是需要有对应厂商的账号，例如codex需要有openai的账号，这些账号并不是所有人都能轻易获取或者负担的（对我而言太复杂也太贵了）。
- 而在cc-Switch中，**路由（Routing**）** 的主要的作用，就是让像 Codex CLI 这样的 AI 编程工具，能够无缝调用 DeepSeek、Kimi 等任意第三方大模型，也同样能够接入L站中佬们辛苦维护的公益站。
## cc-switch中路由的原理
AI工具无法接入其他这是因为 Codex 这类工具和很多第三方大模型的协议不同：
> Codex原生只支持OpenAI的Responses API。
> DeepSeek、Kimi 等普遍使用Chat Completions API
这两种协议在请求格式、参数等方面完全不同，直接对接会导致请求失败。cc-switch通过以下四步解决这个问题：
1. **接管请求**：开启路由后，CC Switch会自动修改 Codex 等工具的配置文件，将其API地址指向本地 `[http://127.0.0.1:15721](http://127.0.0.1:15721)`。这样，工具的所有请求都会先发给CC Switch。
2. **识别来源**：CC Switch接收到请求后，会识别出这是来自哪个应用（如Codex或Claude）的请求。
3. **协议转换**：识别出请求来源后，它会判断目标供应商的接口类型（`apiFormat = “openai_chat”`），然后将Codex标准的Responses API请求，实时改写成第三方模型能理解的Chat Completions API请求。
4. **响应还原**：当收到第三方模型返回的Chat格式响应后，CC Switch会再次进行反向转换，将响应还原成Codex能解析的Responses格式。
了解了cc-switch路由的原理，对于什么情况下需要使用路由，应该会有初步的判断（我最开始是纯试，打开不行就关上，再不行就改url试TAT）。
## 如何使用路由？
使用起来非常直观，主要分两步：
1. **添加供应商**：在 CC Switch 的对应应用标签页（如 `Codex`）下，点击“添加”，从预设列表中选择你的模型供应商或者自定义，填入API Key等参数，打开“需要本地路由映射”（以防有跟我一样，不带脑子的迷糊蛋，“API请求地址”后的完整url也需要打开）。
2. **开启路由**：进入“设置” → “路由”页面，打开“路由服务”总开关，然后在“应用路由”区域，为你想代理的应用（如 Codex）开启开关即可。
## 使用路由和不使用的区别
- 开启路由   ：切换供应商不需重启AI工具 ，即时生效。原理是CC Switch 作为本地代理，动态转发请求。适用于想在在AI工具中接入三方API、多账号经常切换，需要在使用过程中一直启动cc-switch。
- 不开启路由  ：切换供应商必须重启AI工具。原理是CC Switch 直接修改工具的配置文件。适用于账号相对固定单一且符合对应AI工具的协议，一次配置一直省事，配置完就再也不需要打开了。
以上是我在配置过程中了解到的关于路由的一些内容，希望能帮助到一些搞不清cc-switch路由配置的朋友。
