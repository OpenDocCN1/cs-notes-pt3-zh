# 小白教程：皮皮工艺站简单教程（把闲置的token利用起来）



## O、你有没有过这样的烦恼

手里的token太多，薅了很多羊毛用不完浪费了，想分享给佬友们却不知如何下手。难道还要买服务器、学部署、配环境？各种概念劝退了无数热心的萌新佬友们。

好在 [@picpi](/u/picpi) 佬出了在线 [picpi皮皮工艺站](https://linux.do/t/topic/2854658)，可以方便的分享啦。但对于第一次接触sub2api的用户可能还是一脸懵逼，账号、分组、订阅、代理、密钥，这些都是什么呀？他们之间是什么关系？我第一步应该做什么？

那么，今天就用小白的视角，讲一讲这些基本概念和使用方法。

## 一、picpi是什么

picpi 是一个基于 sub2api 等组件搭建的共享 API 中转服务：你把自己的 Claude/ChatGPT 订阅账号（Plus 号）导入进来，它帮你转换成 OpenAI/Anthropic 兼容格式的 API，供各种客户端（思源笔记、Claude Code、Cherry Studio、Lobe 等）调用。

**调用链路：**  你的客户端 → picpi（sub2api）→ 你自己的 Claude/OpenAI 账号

## 二、核心概念（先弄懂这5个）

| 概念 | 作用 |

| --- | --- |

| **账号** | 就是你导入的 Plus 号（OAuth 或 json 配置），是你的算力来源 |

| **分组** | 账号的容器。一个分组 = 一个号池，请求会在组内账号间自动调度、故障切换 |

| **订阅** | 你对某个分组的使用权。picpi中自己建的分组会自动有订阅（即把用户和分组绑定） |

| **API 密钥** | 客户端调用时用的 `sk-xxx`，每个密钥绑定一个分组 |

| **代理** | 为账号提供访问上游平台的网络出口/IP（即从哪里访问账号） |

**关系：**  账号加入分组 → 用户获得该分组的使用权限（订阅）→ 创建绑定该分组的 API 密钥 → 客户端使用密钥调用

一个简单的比喻：

- **账号**：干活的人

- **分组**：人员所在的工作组

- **订阅**：进入这个工作组下单的资格

- **API 密钥**：客户端使用的门禁卡，上面标明进入哪个工作组

- **代理**：干活的人前往上游平台时使用的网络线路

另一个视角：

资源关系：账号 → 加入分组



权限关系：用户 → 持有分组（订阅）



调用关系：API 密钥 → 绑定分组



网络关系：账号 → 绑定代理 → 连接上游

## 三、完整请求链路

这样你可能还不太明白，那么就从你熟悉的 API 密钥开始，讲一下请求从客户端发出到结果返回的完整过程（注意以下是便于理解的简化流程，仅供参考）。

```
① 客户端
   │
   │ 携带 API 密钥 sk-xxx、模型名和对话内容
   ▼
② API 接口／网关
   │
   │ 校验密钥是否存在、启用、过期
   ▼
③ 系统读取 API 密钥绑定的分组
   │
   │ 确定请求需要进入哪个账号池
   ▼
④ 校验用户对该分组的订阅
   │
   │ 检查订阅是否有效、是否过期、额度是否充足
   ▼
⑤ 分组调度器选择账号
   │
   │ 根据平台、模型、状态、额度和负载
   │ 从组内挑选一个可用账号
   ▼
⑥ 被选中的上游账号
   │
   │ 读取该账号保存的 OAuth 凭据、JSON 认证配置或上游 API Key
   ▼
⑦ 账号绑定的网络代理（可选）
   │
   │ 决定通过哪个出口 IP 连接上游
   │ 不绑定则走服务器默认网络
   ▼
⑧ 上游模型平台
   │
   │ OpenAI / Anthropic / Grok 等处理请求
   ▼
⑨ 上游返回模型结果
   │
   │ 流式数据或一次性 JSON
   ▼
⑩ 中转系统接收并转换
   │
   │ 转换为客户端兼容的 API 格式
   │ 记录请求和 Token 用量；如订阅设置了配额，则扣减相应配额；同时更新上游账号的用量窗口和可调度状态
   ▼
⑪ API 网关把结果返回
   ▼
⑫ 客户端收到模型回复
```

## 四、picpi配置流程

理论讲完了，下面开始实战环节。

其实一点都不难，核心三大步，**创建分组 → 创建账号 → 创建密钥**。

### 第 1 步：创建分组（我的分组）

1. 左侧菜单 →「我的分组」→「创建分组」

2. 填写：



**名称**：随意，如 `claude_1`

**平台**：选 `Anthropic`（Claude 号）或 `OpenAI`（ChatGPT 号）。**创建后不可改**

**计费类型**：选「订阅（配额）」。**创建后不可改**

其他（费率倍数、RPM、限额）保持默认即可

3. 一般一个平台一个分组。Claude 和 OpenAI 账号不能混在一个分组里。如果你想把多个平台账号放到一个分组中，这里平台选Composite即可。

### 第 2 步：添加账号（我的账号）

1. 左侧菜单 →「我的账号」→「添加账号」

2. 选择平台（Anthropic / OpenAI）和认证方式：



**OAuth**：跳转官方登录授权

**导入 json**：你的账号配置文件。注意：**必须是 sub2api 格式**，其他格式（cpa 等）需先转换，站长给的转换工具：`https://cvt.okcode.cc.cd/`。支持批量导入

**API Key**：也可以通过api key的方式提供。

3. **选择代理**：可选。可以用公开代理（如"美国纯净家宽1/2/3"），也可以在「我的代理」里添加自己的机场节点（支持常见机场订阅，内置 sing-box）



公开代理人多共用 IP，账号有一定封号风险；重要账号建议用自己的代理

4. 把账号**勾选加入你创建的分组**（编辑账号弹窗底部的"分组"处勾选）

5. 添加后确认账号状态为「正常」、「调度已开启」

- 注意：使用第三方中转都有一定的风控风险，不建议把你重要的账号通过第三方代理。

### 第 3 步：创建 API 密钥（API 密钥页）

1. 左侧菜单 →「API 密钥」→「创建密钥」

2. 选择绑定的**分组**（如 claude_1）

3. 得到 `sk-xxxxxx`，点复制保存好

**注意：这里通过账号选择分组、密钥绑定分组实现了分组和账号、密钥和分组之间的关联。**

### 第 4 步：在客户端配置

**接入端点**（任选一个，按网络情况）：

| 端点 | 说明 |

| --- | --- |

| `https://s2api.top` | 海底光缆直连(推荐) |

| `https://api.s2api.top` | Cloudflare |

| `https://cn2.s2api.top` | 香港CDN(三线优化) |

每个端点旁有「测速」链接，可以先测哪个快。

**客户端填写：**

- API 地址（Base URL）：如 `https://s2api.top`（OpenAI 格式接口是 `/v1/chat/completions`，有的客户端要填到 `/v1`）

- API Key：你的 `sk-xxx`

- 模型名：先请求 `/v1/models` 查看可用列表，或用分组里账号实际支持的模型（如 `claude-fable-5`、`claude-sonnet-4-8` 等）

**注意**：密钥右侧有「使用密钥」按钮，可查看不同的客户端的使用教程。

## 五、其他功能

- **使用记录**：排查请求错误、模型、Token 和消费；

- **分配订阅**：把自己分组的使用权授权给其他 picpi 用户；

- **兑换码**：批量发放订阅权益；

- **我的订阅**：查看自己拥有的分组使用权；

- **我的代理**：测试和管理上游网络出口。

### 如何强行挤进经常错误的站

我添加了账号，明明账号正常，测试也可以用，但是却显示 `424 Failed Dependency: Service temporarily unavailable` 那是因为sub2api请求了一次账号，却收到了上游的 5xx 响应，判断上游不可用，就不会继续尝试了。

[b94527e6ad711fdb84267fe0fa0de791806×101 3.79 KB](https://cdn3.ldstatic.com/original/4X/4/f/3/4f303969fb7fcf7596333efc64230bab555bfd7d.png)

设置为池模式，并且将上游的错误码设置为自动重试例如`502` `503`即可强行挤进，遇到这些错误不会切换账号，而是同账号重试。

[0a2e5f016685c6519508a634157e9cf51412×514 31.2 KB](https://cdn3.ldstatic.com/original/4X/8/2/9/8297222f1b1a3677dfdbe34ee7ff942fe33bfcbd.png)

要设置哪些上游错误自动重试取决于自己的需求，例如如下例子，上游出现了503之后的请求全部报424，说明sub2api判断这个上游不可用，但是也没有其他上游可切换。就可以考虑把这个渠道的503加入自动重试。
