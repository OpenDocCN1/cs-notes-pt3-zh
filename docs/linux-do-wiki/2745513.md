# Java开发教程8-异常处理



本期是Java开发教程系列的第八期,本期主要向各位介绍**异常处理**——程序出错时怎么优雅地应对,而不是直接崩溃.若你已经熟悉 `try`/`catch`/`finally` 和 `throw`,可以跳过本期内容.

**一、什么是异常**

程序运行时出错,Java 会"抛出"一个**异常**对象,如果没人接住,程序就会崩溃退出,控制台会打印一大段红色报错,这叫**堆栈跟踪**:

```
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 10 out of bounds for length 3
    at Main.main(Main.java:5)
```

读报错看三处:第一行的**异常类型**（`ArrayIndexOutOfBoundsException`）、**描述**（访问了下标 10,数组只有 3 个）、最后一行 `at ... (Main.java:5)`——出错的**文件名和行号**.以后报错先看这里,就不用俺寻思之力了.

---

**二、常见的异常**

| 异常 | 什么时候发生 |

| --- | --- |

| `NullPointerException` | 对 null 调方法/取字段,简称 NPE |

| `ArrayIndexOutOfBoundsException` | 数组下标越界 |

| `StringIndexOutOfBoundsException` | 字符串下标越界 |

| `FileNotFoundException` | 文件不存在 |

| `NumberFormatException` | 字符串转数字失败 |

---

**三、try/catch:接住异常**

不想让它崩,把可能出错的代码包进 `try`,用 `catch` 接住:

```
int[] nums = {1, 2, 3};

try {
    System.out.println(nums[10]);   // 这句会抛异常
    System.out.println("这行不会执行");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("数组越界了:" + e.getMessage());
}

System.out.println("程序继续运行,没崩");
```

- `try` 里一旦抛异常,**立刻跳到**对应的 `catch`,后面的代码不执行

- `catch` 括号里写要接的**异常类型**和变量名

- 可以写多个 `catch` 接不同类型的异常,但顺序要**从子类到父类**（先具体后宽泛）

- 可以接更宽泛的 `Exception`——它是所有异常的父类,一网打尽

---

**四、finally:不管怎样都会执行**

`finally` 块在 `try` 正常结束或 `catch` 接住之后,都会执行:

```
try {
    // 可能出错的代码
} catch (Exception e) {
    // 出错时的处理
} finally {
    // 无论成不成都执行:比如关文件、释放资源
}
```

---

**五、主动抛出:throw 和 throws**

有时我们自己发现"这个值不合法",主动扔一个异常:

```
public void setScore(double score) {
    if (score < 0 || score > 100) {
        throw new IllegalArgumentException("成绩必须在 0 到 100 之间");
    }
    this.score = score;
}
```

- `throw` + `new 异常对象` 主动抛

- 方法声明里用 `throws` 告诉调用者"这个方法可能抛异常":

```
public void loadConfig() throws IOException {
    // ...
}
```

- 被 `throws` 声明的异常,调用方要么 `try/catch`,要么继续 `throws` 往上甩——**总得有人接**

- 有些异常（`RuntimeException` 的子类,比如上面的 `IllegalArgumentException`、NPE）可以不声明也不用接,叫**运行时异常**;编译就逼你必须处理的叫**受检异常**,文件操作类的大多是受检异常

**六、小项目:读配置文件的工具**

写一个小工具,从文本文件读一行配置"玩家名=MyCodes",文件不存在或格式不对时给出友好提示而不是崩溃.

文件一 `Config.java`:

```
import java.util.Scanner;
import java.io.File;
import java.io.FileNotFoundException;

public class Config {
    private String playerName;

    // 从文件读取配置
    public void load(String filePath) throws FileNotFoundException {
        File file = new File(filePath);
        Scanner scanner = new Scanner(file);   // 文件不存在会抛 FileNotFoundException

        while (scanner.hasNextLine()) {
            String line = scanner.nextLine();
            if (line.startsWith("playerName=")) {          // 判断这一行是不是以 playerName= 开头
                playerName = line.substring("playerName=".length());   // 截掉前缀,留下值
            }
        }
        scanner.close();
    }

    public String getPlayerName() {
        return playerName;
    }
}
```

文件二 `Main.java`:

```
import java.io.FileNotFoundException;

public class Main {
    public static void main(String[] args) {
        Config config = new Config();
        try {
            config.load("config.txt");
            System.out.println("玩家名:" + config.getPlayerName());
        } catch (FileNotFoundException e) {
            System.out.println("找不到配置文件,请确认 config.txt 存在:" + e.getMessage());
        }
    }
}
```

配套的 `config.txt`(放在项目目录下):

```
playerName=MyCodes
```

运行结果:

```
玩家名:MyCodes
```

如果把 `config.txt` 删掉再运行:

```
找不到配置文件,请确认 config.txt 存在:config.txt (系统找不到指定的文件。)
```

（末尾那个句号是中文 Windows 系统自带的,不同系统提示语略有差异,不用纠结.）

这里用到了 `Scanner`——本节让它去读文件（下一期我们会再用 `Scanner` 读键盘输入,猜数字小游戏就靠它）.`startsWith` 判断字符串以什么开头、`substring(下标)` 截取从某下标开始的子串,都是 String 的方法,注释里解释了,下一期会系统讲 String.

**朝花夕拾:第 1 期的 String name; 是 null**

第 1 期我们写过:

```
String name;   // 只声明,不赋值
```

要分两种情况看 `name` 此时的状态:

- 如果 `name` 是**类的字段**（比如写在类里、方法外）,未赋值时默认值就是 `null`;

- 如果 `name` 是**方法里的局部变量**,未赋值时**编译都过不了**——Java 会拦住你"可能尚未初始化变量 name",根本到不了运行阶段.



`null` 就是"没有任何对象".对 `null` 调方法,就会得到本期讲的第一个异常——`NullPointerException`:

```
String name = null;
System.out.println(name.length());   // 抛 NullPointerException
```

新手最常见的崩溃就是它.以后看到 NPE,先找:哪个引用可能是 null?是不是忘了赋值?

**总结**

本期学会了让程序"优雅出错":

- **异常是对象**:出错时抛出,没人接就崩溃;读堆栈看类型、描述、行号

- **try/catch**:接住异常继续运行;多个 catch 从子类到父类

- **finally**:无论成不成都执行,用来释放资源

- **throw/throws**:主动抛出、声明可能抛出的异常,总得有人接

- 认识了 `Scanner` 读文件,`FileNotFoundException` 是怎么被处理的
