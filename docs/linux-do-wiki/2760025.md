# Java开发教程13-我的世界模组开发之入门介绍



本期是Java开发教程系列的第十三期,也是从"学 Java"到"写 Minecraft 模组"的**桥梁期**.本期不会教太多的新语法,而是把前 12 期学的知识第一次用到 Minecraft 上:搭好开发环境,跑起第一个模组.若你已经能独立创建一个模组项目并在游戏里看到自己的物品,或者对模组开发不感兴趣,可以跳过本期内容.

天外音:知道你们想看什么,直接拉到最后一页吧.

**每期叠甲**:



时间仓促,水平有限,文中难免存在缺点和错误,恳请广大开发者和从业者指正.

---

**一、先想清楚:模组到底是什么**

先摆正一个观念:

> 模组就是一个普通到不能再普通的 Java 程序,只不过运行在游戏内部,能使用游戏提供的 API(比如"往世界添加一个方块"“给玩家发一件物品”).你前 12 期学的类、对象、集合、文件读写,在模组里一个不落全用得上.

但本期的目标很小:

1. 选一个模组加载器(相当于"游戏的插件系统")

2. 把开发环境搭好

3. 让游戏里出现**你自己写的一个物品**



至于"物品怎么挖矿"“方块怎么做”“实体怎么写”,那些是模组 API 的具体内容,以后有机会再说.本期只要**能跑就行**,拿到正反馈.

---

**二、选型:NeoForge 还是 Fabric**

模组加载器是架在 Minecraft 和你的代码之间的桥梁,负责把你的 Java 代码加载进游戏.2026 年的主流有两个(lex和他的forge已经进历史的垃圾堆了):

| 加载器 | 特点 | 适合谁 |

| --- | --- | --- |

| **NeoForge** | 大模组生态丰富,老牌 Forge 的继任者,发布节奏稳重 | 想玩大型整合包、跟随经典模组生态 |

| **Fabric** | 轻量、简洁、API极度有限 | 新手入门、想做小而轻的模组、无法承担复杂模组功能 |

怎么选?给新手的建议:**先选 Fabric**.理由很简单——它结构清爽,概念少,一个 `onInitialize` 就能跑起来,最快拿到正反馈.而且两个加载器背后的 Java 知识完全一样,以后想转 NeoForge,学的是"新API",不是"新语言".本文示例一律用 Fabric.

> 小知识:不管哪个加载器,模组项目本质都是一个 **Gradle 项目**——Gradle 是 Java 界的构建工具,负责下载依赖、编译、打包.你在 IDEA 里点一下"运行",背后是 Gradle 在干活.

---

**三、环境准备**

三样东西,前两样你已经有了:

1. **JDK**(能走到本期,说明它早就装好并在服役了——从第 1 期写第一行代码起就需要它).模组要求 JDK 17 或 21,检查方法:命令行里 `java -version` 看版本号

2. **IDEA** 或其他 Java IDE

3. **Minecraft 本体**(Java 版).这个我们直接用开发环境的runClient吧,具体见接下来的mdk部署.

---

**四、创建第一个模组项目**

Fabric 官方提供了**模板生成器**(Mod Development Kit,简称 MDK),在浏览器打开官网的"模组模板"页面,填几个字段就能下载一个完整项目(Fabric入门简单,上限低,兼容性差):

1. 填**模组名**(自己起一个英文名,比如 `tutorialmod`)

2. 填**包名**(Java 包名,比如 `com.example.tutorialmod`)

3. 下载下来是一个 zip,解压后用 IDEA 打开(选"打开项目",指向文件夹即可)

4. 首次打开后 IDEA 会提示 Gradle 在后台下载依赖,**第一次下载可能要几分钟**,耐心等右下角进度条消失

5. 等待完成后,IDEA 右上角会出现两个运行配置:一个叫 `Minecraft Client`(启动游戏),一个叫 `Minecraft Server`(启动服务器).点客户端那个,稍等片刻——**游戏应该带着你的模组启动了**



如果这一步顺利,你已经在跑自己的模组了——哪怕它现在就是滚木.

> 卡在这一步很正常,九成的报错都发生在 Gradle 上,见第六节.

---

**五、第一个物品:让游戏里出现一颗红宝石**

现在写第一行模组代码.找到主类——模板生成器已经给你建好了,文件名类似 `Tutorialmod.java`,内容里有一个 `implements ModInitializer` 的类.我们在它上面加一个物品:

```
import net.minecraft.item.Item;
import net.minecraft.registry.Registries;
import net.minecraft.registry.Registry;
import net.minecraft.util.Identifier;
import net.fabricmc.api.ModInitializer;

public class Tutorialmod implements ModInitializer {
    // 创建一个物品对象,先不做任何特殊行为
    public static final Item RUBY = new Item(new Item.Settings());

    @Override
    public void onInitialize() {
        // 把物品注册进游戏,id 是 "tutorialmod:ruby"
        Registry.register(Registries.ITEM, Identifier.of("tutorialmod", "ruby"), RUBY);
    }
}
```

再给物品起个中文名.在 `src/main/resources/assets/tutorialmod/lang/` 下新建 `zh_cn.json`:

```
{
  "item.tutorialmod.ruby": "红宝石"
}
```

重新点运行.进游戏后用创造模式物品栏搜"红宝石"——应该能搜到它,拿在手里,出现在你的背包里.

`Registry.register(...)` 这行是模组开发最重要的动作:**注册**——告诉游戏"我这个物品存在了".以后学方块、学附魔,注册流程大同小异,都是"创建对象 → 注册 → 起名".

**六、常见问题**

**1. Gradle 下载卡住/超时.** 国内网络访问 Gradle 依赖仓库慢,换镜像:在项目里找到 `settings.gradle`,把仓库地址改成国内镜像(搜"阿里云 maven 镜像"按官方文档改).改完重开项目再等一次.

**2. 版本不匹配.** 模组加载器、Minecraft 版本、JDK 三者必须匹配:模板生成器生成的版本组合一定是对的,别乱改版本号.游戏本体版本和项目 `gradle.properties` 里的版本要一致.

**3. 运行配置没出现.** 等 Gradle 同步完(右下角进度条消失)再点右上角刷新按钮;还是不行就重启 IDEA.

**4. 找不到包/类名报红.** 模板不同年份略有差异,报红的地方看提示,大部分是"包路径和你的目录结构对不上",按 IDEA 提示的 Alt+Enter 导入即可.

---

另外埋一个坑:很多知名模组是用 **Kotlin** 写的(Fabric 官方就提供 Kotlin 支持).Kotlin 和 Java 同跑在 JVM 上,能互相调用.等 Java 熟练了,建议去翻翻本系列最后的"番外·Kotlin"——那里的结论是"看得懂就行,除了安卓开发别碰语法糖".

---

**总结**

本期不学新语法,算是夹带私货吧:

- 模组**就是 Java 程序**,只是运行在游戏里

- 加载器选型:**NeoForge**(生态大)与 **Fabric**(轻量,新手首选)

- 环境:JDK + IDEA + 游戏本体,模板生成器建项目

- 第一个模组:注册一个**红宝石物品**,游戏里能看到

- 常见坑:Gradle 换镜像、版本匹配、等同步
