# Java开发教程14-泛型与类型擦除



本期是Java开发教程系列的第十四期,本期要介绍泛型,它从第 1 期 `List<String>` 一路陪我们走到现在,但你只见过它的表面.本期讲泛型方法、上下界、通配符,以及"泛型到底去哪了".若你已经精通泛型与类型擦除,可以跳过本期内容.

**一、回顾:我们早就用上泛型了**

第 1 期写 `List<String>`、第 10 期写 `Comparable<Student>`,括号里那个类型就是泛型——它的作用是:**给一个类或方法标上"我是为哪种类型服务的"**.

泛型解决什么问题?举个例子,没有泛型时,装任意对象的列表长这样:

```
List list = new ArrayList();        // 不写类型,什么都敢往里装
list.add("sword");
list.add(42);                        // 数字也能塞进去
String s = (String) list.get(1);     // 取的时候要强转,运行期才报错!
```

(这种不带类型参数的写法叫**原始类型(raw type)**,IDE 会在 `List` 上画黄线警告.它存在只是为了兼容老代码,但不利于维护.)

写了泛型后:

```
List<String> list = new ArrayList<>();
list.add("sword");
list.add(42);                        // 编译直接报错,根本放不进去
String s = list.get(1);              // 不用强转,类型安全
```

一句话:**泛型把错误从运行期提前到了编译期**,顺便省掉一大堆强转.这是它存在的全部意义.

---

**二、泛型方法**

不只类可以有泛型,方法也可以.在方法上声明类型参数,方法就能接受"任意类型的参数":

```
public class BoxUtil {

    // <T> 写在返回值前面,表示"这个方法有一个类型参数 T"
    public static <T> void swap(List<T> list, int i, int j) {
        T temp = list.get(i);
        list.set(i, list.get(j));
        list.set(j, temp);
    }
}
```

调用时,类型由参数**自动推断**,不用写出来:

```
List<String> names = new ArrayList<>();
names.add("小明");
names.add("小红");
BoxUtil.swap(names, 0, 1);      // 现在是小红、小明
```

注意 `swap` 在 `List<Integer>` 上同样能用——同一个方法,服务所有类型.这就是"通用"的含义:用类型参数**占位**,谁调用就变成谁.

---

**三、上界:约束 T 必须"是某种类型或它的子类"**

有的方法不是任何类型都能处理的.比如"求最大值",必须保证类型可以比较大小:

```
public static <T extends Comparable<T>> T max(List<T> list) {
    T best = list.get(0);
    for (T item : list) {
        if (item.compareTo(best) > 0) {   // item 能调用 compareTo,因为 T 被限制了
            best = item;
        }
    }
    return best;
}
```

`<T extends Comparable<T>>` 读作:“T 必须是实现了 Comparable 接口的类型”.这样一来:

- `max(List<Integer>)` 合法——`Integer` 实现了 `Comparable`

- `max(List<Random>)` 编译报错——`Random` 没实现 `Comparable`,没法比大小



`extends` 在这里的语义是"是……的子类或实现者".它是**上界**:T 最多高到 `Comparable`,不能是随便什么类型.求最大值就用它,和传参时"要求一个 Comparable 对象"是同一个道理,只是对象换成了类型.

---

**四、通配符 ?:不关心具体是什么类型**

有时候我们不需要知道类型,只要"这个列表里的东西一定可以读出来".用问号:

```
// 打印任意类型的列表——不关心里面是 String 还是 Integer
public static void printAll(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}
```

`List<?>` 叫"通配符列表".注意一个限制:**只能读,不能写**——编译器不知道里面装的是什么类型,`list.add(...)` 一律拒绝(万一是 String 列表,你往里塞 Integer 怎么办?).

但"只读"还不够,有时还要求"读出来的一定是某种类型的子类".此时给通配符加上界:

```
// 求和:里面的东西至少是个 Number(整数、小数都算)
public static double sumAll(List<? extends Number> list) {
    double sum = 0;
    for (Number n : list) {
        sum += n.doubleValue();
    }
    return sum;
}

/** 语法小补充:Arrays.asList(...) 是"把一串元素变成 List"的工具方法(JDK 的 Arrays 工具类,
*   第 32 期讲适配器时再说吧).这里用它快速造测试用的列表.
*/
sumAll(Arrays.asList(1, 2, 3));        // 传 List<Integer>
sumAll(Arrays.asList(1.5, 2.5));       // 传 List<Double>
sumAll(Arrays.asList("a", "b"));       // 编译报错:String 不是 Number
```

对称地还有下界 `List<? super Integer>`:“装 Integer 或它的父类的列表”——这种列表你可以往里写 Integer(它最差也是个 `List<Object>`,写 Integer 完全安全),但读出来只能当 `Object` 用.

记不住没关系,只要记住一个使用习惯:**只读数据,写 ? extends;只写数据,写 ? super;两种都做,就老老实实写具体类型参数**.工作中九成的 `?` 都是 `? extends`.

> 泛型方法(上界 `T extends`)和通配符(上界 `? extends`)的区别:方法关心的是"这个 T 全程是一种类型"——比如 `max` 里要把第一个元素存进变量 `best`,就必须是同一个 `T`;通配符只关心"这个列表里是某种未知类型的子类",不打算把它存来存去.写代码时先问自己:我要不要"拿着这个类型到处用"?要,就用泛型方法;只是读一遍,就用通配符.

**五、类型擦除:泛型只在编译期存在**

这里有个新手最容易困惑的问题:泛型信息到运行期还剩吗?答案很可惜:**不剩**.

Java 的泛型是"编译期检查,运行期删除",这叫**类型擦除**.你的代码写 `List<String>`,编译成字节码后,`String` 被擦掉了,运行期看到的只是一个普通的 `List`(里面装着 `Object`).编译器在**编译时**用泛型信息做检查,再在**用到的地方自动插上强转**.

看一段能说明问题的代码:

```
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());   // true!
```

两个完全不同类型的列表,class 却相同——因为运行期它们都是 `ArrayList`,泛型信息已不存在.`getClass()` 拿不到泛型,`instanceof List<String>` 这种写法也是语法错误,道理相同:擦除后没有 `List<String>` 这个类型存在.

擦除带来三条硬性限制,记住即可:

1. **不能 new T()** ——运行期不知道 T 是谁,没法构造

2. **不能建泛型数组** `new T[10]` ——数组在运行期要检查元素类型,擦除后检查不了

3. **静态方法/静态字段不能引用类的类型参数** ——类被实例化成什么类型,和静态成员无关,静态成员属于类本身



这三条撞上了都不必慌,解法通常绕一下:用 `List<T>` 代替 `T[]`,给方法传一个 `Class<T>` 参数用反射创建对象.知道"为什么不能"比背写法更重要.

**六、源码:Collections.sort 的签名,一个字母一个字母拆**

第 10 期我们用了 `Collections.sort(list)`,当时只当是"内置方法".现在揭开它的真面目,它的签名是 Java 里最著名的泛型签名之一:

```
public static <T extends Comparable<? super T>> void sort(List<T> list)
```

别被吓到,从左往右拆,就三段:

1. `<T extends Comparable<...>>`:**T 必须能比较**(这是泛型方法的上界,第三节)

2. `Comparable<? super T>`:**T 的父类实现了 Comparable**.意思是"T 自己没实现 Comparable 也行,只要它的某个父类实现了".这保证了 `Student` 的父类有排序能力时,子类也能直接排

3. `List<T>`:要排的列表



为什么设计得这么绕?为了**尽量包容**:一个类继承自"已实现排序的父类"时,子类不必再实现一遍 `Comparable`,直接能用 `sort`.你看,签名里的每个 `extends`、`super` 都是在"放宽条件,让更多类型能用".这是阅读任何泛型源码的心法,也是让你的代码能跑的好办法.

**七、小项目:通用工具类**

把本期知识串成一个小工具类,两个通用方法:

文件 `GenericUtils.java`:

```
import java.util.List;

public class GenericUtils {

    // 通用交换:任意类型列表的两个位置互换
    public static <T> void swap(List<T> list, int i, int j) {
        T temp = list.get(i);
        list.set(i, list.get(j));
        list.set(j, temp);
    }

    // 求最大值:要求元素可以比较
    public static <T extends Comparable<T>> T max(List<T> list) {
        T best = list.get(0);
        for (T item : list) {
            if (item.compareTo(best) > 0) {
                best = item;
            }
        }
        return best;
    }
}
```

文件 `Main.java`:

```
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        // 字符串列表:交换
        List<String> names = new ArrayList<>();
        names.add("小明");
        names.add("小红");
        names.add("小刚");
        GenericUtils.swap(names, 0, 2);
        System.out.println(names);            // [小刚, 小红, 小明]

        // 数字列表:求最大值(自动推断出 T 是 Integer)
        List<Integer> scores = new ArrayList<>();
        scores.add(92);
        scores.add(58);
        scores.add(76);
        System.out.println(GenericUtils.max(scores));   // 92

        // 第 10 期的 Student 也能用!(它实现了 Comparable)
        // List<Student> students = ...;
        // System.out.println(GenericUtils.max(students));
    }
}
```

动手试试:把 `swap` 用在 `List<Integer>` 上;再让 `max` 接收一个"没实现 Comparable 的类",看看编译器报什么错,感受一下"上界"在起作用.

**朝花夕拾:第 10 期那个"不能改的类"**

## 第 10 期我们遇到一个场景:某个类不是自己写的、不能改,又要给它排序——于是单独写了个 `Comparator`.今天学完 `? super T` 再回头看,`Collections.sort(list, comparator)` 的完整签名里同样有 `Comparator<? super T>`:它接受"能比较 T 或 T 的父类"的比较器,为的正是"别人的类也能排".

**总结**

本期填坑泛型:

- **泛型的作用**:编译期检查 + 免强转,错误提前暴露

- **泛型方法**:`<T>` 写在方法上,一个方法服务所有类型

- **上界**:`T extends Comparable<T>`,约束"必须是可比较的类型"

- **通配符**:`?` 只读;`? extends` 只读且限定范围;`? super` 只写

- **类型擦除**:泛型只在编译期存在,运行期删光;由此不能 `new T()`、不能泛型数组

- **源码**:`Collections.sort` 的签名逐段拆解

- 通用工具类:`swap` + `max` 小项目
