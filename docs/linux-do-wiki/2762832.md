# Java开发教程15-Lambda表达式



本期是Java开发教程系列的第十五期,本期介绍 **Lambda 表达式**——一种把"一小段行为"当作值传来传去的奇妙写法.它写起来极其简洁,是后面 Stream 流(下一期)的地基.若你已经熟练使用 Lambda 和四大函数式接口,可以跳过本期内容.

**一、痛点回顾:传"行为"为什么这么啰嗦**

第 10 期我们遇到一件事:给 `Student` 列表排序,但不想改 `Student` 类,于是写了一个单独的类:

```
public class NameComparator implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        return a.name.compareTo(b.name);
    }
}
```

然后 `Collections.sort(list, new NameComparator())`.七行代码,其实核心就一行:`a.name.compareTo(b.name)`.

如果不想新建一个类文件,可以用**匿名类**(不给名字、就地定义的类):

```
Collections.sort(list, new Comparator<Student>() {
    @Override
    public int compare(Student a, Student b) {
        return a.name.compareTo(b.name);
    }
});
```

还是啰嗦.细看会发现:**Comparator 接口只要求实现一个方法**,其他全是包装.而 Lambda 干的事,就是把这层包装剥掉,只留那一行核心.

---

**二、函数式接口:只有一个抽象方法的接口**

能使用 Lambda 的前提:接口里**只有一个抽象方法**.这样的接口叫**函数式接口**.比如:

- `Comparator<T>`:只有一个 `compare(a, b)`

- `Runnable`:只有一个 `run()`



可以在接口上标注 `@FunctionalInterface`,让编译器帮我们检查"是不是只有一个抽象方法"——多写一个抽象方法就报错:

```
@FunctionalInterface
interface SayHello {
    void say(String name);      // 唯一的抽象方法
}
```

为什么必须只有**一个**?因为 Lambda 是"**给这个接口的唯一方法提供实现**"——方法多了,编译器不知道你在实现谁.想写多个方法,要么设成默认方法(带方法体的那种),要么另写一个接口.

---

**三、Lambda 语法:三句话学会**

Lambda 的格式:**(参数列表) → 方法体**.箭头左边是参数,右边是干什么:

```
// 完整写法
Collections.sort(list, (Student a, Student b) -> {
    return a.name.compareTo(b.name);
});

// 省掉参数类型(编译器能从上下文推断)
Collections.sort(list, (a, b) -> {
    return a.name.compareTo(b.name);
});

// 方法体只有一条语句时,省掉大括号和 return
Collections.sort(list, (a, b) -> a.name.compareTo(b.name));
```

三条省略规则:

1. **参数类型可以省**——上下文知道接口方法的参数类型,没必要重复

2. **只有一个参数时,括号也能省**:`name -> System.out.println(name)`

3. **方法体只有一条语句时,大括号和 return 都能省**——这条语句的值就是返回值



三条规则全是"删掉不必要的东西",从完整写法一路删到最简,就是 Lambda 的全部.

> 注意区别:`(a, b) -> a.name.compareTo(b.name)` 没有写 return,但 Java 知道"这条表达式的结果就是返回值";而 `(a, b) -> { a.doIt(); b.doIt(); }` 有花括号,表示执行多条语句,没有返回值.有没有花括号,含义完全不同.

---

**四、四大内置函数式接口**

JDK 为最常见的四种"行为"准备好了函数式接口,写代码时直接复用,不用自己定义:

!?强强?!

| 接口 | 抽象方法 | 参数 → 返回 | 场景 |

| --- | --- | --- | --- |

| `Consumer<T>` | `accept(T)` | 进一个,什么都不回 | 遍历时做一件事 |

| `Function<T, R>` | `apply(T)` | 进一个,出一个 | 转换:类型 A 变类型 B |

| `Predicate<T>` | `test(T)` | 进一个,出 boolean | 判断真假,用于过滤 |

| `Supplier<T>` | `get()` | 什么都不进,出一个 | 生产/提供一个值 |

各配一个例子:

```
import java.util.function.Consumer;
import java.util.function.Function;
import java.util.function.Predicate;
import java.util.function.Supplier;

Consumer<String> print = s -> System.out.println("玩家: " + s);
print.accept("小明");

Function<Integer, String> toText = n -> "第 " + n + " 名";
System.out.println(toText.apply(3));              // 第 3 名

Predicate<Integer> pass = score -> score >= 60;
System.out.println(pass.test(58));                // false

Supplier<Integer> dice = () -> 1 + new java.util.Random().nextInt(6);
System.out.println("掷出 " + dice.get());          // 每次 1~6
```

记忆方法:名字本身已经说明一切——**Consumer** 消费掉、**Function** 做函数转换、**Predicate** 做判断、**Supplier** 供货.后面学 Stream(第 16 期)时,`filter` 收 `Predicate`、`map` 收 `Function`、`forEach` 收 `Consumer`,直接对号入座.

**五、Lambda 里的变量:为什么不能修改外部变量**

Lambda 内部可以使用方法里的局部变量,但有个限制——**这个变量必须是"有效 final"**:声明后不再被赋值.也就是说:

```
int times = 3;
Runnable r = () -> System.out.println("次数: " + times);   // 合法,times 没再被改
times = 4;                                                  // 非法!改了就编译报错
```

为什么这么苛刻?想一个场景:`r` 可能在**别的线程**里执行,也可能在**这个方法返回之后**才执行——那时候 `times` 早就没了.所以 Java 的做法是:**把变量的值拷贝一份,交给 Lambda 使用**.既然用的一直是那份拷贝,那么拷贝之后原始变量再被改,拷贝也不会跟着变,这种行为会把人绕晕,所以 Java 干脆禁止:“用过它的 Lambda,它就不能再被赋值.”

这不算缺陷,而是**保护**——你不需要担心 Lambda 运行时刻意改了什么外面的值,它看到的永远是你写 Lambda 那瞬间的值.

**六、小项目:一行排序**

回到第 10 期的排行榜.那时我们写了两个文件(Student + NameComparator),今天用 Lambda 收敛成一个文件、两三行:

文件 `Main.java`:

```
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Student> list = new ArrayList<>();
        list.add(new Student("小明", 92));
        list.add(new Student("小红", 58));
        list.add(new Student("小刚", 76));

        // 按成绩从高到低:一行排序,再看一眼升序与降序的区别
        list.sort((a, b) -> Double.compare(b.score, a.score));

        // 换成按姓名排序,只改一行:
        // list.sort((a, b) -> a.name.compareTo(b.name));

        for (Student s : list) {
            System.out.println(s.name + " " + s.score);
        }
    }
}
```

`Student` 类(和之前一样):

```
public class Student {
    public String name;
    public double score;

    public Student(String name, double score) {
        this.name = name;
        this.score = score;
    }
}
```

注意这里用了 `Double.compare(b.score, a.score)` 而不是 `b.score - a.score`——两个 `double` 相减当比较结果,在值相差很小或特殊值(比如分数是 NaN)时会出错,`Double.compare` 是标准做法.排序规则以后统一用它.

跑出结果后,把 `list.sort` 那行换成姓名版,再跑一次,体会"改一个参数就换一套规则"——这就是 Lambda 带给排序的灵活性.

**朝花夕拾:从七个文件到一行**

第 10 期我们为"按姓名排"单独开了一个 `NameComparator.java`;今天同样的需求,一行 `(a, b) -> a.name.compareTo(b.name)` 完事.中间经历的过程,恰恰是 Java 代码进化的缩影:类 → 匿名类 → Lambda.不是说类没用——`NameComparator` 那种**要反复复用**的比较器,写成类仍然是正确选择;Lambda 擅长的是"只在这一处用一次的小行为".用哪个,看这个行为要被用多少次.

---

**总结**

本期学会了用最简方式传"行为":

- **函数式接口**:只有一个抽象方法的接口,标注 `@FunctionalInterface` 防呆

- **Lambda 语法**:`(参数) -> 行为`,三条省略规则(省类型/省括号/省大括号)

- **四大内置接口**:`Consumer`/`Function`/`Predicate`/`Supplier`,按"进出"记忆

- **变量捕获**:Lambda 用的是变量的拷贝,所以外部变量必须"有效 final"

- 一行排序小项目:`list.sort((a, b) -> ...)` 换规则只改一行

下一期我们学习 **Stream 流**——集合的处理将进入"一行链式调用"时代,而它的核心参数,正是本期这四大接口.
