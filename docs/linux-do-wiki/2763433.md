# Java开发教程16-Stream流



本期是Java开发教程系列的第十六期,本期介绍 **Stream 流**——把"对集合做一连串处理"写成一条链的写法.它是 Java 处理数据最实用的方式之一,和第 15 期的 Lambda 是黄金搭档.若你已经熟练使用 Stream 的常用操作,可以跳过本期内容.

**一、痛点回顾:传统写法太啰嗦**

假设要给一份成绩单做三件事:只留及格的、按成绩降序、取前 3 名输出.不用 Stream 的写法:

```
List<Student> list = ...;

// 1. 过滤出及格的
List<Student> passed = new ArrayList<>();
for (Student s : list) {
    if (s.score >= 60) passed.add(s);
}

// 2. 排序
passed.sort((a, b) -> Double.compare(b.score, a.score));

// 3. 取前 3 名
for (int i = 0; i < 3 && i < passed.size(); i++) {
    System.out.println(passed.get(i).name);
}
```

到处是临时列表、循环、变量.人读代码要来回跳:"这个 passed 是谁?哦,是过滤结果……"Stream 的写法是这样:

```
list.stream()
    .filter(s -> s.score >= 60)                 // 只留及格的
    .sorted((a, b) -> Double.compare(b.score, a.score))   // 降序
    .limit(3)                                    // 取前 3 个
    .forEach(s -> System.out.println(s.name));   // 逐个输出
```

每行一个步骤,像流水线一样往下流.这就是 Stream 的卖点:**数据像在一条管道里流动,每经过一个环节被处理一次**.

---

**二、认识管道:创建 → 中间操作 → 终止操作**

任何 Stream 用法都是三段式:

```
集合.stream()          // 1. 创建:数据进管道
    .filter(...)       // 2. 中间操作:可连无数个,只做"登记"
    .sorted(...)
    .limit(...)
    .forEach(...);     // 3. 终止操作:管道真正开跑
```

关键规则:中间操作(如 `filter`/`map`)返回的还是 Stream,所以能一直 `.` 下去;**终止操作**(如 `forEach`/`collect`/`count`)返回最终结果,链到此为止.记不住哪些是终止操作?看返回类型——返回 `Stream` 的是中间操作,返回其他东西(或 void)的是终止操作.

**创建流的三种方式**:

```
// 1. 集合都有 stream()
list.stream();

// 2. 数组用 Arrays.stream
int[] nums = {3, 1, 2};
Arrays.stream(nums);

// 3. 零散的值用 Stream.of
Stream.of("a", "b", "c");
```

---

**三、中间操作:filter / map / sorted / distinct / limit / skip**

`filter` 过滤(参数是第 15 期的 `Predicate`——判断每个元素留不留):

```
list.stream().filter(s -> s.score >= 60);     // 留下成绩及格的
```

`map` 转换(参数是 `Function`——每个元素变一个样):

```
list.stream().map(s -> s.name);    // Student 流 → 姓名流
```

`sorted` 排序(和 `Collections.sort` 同一套规则,升序可以不给参数):

```
list.stream().sorted();                                    // 自然序(元素要能比较)
list.stream().sorted((a, b) -> Double.compare(b.score, a.score));  // 自定义规则
```

`distinct` 去重、`limit(n)` 取前 n 个、`skip(n)` 跳过前 n 个:

```
list.stream().map(s -> s.name).distinct();   // 去重,比如两个同名学生只留一个
list.stream().skip(1).limit(3);              // 跳过第 1 个,再取 3 个
```

**四个常用操作会了,链式组合就是自由发挥**.比如"全班前两名以外,各分数段去重后取 5 个"——每个需求都是这些零件拼装.

---

**四、终止操作:collect 与其他**

**collect 是万能的**,把流收成各种容器:

```
import java.util.stream.Collectors;

// 收成 List
List<String> names = list.stream()
        .map(s -> s.name)
        .collect(Collectors.toList());

// 收成 Set(顺带去重)
Set<String> nameSet = list.stream()
        .map(s -> s.name)
        .collect(Collectors.toSet());

// 收成 Map:键是名字,值是成绩
Map<String, Double> scoreMap = list.stream()
        .collect(Collectors.toMap(s -> s.name, s -> s.score));

// 分组:按是否及格分成两组
Map<Boolean, List<Student>> groups = list.stream()
        .collect(Collectors.groupingBy(s -> s.score >= 60));

// 拼成字符串
String joined = list.stream()
        .map(s -> s.name)
        .collect(Collectors.joining(", "));   // 小明, 小红, 小刚
```

**joining 底层是谁?StringJoiner。** `StringJoiner`(JDK 8 加入)是个小类,专干"用分隔符把一串元素拼成一个大字符串"——`joining` 的返回值就是 `StringJoiner` 然后 `toString` 出来的.它直接用的场景:要一边循环一边 `add`、或者要前缀后缀:

```
import java.util.StringJoiner;

StringJoiner sj = new StringJoiner(", ");     // 分隔符
sj.add("小明").add("小红").add("小刚");
System.out.println(sj);                       // 小明, 小红, 小刚

StringJoiner sj2 = new StringJoiner(", ", "[", "]");
sj2.add("小明").add("小红");
System.out.println(sj2);                      // [小明, 小红]
```

不经过 Stream、只想把数组/列表拼起来的场景,`joining` 用不上,用 `String.join`——底层同样是 StringJoiner,一行搞定:

```
String[] names = {"小明", "小红", "小刚"};
String result = String.join(", ", names);     // 小明, 小红, 小刚
```

关系是这样滴:**String.join 和 Collectors.joining 底层都是 StringJoiner,而 StringJoiner 内部就是一个加了分隔符规则和前后缀的 StringBuilder**(第 9 期那个).拼装逻辑一模一样,只是套了层壳——所以不用背新东西.

其他常用终止操作:

```
list.stream().count();                                  // 数量
list.stream().forEach(s -> System.out.println(s.name)); // 逐个处理(等价 for 循环)
list.stream().mapToDouble(s -> s.score).max();          // 最高分(OptionalDouble 包装,第 17 期讲)
// 累加求和:对象流没有"给个初值、逐个加"的双参 reduce;标准做法是先 mapToDouble 再 sum(下面这行)
list.stream().mapToDouble(s -> s.score).sum();          // 累加和
// 若非要用 reduce 写累加,对象流必须用三参重载,给上 combiner(初值、累加器、合并器):
list.stream().reduce(0.0, (sum, s) -> sum + s.score, Double::sum);
```

`groupingBy` 是最容易让新手眼前一亮的:以前"按某字段分组"要写循环 + Map,现在一行.看到它的返回值 `Map<Boolean, List<Student>>` 就能理解:分组依据的类型是键,分出的组是值.

**五、惰性求值:中间操作其实没执行**

前面说中间操作只做"登记"——这句话是真的,而且背后有讲究.看 `Stream` 接口源码里 `filter` 的声明:

```
Stream<T> filter(Predicate<? super T> predicate);
```

它返回一个 Stream.但**调用它时,数据一个都没动**:只是把"过滤这个行为"记在流水线上.直到碰上终止操作,流水线才整体开跑,数据按顺序流过每个环节.

这个设计叫**惰性求值**,好处是:

1. `limit(3)` 配合大集合时,管道可以**边取边停**——取满 3 个就提前收工,不用等全部过滤完

2. 中间操作连得再多,数据也只**遍历一遍**,不会"过滤一遍、排序一遍、再遍历一遍"



做个验证:在 `filter` 的 Lambda 里打一行日志,你会发现日志是**在终止操作那一刻**才打印的:

```
list.stream()
    .filter(s -> { System.out.println("过滤了 " + s.name); return s.score >= 60; })
    .forEach(s -> System.out.println(s.name));
// 运行后会发现:"过滤了"和输出交错出现,而不是先全部过滤再输出
```

> 这里把日志塞进 `filter` 只是为了观察惰性求值,**正式代码不要这么写**——`filter` 的语义是"判断留不留",不该掺副作用(打印、改状态)。真正要"边流边看"元素,用专门的中间操作 `peek`:`.peek(s -> System.out.println(s.name))`,它就是为观察而生的;不过 `peek` 主要用在调试,正式逻辑仍别依赖它的副作用。

**流的另一个特性:一次性**.流用完后不能重放,`stream.count()` 之后再 `stream.forEach(...)` 会报错——需要再遍历,就重新 `list.stream()` 一次.

**六、小项目:成绩单统计**

用 Stream 一行接一行,完成一个班的成绩统计:

文件 `Main.java`:

```
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

public class Main {
    public static void main(String[] args) {
        List<Student> list = new ArrayList<>();
        list.add(new Student("小明", 92));
        list.add(new Student("小红", 58));
        list.add(new Student("小刚", 76));
        list.add(new Student("小丽", 88));
        list.add(new Student("小强", 45));

        // 及格名单(按成绩降序)
        List<String> passed = list.stream()
                .filter(s -> s.score >= 60)
                .sorted((a, b) -> Double.compare(b.score, a.score))
                .map(s -> s.name)
                .collect(Collectors.toList());
        System.out.println("及格名单: " + passed);

        // 平均分(reduce 累加:0.0 起步,每次都把成绩累进 sum)
        double avg = list.stream()
                .mapToDouble(s -> s.score)
                .reduce(0.0, (sum, score) -> sum + score) / list.size();
        System.out.println("平均分: " + avg);

        // 按是否及格分组
        Map<Boolean, List<String>> groups = list.stream()
                .collect(Collectors.groupingBy(s -> s.score >= 60,
                        Collectors.mapping(s -> s.name, Collectors.toList())));
        System.out.println("及格组: " + groups.get(true));
        System.out.println("不及格组: " + groups.get(false));
    }
}
```

`Student` 类(同上一期):

```
public class Student {
    public String name;
    public double score;

    public Student(String name, double score) {
        this.name = name;
        this.score = score;
    }
}
```

运行结果:

```
及格名单: [小明, 小丽, 小刚]
平均分: 71.8
及格组: [小明, 小丽, 小刚]
不及格组: [小红, 小强]
```

动手改一改:把"及格线"改成 70;统计最高分;按分数段(60/70/80/90)分组——每一步都只动管道里的一环.

**朝花夕拾:第 10 期排行榜的进化**

第 10 期我们写排行榜:先 `Collections.sort`,再 `reverse`,再 `for` 取前 3 名——四步.今天一行:

```
list.stream().sorted((a, b) -> Double.compare(b.score, a.score)).limit(3)...
```

而第 15 期的四大函数式接口,今天也集体亮相了:`filter` 收 `Predicate`、`map` 收 `Function`、`forEach` 收 `Consumer`.一个 Stream 链,就是一次"四大接口 + 管道思想"的总复习.回头看 10 期喵,懒得炒冷饭了.

**总结**

本期学会了用管道处理集合:

- **三段式**:创建(`stream()`/`Arrays.stream`/`Stream.of`)→ 中间操作 → 终止操作

- **中间操作**:`filter` 过滤、`map` 转换、`sorted` 排序、`distinct`/`limit`/`skip`

- **终止操作**:`collect` 收容器(`toList`/`toMap`/`groupingBy`/`joining`)、`count`/`forEach`/`reduce`

- **惰性求值**:中间操作只登记,终止操作才开跑,数据只遍历一遍

- **流一次性**:用完不能重放

- **字符串拼接一家**:`joining`/`String.join` 底层都是 `StringJoiner`,StringJoiner 内部是加了分隔符的 StringBuilder
