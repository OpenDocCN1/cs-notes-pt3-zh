# Java开发教程18-线程



本期是Java开发教程系列的第十八期,本期正式进入**多线程**——让一个程序同时干好几件事.这是整个系列里第一个"思维方式要变"的话题:之前我们写的代码都是从上到下一行行执行,今天要开始同时跑.若你已经熟悉线程创建、`start`/`run`、`sleep`/`join`,可以跳过本期内容.

**一、先建立概念:一个程序,同时做好几件事**

到目前为止,我们写的所有程序都是**串行**的:一行一行往下跑,前面没跑完,后面永远轮不到.看这个例子:

```
// 下面这几行要放进某个方法里;Thread.sleep 会抛受检异常 InterruptedException,
// 必须像这样 try-catch(异常处理见第五节),或方法签名 throws InterruptedException
System.out.println("任务一完成");
try {
// 某项目vip为了显得更流畅就是这么干的
    Thread.sleep(3000);      // 假装任务二要 3 秒(异常为什么要这样拦,第五节细说)
} catch (InterruptedException e) {
    e.printStackTrace();
}
System.out.println("任务二完成");
```

总耗时约 3 秒,程序里只有一个"执行主线".而真实世界的程序(游戏、浏览器、服务器)显然不是这样:游戏边渲染画面边播放音乐边接收网络数据,浏览器边下载图片边滚动页面——这些都是**同时**在做的.

**线程(Thread)就是"程序里的一条执行线"**.一个程序默认有一条主线,叫 **main 线程**(就是 `main` 方法所在的那条线);我们可以在代码里**再开几条线**,让它们同时跑.多核 CPU 上,不同线程真的由不同核心同时执行;单核上则是"飞快地轮流干",人眼看来同样是"同时".

打个比方:一条流水线(单线程)和十位厨师各做各的菜(多线程)——后者整体更快,但也带来"抢锅台"的问题(这正是第 19 期要讲的线程安全).

**二、创建线程的两种方式**

**方式一:继承 Thread 类,重写 run 方法**

```
class CountTask extends Thread {
    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(getName() + " 数到 " + i);
        }
    }
}
```

**方式二:实现 Runnable 接口,把任务传给 Thread**

```
class CountTask implements Runnable {
    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + " 数到 " + i);
        }
    }
}
```

两种方式启动方法一样:

```
new CountTask().start();          // 方式一:直接 start
Thread t = new Thread(new CountTask());
t.start();                        // 方式二:Thread 包一层再 start
```

**推荐方式二(实现 Runnable)**.理由和第 6 期一脉相承:Java 类只能继承一个父类,你的任务类继承了 `Thread`,就**不能再继承别的类**了;而实现 `Runnable` 只是实现一个接口,任务类该怎么继承还怎么继承.另外方式二把"任务"和"线程"分开了:同一个任务对象,可以被多个线程执行.

---

**三、start() 与 run()** :



这是新手最容易踩的坑:`start()` 和 `run()`,谁才是"开线程"?

- `run()`:**就是一个普通方法调用**.直接 `t.run()`,还是在 main 线程里从上到下执行,线程根本没开

- `start()`:才**创建新线程**,由新线程去执行 `run` 里的代码



验证一下就知道了——在 run 里打印"当前线程是谁":

```
class WhoAmI implements Runnable {
    @Override
    public void run() {
        System.out.println("当前线程: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        Thread t = new Thread(new WhoAmI());
        t.run();       // 输出:当前线程: main     ← 没开新线程,还是主线程在跑
        t.start();     // 输出:当前线程: Thread-0   ← 新线程在跑!
    }
}
```

`Thread.start()` 的源码指向一个本地方法 `start0()`——它是 Java 调到底层操作系统创建线程的入口(Java 语言本身不直接管操作系统,这段由 JVM 用原生代码实现,我们记结论即可):`start` 一旦被调用,就会请求操作系统创建一个**真实的新线程**.

所以记住:**开线程永远写 start(),run() 只是任务代码本身**.写了 `start()` 却想不起它和 `run` 的区别,面试也常被问——答案就是上面这段.

**四、线程的几种状态(简版)**

线程活着的时候会换几次"身份",记住五个词:

```
新建(还没 start)
  ↓ start()
就绪(排队等 CPU)
  ↓ 抢到 CPU
运行(正在执行)
  ↑ ↓ sleep() / 等待某个条件
阻塞(暂停,比如睡 3 秒)
  ↓ 时间到 / 条件满足
(回到就绪,继续排队)
...最后 → 终止(run 跑完)
```

核心思想:**“运行"不等于"一直跑”**——线程会不断在"排队(就绪)“和"执行(运行)“之间切换,这是操作系统调度的结果,我们控制不了"谁先跑”,只能控制"什么时候让它停一停”.(JDK 官方的线程状态其实有六种:NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED,比上面的简版更细——比如"等待锁"是 BLOCKED、"join 等待"是 WAITING.

**五、sleep 与 join:让线程"睡"和"等"**

**sleep(毫秒):让当前线程睡一会儿,把 CPU 让出来**

```
Thread.sleep(1000);   // 当前线程睡 1 秒(要处理异常,见下)
```

注意两点:睡的单位是**毫秒**(1000 毫秒 = 1 秒);`sleep` 会让出 CPU,别的线程就有机会跑.`sleep` 会抛出 `InterruptedException`(被打断时抛出),所以要么 try-catch 要么方法声明 throws——IDE 会提示你补.

**join():等另一个线程跑完**

```
Thread worker = new Thread(() -> {
    for (int i = 1; i <= 3; i++) {
        System.out.println("下载中 " + i + "/3");
        try { Thread.sleep(500); } catch (InterruptedException e) { }
    }
});
worker.start();      // 启动子线程
worker.join();       // main 线程在这里等 worker 跑完,才继续往下走
System.out.println("下载完成,main 继续");   // 一定在"下载中 3/3"之后输出
```

没有 `join` 时,main 可能**先**打印"下载完成"——因为子线程和 main 各跑各的,顺序没人保证.这正是多线程与串行的本质区别:**顺序不确定**.想让"等它干完再继续",就 `join`.

**两种方式的时机选择**:子线程干活时 main 不想干等着 → 不 join,各干各的;main 的结果依赖子线程干完 → join.第 12 期那种"保存完再退出"的逻辑,在多线程版本里全靠 join 兜底.

**六、小项目:倒计时 + 多任务下载**

写两个小程序,体会"同时进行"和"等一等".

**项目一:后台倒计时**.启动一个子线程每秒报数,main 线程同时打印自己的进度:

```
public class Countdown {
    public static void main(String[] args) throws InterruptedException {
        Thread timer = new Thread(() -> {
            for (int i = 10; i >= 1; i--) {
                System.out.println("倒计时: " + i + " 秒");
                try { Thread.sleep(1000); } catch (InterruptedException e) { return; }
            }
            System.out.println("时间到!");
        });
        timer.start();

        // main 不干等,同步做自己的事:模拟"主线程忙碌"
        for (int i = 0; i < 5; i++) {
            System.out.println("main 线程处理中... " + i);
            Thread.sleep(600);
        }
        timer.join();   // 主线程的事干完,等倒计时结束再收尾
        System.out.println("程序结束");
    }
}
```

运行时会看到两边的输出**交错**出现——倒计时在数,main 也在干活,这就是"同时进行".

**项目二:多任务下载模拟**.三个任务并行下载,每个打印自己的进度:

```
public class Download {
    static class DownloadTask implements Runnable {
        private String name;
        private int seconds;

        DownloadTask(String name, int seconds) {
            this.name = name;
            this.seconds = seconds;
        }

        @Override
        public void run() {
            for (int i = 1; i <= seconds; i++) {
                System.out.println(name + " 下载中 " + i + "/" + seconds);
                try { Thread.sleep(500); } catch (InterruptedException e) { return; }
            }
            System.out.println(name + " 完成!");
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Thread a = new Thread(new DownloadTask("地图资源包", 3));
        Thread b = new Thread(new DownloadTask("音效包", 2));
        Thread c = new Thread(new DownloadTask("皮肤包", 4));

        a.start();
        b.start();
        c.start();

        a.join();
        b.join();
        c.join();
        System.out.println("全部下载完成");
    }
}
```

观察输出:三个包的进度**混着**打印——串行下载要 9 秒,并行只要 4 秒(最慢那个的时长).“总耗时 = 最慢的任务”,这是并行最直观的收益.

**朝花夕拾:第 1 期的循环,今天真的并行起来了**

第 1 期我们写 `for (int i = 0; i < 10; i++)` 时,循环体老老实实一次跑完才进入下一次.今天同一个 for,被放进了不同线程,两个循环**同时**在执行,输出互相穿插——语言没变,思维方式变了.

顺带呼应第 13 期:你玩的 Minecraft 里,渲染、音频、网络、存档各占一条线程,卡顿时"音频线程堵了""存档线程在写盘"都是真实的排查场景.而服务器(后期我们会亲手部署)更是线程大户——每个请求一条线程处理.线程,是所有大程序的骨架.

**总结**

本期打开了多线程的大门:

- **线程**:程序里的一条执行线,多线程 = 同时干多件事

- **两种创建**:继承 `Thread` / 实现 `Runnable`(推荐后者,不占继承名额)

- **start vs run**:`start` 才开线程,`run` 只是普通方法调用;`start` 底层是 `start0()` 请求操作系统建线程

- **状态简版**:新建 → 就绪 → 运行 → 阻塞 → 终止,谁先跑由调度决定

- **sleep / join**:睡一会儿让出 CPU;等另一个线程跑完

- 倒计时、多任务下载两个小项目
