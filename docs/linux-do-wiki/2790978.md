# Java开发教程20-Properties与配置文件



本期是Java开发教程系列的第二十期,本期介绍 **Properties 与配置文件**:把"会变的参数"从代码里拿出来,写进一个独立的文本文件,程序启动时读它.这样改个音量、换个服务器地址,不用改代码、不用重新编译.若你已经熟悉 `Properties` 的读写与编码套路,可以跳过本期内容.

**一、为什么要有配置文件**

回想我们写过的程序:第 12 期的成绩管理系统,存档文件名 `students.txt` 直接写在代码里;第 16 期的及格线 `60`,也写在代码里.这些"写着写着就冒出来的数字和字符串",有个名字叫**魔法值**——因为它们像魔法一样,只有代码知道它是什么.

问题在于:这些值**是会变的**.及格线改成 70 分?存档文件想换名字?改代码 → 重新编译 → 再打包,一条链路,只为改一个数.更麻烦的是,改了代码就等于改了"程序逻辑",万一改错了,整个程序都要重新验证.

配置文件的做法:**把会变的参数从代码里请出去,写进一个独立文件,程序启动时读它**.

```
# 成绩管理系统的配置
saveFile=students.txt
passLine=60
```

以后改及格线,只改这个文件,代码一行不动.这个思想叫**配置与代码分离**,是所有程序(从游戏到服务器)的通用做法:你玩 Minecraft,游戏设置、服务器地址、光影开关,全是配置.

**什么该进配置,什么不该?** 一条标准:这个值**会不会变**、变的时候**要不要动代码**.路径、端口、开关、阈值、显示文案 → 配置;算法、业务规则、类名 → 留在代码.配置文件里不放代码能做的事,代码里不放经常要改的值.

---

**二、Properties 是什么:一张 key=value 的表格**

JDK 自带的 `Properties` 类,专门读写配置文件.它本质是一张**字符串到字符串的表格**,文件格式是一行一条:

```
volume=80
language=zh_cn
difficulty=normal
```

- 每行 `键=值`,`=` 左右不留空格为佳

- `#` 开头是**注释**,给人看的,程序忽略

- 键值都是字符串,数字要转,`80` 读出是字符串 `"80"`



**读取配置**:

```
import java.util.Properties;
import java.io.FileInputStream;

Properties props = new Properties();

// 从文件加载(这是"字节流"版本:load(InputStream) 至今仍按 ISO-8859-1 解码,
// 文件里若有非英文要当心——下面第三节专门讲怎么用 UTF-8 读写中文)
props.load(new FileInputStream("game.properties"));

// 取配置:getProperty 按键取值
String volume = props.getProperty("volume");        // "80"
String notExist = props.getProperty("notExist");    // null!没这个键
```

**写入配置**:

```
import java.io.FileOutputStream;

Properties props = new Properties();
props.setProperty("volume", "90");     // 设置(键不存在就是新增,存在就是覆盖)
props.setProperty("language", "zh_cn");

// 保存到文件,第二个参数是文件头注释(同样是字节流版本,按 ISO-8859-1 写,中文会转义,见第三节)
props.store(new FileOutputStream("game.properties"), "game config");
```

**没查到的键返回 null**.这正是第 17 期 Optional 的老朋友.好在 `getProperty` 自带默认值:

```
String volume = props.getProperty("volume", "80");   // 没有 volume 就用 "80"
```

这个"带默认值的读取"是配置文件最常见的套路:**先给默认值,用户没配就用默认,配了就覆盖**.

**三、中文乱码:绕不开的编码一课**

新手第一次往配置文件里写中文,十有八九乱码.原因一句话:**Properties 早期的文件编码是 ISO-8859-1(只支持英文),中文必须转成 \uXXXX 形式的转义**:

```
language=中文
```

很严重的问题在于,即便是IDEA这种现代IDE,也可能会默认ISO-8859-1作为文件编码,需要手动调整.

`store` 写中文时会**自动**转成这种转义形式,文件里看不到"中文"两个字,但程序读出来是对的.老代码的"中文 = 一长串斜杠 u 数字",就是这个原因.

现在的做法是**指定 UTF-8 读取**,直接读写中文原文,不用管转义:

```
// 读取:用 Reader 并显式指定 UTF-8(注意文件本身也要保存成 UTF-8 编码)
props.load(new java.io.FileReader("game.properties", java.nio.charset.StandardCharsets.UTF_8));

// 写入:同样指定 UTF-8
props.store(new java.io.FileWriter("game.properties", java.nio.charset.StandardCharsets.UTF_8), "game config");
```

两个注意点:

1. **文件本身必须是 UTF-8 编码**:IDEA 右下角能看到当前文件编码,确认是 UTF-8;Windows 记事本默认可能是其他编码,另存为时选 UTF-8

2. 读取和写入的编码要**一致**:用 UTF-8 写,就用 UTF-8 读,混用必乱码

> 小知识:`FileReader`/`FileWriter` 从 Java 11 起支持直接指定字符集,老写法要手动包一层 `InputStreamReader` 并传字符集,效果相同.记住"读写编码一致"就够.

**四、套路:文件不存在就创建,带上默认值**

配置文件的完整套路,四步:

```
import java.util.Properties;
import java.io.File;
import java.io.FileReader;
import java.io.FileWriter;
import java.nio.charset.StandardCharsets;

public class GameConfig {
    private static final File FILE = new File("game.properties");
    private Properties props = new Properties();

    public GameConfig() {
        // 文件不存在:什么都不做,下面读取时用默认值顶上
        // 文件存在:读进来
        if (FILE.exists()) {
            try (FileReader reader = new FileReader(FILE, StandardCharsets.UTF_8)) {
                props.load(reader);
            } catch (Exception e) {
                System.out.println("读取配置失败,使用默认配置: " + e.getMessage());
            }
        }
    }

    // 读取永远带默认值:用户没配就用默认
    public int getVolume() {
        return Integer.parseInt(props.getProperty("volume", "80"));
    }

    public String getLanguage() {
        return props.getProperty("language", "zh_cn");
    }

    public boolean isFullscreen() {
        // Boolean.parseBoolean 和 Integer.parseInt 同族:字符串 → boolean
        return Boolean.parseBoolean(props.getProperty("fullscreen", "false"));
    }

    // 保存:先更新内存里的值,再写回文件(不存在会自动创建)
    public void setVolume(int volume) {
        // String.valueOf(数字) 把数字转成字符串,和第 9 期 Integer.parseInt 正相反
        // 一个"字符串→数字",一个"数字→字符串"
        props.setProperty("volume", String.valueOf(volume));
    }

    public void save() {
        try (FileWriter writer = new FileWriter(FILE, StandardCharsets.UTF_8)) {
            props.store(writer, "game config");
        } catch (Exception e) {
            System.out.println("保存配置失败: " + e.getMessage());
        }
    }
}
```

这个类你以后会反复见到:**读配置带默认值、写配置集中一处**是约定俗成的套路.注意第 1 步:文件不存在时什么都不做,后面 `getProperty` 的默认值兜底,程序永远不会因为"没有配置文件"而崩溃.

**五、小项目:游戏配置保存**

写一个迷你游戏设置面板:调音量、换语言,退出时保存,下次启动读回来.

文件 `Main.java`:

```
import java.util.Properties;
import java.io.File;
import java.io.FileReader;
import java.io.FileWriter;
import java.nio.charset.StandardCharsets;

public class Main {
    public static void main(String[] args) {
        File configFile = new File("game.properties");
        Properties props = new Properties();

        // 启动:读取已有配置(文件不存在就用默认值)
        if (configFile.exists()) {
            try (FileReader reader = new FileReader(configFile, StandardCharsets.UTF_8)) {
                props.load(reader);
            } catch (Exception e) {
                System.out.println("读取配置失败: " + e.getMessage());
            }
        }

        // 模拟玩家调设置
        int volume = Integer.parseInt(props.getProperty("volume", "80"));   // 默认 80
        volume = Math.min(100, volume + 10);                                 // 玩家把音量调高 10
        props.setProperty("volume", String.valueOf(volume));
        props.setProperty("language", "zh_cn");

        // 退出:保存
        try (FileWriter writer = new FileWriter(configFile, StandardCharsets.UTF_8)) {
            props.store(writer, "game config");
        } catch (Exception e) {
            System.out.println("保存配置失败: " + e.getMessage());
        }

        // 打印当前配置(第 16 期的流也露一手)
        props.forEach((k, v) -> System.out.println(k + " = " + v));
    }
}
```

第一次运行:文件不存在,音量默认 80,调成 90,生成 `game.properties`.第二次运行:读到 90,再调成 100.看看文件里的内容:

```
#game config
#Mon Aug 11 ...
language=zh_cn
volume=100
```

动手试试:删掉 `game.properties` 再运行(回到默认 80);把 `language=zh_cn` 手工改成 `language=en_us` 再运行,看程序读到的值:**改配置,不动代码**,这正是配置文件的意义.

**朝花夕拾:从第 1 期的 File,到今天的配置文件**

第 1 期我们认识了 `File`,当时说它只是"路径的抽象",真正读写是 `FileReader`/`FileWriter`(第 11 期).今天这套组合拳第一次收口:配置文件 = `File` 定位 + `FileReader`/`FileWriter` 读写 + `Properties` 处理键值.而第 12 期成绩管理系统的 `students.txt`,本质上也是"配置文件"的近亲.只是存的是数据,不是设置.

**总结**

本期学会了让程序"读外部参数":

- **配置与代码分离**:会变的参数进文件,改配置不动代码

- **Properties**:`load`/`store` 读写 `key=value` 文件,`getProperty(key, 默认值)` 兜底

- **编码**:老格式只支持英文会转义;统一指定 UTF-8 读写,读写编码必须一致

- **套路**:文件不存在不报错 → 读取带默认值 → 保存集中一处

- 游戏配置保存小项目:调音量改语言,退出保存启动恢复
