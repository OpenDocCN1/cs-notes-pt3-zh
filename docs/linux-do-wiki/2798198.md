**一、程序怎么"找到"另一个程序**
你的电脑和全世界联网,靠的是三样东西:
1. **IP 地址**:机器的门牌号,比如 `192.168.1.100`.`127.0.0.1` 是特殊地址,叫 **localhost**,指"本机自己"
2. **端口**:同一台机器上可能跑着几百个程序,光有 IP 还不够,得说"找哪扇门".端口就是门牌号后面的"房间号",比如 Web 服务常用 8080.一台机器,IP 定位机器,**端口定位程序**
3. **协议**:约定好怎么说话.网页用 **HTTP**,聊天/游戏实时通信常用 **TCP**(传输层,后期细讲)

所以"访问一个网站"= 通过 IP 找到那台机器,敲开某个端口的门,按 HTTP 的规矩说话.
**URL 就是这三样东西的打包**:`http://localhost:8080/api/greeting` :协议 `http`、地址 `localhost`、端口 `8080`、路径 `/api/greeting`.

**二、HTTP 请求-响应:一问一答**
HTTP 的模型简单得像个电话亭:**客户端发一个请求,服务器回一个响应**,然后各走各的.请求里带着"我要什么"(方法 + 路径),响应里带着"你要的"(状态码 + 内容).
最常见的 GET 请求就是"给我拿点东西".Java 11 起,JDK 自带的 `HttpClient` 就能发:
```
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class HttpDemo {
    public static void main(String[] args) throws Exception {
        // 1. 建一个客户端
        HttpClient client = HttpClient.newHttpClient();

        // 2. 拼一个 GET 请求(一言:每次返回一句名言/台词)
        HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create("https://v1.hitokoto.cn"))
                .build();

        // 3. 发出去,等响应
        HttpResponse<String> response = client.send(request,
                HttpResponse.BodyHandlers.ofString());

        // 4. 看结果:状态码 200 表示成功
        System.out.println("状态码: " + response.statusCode());
        System.out.println("返回内容: " + response.body());
    }
}
```
运行后你会看到一段 JSON(第 23 期会专门讲怎么解析它):
```
{"hitokoto":"...","from":"...",...}
```
这就是**调用网络接口**的全部套路:建客户端 → 拼请求 → 发出去 → 解析响应.你把 URL 换成天气接口、翻译接口,代码结构一模一样——世界上的 API 都是这个姿势.
> `HttpClient` 是 JDK 11 加入的,如果你的 JDK 更老,用老式的 `HttpURLConnection`,套路相同:`openConnection()` → `getInputStream()` 读响应.教程默认 JDK 17+,直接用 `HttpClient`.

**三、Socket:亲手搬一条"网络管道"**
HTTP 请求是"一问一答"的高级模式;更底层的是 **Socket(套接字)**.它直接在两台程序之间拉一条"管道",两边往里写、往外读,想聊几句聊几句,像打电话.
管道两端:
- **服务器端**:先开机,一直等着接电话:`ServerSocket` 监听某个端口
- **客户端**:主动打过去:`Socket` 连服务器的 IP + 端口

连上之后,**两端各自拿到一个输入流和一个输出流**,读写就是第 11 期学过的流操作:网络通信和文件读写,本质是同一件事:往流里写字节,从流里读字节.
**服务器端**(先跑起来,等着):
```
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;

public class ChatServer {
    public static void main(String[] args) throws Exception {
        ServerSocket server = new ServerSocket(8888);   // 监听 8888 端口
        System.out.println("服务器已启动,等待连接...");

        Socket socket = server.accept();     // 一直等到有人连上来
        System.out.println("客户端连上了: " + socket.getInetAddress());

        BufferedReader in = new BufferedReader(
                new InputStreamReader(socket.getInputStream()));
        PrintWriter out = new PrintWriter(socket.getOutputStream(), true);

        String line;
        while ((line = in.readLine()) != null) {    // 读客户端发来的每一行
            System.out.println("收到: " + line);
            out.println("已收到: " + line);          // 回一句
        }
        socket.close();
        server.close();
    }
}
```
**客户端**(另开一个终端运行,连上去):
```
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;

public class ChatClient {
    public static void main(String[] args) throws Exception {
        // 连本机的 8888 端口
        Socket socket = new Socket("127.0.0.1", 8888);

        BufferedReader in = new BufferedReader(
                new InputStreamReader(socket.getInputStream()));
        PrintWriter out = new PrintWriter(socket.getOutputStream(), true);

        BufferedReader keyboard = new BufferedReader(new InputStreamReader(System.in));

        String line;
        System.out.println("输入消息(exit 退出):");
        while ((line = keyboard.readLine()) != null) {
            out.println(line);                       // 发给服务器
            if (line.equals("exit")) break;
            System.out.println("服务器: " + in.readLine());   // 等回应
        }
        socket.close();
    }
}
```
运行顺序:先启动 `ChatServer`,再启动 `ChatClient`;在客户端输入一句话,服务器收到后原样回一句.这就是一个能跑的**局域网聊天雏形**:把 `127.0.0.1` 换成同事电脑的局域网 IP,两台电脑就能聊(前提:同一局域网、防火墙放行 8888 端口).
**accept() 是阻塞的**:没客户端来时,服务器就停在那等:这是服务器最朴素的形态.真实服务器(第 18/19 期的线程池)会为每个连接开一条线程,同时接待很多人;我们的 `ServerSocket` 同一时刻只能接待一个,聊完一个才接下一个.体会"阻塞 → 多线程 → 线程池"这条进阶线,你会越来越理解服务器为什么长那样.
**两个代码里藏着、却必须懂的细节**:
1. **PrintWriter(socket.getOutputStream(), true) 的第二个参数 true 是"自动刷新"**:每 `println` 一次,数据立刻冲刷到网络里发给对方.如果漏掉这个 `true`,数据会积在缓冲区里不出去,出现"我发了消息,对方就是收不到"的卡死假象(要等到缓冲区满或流关闭才发):新手调网络程序第一个坑.想验证?把 `true` 删掉跑一遍,你就懂了.
2. **网络资源用完必须关,比文件还要命**:每个 Socket 连接在操作系统里占一个**文件句柄**,进程能打开的数量有限(几千到几万).代码里 `socket.close()` 忘了写或没执行到,连接就泄漏一个;循环开连接不关,迟早把句柄耗尽,然后**新连接全部失败**,只能重启程序.所以网络代码的规矩是:谁开的谁关,实在不放心的场景用 try-with-resources(第 11 期)自动关.上面小项目里 `try (Socket socket = ...)` 就是这么干的.

**四、小项目:调接口 + 局域网聊天**
把今天两块内容串成一个小工具:**一言播报器**.从网络接口取一句名言,再通过局域网聊天发给队友.
文件 `Main.java`:
```
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class Main {
    public static void main(String[] args) throws Exception {
        // 1. 调一言接口
        HttpClient client = HttpClient.newHttpClient();
        HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create("https://v1.hitokoto.cn"))
                .build();
        HttpResponse<String> response = client.send(request,
                HttpResponse.BodyHandlers.ofString());
        System.out.println("取到一句话,状态码: " + response.statusCode());

        // 2. 发给局域网里的服务器(配合 ChatServer 使用)
        try (Socket socket = new Socket("127.0.0.1", 8888);
             PrintWriter out = new PrintWriter(socket.getOutputStream(), true)) {
            out.println(response.body());
            System.out.println("已发给服务器");
        } catch (Exception e) {
            System.out.println("没连上服务器(先运行 ChatServer): " + e.getMessage());
        }
    }
}
```
动手顺序:先跑 `ChatServer`,再跑 `Main`:服务器端会看到一行 JSON 名言,这就是"我的程序从互联网取数据,再发给另一台机器"的完整闭环.

**朝花夕拾:第 11 期的流,今天通了网**
第 11 期我们学的 `BufferedReader` 读文件、各种 `Writer` 写文件,今天几乎原封不动出现在 Socket 上,区别只是流的**另一头从"文件"换成了"另一台程序"**.这也是 Java 流设计的初衷:管他对面是文件、网络还是内存,读写方法一模一样.你玩的 Minecraft 联机、你调的每一个 API,底层都是今天这一幕.
