**一、什么是设计模式**
先纠正一个常见误解:设计模式**不是一段可以直接抄的代码**,而是**一类反复出现的问题的成熟解法**:是"思路",不是"模板".
比如你写程序时一定遇到过这个场景:某个类**只想让它有一个实例**(配置文件读取器,全程序共用一个就够了).这个问题在无数项目里反复出现,大家摸索出的成熟解法就叫**单例模式**(第 29 期).再比如"给一个老接口包一层,让新代码能用它",也是反复出现的问题,解法叫**适配器模式**(第 32 期).
所以设计模式的价值有两个:
1. **它给问题起好了名字**:你一说"这要个单例",同行立刻懂你要干什么,交流成本骤降
2. **它给答案画好了草图**:不用从零摸索,照着思路踩过的坑就少了
**设计模式 = 经验的名字**.你在 JDK、Spring、MyBatis 里到处见到它们,不是巧合,是它们确实好用.

**二、23 种模式怎么分类:三大类**
GoF 的经典分类按"解决什么问题"分成三大类:
**创建型 5 种:管"对象怎么造"**

核心思想:把"创建对象"这件事从业务代码里解耦出去,业务代码不该到处 `new`,创建逻辑应该集中、灵活、可控.
| 模式 | 一句话名片 | 前面学过的影子(第 1–25 期) |
| --- | --- | --- |
| 单例 | 全局只有一个实例 | — |
| 工厂方法 | 定义"制造"接口,各工厂各造各的 | `Executors`(第 19 期)、`HttpClient.newHttpClient`(第 22 期) |
| 抽象工厂 | 一族产品成套交付 | — |
| 建造者 | 参数太多,链式搭积木 | `StringBuilder`(第 9 期) |
| 原型 | 克隆已有对象当模板 | — |
**结构型 7 种:管"对象怎么组合"**

核心思想:把类组合成更大的结构,同时让结构灵活、不僵硬.优先用"组合"而不是"继承"来扩展.
| 模式 | 一句话名片 | 前面学过的影子(第 1–25 期) |
| --- | --- | --- |
| 适配器 | 老接口转新接口,中间加翻译层 | `InputStreamReader`(第 22 期)、`Arrays.asList`(第 14 期) |
| 桥接 | 抽象与实现分离,各自独立变化 | — |
| 组合 | 树形结构,叶子和大树一样对待 | — |
| 装饰器 | 不改原类,套壳加功能 | `BufferedReader` 包 `FileReader`(第 11 期) |
| 外观 | 一键开机:给一堆复杂对象一个简单入口 | `HttpClient`(第 22 期) |
| 享元 | 小对象大量重复,共享不重建 | — |
| 代理 | 找个中间人,控制访问 | — |
**行为型 11 种:管"对象怎么协作"**

核心思想:把对象之间的交互、职责分配设计清楚.谁做什么、谁通知谁、怎么接力.
| 模式 | 一句话名片 | 前面学过的影子(第 1–25 期) |
| --- | --- | --- |
| 责任链 | 一件事接力处理,传到能办的人手里 | — |
| 命令 | 把"操作"打包成对象,能存能撤销 | `Runnable`(第 18 期) |
| 解释器 | 定义语言规则并解析 | — |
| 迭代器 | 统一遍历方式,不暴露内部结构 | 增强 for(第 1 期) |
| 中介者 | 大家别互相喊,都找中间人 | 聊天室服务器(第 22 期) |
| 备忘录 | 存快照,支持回退 | 游戏存档(第 12/21 期) |
| 观察者 | 一有风吹草动,通知所有订阅者 | — |
| 状态 | 状态变了,行为跟着变 | 线程的五种状态(第 18 期) |
| 策略 | 算法可替换,换策略不换代码 | `Comparator`(第 10/15 期) |
| 模板方法 | 骨架定死,细节留给子类 | — |
| 访问者 | 数据结构不动,给数据加新操作 | — |
(第三列是"—"的模式,说明前 25 期还没遇到过.没关系,它们的完整小项目会在自己的那期登场.)
(记忆方法:创建型看"造",结构型看"拼",行为型看"聊":象怎么造、怎么拼、怎么聊.)

**三、怎么学才不白学**
四个建议,照做能少走弯路:
**1. 先认,再写.** 27–49 期每期讲一种模式,其中很多你**早就在用**了.学新模式时先找"我在哪儿见过它",再动手写小项目.
**2. 记场景,不记代码.** 面试问"什么是单例",最差的回答是背代码;好的回答是"我需要全局唯一对象时用单例,比如配置管理器,它的写法有几种……".**模式=场景+解法**,场景记牢,代码自然会写.
**3. 别为了用而用.** 这是新手最容易犯的:学了模式后看什么都想套.设计模式的边界是"**这个问题真的反复出现/真的复杂**":一行 `new` 能解决的,套个工厂就是过度设计.我们第 27–49 期每期都会讲"什么时候**不该**用",和"什么时候用"一样重要.
**4. 模式是语言无关的思想.** 学的是"思路",不是 Java 语法.将来写 Kotlin、写 C#,同一套思想照样适用.

**四、接下来的路线图**
第 27–49 期,每期一种模式,顺序:
- **27–31 创建型** **32–38 结构型** :适配器 → 桥接 → 组合 → 装饰器 → 外观 → 享元 → 代理
- **39–49 行为型**:责任链 → 命令 → 解释器 → 迭代器 → 中介者 → 备忘录 → 观察者 → 状态 → 策略 → 模板方法 → 访问者
每期结构:这个模式解决什么问题 → 核心思想 → 代码示例(含源码实例) → 小项目 → 什么时候别用.学到第 49 期,23 种模式全部过完,你再看 Spring 的源码,会发现满屏都是熟人.
---
**朝花夕拾:原来前 25 期我们一直在"写模式"**
回头看,设计模式不是从今天开始的:
- 第 10 期写 `Comparator` 换排序规则 → **策略模式**
- 第 15 期 Lambda 传行为 → 策略模式的现代写法
- 第 19 期 `Executors.newFixedThreadPool()` → **工厂方法**(你只调用,不知道线程池怎么造的)
- 后面第 30 期要讲的 `StringBuilder.append(...).append(...)` 链 → **建造者**
- 第 11 期 `BufferedReader` 包 `FileReader` → **装饰器**
这些例子告诉你一件事:你已经在用设计模式,只是还没有告诉你名字.接下来的 23 期,我们会逐一精讲每一种.那时你会发现,**先有手感,后有理论**,理论才有落点.
