# Java开发教程27-工厂方法模式



本期是Java开发教程系列的第二十七期,设计模式专题第一期,讲**工厂方法模式**:把"创建对象"这件事从业务代码里请出去,集中管理.这是创建型模式的开篇,也是你见过的第一个"模式"名字:第 19 期的 `Executors.newFixedThreadPool()`,背后就是它.若你已经理解简单工厂与工厂方法的区别,可以跳过本期内容.

**一、问题:到处 new 有什么不好**

假设要写一个日志系统,支持三种日志:控制台打印、写文件、发数据库.最直白的写法:

```
// 业务代码里,到处是这种分支
Logger logger;
String type = config.get("logger.type");
if (type.equals("console")) {
    logger = new ConsoleLogger();
} else if (type.equals("file")) {
    logger = new FileLogger("app.log");
} else {
    logger = new DatabaseLogger();
}
logger.log("玩家上线");
```

这段"选择哪种日志、怎么构造"的逻辑,会出现在**每一个需要日志的类里**.十几个类,每处复制一份.问题随之而来:

1. **改动扩散**:日志类型想加一种(比如网络日志),这十几个地方的 if-else 全要改

2. **依赖混乱**:业务代码直接依赖所有 Logger 实现类,第 7 期讲的"面向接口"形同虚设

3. **构造细节泄漏**:业务代码不该知道"文件日志要传文件名"

**解决方向:把"怎么造 Logger"集中到一个地方,业务代码只说"我要个 Logger"**.这就是工厂的由来.

---

**二、简单工厂:一个方法,按参数造**

先把创建逻辑收进一个类:

```
public class LoggerFactory {

    // 简单工厂:一个静态方法,按类型返回不同对象
    public static Logger create(String type) {
        if (type.equals("console")) {
            return new ConsoleLogger();
        } else if (type.equals("file")) {
            return new FileLogger("app.log");
        } else {
            return new DatabaseLogger();
        }
    }
}
```

业务代码变成一行:

```
Logger logger = LoggerFactory.create(config.get("logger.type"));
logger.log("玩家上线");
```

这就是**简单工厂**(严格说不是 23 种模式之一,是工厂方法的前奏):好处立刻可见,"怎么造"只在一个类里,业务代码不再关心;想改构造方式只改这一处.

但它还有个尾巴:这个类里**仍然**有 if-else,每加一种日志还是要改 `LoggerFactory` 本身,违反了"对修改关闭"的直觉(加新东西不该改旧代码).工厂方法模式就是来解决这个尾巴的.

---

**三、工厂方法:把"造对象"也做成接口**

工厂方法的核心思想:**定义"制造日志"的接口,每一种日志配一个工厂类,各自实现"制造"逻辑** ![:shortcake:](img/6874ed782ba16c7eeacbd5ee93ebc882.png)

```
// 产品接口:业务代码只认识它
public interface Logger {
    void log(String message);
}

// 具体产品
public class ConsoleLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[控制台] " + message);
    }
}

public class FileLogger implements Logger {
    private String fileName;
    public FileLogger(String fileName) { this.fileName = fileName; }
    @Override
    public void log(String message) {
        System.out.println("[文件 " + fileName + "] " + message);
    }
}

// 工厂接口:定义"制造"方法
public interface LoggerFactory {
    Logger create();
}

// 具体工厂:每种产品一个工厂,各造各的
public class ConsoleLoggerFactory implements LoggerFactory {
    @Override
    public Logger create() {
        return new ConsoleLogger();
    }
}

public class FileLoggerFactory implements LoggerFactory {
    @Override
    public Logger create() {
        return new FileLogger("app.log");    // 构造细节只在自家工厂里
    }
}
```

业务代码这样用:

```
LoggerFactory factory = new FileLoggerFactory();   // 想用哪种,换工厂
Logger logger = factory.create();
logger.log("玩家上线");
```

**新增一种日志(比如网络日志)时**:写一个 `NetworkLogger` + 一个 `NetworkLoggerFactory`,**一行旧代码都不用改**.这就是工厂方法最大的价值:产品可以无限扩展,工厂接口和业务代码纹丝不动.当初那个"十几处复制 if-else"的问题,连根拔起.

---

**四、什么时候用,什么时候别用**

**用工厂方法**:

- 创建逻辑复杂(多个步骤、需要配置)或创建类型会变(按配置/按环境选实现)

- 想隐藏"具体是哪个实现".`Calendar.getInstance()` 你可能传了地区参数,拿到的可能是不同子类,但调用方无所谓

**别用工厂方法**:

- `new` 一下就完事、没有分支、不会变.为它写两个接口五个类,就是第 26 期说的**过度设计**

- 工厂的价值是"集中 + 解耦",这两样你都不需要时,直接 new

**工厂方法解决"创建逻辑会扩散、创建类型会变化"的痛;痛不存在的项目,别给自己找痛**.

**五、源码:Calendar.getInstance 里的工厂**

JDK 里最经典的工厂方法,是 `java.util.Calendar`:

```
Calendar calendar = Calendar.getInstance();
```

这个"getInstance"听着像单例,其实是工厂.看它背后的逻辑:你调用时**没有指定实现类**,它根据你的**时区、语言环境**当场决定返回哪个 `Calendar` 子类(公历 `GregorianCalendar` 是默认,日本地区可能返回日本历).调用方全程只知道 `Calendar`,不知道(也不关心)具体子类是谁.

再想想第 19 期:`Executors.newFixedThreadPool()` 返回 `ThreadPoolExecutor`,这也是工厂,把"线程池怎么造"藏起来了.还有一个等学到数据库才会见的:`DriverManager.getConnection(url)` 按 URL 返回不同数据库的连接(MySQL 的、PostgreSQL 的):那是全世界最成功的工厂方法应用之一.看到这类"getXxx/createXxx/newXxx 方法背后藏着多选一"的 API,你就知道工厂又出现了.

**六、小项目:日志记录器工厂**

动手实现上面完整的工厂方法:三种日志 + 三个工厂 + 业务代码.

文件 `Logger.java`:

```
public interface Logger {
    void log(String message);
}
```

文件 `ConsoleLogger.java` / `FileLogger.java`:

```
public class ConsoleLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[控制台] " + message);
    }
}

public class FileLogger implements Logger {
    private String fileName;

    public FileLogger(String fileName) {
        this.fileName = fileName;
    }

    @Override
    public void log(String message) {
        System.out.println("[文件 " + fileName + "] " + message);
    }
}
```

文件 `LoggerFactory.java` + 两个工厂:

```
public interface LoggerFactory {
    Logger create();
}

public class ConsoleLoggerFactory implements LoggerFactory {
    @Override
    public Logger create() {
        return new ConsoleLogger();
    }
}

public class FileLoggerFactory implements LoggerFactory {
    @Override
    public Logger create() {
        return new FileLogger("app.log");
    }
}
```

文件 `Main.java`:

```
public class Main {
    public static void main(String[] args) {
        // 模拟"从配置选工厂"
        String type = "file";

        LoggerFactory factory;
        if (type.equals("console")) {
            factory = new ConsoleLoggerFactory();
        } else {
            factory = new FileLoggerFactory();
        }

        // 业务代码永远只碰接口
        Logger logger = factory.create();
        logger.log("玩家 Steve 上线");
        logger.log("玩家 Steve 下线");
    }
}
```

动手扩展(体会"不改旧代码"):自己加一种 `NetworkLogger`,打印 `[网络] 消息`,配一个 `NetworkLoggerFactory`.注意 `Main` 里只需要加一个分支,而 `Logger`/两个旧工厂/`ConsoleLogger`/`FileLogger` 一行都不用动.这就是工厂方法对"扩展"的友善.

**朝花夕拾:第 19 期那句"别裸 new Thread"**

第 19 期我们学线程池,写了 `Executors.newFixedThreadPool(4)`.今天回头:`Executors` 就是一个工厂:把"构造线程池的复杂逻辑"藏起来,你只需说"给我个固定 4 线程的池子".如果当时没有它,每个用线程池的地方都要自己拼 `new ThreadPoolExecutor(4, 8, ...)` 那七个参数.工厂的价值,在你还是新手时就已经受惠了.

---

**总结**

本期学会了第一种设计模式:

- **问题**:创建逻辑分散、到处 new、扩展要改一堆旧代码

- **简单工厂**:一个方法集中创建,但加产品还要改它

- **工厂方法**:创建也接口化,每产品一工厂,新增产品不改旧代码

- **场景判断**:创建复杂或会变才用;`new` 就行的别硬套

- **源码**:`Calendar.getInstance`、`Executors`、`DriverManager.getConnection` 全是工厂

- 日志记录器工厂小项目

- 实际上工厂模式方法在NeoForge经常出现,极大的简化了其他开发者注册和开发新功能的过程.

下一期讲创建型的第二种:**抽象工厂**.工厂方法管"一种产品",它管"一整套产品".
