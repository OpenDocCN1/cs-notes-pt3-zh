# Java开发教程30-建造者模式

本期是Java开发教程系列的第三十期,设计模式专题第四期,讲**建造者模式**(Builder):当对象有一大堆可选参数时,用链式调用一块块"搭"出来,告别写到手抽筋的长构造器和记不住的参数顺序.你早就会用它了:`StringBuilder.append(...).append(...)`,就是最朴素的建造者.若你已经理解 Builder 与构造器/setter 的区别,可以跳过本期内容.

时间仓促,水平有限,文中难免存在缺点和错误,恳请广大开发者和从业者指正.

**一、问题:参数多到记不住**
设想游戏里的玩家属性:
```
public class Player {
    private String name;      // 必填
    private int level;        // 默认 1
    private double hp;        // 默认 20
    private int attack;       // 默认 5
    private double speed;     // 默认 4.3
    private String skin;      // 默认 null(用默认皮肤)
    private boolean isOp;     // 默认 false
    ...
}
```
7 个字段,1 个必填 6 个可选.用构造器怎么写?
```
// 方案一:8 个重载构造器,组合爆炸,写死
Player p1 = new Player("Steve");
Player p2 = new Player("Steve", 10);
Player p3 = new Player("Steve", 10, 20.0);
Player p4 = new Player("Steve", 10, 20.0, 8);
// ...每个可选字段的组合都要一个构造器,7 个字段要 128 个

// 方案二:全参数构造器 + 用不到也传
Player p5 = new Player("Steve", 10, 20.0, 8, 4.3, null, false);
// 谁能记住第 5 个参数是速度还是攻击力?传错位置编译期还发现不了!
```
方案二最大的坑:**参数位置错误在编译期完全不报错** !!!  `new Player("Steve", 10, 20.0, 8, 4.3, ...)` 把 attack 和 speed 传反,程序照样编译通过,跑起来数值全错.
**方案三:setter 填充**?解决了顺序问题,但对象变成了"可变的半成品":`new Player()` 后忘了 set,拿到的就是残缺对象;而且对象创建后还能随意改动,想"构建完就定死"做不到.
我们需要:参数一个个给(像 setter 那样舒服)+ 构建完不可变 + 必填参数必须给.这就是 Builder.
---
**二、Builder:把"组装"交给专门的对象**
建造者模式的结构:一个 `Builder` 类,每个可选字段一个"设置方法",每个方法返回 `this` 支持链式;最后 `build()` 一次性产出目标对象:
```
public class Player {
    // 字段全私有 final:构建完不可变
    private final String name;
    private final int level;
    private final double hp;
    private final int attack;

    // 构造器私有:只有 Builder 能调用
    private Player(Builder b) {
        this.name = b.name;
        this.level = b.level;
        this.hp = b.hp;
        this.attack = b.attack;
    }

    // 建造者:字段抄一份,默认值在此定义
    public static class Builder {
        private String name;      // 必填,没有默认值
        private int level = 1;    // 可选字段都有默认值
        private double hp = 20.0;
        private int attack = 5;

        public Builder(String name) {       // 必填参数进 Builder 构造器,逼你给
            this.name = name;
        }

        public Builder level(int v) { level = v; return this; }
        public Builder hp(double v) { hp = v; return this; }
        public Builder attack(int v) { attack = v; return this; }

        public Player build() {
            return new Player(this);
        }
    }
}
```
用法:
```
Player steve = new Player.Builder("Steve")
        .level(10)
        .hp(30.0)
        .attack(8)
        .build();          // 一条链,一个对象

Player alex = new Player.Builder("Alex").build();   // 全默认值,一行完事
```
四条设计要点:
1. **每个 set 方法返回 this**:这是链式的机关,`level(10)` 之后还能继续 `.hp(30.0)`
2. **默认值集中在 Builder 里**:不设置就用默认,干净
3. **必填参数放在 Builder 构造器**;想绕过都不行,编译期强制
4. **目标类构造器私有 + 字段 final**:对象只能由 Builder 造出来,造完就不可变
对比之前的三个方案:顺序问题(解决:名字就是意义)、默认值(解决:Builder 里定)、不可变(解决:final 字段)、必填强制(解决:Builder 构造器).

**三、源码:JDK 里无处不在的 Builder**
**StringBuilder**:最朴素的建造者:`append` 每次返回 `this`,链式拼装,最后 `toString()` 一次性出结果:
```
StringBuilder sb = new StringBuilder();
sb.append("玩家 ").append(name).append(" 等级 ").append(level);   // 链式
String msg = sb.toString();
```
**JDK 8 的 Stream.Builder**:流也能链式构造:
```
Stream<String> stream = Stream.<String>builder()
        .add("a").add("b").add("c")
        .build();
```
**Lombok 的 @Builder**:注解自动生成 Builder 类(工程上天天见,是第 24 期讲的"编译期注解处理"的功劳,它在**编译期**改写字节码生成 Builder 代码,**不走运行期反射**):
```
@Builder
public class Player {
    private String name;
    private int level;
}
// 自动生成 Player.builder().name("Steve").level(10).build()
```
**Spring 里**:`UriComponentsBuilder`、`RestTemplateBuilder`……凡是你看到"类名.builder().xxx().yyy().build()",都是它.
---
**四、什么时候用,什么时候别用**
**用 Builder**:
- 参数多(一般认为超过 3~4 个)且多为可选,尤其带默认值
- 构建后要**不可变**(final 字段),又要灵活的构造体验
- 参数间有约束(比如"攻击力不能超过等级×2"),可以在 `build()` 里统一校验,构造器做不到这么优雅
机言机语:哈哈!我现在彻底明白用户的需求了,看我优雅注释优雅编码优雅报错优雅退出!
**别用 Builder**:
- 参数就两三个、都是必填:直接构造器,Builder 是多余的包装
- 对象本就需要频繁改字段:那 setter 才是对的,Builder 造完不可变反而碍事
**和 setter 的分工**记住一句:**要"造完就定型"用 Builder,要"随时可改"用 setter**.游戏里的配置对象、请求对象、不可变值对象,用 Builder;玩家操作中的血量这种实时变化的,用 setter.

**五、小项目:玩家属性构建器**
写一个完整的玩家构建器,包含校验与默认值:
文件 `Player.java`:
```
public class Player {
    private final String name;
    private final int level;
    private final double hp;
    private final int attack;
    private final double speed;

    private Player(Builder b) {
        this.name = b.name;
        this.level = b.level;
        this.hp = b.hp;
        this.attack = b.attack;
        this.speed = b.speed;
    }

    public static class Builder {
        private final String name;
        private int level = 1;
        private double hp = 20.0;
        private int attack = 5;
        private double speed = 4.3;

        public Builder(String name) {
            this.name = name;          // 必填
        }

        public Builder level(int v) { level = v; return this; }
        public Builder hp(double v) { hp = v; return this; }
        public Builder attack(int v) { attack = v; return this; }
        public Builder speed(double v) { speed = v; return this; }

        // 构建前统一校验:不合法直接拒绝
        public Player build() {
            if (attack > level * 3) {
                throw new IllegalArgumentException("攻击力不能超过等级的三倍");
            }
            if (hp < 0) {
                throw new IllegalArgumentException("血量不能为负");
            }
            return new Player(this);
        }
    }

    @Override
    public String toString() {
        return name + " Lv." + level + " HP:" + hp + " ATK:" + attack + " SPD:" + speed;
    }
}
```
文件 `Main.java`:
```
public class Main {
    public static void main(String[] args) {
        // 完整链式
        Player hero = new Player.Builder("英雄")
                .level(10)
                .hp(50.0)
                .attack(20)
                .speed(5.0)
                .build();
        System.out.println(hero);

        // 全部默认:一行
        Player nobody = new Player.Builder("路人").build();
        System.out.println(nobody);

        // 校验生效:攻击力超过等级三倍,构建失败
        try {
            new Player.Builder("作弊者").level(1).attack(99).build();
        } catch (IllegalArgumentException e) {
            System.out.println("构建失败: " + e.getMessage());
        }
    }
}
```
运行结果:
```
英雄 Lv.10 HP:50.0 ATK:20 SPD:5.0
路人 Lv.1 HP:20.0 ATK:5 SPD:4.3
构建失败: 攻击力不能超过等级的三倍
```
动手练习:给 Builder 加一个 `skin(String)` 字段(默认 `"default"`);把 `build()` 里的校验规则改成"血量小于 1 拒绝",体会"校验集中在 build,调用方永远拿不到非法对象".
---
**朝花夕拾:第 9 期那个 append 链,今天有了理论名**
第 9 期我们第一次写 `sb.append("a").append("b").append(1)`,当时只说"可以连续调用".今天给它补上了名字:**建造者模式**.`append` 返回 `this` 的链式设计,正是 Builder 的标志.而第 2 期学的构造器、第 5 期学的 setter,今天和 Builder 三者关系:**构造器给"少参数必填",setter 给"需要可变",Builder 给"多参数 + 不可变 + 校验"**.三件工具各管一摊,别再混着用了.混了就等着面试挂了吧.

**总结**
本期学会了"搭积木式"建对象:
- **问题**:参数爆炸、位置易错、setter 半成品、不可变难保证
- **Builder 结构**:私有构造器 + 内部 Builder 类;set 返回 this 成链;默认值/必填/校验集中在 Builder
- **效果**:链式舒服、造完不可变、必填编译期强制
- **源码**:`StringBuilder`、`Stream.builder`、Lombok `@Builder`
- **分工**:多参数不可变用 Builder,随时可变用 setter
