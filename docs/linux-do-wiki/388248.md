# Windows上无GUI运行Transmission并配置代理

## 经多次检验，此方法实际效果并不理想，无法完成让Transmission流量全部走直连的任务，十分抱歉！
Transmission是被除了天雪之外各支持利用BT协议共享文件的站点所广泛接受的能源消耗最少的BT客户端（如果不是还请补充）。但不知为何在某个版本后无法直接配置代理了（但也许只是我没找到直接配置代理的办法？如有还请指出），就导致BT传输的流量可能会把代理的流量消耗殆尽。不过Transmission有官方的Docker镜像，因此，我们可以通过使用V2rayA为Docker容器配置代理的方法来实现为Transmission配置代理以让其与Peers及Tracker直连。这里采用在Windows10中安装[ArchWSL](https://github.com/yuk7/ArchWSL)，在ArchWSL中安装Docker的办法来配置无GUI的Docker。至于为何不直接安装ArchLinux，主要是因为该机算计不仅我一人使用，安装ArchLinux或ArchLinux+Windows双系统可能会造成极大的麻烦。
ArchWSL本身可以通过Scoop来快速安装。具体可见ArchWSL的官方文档。

安装好后先配置DNS。

查看`/etc/resolv.conf`文件，不出意外会有注释表明不要编辑此文档而是按照提示去编辑`/etc/wsl.conf`。按照注释在`/etc/wsl.conf`中加入下列内容：
```
[network]
generateResolvConf = false
nameserver 233.5.5.5           #此处可自行更改相应的DNS服务器
```
完成后[编辑Pacman的镜像](https://wiki.archlinuxcn.org/wiki/%E5%AE%89%E8%A3%85%E6%8C%87%E5%8D%97#%E9%80%89%E6%8B%A9%E9%95%9C%E5%83%8F%E7%AB%99)

之后在Windows主机的终端内重启wsl
```
wsl --shutdown | wsl
```
之后找个地方依照 Transmission 的官方文档创建并配置 Transmission 的`docker-compose.yml`文件，这里给出的示例还包含对网络的配置，窃以为这是为方便配置代理必不可少的步骤。

`vim /usr/bin/transmission-docker/docker-compose.yml`
```
services:
  transmission:
    image: lscr.io/linuxserver/transmission:latest #可自行更改版本
    container_name: transmission
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Etc/UTC
      - TRANSMISSION_WEB_HOME= #optional
      - USER= #optional
      - PASS= #optional
      - WHITELIST= #optional
      - PEERPORT= #optional
      - HOST_WHITELIST= #optional
    volumes:
      - /path/to/transmission/data:/config #建议挂载路径与与 docker-compose.yml 的路径保持一致，若不挂载 /config 可能导致无法保存 Transmission 的做种状态及各设置
      - /path/to/downloads:/downloads #对于 Windows 主机的文件， ArchWSL 中可在 /mnt/* 中查看，其中*一般为Windows中的盘符
      - /path/to/watch/folder:/watch #optional
    ports:
      - 9091:9091
      - 51413:51413
      - 51413:51413/udp
    restart: unless-stopped
    networks:
      mynet1:
        ipv4_address: 172.*.*.* #除docker默认网桥 172.17.*.* 基本都可，可分配的 IP 地址范围为 172.*.*.1 到 172.*.*.254

networks:
  mynet1:
    driver: bridge
    ipam:
      config:
        - subnet: 172.*.*.0/24 #子网掩码应为有效的 CIDR 格式，如 /24、/16 等
```
至此，Transmission在Docker内的部署基本完成，后续若要更改Transmission的设置，修改挂为`/config`的文件夹内的`settings.json`即可，这里不做赘述。
然后，参考[V2rayA的官方文档](https://v2raya.org/docs/advanced-application/specify-container-proxy/)，在RoutingA中加入如下内容
```
# 将规则插入到较前位置
source(172.*.*.*) -> direct
source(172.*.*.0/24) -> direct
```
并将”规则端口的分流模式“设置为”RoutingA“，”透明代理/系统代理“设置为”启用：分流规则与分流端口所选模式一致“。

至此，Transmission在Windows上无GUI运行，并配置直连代理的设置基本完成。
