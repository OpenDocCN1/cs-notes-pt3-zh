# DeepSeek 新手上路 (二) 模型自部署



> 前言：笔者最开始接触LLM还是在22年底，当时INT8量化红极一时。 后来转战LLM训练，Zero&张量并行&流水线并行 方兴未艾，再到封闭平台的基础Framework/算子支持，逐渐被LLM应用侧的先进work远远甩开辣，重新变新手上路，也给其他新手佬友提供些思路。

简单记录下在计算集群上自部署DeepSeek的过程。

- 自部署的目的是：



告别 服务器繁忙

需要借助模型完成 隐私敏感型任务

乐于折腾+真的好玩

刚好能接触到一些 有一定算力的硬件

评估硬件性能及提供内部服务的可能性

## 1. 工具及模型选择

本地部署模型并不复杂，主要矛盾是佬友们日益增长的高质量模型需要同孱弱的个人硬件性能之间的矛盾。

部署工具方面已经非常成熟，笔者大致扫了下当前关于DeepSeek本地部署的文章和教程，主流的部署工具一般会选择：

- [Ollama](https://ollama.com/)

- [LM Studio](https://lmstudio.ai/)

- [llama.cpp](https://github.com/ggerganov/llama.cpp)



[开源大模型的本地部署,本地大语言模型部署工具对比：Ollama vs LM Studio 如何选择适合自己的 AI 助手](https://linux.do/t/topic/414577)



有佬友简单对比过这两个工具的差异，看起来LM Studio貌似更加友好、功能全面一些，也包含了一些Hugging Face等来源的多样化模型。Ollama更加轻量，提供了模型下载到部署到用户端供给的全流程，Ollama采用了llama.cpp作为底层库。



此外，传统老牌库llama.cpp也可以直接部署DeepSeek，只不过功能上较为简陋一些。



笔者部署任务所采用的系统环境为Ubuntu 20/22，更喜欢轻量一些的环境，于是选择了Ollama。

模型选择上，当然是满血模型啦，部署时跑个Q4量化，671 我来啦![:hot_face:](img/1cffd6175544f404158ba2116cf8a60a.png)

## 2. 部署实践

ollama提供了完整的下载-运行 脚手架，最简单的模型部署只需要



1.下载ollama(打开冰箱)，2.使用ollama下载模型(把大象塞进去)，3.运行模型(关上冰箱)。

#### 2.1 ollama 安装

官方给出了懒人一键安装，但ollama安装到/usr/local位置(注意权限)

```
curl -fsSL https://ollama.com/install.sh | sh
```

由于权限问题，笔者选择手动安装。

```
# 如果服务端没有网络 可以本地下载(约1.6G) 远程rsync/scp/sftp
curl -L https://ollama.com/download/ollama-linux-amd64.tgz -o ollama-linux-amd64.tgz
mkdir -p ~/opt/ollama
tar -zxf ollama-linux-amd64.tgz -C ~/opt/ollama
# 打开.zshrc之类 添加环境变量
export PATH=~/opt/ollama/bin/:$PATH
export LD_LIBRARY_PATH=~/opt/ollama/lib:$LD_LIBRARY_PATH
#写完soruce下
source ~/.zshrc
```

检查ollama能否正常运行：

```
# 查看 版本
ollama -v
# 起一个tmux窗口，启动 ollama
ollama serve
```

#### 2.2 模型下载

模型文件 可以通过 ollama 脚手架下载，例如：

```
ollama pull deepseek-r1:671b
```

可以参见ollama支持的[DeepSeekR1模型列表](https://ollama.com/library/deepseek-r1/tags)。这里简单说下671B模型的几个版本：

- `671b` ：指向的是`671b-q4_K_M` ，约404GB。

- `671b-fp16`： fp16格式未经量化版本，模型大小约1.3TB。

- `671b-q8_0`：8位量化版本，模型大小约713GB。

- `671b-q4_K_M`：4位量化版本，模型大小约404GB。

其余蒸馏阉割版本请自行查阅，笔者下载了q4和q8的版本。

![1882×216 36.9 KB](https://cdn3.ldstatic.com/original/4X/3/6/1/3615b740a6e47ac14d0b68605a493d1df8126bd9.png)

当然也可以直接在[huggingface/deepseek-ai](https://huggingface.co/deepseek-ai/DeepSeek-R1) 或者 [modelscope/deepseek-ai](https://modelscope.cn/models/deepseek-ai/DeepSeek-R1/)上进行下载`safetensors`格式的模型，再本地导入到其他的工具(例如ollama)中。

```
mkdir models && cd models

## 方案一 git 下载
git lfs install
git clone https://www.modelscope.cn/deepseek-ai/DeepSeek-R1.git

## 方案二 modelscope 脚手架下载
pip install modelscope
modelscope download --model deepseek-ai/DeepSeek-R1
```

如果使用llama.cpp，可以在[huggingface/unsloth](https://huggingface.co/unsloth/DeepSeek-R1-GGUF)下载`GGUF`格式的模型，再本地导入。

可以参考 [Ollama导入本地模型(Safetensors/GGUF)](https://github.com/qianniuspace/ollama-doc/blob/main/ollama/docs/Ollama%20%E5%AF%BC%E5%85%A5%E6%A8%A1%E5%9E%8B.md)。

#### 3.2 vLLM尝试

参考 [vLLM-docs](https://docs.vllm.ai/en/latest/getting_started/installation/gpu/index.html)进行环境安装。



前提环境：

- CUDA (12.1)

- GPU: compute capability 7.0 or higher (V100/RTX20系起步)

```
conda create -n vllm python=3.12 -y
conda activate vllm
pip install vllm
```

之前一位佬友提到想测下70B模型的环境，这里就选它。 (如果服务器能正常访问hugging face可跳过该步骤)下载模型 70BLLaMA蒸馏的未量化版本(约140+GB)。

```
pip install modelscope
modelscope download --model deepseek-ai/DeepSeek-R1-Distill-Llama-70B --local_dir <your_local_path>
```

默认会安装到`~/.cache/modelscope/`中。

模型运行可直接使用 vllm的[openAI-Compatible Server](https://docs.vllm.ai/en/stable/serving/openai_compatible_server.html)，参考其中的CLI工具 `vllm-serve`。



给一组运行命令，eg：

```
#自动从hugging face下载并运行模型
vllm serve  "deepseek-ai/DeepSeek-R1-Distill-Llama-70B" --tensor-parallel-size <GPU_num>  --trust-remote-code --host 0.0.0.0 --port <your_port> --served-model-name <customed-model-name>

#运行本地模型
vllm serve  <path/to/your/local/model> --tensor-parallel-size <GPU_num> --trust-remote-code --max-model-len 4096 --host 0.0.0.0 --port <your_port> --served-model-name <customed-model-name>
```

成功运行后，会在服务器的对应port提供服务，可以使用OpenAPI的API接口规范进行请求， `serverd-model-name`就是post请求时传的model名，不指定就默认用`--model`的名字(本地模型得包含路径就会很奇怪)。当然，你也可以在运行时添加 `--api-key <key content>` ，来要求使用者提供api_key，默认无需key。

#### 3.3 模型格式相关

在搞推理部署的时候，经常会遇到下载源提供不同模型格式，或者不同框架要求不同格式，这里补充点最近踩的坑，欢迎佬友们补充：



笔者目前遇到了如下格式：

- ollama 下载的模型 (格式未知)

- GGUF 格式 (llama.cpp、 Ktransformers、vllm)

- safetensors格式 (llamacpp、 vllm)

Notes:

- ollama 可以使用 GGUF格式，但是需要手写一个Modelfile；safetensors格式要先转gguf。

- vllm 对GGUF支持有限，目前只支持读取单个gguf文件，多gguf文件需要合并。

- ktransformers 看官方示例和issue区讨论，尚未找到关于safetensors的支持。ktransformers部署模型需要两部分：



gguf格式的模型(`--gguf_path`)

模型/tokenizer配置文件等(`--model_path`)，通常可以在safetensors格式模型的同目录下找到。如果需要本地下载(比如魔搭)，可以通过 `--exclude`来排除safetensors格式文件。



`modelscope download --model deepseek-ai/DeepSeek-R1 --exclude "*.safetensors"`

无论是格式转换，还是gguf的合并与切割，都可以使用llama.cpp中提供的工具。



llamacpp构建

```
git clone https://github.com/ggerganov/llama.cpp.git
cd llama.cpp
#CPU版编译 (并行编译自行 -j<core_num> )
cmake -B build #GPU则附 -DGGML_CUDA=ON
cmake --build build --config Release

#如需要python工具
conda create -n llamacpp python=3.10 -y
conda activate llamacpp
pip install -r requirements.txt
```

safetensors 转 tensor可以参考如下：

```
cd llama.cpp
./convert_hf_to_gguf.py <safetensors_model_path> --outfile  xxx.gguf
```

gguf合并时，多个gguf文件的名字应符合规范，例如`model-00001-of-00003.gguf` …`model-00003-of-00003.gguf`，只需要传`model-00001-of-00003.gguf`即可。



可以参考如下：

```
cd llama.cpp/build/bin
./llama-gguf-split --merge /path/model-00001-of-00003.gguf /path/model-merge.gguf

#split 同理，可以支持按tensor或者size进行分割
./llama-gguf-split --split --split-max-size 40G /path/model-merge.gguf /path/model-split/
```

在实际测试中，我分别使用vllm加载了hf下载的safetensors权重、自行使用llamacpp转换到gguf的权重、hf的gguf分割权重并用llamacpp合并gguf的权重，**模型推理速度与模型输出效果，并无明显差异。**

此外，还可以根据你现有的高精度版本模型来本地量化得到其他版本，例如：

```
cd llama.cpp/build/bin
./llama-quantize <old_model_gguf> <new_model_gguf> <quantize_method>
#例如，对fp16量化得到常见的Q8_0和Q4_K_M
./llama.cpp/quantize DeepSeek-70B-FP16.gguf DeepSeek-70B-Q8_0.gguf Q8_0

./llama.cpp/quantize DeepSeek-70B-FP16.gguf DeepSeek-70B-Q4_K_M.gguf Q4_K_M
```
