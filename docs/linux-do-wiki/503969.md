# 运维监控：prometheus+grafana+alertmanager



# prometheus监控虚拟机

## 简介

	Prometheus的基本原理是通过HTTP协议周期性抓取被监控组件的状态，任意组件只要提供对应的HTTP接口就可以接入监控。输出被监控组件信息的HTTP接口被叫做exporter，比如node_exporter（监控服务器本身）、mysqld_exporter（监控mysql服务）。基于时间序列数据库TSDB存储，默认存储15天数据。

	Alertmanager 用于管理和处理警报。它接收警报、去 重、分组、抑制并通过多种方式发送通知。

	Prometheus中的告警规则允许你基于PromQL表达式定义告警触发条件，Prometheus后端对这些触发规则进行周期性计算，当满足触发条件后则会触发告警通知。默认情况下，用户可以通过Prometheus的Web界面查看这些告警规则以及告警的触发状态。当Promthues与Alertmanager关联之后，可以将告警发送到Alertmanager中，并通过Alertmanager可以对这些告警进行进一步的处理。

	Grafana 是一个开源的可视化平台，广泛用于展示和分析时间序列数据。在此案例中，使用prometheus为数据源，将prometheus获取到的指标通过图形化进行展示。

## 部署

可以通过源码包部署，也可以通过容器部署，本次采取通过docker来部署prometheus、alertmanager、grafana。

prometheus对时间很敏感，所以时间同步必须做。

### 1.部署prometheus

### 创建目录用于promehtues配置文件和数据的持久化

```
mkdir -p /data/prometheus/config && mkdir -p /data/prometheus/data
chmod 777 /data/prometheus/data #由于prometheus要写入数据到该目录，所以需要权限。
```

### 默认配置文件

/data/prometheus/config/prometheus.yml

```
# my global config
global:
  scrape_interval: 15s # Set the scrape interval to every 15 seconds. Default is every 1 minute.
  evaluation_interval: 15s # Evaluate rules every 15 seconds. The default is every 1 minute.
  # scrape_timeout is set to the global default (10s).

# Alertmanager configuration
alerting:
  alertmanagers:
    - static_configs:
        - targets:
          # - alertmanager:9093

# Load rules once and periodically evaluate them according to the global 'evaluation_interval'.
rule_files:
  # - "first_rules.yml"
  # - "second_rules.yml"

# A scrape configuration containing exactly one endpoint to scrape:
# Here it's Prometheus itself.
scrape_configs:
  # The job name is added as a label `job=<job_name>` to any timeseries scraped from this config.
  - job_name: "prometheus"

    # metrics_path defaults to '/metrics'
    # scheme defaults to 'http'.

    static_configs:
      - targets: ["localhost:9090"]
```

### docker运行prometheus命令

```
docker run \
    --name prometheus \
    --restart always \
    -p 9090:9090 \
    -v /data/prometheus/config:/etc/prometheus \
    -v /data/prometheus/data:/prometheus \
    -d prom/prometheus
```

–name：指定容器名字，这里名字是prometheus

-p：端口映射，宿主机端口:容器

-v：将本地目录或者文件挂载到容器内，宿主机目录：容器目录

-d：后台运行

prom/prometheus：镜像名称

### 配置文件

/data/alertmanager/alertmanager.yml

```
global:
  resolve_timeout: 5m # 告警恢复后的等待时间
  smtp_smarthost: 'smtp.163.com:25' # SMTP 服务器地址和端口
  smtp_from: 'zhanghao96z@163.com' # 发件人邮箱
  smtp_auth_username: 'zhanghao96z@163.com' # SMTP 认证用户名
  smtp_auth_password: 'NBKZWEGJUKWQWFMK' # SMTP 认证密码
  smtp_require_tls: false # 不强制使用 TLS 加密

templates:
  - './*.tmpl'  # 模板的路径

route:
  group_by: ['alertname'] # 按照告警名称分组,比如两个主机都告警cpu使用率超过80%,那么会合成一个告警,里面有两个ip。
  group_wait: 30s # 在新的一组告警被创建时,等待至少 30 秒才发送初始通知。
  group_interval: 10s # 当第一个通知发送后,等待 5 分钟(为了测试改为10s)才发送该组中新触发的一批告警。
  repeat_interval: 10s # 成功发送了告警后再次发送告警信息需要等待的时长。
  receiver: 'webhook_and_email' # 默认接收者

receivers:
  - name: 'webhook_and_email' # 接收者名称
    webhook_configs: # webhook
      - url: 'http://10.0.0.80:8000/api/webhook'

    email_configs: # email
      - to: 'zhanghao96z@126.com'
        html: '{{ template "email.html" .}}'
        send_resolved: true

#下面这段配置的意思是：如果有一个严重级别（critical）的告警存在，那么在相同的alertname和instance标签下，警告级别（warning）的告警将会被抑制，不会单独发送警报。这样可以避免同时收到多个告警，特别是当严重告警已经存在时，警告级别的告警会被抑制。
inhibit_rules:
  - source_match:
      severity: 'critical' # 源告警的严重性为 critical
    target_match:
      severity: 'warning' # 目标告警的严重性为 warning
    equal: ['alertname', 'instance'] # 匹配相同的告警名称和实例，抑制目标告警
```

### 接收告警信息的服务

```
from fastapi import FastAPI, Request
from datetime import datetime, timedelta
import requests
import json

app = FastAPI()

def time_conversion(utc_time_list: list) -> list:
    china_time_list = []
    for utc_time_str in utc_time_list:
        utc_time = datetime.strptime(utc_time_str, '%Y-%m-%dT%H:%M:%S.%fZ')
        china_time = utc_time + timedelta(hours=8)
        china_time = china_time.strftime('%Y-%m-%d %H:%M:%S')
        china_time_list.append(china_time)
    return china_time_list

def send_feishu_msg(alertname, china_time_list, instance, description, severity):
    bot_url = "https://open.feishu.cn/open-apis/bot/v2/hook/f8333530-f12a-41e9-af89-5c4b1ee1587a"
    headers = {
        "Content-Type": "application/json"
    }
    payload = {
        "msg_type": "post",
        "content": {
            "post": {
                "zh_cn": {
                    "title": "告警通知",
                    "content": [
                        [{
                            "tag": "text",
                            "text": f"告警名称: {alertname}\n开始时间: {china_time_list}\n实例: {instance}\n详细: {description}\n程度: {severity}",
                        }]
                    ]
                }
            }
        }
    }
    res = requests.post(url=bot_url, headers=headers, json=payload)

    print("Status Code:", res.status_code)
    print("Response Body:", res.text)

@app.post("/api/webhook")
async def webhook(request: Request):
    body = await request.body()
    data = json.loads(body.decode("utf-8"))

    alertname = data["alerts"][0]["labels"]["alertname"]
    severity = data["alerts"][0]["labels"]["severity"]
    utc_time_list = [alert["startsAt"] for alert in data["alerts"]]
    china_time_list = time_conversion(utc_time_list)
    if len(data.get("alerts")) >= 2:
        instance = [alert["labels"]["instance"] for alert in data["alerts"]]
        description = [alert["annotations"]["description"] for alert in data["alerts"]]
    else:
        instance = data["alerts"][0]["labels"]["instance"]
        description = data["alerts"][0]["annotations"]["description"]
    #print({"告警名称": alertname, "开始时间": china_time_list, "实例": instance, "详细": description, "程度": severity})
    send_feishu_msg(alertname, china_time_list, instance, description, severity)
    return {"status": "received"}
```

### /data/prometheus/config/rules/node_rules.yml

可以参考，开箱即用：[Awesome Prometheus alerts | Collection of alerting rules](https://samber.github.io/awesome-prometheus-alerts/)

```
groups:

- name: node_exporter_rules
  rules:
  #node_exporter服务down了
  - alert: InstanceDown
    expr: up == 0
    for: 5s
    labels:
      severity: critical
    annotations:
      summary: "Instance {{ $labels.instance }} down"
      description: "{{ $labels.instance }} of job {{ $labels.job }} has been down for more than 5s."

  #内存剩余小于10%
  - alert: HostOutOfMemory
    expr: (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100 < 10) * on(instance) group_left (nodename) node_uname_info{nodename=~".+"}
    for: 5s
    labels:
      severity: warning
    annotations:
      summary: Host out of memory (instance {{ $labels.instance }})
      description: "Node memory is filling up (< 10% left)  VALUE = {{ $value }}  LABELS = {{ $labels }}"

  #cpu load > 80%
  - alert: HostHighCpuLoad
    expr: (sum by (instance) (avg by (mode, instance) (rate(node_cpu_seconds_total{mode!="idle"}[2m]))) > 0.8) * on(instance) group_left (nodename) node_uname_info{nodename=~".+"}
    for: 5s
    labels:
      severity: warning
    annotations:
      summary: Host high CPU load (instance {{ $labels.instance }})
      description: "CPU load is > 80%  VALUE = {{ $value }}  LABELS = {{ $labels }}"
```
