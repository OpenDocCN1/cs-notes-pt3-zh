在写复杂项目时很可能产生同名变量，一般可以通过分模块来**解决命名冲突**。

C++20标准之前，C++没有专门的模块语法，而是使用其他语法特性来表示，命名空间就是其中之一。

# ◢ 命名空间

命名空间是C++提供的**自定义作用域**机制，使用语法为：

```
namespace [命名空间名]{
    // 内容，可填任意对象的定义
}
```

命名空间会将定义放在指定作用域内，**限定访问方式**。

以下述命名空间为例，

```
namespace n1{
    int a;
}
```

有三种访问方式：

- **显示限定访问**



直接使用**作用域限定符**`::`告诉编译器到哪个作用域[名字查找](https://linux.do/t/topic/716778/7)指定变量。`n1::a = 1; `

- **using声明**



在所在作用域中将`n1::a`在名称查找中视为无限定。`using n1::a;    // 视为a变量 a = 1; `

- **using编译指令**



在所在作用域中将`n1`中所有变量在名称查找中视为无限定。`using namespace n1; a = 1; `

## ❖ 访问方式最佳实践

using声明和指令将命名空间开放查找，使得命名空间失去作用。

我们要明晰什么时候才使用：

- **一般使用显式限定**。

- using声明：仅在**局部作用域**中当显式限定影响可读性时使用。

- using指令：在完全了解有什么成员（免得命名冲突）的情况下，且显式限定影响可读性时在**局部作用域**中使用。**禁止在头文件中使用**，这种做法是将命名冲突扩散到所有用到该头文件的文件中，很危险。

| 访问方式 | 实践推荐 |

| --- | --- |

| 显式限定 | 常用 |

| using声明 | 局部作用域+限定麻烦 |

| using指令 | 局部作用域+限定麻烦+了解成员+**禁止**头文件 |

## ❖ 使用

**嵌套使用**:

```
namespace n1{
    namespace n2{
        int a;
    }
}

// 显式限定
n1::n2::a;
// using声明
using n1::n2::a;
// using指令
using namespace n1::n2;
```

注意，命名空间**不能定义在类定义和函数定义中**，一般放在全局作用域中。

**别名使用**：



当命名空间名字过长或者嵌套过长时，可以取别名再使用，格式为`namespace <别名> = 原名`：

```
namespace n1{
    namespace n2{
        int a;
    }
}

namespace n2 = n1::n2;
n2::a = 1;
```

注意，不要和[类型别名](https://linux.do/t/topic/716778/8)的取名混淆。

**匿名使用**



`namespace [命名空间名]{}`的`[]`指可选。



当不写名字时，编译器默认分配一个[翻译单元](https://linux.do/t/topic/716778/9)独有标识符来命名这个空间。

匿名命名空间视为**定义后直接使用using指令**，即：

```
namespace{
    int a = 1;
}
```

等价于：

```
namespace $$${    // $$$为编译器分配的独有标识
    int a = 1;
}
using namespace $$$;
```

其他[翻译单元](https://linux.do/t/topic/716778/9)因为不知道这个标识，具有内部链接，因此无法访问里面的变量，即**仅本翻译单元可见**。

## ❖ 特性

**开放性**:



**同一作用域**下，同名命名空间视为同一个。

```
namespace n1{
    int a;
}
// 此时可以访问n1::a
namespace n1{
    int b;
}
// 此时可以访问n1::a和n1::b
```

注意：**别名不具有开放性**，无法添加成员：

```
namespace n1{
    int a;
}
namespace n2 = n1;
namespace n2{    // 报错
    int b;
}
```

限定符也不具有开放性：

```
namespace n1{
    int a;
}
n1::b = 1;  // 报错而不是添加
```

## ❖ 附带作用

**组织代码**



当接口组使用，把相关联的功能放到同一个命名空间中。

**最佳实践**：除main外所有实体应该处于一个命名空间中。

**版本控制**



将不同版本嵌套到定义中，使用`inline`指定使用哪个版本：

```
namespace App{	// App有V1,V2两个版本
    namespace V1{
        int data = 1;
    }

    inline namespace V2{	// 使用inline指定使用V2版本
        int data = 2;
    }
}
```

使用上就行直接定义在`App`中，但也可以显式指定调用的版本：

```
a = App::data;	// a获得2

// 依旧保留显式调用方法
a = App::V1::data;	// a获得1
a = App::V2::data;	// a获得2
```

注意，不可以同时`inline`多个版本，会报错。

## ❖ 全局命名空间

全局命名空间的名字视为空字符串

```
int a = 1;

int main() {
    a = 2;
    ::a = 3;  // 空字符串来限定作用域
    return 0;
}
```

当局部变量将全局变量遮蔽时，可以使用该方法访问全局变量：

```
int a = 1;

int main() {
    int a = 2;
    a;   // 值为2，遮蔽全局变量
    ::a; // 值为1
    return 0;
}
```
