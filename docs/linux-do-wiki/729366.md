c++中，广义的对象指的是**内存上的一片空间**。

对象的值是这边内存空间中**保存的数据**。

左值则是**表示对象**的一条表达式，**左值不是对象的值，是表达式的一种**。
```
int* arr;
// arr是表达式，代表一个在内存上的指针对象，是左值
// arr+1是表达式，代表下一个元素对象地址，是计算结果，不是左值
```
c++11在程序语言设计一书中将表达式根据**是否有身份i**和**是否可移动m**（即资源转移，下文会讲）分为三种范围不重叠的：
- lvalue：左值，有身份不可移动。
- xvalue：特殊值，有身份可移动。
- prvalue：纯右值，无身份可移动。
然后将左值和特殊值统称为广义左值，将特殊值和纯右值统称为右值，如图：
[image2804×1044 123 KB](https://cdn3.ldstatic.com/original/4X/f/d/7/fd76dfd5d1b4691064055da8524c97c142a5a6fc.png)
一般我们根据经验判断的“**能取地址是左值，不能取地址是右值**”严格来说应该是对广义左值和纯右值的区分。
标准意义上的左右值区分应该是是否可移动，但一来其判断没那么直观，二来xvalue的取地址方法比较取巧（后面会提），一般不允许直接取址，所以在不想取址xvalue的场景下直接用上述经验判断就行，**通用于大多数场景**。
为了直观通义。下文中的**左右值将采用标准中的定义**进行讨论。
在讲移动语义之前需要引入**引用**。
# ◢ 引用
从[指针与数组](https://linux.do/t/topic/724224)继续讨论，在使用指针时会受到包括但不限于的下述困扰：
- 使用麻烦，使用成员要用`->`，取值要解引用。
- 需要判空nullptr
- 需要判断指向是不是被意外更改了
- 使用函数要专门看定义是传值`fun(a)`还是传地址`fun(&a)`
为解决指针使用麻烦的问题，c++引入了引用的概念。
---
引用在**逻辑上**可以视为变量的别名，但一般底层还是指针实现的。
有的编译器将引用实现为**自动解引用的T* const p指针**，虽然标准没有规定怎么实现，但我们可以借由这样的实现来推测学习引用的特性。
- 自动解引用：对引用的所有操作都相当于作用在解引用后的原变量之上，即直**接作用在原变量内存空间上**。

所有操作的操作对象会依据底层存储的地址**间接寻址**到原变量内存空间生效，包括取址符，对引用的取址得到的是原变量的地址。

引用本身的地址被编译器隐藏，一般手段无法访问，一种方法是使用C的强制转换引用为地址类型，此时的取址就是引用本身的地址，存的值是原变量的地址。
- `T* const p`：即指针的指向为常量不可改，而常量的特性就是要定义时初始化。

那么可知，**引用定义时必须绑定到左值对象上**（即有身份，在内存上有一片空间），且**绑定后不可改**（指向是常量）。
## ❖ 引用作为函数参数
引用有操作自动解引用指针的特性，传参不用拷贝原值，且函数对其的修改能反映到原变量上。

具有只是指向不变，并不是指向的值不可改，如果希望传入的引用不被修改，则加上const修饰，传入const引用即可。

注意const引用只是限制**不能通过**引用修改原变量，**没有限制原变量的直接修改**。
```
int a = 1;
const int& b = a;   // 不能通过b改a
a = 2;  // 使用a仍可以改a，此时读取b为2
```
也就是你拿到了一个const引用，改不了值，但不意味着值不会变。
## ❖ 引用作为函数返回值
非引用返回的函数是复制值返回，而引用类型返回则是将返回的引用绑定到返回值本身。（当然在C++17/编译器优化下可能不是复制值返回，而是直接在调用者的接收变量内存上直接创建，在此不讨论）
```
int  fun1(){
    // ...
    return a;   // 会发生复制
}

int& fun2(){
    // ...
    return a;   // 不会发生复制 ，节省开销
}
```
注意不要返回**生命周期短于函数本身**的变量的引用，即不要返回栈帧中创建的变量的引用。
# ◢ 移动语义
上面说到函数不要返回生命周期短于变量的引用，那就意味着走普通拷贝传值返回。
这相当于因为a变量要被销毁了，创建一个b变量，把a的数据复制过去，再销毁a。这开销是极其不划算的，a的数据反正要销毁，不如直接把资源归属转移给b，省去复制和销毁的开销要方便许多。
[22d462fa412da3ce3fa740c0eab7f582626×406 36.6 KB](https://cdn3.ldstatic.com/original/4X/5/d/9/5d9ff02af0e73c08c80f7569aee3b35ba0e0afa4.jpeg)
c++的移动语义就提供了这样的机制。

首先这种“**马上被销毁，资源可被移走**”的特性在C++中指的就是右值。
c++特意为引用绑定右值设计了规则，允许右值绑定到const引用：
首先引用需要绑定到对象，则纯右值需要**物化为一个临时对象**才能绑定到引用。此时这个临时对象在内存有身份（虽然不能直接读地址），又具有右值可转移资源的特点，成为一个xvalue类型的右值。（C++11是所有prvalue都会生成其临时对象，而C++17是需要才会生成临时对象，这导致C++17中的prvalue不是可移动的）
其次，为防止引用绑定左右值产生语义混乱（主要体现在修改左右值的结果表现不同），引用不能直接绑定右值，要绑定也**要用const引用**表示不会对右值修改。
但const就不能转移其资源了，反而失去了右值的特性，此外也需要专门的右值类型来表示只接收可转移资源的对象，于是c++提供了右值引用`T&&`来承接右值。
无论是const引用还是右值引用，右值一旦绑定到引用上，它的**生命周期将延长至所绑定的引用销毁**。
## ❖ std::move
转移资源意味着省去一次资源的拷贝和释放，这是十分诱人的，理应给我左值也安排上才是。
[31fb2c731a4a7035ba3572a4e605eb931058×985 74.9 KB](https://cdn3.ldstatic.com/original/4X/3/e/5/3e5455a56c179a6b5355aa5dd8d7d373867323a0.jpeg)
类似于函数`return 0`转右值是从纯右值物化一个临时对象，然后承接的右值引用绑定到该右值对象上。而`std::move`转化的右值不会创建临时对象，而是右值引用绑到原左值对象上。
我上面说过一句话
> xvalue的取地址方法比较取巧
xvalue的取址方式就是通过绑定它的引用来取址：
```
int a = 1;
int&& b = std::move(a);
```

---
右值的取址可以通过绑定的引用取址，这就是为什么在前面说“**能取地址是左值，不能取地址是右值**”稍有瑕疵，不过一般没事不会去拿临时对象或者原左值对象的地址，直接那么认为问题不大。
## ❖ 绑定类型与隐式转换
对于下式
```
double b = 0.0;
int a = 0;
a = b;    // 隐式转换
```
隐式转换的实现细节是b先转换成int类型的**临时变量**，再拷贝（或移动）给a。
而非const引用由于不能绑定到右值，因此**非常量左值引用只能绑定到对应类型**，不能绑定到需要隐式转换且产生临时对象的类型，例如：
```
int a = 0;
double& b = a;  // 报错
```
那有没有不会产生临时对象的隐式转换呢？
[af53518536894369687706849751f575474×474 55 KB](https://cdn3.ldstatic.com/original/4X/b/b/2/bb220f94e6659bbbaf546f4d79ebf37663e935e3.jpeg)
```
struct Base {};
struct Derived : Base { };

int main() {
    Derived d;      // 子类对象
    Base& ref = d;  // 让父类引用绑定到子类对象

    return 0;
}
```
---
此外，右值引用设计目的之一就是区分左右值的承接类型，因此其**不能绑定左值**。
# ◢ 无尽的&
已知`int &`是引用，`int &&`是右值引用。

那我祭出`int &&&&&&&`
[image706×668 31.3 KB](https://cdn3.ldstatic.com/original/4X/f/8/5/f856c861fbc29de6121c52f119ee15965f28390a.jpeg)
很不幸，c++并不允许你在类型中写出`>=3`个数的&。

但是可以在模板中嵌套：
```
template<class T>
void foo(T&);           // 加一层 &
```
所以即使c++不让我们写多个连续&，在模板类型推导时也会不可避免的出现多个&的情况，此时c++根据下述规则进行处理：
- 引用的同类引用类型不变，即`&`+`&`=`&`；`&&`+`&&`=`&&`
- 左值引用优先于右值引用，即`&`+`&&` =`&`
很容易看到，如果模板形参设置的是`T&&`，那么传入左值就解释为左值，传入右值则解释为右值，不像传统函数传参后在函数内均视为左值：
```
template<class T>
void foo(T&&);           // 万能转发
```
# ◢ 实战
对于传统的交换函数，会在交换途中产生大量复制：
```
template <class T>
void swap(T& a,T& b){
    T temp{a};  // 拷贝一次到temp
    a = b;      // 拷贝一次到a
    b = temp;   // 拷贝一次到b
}
```
对于数据量大的T无疑是开销巨大的，而在使用移动语义后则不需要复制即可完成。
```
template <class T>
void swap(T& a,T& b){
    using std::move;
    T temp{move(a)};
    a = move(b);
    b = move(temp);
}
```
