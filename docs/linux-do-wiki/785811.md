## 链式代理

sing-box的链式代理相当简单暴力，如果你原来的节点信息如下：

```
    {
      "tag": "我是一只落地鸡",
      "type": "trojan",
      "server": "<xxx.com>",
      "server_port": <port_num>,
      "password": "<password>",
      "tls": {
        "enabled": true,
        "server_name": "<xxx.com>",
        "insecure": true
      }
    },
```

你只需要将它修改成

```
    {
      "tag": "我是一只落地鸡",
      "type": "trojan",
      "server": "<xxx.com>",
      "server_port": <port_num>,
      "password": "<password>",
      "tls": {
        "enabled": true,
        "server_name": "<xxx.com>",
        "insecure": true
      },
      "detour": "其他节点的tag或者代理分组tag"
    },
```

没错，只需要添加一个detour字段即可实现链式代理，并且这个字段支持sing-box客户端配置中的代理分组而非只是特定的节点，适用于任何sing-box支持的协议，如：vless+vision+reality，vless+reality+tcp_brutal，都只需要加一行detour即可。

因为这个特性，我们可以将节点的detour填写为"detour": “![:link:](img/b4a2bdf55da20064e573d1dd2d9837c2.png) 中继节点”，并对应的在客户端配置中增加一个tag为"![:link:](img/b4a2bdf55da20064e573d1dd2d9837c2.png) 中继节点"的代理分组，就可以实时为链式代理节点切换不同的前置了。

注：如果要将这个链式节点作为sub-store中的单条节点保存，须使用单行json模式，也就是mihomo的节点格式，形如：

```
{"name":"My Brutal Node","type":"vless","server":"server","port":443,"uuid":"uuid","network":"tcp","tls":true,"udp":true,"flow":"","reality-opts":{"public-key":"xxx","short-id":"xxx"},"client-fingerprint":"chrome","smux":{"enabled": true,"protocol":"smux","max-streams": 10, "padding": true, "brutal-opts": { "enabled": true, "up": 45, "down": 240 } },"servername":"www.microsoft.com", "xudp": true, "detour":"🔗 中继节点" }
```

我已经为你准备好了完整的配置模板+用于追加节点的js脚本（和上期一样在sub-store内使用，不同之处主要是排除了将链式节点追加到中继分组造成的回环问题）：[>>>点我获取完整配置模板+js脚本](https://github.com/LongLights/sing-box_template_merge_sub-store/tree/main/NoRegion)

## 自定义规则

我相信90%主力使用sing-box的朋友们都是通过手搓的配置跑裸核，或者是类似我第一期介绍的动态追加节点至配置模板的操作，而非是依赖gui软件提供的覆写功能（用过的都知道有多坑）。

这就造成了一个问题，你很可能准备了多套配置模板，用于不同的终端（他们之间主要是inbounds字段不同），如Linux、windows、iOS，因此当你修改自定义规则的时候，需要同时修改多套json。

依赖sub-store，可以很容易解决这个问题，你只需要在sub-store中存储一个名为“custom_rules.json”的文件，内容格式如下：

```
[
  {
    "port": 22,
    "outbound": "🚅 国内流量"
  },
  {
    "source_ip_cidr": "10.0.0.251/32",
    "outbound": "🚅 国内流量"
  },
  {
    "domain_suffix": ["7pzzv.us", "j03og.app"],
    "outbound": "🐋 默认节点"
  },
  {
    "domain_suffix": "dcard.tw",
    "outbound": "链式节点 | 台湾Akile"
  }
]
```

随后在sub-store存储的完整json配置下方添加脚本操作（不能使用远程js链接，只能完整复制这段脚本，如果用的配置模板不是我提供的，确保你的json配置中route.rules存在一条"clash_mode": “Global”）：

```
// 读取原始配置
const config = JSON.parse($content);

// 读取外部规则文件
const customRulesContent = await produceArtifact({
  type: 'file',
  name: 'custom_rules.json'
});

// 解析自定义规则
const customRules = JSON.parse(customRulesContent);

// 插入规则逻辑
const rules = config.route?.rules || [];
const insertIndex = rules.findIndex(rule => rule.clash_mode === "Global");

if (insertIndex !== -1) {
  rules.splice(insertIndex + 1, 0, ...customRules);
} else {
  rules.push(...customRules);
}

// ✅ 重要：写回最终构建内容
$content = JSON.stringify(config, null, 2);
```
