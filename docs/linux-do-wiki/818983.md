# 准备工作
对于 LobeChat 的 DB 版，正常的部署流程都需要包含三个模块的配置：
1. 数据库配置（注册neon）；
2. 身份验证服务配置（注册clerk）；
3. S3 存储服务配置（使用cf r2）。
## 零.部署一遍不含数据库版本
- 使用github 仓库的 Fork 按钮，Fork 本项目；
- 在 `Vercel` 上重新选择并部署。（ 直接使用 GitHub 账号登录即可，记得在环境变量页填入 `OPENAI_API_KEY`）
- 可以自己绑定域名（免费二级域名绑定会有问题）
### 启动自动更新
如果你在执行 `Upstream Sync` 时遇到错误，请尝试手动执再行一次
当你 Fork 了项目后，由于 Github 的限制，你需要手动在你 Fork 的项目的 Actions 页面启用 Workflows，并启动 Upstream Sync Action。启用后，你可以设置每小时进行一次自动更新。
[启动自动更新 S11920×1080 214 KB](https://cdn3.ldstatic.com/original/4X/8/1/a/81a5c21926a8f7bf98dca7e47dd7cec29d8aec73.jpeg)

> 图片来源于lobechat官网
如果你遇到了同步失败的情况，你需要手动重新点一次 「Update Branch」。

### 添加 `KEY_VAULTS_SECRET` 环境变量
该变量用于加密用户存储的 apikey 等敏感信息。你可以使用 `openssl rand -base64 32` （自行google如何使用）生成一个随机的 32 位字符串作为密钥。同样添加至vercel


填我们第一次部署的vercel分配的网址（如果绑定自定义域名就填自己域名）（知道为什么要先部署一遍了吧）
## 二、 配置身份验证服务
前往 [Clerk](https://clerk.com/) 注册并创建应用，获取相应的 Public Key 和 Secret Key。
### 在 Vercel 中添加公、私钥环境变量
添加 `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY` 环境变量。在菜单中点击「API Keys」，然后复制对应的值填入 Vercel 的环境变量中。
[image848×1233 46.3 KB](https://cdn3.ldstatic.com/original/4X/7/4/b/74bbf7c174f4dbc58c2db0b476657e0694acb32f.png)
[image2094×1257 191 KB](https://cdn3.ldstatic.com/original/4X/9/1/d/91dbaeff38ea62a74b9251e2994536e0549a4eaa.png)
此步骤所需的环境变量如下：
```
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=
CLERK_SECRET_KEY=
```
添加上述变量到 Vercel 中：
[在 Vercel 中添加 Clerk 公私钥环境变量|800x534.76856835306781858×1242 118 KB](https://cdn3.ldstatic.com/original/4X/f/f/c/ffcc672bd060002bcf1c7ea9aff3064c54a7e1b6.png)
### 在 Clerk 中创建并配置 Webhook
我们需要在 Clerk 的 Webhooks 中添加一个端点，告诉 Clerk 当用户发生变更时，向这个端点发送通知。
[Clerk 添加 Webhooks 端点|800x389.243277048155053198×1556 221 KB](https://cdn3.ldstatic.com/original/4X/f/2/7/f2727b603c7c906d9217de44e56c6234948bc0de.png)
在 endpoint 中填写你的 Vercel 项目的 URL，如 `https://your-project.vercel.app/api/webhooks/clerk`。然后在订阅事件（Subscribe to events）中，勾选 user 的三个事件（`user.created` 、`user.deleted`、`user.updated`），然后点击创建。
**URL 的https://不可缺失，须保持 URL 的完整性**
[添加 Clerk Webhooks 时，配置 URL 和用户事件|800x721.04121475054231844×1662 135 KB](https://cdn3.ldstatic.com/original/4X/b/c/4/bc4989798bf574b2079c52ef1ab74478eb1eefa0.png)
### 将 Webhook 秘钥添加到 Vercel 环境变量
创建完毕后，可以在右下角找到该 Webhook 的秘钥：
[查看 Clerk Webhooks 秘钥|800x515.00484027105522066×1330 180 KB](https://cdn3.ldstatic.com/original/4X/8/2/b/82bec36ea5b78c46c3b19861991be1319cf94e46.png)
这个秘钥所对应的环境变量名为 `CLERK_WEBHOOK_SECRET`：
shell
```
CLERK_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxxxx
```
将其添加到 Vercel 的环境变量中：
[在 Vercel 中 添加 Clerk Webhooks 秘钥|800x568.39779005524861810×1286 125 KB](https://cdn3.ldstatic.com/original/4X/9/4/7/9477bb2357463fc8a8db88e8f297bbd74a393ef7.png)
这样，你已经成功配置了 Clerk 身份验证服务。
## 三、 配置 S3 存储服务
S3 所指代的是指兼容 S3 存储方案，即支持 Amazon S3 API 的对象存储系统，常见例如 Cloudflare R2 、阿里云 OSS 等均支持 S3 兼容 API。
### 配置并获取 S3 存储桶
你需要前往你的 S3 服务提供商（如 AWS S3、Cloudflare R2 等）并创建一个新的存储桶（Bucket）。接下来以 Cloudflare R2 为例，介绍创建流程。
[Cloudflare R2 存储界面|800x395.67747298420622406×1190 114 KB](https://cdn3.ldstatic.com/original/4X/d/4/f/d4fdee39577b56b89da459be7a4096a565fc289d.png)
创建存储桶时将指定其名称(我建议lobechat），然后点击创建。
[image1675×1125 58.3 KB](https://cdn3.ldstatic.com/original/4X/6/7/0/67062dd26f417ca9a4e3498581098268c3d814d9.png)
### 获取存储桶相关环境变量
在 R2 存储桶的设置中，可以看到桶配置的信息：
[image1675×1186 71.5 KB](https://cdn3.ldstatic.com/original/4X/5/d/e/5ded4bc9d5391bb968ad04c93750084b13ca1237.png)
其对应的环境变量为：
```
# 存储桶的名称
S3_BUCKET=lobechat
# 存储桶的请求端点(注意此处链接的路径带存储桶名称，必须删除该路径)
S3_ENDPOINT=https://xxxxxxxxxxxxxxxxxxxxx.r2.cloudflarestorage.com
# 存储桶对外的访问域名
S3_PUBLIC_DOMAIN=https://s3-for-lobechat.your-domain.com
```
`S3_ENDPOINT`必须删除其路径，否则会无法访问所上传文件
### 获取 S3 密钥环境变量
你需要获取 S3 的访问密钥，以便 LobeChat 的服务端有权限访问 S3 存储服务。在 R2 中，你可以在账户详情中配置访问密钥：
[查看存储桶的访问秘钥|800x279.26829268292682624×916 117 KB](https://cdn3.ldstatic.com/original/4X/c/6/f/c6f4a7b9c5c1014f47b64cf42dffb2ad81c1cf01.png)
点击右上角按钮创建 API token，进入创建 API Token 页面
[创建对应 API token|800x197.583081570996972648×654 53.2 KB](https://cdn3.ldstatic.com/original/4X/f/7/0/f70d40eb4b9880de6dd5942c3a3894c611da8ed7.png)
鉴于我们的服务端数据库需要读写 S3 存储服务，因此权限需要选择`对象读与写`，然后点击创建。
[配置 API token 权限|800x564.25120772946852484×1752 206 KB](https://cdn3.ldstatic.com/original/4X/0/2/d/02d987875be7a11d1eaa072832fa5bb709455760.png)
创建完成后，就可以看到对应的 S3 API token
[复制 API token|800x573.8424045491472462×1766 176 KB](https://cdn3.ldstatic.com/original/4X/3/6/d/36d76e61fe34188213060ffa97bc04b3fe8352a2.png)
其对应的环境变量为：
```
S3_ACCESS_KEY_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
S3_SECRET_ACCESS_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```
### 在 Vercel 中添加对应的环境变量
不同 S3 服务商获取所需环境变量的步骤可能有所不同，但最终获得到的环境变量应该都是一致的：
URL 的`https://`不可缺失，须保持 URL 的完整性
小总结
```
# S3 秘钥
S3_ACCESS_KEY_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
S3_SECRET_ACCESS_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# 存储桶的名称
S3_BUCKET=lobechat
# 存储桶的请求端点
S3_ENDPOINT=https://xxxxxxxxxxxxxxxxxxx.r2.cloudflarestorage.com
# 存储桶对外的访问域名
S3_PUBLIC_DOMAIN=https://s3-dev.your-domain.com

# 桶的区域，如 us-west-1，一般来说不需要添加，但某些服务商则需要配置
# S3_REGION=us-west-1
```
然后将上述环境变量填入 Vercel 的环境变量中：
[在 Vercel 中添加 S3 的环境变量|800x575.85825027685481806×1300 167 KB](https://cdn3.ldstatic.com/original/4X/3/4/0/340f84783bcb386b4705be421e5026f1a192df48.png)
### 配置跨域（CORS)
在 R2 中，你可以在存储桶的设置中找到跨域配置：
[Cloudflare R2 的跨域设置|800x522.73068267066762666×1742 251 KB](https://cdn3.ldstatic.com/original/4X/3/c/5/3c574697f8f4c4125d5b7dc30812dd304b873ed6.png)
添加跨域规则，允许你的域名（在上文是 `https://your-project.vercel.app`）来源的请求：
[配置允许你的站点域名|800x437.96507213363712634×1442 82 KB](https://cdn3.ldstatic.com/original/4X/d/d/c/ddcf5c1a22daef73578a4ba90d21af2fb34f1816.png)
示例配置如下：
```
[
  {
    "AllowedOrigins": ["https://your-project.vercel.app(填写自己域名）"],
    "AllowedMethods": ["GET", "PUT", "HEAD", "POST", "DELETE"],
    "AllowedHeaders": ["*"]
  }
]
```
配置后点击保存即可。
