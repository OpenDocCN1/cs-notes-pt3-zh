# 调用大型语言模型（LLM）的API时状态码详解（水个帖子）

在调用大型语言模型（LLM）的API时，遇到的错误码绝大多数遵循标准的HTTP状态码规范，但其背后的具体原因与LLM的特性息息相关。
### 核心概念：HTTP 状态码 (HTTP Status Codes)
API 的报错号码绝大多数都遵循 HTTP 协议定义的状态码标准。这是一个由三位数字组成的代码，第一个数字定义了响应的类别：
- **1xx**: **信息性 (Informational)** - 表示服务器已接收到请求，正在处理。
- **2xx**: **成功 (Success)** - 表示请求已成功被服务器接收、理解、并接受。
- **3xx**: **重定向 (Redirection)** - 表示需要客户端采取进一步的操作才能完成请求。
- **4xx**: **客户端错误 (Client Error)** - 表示客户端的请求有语法错误或请求无法实现。
- **5xx**: **服务器错误 (Server Error)** - 表示服务器在处理一个有效请求时发生内部错误。
下面，我将详细列举并解释每个类别下最重要的状态码。
---
### 4xx 客户端错误 (Client Errors)
**这是最常见的“报错”类型，意味着问题出在发送请求的一方（比如你的代码、浏览器或App）。**
| 状态码 | 名称 (Name) | 通俗解释 | 常见原因及解决方法 |
| --- | --- | --- | --- |
| **400** | **Bad Request** | **请求无效** | 服务器无法理解你发送的请求。通常是请求的格式有问题。**检查：** 请求参数是否缺失、参数格式是否错误（如JSON格式不正确）、请求头是否规范。 |
| **401** | **Unauthorized** | **未授权/未认证** | 你需要先登录或提供有效的身份凭证（如Token、API Key）才能访问这个资源。**检查：** 是否在请求头中正确添加了`Authorization`字段，并且Token是否有效、未过期。 |
| **403** | **Forbidden** | **禁止访问** | 你已经登录（身份已被识别），但你没有权限访问这个资源。这是权限问题，不是身份问题。**检查：** 确认当前用户/API Key的角色和权限是否足够。联系服务提供方确认权限配置。 |
| **404** | **Not Found** | **未找到资源** | 你请求的URL地址或资源在服务器上不存在。**检查：** URL拼写是否正确、路径是否有效、请求的资源ID是否存在。这是最常见的错误之一。 |
| **405** | **Method Not Allowed** | **方法不允许** | 你使用了错误的HTTP请求方法。例如，一个只接受GET请求的URL，你却用了POST请求。**检查：** API文档，确认该URL支持哪种HTTP方法（GET, POST, PUT, DELETE等）。 |
| **406** | **Not Acceptable** | **无法接受** | 服务器无法根据你请求中`Accept`头指定的格式生成响应。比如你要求返回XML，但服务器只能生成JSON。**检查：** `Accept`请求头的内容，或尝试使用服务器支持的格式。 |
| **409** | **Conflict** | **请求冲突** | 请求与服务器当前状态冲突。例如，你要创建一个已存在的资源（如用户名已被注册）。**检查：** 你的操作是否会与现有数据产生冲突。 |
| **413** | **Payload Too Large** | **请求体过大** | 你发送的数据（如上传的文件）大小超过了服务器的限制。**解决方法：** 压缩数据，或检查API文档关于上传大小的限制。 |
| **415** | **Unsupported Media Type** | **不支持的媒体类型** | 你发送的请求体`Content-Type`服务器不支持。例如，你发送了XML数据，但服务器只接受`application/json`。**检查：** `Content-Type`请求头是否设置正确。 |
| **422** | **Unprocessable Entity** | **无法处理的实体** | 请求格式正确，但内容有语义错误。例如，你提交的表单中，所有字段都存在，但某个字段的值不符合业务规则（如邮箱格式错误）。这是400的更具体版本。 |
| **429** | **Too Many Requests** | **请求过多** | 你在单位时间内发送的请求次数超过了API的速率限制（Rate Limiting）。**解决方法：** 降低请求频率，或使用带有指数退避（Exponential Backoff）的重试策略。 |
---
### 5xx 服务器错误 (Server Errors)
**这类错误意味着问题出在服务器端，客户端的请求是有效的。通常客户端无法直接解决，但可以采取一些策略。**
| 状态码 | 名称 (Name) | 通俗解释 | 客户端应如何处理 |
| --- | --- | --- | --- |
| **500** | **Internal Server Error** | **服务器内部错误** | 这是最笼统的服务器错误。服务器在执行请求时遇到了意外情况，导致无法完成请求。通常是服务器代码Bug、数据库问题等。**处理：** 记录错误日志，稍后重试。如果持续出现，需联系API服务提供方。 |
| **502** | **Bad Gateway** | **网关错误** | 服务器作为网关或代理，从上游服务器收到了无效的响应。例如，Nginx后面的应用服务器挂了。**处理：** 通常是临时性问题，可以稍后重试。 |
| **503** | **Service Unavailable** | **服务不可用** | 服务器当前无法处理请求。通常是因为服务器过载或正在进行维护。**处理：** 服务器通常会返回`Retry-After`头告诉客户端何时可以重试。可以根据这个时间进行重试。 |
| **504** | **Gateway Timeout** | **网关超时** | 服务器作为网关或代理，未能及时从上游服务器获取响应。例如，Nginx等待应用服务器处理请求，但应用服务器处理太慢超时了。**处理：** 可以稍后重试，这通常表示后端服务压力大或有性能问题。 |
---
### 2xx 成功 (Success)
虽然不是错误，但理解它们对于判断API调用是否真正成功至关重要。
| 状态码 | 名称 (Name) | 解释 |
| --- | --- | --- |
| **200** | **OK** | 请求成功。对于GET和POST请求，响应中会包含相应的数据。 |
| **201** | **Created** | 请求成功，并且服务器创建了新的资源。通常在POST或PUT请求后返回。 |
| **202** | **Accepted** | 服务器已接受请求，但尚未处理完成。适用于异步任务或需要较长时间处理的请求。 |
| **204** | **No Content** | 请求成功，但响应体中没有内容。常用于DELETE请求或某些PUT更新操作。 |
---
### 3xx 重定向 (Redirection)
| 状态码 | 名称 (Name) | 解释 |
| --- | --- | --- |
| **301** | **Moved Permanently** | 永久重定向。请求的资源已永久移动到新URL。 |
| **302** | **Found** | 临时重定向。请求的资源临时移动到新URL。 |
| **304** | **Not Modified** | 未修改。资源自上次请求后未发生变化，客户端可使用缓存的版本。 |
