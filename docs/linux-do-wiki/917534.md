# 记录一些 claude code 的工作流以及 CLAUDE.md【持续更新】📚



最近浅浅研究了一下工作流五花八门，收集了几个还不错的。最终还是要根据自己场景来定制化自己的工作流。

欢迎各位佬友持续推荐和编辑！

## 工作流

- 站内佬的一个方法论 [研究 PRD / SPEC / BMAD，我们在追求什么](https://linux.do/t/topic/880712)

- BMAD-Method(多agents协作，自动维护上下文传递) [https://github.com/bmad-code-org/BMAD-METHOD](https://github.com/bmad-code-org/BMAD-METHOD) 优点是可以随便clear上下文有agent帮忙传递上下文。还不限制calude code一个工具可以和 cursor codex cli 等工具配合开发

- spec-workflow(类似kiro工作流) [GitHub - Pimzino/claude-code-spec-workflow: Automated workflows for Claude Code. Features spec-driven development for new features (Requirements → Design → Tasks → Implementation) and streamlined bug fix workflow for quick issue resolution (Report → Analyze → Fix → Verify).](https://github.com/Pimzino/claude-code-spec-workflow)

问题![:memo:](https://linux.do/images/emoji/twemoji/memo.png?v=15)：另外发现很多工作流都是定好需求基于prd文档开始定制开发，相当于先把需求定死。但是实际开发需求经常变，那么这些工作流维护的一大堆的文档也要变是个比较棘手的点，目前还没找到处理动态需求的工作流。
