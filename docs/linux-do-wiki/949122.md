# 笔记：Windows 透明代理的实现



从[ProxyCap和Proxifier类似，且支持UDP](https://linux.do/t/topic/890011)继续讨论：

体验了大概20天。据我所知的和一些刚刚查的资料，实现类Linux的透明代理（非TUN）主要有三：

1. 在用户空间实现的DLL注入 & API挂钩（DLL injection & API hooking）



拦截wininet.dll或ws2_32.dll，前者是HTTP层，后者是Winsock层。其中LSP (layered service provider)是微软提供标准化的Winsock注入机制。

2. 传统的编写内核驱动方案



针对L4的TDI Filter drivers和L2/L3的NDIS Intermediate and NDIS-hooking drivers，前者（Transport Driver Interface）是类似于Winsock的内核级接口，其前是afd.sys，其后是tcpip.sys，后者（Network Driver Interface Specification）是具体网卡驱动（NIC Driver）与tcpip.sys之间的发送和接收数据的统一接口，中间层驱动（NDIS Intermediate Driver）对tcpip.sys是微端口驱动，对网卡驱动是协议驱动， NDIS Hooking就是对关键函数拦截再修改，会违反内存完整性（HVCI）等Windows安全机制（内核层面的安全机制重要性不用我多说吧）。

可能你看不太懂，那么在这里梳理一下简化流程图：wininet.dll? → ws2_32.dll → LSPs → afd.sys → TDI Filter drivers → tcpip.sys → NDIS Layer: [ NDIS Intermediate/Hooking → NIC Driver ]



注：wininet.dll?表示这是可选的。

3. 更现代的WFP/LWF



因为TDI和NDIS带来了太多混乱，所以随着Windows Vista和NDIS 6.0的到来，WFP（Windows Filtering Platform）取代了 TDI Filter drivers， LWF（NDIS Lightweight Filter）取代了 NDIS Intermediate and NDIS-hooking drivers。

这一点与2一样是需要编写驱动的，因为是更现代的方案，所以拎出来。

一般来说，要实现透明代理，要么发生在用户空间，要么发生在内核空间的 TDI 附近。

# Q&A

- 为什么 Proxifier 不支持 UDP？

TCP是有状态的，UDP是无状态的。HTTP/HTTPS基于TCP协议，很显然无法支持UDP代理。SOCKS5协议支持UDP，前提是建立一个TCP连接作为控制通道，如果要支持UDP代理，难点是：协议混搭、状态管理（几乎是需要实现一个小型NAT路由器）、动态资源管理（需要超时机制释放资源）、数据包处理（封装与解封装），这些无疑会带来较高的延迟。如果 Proxifier 支持 Shadowsocks 那么问题或许可以解决，不过SOCKS是互联网标准，而Shadowsocks不是。
