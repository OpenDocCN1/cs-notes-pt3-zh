# GitHub删除幽灵通知教程

GitHub里面所有通知都已经归档了，但是还提示有通知。无法“Done”。这通常发生在相关仓库或 issue/PR 被删除，尤其是被标记为垃圾信息（Spam）并由官方清理后，但通知本身却“卡”在了收件箱里。本教程可以把这些幽灵通知都删除。
1. **确保已安装并登录 GitHub CLI**。如果未安装，可以参考 [官方文档](https://cli.github.com/) 进行安装，然后运行 `gh auth login` 登录。
2. **找到并删除特定的通知线程**：
- 运行以下命令，列出您所有通知的 ID、标题和仓库信息：
> `gh api notifications | jq '.[] | {id, title: .subject.title, repo: .repository.full_name}'`
- 在输出的结果中，找到那个无法清除的通知对应的 `id` (通常是一长串数字)。那个垃圾信息仓库的名称应该会很显眼。
- 复制这个 `id`，然后运行下面的命令来删除它（将 `$THREAD_ID` 替换为您复制的 ID）：
> `gh api --method DELETE notifications/threads/$THREAD_ID`
- 例如：`gh api --method DELETE notifications/threads/1234567890`
- 如果这条通知还在左侧仓库列表中“纠缠不休”，可以再运行以下命令取消对它的订阅：
> `gh api --method DELETE notifications/threads/$THREAD_ID/subscription`
