# C语言系统编程：17：流程管理 🚀

![](img/7c2376d561b54e62871032ab4edc06c7_1.png)

在本节课中，我们将深入学习进程管理。我们将打破一个贯穿整个学期的假设，即一个程序只对应一个进程。实际上，程序可以创建并与其自身的额外进程进行交互。这是构建像Shell这样的程序的基础，Shell能够根据用户请求执行其他程序。

![](img/7c2376d561b54e62871032ab4edc06c7_3.png)

## 系统级函数与进程管理

如果把Linux操作系统看作一个大型模块，那么系统级函数就是进入该模块的接口。这些特殊函数会进入操作系统内核，并请求操作系统代表用户进程执行工作。用户进程自身无法完成这些工作，可能是因为工作需要特殊权限、访问权，或者需要与某些硬件（如I/O）交互。

![](img/7c2376d561b54e62871032ab4edc06c7_5.png)

就像动态内存管理有四个核心函数（`malloc`、`calloc`、`realloc`、`free`）一样，进程管理也有四个核心函数：`fork`、`exec`家族、`wait`和`exit`。

![](img/7c2376d561b54e62871032ab4edc06c7_7.png)

## 创建子进程：`fork`函数

Shell是一个典型的例子，当用户请求执行一个程序时，它必须创建新进程。另一个例子是Web服务器，它在收到请求时，会将该请求的处理委托给一个新进程，以便服务器可以继续监听其他请求。

![](img/7c2376d561b54e62871032ab4edc06c7_9.png)

![](img/7c2376d561b54e62871032ab4edc06c7_11.png)

那么如何实现呢？我们使用“父进程”和“子进程”这种通用的层级术语来描述。

创建新进程的机制可能并不直观：父进程创建一个新进程，这个新进程实际上是父进程自身的精确副本。然后，子进程会发出一个命令，表示它不再想成为父进程，而是希望变成另一个程序。这就像是进程家族中的“青春期叛逆”。

![](img/7c2376d561b54e62871032ab4edc06c7_13.png)

### `fork`的工作原理

系统级函数`fork`用于创建一个新的、重复的进程。`fork`会创建一个父进程的精确副本，包括处理器状态、内存状态等，但有一个例外（稍后讨论）。这个副本是在父进程调用`fork`的那一刻创建的。

![](img/7c2376d561b54e62871032ab4edc06c7_15.png)

这意味着`fork`会返回两次：一次返回到调用它的父进程中，另一次返回到这个新创建的子进程中，子进程从`fork`返回处开始执行。

### 区分父进程与子进程

父进程和子进程之间唯一的区别在于`fork`的返回值。`fork`被调用一次但返回两次，因此可以有两个返回值：
*   子进程得到的返回值是 **0**。
*   父进程得到的返回值是 **子进程的PID**。

![](img/7c2376d561b54e62871032ab4edc06c7_17.png)

这个关键区别允许我们在程序中通过条件判断来区分当前代码是在父进程还是子进程中执行。

![](img/7c2376d561b54e62871032ab4edc06c7_19.png)

## 多进程并发执行

当有多个进程运行时，处理器会在它们之间频繁地进行上下文切换，给每个进程一种拥有自己私有控制流的错觉。在现代多核机器上，这些进程实际上可以并行运行。

![](img/7c2376d561b54e62871032ab4edc06c7_21.png)

现在，我们有多个进程并发地运行我们的程序。它们相互竞争资源，最显著的就是处理器的运行状态。让我们通过一个初始例子来观察。

### 示例分析：不确定的执行顺序

![](img/7c2376d561b54e62871032ab4edc06c7_23.png)

![](img/7c2376d561b54e62871032ab4edc06c7_25.png)

考虑以下程序：
```c
int main() {
    printf("1\n");
    fork();
    printf("2\n");
    return 0;
}
```
这个程序会向标准输出打印什么？我们来追踪一下。

![](img/7c2376d561b54e62871032ab4edc06c7_27.png)

程序开始时只有一个进程（父进程）。它打印“1”，然后调用`fork`。现在有两个进程（父进程和子进程），它们都位于程序中`fork`调用之后的位置。由于上下文切换是不确定的，我们无法预测哪个进程会先执行`printf("2\n")`。

![](img/7c2376d561b54e62871032ab4edc06c7_29.png)

*   **情况A**：如果子进程先运行，则输出顺序为：`1`（父进程）、`2`（子进程）、`2`（父进程）。
*   **情况B**：如果父进程先运行，则输出顺序为：`1`（父进程）、`2`（父进程）、`2`（子进程）。

两种情况的输出都是“1”后面跟着两个“2”，但两个“2”的顺序可能不同。在这个简单例子中，顺序无关紧要，因为输出内容相同。

![](img/7c2376d561b54e62871032ab4edc06c7_31.png)

然而，当代码根据`fork`的返回值进行不同操作时，执行顺序就变得至关重要了。在一般情况下，两个进程指令的所有可能交错顺序都是可能的执行路径，这使得预测程序行为变得复杂。

### 示例分析：数据独立性与写时复制

看另一个例子：
```c
int main() {
    int x = 1;
    pid_t pid = fork();
    if (pid == 0) {
        x--;
        printf("child: %d\n", x);
        exit(0);
    } else {
        x++;
        printf("parent: %d\n", x);
        exit(0);
    }
}
```
这个程序会打印什么？答案是：可能是“child: 0”然后“parent: 2”，也可能是“parent: 2”然后“child: 0”。顺序不确定。

![](img/7c2376d561b54e62871032ab4edc06c7_33.png)

![](img/7c2376d561b54e62871032ab4edc06c7_35.png)

这里引入了一个重要概念：**写时复制**。在`fork`发生时，父进程和子进程拥有完全相同的数据。只有当其中一个进程试图修改数据（如这里的`x`）时，操作系统才会为它们创建独立的数据副本。因此，子进程中对`x`的递减操作不会影响父进程中的`x`，反之亦然。从`fork`的那一刻起，它们就是独立的进程。

![](img/7c2376d561b54e62871032ab4edc06c7_37.png)

**关于`exit`的说明**：在子进程分支中，我们使用`exit(0)`而不是`return 0`。这是正确的，并且通常是更好的做法。如果使用`return`，且代码不在`main`函数中而是在深层调用栈里，子进程可能会意外地继续执行父进程的代码，导致两个程序副本同时运行，引发严重错误。使用`exit`可以确保进程立即终止。

![](img/7c2376d561b54e62871032ab4edc06c7_39.png)

![](img/7c2376d561b54e62871032ab4edc06c7_41.png)

![](img/7c2376d561b54e62871032ab4edc06c7_43.png)

## 控制执行顺序：`wait`函数

![](img/7c2376d561b54e62871032ab4edc06c7_47.png)

在上一个例子中，哪个进程先运行会影响输出顺序。如果我们受制于操作系统和CPU的调度，如何编写代码来满足程序对顺序的要求呢？

`wait`系统级函数可以挂起（暂停）一个进程的运行，直到它的一个子进程终止。一旦有子进程终止，父进程就会被唤醒并继续执行。这允许我们强制规定执行顺序。

![](img/7c2376d561b54e62871032ab4edc06c7_49.png)

### 使用`wait`的示例

![](img/7c2376d561b54e62871032ab4edc06c7_51.png)

考虑以下程序：
```c
int main() {
    pid_t pid = fork();
    if (pid == 0) {
        printf("child\n");
        exit(0);
    }
    wait(NULL);
    printf("parent\n");
    return 0;
}
```
无论操作系统选择让父进程还是子进程先运行，`wait`调用都保证了输出顺序永远是：
```
child
parent
```
*   如果父进程先运行，它会立即调用`wait`并进入等待状态，让子进程得以运行和打印。子进程退出后，父进程才被唤醒并打印。
*   如果子进程先运行，它会打印并退出。当父进程随后运行时，`wait`会立即返回（因为已有一个终止的子进程未被等待），然后父进程打印。

通过`wait`，我们成功地控制了进程的执行顺序。

## 孤儿进程与僵尸进程

即使不需要控制顺序，让父进程等待其所有子进程也被认为是良好的实践。如果父进程不等待，子进程可能会进入两种状态：**孤儿进程**或**僵尸进程**。

![](img/7c2376d561b54e62871032ab4edc06c7_53.png)

*   **孤儿进程**：一个仍在运行的进程，其父进程已经终止。父进程显然没有等待它。
*   **僵尸进程**：一个已经终止但尚未被父进程`wait`（或“收割”）的进程。

僵尸进程会一直存在，等待父进程来“收割”它们，这会占用系统资源。为了避免孤儿进程变成永久的僵尸进程，操作系统会安排一个“收养”进程（传统上是`init`进程，PID为1；现代Linux中可以是任何声明为“子收割者”的进程）来最终等待它们。

因此，良好的编程习惯是：父进程应该适时调用`wait`来回收其终止的子进程，避免产生僵尸进程。

![](img/7c2376d561b54e62871032ab4edc06c7_55.png)

## 改变程序身份：`exec`家族函数

![](img/7c2376d561b54e62871032ab4edc06c7_57.png)

如前所述，`fork`创建的子进程是父进程的副本。子进程可以通过调用`exec`家族的系统调用来“改变自己”，用另一个完全不同的程序替换当前正在运行的程序。这就像是进程的“快速换装”。

`exec`函数用新程序替换当前进程的代码段、数据段等。如果`exec`调用成功，**它永远不会返回**——进程从此开始执行新程序的代码。如果失败（例如指定的命令不存在），则会返回-1，程序应处理这种错误情况（通常调用`exit`）。

### `exec`示例

![](img/7c2376d561b54e62871032ab4edc06c7_59.png)

![](img/7c2376d561b54e62871032ab4edc06c7_61.png)

```c
int main() {
    char *cmd = "cat";
    char *argv[] = {"cat", "readme.txt", NULL};
    execvp(cmd, argv);
    // 如果execvp成功，下面的代码永远不会执行
    perror("execvp failed");
    exit(EXIT_FAILURE);
}
```
这个程序会尝试将自身转变为`cat`程序，并执行`cat readme.txt`命令。如果`cat`程序存在且可执行，原程序的后续代码将不会运行。

![](img/7c2376d561b54e62871032ab4edc06c7_63.png)

![](img/7c2376d561b54e62871032ab4edc06c7_65.png)

## 经典组合：`fork` + `exec` + `wait`

![](img/7c2376d561b54e62871032ab4edc06c7_67.png)

`fork`（创建子进程）、子进程中`exec`（执行新程序）、父进程中`wait`（等待子进程结束）这三者的组合极为常见，以至于有一个快捷函数`system`将它们封装起来。

![](img/7c2376d561b54e62871032ab4edc06c7_69.png)

### 实现一个简单Shell的核心逻辑

![](img/7c2376d561b54e62871032ab4edc06c7_71.png)

![](img/7c2376d561b54e62871032ab4edc06c7_73.png)

现在我们可以理解Shell（如`bash`）的内部工作原理了。Shell本质上就是一个大循环：
1.  **读取并解析**用户输入的命令。
2.  **`fork`** 创建一个子进程。
3.  **在子进程中**：调用`exec`执行用户指定的命令。
4.  **在父进程中**：调用`wait`等待子进程结束。
5.  清理（如果需要），然后**回到第1步**，开始新的循环。

![](img/7c2376d561b54e62871032ab4edc06c7_75.png)

![](img/7c2376d561b54e62871032ab4edc06c7_77.png)

以下是一个简化的伪代码/C代码混合示例：
```c
while (1) {
    // 1. 读取并解析命令
    char *cmd = read_command();
    char **argv = parse_arguments(cmd);

    // 2. 创建子进程
    pid_t pid = fork();
    if (pid == -1) {
        // 处理fork错误
        perror("fork");
        continue;
    }

    if (pid == 0) {
        // 3. 在子进程中：执行命令
        execvp(argv[0], argv);
        // 如果execvp失败
        perror("execvp");
        exit(EXIT_FAILURE);
    } else {
        // 4. 在父进程中：等待子进程
        wait(NULL);
        // 5. （可选）清理，然后循环继续
    }
}
```
**关于后台进程**：当我们在命令后加上`&`（如`ls &`）时，Shell不会等待该命令完成就立即返回提示符。这可以通过在`fork`后，父进程**不**立即调用`wait`来实现。父进程需要记录这些后台作业，并可能通过非阻塞的`wait`变体（如`waitpid` with `WNOHANG`）或通过处理`SIGCHLD`信号来定期检查并回收已终止的后台子进程。

## 总结 🎯

本节课我们一起深入学习了进程管理。我们首先打破了“一个程序一个进程”的假设，引入了父进程与子进程的概念。我们详细探讨了四个核心系统调用：
*   **`fork`**：创建当前进程的副本，是区分父子进程的基础。
*   **`exec`**：用新程序替换当前进程，实现“变身”。
*   **`wait`**：父进程等待子进程终止，用于控制执行顺序和回收资源。
*   **`exit`**：终止进程。

![](img/7c2376d561b54e62871032ab4edc06c7_79.png)

![](img/7c2376d561b54e62871032ab4edc06c7_81.png)

我们了解了**写时复制**机制如何保证`fork`后进程内存的独立性，以及不恰当管理子进程可能导致的**孤儿进程**和**僵尸进程**问题。最后，我们看到了如何将这些调用组合起来，实现像Shell这样的复杂程序的核心循环逻辑。掌握这些知识是理解操作系统多任务处理和构建高级应用程序的基础。
