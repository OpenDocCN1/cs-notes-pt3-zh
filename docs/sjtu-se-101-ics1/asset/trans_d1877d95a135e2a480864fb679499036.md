## 共享库

- 静态库的缺点
  - 在可执行文件中重复大量公共代码
    - 例如，每个 C 程序都需要标准 C 库
  - 在虚拟内存空间中重复大量代码
  - 系统库的小错误修复需要每个应用程序显式重新链接

## 示例 (1/3)

```
(a) addvec.o
void addvec(int *x, int *y, int *z, int n)
{
    int i;

    for (i = 0; i < n; i++)
        z[i] = x[i] + y[i];
}
```

## 示例 (2/3)

```
(b) multvec.o
void multvec(int *x, int *y,
int *z, int n)
{
    int i;

    for (i = 0; i < n; i++)
        z[i] = x[i] * y[i];
}
unix> gcc -c addvec.c multvec.c

```

## 共享库 — 解决方案

Unix> gcc -shared -fPIC -o libvector.so addvec.c multvec.c

- 共享库
- DLL（动态链接库）
- 成员
  - 在运行时动态加载到内存中，并
  - 在运行时链接到应用程序

## 共享库 — 解决方案

```
Unix>gcc -o p2 main2.c ./libvector.so
```

- 加载时链接
  - Linux 中的常见情况，由 ld-linux.so 自动处理
- 运行时链接
  - 在 Linux 中由用户使用 dlopen() 显式完成
- 共享库例程可以由多个进程共享。

## 位置无关代码（PIC）

- 允许多个正在运行的进程共享相同的库代码
  - 节省宝贵的内存资源
- 朴素方法：分配专用地址
  - 地址空间使用效率低
  - 难以管理
- 更好的方法：在任何地址加载和执行
  - 位置无关代码（PIC）
  - 使用 -fPIC 的 gcc

## 位置无关代码（PIC）

- 位置无关代码（PIC）
  - 内部定义的过程（可行）
    - PC 相对引用
  - 外部定义的过程和对全局变量的引用（不可行）
    - 间接引用
    - 全局偏移表（GOT）
      - 私有
      - 位于 .data 的开头

## 位置无关代码（PIC）

• PIC 数据引用

```
call        L1
L1:    popl    %ebx
       addl    $VAROFF, $ebx
       movl    (%ebx), %eax
       movl    (%eax), %eax
```

- 性能缺点（5 条指令）
- 对 GOT 的一次额外内存引用
- 一个额外的寄存器用于保存 GOT 条目
