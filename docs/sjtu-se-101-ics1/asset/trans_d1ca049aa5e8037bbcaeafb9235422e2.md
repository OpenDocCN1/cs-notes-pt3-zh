

## 字长
- 表示
  - 指针数据的正常大小
- 虚拟地址由
  - 这样一个字编码
- 虚拟地址空间的最大大小
  - 由字长决定的最重要的系统参数

## 字长
- 对于具有 n 位字长的机器
  - 虚拟地址的范围可以从 0 到 2ⁿ-1
- 当前大多数机器为 32 位（4 字节）
  - 地址限制为 4GB
  - 对于内存密集型应用来说变得太小了
- 高端系统为 64 位（8 字节）
  - 潜在可寻址 1.8 X 10¹⁹ 字节

## 字长
- 不幸的是
  - 它也曾被用来表示整数的正常大小
- 机器支持多种数据格式
  - 始终是字节的整数倍

## 数据大小
- **C 对象的大小（以字节为单位）**

| C 数据类型 | 32-bit | 64-bit |
|---|---|---|
| char | 1 | 1 |
| short | 2 | 2 |
| int | 4 | 4 |
| long int | 4 | 8 |
| long long int | 8 | 8 |
| char * | 4 | 8 |
| float | 4 | 4 |
| double | 8 | 8 |

## intN_t 和 uintN_t
- 另一类整数类型
  - 指定 N 位有符号和无符号整数
  - 由 ISO C99 标准引入
  - 在文件 stdint.h 中。
- 典型值
  - int8_t, int16_t, int32_t, int64_t
  - uint8_t, uint16_t, uint32_t, uint64_t
  - N 取决于实现

## 数据大小
- 使程序在不同机器和编译器之间可移植的困难
  - 程序对不同数据类型的确切大小敏感
  - C 标准对不同数据类型的数值范围设定了下限
  - 但没有上限

## 数据大小相关错误
- 使程序在不同机器和编译器之间可移植的困难
  - 程序对不同数据类型的确切大小敏感
  - C 标准对不同数据类型的数值范围设定了下限
  - 但没有上限

## 数据大小相关错误
- 32 位机器在过去 20 年里一直是标准
- 许多程序已被编写
  - 假设表中列出的“32 位”分配
- 随着 64 位机器的增加
  - 许多隐藏的字长依赖性表现为
    - 将这些程序迁移到新机器时的错误

## 示例
- 许多程序员假设
  - 声明为类型 int 的程序对象可用于存储指针
- 这对大多数 32 位机器来说运行良好
- 但在 64 位机器上会导致问题

## 虚拟内存
- 之前幻灯片中介绍的内存
  - 只是一个概念对象，并且
  - 实际上并不存在
- 它为程序提供了一个看似单一的字节数组
- 它是向机器级程序呈现的概念映像

## 虚拟内存
- 实际实现使用组合
  - 硬件
  - 软件
- 硬件
  - 随机存取存储器（RAM）（物理）
  - 磁盘存储（物理）
  - 特殊硬件（执行抽象）
- 软件
  - 和操作系统软件（抽象）
