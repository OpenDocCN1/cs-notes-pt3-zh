

## 常用函数的打包

- 如何打包程序员常用的函数？
- 数学、I/O、内存管理、字符串操作等。

## 常用函数的打包

- 目前的链接器框架下很尴尬：
  - 方案 1：将所有函数放在单个源文件中
    - 程序员将大的目标文件链接到他们的程序中
    - 空间和时间效率低下
  - 方案 2：将每个函数放在单独的源文件中
    - 程序员显式链接适当的二进制文件到他们的程序中
    - 更高效，但对程序员负担重

## 常用函数的打包

- 解决方案：静态库（.a 归档文件）
  - 将相关的可重定位目标文件连同索引一起串联成单个文件（称为归档）
  - 增强链接器，使其尝试通过在一個或多个归档中查找符号来解析未解析的外部引用
  - 如果归档成员文件解析了引用，则将其链接到可执行文件

## 静态库（归档）

![](img/b3f8b91675c485f1e811aa092ebbf3d4_800_0.png)

可重定位目标文件串联成一个文件的静态库（归档）。

可执行目标文件（仅包含从 p1.c 和 p2.c 调用的 libc 函数的代码和数据）

通过打包常用函数进一步提高模块化和效率（例如，C 标准库、数学库）

链接器有选择地仅将归档中程序实际需要的 .o 文件链接进去。

## 创建静态库

![](img/b3f8b91675c485f1e811aa092ebbf3d4_801_0.png)

归档器允许增量更新：

- 重新编译发生变化的函数并替换归档中的 .o 文件。

```
ar rs libc.a atoj.o printf.o ... random.o
```

## 使用静态库

- **E:**
  - 将合并形成可执行文件的可重定位目标文件
- **U:**
  - 未解析的符号
- **D:**
  - 在之前的输入文件中已定义的符号
- 最初全部为空

## 使用静态库

- 按命令行顺序扫描 .o 文件和 .a 文件。
- 当扫描目标文件 f 时，
  - 将 f 添加到 E
  - 更新 U、D
- 当扫描归档文件 f 时，
  - 解析 U
  - 如果 m 用于解析符号，则 m 被添加到 E
  - 使用 m 更新 U、D

## 使用静态库

- 如果扫描结束时未解析列表中仍有条目，则报错
- 问题：
  - 命令行顺序很重要！
  - 道理：将库放在命令行的末尾。

## 多重定义的全局符号

- **强符号：**
  - 函数和已初始化的全局变量
- **弱符号：**
  - 未初始化的全局变量
- **规则：**
  - 不允许多个强符号
  - 给定一个强符号和多个弱符号，选择强符号
  - 给定多个弱符号，选择其中任意一个弱符号

## 多重定义的全局符号

```

    return 0;
}

{
    x = 15212 ;
```
