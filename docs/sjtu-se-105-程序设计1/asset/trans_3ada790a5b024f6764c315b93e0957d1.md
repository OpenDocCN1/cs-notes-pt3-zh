

- 在C++程序中的名字
  - 以字母开头，包含字母、数字和下划线
    - x, number_of_elements, Fourier_transform, z2
  - 不合法的名字
    - 12x
    - time$to$market
    - main line
  - 不要以下划线开头: _foo
    - 这类名字为保留名
  - 用户使用关键字来定义名字
    - 例如:
      - int
      - if
      - while
      - double

- 选择有意义的名字
  - 缩写容易误导人
    - mtbf, TLA, myw, nbv
  - 短名字也可以有含义
    - 惯例用法:
      - x 是局部变量
      - i 是循环索引
  - 不要使用过长的名字
    - Ok:
      - partial_sum
      - element_count
      - staple_partition
    - Too long:
      - the_number_of_elements
      - remaining_free_slots_in_the_symbol_table
  - 不要使用中文做名字
    - 包括文件名、变量名、函数名、常量名等

## 类型

- C++ 提供了一组类型
  - 例如 bool, char, int, double
  - 称为“内置类型”
- C++ 程序员可以定义新类型
  - 称为“用户定义类型”
- C++ 标准库提供了一组类型
  - 例如 string, vector, complex
  - 技术上讲，这些也是用户定义类型

## 类型安全

- 语言规则：类型安全
  - 每一个对象都将根据其类型使用
    - 变量只有被初始化之后才能使用
    - 只有为变量声明的类型而定义的操作采用应用其上
    - 为变量定义的每个操作在执行后，该变量都将获得一个有效的值
- 理想：静态类型安全
  - 违反类型安全的程序将无法通过编译
    - (在理想系统中)编译器会报告所有这类违反类型安全的问题
- 理想：动态类型安全
  - 如果编写的程序违反了类型安全，在运行时刻可以探测到
    - (在理想系统中)某些代码(通常是“运行时系统”)会探测编译器没有发现的所有违规情况

## 类型安全

- 类型安全事关重大
  - 要十分仔细，不能违反它
  - 在编程时，编译器是最好的朋友
- C++ 不是(完全)静态类型安全
  - 没有一种广泛使用的语言是(完全)静态类型安全的
  - 要做到完全静态类型安全，可能会影响你表达思想
- C++ 不是(完全)动态类型安全
  - 许多语言都是动态类型安全的
  - 要做到完全静态类型安全，可能会影响你表达思想
  - 并且经常会使得产生的代码量很大或者运行速度很慢
- 这里要学习的大多数内容都是类型安全
  - 我们会提到所有类型不安全的做法

## 类型安全准则－隐式窄化

```cpp
// 当心: C++ 不会阻止你将一个可能导致溢出的值赋给一个变量
// 尽管编译器有可能会警告

int main()
{
    int a = 20000;
    char c = a;
    int b = c;
    if (a != b)              // != 表示“不等于”
        cout << "oops!: " << a << " != " << b << '\n';
    else
        cout << "Wow! We have large characters\n";
}
```

```
int main()
{
    int x;        // x 得到一个“随机”初始值
    char c;       // c 得到一个“随机”初始值
    double d;     // d 得到一个“随机”初始值
                  //   — 并非每一种位模式对浮点数都是有效的
    double dd = d;      // 潜在错误: 某些实现无法复制无效的浮点数
    cout << " x: " << x << " c: " << c << " d: " << d << "\n";
}
```

- 总是初始化变量

- 安全转换
  - bool → char
  - bool → int
  - bool → double
  - char → int
  - char → double
  - int → double

- 不安全转换
  - double → int
  - double → char
  - double → bool
  - int → char
  - int → bool
  - char → bool

## 技术细节

- 在内存中一切都是 bit，类型是赋予这些 bit 的意义
  - (bits/binary) 01100001 是 int 97 也是 char 'a'
  - (bits/binary) 01000001 是 int 65 也是 char 'A'
  - (bits/binary) 00110000 是 int 48 也是 char '0'

```
char c = 'a';
cout << c;    // 打印字符c的值，其值为 a
int i = c;
cout << i;    // 打印字符c的整数值，其值为97
```

- 这就是“真实的世界”:
  - “42” 什么意思？
  - 除非你知道如何使用它们，否则你不知道它的意思
    - 米？英尺？摄氏度？$？门牌号？高度？...

## 效率

- 到目前为止，不用担心“效率”
  - 聚焦在代码的正确性和简洁性上
- C++ 是从 C 派生的，而 C 是一种系统编程语言
  - C++的内置类型直接映射到计算机的主存上
    - 一个 `char` 存储在一个 byte 中
    - 一个 `int` 存储在一个 word 中
    - 一个 `double` 适合浮点寄存器
  - C++的内置操作直接映射到机器指令上
    - 一个整数 `+` 是由一个整数加法操作实现的
    - 一个整数 `−` 是由一个复制操作实现的
  - C++ 提供对大部分现代硬件设备提供的工具进行直接访问的能力
- C++ 帮助用户使用内置类型和操作构建更安全、更优雅、更高效的新类型和新操作
  - 例如：字符串 string
  - 最终，我们将展示它是如何做到的

## 编程哲学

- 到目前为止，不用担心“效率”
  - 聚焦在代码的正确性和简洁性上
- 编程与其他类型的工程相似点之一就是要权衡
- 你必须有理想，但是它们经常互相冲突，因此你必须确定哪些对程序是最重要的
  - 类型安全
  - 运行时性能
  - 在指定平台上运行的能力
  - 在多种平台上运行出相同结果的能力
  - 与其他代码和系统的兼容性
  - 构建的难易度
  - 维护的难易度
- 不要敷衍对待正确性与测试
- 缺省情况下的目标应该是类型安全和可移植性
