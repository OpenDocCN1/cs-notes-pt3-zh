

## 赋值操作符

- 但是，左值的类实例必须先被销毁
  - 否则会造成内存泄露
- 要实现这个目的，需要为IntSet类重新定义赋值操作符
- 这称为操作符重载

- 赋值操作符
  - 向其提供目标实例和源实例
  - 将目标实例变成源实例的一个副本

- 下面是我们定义的赋值操作符：

```
class IntSet {
    // data elements
    ...
public:
    // Constructors
    ...
    IntSet& operator= (const IntSet& is);
    ...
};
```

- 就像复制构造函数一样
  - 赋值操作符接受一个指向常量实例的引用，将其传递给copyFrom
- 但是，它会返回一个指向拷贝而来的对象的引用
- 考虑下面的C++表达式
  - `x=y=z`
- 这是一个复合表达式
  - 由于“=”是自右向左结合的
  - 因此，首先将z赋值给y，这个表达式产生了新的“y”值
  - 然后再赋值给x

- 基本课程中，我们不需要知道：
  - 为什么赋值操作符会返回左值的引用
  - 只需要知道它就是这样做的即可
- 这里“酷”的是
  - 由于我们已经写好了 copyFrom
  - 所以赋值操作符很容易实现
- 我们只需直接使用 copyFrom 即可

```
IntSet& IntSet::operator=(const IntSet &is)
{
    if (sizeElts != is.sizeElts) {
        delete [] elts;
        numElts = is.numElts;
        elts = new int[numElts];
    }
    copyFrom(is);
    return *this;
}
```

- 最后一行显得有些奇怪
- 每个方法都有一个隐式局部变量 this
  - this是一个指针，指向在其上调用该方法的当前实例
  - 这一行会对该指针解引用，并返回它所指向对象的引用
- 我们不能只返回this
  - 因为指针与引用并不完全一样
- 但是，我们必须返回被赋值对象的引用
  - 而不是赋值来源对象的引用

## 数组增长

- 我们需要定义 `grow()`
- `grow` 不需要接受任何引元或返回任何值
- 它也从来不需要在类的外部被调用
  - 因此，我们将其作为 private 方法添加到类中
  - 不接受任何引元并且返回 `void`

```
class IntSet {

    // data members ...
    void grow();
    // EFFECTS: enlarge array, preserving current contents

public:
    // ...
}
```

- 增长看起来很像赋值操作符
- 它必须执行下面的步骤:
  - 分配一个更大的数组
  - 复制较小的数组到较大的数组中
  - 销毁较小的数组
  - 修改elts/sizeElts的值为新数组的状态

## grow函数

```
void grow()
{
    int *tmp = new int[sizeElts + 1];
    for (int i = 0; i < numElts; i++) {
        tmp[i] = elts[i];
    }
    delete [] elts;
    elts = tmp;
    sizeElts += 1;
}
```

- 这个函数的思想是：
- 如果数组为空，并且我们想插入新对象
- 那么就创建一个足够大到能够放下新对象的数组
- 复制数组中的元素，然后继续

## grow函数的缺陷

- 有可能会导致执行大量的复制操作
- 假设用户创建了一个容量为 1 的IntSet
  - 然后向其中插入 N 个元素
- 在将持有整数个数的上限设置得很紧凑时
  - 在最坏情况下，这个函数在不停地进行复制
- 那么，当我们将数组扩展到可以包括第 N 个元素时
  - 必须将前 N-1 个元素复制到数组中
- 当我们将数组扩展到可以包括第 N-1 个元素时
  - 必须将前 N-2 个元素复制到数组中

- 怎样才能改善这种情况呢？
- 直觉告诉我们
  - 我们没有在每次复制数组时扩展足够多的空间
- 我们是复制了N个元素，但是只多扩展了一个空位
- 因此，可以为需要复制的N个元素扩展更多的空位
- 这就可以极大地减少执行复制的次数

- 下面是一个新版本的grow函数
  - 它只是对旧版本进行了稍微的改动
  - 但是其性能特性就完全不同了

```
void grow()
{
    int *tmp = new int[sizeElts * 2];
    for (int i = 0; i < numElts; i++) {
        tmp[i] = elts[i];
    }
    delete [] elts;
    elts = tmp;
    sizeElts *= 2;
}
```

- 唯一的不同就是数组扩展了两倍而不是一个空位

- 在最坏情况下，我们要复制N-1个元素以便插入第N个元素
- 但是，在此次复制之前的那次复制中
  - 我们为了插入第 N/2 个元素，复制了前(N/2-1)个元素
- 依此类推，总共的复制数量为：
  - T=(N-1)+(N/2-1)+(N/4-1)+(N/8-1)+......
- 我们可以将每一步的"-1"项省略
  - T< N+N/2+N/4+N/8+......

- 因此，这里的根本问题是
  - 在公式右边终结前到底有多少项
- 公式右边最终会终结
  - 因为我们只复制了有限个数的整数
- 从合并项开始计算：
  - T < N+(N/2+N/4)+N/8+...
  - < N+3N/4+N/8+...
  - < N+(3N/4+N/8+...
  - < N+7N/8+...

- 依此类推

- 公式T < N + N/2 + N/4 + N/8 + ...
- 右边是一个等比数列
  - 每一项都是前一项的1/2
- 等比数列的前n项和为

$$\sum_{i=0}^{n-1} a * r^{i} = a * \frac{1 - r^{n}}{1 - r}$$

- 其中 a=N， r=1/2
- 当 n 变大时， r^n 项就会变小，所以可以忽略它
- 这样，就可得 T < N(1)/(1-1/2) = N*2
