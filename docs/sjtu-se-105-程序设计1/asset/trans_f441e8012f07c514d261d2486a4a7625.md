## 程序设计的基本思路

- 解决任何大型问题的基本范例
- 分而治之
- 分解程序是指将程序分解为更小的程序（片段），它们可以通过简单的、定义良好的方式彼此交互
- 函数签名
- 接口
- 人们有不同的分解方式

## 分解的方式

- 每个子问题在详细程度上处于同一个水平
- 每个子问题都可以独立地解决
- 子问题的解决方案结合在一起就构成了对原始问题的解

- ◆ 过程化程序设计方法
1、开始游戏
2、黑子先走
3、绘制画面
4、判断输赢
5、轮到白子
6、绘制画面
7、判断输赢
8、返回步骤2
9、输出最后结果

- ◆ 对象化程序设计方法
1、黑白双方，这两方的行为是一模一样的
2、棋盘系统，负责绘制画面
3、规则系统，负责判定诸如犯规、输赢等

- 分解并非包治百病的万灵药
- 分解并非总是正确的
- 对问题的不正确或不全面的理解
- 假设由一组编剧编写一个剧本
- 给出所有角色的列表和每一幕的轮廓
- 每位作者写一个角色所对应的故事线
- 最后将所有的故事线合在一起很难构成剧本

## 抽象

- 如何有效地分解？
- 抽象-不断地变化要考虑的细节程度
- 编写剧本可以确定它包含多少幕
- 分解
- 用来将软件分离成多个部分，它们组合起来就可以解决最初的问题
- 抽象
- 协助我们做出关于分解的正确（良好）选择

## 抽象

- 抽象的过程可以被看作是一种“多对一”的映射
- 忽略某些信息，将不同的事物看作是相同的事物处理

![](img/d2d3f908f0e1c0f8ca98d9dfbe006a9f_162_0.png)

```
found = false;
for (int i = 0; i < a.length; i++)
    if (a[i] == e) {
        z = i;
        found = true;
    }
```

```
found = false;
for (int i a.length - 1; i >= 0; i--)
    if (a[i] == e) {
        z = i;
        found = true;
    }
```

- 这两段代码的行为相同，如果有isIn和indexOf()这样的函数就好了！

```
found = a.isIn(e);
if (found)
    z = a.indexOf(e);
```

- 依赖于语言必须提供这样的函数

- 我们可以构建自己的抽象，因此需要有函数机制

- 输入一个字符串，该字符串全部由数字构成。将字符串以每3个字符进行分割，可以得到若干个百位数，如果最后一个数字位数不满，则后面填补0。写一个函数来计算这些百位数中的最大数字，并在main()函数内检查输入输出。

- 例子：
- 输入：34025003792488035904。该字符串可被分割为：340，250，037，924，880，359，040
- 输出：924（前面位数为0的最大数字需要舍弃0，如097，则输出97）
