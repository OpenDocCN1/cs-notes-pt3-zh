

## 虚函数与重载函数

```
class parent { public:
    void printclass() {printf("p ");};
    virtual void printvirtual() {printf("p ");};  };
class child : public parent { public:
    void printclass() {printf("c ");};
    virtual void printvirtual() {printf("c ");};  };
main() {
    parent p; child c; parent *q;
    p.printclass(); p.printvirtual(); c.printclass(); c.printvirtual();
    q = &p; q->printclass(); q->printvirtual();
    q = &c; q->printclass(); q->printvirtual();
}
```

输出：p p c c p p p c

## 原则上的子类型

- A <: B 如果每当需要一个 B 对象时，每个 A 对象都可以在不产生类型错误的情况下使用
- 示例：

```
Point:
  int getX();
  void move(int);
```

## 独立类不是子类型

```
class Point {
    public:
        int getX();
        void move(int);
    protected:  ...
    private:    ...
};
```

```
class ColorPoint {
    public:
        int getX();
        void move(int);
        int getColor();
        void darken(int);
    protected:  ...
    private:    ...
};
```

C++ 不将 ColorPoint <: Point 视为如上所述

- 需要公共继承 ColorPoint : public Point
- 为什么？？

## 为什么是 C++ 设计？

- ◆ 客户端代码仅依赖于公共接口
  - 原则上，如果 ColorPoint 接口包含 Point 接口，则任何客户端都可以使用 ColorPoint 代替 point
  - 然而 -- 虚函数表中的偏移可能不同
  - 失去实现效率（像 Smalltalk）

- ◆ 没有继承的链接
  - 子类型导致实现效率的损失

- ◆ 还有封装问题：
  - 基于继承的子类型在基类修改下得以保留 ...

## 函数的子类型

```
class Point {
public:
    int getX();
    virtual Point * move(int);
protected:    ...
private:      ...
};
```

```
class ColorPoint: public Point {
public:
    int getX();
    int getColor();
    ColorPoint * move(int);
    void darken(int);
protected:    ...
private:      ...
};
```

继承，但为清晰起见在此重复

- **原则上：** 可以有 `ColorPoint <: Point`
- **实践中：** 有些编译器允许，其他则没有

## 抽象类

- 抽象类：
  - 一个没有完整实现的类
  - 通过 =0 声明（多么棒的语法！）
  - 有用因为它可以有派生类
    由于 C++ 中子类型遵循继承，使用抽象类来构建子类型层次结构。
  - 建立虚函数表（vtable）的布局

- 示例
  - 读者附录中的几何类
    - Shape 是 circle、rectangle 等的抽象超类型

## 问题：名称冲突

```
class A {
    public:
        void virtual f() { ... }
};
class B {
    public:
        void virtual f() { ... }
};
class C : public A, public B { ... };
...
    C* p;
    p->f();    // error
```

在 2 个基类中同名

## 名称冲突的可能解决方案

- 三种通用方法
  - 隐式解析
    - 语言用任意规则解决名称冲突
  - 显式解析
    - 程序员必须显式解决名称冲突
  - 禁止名称冲突
    - 程序不允许包含名称冲突

- 没有解决方案总是最好

- C++ 使用显式解析
