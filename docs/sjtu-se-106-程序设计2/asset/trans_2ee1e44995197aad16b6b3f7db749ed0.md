
## 资源获取即初始化（RAII）

- 也称为“守护惯用法”
- 然而，“RAII”这一术语在 C++ 中更为常用
- 依赖于这样一个事实：在 C++ 中，当栈帧弹出时，栈对象的析构函数会被调用
- 思想：我们可以使用栈对象来持有堆对象或任何其他需要显式清理的资源的所有权
  - 在资源分配时初始化栈对象
  - 在栈对象的析构函数中释放资源

## RAII 示例：守护新分配的对象

```
shared_ptr<Foo> createAndInit() {
  Foo *f = new Foo;
  shared_ptr<Foo> p(f);
  init(f); // may throw exception
  return p;
}

int run () {
  try {
    shared_ptr<Foo> spf =
        createAndInit();
    cout << "*spf is " << *spf;
  } catch (...) {
    return -1
  }
  return 0;
}
```

- 通过 **shared_ptr** 类模板展示的 RAII 惯用法示例
  - `#include <memory>`
  - `using namespace std;`
- **shared_ptr<X>** 假定并维护对别名 **X** 的所有权
- 可以通过它（`*spf`）访问别名 **X**
- 当安全时（依据接下来讨论的引用计数惯用法），**shared_ptr** 析构函数会对所拥有的 **X** 的指针调用 `delete`
- 与其他内存惯用法结合得很好

## 引用计数简介

- 基本问题
  - 资源共享通常比复制更高效
  - 但很难判断所有使用者何时用完某个资源
  - 必须避免过早删除
  - 必须避免泄漏
- 解决方法
  - 共享资源的同时也共享一个计数器
  - 每个新引用都会使计数器递增
  - 当一个引用用完时，计数器递减
  - 当计数降至零时，删除资源和计数器
  - “最后离开的人关灯”

## 写时复制简介

- 基本问题
  - 引用计数实现了安全高效的共享
  - 但如果对资源进行了修改怎么办？
  - 可能希望拥有逻辑上独立的资源副本
- 解决方法
  - 从引用计数开始
  - 写入者检查计数是否大于 1
    - 复制引用和计数器
    - 更新两个计数器
    - 执行写入
  - 所有读取者共享一个副本，每个写入者可以拥有自己的副本
