

## 冲突解决策略

- 两个类别：
  1. 开放哈希，又称分离链接
  2. 闭合哈希，又称开放寻址
- 区别在于冲突是存储在*表外*（开放哈希）还是冲突导致记录存储在表的*另一个槽位*中（闭合哈希）

## 闭合哈希

- 与闭合哈希相关的是*再哈希策略*：
  “如果我们尝试将 x 放入桶 h(x) 中并发现已被占用，则寻找替代位置 h₁(x)、h₂(x) 等。按顺序尝试每个位置，如果都无空闲则表已满，” 
- h(x) 称为*主桶*
- 最简单的再哈希策略称为*线性哈希*
  hᵢ(x) = (h(x) + i) % D
- 一般来说，冲突解决策略是生成可容纳记录的哈希表槽序列（探测序列）；测试每个槽直到找到空槽（探测）

## 示例线性（闭合）哈希

- D=8，键 a,b,c,d 的哈希值为 h(a)=3, h(b)=0, h(c)=4, h(d)=3
  - 我们把 d 插入哪里？3 已被填满
  - 使用线性哈希的探测序列：
    - h1(d) = (h(d)+1)%8 = 4%8 = 4
    - h2(d) = (h(d)+2)%8 = 5%8 = 5*
    - h3(d) = (h(d)+3)%8 = 6%8 = 6
    - 等等。
    - 7, 0, 1, 2
  - 在表的开头处回绕！

## 使用线性哈希的操作

- 成员资格测试：*findItem*
  - 检查 h(k)、h₁(k)、h₂(k)、…，直到找到 k 或空桶或主桶
- 如果不允许删除，该策略有效！
- 如果允许删除怎么办？
  - 如果到达空桶，就不能确定 k 是否在别处，而空桶在 k 插入时曾被占用
  - 需要特殊占位符 *deleted*，以区分从未使用过的桶和曾经存放过值的桶
  - 删除过多后可能需要重新组织表

## 性能分析 - 最坏情况

- 初始化：O(b)，b 为桶的数量
- 插入和搜索：O(n)，n 为表中的元素数量；所有 n 个键值具有相同的主桶
- 对于维护字典，不比线性列表更好！

## 性能分析 - 平均情况

- 区分成功和不成功的搜索
  - 删除 = 成功搜索待删除的记录
  - 插入 = 沿其探测序列的不成功搜索
- 哈希的期望成本是表填充程度的函数：负载因子 α = n/b
- 已证明线性哈希（探测）下的平均成本为：
  - 插入：1/2(1 + 1/(1 - α)²)
  - 删除：1/2(1 + 1/(1 - α))

## 改进的冲突解决

- 线性探测：hᵢ(x) = (h(x) + i) % D
  - 在探测序列返回主位置之前，表中的所有桶都将成为插入新记录的候选
  - 记录聚集，导致探测序列变长
- 跳跃线性探测：hᵢ(x) = (h(x) + i c) % D
  - c 为 1 以外的常数
  - 主桶相邻的记录不会遵循相同的探测序列
- （伪）随机探测：hᵢ(x) = (h(x) + rᵢ) % D
  - rᵢ 是从 1 到 D-1 的数字随机排列中的第 i 个值
  - 插入和搜索使用相同的“随机”数字序列
