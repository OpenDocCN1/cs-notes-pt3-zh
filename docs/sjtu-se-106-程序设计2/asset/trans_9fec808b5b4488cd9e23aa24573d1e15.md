## C++ 回顾

## 历史
- C++ 是 C 的面向对象扩展
- C 由 Dennis Ritchie 在贝尔实验室设计
  - 用于编写 Unix，基于 BCPL
- C++ 由 Bjarne Stroustrup 在贝尔实验室设计
  - 他在贝尔的最初兴趣是仿真研究
  - 对 C 的早期扩展主要基于 Simula
  - 在 1980 年代早期被称为“C with classes”
  - 在 1980 年代后期和 1990 年代早期流行度增加
  - 特性是逐步添加的
    类、模板、异常、多重继承、类型测试...

## 设计目标
- 在基于 C 的语言中提供面向对象特性，同时不损害效率
  - 与 C 向后兼容
  - 更好的静态类型检查
  - 数据抽象
  - 对象和类
  - 在可能的情况下优先考虑编译代码的效率
- 重要原则
  - 如果你不使用某个特性，你的编译代码应与该语言不包含该特性时一样高效。 （与 Smalltalk 相比）

## 成功程度如何？
- 鉴于设计目标和约束，
  - 这是一种设计非常好的语言
- 用户众多——取得了巨大的流行成功
- 然而，设计非常复杂
  - 许多特性之间存在复杂交互
  - 难以从基本原则预测
  - 大多数严肃用户选择了语言的子集
    - 完整语言复杂且不可预测
  - 许多实现相关的属性
  - 冒险游戏爱好者的语言

## 重要约束
- C 有特定的机器模型
  - 访问底层架构
- 没有垃圾回收
  - 与效率目标一致
  - 需要显式管理对象内存
- 局部变量存储在激活记录中
  - 对象被视为结构体的一种泛化
    - 对象可以分配在栈上并被视为左值
    - 栈/堆差异对程序员可见

## C++ 对象系统

### 面向对象特性
- 类
- 对象，具有虚拟函数的动态查找
- 继承
  - 单继承和多重继承
  - 公有和私有基类
- 子类型
  - 与继承机制绑定
- 封装

## 一些好的决策
- 公有、私有、受保护的可见性级别
  - Public: 在任何地方都可见
  - Protected: 在类和子类声明内
  - Private: 仅在声明的类内可见
- 友元函数和类
  - 对可见性和数据抽象的细致关注
- 允许继承而不进行子类型化
  - 比没有私有基类时对子类型有更好的控制

## 一些问题区域
- **Casts**
  - 有时是无操作，有时不是（例如，多重继承）
- **缺乏垃圾回收**
  - 内存管理容易出错
    - 构造函数、析构函数是有帮助的
- **对象分配在栈上**
  - 更好的效率，与异常的交互
  - 但是赋值工作不佳，可能出现悬空指针
- **Overloading**
  - 代码选择机制太多？
- **Multiple inheritance**
  - 为效率而做的努力导致行为复杂

## 虚拟函数
- 成员函数要么是
  - 虚拟的，如果显式声明或继承为虚拟
  - 否则为非虚拟
- 虚拟函数
  - 通过对象中的指针间接访问
  - 可以在派生（子）类中重新定义
- 非虚拟函数
  - 以通常的方式调用。 *只是普通函数。*
  - 不能在派生类中重新定义（除重载外）
- 只有在使用虚拟函数时才支付开销
