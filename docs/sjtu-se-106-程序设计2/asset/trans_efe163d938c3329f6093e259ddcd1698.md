## 快速排序运行时间

- 最坏情况：当枢轴没有将序列分成两部分时
  - 在每一步，序列的长度仅减少 1
  - 总运行时间
  - $$\sum_{i=n}^{1} length(S_i) = O(n^2)$$
- 一般情况：
  - 树中第 i 层的花费时间为 O(n)
  - 运行时间：O(n) * O(height)
- 平均情况：
  - O(n log n)

    - 最坏情况可能发生，但不太可能

## 桶排序

- **桶排序**
  - 假设：键在范围 [0, N) 内
  - 基本思想：
    1. 创建 N 个链表（桶）将区间 [0,N) 分成大小为 1 的子区间
    2. 将每个输入元素添加到适当的桶中
    3. 连接桶
  - 预期总时间为 O(n + N)，其中 n = 原始序列的大小
    - 如果 N 是 O(n) → O(n) 的排序算法！

- 如果键不是整数怎么办？
  - 假设：输入是 [0, 1) 中的 n 个实数
  - 基本思想：

## 基数排序

- 直观上，你可能会按最高有效位排序，然后是第二位，等等。
- 问题：需要跟踪大量中间的卡片堆
- 关键思想：先排序*最低*有效位

```
RadixSort(A, d)
    for i=1 to d
        StableSort(A) on digit i
```
