

## 指令控制单元

- 取指控制
  - 预取当前正在访问的指令
    - 足够的时间来解码指令并将解码后的操作发送到执行单元

![](img/9bd5f6161cb6607b56d2fb964d1b8794_305_0.png)

### 取指控制

- 分支预测
  - 分支被取或顺序执行
  - 猜测分支是否被取
- 推测执行
  - 仅根据分支预测进行取指、解码和执行
  - 在分支预测是否确定之前

## 指令控制单元

- 指令解码逻辑
  - 获取实际的程序指令

![](img/9bd5f6161cb6607b56d2fb964d1b8794_307_0.png)

## 指令控制单元

- 指令解码逻辑
  - 获取实际的程序指令
  - 将它们转换为一组基本操作
    - 一条指令可以被解码为可变数量的操作
  - 每个基本操作执行某个简单任务
    - 简单算术、Load、Store
  - 寄存器重命名

```
addl %eax, 4(%edx)
```

```
load 4(%edx) → t1
addl %eax, t1 → t2
store t2, 4(%edx)
```

## 执行单元

- 多功能单元
  - 从 ICU 接收操作
  - 在每个时钟周期执行多个操作
  - 处理特定类型的操作

![](img/9bd5f6161cb6607b56d2fb964d1b8794_309_0.png)

### 多功能单元

- 多条指令可以并行执行
  - Nehalem CPU（Core i7）
    - 1 次加载，带地址计算
    - 1 次存储，带地址计算
    - 2 个简单整数（其中一个可能是分支）
    - 1 个复杂整数（乘法/除法）
    - 1 个 FP 乘法
    - 1 个 FP 加法

### 多功能单元

- 有些指令需要 > 1 个周期，但可以流水线化

Nehalem（Core i7）

| Instruction | Latency | Cycles/Issue |
|---|---|---|
| Integer Add | 1 | 0.33 |
| Integer Multiply | 3 | 1 |
| Integer/Long Divide | 11--21 | 5--13 |
| Single/Double FP Add | 3 | 1 |
| Single/Double FP Multiply | 4/5 | 1 |
| Single/Double FP Divide | 10--23 | 6--19 |

## 执行单元

- 操作被分派到多功能单元之一，只要
  - 操作的所有操作数都已准备好
  - 有合适的功能单元可用
- 执行结果在功能单元之间传递

## 执行单元

- 寄存器重命名
  - 值直接从生产者传递给消费者
  - 为操作的结果生成一个标签 †
    - 例如 %ecx.0, %ecx.1
  - 重命名表
    - 维护程序寄存器 r 与将更新此寄存器的操作的标签 † 之间的关联

## 理解翻译示例

| mulss (%rax,%rdx,4),%xmm0 | load (%rax,%rdx.0,4) ➔ t.1
mulq t.1, %xmm0.0 ➔ %xmm0.1 |

- 分成两个操作
  - Load 从内存读取以生成临时结果 t.1
  - 乘法操作仅在寄存器上操作

## 理解翻译示例

| mulss (%rax,%rdx,4),%xmm0 | load (%rax,%rdx.0,4) ➔ t.1
mulq t.1, %xmm0.0  ➔ %xmm0.1 |

- 操作数
  - 寄存器 %rax 在循环中不改变
  - 值将在解码期间从寄存器文件检索
