

## 标准 I/O

- 标准 I/O 将文件建模为 **流**
  - 文件描述符和内存中缓冲区的抽象。
  - 类似于带缓冲的 RIO
- C 程序开始时打开了三个流（在 `stdio.h` 中定义）
  - `stdin`（标准输入 fd=0）
  - `stdout`（标准输出 fd=1）
  - `stderr`（标准错误 fd=2）

## 标准 I/O 中的缓冲

- 标准 I/O 函数使用缓冲 I/O
- 缓冲区在遇到 "\n" 或调用 fflush() 时刷新到输出 fd

## Unix I/O 的优缺点

- **优点**
  - Unix I/O 是最通用且开销最低的 I/O 形式。
    - 所有其他 I/O 包都是使用 Unix I/O 函数实现的。
  - Unix I/O 提供了访问文件元数据的函数。
  - Unix I/O 函数是异步信号安全的，可以安全地在信号处理程序中使用。

## Unix I/O 的优缺点

- **缺点**
  - 处理短计数很棘手且容易出错。
  - 高效读取文本行需要某种形式的缓冲，这也很棘手且容易出错。
  - 这两个问题都由标准 I/O 和 RIO 包解决。

## 标准 I/O 的优缺点

- 优点：
  - 缓冲通过减少 `read` 和 `write` 系统调用次数来提高效率
  - 短计数会自动处理

## 标准 I/O 的优缺点

- 缺点：
  - 未提供访问文件元数据的函数
  - 标准 I/O 函数不是异步信号安全的，不适合用于信号处理程序。
  - 标准 I/O 不适合用于网络套接字上的输入和输出
    - 对流有文档记录不佳的限制，与套接字的限制相互作用不良

## 选择 I/O 函数

- 一般规则：使用你能使用的最高级 I/O 函数
  - 许多 C 程序员能够仅使用标准 I/O 函数完成所有工作

## 选择 I/O 函数

- 何时使用标准 I/O
  - 处理磁盘或终端文件时
- 何时使用原始 Unix I/O
  - 在信号处理程序内部，因为 Unix I/O 是异步信号安全的。
  - 在极少数需要绝对最高性能的情况下。
- 何时使用 RIO
  - 当你读取和写入网络套接字时。
  - 避免在套接字上使用标准 I/O。

## 客户端-服务器事务

- 大多数网络应用程序基于客户端-服务器模型
  - 一个服务器进程和一个或多个客户端进程
  - 服务器管理某些资源
  - 服务器通过为客户端操作资源来提供服务
  - 服务器由客户端请求激活

## 计算机网络

- **网络** 是按地理邻近性组织的盒子和线路的层次系统
  - SAN（系统区域网络）跨越集群或机房
    - 交换式以太网、Quadric QSW
  - LAN（局域网）跨越建筑物或校园
    - 以太网是最突出的例子
  - WAN（广域网）跨越国家或世界
    - 通常是高速点对点电话线路
