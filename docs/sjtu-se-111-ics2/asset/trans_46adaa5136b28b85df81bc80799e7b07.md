## 非局部跳转

```
#include <setjmp.h>

int sigsetjmp(sigjmp_buf env, int savesigs);
Returns: 0 from sigsetjmp, nonzero from siglongjumps

#include <setjmp.h>
void siglongjmp(sigjmp_buf env, int retval);
Never returns
```

```c
#include "csapp.h"
sigjmp_buf buf;

void handler(int sig) { siglongjmp(buf, 1); }

int main()
{
    Signal(SIGINT, handler);

    if (!sigsetjmp(buf, 1))
        printf("starting\n");
    else
        printf("restarting\n");

    while(1) {
        sleep(1);
        printf("processing...\n");
    }
    exit(0);
}
```

## 系统级 I/O

## 大纲

- Unix I/O
- 读取文件元数据
- 共享文件与 I/O 重定向
- 健壮的 I/O
- 标准 I/O
- 建议阅读
  - 10.1~10.3, 10.5~10.7, 10.4, 10.8

## 为什么是 Unix I/O

- 输入/输出
  - 在主内存和外部设备之间复制数据的过程
- 标准 I/O 库
  - 用户级或高级 I/O 函数

## 为什么是 Unix I/O

- Unix I/O
  - 内核提供的 I/O 函数
  - 帮助你理解其他系统概念
    - I/O 与进程
  - 有时，这是唯一的选择

## Unix I/O

- Unix 文件是一个由 m 个字节组成的序列
  - B₀, B₁, ......, Bₖ, ......, Bₘ
- 所有 I/O 设备都被建模为文件
  - 例如网络、磁盘和终端
  - 使 Unix 能够导出一个简单、低级的应用程序接口，称为 Unix I/O，

## Unix I/O

- 所有输入和输出都是通过读取和写入适当的文件来执行的
  - 使所有输入和输出能够以统一和一致的方式执行。

## 打开文件

- 应用程序宣布其访问 I/O 设备的意图
  - 内核打开相应的文件
  - 内核返回一个小的非负整数，描述符
    - 在对文件的后续所有操作中标识该文件
  - 内核跟踪有关打开文件的所有信息
    - 为每个打开文件维护一个文件位置 k，初始为 0

## 描述符表

- 每个进程都有自己的独立描述符表
  - 其条目由进程的打开文件描述符索引
  - 每个打开描述符条目指向文件表中的一个条目

## 文件表

- 打开文件的集合由文件表表示
- 文件表由所有进程共享
- 每个文件表条目包含
  - 当前文件位置
  - 当前指向它的描述符条目的数量的引用计数
  - 指向 v-node 表中条目的指针
  - 当其引用计数变为零时，内核删除一个文件表条目

## V-node 表

- V-node 表由所有进程共享
- 每个条目包含文件的大部分信息
