

## 我们的预测策略

- 条件跳转
  - 预测下一个 PC 为 valC（目标地址）
  - 仅当分支被采用时才正确
    - 通常 60% 的情况下是正确的
    - 恢复：M_Cnd 和 M_valA（valP：下一个 PC）
- 返回指令
  - 不尝试预测

## 选择 PC

```text
int f_predPC = [
    f_icode in {IJXX, ICALL} : f_valC;
    1: f_valP;
];
```

## 选择 PC

```text
int f_PC = [
  #mispredicted branch. Fetch at incremented PC
    M_icode == IJXX && !M_Cnd : M_valA;
  #completion of RET instruction
    W_icode == IRET : W_valM;
  #default: Use predicted value of PC
    1: F_predPC
];
```

## 处理器中的数据依赖

```text
1   irmovl $50, %eax
2   addl %eax, %ebx
3   mrmovl 100(%ebx), %edx
```

- 一条指令的结果被用作另一条指令的操作数
  - 写后读（RAW）依赖
- 在实际程序中非常常见
- 必须确保我们的流水线正确处理这些情况
  - 获得正确的结果
  - 最小化性能影响

## 数据冒险的分类

当一条指令更新程序状态中会被后续指令读取的部分时，就可能出现冒险。

## 数据冒险的分类

- **程序状态：**
  - 程序寄存器（已标识）
  - 条件码（**无冒险**）
    - 在执行阶段同时写入和读取。
  - 程序计数器（第 4.5.11 节）
    - 更新和读取 PC 之间的冲突会导致控制冒险（例如预测错误的分支和 `ret`）
  - 内存
    - 在访存阶段同时写入和读取。
    - 如果没有_自修改_代码，**则无冒险**。
  - 状态寄存器（第 4.5.9 节）
    - 当异常发生时有序停机

## 停顿条件

- **源寄存器**
  - 解码阶段当前指令的 srcA 和 srcB
- **目的寄存器**
  - dstE 和 dstM 字段
  - 执行、访存和写回阶段的指令
- **条件**
  - srcA==dstE 或 srcA==dstM
  - srcB==dstE 或 srcB==dstM
- **特殊情况**
  - 不要为寄存器 ID F 停顿
    - 表示不存在寄存器操作数
