

## 发送信号
- 内核
  - **发送**（传递）一个信号到目标进程
    - 通过更新目标进程上下文中的某些状态。
- 信号被传递的原因有两种
  - 内核检测到系统事件
    - 除零错误，子进程终止
  - 一个进程调用了 `kill` 函数
    - 以显式请求内核向目标进程发送信号。
    - 一个进程可以向自身发送信号。

## 待处理信号
- 待处理信号
  - 已发送但尚未接收的信号
- 只有一个
  - 在任何时刻，
  - 特定类型的待处理信号最多只能有一个
- 不排队
  - 如果一个进程已有类型为 k 的待处理信号
  - 那么随后发送给该进程的任何类型为 k 的信号都不会排队
  - 它们将被直接丢弃。
- 一个待处理信号最多只会被接收一次。

## 阻塞信号
- 一个进程可以有选择地 **阻塞** 某些信号的接收。
- 当一个信号被阻塞时
  - 它可以被传递
  - 但由此产生的待处理信号将不会被接收
  - 直到进程解除对该信号的阻塞

## 内部数据结构
- 对于每个进程，内核维护
  - 待处理信号的集合在 **pending 位向量** 中
  - 被阻塞信号的集合在 **blocked 位向量** 中
- 内核设置 **pending** 中的位 k
  - 每当类型为 k 的信号被传递时
- 内核清除 **pending** 中的位 k
  - 每当类型为 k 的信号被接收时。

## 进程组
```
#include <unistd.h>
pid_t getpgrp(void);
    returns: process group ID of calling process
#include <unistd.h>
pid_t setpgid(pid_t pid, pid_t pgid);
    returns: 0 on success, -1 on error
```
- 将进程 pid 的进程组更改为 pgid
- 如果 pid 为零，则使用当前进程的 PID
- 如果 pgid 为零，则使用由 pid 指定的进程的 PID 作为进程组 ID

## setgpid 函数
e.g. `setpgid(0, 0);`
- 假设进程 15213 是调用进程，
- 那么此函数调用
  - 创建一个新的进程组，其进程组 ID 为 15213
  - 将进程 15213 添加到该新组中。

## kill 程序
- Kill 程序
  - 位于目录 `/bin/` 中
  - 向另一个进程发送任意信号
```
e.g. unix> kill -9 15213
```
- 向进程 15213 发送信号 9（SIGKILL）。

## kill 程序
- 通过 kill 向进程组发送信号
  - 使用负的 PID
  - 这会导致信号被发送到进程组 PID 中的每个进程
- e.g. unix> kill -9 -15213
  - 向进程组 15213 中的每个进程发送 SIGKILL 信号。

## 从键盘发送信号
- **作业**
  - Unix shell 使用的抽象
  - 表示作为评估单个命令行结果而创建的进程
  - 在任何时候，最多有一个前台作业和零个或多个后台作业
  - **例如** `unix> ls | sort`
    - 由两个通过管道连接的进程组成的前台作业

## 从键盘发送信号
- shell 为每个作业创建一个单独的进程组
  - 通常，进程组 ID 取自作业中某个父进程

## 从键盘发送信号
- 在键盘上键入 **ctrl-c**
  - 会向 shell 发送一个 SIGINT 信号
  - shell 捕获该信号
  - 然后向前台进程组中的每个进程发送 SIGINT
  - 结果是终止前台作业（默认）
