## 基于进程的并发服务器

```
int main(int argc, char **argv)
{
    int listenfd, connfd, port = atoi(argv[1]);
    struct sockaddr_in clientaddr;
    int clientlen = sizeof(clientaddr);

    Signal(SIGCHLD, sigchld_handler);
    listenfd = Open_listenfd(port);
    while (1) {
        connfd = Accept(listenfd, (SA *) &clientaddr, &clientlen);
        if (Fork() == 0) {
            Close(listenfd); /* Child closes its listening socket */
            echo(connfd);    /* Child services client */
            Close(connfd);   /* Child closes connection with client */
            exit(0);         /* Child exits */
        }
        Close(connfd); /* Parent closes connected socket (important!) */
    }
}
```

- 为每个客户端派生单独的进程
- 不允许不同客户端处理器之间进行任何通信

## 使用进程进行并发编程

- 内核提供具有独立地址空间的多个控制流。
- 标准 Unix 进程控制和信号。
- 显式的进程间通信机制

## 进程的实现问题

- 如果 accept 调用被转移控制到 SIGCHLD 处理程序中断，服务器应重新启动 accept 调用
- 服务器必须回收僵尸子进程
  - 以避免致命的内存泄漏

```
void sigchld_handler(int sig)
{
    while (waitpid(-1, 0, WNOHANG) > 0)
        ;
    return;
}
```

## 进程的实现问题

- 服务器必须关闭其 connfd 的副本。
  - 内核为每个套接字保留引用。
  - fork 后，refcnt(connfd) = 2。
  - 直到 refcnt(connfd)=0，连接才会被关闭。

## 进程的优缺点

- 进程控制的额外开销。
- 在进程之间共享数据并不简单。
  - 需要 IPC（进程间通信）机制
    - FIFO（命名管道）、System V 共享内存和信号量

## 具有多个线程的进程

- 可以将多个线程与一个进程关联
- 每个线程都有自己的逻辑控制流（PC 值序列）
- 每个线程共享相同的代码、数据和内核上下文
- 每个线程都有自己的线程 ID（TID）
