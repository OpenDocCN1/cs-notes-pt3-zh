

## 线程设计设计的优缺点

- 线程间易于共享数据结构
  - 例如，日志信息、文件缓存。
- 线程比进程更高效
- 非预期的共享可能引入难以重现的微妙错误！
  - 数据易于共享既是线程的最大优点，也是最大的弱点
  - 难以知道哪些数据被共享以及私有

## I/O 多路复用：select() 函数

```c
#include <sys/select.h>

int select (int maxfd, fd_set *readset,
            NULL, NULL, NULL);
```

Return nonzero count of ready descriptors, -1 on error

## I/O 多路复用：select() 函数

- select()
  - 睡眠直到集合 readset 中的一个或多个文件描述符可读
  - 返回就绪描述符的数量并设置 readset 的每一位以指示其对应描述符的就绪状态

## I/O 多路复用：select() 函数

- readset
  - 位向量（最多 FD_SETSIZE 位）指示描述符集合的成员资格
  - 如果位 k 为 1，则描述符 k 是描述符集合的成员
- maxfd
  - readset 的基数
  - 测试描述符 0, 1, 2, ..., maxfd-1 的集合成员资格

## 操作集合描述符的宏

```
/* clear all bits in fdset. */
void FD_ZERO(fd_set *fdset);

/* clear bit fd in fdset */
void FD_CLR(int fd, fd_set *fdset);

/* turn on bit fd in fdset */
void FD_SET(int fd, fd_set *fdset);

/* Is bit fd in fdset on? */
int FD_ISSET(int fd, *fdset);
```

## 使用 I/O 多路复用的并发编程

```c
#include "csapp.h"

int main(int argc, argv)
{
    int listenfd, connfd, port;
    socklen_t clientlen=sizeof(struct sockaddr_in);
    struct sockaddr_in clientaddr;
    fd_set read_set, ready_set;
    if (argc != 2) {
        fprintf(stderr, "usage: %s <port>\n",argv[0]);
        exit(0);
    }
    port = atoi(argv[1]);
    listenfd = Open_listenfd(port);
```

FD_ZERO(&read_set);
FD_SET(STDIN_FILENO, &read_set);
FD_SET(listenfd, &read_set);
while(1) {
    ready_set = read_set;
    Select(listenfd+1, &ready_set,
            NULL, NULL, NULL);
    if (FD_ISSET(STDIN_FILENO, &ready_set)
        /*read command line from stdin */
        command();
    if (FD_ISSET(listenfd, &ready_set)){
        connfd = Accept(listenfd,
                (SA *)&clientaddr, &clientlen);
        echo(connfd);
    }
}
}

## 使用 I/O 多路复用的并发编程

```c
void command(void)
{
    char buf[MAXLINE];
    if (!Fgets(buf, MAXLINE, stdin))
        exit(0);   /* EOF */
    /*Process the input command */
    printf("%s", buf);
}
```

## I/O 多路复用的优缺点

- 一个逻辑控制流。
- 可以用调试器单步执行。
- 没有进程或线程控制开销。
  - 高性能 Web 服务器和搜索引擎的首选设计。
- 编码比基于进程或线程的设计复杂得多。
- 难以提供细粒度的并发
  - 例如，我们的示例会在部分行时挂起。
- 无法利用多核
  - 单一控制线程

## 并发方法

- **进程**
  - 难以共享资源：易于避免非预期共享
  - 添加/移除客户端的开销高
- **线程**
  - 易于共享资源：也许太容易了
  - 中等开销
  - 对调度策略控制不多
  - 难以调试：事件顺序不可重复
- **I/O 多路复用**
  - 乏味且底层
  - 对调度有完全控制
  - 开销非常低
  - 无法创建更细粒度的并发级别
  - 不利用多核
