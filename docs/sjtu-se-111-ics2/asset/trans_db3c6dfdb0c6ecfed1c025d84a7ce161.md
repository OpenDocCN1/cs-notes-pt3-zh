

## 虚拟寻址

- 地址转换
  - 将虚拟地址转换为物理地址
  - 需要 CPU 硬件和操作系统之间紧密协作
    - HW：内存管理单元（MMU）
      - CPU 芯片上用于实时转换虚拟地址的专用硬件
    - SW：查找表
      - 存储在主内存中
      - 内容由操作系统管理

## 地址空间

- 地址空间
  - 有序的非负整数地址集合
- 线性空间
  - 地址空间中的整数是连续的
- N 位地址空间

## 地址空间

线性地址空间：有序的连续非负整数地址集合：
{0, 1, 2, 3 ... }

虚拟地址空间：N = 2ⁿ 个虚拟地址的集合
{0, 1, 2, 3, ..., N-1}

物理地址空间：M = 2ᵐ 个物理地址的集合
{0, 1, 2, 3, ..., M-1}

- 数据（字节）与其属性（地址）之间清晰区分
- 每个对象现在可以拥有多个地址
- 主内存中的每个字节：
  一个物理地址，一个或多个虚拟地址

## 为什么使用虚拟内存（VM）？

- 高效使用主内存
  - 将 DRAM 用作虚拟地址空间部分的缓存
- 简化内存管理
  - 每个进程获得相同的统一线性地址空间
- 隔离地址空间
  - 一个进程无法干扰另一个进程的内存
  - 用户程序无法访问特权内核信息

## 将主内存用作缓存

- DRAM 与磁盘之间的差异比 SRAM 与 DRAM 更极端
  - 访问延迟：
    - DRAM 比 SRAM 慢 ~10 倍
    - 磁盘比 DRAM 慢 ~100,000 倍
  - 结论：
    - 为 DRAM 缓存做出的设计决策由缺失的巨大成本驱动

## 设计考虑

- 行大小？（大 vs 小）
  - **大**，因为磁盘更擅长传输大块数据
- 相联度？（全相联 vs 直接映射）
  - **全相联**，以最小化未命中率
- 写穿还是写回？（WB vs WT）
  - **写回**，因为无法承受对磁盘执行小写操作

## 页

- 虚拟内存
  - 概念上组织为存储在磁盘上的连续字节大小单元的数组。
  - 每个字节都有唯一的虚拟地址，可作为数组的索引
  - 磁盘上数组的内容缓存在主内存中

## 页

- 磁盘上的数据被划分为 **块**
  - 作为磁盘与主内存之间传输单元
  - 虚拟 *页*（VPs）
  - 物理 *页*（PPs）
    - 或页帧

![](img/9bd5f6161cb6607b56d2fb964d1b8794_927_0.png)

## 页属性

- 未分配：
  - VM 系统尚未分配（或创建）的页
  - 没有任何关联数据
  - 不占用磁盘上的任何空间。

## 页属性

- 已缓存：
  - 已分配且当前缓存在物理内存中的页。
- 未缓存：
  - 已分配但未缓存在物理内存中的页。

## 页表

- 每个已分配的虚拟内存页在页表中都有条目
- 虚拟页到物理页的映射
  - 从未缓存形式到已缓存形式
- 即使页不在内存中也有页表项
  - 指定磁盘地址
- OS 检索信息
