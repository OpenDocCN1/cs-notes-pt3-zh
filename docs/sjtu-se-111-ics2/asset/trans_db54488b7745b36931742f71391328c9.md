## 线程 vs. 进程

- 线程和进程的相似之处
  - 各自拥有自己的逻辑控制流
  - 各自可以与其他线程并发运行（可能在不同核心上）
  - 各自会被上下文切换

## 线程 vs. 进程

- 线程和进程的**不同之处**
  - 线程共享代码和部分数据
    - 进程（通常）不共享
  - 线程的开销比进程**小一些**
    - 进程控制（创建和回收）的开销是线程控制的两倍
    - Linux 数据：
      - 创建和回收一个进程约需 ~20K cycles
      - 创建和回收一个线程约需 ~10K cycles（或更少）

## Posix 线程（Pthreads）接口

- Pthreads：约 60 个函数的标准接口
  - 从 C 程序操作线程
  - 创建和回收线程
    - pthread_create
    - pthread_join
  - 确定你的线程 ID
    - pthread_self
  - 终止线程
    - pthread_cancel
    - pthread_exit
    - exit [终止所有线程]
    - return [终止当前线程]

## Pthreads 的 "hello, world" 程序

```
/* hello.c - Pthreads "hello, world" program */
#include "csapp.h"

/* thread routine */
void *thread(void *varp) {
    printf("Hello, world!\n");
    return NULL;
}

int main() {
    pthread_t tid;
    Pthread_create(&tid, NULL, thread, NULL);
    Pthread_join(tid, NULL);
    exit(0);
}
```

## 基于线程的并发服务器（续）

```
int main(int argc, char **argv){
    int listenfd, *connfdp, port, clientlen;
    struct sockaddr_in clientaddr;
    pthread_t tid;

    if (argc != 2) {
        fprintf(stderr, "usage: %s <port>\n", argv[0]);
        exit(0);
    }
    listenfd = open_listenfd(port);
    while (1) {
        clientlen = sizeof(clientaddr);
        connfdp = Malloc(sizeof(int));
        *connfdp = Accept(listenfd,
            (SA *)&clientaddr, &clientlen);
        Pthread_create(&tid, NULL, thread, connfdp);
    }
}
```

## 基于线程的并发服务器（续）

```
/* thread routine */
void *thread(void *vargp)
{
    int connfd = *((int *)vargp);

    Pthread_detach(pthread_self());
    Free(vargp);

    echo_r(connfd); /* reentrant version of echo() */
    Close(connfd);
    return NULL;
}
```

## 基于线程的服务器的问题

- 必须以 "detached" 方式运行以避免内存泄漏。
  - 在任意时刻，一个线程要么是可连接的要么是分离的
  - 可连接线程可以被其他线程回收和杀死。
    - 必须被回收（使用 pthread_join）以释放内存资源。

## 基于线程的服务器的问题

- 必须以 “detached” 方式运行以避免内存泄漏。
  - 分离线程不能被其他线程回收或杀死。
    - 资源在终止时**自动回收。**
  - 默认状态是可连接的。
    - 使用 `pthread_detach(pthread_self())` 使其分离。
