# 查询成本度量

- 成本通常以回答查询的总耗时来衡量
  - 许多因素都会影响时间成本
    - 磁盘访问、CPU，甚至网络通信
- 通常磁盘访问是主要成本，也相对容易估计。通过考虑以下因素来衡量
  - 寻道次数 * 平均寻道成本
  - 读取块数 * 平均块读取成本
  - 写入块数 * 平均块写入成本
    - 写入块的成本高于读取块的成本
      - 数据在写入后会被读回以确保写入成功

# 查询成本度量（续）

- 为简化起见，我们仅使用从磁盘传输的块数和寻道次数作为成本度量
  - t_T - 传输一个块的时间
  - t_S - 一次寻道的时间
  - b 次块传输加 S 次寻道的成本
    b * t_T + S * t_S
- 为简化起见，我们忽略 CPU 成本
  - 实际系统确实会考虑 CPU 成本
- 我们在成本公式中不包括将输出写入磁盘的成本

# 查询成本度量（续）

- 若干算法可通过使用额外的缓冲区空间来减少磁盘 I/O
  - 可用于缓冲的实际内存量取决于其他并发查询和操作系统进程，仅在执行期间才知道
  - 我们通常使用最坏情况估计，假设仅有操作所需的最小内存量可用
- 所需数据可能已驻留在缓冲区中，从而避免磁盘 I/O
  - 但在成本估算中难以考虑

# 文件扫描

- **算法 A1（线性搜索）。** 扫描每个文件块并测试所有记录以查看它们是否满足选择条件。
  - 成本估计 = $b_r$ 次块传输 + 1 次寻道
    - $b_r$ 表示包含关系 $r$ 记录的块数
  - 如果选择是在键属性上，可以在找到记录时停止
    - 成本 = $(b_r / 2)$ 次块传输 + 1 次寻道
