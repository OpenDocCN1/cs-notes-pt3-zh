

## 磁盘块访问的优化（续）

- 日志磁盘——专门用于按顺序写入块更新日志的磁盘
  - 其用途与非易失性RAM完全相同
    - 由于无需寻道，写入日志磁盘的速度非常快
    - 无需特殊硬件（NV-RAM）
- 文件系统通常会重新排序对磁盘的写入以提高性能
  - 日志文件系统将数据按安全顺序写入NV-RAM或日志磁盘
  - 无日志情况下的重排序：可能导致文件系统数据损坏

## 闪存存储

- NOR闪存 与 NAND闪存 的对比
- NAND闪存
  - 广泛用于存储，因为它比NOR闪存便宜得多
  - 需要按页读取（页大小：512字节到4 KB）
  - 传输速率约为20 MB/秒
  - 固态硬盘：使用多个闪存存储设备以提供100到200 MB/秒的更高传输速率
  - 擦除操作非常慢（1到2毫秒）
    - 擦除块包含多个页
      - 将逻辑页地址重映射到物理页地址可避免等待擦除
        - 转换表跟踪映射关系
          - 同时也存储在闪存页的标签字段中
        - 重映射由闪存转换层执行
      - 经过10万到100万次擦除后，擦除块将变得不可靠且无法使用
        - 磨损均衡

## 数据访问

- **物理块**是驻留在磁盘上的块。
- **缓冲块**是暂时驻留在主内存中的块。
- 磁盘与主内存之间的块移动通过以下两个操作发起：
  - **input(B)** 将物理块B传输到主内存。
  - **output(B)** 将缓冲块B传输到磁盘，并替换那里的相应物理块。
- 每个事务Ti都有其私有工作区，其中保存了它所访问和更新的所有数据项的本地副本。
  - Ti对数据项X的本地副本称为xi。
- 为简单起见，我们假设每个数据项都适合存储在一个单独的块中。

## 数据访问（续）

- 事务使用以下操作在系统缓冲块与其私有工作区之间传输数据项：
  - read(X) 将数据项X的值赋给局部变量xi。
  - write(X) 将局部变量xi的值赋给缓冲块中的数据项X。
  - 如果X所在的块BX尚未在内存中，这两个命令都可能在赋值之前需要发出input(BX)指令。
- 事务
  - 在首次访问X时执行read(X)；
  - 所有后续访问均针对本地副本。
  - 在最后一次访问之后，事务执行write(X)。
- output(BX) 不必紧跟在write(X)之后。系统可以在其认为合适的时候执行输出操作。

## 基于日志的恢复

- **日志**保存在稳定存储器上。
  - 日志是一系列**日志记录**，维护数据库上的更新活动记录。
- 使用日志的两种方法
  - 延迟数据库修改
  - 立即数据库修改

### 延迟数据库修改

(a)

```txt
<T0 start>
<T0, A, 950>
<T0, B, 2050>
```

(b)

```txt
<T0 start>
<T0, A, 950>
<T0, B, 2050>
<T0 commit>
<T1 start>
<T1, C, 600>
```

(c)

```txt
<T0 start>
<T0, A, 950>
<T0, B, 2050>
<T0 commit>
<T1 start>
<T1, C, 600>
<T1 commit>
```

### 立即数据库修改

(a)

```txt
⟨T₀ start⟩
⟨T₀, A, 1000, 950⟩
⟨T₀, B, 2000, 2050⟩
```

(b)

```txt
⟨T₀ start⟩
⟨T₀, A, 1000, 950⟩
⟨T₀, B, 2000, 2050⟩
⟨T₀ commit⟩
⟨T₁ start⟩
⟨T₁, C, 700, 600⟩
```

(c)

```txt
⟨T₀ start⟩
⟨T₀, A, 1000, 950⟩
⟨T₀, B, 2000, 2050⟩
⟨T₀ commit⟩
```
