
## 使用索引的选择

- **索引扫描** - 使用索引的搜索算法
  - 选择条件必须是索引搜索键上的条件。
- **A2**（**主索引，键上等值**）。检索满足相应等值条件的单个记录
  - *代价* = ($h_i$ + 1) * ($t_T$ + $t_S$)
- **A3**（**主索引，非键上等值**）检索多条记录。
  - 记录将位于连续的块中
  - 设 b = 包含匹配记录的块数
  - *代价* = $h_i$ * ($t_T$ + $t_S$) + $t_S$ + $t_T$ * b

- A4（辅助索引，非键上等值）。
  - 如果搜索键是候选键，则检索单个记录
    - 代价 = (hᵢ + 1) * (tₜ + tₛ)
  - 如果搜索键不是候选键，则检索多条记录
    - n 个匹配记录中的每一个可能位于不同的块上
    - 代价 = (hᵢ + n) * (tₜ + tₛ)
    - 可能非常昂贵！

## 涉及比较的选择

- 可以通过以下方式实现形式为 $A \vee (r)$ 或 $A \wedge (r)$ 的选择：
  - 线性文件扫描，
  - 或以以下方式使用索引：

- **A5** *（主索引，比较）*。（**关系按 $A$ 排序**）
  - 对于 $A \vee (r)$，使用索引找到第一个元组 $\geq v$，然后从那里顺序扫描关系。
  - 对于 $A \wedge (r)$，只需顺序扫描关系直到第一个元组 $> v$；不要使用索引。

- A6（辅助索引，比较）。
  - 对于 A v(r)，使用索引找到第一个索引项 v，然后从那里顺序扫描索引，以找到指向记录的指针。
  - 对于 A v(r)，只需扫描索引的叶页面，找到指向记录的指针，直到第一个条目 > v
  - 无论哪种情况，检索被指向的记录
    - 每条记录需要一次 I/O
    - 线性文件扫描可能更便宜

## 复杂选择的实现

- 合取：σ₁ σ₂ ... σₙ(r)
- A7（使用一个索引的合取选择）。
  - 选择 σᵢ 和算法 A1 到 A7 的组合，使得 σᵢ(r) 的成本最小。
  - 将元组取入内存缓冲区后，对其测试其他条件。
- A8（使用复合索引的合取选择）。
  - 如果可用，使用适当的复合（多键）索引。

- **合取：**
  
  `1      2   ...   n(r)`

- **A9** *（通过标识符交集进行合取选择）*
  - 需要带有记录指针的索引。
  - 对每个条件使用相应的索引，并取所有获得的记录指针集合的交集。
  - 然后从文件中获取记录。
  - 如果某些条件没有合适的索引，则在内存中进行测试。

## 复杂选择的算法

- **析取：** $1, 2, \ldots, n(r)$.
- **A10** *（通过标识符并集进行析取选择）*
  - 如果*所有*条件都有可用索引，则适用。
    - 否则使用线性扫描。
  - 对每个条件使用相应的索引，并取所有获得的记录指针集合的并集。
  - 然后从文件中获取记录

- 否定：(r)
  - 对文件使用线性扫描
  - 如果满足条件的记录很少，并且索引适用于该条件
    - 使用索引查找满足条件的记录并从文件中获取

## 连接操作

- 实现连接有几种不同的算法
  - 嵌套循环连接
  - 块嵌套循环连接
  - 索引嵌套循环连接
  - 合并连接
  - 哈希连接
- 基于代价估算选择
- 示例使用以下信息
  - *student* 的**记录**数：5,000
    *takes*：10,000
  - *student* 的**块**数：100
    *takes*：400

## 嵌套循环连接

• 要计算 theta 连接 r ⋈ s
for each tuple t_r in r do begin
  for each tuple t_s in s do begin
    test pair(t_r, t_s) to see if they satisfy the join condition
    if they do, add t_r · t_s to the result.
  end
end
r 称为连接的外关系，s 称为连接的内关系。
不需要索引，可用于任何类型的连接条件。
由于检查两个关系中的每一对元组，代价高昂。
