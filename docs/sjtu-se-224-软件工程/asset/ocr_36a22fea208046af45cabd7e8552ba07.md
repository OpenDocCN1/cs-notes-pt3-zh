# 质量因素的架构设计技术（1）

| 质量因素 | 设计技术 |
|---|---|
| 易用性 | 1.为用户提供易用的反馈机制
2.将用户界面与其它系统功能分离
3.提供帮助信息
4.建立用户界面，任务简单和易于操控 |
| 可靠性 即可用性 | 1.错误恢复，如心跳、冗余、命名空间
2.错误检测，如定时器、冗余、检查点、检查点和恢复
3.容错，如冗余、重启动、失败检测、失败恢复 |
| 性能 | 1.资源管理，如缓冲、缓存、减少I/O开销、控制资源竞争率、提高I/O效率
2.提高I/O效率，如输入输出缓冲、增加可用资源、维持数据或计算的多副本
3.资源估计，如优先级、优先级调度 |

# 质量因素的架构设计技术（2）

| 质量因素 | 设计技术 |
|---|---|
| 安全性 | 1.标识和验证访问，如用户身份验证、用户授权、限制易被窃取的信息、防火墙
2.从系统中删除，如撤销非授权访问、采用可审计机制及技术 |
| 可维护性 | 1.模块的输入输出，如深层模块，接口定义清晰、将模块与实现分离、简化功能
2.内部设计，如内置测试器 |
| 可移植性 | 1.防止代码依赖，如硬件依赖、期望环境的变化、限制可能的选项
2.防止失效机制，如避免信息隐藏、能够有条件、限制通信细节
3.选择标准时间 |

# Characteristics of a Good Architecture

+   - Resilient
+   - Simple
+   - Approachable
+   - Clear separation of concerns
+   - Balanced distribution of responsibilities
+   - Balances economic and technology constraints

# Architecture Constrains Design and Implementation

+   - Architecture involves a set of strategic design decisions, rules or patterns that constrain design and construction.

![](bbox=[0.58, 0.63, 0.73, 0.75])

> Architecture decisions are the most fundamental decisions, and changing them will have significant effects.

# 详细设计

+   - 详细设计软件架构中的每个模块：
+     - 将模块进一步细分子模块—子子模块—…
+       - 原子模块为类、函数、过程等
+     - 为所有数据对象定义数据结构
+     - 为所有在模块内发生的处理定义算法细节、控制流和数据流
