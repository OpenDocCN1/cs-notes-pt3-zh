# Actor 和 Use Case

![](bbox=[0.12, 0.52, 0.22, 0.72])

Actor
和系统交互的系统外的某些人或某些系统：
• 终端用户
• 外界软硬件系统
• 外部硬件设备

Use case
Actor 想要用系统去做的事

# 如何识别Actor

+   • 需要要在系统的帮助下完成自己的任务？
+   • 需要谁去执行系统的核心功能？
+   • 需要谁去完成系统的管理和维护？
+   • 系统是否需要和外界的硬件或软件系统进行交互？

# 如何识别Use Case

+   • 每个actor的目标和需求是什么？
+   • actor希望系统提供什么功能？
+   • actor 将创建、存储、修改和删除数据吗？
+   • actor 是否告知系统外界的事件？
+   • actor 需要被告知系统中发生的事件吗？

# 避免功能分解

现象
• use case 太小
• use cases 太多
• Uses case 没有信息回报
• 命名以频繁的动作
  • "Operation" + "object"
  • "Function" + "data"
  • Example: "Insert Card"
• 很难理解整个模型

纠正措施
• 寻找更大的上下文
• "为什么你要做本系统
  呢？"
• 注意自己在用户的角度
  "用户想要到什么"
• "这个 use case 能满足
  谁的需求？"
• "这个 use case 能够值
  什么？"
• "这个 use case 还有
  其它故事？"

一个用例定义了和actor之间的一次完整对话。
