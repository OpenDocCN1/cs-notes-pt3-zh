# 性能测试

+   - 性能测试（performance testing）用来测试软件在规定条件下，相对于所用资源的数目，可视该当性能的能力。
+   - 时间响应测试。测试在规定条件下，软件执行其功能时，提供响应的时间和处理时间以及其它条件下的性能。
+   - 资源利用率测试。测试在规定条件下，软件执行其功能时，使用各种资源和类别的资源的能力。这些资源包括CPU、内存等。
+   - 性能从属性测试。测试软件连续性能相关的属性、标准或方法。
+   - 压力测试（stress testing），又称负载测试，是一种将配置功能从正常测试，允许某些部件失效、硬软件资源耗尽等情况下执行系统，以测试系统在非正常情况下的性能。如大量数据的输入、处理和输出，大并发用户等）等手受影响。
+   - 自动化的性能/压力测试。HP的Loadrunner、开源的Jmeter等。

+   - 例如，4S系统的系统测试时，
+   - 连续运行4S系统100小时，计算系统正常运行时间总占时间总数的比例，以及故障恢复的平均用时；
+   - 通过强制系统重启、按网络等各种手段，让4S系统发生故障，观察恢复系统是否能降级运行，是各能及时地恢复运行，数据库中的数据是否因此留下了“脏”数据等。

# 易用性测试

+   - 易用性测试（usability testing）用来评价用户学习和使软件工作的（包括用户文档）的难易程度，支持用户任务的有效程度，以及用户的错误中恢复的能力。
+   - 易理解性测试，测试软件使用界面是否合适以及是否能帮助用户使用软件的功能。
+   - 易学性测试，测试软件使用者的学习能力。
+   - 易操作性测试，测试软件使用界面操控的能力。
+   - 易容错性测试，测试软件帮助用户纠正错误的能力。
+   - 易记住性测试，测试软件易用性相关的属性、标准或方法。
+   - 易用性测试可以采用模拟用户的方式进行，也可以通过观察用户的操作行为来执行。

+   - 例如，4S系统的系统测试时，
+   - 采用Loadrunner进行自动化性能测试，模拟不同数量的并发用户，在不同的数据量情况下，观察系统的响应时间和资源使用情况。

# 可移植性测试

+   - 可移植性测试（portability testing）用来测试软件从一种环境迁移到另一环境的能力。
+   - 适应性测试。测试软件所需采用额外的动作或手段是否不同环境下的能力。
+   - 易安装测试。测试软件在指定环境中安装的能力。
+   - 共存性测试。测试软件在公共环境中与其它分享公共资源的其他软件或系统的能力。
+   - 易替换性测试。测试软件在同环境下，替代另一个相同用途的指定软件产品的能力。
+   - 可移植性的从属性测试。测试软件遵循可移植性相关的协议、标准或方法的能力。

+   - 例如，4S系统的易用性测试时，
+   - 测量用户所需培训时间
+   - 观察销售人员在指定下订单的任务平均需要多少步骤
+   - 测试各界面风格是否一致
+   - 信息显示和反馈是否准确
+   - 是否提供在线的支持帮助等等。
