# 1）系统响应时间（Response time）

+   - 系统响应时间是指从用户执行某个控制动作（如按回车键或点鼠标）到软件作出响应（期望的输出或动作）的时长。
+   - 时间长度：系统响应时间过长会使用户感到不安和担忧，人的一般容忍度为15秒。
+   - 可变性：稳定的响应时间（如1秒）比不稳定的响应时间（如0.1秒到2.5秒）要好。用户往往比较敏感，总是有关心界面背后是否发生了异常。

# 及时反馈操作信息

+   - 当用户进行某项操作后，如果没有一会儿（几分钟）用户马上知道反馈信息，这就使用户感到迷惑和不安，因为他不知道自己是否操作了该操作成功了。
+   - 及反馈信息很重要，至少要使用户放心心安。如通过该任务处理是否完毕，有什么结果。
+   - 例如下载一个文件，屏幕上就显示“百分比”或相关数字来表示下载的进度。若用户认为进度要变得多非常慢，如某类任务处理不能进行时等，就要至少要给出提示信息“正在处理...等待...”，就最好提供给用户的动作，让用户明白系统正在干着，没有死机。

# 2）帮助设施（Help facilities）

+   - 关于帮助设施，在设计时须考虑以下问题：
+   - 在系统交互时，是否能提供各种系统功能的操作？是否能提供功能的帮助？
+   - 用户应怎样寻求帮助？使用帮助菜单、滚动功能键还是HELP命令。
+   - 帮助显示如何？在另一个窗口中，指出某个某类个材料（不是理想的方式）还是在屏幕特定位置的简单提示。
+   - 用户怎样得到常规的或非正常方式？可以提供帮助，屏幕上是否显示？功能或操作？
+   - 怎样构造帮助信息？是平面式的，所有信息均通过关键字来访问），分离式（用户可以进一步查询得到更详细的信 息）还是超文本式。
