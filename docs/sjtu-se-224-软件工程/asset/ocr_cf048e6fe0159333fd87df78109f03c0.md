# 2）测试设计

+   - 任务：设计测试用例
+   - 测试用例（test case）是按一定顺序执行的与测试目标相关的一系列测试。其主要内容包括：
+     - 前置条件（Pre-conditions）Optional
+     - 测试输入（Test input）
+     - 观察点（Observation Points）Optional
+     - 控制点（Control Points）Optional
+     - 预期结果（Expected Results）
+     - 后置条件（Post-conditions）Optional

# 3）测试开发

+   - 任务：开发测试脚本、桩和驱动模块
+   - 测试脚本（test script）是具有正规语法的數據和指令的集合，在测试执行自动工具使用中，通常以文件形式保存

# 4）测试执行

+   - 任务：执行测试用例
+   - 对于手工测试：
+     - 测试者按事先分配好的手工过程进行测试，测试者输入数据，观察输出、记录发现的问题。
+   - 对于自动测试：
+     - 可能只需要启动测试工具，并告诉工具执行哪些测试用例。
+   - 文档：测试记录、缺陷报告

# 缺陷报告

+   - 内容包括：缺陷名称、分类、等级、发现时间、发现人、所执行的测试用例、现象等
+   - 缺陷等级
+     - 5级：灾难性的一系统崩溃、数据被破坏
+     - 4级：很严重的一致性被破坏
+     - 3级：严重的一性不能运行、无法替代
+     - 2级：中等的一性不能运行、可以替代
+     - 1级：烦恼的提示不正确、报错不确切
+     - 0级：轻微的一表面化的错误、排字错等
+   - 缺陷报告通常保存在缺陷跟踪系统
