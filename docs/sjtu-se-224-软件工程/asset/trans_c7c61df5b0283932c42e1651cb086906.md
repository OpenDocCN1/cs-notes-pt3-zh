## 需要多少个类？

- **许多简单类**意味着每个类
  - 封装了**更少**的整体系统智能
  - **更**可重用
  - **更容易**实现
- **少数复杂类**意味着每个类
  - 封装了整体系统智能的**较大**部分
  - **不太**可能被重用
  - **更难**实现

一个类应该有一个单一且聚焦的目的。一个类应该只做一件事并且做好！

## 命名和描述操作

- 适当的操作名称
  - 表明结果
  - 使用客户端视角
  - 在类之间保持一致
- 定义操作签名
  - `operationName(parameter : class,...) : returnType`
- 提供简短描述，包括所有参数的含义

## 指南：设计操作签名

- 设计操作签名时，考虑参数是否：
  - 按值传递还是按引用传递？
  - 被操作更改？
  - 可选？
  - 设置为默认值？
  - 在有效参数范围内？
- 参数越少越好
- 传递对象而不是“数据位”

## 操作可见性

- 可见性用于强制封装
- 可能是 public、protected 或 private

![](img/bd1e40ee9d51e0bf88db831d8e65a09d_230_0.png)

## 如何表示可见性？

以下符号用于指定导出控制：

- **+ Public access**
- **# Protected access**
- **- Private access**

| Class |
|---|
| - privateAttribute |
| # protectedAttribute |
| +publicOp() |
| # protectedOp() |
| - privateOp() |

## 作用域

- 确定属性/操作的实例数量
  - Instance: 每个类实例一个实例
  - Classifier: 所有类实例共用一个实例
- 分类器作用域用下划线属性/操作名称表示
