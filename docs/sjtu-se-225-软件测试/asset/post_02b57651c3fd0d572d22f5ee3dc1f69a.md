
- **Statement coverage**: amounts to running tests in which every statement in the code is executed at least once.
- **Branch coverage**: makes sure that each branching point is tested at least once.
- **Path coverage**: makes sure that every different path is tested at least once.

## 3.3 Formal verification

### Correctness proofs

It is a mathematical technique for showing that a product is correct, in other words, that it satisfies its specifications.

To see how correctness is proven, consider the fragment (next slide).

We now show that the code fragment is correct: after execution, the variable `s` will contain the sum of the `n` elements of array `y`.

```
int k, s;
int y[n];

k = 0;
s = 0;
while (k < n)
{
    s = s + y[k];
    k = k + 1;
}
```

*Code fragment*

![](img/8454895dcf92bedbe5b40d0487077d64_131_0.png)

*Flowchart*

### An assertion is placed before and after each statement, at the place labeled with the letters A through H

```
n ∈ {1, 2, 3, …} (input specification)

k ← 0

k = 0

s ← 0

k = 0 and s = 0

k ≤ n and s = y[0] + y[1] + ... + y[k-1] (loop invariant)

Is k ≥ n?

Yes
k = n and s = y[0] + y[1] + ... + y[n-1] (output specification)

No
k < n and s = y[0] + y[1] + ... + y[k-1]

s ← s + y[k]

k < n and s = y[0] + y[1] + ... + y[k]

k ← k + 1

k ≤ n and s = y[0] + y[1] + ... + y[k-1]
```

Input specification: n is a positive integer.

**A:** n ∈ {1, 2, 3, …}

Output specification is that if control reaches point **H**, the value of **s** contains the sum of **n** values stored in array **y**:

**H:** s = y[0] + y[1] + … + y[n-1]

A stronger output specification is:

**H:** k = n and s = y[0] + y[1] + … + y[n-1]

How is it proven from **A** to **H**? The key is proving the invariant of the loop, that is,

**D:** k ≤ n and s = y[0] + y[1] + … + y[k-1]

### First

**B:** k = 0

This is easy to prove, because assignment statement `k ← 0` is executed.

At point C, the second assignment statement `s ← 0` is executed, and the following assertion is true:

`k = 0 and s = 0` (6)

Now the loop is entered. Before the loop executes, assertion (6) holds k = 0 and s = 0. By assertion (1), n ≥ 1, so it follows that k ≤ n is required. Because k = 0, it follows that k − 1 = −1, so the sum in (4) is empty, s = 0. Therefore loop invariant (4) is true just before the first loop is entered.

Now, assume that, at some stage during the execution of the code fragment, the loop invariant holds. That is, k has some value k₀, 0 ≤ k₀ ≤ n:

**D:** k₀ ≤ n and s = y[0] + y[1] + ... + y[k₀−1] (7)

We should prove that after executing the code fragment, the loop invariant is still true or we get the output specification.
