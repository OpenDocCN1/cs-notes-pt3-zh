## 5.1 Boundary Value Testing

The function F: Y = F(x₁, x₂)

the input variables x₁ and x₂ will have some (possibly unstated) boundaries:

a ≤ x₁ ≤ b

c ≤ x₂ ≤ d

![](img/8454895dcf92bedbe5b40d0487077d64_211_0.png)

## Normal Boundary Value Testing

refers to these values as min, min+, nom, max−, and max.

**“single fault” assumption:** failures are only rarely the result of the simultaneous occurrence of two (or more) faults.

![](img/8454895dcf92bedbe5b40d0487077d64_212_0.png)

if we have a function of n variables, boundary value analysis yields **4n + 1** unique test cases.

## Limitations of Boundary Value Analysis

- Boundary value analysis works well when the program to be tested is a function of several independent variables that represent bounded physical quantities.
- Why?
- 1. the variables need to be described by a true ordering relation.
- 2. value analysis presumes the variables to be truly independent.
- 3. no consideration of the nature of the function, nor of the semantic meaning of the variables.

## Worst-Case Boundary Value Testing

- **Rejecting single-fault assumption**
  - worst-case testing for a function of n variables: generates 5ⁿ test cases.
  - robust worst-case testing for a function of n variables: generates 7ⁿ test cases.
- **Test Cases for the Triangle Problem**
  - 3 sides: a、b、c;
  - each side: （1~200）
  - Normal Boundary Value Testing: 4×3+1=13 （Table 5.1）
  - Worst-Case Boundary Value testing : 5³=125个 （Table 5.2）
