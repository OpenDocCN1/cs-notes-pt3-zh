### I/O 硬件

- I/O 控制器
  - CPU 与 I/O 设备之间的接口
  - 为 CPU 提供特殊指令和寄存器
- I/O 地址
  - CPU 用于控制 I/O 硬件的“名称”
  - 内存位置或端口号
- 操作系统机制
  - 使用 I/O 指令和 I/O 地址来控制设备
  - 与 I/O 硬件交互的 3 种方式：轮询、中断驱动和 DMA

### CPU 究竟如何连接到设备？

- CPU 与控制器通信
- 通过以下两种方式
  - I/O 指令
  - 内存映射 I/O

### I/O 指令与内存映射 I/O

- I/O 指令
  - 通过 I/O 端口号访问设备的寄存器
  - 处理 I/O 的特殊 CPU 指令
  - Intel 架构示例：`out 0x21,AL`
- 内存映射 I/O（MMIO）
  - 设备的寄存器/内存出现在 CPU 的物理地址空间中
  - I/O 通过内存加载/存储指令完成
  - 由 MMU 映射，地址通过硬件跳线或启动时的编程设置
  - 可以使用页表进行保护

### 示例：内存映射显示控制器

- 只需写入显示内存即可改变屏幕上的图像
  - 地址：0x8000F000—0x8000FFFF
  - 也称为“帧缓冲”
- 可以将图形描述写入命令队列区域
  - 例如，输入一组描述某个场景的三角形
- 写入命令寄存器可能促使板载图形硬件执行某些操作

### 与控制器之间的数据传输

- 程序控制 I/O（PIO）：
  - 每个字节通过处理器的输入/输出或加载/存储指令传输
  - 优点：硬件简单，易于编程
  - 缺点：消耗的处理器周期与数据大小成正比
  - 适用于小型/简单的 I/O
- 直接内存访问（DMA）：
  - 赋予控制器访问内存总线的权限
  - 要求其直接将数据从内存传输到设备或反向传输
  - 优点：设备传输数据时无需占用 CPU
  - 缺点：需要设置
  - 适用于高吞吐量的 I/O

### DMA 传输的步骤

![](img/53ee1e3b0eba43505c7d530851f32f6f_492_0.png)

1. 设备驱动程序被告知将磁盘数据传输到地址 X 处的缓冲区
2. 设备驱动程序告诉磁盘控制器将 C 字节从磁盘传输到地址 X 处的缓冲区
3. 磁盘控制器发起 DMA 传输
4. 磁盘控制器将每个字节发送给 DMA 控制器
5. DMA 控制器将字节传输到缓冲区 X，递增内存地址并递减 C，直到 C = 0
6. 当 C = 0 时，DMA 中断 CPU 以通知传输完成

### I/O 设备通知操作系统

- 操作系统需要知道以下时刻：
  - I/O 设备已完成某项操作
  - I/O 操作遇到错误
- 两种方法
  - 轮询
  - 中断驱动
- 轮询：
  - I/O 设备将完成/错误信息放入设备特定的状态寄存器中
  - 操作系统定期检查状态寄存器
  - 优点：开销低
  - 缺点：如果 I/O 操作不频繁或不可预测，轮询可能会浪费大量周期
