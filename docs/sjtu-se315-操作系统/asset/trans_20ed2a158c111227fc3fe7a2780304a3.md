

## VMM 中的内存管理

- 配置 VM 使用比实际可用更多的内存
- 内存耗尽时会发生什么？
- 临时方案：在 VMM 中使用 LRU 分页
  - 操作系统已使用 LRU → 分页翻倍
  - 操作系统会回收 VMM 刚刚换出的页面
  - 更好的做法是随机驱逐

## ESX：跨 VM 共享页面

- 许多 VM 运行相同的操作系统和程序
  - 许多运行 Apache 服务器的 Linux 机器
- 思路：对相同的物理页面使用 1 个机器页面
- 定期扫描以查找相同的机器页面
  - 执行写时复制以消除冗余
- 优化：使用以 hash(content) 为键的哈希表
  - 允许基于页面内容快速查找

## 直接访问设备虚拟化

- 允许客户机操作系统直接访问底层设备
- 优点
  - 快速
  - 简化监视器
    - 所需设备驱动程序有限
- 缺点
  - 需要硬件支持以确保安全（IOMMU）
  - 需要硬件支持以实现复用
  - 硬件接口对客户机可见
    - 限制 VM 的移动性
  - 拦截按定义难以实现

## 优点

- 平台稳定性
- 允许拦截
- 无需特殊硬件支持
  - 隔离、复用由监视器实现

## 缺点

- 可能很慢
- 需要在监视器或主机中提供驱动程序

## 半虚拟化设备

Guest 将请求以更高抽象级别传递给 Monitor

- 通过 Monitor 调用发起请求
- Guest / monitor 之间共享缓冲区

优点

- 简化监视器
- 快速

缺点

- Monitor 需要提供特定于客户机的驱动程序
- 启动问题

## VirtIO：统一的半虚拟化 I/O

动机：Linux 至少支持 8 个虚拟化平台，每个平台都有自己的半虚拟化 I/O 设计/接口
VirtIO：为半虚拟化设备提供统一的 I/O 模式
被 KVM 和 lguest 采用

```
struct virtqueue {
void (*callback)(struct virtqueue *vq);
struct virtio_device *vdev;
struct virtqueue_ops *vq_ops;
void *priv;
};

struct virtqueue_ops {
int (*add_buf)(struct virtqueue *vq,
struct scatterlist sg[],
unsigned int out_num,
unsigned int in_num,
void *data);
void (*kick)(struct virtqueue *vq);
void *(*get_buf)(struct virtqueue *vq,
unsigned int *len);
void (*disable_cb)(struct virtqueue *vq);
bool (*enable_cb)(struct virtqueue *vq);
};
```

 u8 (*get_status)(struct virtio_device *vdev);
