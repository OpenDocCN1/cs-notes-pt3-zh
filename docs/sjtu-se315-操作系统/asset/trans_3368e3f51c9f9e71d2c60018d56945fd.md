

## Cachegrind 摘要

- Cachegrind 是一个缓存模拟器
- 提供总计、每个函数和每行命中/未命中计数
- 模拟不完美，但仍然有用
- 用于特征分析、优化和评估

## Callgrind：一个调用图分析器

## Callgrind

- Cachegrind 的扩展
- 由 Josef Weidendorfer 实现
- 还提供：
  - 调用图信息
  - 图形结果查看器（KCachegrind）
    - 允许交互式浏览结果

  - 对分析代码的更大选择性

## 选择性分析

- 可以在特定时间转储计数
  - 在终止时（与 Cachegrind 相同）
  - 定期（每 N 个代码块）
  - 在命名函数的入口/出口处
  - 在特定程序点（使用客户端请求）
  - 任何时间（通过调用单独脚本）
- 每次转储后计数器清零
- 可以选择要计数的事件
  - 指令
  - 内存事件（用于缓存模拟）
  - 函数入口/出口

## 一个有趣的难题

- Callgrind 维护一个调用栈
  - 用于跟踪函数入口/出口
- 存在若干困难：
  - `setjmp/longjmp`
  - 尾递归
  - 动态链接
    - 通过跳转表调用
    - 跳转表在加载后首次调用时被修补
  - 栈切换
- 未捕获的入口/出口会使一切出错

## Massif

- 测量堆和栈
  - 每个堆分配点是一个带
  - 栈是一个带
- 还产生 HTML 输出
  - 表示分配的底层调用图
  - 用户可以从分配点通过调用链下钻
- 与 Valgrind 核心的简单交互
  - 仅使用函数包装
  - 不对代码块进行插装
  - 复杂性在工具内部，而非核心/工具边界

## 隔离

- 故障隔离
  - 虚拟化的基本属性
- 软件隔离
  - 软件版本控制
  - DLL 地狱
- 性能隔离
  - 通过调度和资源分配实现

## 封装

- 所有 VM 状态都可以捕获到一个文件中
  - 通过操作文件来操作 VM
  - mv, cp, rm
- 复杂性
  - 与虚拟 HW 模型成比例
  - 与客户软件配置无关

## 拦截

- 所有客户操作都经过监视器
- 监视器可以检查、修改、拒绝操作
- 例
  - 压缩
  - 加密
  - 分析
  - 翻译

## 为什么不是操作系统？

- 这关乎接口
  - VMM 在硬件接口处运行
  - 硬件接口通常比软件接口更小、定义更好
- 通用操作系统的微内核
- 位于监视器中的缺点
  - 对客户在做什么的可见性较低
