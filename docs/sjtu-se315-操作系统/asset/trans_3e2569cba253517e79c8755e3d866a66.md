

## 文件和文件夹的压缩

- 在 NTFS 卷内移动文件或文件夹
  - 无论移动到的文件夹的压缩状态如何，都保持其压缩状态
- 在 NTFS 卷内复制文件或文件夹
  - 采用复制到的文件夹的压缩状态。
- 在 FAT 和 NTFS 卷之间
  - FAT -> NTFS：采用目标文件夹的压缩属性
  - NTFS -> FAT：未压缩

## 硬链接

- 硬链接
  - 为硬链接添加目录项，而不复制原始文件
  - 应用程序可以通过其任何硬链接修改文件
  - 不能基于每个硬链接为文件提供不同的安全描述符

## 稀疏文件

- 稀疏文件
  - 专注于文件包含大量由零组成的数据段
  - 存储
    - 仅为应用程序明确指定的数据分配磁盘簇
    - 文件中未指定的范围由磁盘上的未分配空间表示
  - 读取
    - 从已分配的范围返回存储的数据
    - 从未分配的范围返回零

## 文件系统可恢复性

- 恢复 NTFS 文件结构
  - 将每个操作视为事务并将其作为一个整体单元管理
  - 每个事务
    - 在内存中缓存的日志文件中记录元数据操作
    - 在内存中记录实际的元数据操作
    - 将事务标记为已提交到缓存的日志文件
    - 将日志文件刷新到磁盘
    - 将实际的元数据操作刷新到磁盘

## 扩展分区

- 在某些情况下，您可能想要 >4 个分区
- 现代操作系统支持扩展分区

![](img/53ee1e3b0eba43505c7d530851f32f6f_607_0.png)

- 扩展分区可能使用特定于操作系统的分区表格式（元数据）
  - 因此，其他操作系统可能无法读取逻辑分区

## 根文件系统类型

- Windows 暴露了一个多根系统
  - 每个设备和分区都被分配一个字母
  - 内部维护一个单一根
- Linux 有一个单一根
  - 一个分区被挂载为 /
  - 所有其他分区都被挂载在 / 下的某个位置
- 通常，包含内核的分区被挂载为 / 或 C:

## 挂载文件系统

- 1. 读取目标文件系统的超级块
  - 包含有关文件系统的元数据
  - 版本、大小、磁盘上关键结构的位置等。
- 1. 确定挂载点
  - 在 Windows 上：选择一个驱动器号
  - 在 Linux 上：在特定目录下挂载新文件系统

## 虚拟文件系统接口

- 问题：操作系统可能挂载包含不同底层文件系统的多个分区
  - 如果进程必须为不同的文件系统使用不同的 API 那就不好了
- Linux 使用虚拟文件系统接口（VFS）
  - 向进程公开 POSIX API
  - 将请求转发给底层文件系统特定驱动程序
- Windows 使用类似的系统
