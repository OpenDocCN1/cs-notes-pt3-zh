- 新的系统调用机制 – 灵活的系统调用

- 内核线程会轮询系统调用页中的系统调用请求

## 无异常系统调用

```
write(fd, buf, 4096);

entry = free_syscall_entry();
/* write syscall */
entry->syscall = 1;
entry->num_args = 3;
entry->args[0] = fd;
entry->args[1] = buf;
entry->args[2] = 4096;
entry->status = SUBMIT;

while (entry->status != DONE)
    do_something_else();

return entry->return_code;
```

## I/O 子系统的目标

- 尽管设备种类繁多，提供统一的接口
- 这段代码可在许多不同设备上运行：
  ```
  FILE fd = fopen("/dev/something","rw");
  for (int i = 0; i < 10; i++) {
      fprintf(fd,"Count %d\n",i);
  }
  close(fd);
  ```
- 为什么？
- 因为控制设备的代码（“设备驱动程序”）实现了标准接口。
- 提供 I/O 硬件的抽象层
- 管理并与硬件交互
- 隐藏硬件和操作细节

## 三种设备接口类型

- 三种常见的设备接口类型
- 字符设备
- 块设备
- 网络设备

![](img/53ee1e3b0eba43505c7d530851f32f6f_480_0.png)

## 字符设备

- 字符设备
- 示例：键盘/鼠标、串口、某些 USB 设备
- 顺序访问，一次一个字符
- I/O 命令：get()、put() 等
- 通常使用打开文件接口和语义

## 块设备和网络设备

- 块设备
- 示例：磁盘驱动器、磁带驱动器、DVD-ROM
- 统一的块 I/O 接口用于访问数据块
- 原始 I/O 或文件系统访问
- 支持内存映射文件访问
- 网络设备
- 示例：以太网、无线、蓝牙
- 与块/字符设备足够不同以拥有自己的接口
- 提供特殊的网络接口以支持各种网络协议
- 例如，发送/接收网络数据包

## 用户如何处理时序？

- **阻塞 I/O：**“等待”
  - 当请求数据（例如 read() 系统调用）时，将进程置于等待状态，直到数据准备好
  - 当写入数据（例如 write() 系统调用）时，将进程置于等待状态，直到设备准备好接收数据
- **非阻塞 I/O：**“不要等待”
  - 从 read 或 write 请求立即返回，已成功传输的字节数
  - Read 可能返回空，write 可能写入空
- **异步 I/O：**“稍后通知我”
  - 当请求数据时，取用户缓冲区的指针，立即返回；稍后内核填充缓冲区并通知用户
  - 当发送数据时，取用户缓冲区的指针，立即返回；稍后内核取走数据并通知用户
