## 虚拟化系统 ISA

- 监控器所需的硬件
  - 例如：监控器必须控制真实的硬件中断
- 访问硬件会允许 VM 损害隔离边界
  - 例如：访问 MMU 会允许 VM 写入任意页面
- 因此...
  - 来宾对虚拟系统 ISA 的所有访问都必须由监控器在软件中模拟。
  - 系统状态保存在内存中。
  - 系统指令在监控器中作为函数实现。

## 示例：CPUState

```c
static struct {
    uint32 GPR[16];
    uint32 LR;
    uint32 PC;
    int    IE;
    int    IRQ;
} CPUState;

void CPU_CLI(void)
{
    CPUState.IE = 0;
}

void CPU_STI(void)
{
    CPUState.IE = 1;
}
```

- CPU 虚拟化技术的目标
  - 尽可能快地处理普通指令
  - 将特权指令转发到模拟例程

## 定义

- **敏感指令**
  - 检查或更改处理器系统状态的指令
  - 例如，mov 到 CR 寄存器
- **特权指令**
  - 在高特权级别执行的指令
- 如果一条指令是敏感的但不是特权的会怎样？

## 虚拟化的正式要求

- Popek & Goldberg, 1974 “Formal Requirements for Virtualizable Third Generation Architectures”
- 由“虚拟机监控器”提供，具有三个基本特征：
  - 基本上相同的执行环境（与真实机器相同）
  - VM 中程序的性能损失很小
  - VMM 对系统资源具有完全控制权

## x86 虚拟化挑战

- IA-32 指令集包含 17 条敏感的非特权指令：
  - 敏感寄存器指令：读取或更改敏感寄存器和/或内存位置，例如时钟寄存器或中断寄存器：
    - SGDT, SIDT, SLDT, SMSW, PUSHF, POPF
  - 保护系统指令：引用存储保护系统、内存或地址重定位系统：
    - LAR, LSL, VERR, VERW, POP, PUSH, CALL, JMP, INT n, RET, STR, MOV

## 陷阱并模拟的问题

- 并非所有架构都支持它
- 陷阱成本可能很高
- 监控器使用一个特权级别
  - 需要虚拟化保护级别

## “严格可虚拟化”

如果处理器或处理器的模式在较低特权模式下执行时满足以下条件，则该处理器或模式是严格可虚拟化的：

- 访问特权状态的所有指令都会陷阱
- 所有指令要么陷阱要么完全相同地执行
- ...
