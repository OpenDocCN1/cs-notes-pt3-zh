## 启动过程

- **BIOS** 和 CPU 启动加电自检
- **BIOS** 找到启动设备
- **BIOS** 加载第一个物理扇区 (**MBR**)
- 将 CPU 执行转移到 MBR
- MBR 扫描分区表
- 加载活动分区的 **引导扇区** 副本
- 将 CPU 执行转移到引导扇区

## FAT 集群上的文件处理

- 存储文件信息
  - 继续将文件信息存储在下一个可用集群中
    - 当文件需要的空间大于集群大小时。
  - e.g.
    - 三个文件：1 号为 (2-3-6-8)，2 号为 (4-5)，3 号为 (7)

## FAT：优点与缺点

- 优点 – FAT 支持：
  - 目录和文件的层次树结构
  - 可变长度文件
  - 基本的文件和目录元数据
- 缺点
  - 最多，FAT32 支持 2TB 磁盘
  - 定位空闲块需要扫描整个 FAT
  - 易受内部和外部碎片影响
    - 大块 → 内部碎片
  - **读取需要大量随机寻道**

## 大量寻道

- 考虑以下代码：

```
int fd = open("my_file.txt", "r");
int r = read(fd, buffer, 1024 * 4 * 4); // 4 4KB blocks
```

## NTFS 集群

- 集群：分配给文件存储的最小磁盘空间
  - 从分区开始按顺序的逻辑集群编号
  - 集群从扇区 ZERO 开始（与 FAT 不同）
  - 软盘不使用 NTFS
  - 不同卷大小对应不同集群大小

| 卷大小 | NTFS 集群大小 |
|---|---|
| 7MB ~ 512MB | 512 bytes |
| 513MB ~ 1GB | 1KB |
| 1GB ~ 2GB | 2KB |
| 2GB ~ 2TB | 4KB |

默认 NTFS 集群大小

## NTFS 引导扇区

- NTFS 引导扇区
  - 位于每个分区的第一个逻辑扇区
  - 在格式化卷时创建
  - 以 2 字节扇区标记结尾（始终为 0x55AA）
- 组件
  - 一个 x86-b
  - 原始设备制造商标识 (OEM ID)
  - BIOS 参数块 (BPB)
  - 扩展 BPB
  - 可执行引导代码

与 FAT 文件系统相同

## 引导扇区组件

| 0x00 | 0x03 | 0x0B | 0x24 | 0x54 | 0x01FE |
|---|---|---|---|---|---|
| Jump | OEM ID | BPB | Ex-BPB | Bootstrap Code | Marker |
| 3Bs | 8Bs | 25Bs | 48Bs | 426Bs | 2Bs |

- Jump: 跳过下一个几个不可执行字节
- OEM ID: ...
  - 格式化该卷的操作系统的名称
- BPB & Ex-BPB: 卷的信息
  - 每扇区字节数，每集群扇区数，媒体描述符，总扇区数，“MFT”的逻辑集群编号，...
- Bootstrap Code: 启动操作系统的可执行代码
- Marker: 引导扇区结束
