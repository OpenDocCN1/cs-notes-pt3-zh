

## 间接通信

- 邮箱共享
  - $P_1$, $P_2$, 和 $P_3$ 共享邮箱 A
  - $P_1$, 发送；$P_2$ 和 $P_3$ 接收
  - 谁收到消息？
- 解决方案
  - 允许一个链接最多关联两个进程
  - 允许一次只有一个进程执行接收操作
  - 允许系统任意选择接收者。发送者会被通知接收者是谁。

## 同步与异步

- 消息传递可能是阻塞或非阻塞
- **阻塞** 被认为是 **同步**
  - **阻塞发送** 使发送者在消息被接收前阻塞
  - **阻塞接收** 使接收者在有消息可用前阻塞
- **非阻塞** 被认为是 **异步**
  - **非阻塞** 发送使发送者发送消息后继续执行
  - **非阻塞** 接收使接收者接收有效消息或 null

## 缓冲

- 附加到链接的消息队列；以三种方式之一实现
  1. 零容量 – 0 条消息
     发送者必须等待接收者（会合）
  2. 有界容量 – *n* 条消息的有限长度
     链接满时发送者必须等待
  3. 无界容量 – 无限长度
     发送者永不等待

## IPC 系统示例 - POSIX

- POSIX 共享内存
  - 进程首先创建共享内存段
    `segment id = shmget(IPC PRIVATE, size, S IRUSR | S IWUSR);`
  - 想要访问该共享内存的进程必须附加到它
    `shared memory = (char *) shmat(id, NULL, 0);`
  - 现在进程可以写入共享内存
    `sprintf(shared memory, "Writing to shared memory");`
  - 完成后进程可以从其地址空间分离共享内存
    `shmdt(shared memory);`

## IPC 系统示例 - WinXP （续）

- 通信按如下方式进行：
  - 客户端打开对子系统连接端口对象的句柄
  - 客户端发送连接请求
  - 服务器创建两个私有通信端口并将其中一个的句柄返回给客户端
  - 客户端和服务器使用相应的端口句柄发送消息或回调并监听回复

## 要求

- 必须保存处理器的寄存器以便未来透明恢复
- 必须为在内核中执行而设置
- 必须选择内核开始执行的位置
- 必须能够检索有关事件的信息，例如系统调用参数
- 必须全部安全完成
- 必须保持用户进程和内核的隔离

## IDT

- IDT：中断描述符表
  - 有 256 个条目
  - 每个给出处理相应中断时使用的 %cs 和 %eip
- 系统调用
  - 程序调用 *int n*
  - *n* 指定 IDT 中的索引

## Review: Threads in xv6

```
// Saved registers for kernel context switches.
// Don't need to save all the segment registers (%cs, etc),
// because they are constant across kernel contexts.
// Don't need to save %eax, %ecx, %edx, because the
// x86 convention is that the caller has saved them.
// Contexts are stored at the bottom of the stack they
// describe; the stack pointer is the address of the context.
// The layout of the context matches the layout of the stack in swtch.S
// at the "Switch stacks" comment. Switch doesn't save eip explicitly,
// but it is on the stack and allocproc() manipulates it.
struct context {
  uint edi;
  uint esi;
  uint ebx;
  uint ebp;
  uint eip;
};
```
