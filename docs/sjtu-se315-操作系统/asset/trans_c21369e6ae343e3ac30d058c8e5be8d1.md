
# 中断驱动

- CPU 在 I/O 之前设置中断处理程序向量
- CPU 发出 I/O 请求并继续执行其他任务
- I/O 设备处理 I/O 请求
- I/O 设备触发 CPU 中断请求线
- 中断处理程序接收中断并分派给正确的处理程序

# 中断驱动

- 优点：能够很好地处理不可预测的事件
- 缺点：中断开销相对较高

- 某些设备可能同时结合轮询和中断驱动
  - 高带宽网络设备示例：
    - 第一个到达的数据包使用中断
    - 后续数据包使用轮询，直到硬件队列为空

# 直接内存访问（DMA）

- 操作系统使用 DMA 的步骤：

  - 准备并注册中断服务例程
  - 告诉 DMA 控制器开始
  - 当传输完成时，控制器会发起中断

# 设备驱动程序

- 内核中与设备硬件直接交互的设备特定代码
  - 支持标准的内部接口
  - 相同的内核 I/O 系统可以轻松地与不同的设备驱动程序交互
  - 通过 ioctl() 系统调用支持特定的设备专用配置
- 设备驱动程序通常分为两部分：
  - 上半部
  - 下半部

# CGA

```
static void
cgaputc(int c)
{
    int pos;
    // Cursor position: col + 80*row.
    outb(CRTPORT, 14);
    pos = inb(CRTPORT+1) << 8;
    outb(CRTPORT, 15);
    pos |= inb(CRTPORT+1);
    if(c == '\n')
        pos += 80 - pos%80;
    else if(c == BACKSPACE){
        if(pos > 0) --pos;
    } else
        crt[pos++] = (c&0xff) | 0x0700;  // black on white
    if((pos/80) >= 24){ // Scroll up.
        memmove(crt, crt+80, sizeof(crt[0])*23*80);
        pos -= 80;
        memset(crt+pos, 0, sizeof(crt[0])*(24*80 - pos));
    }
    outb(CRTPORT, 14);
    outb(CRTPORT+1, pos>>8);
    outb(CRTPORT, 15);
    outb(CRTPORT+1, pos);
    crt[pos] = ' ' | 0x0700;
}
```

# 回顾：read

- readi()->bread()
  - 首先调用 bget() 从缓冲区缓存中读取
  - 如果没有找到，则调用 iderw() 从磁盘读取，并标记为有效。

```
// Return a B_BUSY buf with the contents of the indicated disk sector.
struct buf*
bread(uint dev, uint sector)
{
    struct buf *b;

    b = bget(dev, sector);
    if(!(b->flags & B_VALID))
        iderw(b);
    return b;
}
```
