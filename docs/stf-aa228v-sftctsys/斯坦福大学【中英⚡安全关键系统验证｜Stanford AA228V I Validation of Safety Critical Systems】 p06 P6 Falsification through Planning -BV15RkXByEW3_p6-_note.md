在本节课中，我们将学习如何通过优化方法寻找系统可能出现的故障。我们将重点讨论如何将轨迹的“可能性”纳入优化目标，以寻找更现实、更可能发生的故障，而不仅仅是理论上存在的故障。

## 概述

上一节我们介绍了使用优化方法寻找故障的基本框架。我们设定了一个优化问题，通过选择初始状态和一系列扰动来最小化一个代表“接近故障程度”的目标函数。我们曾提出使用“鲁棒性”作为这个目标函数。然而，单纯最小化鲁棒性可能导致算法找到一些虽然能引发故障，但在现实中极不可能发生的轨迹。因此，本节我们将探讨如何改进目标函数，将轨迹的可能性纳入考量，从而寻找更可能发生的故障。

## 计算轨迹的可能性

为了将可能性纳入目标，我们首先需要知道如何计算一个给定轨迹的可能性。

轨迹的可能性由初始状态的可能性以及后续每一步所采样扰动的可能性共同决定。具体来说，轨迹 `τ` 的概率 `P(τ)` 等于初始状态概率密度与每一步扰动概率密度的乘积。

以下是计算轨迹可能性的方法：
*   初始状态概率：我们首先采样一个初始状态 `x₀`，其概率密度为 `p(x₀)`。
*   扰动概率：在仿真的每个时间步 `t`，我们根据当前状态和动作，从扰动分布中采样一个扰动 `ω_t`。其概率密度为 `p(ω_t | x_t, a_t)`。
*   总概率：轨迹的总概率密度是所有这些概率密度的乘积：`P(τ) = p(x₀) * Π_{t=0}^{T-1} p(ω_t | x_t, a_t)`。

在实际代码实现中，我们通常计算其**对数概率**（log probability），因为直接连乘许多很小的概率值会导致数值下溢问题。通过对数运算，可以将连乘转换为连加，提高数值稳定性。

```python
# 伪代码示例：计算轨迹的对数概率
log_prob = log(initial_state_pdf(x0))
for t in range(T):
    disturbance = sampled_disturbances[t]
    log_prob += log(disturbance_pdf(disturbance, state_t, action_t))
```

## 结合可能性的新目标函数

现在我们知道如何计算轨迹的可能性，接下来可以将其融入我们的优化目标函数中。目标是引导优化算法寻找那些**既是故障、又很可能发生**的轨迹。

我们设计的新目标函数 `J(τ)` 如下：

*   **情况一：轨迹是故障（τ ∉ Ψ）**
    如果轨迹不满足规约（即发生了故障），则目标函数返回该轨迹可能性的负值：`J(τ) = -P(τ)`。
    这意味着优化器会尝试**最大化故障轨迹的可能性**（因为最小化负可能性等价于最大化可能性）。

*   **情况二：轨迹是成功的（τ ∈ Ψ）**
    如果轨迹满足规约（即成功），我们暂时不关心它的可能性，只希望它更接近故障状态。因此，我们仍然最小化其鲁棒性值：`J(τ) = ρ(τ)`。
    这里的 `ρ(τ)` 代表轨迹 `τ` 的鲁棒性（或平滑鲁棒性）。

这个目标函数的核心思想是：对于成功的轨迹，我们推动它向故障边界靠近；对于已经失败的轨迹，我们则筛选并保留其中更可能发生的那些。

## 目标函数效果对比

为了直观展示新目标函数的效果，我们考虑一个网格世界的例子。智能体需要避开障碍物到达目标点，但其行动有一定概率会“打滑”到非预期的方向。

以下是两种优化目标的对比结果：

*   **仅最小化鲁棒性**：优化算法找到的故障轨迹可能非常极端，例如智能体从一开始就直接冲向障碍物。这种轨迹虽然引发了故障，但对应的扰动序列在现实中极不可能发生。
*   **最小化新目标函数**：优化算法找到的故障轨迹会倾向于保持在正常路径附近，只在关键时刻因一个较可能的扰动而偏离并撞上障碍物。这种故障模式更现实，也更有参考价值。

通过这种对比，我们可以看到，结合了可能性的目标函数能引导搜索方向，找到更合理、更值得关注的故障案例。

## 关于目标函数的注意事项

虽然上述目标函数在理论上是理想的（若能找到全局最优解，就能得到“最可能的故障”），但在实际应用中需要注意以下几点：

1.  **故障目标值必须低于成功目标值**：这是为了确保优化算法有动力去寻找故障，而不是停留在一个看似“更好”的成功状态上。在我们设计的函数中，成功的轨迹返回正鲁棒性值（>0），而故障的轨迹返回负的可能性值（<0），因此满足了这一条件。
2.  **数值稳定性问题**：轨迹的可能性 `P(τ)` 是许多小概率值的乘积，结果可能极其微小，导致数值计算困难（下溢）。虽然我们可以使用对数概率来缓解，但这会破坏上一条性质，因为对数概率可能为负，导致 `-log(P(τ))` 为正，从而可能高于某些成功轨迹的鲁棒性值。
3.  **优化算法的局限性**：复杂的优化地形可能使算法难以找到全局最优解，通常我们只能找到局部最优解。

因此，在实践中，有时会采用一些简化的或启发式的目标函数，在寻找可能故障和算法稳定性之间取得平衡。
