## 策略可视化 📊

上一节我们介绍了重要性采样在评估碰撞避免系统性能中的应用。本节中，我们来看看如何通过可视化来理解系统策略本身。

![](img/2cdb4fb928bad00ff67e02bf8af60b04_2.png)

策略可视化是理解系统行为最直接的方法之一。以下是几种常见的可视化方式：

### 观察系统运行轨迹

你可以通过模拟并观察系统在多种场景下的运行轨迹来获得直观感受。例如，对于碰撞避免系统，我们可以运行多次模拟，观察其行为模式。通常会发现两种主要行为：飞机从入侵者上方或下方通过。这是设计系统后首先应进行的检查，以确保行为合理。

同样，对于倒立摆系统，我们可以观察到在大多数情况下它能保持直立（角度为零），但偶尔也会倒下。

### 绘制策略函数图

另一种方法是直接绘制智能体的策略函数。这对于状态空间维度较低的系统尤其有效。

**以倒立摆为例**：其状态是二维的（角度 `θ` 和角速度 `ω`），策略仅依赖于当前状态。我们可以绘制一个热图，显示在每个 `(θ, ω)` 状态下智能体建议施加的扭矩 `τ`。
*   在原点 `(0, 0)`，即完全直立且静止时，策略输出扭矩为 `0`，这符合预期。
*   当 `θ` 为正（向右倾斜）时，策略输出负扭矩以将其推回。
*   当 `θ` 为负时，则输出正扭矩。

**代码示例（概念性）**：
```python
# 伪代码：遍历状态空间网格，查询策略并绘图
for theta in theta_range:
    for omega in omega_range:
        state = (theta, omega)
        action = policy(state)  # 获取建议的扭矩
        plot_point(theta, omega, color_based_on(action))
```

**对于碰撞避免系统**：其状态是四维的，动作是离散的（如爬升、下降、无建议）。我们无法一次性可视化整个策略，但可以绘制状态空间的二维切片。例如，我们可以固定其他两个状态维度，绘制“碰撞时间”与“相对高度”的关系图，并标注在每个点系统会建议采取何种动作。通过这种可视化，有时能发现反直觉的策略区域。

### 通过轨迹分区进行可视化

对于状态维度更高或具有非马尔可夫性（即决策依赖于历史状态）的复杂系统，我们可以采用另一种方法：
1.  将状态空间划分为多个区域。
2.  运行大量模拟轨迹。
3.  记录轨迹经过每个区域时所采取的动作。
4.  对于每个区域，可以统计最常采取的动作并进行可视化（例如，用不同颜色表示不同动作）。

这种方法的好处是它不依赖于策略是否仅为当前状态的函数，因此也适用于历史依赖型的复杂系统。

总之，策略可视化是一种简单但强大的工具，能有效帮助发现系统设计中的潜在问题。

## 特征重要性 🔍

上一节我们探讨了如何直观地可视化策略。本节中，我们将深入探讨一个更核心的可解释性概念：特征重要性。

特征重要性分析旨在量化系统决策中每个输入特征（或状态变量）的贡献程度。这是许多人提到“可解释性”时首先想到的技术。理解哪些特征对决策影响最大，能帮助我们判断系统是否依赖于合理的逻辑，还是被无关或虚假的关联所误导。

**核心思想**：通过系统性地扰动或移除某个输入特征，观察模型输出（如决策或预测）的变化程度。变化越大，说明该特征越重要。

**常见方法包括**：
*   **排列重要性**：在验证集上随机打乱某一特征的值，破坏其与真实标签的关系，然后评估模型性能下降的幅度。
*   **基于梯度的敏感度分析**：对于可微模型（如神经网络），计算模型输出相对于输入特征的梯度。梯度绝对值大的特征，其微小变化会导致输出剧烈变动，表明其重要性高。
*   **SHAP值**：一种基于博弈论的方法，为每个特征分配一个数值，代表该特征对某个特定预测的贡献。

通过特征重要性分析，我们不仅能验证系统是否如我们所期望的那样关注关键变量（例如，碰撞避免系统应高度关注“碰撞时间”和“相对距离”），还能发现潜在的偏见或对无关特征的过度依赖。
