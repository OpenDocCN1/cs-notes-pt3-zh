在本节课中，我们将学习代数编码理论的基本动机和核心问题。编码理论旨在解决信息在存储或传输过程中可能被破坏的问题，通过引入冗余来保护原始数据。

## 基本问题

编码理论的基本问题如下：我们有一个长度为 **K** 的消息 **X**（例如一个长度为 K 的比特串）。我们通过某种方式对 **X** 进行**编码**，得到一个长度为 **N** 的**码字 C**，其中 **N > K**。这样做的目的是为原始数据添加冗余。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_5.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_7.png)

接下来，预期会发生一些“坏事”，例如某些比特在传输或存储过程中被破坏（如翻转）。我们最终得到的是一个被破坏的码字，记作 **C̃**。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_9.png)

编码理论的目标是设计这种编码映射方式，使得在给定被破坏的码字 **C̃**（或对其的部分访问）后，我们能够**恢复出原始消息 X** 或其相关信息。

## 典型应用场景

这个基本框架出现在许多应用中。以下是两个典型例子：

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_13.png)

### 1. 通信 📡

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_15.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_17.png)

假设有一个发送者**爱丽丝**和一个接收者**鲍勃**。爱丽丝希望发送消息 **X** 给鲍勃，但他们之间存在一个**有噪信道**。任何通过该信道发送的信息都可能在途中被破坏。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_19.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_20.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_21.png)

以下是通信场景的步骤：
1.  爱丽丝将消息 **X** 编码为码字 **C**。
2.  爱丽丝通过有噪信道发送 **C**。
3.  信道对 **C** 造成破坏，鲍勃接收到的是 **C̃**。
4.  鲍勃需要从 **C̃** 中解码，恢复出爱丽丝原本想发送的消息 **X**。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_23.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_25.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_27.png)

### 2. 存储 💾

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_29.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_30.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_32.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_34.png)

在这个例子中，消息 **X** 不再是要传输的信息，而是我们想要存储的文件（同样是一个长度为 K 的比特串）。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_36.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_37.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_39.png)

以下是存储场景的步骤：
1.  我们不直接存储文件 **X**，而是先将其编码为码字 **C** 以引入冗余。
2.  将码字 **C** 存储到存储介质（如硬盘、U盘）上。
3.  存储介质可能发生故障（如磁盘退化、损坏），导致读取时得到的是被破坏的码字 **C̃**。
4.  我们需要从 **C̃** 中恢复出原始文件 **X**，以避免数据丢失。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_41.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_42.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_44.png)

## 编码方案的核心考量

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_52.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_54.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_56.png)

现在，让我们聚焦于我们对一个编码方案关心哪些方面。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_58.png)

以下是四个核心考量因素：
1.  **处理“坏事”的能力**：即方案能够应对何种类型的错误或损坏。
2.  **恢复所需信息的能力**：即我们期望从被破坏的数据中恢复出关于 **X** 的哪些信息（例如全部恢复，或仅恢复部分）。
3.  **最小化开销**：对我们而言，这通常意味着希望最大化比率 **K / N**。这里，**K** 是原始消息长度，**N** 是最终存储或发送的码字长度。这个比率被称为**码率**。比率越接近 1，意味着冗余开销越小；比率越小，则开销越大。我们的目标是尽可能减少开销，即让码率尽可能接近 1。
4.  **效率**：例如，编码映射（将 **X** 映射为 **C**）和解码映射（从 **C̃** 恢复 **X**）需要能够高效运行。

## 核心问题与权衡

考虑到以上四个我们关心的方面，本课程后续要解决的核心问题（或者说是一系列问题）是：**在这些因素之间，最佳的权衡是什么？**

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_67.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_68.png)

例如，一个直观的权衡是：如果我们极力最小化开销（即添加很少的冗余），那么保护数据免受损坏并恢复信息的能力就会变得困难得多。

之所以说这是一系列问题而非单一问题，是因为我们尚未精确定义上述概念：
*   “坏事”具体指什么？是指一定比例的符号被破坏，还是指部分符号丢失（删除），或是其他情况？
*   我们想恢复关于 **X** 的什么信息？是完全恢复 **X**，还是仅恢复其第一位，或是其他？
*   “高效”具体指什么？我们以何种方式、多大成本访问被破坏的码字 **C̃**？我们拥有多少计算资源来处理获得的信息？

定义这些概念的方式有很多种，每种定义都会引出一系列关于这些权衡的、各不相同且非常有趣的问题。

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_70.png)

![](img/4f1c76e21b52d5bd48a2118ef3b08f79_72.png)
