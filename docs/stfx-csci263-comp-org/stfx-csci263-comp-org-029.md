在本节课中，我们将学习如何为我们的计算机系统添加条件判断能力。目前，我们的指令集缺少像“如果某个条件成立，则执行A，否则执行B”这样的分支指令。我们将通过引入一个**状态标志寄存器**来解决这个问题，它能够记录算术运算的结果状态，从而为条件分支提供依据。

## 当前系统的局限性

![](img/9fddddf62418395b6af8557fe518611e_9.png)

![](img/9fddddf62418395b6af8557fe518611e_10.png)

![](img/9fddddf62418395b6af8557fe518611e_12.png)

上一节我们介绍了基本的算术逻辑单元（ALU）和指令执行流程。本节中我们来看看一个关键缺失的功能：条件分支。

![](img/9fddddf62418395b6af8557fe518611e_14.png)

![](img/9fddddf62418395b6af8557fe518611e_16.png)

![](img/9fddddf62418395b6af8557fe518611e_18.png)

我们目前无法实现条件判断。例如，我们无法编写类似“如果某个数小于10，则输出0，否则输出1”的程序。虽然我们有跳转（Jump）指令，但它是一个无条件跳转，无论情况如何都会执行。

以下是一个理想中的条件判断程序逻辑：
```
加载数值 F
如果 F < 10，则跳转到地址 4
输出 D（假设D=1）
停机
地址4：
输出 D（假设D=0）
停机
```
这个程序展示了我们需要的核心能力：**仅当特定条件为真时才进行跳转**。然而，我们目前没有硬件机制来检查“F < 10”这样的条件。

![](img/9fddddf62418395b6af8557fe518611e_20.png)

![](img/9fddddf62418395b6af8557fe518611e_22.png)

## 引入条件检查的思路

为了支持条件分支，我们需要硬件能够检查某些条件。一个通用的方法是围绕数字“0”来构建条件，因为检查结果是否为0相对容易。

我们可以通过计算两个数的差值来判断它们的关系：
*   **检查相等**：如果差值为0，则两数相等。
*   **检查大小**：如果差值为负，则第一个数小于第二个数；如果为正，则大于。

![](img/9fddddf62418395b6af8557fe518611e_24.png)

![](img/9fddddf62418395b6af8557fe518611e_26.png)

因此，我们将重点关注三种运算结果状态：
1.  **结果是否为0（Zero）**
2.  **结果是否为负（Negative）** - 对于有符号数，检查最高位（符号位）
3.  **运算是否产生进位/溢出（Carry）** - 当结果超出表示范围时发生

![](img/9fddddf62418395b6af8557fe518611e_28.png)

![](img/9fddddf62418395b6af8557fe518611e_29.png)

从理论上讲，只需要一种条件判断就可以实现所有逻辑，但那样会使编程变得复杂。提供多种状态标志可以简化程序设计。

## 状态标志的实现原理

![](img/9fddddf62418395b6af8557fe518611e_31.png)

观察典型的ALU设计，除了输出运算结果外，它还会产生一些“副作用”输出，即状态标志。这正是我们需要的。

![](img/9fddddf62418395b6af8557fe518611e_33.png)

![](img/9fddddf62418395b6af8557fe518611e_35.png)

在之前的实验中，我们构建过比较器电路。而我们现在要采用的策略——使用专门的寄存器来锁存ALU的状态标志——是硬件中常见且易于理解的一种实现方式。

![](img/9fddddf62418395b6af8557fe518611e_37.png)

![](img/9fddddf62418395b6af8557fe518611e_39.png)

![](img/9fddddf62418395b6af8557fe518611e_41.png)

以下是三种状态标志的具体检测方法：

![](img/9fddddf62418395b6af8557fe518611e_43.png)

**1. 零标志（Z）**
检测结果是否为零，即检查结果的所有位是否都为0。
*   **实现思路**：对结果的所有位进行**或非（NOR）** 运算。当所有位都为0时，NOR输出为1。
    *   公式：`Z = NOR(bit7, bit6, bit5, bit4, bit3, bit2, bit1, bit0)`

![](img/9fddddf62418395b6af8557fe518611e_45.png)

**2. 符号标志（S）/负标志（N）**
检测结果的最高位（对于有符号数，即符号位）是否为1。
*   **实现思路**：直接取运算结果的最高位。
    *   代码表示：`S = result[7]` （假设为8位系统，最高位是第7位）
*   **注意**：硬件本身不知道数据是**有符号**还是**无符号**整数。它只是报告最高位的状态。程序员需要根据上下文解释该标志的含义。

![](img/9fddddf62418395b6af8557fe518611e_47.png)

![](img/9fddddf62418395b6af8557fe518611e_49.png)

![](img/9fddddf62418395b6af8557fe518611e_51.png)

![](img/9fddddf62418395b6af8557fe518611e_53.png)

**3. 进位标志（C）**
检测运算（如加法）是否产生了进位。
*   **实现思路**：直接连接加法器电路的进位输出信号。
    *   代码表示：`C = adder_carry_out`

![](img/9fddddf62418395b6af8557fe518611e_55.png)

## 关键设计挑战与解决方案

![](img/9fddddf62418395b6af8557fe518611e_57.png)

现在，我们计划在ALU输出后添加检测电路来生成Z、S、C信号。但这里存在一个关键的设计问题。

考虑指令执行过程：例如执行减法指令时，一个微步骤是将ALU的结果写回A寄存器。问题在于：
1.  在“写回”这个瞬间，ALU输出的是我们关心的差值结果（例如 5 - 5 = 0）。此时零标志应为真。
2.  但是，一旦结果存入A寄存器，A寄存器的值就变成了0。
3.  由于ALU始终对A和B寄存器的当前值进行运算，在下一个瞬间，ALU计算的就是 `0 - 5`，其状态标志会立刻改变，而这并不是我们关心的上次运算的结果。

![](img/9fddddf62418395b6af8557fe518611e_59.png)

![](img/9fddddf62418395b6af8557fe518611e_60.png)

![](img/9fddddf62418395b6af8557fe518611e_62.png)

**核心矛盾**：ALU的状态标志始终在变化，但我们只关心在**执行特定算术指令的那个时刻**所产生的标志。

![](img/9fddddf62418395b6af8557fe518611e_64.png)

![](img/9fddddf62418395b6af8557fe518611e_66.png)

![](img/9fddddf62418395b6af8557fe518611e_68.png)

**解决方案**：使用一个寄存器来锁存状态标志。
我们引入一个**标志寄存器（Flag Register）**。仅当执行我们关心的算术运算（如ADD， SUB）时，才使能这个寄存器，将此刻的Z、S、C信号保存下来。在其他时间，该寄存器保持内容不变。这样，所有后续的条件检查都基于这个寄存器中保存的、上一次有效运算的状态。

![](img/9fddddf62418395b6af8557fe518611e_70.png)

![](img/9fddddf62418395b6af8557fe518611e_71.png)

## 标志寄存器的工作机制

![](img/9fddddf62418395b6af8557fe518611e_81.png)

![](img/9fddddf62418395b6af8557fe518611e_83.png)

以下是结合了标志寄存器的系统设计思路：
1.  ALU持续运算并产生实时状态标志（Z， S， C）。
2.  在执行加法或减法指令的“写回结果”微操作时，控制逻辑同时发出三个信号：
    *   使能A寄存器（接收结果）
    *   使能标志寄存器（锁存当前状态标志）
    *   设置相应的ALU操作码（如减法）
3.  标志寄存器将此刻的状态保存下来。
4.  此后，无论A、B寄存器如何变化，标志寄存器中的值保持不变，直到下一次算术运算被锁存。

![](img/9fddddf62418395b6af8557fe518611e_85.png)

![](img/9fddddf62418395b6af8557fe518611e_87.png)

![](img/9fddddf62418395b6af8557fe518611e_89.png)

通过这种方式，我们成功地将“上一次算术运算的结果状态”保存了下来，为实现条件跳转指令（如“如果为零则跳转”、“如果为负则跳转”）奠定了硬件基础。
