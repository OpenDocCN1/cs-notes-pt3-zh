# 030：条件跳转指令的实现 🧠






在本节课中，我们将学习如何为我们的计算机系统实现条件跳转指令。我们将探讨如何利用状态标志寄存器，以及如何修改控制逻辑，使得程序能够根据算术运算的结果（如是否为0、是否为负、是否产生进位）来决定是否跳转到不同的内存地址执行代码。

---




上一节我们介绍了状态标志寄存器的硬件设计，它能够捕获并存储ALU运算结果的状态（零标志、符号标志、进位标志）。本节中我们来看看如何利用这些标志来实现条件跳转指令。


## 条件跳转指令的需求

条件跳转指令允许程序根据某些条件（即状态标志是否为高电平）跳转到RAM的不同部分执行。如果相应的状态标志为高，则执行跳转；如果为低，则指令相当于一个空操作（NOP），程序继续顺序执行。



例如，考虑一个“为零则跳转”（JMP Z）指令。如果零状态标志为高，则更新程序计数器（PC）以跳转；如果为零，则忽略该指令并继续执行。




## 控制逻辑的扩展


为了实现条件跳转，我们需要扩展现有的控制逻辑。核心挑战在于：同一条指令（如JMP Z）需要根据状态标志的不同，执行两种完全不同的微码序列（跳转或NOP）。

以下是实现这一点的关键步骤：

1.  **扩展查找表输入**：我们原有的控制逻辑查找表有6个输入（4位操作码 + 2位微码计数器）。现在需要增加3个输入，分别对应三个状态标志（进位C、零Z、符号S）。因此，查找表现在有9个输入。
    *   输入模式示例：`[C Z S] [操作码] [微码计数器]`
2.  **增大查找表**：由于增加了3个输入，查找表的条目数变为原来的2^3 = 8倍。这意味着对于每一个操作码和微码计数器的组合，现在都有8个对应的输出条目，分别对应8种不同的标志位状态组合（000, 001, 010, ..., 111）。
3.  **处理冗余**：对于绝大多数非条件跳转指令（如加法、加载），无论状态标志为何值，其控制信号都应相同。因此，查找表中这8个条目的大部分内容是重复的。只有针对三条条件跳转指令（JMP C, JMP Z, JMP S）的条目，才会根据对应的标志位状态发生变化。
4.  **新增控制信号**：我们需要一个新的控制信号 `FLG_EN`，用于在适当的时机（仅在执行加法或减法操作时）将ALU的状态锁存到标志寄存器中。




## 状态标志的锁存时机

一个关键的设计决策是：何时启用标志寄存器以锁存ALU的状态？


*   **不能在取指阶段**：取指操作对所有指令都应一致，不应在此修改标志。
*   **不能在“ALU输出到A寄存器”之后**：如果在这之后锁存，A寄存器的值已经改变，ALU的输入也随之改变，此时锁存的状态已不是上一运算的结果。
*   **正确时机**：应在“ALU输出”微码步骤的同一时刻锁存。此时，ALU输出的正是刚刚计算完成的结果值，其状态标志（如结果是否为0）正是我们想要记录的。
    *   在微码序列中，这对应于加法/减法指令的第三个时钟周期（假设每个指令固定4周期）。我们需要在该周期的控制信号中同时包含 `ALU_OUT` 和 `FLG_EN`。


虽然理论上存在锁存时序风险（A寄存器先于标志寄存器更新），但在我们同步的系统中，只要控制信号在同一时钟沿生效，这个风险可以忽略。更保守的做法是为锁存标志增加一个独立的时钟周期，但这会降低性能。

## 更新系统与查找表内容




现在，我们将标志寄存器集成到完整的系统图中。ALU的输出连接到标志检测逻辑，标志寄存器的输出（3位）作为新增的输入送入控制逻辑查找表。`FLG_EN` 信号则作为查找表的一个新输出控制信号。



最后，我们需要使用脚本重新生成查找表（ROM）的内容。脚本的逻辑如下：


1.  为所有指令定义其基本的微码序列（对应标志位为000的情况）。
2.  对于8种可能的标志位状态组合（000到111），分别生成一个指令微码列表。
3.  在这个列表中，对于三条条件跳转指令（JMP C, JMP Z, JMP S），检查当前标志位组合中对应的位是否为1。
    *   如果为1，则将该指令的微码替换为无条件跳转（JMP A）的微码。
    *   如果为0，则保持其原有的NOP微码。
4.  将所有8个列表的内容顺序写入ROM文件。

通过这种方式，当CPU执行 `JMP Z` 且零标志为1时，查找表会根据输入 `[操作码][Z=1]` 找到对应的条目，该条目输出的控制信号与 `JMP A` 相同，从而执行跳转。

## 条件跳转的应用示例



有了条件跳转，我们可以实现真正的分支逻辑。回顾之前“判断某值是否小于10”的问题，现在可以这样实现：


1.  `LDAI val`    // 加载值到A寄存器
2.  `SUBI 10`     // 用A寄存器的值减去10
3.  `JMPS label`  // 如果结果为负（符号标志S=1），则跳转到 `label` 处
4.  `OUTD`        // 否则（值>=10），输出0
5.  `HALT`
6.  `label: OUTE` // 跳转到这里（值<10），输出1
7.  `HALT`


对应的机器码可能如下所示（假设地址和操作码）：
`[LDAI] [5] [SUBI] [10] [JMPS] [6] [OUTD] [HALT] [OUTE] [HALT]`

本节课中我们一起学习了条件跳转指令的实现原理。我们扩展了控制逻辑查找表，利用状态标志位作为额外的输入来选择指令的执行路径，从而实现了基于运算结果的分支决策。这使得我们的计算机系统达到了“图灵完备”，能够执行任何可计算的任务（在有限内存范围内）。核心的修改在于硬件上增加了标志寄存器，并在软件（微码）上通过扩展的查找表来响应这些标志。
