# 操作系统：31：伙伴分配器与Slab分配器 🧠

在本节课中，我们将学习两种用于动态内存分配的高效算法：伙伴分配器和Slab分配器。这两种方法通过限制分配请求的特性（如大小必须是2的幂次或所有对象大小相同），来简化管理并提升性能。这对于操作系统内核管理内存尤其重要。

## 伙伴分配器

上一节我们讨论了通用的动态内存分配（如`malloc`）。本节中我们来看看伙伴分配器，它通过限制分配大小为2的幂次来优化性能。

伙伴分配器的工作原理是：它管理一大块连续内存，并将其递归地分割成大小为2的幂次的小块，直到找到能满足请求的最小块。释放时，它会尝试合并相邻的“伙伴”块以形成更大的空闲块。

### 核心概念与数据结构

伙伴分配器为每个可能的2的幂次大小维护一个独立的空闲链表。假设最大块大小为 `2^n`，那么我们需要 `n+1` 个空闲链表。

**公式**： 分配大小 = `2^k`，其中 `0 <= k <= n`。

### 分配算法

以下是分配内存的步骤：

1.  用户请求大小为 `s` 的内存。
2.  计算满足 `2^k >= s` 的最小 `k`。如果 `s` 不是2的幂次，则会产生内部碎片。
3.  检查大小为 `2^k` 的空闲链表。
    *   如果链表非空，则取出第一个块分配给用户。
    *   如果链表为空，则检查 `2^(k+1)` 的空闲链表，依此类推，直到找到一个非空的链表。
4.  当找到一个更大的空闲块（例如大小为 `2^m`，其中 `m > k`）时，递归地将其对半分割，直到得到大小为 `2^k` 的块。
    *   每次分割产生的“伙伴”块会被插入到对应大小的空闲链表中。
5.  将最终得到的大小为 `2^k` 的块标记为已使用，并返回给用户。

### 释放与合并算法

以下是释放内存的步骤：

1.  用户释放一个大小为 `2^k` 的块。
2.  找到该块的“伙伴”块（其地址可以通过简单的位运算确定）。
3.  检查伙伴块是否空闲且大小相同。
4.  如果伙伴块空闲，则将这两个块合并成一个大小为 `2^(k+1)` 的大块。
5.  递归地尝试合并新形成的大块与其伙伴，直到无法合并为止。
6.  将最终合并得到的块插入到对应大小的空闲链表中。

### 示例说明

假设伙伴分配器管理着256字节的内存。当前状态如下图所示，红色块（32B）和蓝色块（64B）已被分配。

![](img/9fe48bfdedc3fe1a2147528bdddfa38f_1.png)

此时，空闲链表情况如下：
*   32B 链表：有1个空闲块（图中白色32B块）。
*   64B 链表：有2个空闲块（图中两个白色64B块）。

**场景1：请求分配28字节**
1.  28不是2的幂次，向上取整为32。
2.  检查32B空闲链表，发现有一个空闲块。
3.  直接将该块分配出去，并标记为已使用。

**场景2：再次请求分配32字节**
1.  检查32B空闲链表，发现已无空闲块。
2.  检查64B空闲链表，发现有空闲块。
3.  取出一个64B空闲块，将其分割成两个32B的“伙伴”块。
4.  将一个32B块分配给用户，将另一个32B块插入32B空闲链表。

**场景3：释放蓝色的64B块**
1.  找到其伙伴块（相邻的64B块），发现它是空闲的。
2.  将这两个64B块合并成一个128B的空闲块。
3.  尝试进一步合并这个128B块与其伙伴，但伙伴（另一个128B块）已被使用，因此停止合并。
4.  将合并得到的128B块插入128B空闲链表。

### 优缺点

**优点**：
*   **搜索速度快**：只需检查对应大小的链表是否为空，最坏情况为 `O(log n)`。
*   **合并高效**：通过“伙伴”关系，可以快速、确定性地合并相邻空闲块，减少外部碎片。
*   **实现相对简单**。

**缺点**：
*   **内部碎片**：如果请求大小不是2的幂次，必须向上取整，导致内存浪费。
*   **内存利用率可能不高**：对于大小接近但略超2的幂次的请求，浪费可能接近50%。

## Slab分配器

伙伴分配器处理的是不同大小的请求。本节我们来看Slab分配器，它专门用于高效分配大量**相同大小**的对象。

Slab分配器的核心思想是：预先从底层分配器（如伙伴分配器）申请一大块连续内存（称为一个“Slab”或“缓存”），并将其划分为多个等大的“槽位”（Slots），用于存放特定类型的对象。通过位图来管理每个槽位的分配状态。

### 核心概念与数据结构

*   **缓存 (Cache)**： 管理同一类对象的所有Slab。
*   **Slab**： 一个连续的内存页或块，被分割成多个等大的对象槽位。
*   **位图 (Bitmap)**： 每个Slab关联一个位图，每一位对应一个槽位。`0`表示空闲，`1`表示已分配。

**代码描述**： 分配状态可以用一个字节数组表示：
```c
unsigned char bitmap[BITMAP_SIZE]; // 每一位代表一个槽位
```

### 工作原理

1.  **初始化**： 为特定对象类型创建一个缓存，并从底层分配器（如伙伴分配器）申请第一个Slab。
2.  **分配对象**：
    *   扫描Slab的位图，寻找第一个为 `0` 的位。
    *   将该位置 `1`。
    *   根据位索引计算出对应槽位的内存地址，返回给用户。
3.  **释放对象**：
    *   根据对象地址计算出它在Slab中的位索引。
    *   将位图中对应的位清 `0`。
4.  **Slab管理**：
    *   如果一个Slab的所有槽位都满了，当再有分配请求时，缓存会从底层分配器申请一个新的Slab。
    *   如果一个Slab的所有槽位都变为空闲，缓存可以选择将此Slab释放回底层分配器，以减少内存占用。

### 示例与优势

假设对象A的大小为20字节。如果直接使用伙伴分配器，每次分配都要向上取整到32字节，浪费12字节。

使用Slab分配器：
1.  向伙伴分配器申请一个较大的块（如1024字节）作为一个Slab。
2.  在这个Slab中，可以容纳 `1024 / 20 ≈ 51` 个对象A，外加少量空间用于管理位图。
3.  分配和释放对象只需操作位图，速度极快。
4.  由于对象大小固定，**没有内部碎片**（在Slab内部）。Slab本身的大小可能不是对象大小的整数倍，会产生少量“Slab内部碎片”，但相比每次分配都浪费要少得多。

### 应用场景

Slab分配器非常适合操作系统内核中频繁分配和释放的小型、固定大小的数据结构，例如：
*   进程描述符 (`task_struct`)
*   文件对象 (`file`)
*   索引节点 (`inode`) —— 这与实验6中管理`inode`表的方式非常相似。

## 总结

本节课中我们一起学习了两种高效的内存分配策略：

1.  **伙伴分配器**：通过将分配大小限制为2的幂次，使用多级空闲链表和递归的拆分/合并算法，实现了快速且碎片化程度可控的内存分配。它牺牲了部分内部碎片来换取性能和可预测性。
2.  **Slab分配器**：针对固定大小对象的分配进行优化。它从底层分配器获取大块内存并划分为等大的槽位，使用位图进行管理，实现了近乎零开销的分配与释放，并基本消除了内部碎片。

![](img/9fe48bfdedc3fe1a2147528bdddfa38f_3.png)

这两种分配器并非互斥，在实际系统（如Linux内核）中常常结合使用：伙伴分配器作为页级分配器，管理大块的物理内存页；而Slab分配器则构建在伙伴分配器之上，用于高效分配内核中的小对象。理解这些机制有助于我们设计更高效、更可靠的内存管理系统。
