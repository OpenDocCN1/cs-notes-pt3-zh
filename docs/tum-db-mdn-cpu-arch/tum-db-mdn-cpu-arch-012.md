## 排序操作 🔄

上一节我们介绍了连接操作的实现，本节中我们来看看排序操作。排序是一个极其有用的运算符，因为你可以使用排序来实现许多其他运算符。虽然从性能角度看，排序通常不如哈希连接高效，但它是一种极其通用的方案。

排序的基本策略是外部排序。首先，我们将尽可能多的数据加载到主内存中，然后在内存中使用某种算法进行排序，接着将排序后的数据作为一个“有序段”写入磁盘。重复此过程，我们会得到许多有序段。最后，我们通过合并这些有序段来得到最终排序结果。

以下是外部排序的高层步骤：
1.  加载数据到内存直到内存满。
2.  在内存中对数据进行排序。
3.  将排序后的数据作为一个有序段写入磁盘。
4.  重复步骤1-3，直到处理完所有输入数据。
5.  合并所有磁盘上的有序段。

在实现排序时，有两个关键设计点：如何将内存中的数据排序后写入磁盘（刷新），以及如何合并有序段。

### 刷新策略

最简单的刷新策略是使用快速排序。当内存满时，调用快速排序算法对内存中的数据进行排序，然后写入磁盘并释放内存。快速排序实现得当的话速度很快。

![](img/405316ba79d12997a8d94943ed9d528b_3.png)

然而，如果考虑到磁盘I/O较慢，我们可能更倾向于第二种方案：堆排序与替换选择。这种方法可以产生比内存容量更长的有序段。其工作原理是维护一个最小堆。当新元组到来时，如果堆未满则插入；如果堆已满，则输出堆顶的最小元素，并用新元组替换堆顶，然后恢复堆的性质。如果新元组比已输出的最小元素还小，则将其放入一个新堆中。这种方法在输入数据接近有序时尤其高效，可能只产生一个有序段。

### 合并策略

合并阶段通常采用“即时合并”的方式，即并行读取所有有序段，并始终输出当前最小的元素。为了高效地找到N个有序段中的最小元素，不应遍历所有元素，而应使用优先队列（如堆）。更高效的数据结构是“败者树”，它可以将比较次数减少一半。

如果有序段数量过多，无法一次性合并，则需要进行多轮部分合并，即每次合并一部分有序段，生成更大的有序段，直到可以最终合并为止。

## 分组操作 📊

分组操作通常与聚合函数（如 `SUM`, `COUNT`）一起使用。实现分组有两种主要方法：基于排序和基于哈希。

基于排序的方法很简单：先按分组属性对输入进行排序，然后顺序扫描，相同分组的元组会相邻，从而轻松进行聚合。但排序的复杂度是 `O(N log N)`，成本较高。

基于哈希的方法则是在内存中构建一个哈希表。对于每个输入元组，根据分组属性计算哈希值，在哈希表中查找或创建对应的组，并更新聚合值。只要哈希表能放入内存，这种方法就非常高效。如果数据量超过内存，则需要像哈希连接一样进行分区和合并。

以下是一个内存中分组操作的伪代码框架：
```python
# 初始化哈希表
hash_table = {}

def consume(tuple):
    key = tuple.group_by_attribute
    if key in hash_table:
        # 更新现有组的聚合值，例如 sum
        hash_table[key].aggregate_value += tuple.value
    else:
        # 创建新组
        hash_table[key] = new Group(tuple.value)

# 处理完所有输入后，扫描哈希表输出结果
for group in hash_table.values():
    output(group)
```
处理可变长度数据（如字符串的 `MIN/MAX`）时，需要预留最大空间或使用动态内存分配。

## 集合运算 ➕➖✖️

集合运算包括并集（`UNION`）、交集（`INTERSECT`）和差集（`EXCEPT`），每种都有允许重复（`ALL`）和不允许重复两种语义。

*   **`UNION ALL`**：实现非常简单，只是将两个输入流拼接起来。
*   **`UNION`（去重）**：可以先执行 `UNION ALL`，然后通过分组操作去除重复。或者直接构建一个哈希表来去重。
*   **`INTERSECT` 和 `EXCEPT`**：与半连接和反连接类似，但需要注意重复项的处理。对于 `INTERSECT ALL` 和 `EXCEPT ALL`，其语义可以通过计算元素在左右两边出现的频率（计数）来定义。
    *   `INTERSECT ALL` 的结果中，每个元素的出现次数是其左右两边出现次数的最小值。
    *   `EXCEPT ALL` 的结果中，每个元素的出现次数是其左边出现次数减去右边出现次数（结果不小于0）。

因此，可以通过先对两边分别进行分组计数，然后根据上述规则计算最终输出的元素及其次数来实现 `INTERSECT ALL` 和 `EXCEPT ALL`。

## 代码生成 🛠️

![](img/405316ba79d12997a8d94943ed9d528b_7.png)

为了获得最佳性能，我们需要将查询计划编译成可执行代码，而不仅仅是解释执行。虽然可以生成字节码，但生成机器码能带来最高的效率。如今，我们可以利用现有的代码生成框架（如 LLVM）来简化这项工作，无需手动编写汇编代码。

LLVM 是一个编译器基础设施，它提供了类似低级汇编的中间表示，但具有一些优点：
*   **无限寄存器**：在 LLVM IR 中，可以假设有无限多个寄存器，由后端负责映射到物理寄存器。
*   **强类型**：每个寄存器都有明确的类型。
*   **静态单赋值**：每个变量只被赋值一次，这简化了数据流分析。循环等控制流通过 `phi` 节点来处理。

![](img/405316ba79d12997a8d94943ed9d528b_9.png)

将标量表达式（如算术运算、比较）编译到 LLVM IR 通常很直接。复杂的操作（如正则表达式匹配）则更适合用 C++ 实现预编译函数，然后从生成的代码中调用。

![](img/405316ba79d12997a8d94943ed9d528b_11.png)

真正的挑战在于如何编译关系运算符（如连接、分组）。传统的迭代器模型在代码局部性和减少分支方面并非最优。

![](img/405316ba79d12997a8d94943ed9d528b_13.png)

![](img/405316ba79d12997a8d94943ed9d528b_15.png)

### 数据中心的执行模型

![](img/405316ba79d12997a8d94943ed9d528b_17.png)

![](img/405316ba79d12997a8d94943ed9d528b_19.png)

![](img/405316ba79d12997a8d94943ed9d528b_21.png)

![](img/405316ba79d12997a8d94943ed9d528b_23.png)

更好的方法是采用**数据中心的执行模型**。其核心思想是让代码围绕数据组织，而不是让数据在操作符间移动。目标是尽可能少地读写数据，将数据长时间保留在 CPU 寄存器中，从而提高局部性并减少分支。

![](img/405316ba79d12997a8d94943ed9d528b_25.png)

在这种模型下，查询计划被划分为多个**流水线**。每个流水线是一段紧凑的循环代码，它从数据源读取一批数据，应用一系列操作（过滤、计算哈希、探测等），然后将结果物化到下一个流水线断点（如哈希表）。操作符的边界变得模糊，代码根据数据流而非操作符逻辑来组织。

![](img/405316ba79d12997a8d94943ed9d528b_27.png)

![](img/405316ba79d12997a8d94943ed9d528b_28.png)

![](img/405316ba79d12997a8d94943ed9d528b_30.png)

例如，一个包含过滤和哈希连接的计划可能被编译成两个流水线：
1.  流水线1：循环扫描表R1，过滤元组，并将其插入哈希表H1。
2.  流水线2：循环扫描表R2，过滤元组，探测哈希表H1，并输出结果。

![](img/405316ba79d12997a8d94943ed9d528b_32.png)

### 生成代码的过程

![](img/405316ba79d12997a8d94943ed9d528b_34.png)

代码生成使用“生产者-消费者”接口的概念，但这发生在编译时。每个操作符提供“生成代码”的函数。例如，哈希连接的 `produce` 函数会：
1.  递归调用左子节点的 `produce` 函数，生成构建哈希表的代码（循环读取、计算哈希、物化到内存）。
2.  递归调用右子节点的 `produce` 函数，生成探测哈希表的代码（循环读取、计算哈希、探测、检查条件、输出）。

在生成过程中，会调用辅助函数来生成计算哈希值、比较元组等具体操作的 LLVM IR 指令。最终结果是多个紧密循环的机器码，每个循环对应一个流水线。

## 并行执行 ⚡

![](img/405316ba79d12997a8d94943ed9d528b_36.png)

现代 CPU 拥有多个核心，为了充分利用硬件，必须实现查询内的并行执行。并行有两种主要形式：
*   **查询间并行**：多个查询同时运行，相对简单。
*   **查询内并行**：单个查询利用多个核心执行，这是我们关注的重点。

查询内并行又可分为：
*   **水平并行**：将查询计划树的不同独立分支分配到不同线程执行。
*   **垂直并行**（流水线并行）：在单个操作符内部实现并行，这是最强大和最通用的方式。

![](img/405316ba79d12997a8d94943ed9d528b_38.png)

### 传统的交换操作符模型

早期系统使用**交换操作符**来封装并行性。操作符本身不知道并行，交换操作符负责在线程间重新分区数据。例如，对于并行分组聚合，可以先将数据哈希分区到多个线程，每个线程进行本地聚合，然后通过交换操作符将结果汇总到单个线程进行最终聚合。

![](img/405316ba79d12997a8d94943ed9d528b_40.png)

![](img/405316ba79d12997a8d94943ed9d528b_42.png)

然而，这种方法有几个缺点：
1.  并行度被硬编码在查询计划中，不灵活。
2.  容易造成负载不均衡。
3.  数据重分区（交换）本身开销很大。

![](img/405316ba79d12997a8d94943ed9d528b_44.png)

![](img/405316ba79d12997a8d94943ed9d528b_46.png)

![](img/405316ba79d12997a8d94943ed9d528b_48.png)

### 现代无共享并行执行

![](img/405316ba79d12997a8d94943ed9d528b_50.png)

更现代的方法是让每个操作符都感知并行，多个线程可以同时处理同一份数据。这要求数据结构（如哈希表）是线程安全的，但通过精心设计可以避免昂贵的锁。

一种高效的模式是**任务驱动并行**。将输入数据动态划分为大小适中的工作单元（称为 `morsel`）。一个调度器负责将这些 `morsel` 分配给空闲的工作线程。线程处理完一个 `morsel` 后，再从调度器获取下一个。这实现了动态的负载均衡，因为处理速度快的线程会处理更多的工作单元。

![](img/405316ba79d12997a8d94943ed9d528b_52.png)

对于哈希连接，可以这样实现：
1.  **构建阶段**：每个线程扫描部分输入数据，将元组存储在线程本地的内存中。所有线程完成后，我们就知道了元组总数，从而可以一次性分配一个大小合适的全局哈希表。然后，每个线程再次扫描自己本地存储的元组，使用原子操作（如 `compare-and-swap`）将元组指针安全地插入到全局哈希表的对应桶中。
2.  **探测阶段**：完全并行。每个线程获取输入数据的 `morsel`，计算哈希值，读取全局哈希表进行探测并生成结果。由于探测阶段是只读的，不需要同步。

![](img/405316ba79d12997a8d94943ed9d528b_54.png)

![](img/405316ba79d12997a8d94943ed9d528b_55.png)

这种方法避免了动态调整哈希表大小的复杂性，并通过任务窃取实现了良好的负载均衡。

![](img/405316ba79d12997a8d94943ed9d528b_57.png)

## 总结 📝

本节课我们一起深入学习了数据库系统中几个关键部分的实现。
*   我们探讨了**外部排序**的算法，包括刷新阶段的快速排序与替换选择策略，以及合并阶段的优先队列与败者树优化。
*   我们分析了**分组聚合**的两种实现方式：基于排序和基于哈希，并了解了如何处理可变长数据的聚合。

*   我们重点介绍了**代码生成**技术，了解了为何数据中心的执行模型比传统的迭代器模型更高效，以及如何利用 LLVM 等框架将查询计划编译成高效的、流水线化的机器码。
*   最后，我们讨论了**并行查询执行**，对比了传统的交换操作符模型与现代的无共享、任务驱动并行模型，并学习了如何实现一个线程安全、负载均衡的并行哈希连接。
