## 创建可执行脚本

![](img/5993a9a352f015b58d6149d8acf24f23_11.png)

到目前为止，我们一直在命令行进行交互式操作。但当你需要运行一个完整的分析，尤其是希望其他人能复现你的步骤时，将所有指令写入一个脚本会非常有帮助。脚本就像一份食谱，每次使用相同的工具运行相同的脚本，都应该得到相同的结果。

脚本本质上是一系列预先录制的指令，你可以一次性执行它们。无论是Python脚本、R脚本还是Shell脚本，这一点都成立。本节我们将主要使用Shell脚本。

### 脚本的运行方式

大多数脚本通过一个**解释器**在命令行运行。解释器是知道如何处理你提供的命令的程序。例如，Python和R是解释器，Shell程序（如bash）本身也是一个解释器。

![](img/5993a9a352f015b58d6149d8acf24f23_13.png)

运行脚本的常见模式如下：
```
解释器 脚本名 参数
```
例如，运行一个名为 `script.py` 的Python脚本：
```bash
python script.py input.txt output.txt
```

然而，还有另一种更简洁的方法：创建**可执行脚本**，这样你就不必在每次运行时都先指定解释器。调用方式如下：
```bash
./script.py input.txt output.txt
```
这里的 `./` 表示在当前目录下查找文件。之所以需要这样做，是因为Shell默认只在系统路径中查找命令，而新创建的脚本通常不在路径中。

### Shebang：指定解释器

为了让Shell知道如何处理一个未指定解释器的可执行脚本，我们需要在脚本的第一行添加一个特殊的行，称为 **shebang**（或 hashbang）。它由 `#!` 开头，后面紧跟解释器的路径。

![](img/5993a9a352f015b58d6149d8acf24f23_15.png)

![](img/5993a9a352f015b58d6149d8acf24f23_17.png)

**Shebang的格式**：
```
#!解释器路径 [可选参数]
```
例如，指定使用bash解释器：
```bash
#!/usr/bin/env bash
```
使用 `#!/usr/bin/env bash` 是一种更灵活的方式，它会在当前环境变量 `PATH` 中查找 `bash`，这在你使用Pixi等工具管理环境时尤其重要，可以确保使用正确版本的bash。

### 实战：创建一个简单的Bash脚本

接下来，我们将创建一个名为 `beacon.sh` 的简单bash脚本。该脚本接受一个名字作为参数，然后每秒打印一次问候语。

1.  **创建脚本文件**：
    ```bash
    nano beacon.sh
    ```

![](img/5993a9a352f015b58d6149d8acf24f23_19.png)

2.  **编写脚本内容**：
    ```bash
    #!/usr/bin/env bash

    name=$1
    while true
    do
        echo "Hello $name"
        sleep 1
    done
    ```
    *   `#!/usr/bin/env bash`：shebang行，指定使用bash。
    *   `name=$1`：将命令行的第一个参数赋值给变量 `name`。注意，bash中变量赋值时等号两边不能有空格。
    *   `while true`：一个无限循环。
    *   `echo "Hello $name"`：打印问候语。使用变量时需加 `$` 符号。
    *   `sleep 1`：暂停1秒。
    *   `done`：标记while循环结束。

3.  **保存并退出nano**：
    按 `Ctrl+O` 保存，按 `Ctrl+X` 退出。

![](img/5993a9a352f015b58d6149d8acf24f23_21.png)

4.  **赋予脚本执行权限**：
    创建的文件默认没有执行权限。我们需要使用 `chmod` 命令修改文件权限。
    ```bash
    chmod u+x beacon.sh
    ```
    *   `chmod`：修改文件模式（权限）。
    *   `u+x`：为文件所有者（user）添加执行（execute）权限。

5.  **运行脚本**：
    ```bash
    ./beacon.sh Wes
    ```
    脚本将开始每秒打印“Hello Wes”。要停止脚本，请按 `Ctrl+C`。

![](img/5993a9a352f015b58d6149d8acf24f23_23.png)

## 使用Tmux管理持久会话

![](img/5993a9a352f015b58d6149d8acf24f23_25.png)

![](img/5993a9a352f015b58d6149d8acf24f23_27.png)

在远程高性能计算（HPC）环境中，我们经常需要运行耗时很长的任务。如果直接关闭终端窗口，正在运行的程序也会被终止。为了解决这个问题，我们需要一种方法来创建**持久化的会话**，即使断开连接，程序也能继续运行。

![](img/5993a9a352f015b58d6149d8acf24f23_29.png)

![](img/5993a9a352f015b58d6149d8acf24f23_31.png)

### 什么是Tmux？

`tmux`（终端复用器）是一个强大的工具，它允许你在一个终端窗口中创建多个**会话**、**窗口**和**窗格**。最重要的是，你可以从tmux会话中**分离**（detach），而会话及其内部运行的程序会在后台继续运行。之后你可以随时**附加**（attach）回该会话。

![](img/5993a9a352f015b58d6149d8acf24f23_33.png)

![](img/5993a9a352f015b58d6149d8acf24f23_35.png)

### Tmux基础操作

1.  **启动一个新的tmux会话**：
    ```bash
    tmux
    ```
    或创建一个命名会话：
    ```bash
    tmux new-session -s beacon
    ```

![](img/5993a9a352f015b58d6149d8acf24f23_37.png)

![](img/5993a9a352f015b58d6149d8acf24f23_39.png)

2.  **在tmux会话中工作**：
    此时，你处于tmux会话内部，可以像在普通终端一样运行任何命令（例如，运行 `./beacon.sh`）。

![](img/5993a9a352f015b58d6149d8acf24f23_41.png)

![](img/5993a9a352f015b58d6149d8acf24f23_43.png)

3.  **分离当前会话**：
    要离开tmux会话但让其继续运行，需要先进入tmux的**命令模式**。默认的触发键是 `Ctrl+B`，然后按 `d`。
    *   操作：先按 `Ctrl+B`，松开后再按 `d`。
    现在你回到了启动tmux之前的原始shell中，但 `beacon.sh` 仍在后台运行。

![](img/5993a9a352f015b58d6149d8acf24f23_45.png)

![](img/5993a9a352f015b58d6149d8acf24f23_47.png)

4.  **列出所有会话**：
    ```bash
    tmux list-sessions
    ```

5.  **重新附加到会话**：
    ```bash
    tmux attach -t beacon  # -t 代表目标(target)，后接会话名
    ```

![](img/5993a9a352f015b58d6149d8acf24f23_49.png)

![](img/5993a9a352f015b58d6149d8acf24f23_51.png)

6.  **在会话内终止程序**：
    在tmux会话内，按 `Ctrl+C` 可以终止当前正在前台运行的程序（如我们的beacon脚本）。

7.  **结束一个tmux会话**：
    在tmux会话内，直接输入 `exit` 或按 `Ctrl+D`，会结束该会话及其中的所有进程。

![](img/5993a9a352f015b58d6149d8acf24f23_53.png)

![](img/5993a9a352f015b58d6149d8acf24f23_55.png)

![](img/5993a9a352f015b58d6149d8acf24f23_57.png)

### Tmux窗格管理

![](img/5993a9a352f015b58d6149d8acf24f23_59.png)

![](img/5993a9a352f015b58d6149d8acf24f23_61.png)

除了会话，tmux还可以在同一个窗口内分割出多个**窗格**，方便同时查看代码和运行结果。

![](img/5993a9a352f015b58d6149d8acf24f23_63.png)

*   **垂直分割**：在tmux命令模式下（`Ctrl+B`），输入 `:split-window -v`。
*   **水平分割**：在tmux命令模式下，输入 `:split-window -h`。
*   **在窗格间导航**：在tmux命令模式下（`Ctrl+B`），使用方向键（上、下、左、右）在窗格间切换。
*   **关闭当前窗格**：在tmux命令模式下（`Ctrl+B`），按 `x`，然后确认。

![](img/5993a9a352f015b58d6149d8acf24f23_65.png)

![](img/5993a9a352f015b58d6149d8acf24f23_67.png)

## 监控进程与资源使用

![](img/5993a9a352f015b58d6149d8acf24f23_71.png)

为了在高性能计算集群上高效运行任务，我们需要了解程序使用了多少资源（CPU、内存、时间、磁盘空间）。这有助于我们在提交作业时，提出准确合理的资源请求。

### 查看进程：`ps` 命令

![](img/5993a9a352f015b58d6149d8acf24f23_73.png)

![](img/5993a9a352f015b58d6149d8acf24f23_75.png)

`ps` 命令用于显示当前进程的快照。

![](img/5993a9a352f015b58d6149d8acf24f23_77.png)

![](img/5993a9a352f015b58d6149d8acf24f23_79.png)

*   **查看当前终端内的进程**：
    ```bash
    ps
    ```
    输出列包括：
    *   `PID`：进程ID，操作系统分配的唯一标识符。
    *   `TTY`：进程关联的终端。
    *   `TIME`：进程使用的CPU时间。
    *   `CMD`：启动进程的命令。

*   **查看用户的所有进程**：
    ```bash
    ps -u username
    ```

![](img/5993a9a352f015b58d6149d8acf24f23_81.png)

*   **查看更详细的进程树关系**：
    ```bash
    ps -fj -u username
    ```
    这会显示父进程ID（PPID），有助于理解进程间的层级关系。

![](img/5993a9a352f015b58d6149d8acf24f23_83.png)

![](img/5993a9a352f015b58d6149d8acf24f23_85.png)

![](img/5993a9a352f015b58d6149d8acf24f23_86.png)

### 终止进程：`kill` 命令

如果一个进程无响应，可以使用其PID来终止它。
```bash
kill PID号
```
例如，根据 `ps` 命令找到beacon.sh的PID，然后执行 `kill 12345`。

![](img/5993a9a352f015b58d6149d8acf24f23_88.png)

![](img/5993a9a352f015b58d6149d8acf24f23_90.png)

### 动态监控资源：`top` 命令

`top` 命令提供一个动态更新的视图，显示系统中进程的资源使用情况。

![](img/5993a9a352f015b58d6149d8acf24f23_92.png)

*   **启动top**：
    ```bash
    top
    ```

*   **仅查看当前用户的进程**：
    ```bash
    top -u username
    ```

![](img/5993a9a352f015b58d6149d8acf24f23_94.png)

*   **在top中切换内存显示单位**：
    *   按 `E`（大写）循环切换顶部汇总信息的内存单位（KB, MB, GB...）。
    *   按 `e`（小写）循环切换进程列表中的内存单位。

![](img/5993a9a352f015b58d6149d8acf24f23_96.png)

![](img/5993a9a352f015b58d6149d8acf24f23_98.png)

*   **退出top**：
    按 `q`。

### 监控GPU资源

如果程序使用GPU，可以使用 `nvidia-smi` 命令来监控GPU使用情况和内存。
```bash
nvidia-smi
```
注意：此命令需要在有GPU的节点上运行，登录节点通常没有GPU。

### 检查磁盘使用情况

*   **查看目录磁盘使用**：`du`（disk usage）
    ```bash
    du -h --max-depth=1
    ```
    *   `-h`：人类可读的格式（如K，M，G）。
    *   `--max-depth=1`：只显示指定目录下一级子目录的大小。

![](img/5993a9a352f015b58d6149d8acf24f23_100.png)

*   **查看磁盘可用空间**：`df`（disk free）
    ```bash
    df -h .
    ```
    *   `-h`：人类可读的格式。
    *   `.`：查看当前目录所在文件系统的使用情况。

![](img/5993a9a352f015b58d6149d8acf24f23_102.png)

![](img/5993a9a352f015b58d6149d8acf24f23_104.png)

## 估算代码资源需求与时间复杂度

![](img/5993a9a352f015b58d6149d8acf24f23_113.png)

为了合理申请HPC资源，我们需要估算代码的运行时间和内存消耗。一个有效的方法是进行**基准测试**。

### 使用 `time` 命令测量运行时间

`time` 命令可以测量一个命令或脚本执行所需的时间。
```bash
time ./nested.sh 100
```
输出示例：
```
real    0m0.101s
user    0m0.060s
sys     0m0.032s
```
*   `real`：实际流逝的“墙钟”时间。
*   `user`：进程在用户态消耗的CPU时间。
*   `sys`：进程在内核态消耗的CPU时间。

![](img/5993a9a352f015b58d6149d8acf24f23_115.png)

![](img/5993a9a352f015b58d6149d8acf24f23_117.png)

![](img/5993a9a352f015b58d6149d8acf24f23_119.png)

![](img/5993a9a352f015b58d6149d8acf24f23_120.png)

### 理解时间复杂度（Big O Notation）

![](img/5993a9a352f015b58d6149d8acf24f23_122.png)

代码的性能通常与输入数据的大小（n）相关，这种关系用**大O符号**描述：
*   **O(1)**：常数时间，运行时间不随n增长。
*   **O(n)**：线性时间，运行时间与n成正比。
*   **O(n²)**：平方时间，运行时间与n的平方成正比（例如，双重嵌套循环）。

### 实践：通过基准测试推断

我们可以运行不同规模的小型测试，来推断处理大规模数据所需的资源。

![](img/5993a9a352f015b58d6149d8acf24f23_124.png)

![](img/5993a9a352f015b58d6149d8acf24f23_126.png)

![](img/5993a9a352f015b58d6149d8acf24f23_128.png)

![](img/5993a9a352f015b58d6149d8acf24f23_130.png)

![](img/5993a9a352f015b58d6149d8acf24f23_132.png)

1.  **创建测试脚本** `nested.sh`（一个双重循环）：
    ```bash
    #!/usr/bin/env bash
    for ((i=1; i<=$1; i++))
    do
        for ((j=1; j<=$1; j++))
        do
            : # 空操作，仅消耗循环开销
        done
    done
    ```

![](img/5993a9a352f015b58d6149d8acf24f23_134.png)

2.  **运行并计时**：
    ```bash
    time ./nested.sh 100
    time ./nested.sh 200
    ```

3.  **分析结果**：
    *   如果输入从100变为200（翻倍），而运行时间变为原来的4倍，那么代码很可能是 **O(n²)** 复杂度。
    *   利用这个比例关系，你就可以估算出处理更大规模数据（如n=10000）所需的时间，从而为HPC作业申请合适的运行时间。

**将输出重定向到文件**：
如果程序输出大量内容到屏幕，可以将其重定向到文件，避免干扰且便于保存。
```bash
time ./nested.sh 1000 > output.txt 2>&1
```
*   `>`：将标准输出重定向到文件。
*   `2>&1`：将标准错误也重定向到标准输出（即同一个文件）。
