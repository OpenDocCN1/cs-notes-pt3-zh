## CPU调度补充

上一节我们介绍了Minix的16级MLFQ调度器。本节中，我们来看看其实现的一些额外细节。

Minix的CPU调度策略并非完全在内核中实现。实际上，大部分调度逻辑被移到了用户空间的一个独立进程中，即调度服务器。

以下是调度系统的工作方式：
*   内核负责处理时钟中断、进程队列的基础操作等底层任务。
*   用户级的调度服务器进程通过特定的内核调用（如 `schedule` 和 `sched_ctl`）与内核交互，并接收来自内核的通知消息。
*   主要的调度决策（如选择下一个运行的进程）由这个用户级进程根据MLFQ策略做出。

这种设计的优势在于灵活性和可扩展性。由于调度策略在用户空间实现，理论上可以运行多个不同的调度器，并为不同的进程组应用不同的策略，而无需重新编译内核。

## 进程间通信与中断处理

在深入进程创建之前，我们需要了解Minix中进程间通信的基本框架，这对理解系统调用和中断处理至关重要。

### 消息传递

Minix的核心通信机制是同步消息传递。系统预定义了七种基本的消息类型，涵盖了常见的数据组合（如整数、指针、字符数组等）。发送和接收消息是阻塞操作，这实现了“会合”机制。

消息传递的API主要包括：
*   `send`：发送消息并阻塞，直到接收方接收。
*   `receive`：接收消息并阻塞，直到有消息到达。
*   `sendrec`：组合发送与接收，常用于请求-响应模式。
*   `notify`：发送非阻塞的通知消息。

### 中断处理

中断是硬件通知CPU有事件需要处理的方式。例如，每次按键都会触发一个键盘中断。

中断处理的基本流程如下：
1.  硬件设备通过特定引脚发送电信号（中断）。
2.  CPU收到中断后，保存当前正在执行进程的状态（寄存器等）。
3.  CPU根据中断号，查询**中断向量表**，跳转到对应的中断处理程序地址开始执行。
4.  中断处理程序执行完毕后，恢复之前保存的进程状态，继续执行。

在Minix这样的微内核系统中，中断处理更为复杂。因为设备驱动程序运行在用户空间，当中断发生时，内核首先接收到中断，然后必须通过消息通知相应的用户空间驱动程序来处理。这增加了一些开销，但保持了内核的简洁性。

系统调用在软件层面使用了与中断类似的机制。通过执行一条特殊指令（如 `int 0x80`）触发一个软件中断，CPU便会切换到内核模式，并跳转到系统调用处理程序。

## 进程与线程

现在，让我们回到进程管理的核心概念。

### 进程定义

一个**进程**就是一个正在执行的程序。它是系统进行资源分配和调度的基本单位。每个进程都包含：
*   **地址空间**：存放代码、数据和堆栈的内存区域。
*   **进程状态**：运行、就绪、阻塞等。
*   **执行上下文**：程序计数器、寄存器、栈指针等。
*   **其他资源**：打开的文件、信号处理等。

操作系统通过**进程控制块**（PCB）数据结构来跟踪和管理所有这些信息。在Minix中，PCB的信息被拆分并存储在内核、进程管理器和内存管理器中。

### 线程定义

**线程**是进程内的执行单元，也称为“轻量级进程”。一个进程可以包含多个线程，它们共享进程的地址空间（代码段、堆）和系统资源，但每个线程拥有自己独立的栈和寄存器上下文。

线程提供了以下优势：
*   **并发性**：在单核CPU上，多个线程可以交替执行，形成并发。
*   **并行性**：在多核CPU上，多个线程可以真正同时执行。
*   **资源共享**：线程间共享内存，通信和数据共享比进程间更容易。

### 用户级线程与内核级线程

线程的实现方式主要有两种：
*   **内核级线程**：操作系统内核直接感知和管理线程。线程调度由内核完成，能够利用多核实现真正的并行。
*   **用户级线程**：线程的管理完全由用户空间的线程库（如Pthreads）实现，内核对此一无所知。内核仍然以进程为单位进行调度。用户级线程的优点是切换速度快，但缺点是无法获得真正的多核并行，且一个线程的阻塞会导致整个进程阻塞。

Minix本身只支持进程，不提供内核级线程。因此，在Minix上实现多线程编程必须使用用户级线程库。

## 进程创建：Fork 与 Exec

进程创建是操作系统的基础功能。在Unix-like系统中，这通常通过两个系统调用组合完成：`fork` 和 `exec`。

### Fork 系统调用

`fork()` 的作用是创建一个新的进程，这个新进程是调用进程（父进程）的一个**完全相同的副本**。子进程获得父进程地址空间、文件描述符等资源的拷贝。

`fork()` 的一个关键特性是它只被调用一次，但会返回两次：一次在父进程中，一次在子进程中。
*   在**父进程**中，`fork()` 返回新创建子进程的**进程ID（PID）**。
*   在**子进程**中，`fork()` 返回 **0**。

通过判断返回值，父进程和子进程可以执行不同的代码路径。

```c
pid_t pid = fork(); // 调用fork，创建子进程
if (pid == 0) {
    // 这段代码只在子进程中执行
    printf("I am the child process.\n");
} else if (pid > 0) {
    // 这段代码只在父进程中执行
    printf("I am the parent process. My child's PID is %d.\n", pid);
} else {
    // fork失败
    perror("fork failed");
}
```

### Exec 系统调用

`fork()` 只创建了副本，但通常我们想要运行一个全新的程序。这时就需要 `exec()` 系列系统调用。

`exec()` 会用指定的新程序**替换**当前进程的地址空间。代码段、数据段、堆栈都被新程序的内容覆盖。进程ID保持不变，但进程执行的是全新的代码。

`fork()` 和 `exec()` 的经典组合如下：
1.  父进程（如Shell）调用 `fork()` 创建子进程。
2.  子进程调用 `exec()` 来加载并执行一个新程序（如 `ls`, `gcc`）。
3.  父进程通常调用 `wait()` 等待子进程结束。

```c
pid_t pid = fork();
if (pid == 0) {
    // 子进程：变成 /bin/ls
    execl("/bin/ls", "ls", "-l", NULL);
    // 如果execl成功，这行代码永远不会执行
    perror("execl failed");
    exit(1);
} else if (pid > 0) {
    // 父进程：等待子进程结束
    wait(NULL);
    printf("Child process finished.\n");
}
```

### 创建过程简述

在操作系统内部，`fork()` 大致需要完成以下步骤：
1.  检查进程表是否有空位。
2.  为子进程分配新的PCB。
3.  为子进程分配内存空间。
4.  将父进程地址空间的内容复制到子进程空间。
5.  复制父进程的其他资源（文件描述符等）。
6.  为子进程分配唯一的PID，并将其状态设为就绪。

`exec()` 则需要：
1.  验证要执行的程序文件是否存在且有执行权限。
2.  释放进程当前占用的部分内存。
3.  将新程序的代码和数据加载到进程地址空间。
4.  设置新的堆栈并初始化（如传递参数`argc`, `argv`）。
5.  将程序计数器设置为新程序的入口点，开始执行。
