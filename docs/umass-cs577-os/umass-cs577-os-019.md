## 物理地址与虚拟地址

在深入具体技术之前，我们需要理解两个核心概念：物理地址和虚拟地址。

*   **物理地址**：这是内存（RAM）中实际存储单元的地址。例如，一块从0到2400的RAM，其地址0、1、2……对应着内存中的第一个字、第二个字等。
*   **虚拟地址**：这是由进程生成的地址。它是一个相对于进程起始位置的地址。例如，进程说“地址5”，指的是从该进程起始位置算起的第5个字。

**关键点**：进程生成的始终是虚拟地址。硬件（或操作系统）需要在运行时将其转换为物理地址。这是因为在编写程序时，我们无法预知操作系统会将进程加载到内存的哪个位置。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_10.png)

**公式**：
`物理地址 = 进程起始地址（基址） + 虚拟地址`

![](img/b4ebac09ec5e1c5bda029285cb29d06f_12.png)

## 重定位

![](img/b4ebac09ec5e1c5bda029285cb29d06f_14.png)

上一节我们介绍了地址的概念，本节我们来看看如何将进程的虚拟地址转换为物理地址，这个过程称为重定位。

重定位有两种主要方法：静态重定位和动态重定位。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_16.png)

### 静态重定位

![](img/b4ebac09ec5e1c5bda029285cb29d06f_18.png)

在静态重定位中，转换工作在**加载时**完成。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_20.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_21.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_23.png)

*   **过程**：加载器（loader）将可执行文件读入内存时，会扫描其指令，将所有虚拟地址加上进程被加载的起始地址（基址），从而直接修改二进制代码，将虚拟地址替换为物理地址。
*   **缺点**：一旦进程被加载，其地址就固定了。如果之后需要移动进程（例如为其他进程腾出空间），所有地址都会变得无效，需要重新计算和修改，这非常低效。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_25.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_27.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_28.png)

### 动态重定位

![](img/b4ebac09ec5e1c5bda029285cb29d06f_30.png)

在动态重定位中，转换工作在**运行时**由硬件完成。

*   **过程**：CPU中使用两个专用寄存器：
    1.  **基址寄存器**：存放进程在内存中的起始地址。
    2.  **界限寄存器**：存放进程的结束地址（或长度）。
*   **地址转换**：当进程生成一个虚拟地址时，硬件自动将其与基址寄存器的值相加，得到物理地址。
*   **安全检查**：硬件同时会检查生成的物理地址是否超出了界限寄存器规定的范围。如果超出，则触发一个错误（陷阱），防止进程访问其他进程的内存。
*   **优点**：
    *   **透明性**：进程无需感知地址转换。
    *   **安全性**：界限检查确保了内存访问安全。
    *   **高效性**：由专用硬件完成，速度很快。
    *   **灵活性**：通过简单地更新基址和界限寄存器的值，可以轻松地在内存中移动进程。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_32.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_33.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_34.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_36.png)

**代码/硬件描述**：
```
物理地址 = 基址寄存器 + 虚拟地址
if (物理地址 > 界限寄存器) then 触发陷阱(寻址错误)
```

![](img/b4ebac09ec5e1c5bda029285cb29d06f_38.png)

## 连续内存分配

![](img/b4ebac09ec5e1c5bda029285cb29d06f_40.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_41.png)

理解了地址转换后，我们来看看操作系统如何为进程分配内存。最简单的方法是连续内存分配。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_43.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_45.png)

连续内存分配是指为每个进程分配一块连续的物理内存区域。

*   **管理空闲内存**：操作系统需要维护一个**空闲分区列表**（或“空洞”列表），记录内存中哪些区域是未分配的。
*   **分配策略**：当新进程到达时，操作系统需要从空闲列表中找到一个足够大的分区来容纳它。常见的策略有：
    *   **首次适应**：从列表开头扫描，找到第一个足够大的分区。
    *   **最佳适应**：扫描整个列表，找到能满足需求的最小分区。
    *   **最差适应**：扫描整个列表，找到能满足需求的最大分区。

### 碎片化问题

![](img/b4ebac09ec5e1c5bda029285cb29d06f_47.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_49.png)

连续内存分配的主要问题是**碎片化**。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_51.png)

*   **外部碎片**：随着进程的创建和终止，空闲内存会被分割成许多小块。虽然所有小块的总和可能很大，但没有一个单独的小块足以满足新进程的需求。这导致了内存的浪费。
*   **内部碎片**：分配给进程的内存块可能比进程实际需要的大一点。这多出来的、进程未使用的部分就是内部碎片。虽然浪费，但有时为了管理方便（避免产生极小的、无法利用的外部碎片）而接受。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_53.png)

**解决方案**：**压缩**。通过移动内存中的进程，将所有空闲空间合并成一个大的连续区域。但这涉及到大量的内存拷贝，开销较大。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_55.png)

## 分页

![](img/b4ebac09ec5e1c5bda029285cb29d06f_63.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_65.png)

为了解决连续分配带来的碎片问题，我们引入了分页技术。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_67.png)

分页的核心思想是：将物理内存和进程的地址空间都划分为固定大小的块。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_69.png)

*   **帧**：物理内存被划分为固定大小的块，称为“帧”。
*   **页**：进程的地址空间被划分为同样大小的块，称为“页”。
*   **关键优势**：一个进程的页可以被分配到任何可用的帧中，**无需连续**。这彻底消除了外部碎片。

### 地址转换

由于进程的页在内存中不连续，我们需要一种新的地址转换机制。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_71.png)

*   **页表**：操作系统为每个进程维护一个数据结构，称为页表。它记录了该进程的每一页被存放在哪个物理帧中。
*   **转换过程**：
    1.  虚拟地址被分为两部分：**页号** 和 **页内偏移**。
    2.  使用页号作为索引查找页表，得到对应的**帧号**。
    3.  将**帧号**与**页内偏移**组合，得到物理地址。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_73.png)

**公式**（假设页大小为2的幂次方，如4KB）：
```
页号 = 虚拟地址 / 页大小
偏移量 = 虚拟地址 % 页大小
物理地址 = (帧号 * 页大小) + 偏移量
```
在硬件中，这通常通过位操作实现（例如，取虚拟地址的高位作为页号，低位作为偏移量）。

### 性能问题与TLB

![](img/b4ebac09ec5e1c5bda029285cb29d06f_75.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_77.png)

分页引入了一个性能问题：每次内存访问现在需要两次内存读取（一次读页表，一次读实际数据），速度减半。

**解决方案**：**转换后备缓冲器**。

*   **TLB** 是页表的一个小型、高速硬件缓存。
*   当需要地址转换时，首先在TLB中查找。如果找到（TLB命中），则直接获得帧号，速度极快。
*   如果未找到（TLB缺失），才需要访问内存中的页表，并将该表项存入TLB。
*   由于程序访问具有**局部性**（倾向于重复访问相同的页），TLB命中率通常很高，从而极大地缓解了性能开销。

**有效内存访问时间公式**：
```
设：
内存访问时间 = m
TLB命中率 = p
TLB查找时间 = ε (通常远小于m)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_79.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_81.png)

有效访问时间 ≈ p * (ε + m) + (1 - p) * (ε + 2m)
当p很高时，有效时间接近 (ε + m)，远优于 2m。
```

![](img/b4ebac09ec5e1c5bda029285cb29d06f_83.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_85.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_86.png)

## 分段

分页是从操作系统管理角度出发的技术。而分段则更贴近进程自身的逻辑视图。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_92.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_94.png)

一个进程在逻辑上通常由几个部分组成：
*   **代码段**：存放程序指令。
*   **数据段**：存放全局变量。
*   **堆段**：动态分配的内存，向上增长。
*   **栈段**：存放局部变量和函数调用信息，向下增长。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_96.png)

分段就是按照进程的这种逻辑视图来分配内存：为每个逻辑段分配一块连续的内存区域。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_98.png)

### 地址转换

![](img/b4ebac09ec5e1c5bda029285cb29d06f_100.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_102.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_104.png)

*   **段表**：每个进程有一个段表，每个表项包含该段的**基址**和**界限**。
*   **虚拟地址**：形式为`<段号， 段内偏移>`。
*   **转换过程**：
    1.  用段号索引段表，获得该段的基址和界限。
    2.  检查偏移量是否超出界限，若超出则触发**段错误**。
    3.  物理地址 = 基址 + 偏移量。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_106.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_108.png)

**优点**：符合程序员的直观感受，易于实现共享和保护（例如，将代码段设为只读）。
**缺点**：回到了连续分配的老路，会产生**外部碎片**。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_110.png)

## 段页式存储

![](img/b4ebac09ec5e1c5bda029285cb29d06f_112.png)

我们既喜欢分段符合逻辑视图的优点，又喜欢分页无外部碎片的优点。能否结合两者？答案是：段页式存储。

在段页式系统中：
1.  进程的地址空间先按逻辑分段。
2.  每个段再进一步被分页。
3.  内存分配以页为单位进行。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_114.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_116.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_117.png)

### 地址转换

这引入了两级查找，更为复杂：
1.  根据虚拟地址中的**段号**查找段表，段表项指向该段的**页表**。
2.  根据虚拟地址中的**页号**，在该段的页表中查找，得到**帧号**。
3.  将**帧号**与**页内偏移**组合，得到物理地址。

**性能考虑**：这可能导致三次内存访问（段表、页表、数据）。为了加速：
*   段表可以很小，通常放在快速的CPU寄存器中。
*   页表访问仍然依靠TLB来加速。

**共享内存**：段页式非常利于共享。例如，多个进程可以共享同一个库（如libc），只需让它们的段表中对应库的条目指向**同一个页表**即可。

## 请求分页（虚拟内存）

![](img/b4ebac09ec5e1c5bda029285cb29d06f_127.png)

到目前为止，我们都假设整个进程必须都在内存中才能运行。请求分页打破了这一限制，它是实现虚拟内存的核心。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_129.png)

**核心思想**：并非将进程的所有页都装入内存，而是只将当前需要的页（称为**工作集**）留在内存中，其余页保存在磁盘的**交换空间**中。

*   **页错误**：当进程访问一个不在内存中的页时，硬件会触发一个**页错误**异常。
*   **处理过程**：操作系统捕获这个异常，然后：
    1.  从磁盘交换空间找到所需的页。
    2.  在物理内存中找到一个空闲帧（如果没有，则需要**置换**出一个现有页）。
    3.  将磁盘上的页读入该帧。
    4.  更新页表。
    5.  重新执行引发页错误的指令。
*   **性能基石**：这一切都建立在**局部性原理**之上。程序在一段时间内倾向于集中访问一小部分页面（工作集）。只要工作集在内存中，页错误就会很少发生，性能接近全部在内存的情况。如果页错误频繁，程序性能将因磁盘I/O而急剧下降。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_131.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_133.png)

### 页面置换算法

![](img/b4ebac09ec5e1c5bda029285cb29d06f_136.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_138.png)

当需要从磁盘调入新页而内存已满时，必须选择一个旧页置换出去。这就是页面置换算法。

以下是几种经典算法：
*   **最优置换**：置换未来最长时间不会被访问的页。这是理论最优，但无法实现（无法预知未来）。
*   **先进先出**：置换在内存中停留时间最长的页。实现简单，但性能可能不好。
*   **最近最少使用**：置换最长时间没有被访问的页。这近似于最优置换，性能很好，但实现开销较大。

## 总结

![](img/b4ebac09ec5e1c5bda029285cb29d06f_143.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_144.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_146.png)

![](img/b4ebac09ec5e1c5bda029285cb29d06f_148.png)

本节课我们一起回顾了内存管理的关键技术脉络：
1.  从最简单的**连续分配**开始，理解了**物理/虚拟地址**和**重定位**的概念，但也认识了其**碎片化**的致命弱点。
2.  引入**分页**来解决外部碎片，通过**页表**和**TLB**实现高效的地址转换。
3.  引入**分段**以匹配进程的逻辑视图，但带来了新的碎片问题。
4.  结合两者优点的**段页式存储**，成为现代复杂操作系统的基础。
5.  最后，通过**请求分页**实现了**虚拟内存**，使得程序大小可以超过物理内存，其性能依赖于**局部性原理**和有效的**页面置换算法**。

![](img/b4ebac09ec5e1c5bda029285cb29d06f_150.png)

Minix主要使用了简单的连续分配和基础分页。而像Linux这样的通用操作系统，则实现了复杂的段页式虚拟内存管理。理解这些基础概念，是学习具体系统实现的必经之路。
