# 028：Linux内核 - 第二部分 (03/12/20) 🐧

在本节课中，我们将深入学习Linux内核，特别是中断处理机制。我们将探讨系统调用、中断与异常的区别、中断处理程序的结构（上半部和下半部），以及Linux中实现下半部处理的各种方法。课程内容旨在让初学者能够理解这些核心概念。

---

上一节我们介绍了Linux内核的概述和基本数据结构。本节中，我们来看看Linux中用户与内核交互的唯一方式：系统调用。

系统调用是用户空间程序请求内核服务的接口。Linux努力保持系统调用的数量尽可能少。

每个Linux系统调用都需要返回一个类型为`long`的值。每个系统调用都有一个编号，这与Minix类似。这些编号通常是架构相关的。

系统调用表`sys_call_table`包含了所有系统调用的入口。Linux与Minix的一个主要区别在于，Linux没有为每个服务单独实现系统调用表。

系统调用的调用栈非常相似。从用户空间（例如C或Python程序）开始，程序调用C库函数（如`printf`）。C库函数内部会映射到一个具体的系统调用（如`write`）。

系统调用在Linux中的工作方式是，它们会导致一个异常（或陷阱）。控制权随后切换到内核空间。

所有系统调用共享同一个异常（中断）号，在x86架构上是128。系统调用号通过`EAX`寄存器从用户空间传递给内核。

以下是定义系统调用的方式：
```c
SYSCALL_DEFINE0(getpid)
```
这里的`0`表示该系统调用有零个参数。例如，`getpid`系统调用返回当前进程的PID，不需要任何参数。

每个系统调用都有一个定义好的处理程序，负责实际工作。

---

现在，我们进入本讲的核心内容：中断。

为什么需要中断？处理器运行速度极快，而硬件设备相对较慢。中断使处理器能够高效地与这些慢速设备通信。

有两种方式实现设备通信：中断和轮询。大多数硬件使用中断。当硬件就绪时，它会向处理器发送一个电子信号。轮询则要求处理器定期询问设备状态。

中断的好处是，它允许硬件异步地通知处理器，无需同步不同硬件芯片的时钟。

中断控制器是一个简单的芯片，它有一个向量表，将特定的引脚信号映射到特定的中断号。

每个中断都有一个唯一的编号，称为IRQ号。例如：
*   IRQ 0：定时器中断
*   IRQ 1：键盘中断

并非所有IRQ号都是预先静态定义的。许多IRQ号是动态分配给设备的（例如PCI总线上的设备），这允许系统支持几乎无限的新硬件。

中断与异常的区别在于：中断源于硬件，异常源于软件（如系统调用）。

每个设备产生的中断都与一个中断处理程序相关联。这就是设备驱动程序的主要部分。驱动程序可以以内核模块形式实现。

中断处理程序运行在一个特殊的“中断上下文”中。它必须是原子的且不能阻塞，因此必须执行得非常快。

---

由于中断处理程序必须快速执行，现代驱动程序将其工作分为两部分：上半部和下半部。

上半部是实际的中断处理程序，由内核直接调用。它应该只执行时间紧迫的工作：
*   确认收到中断。
*   重置硬件以便接收新中断。
*   执行必须立即完成的关键任务（例如，将数据从网络卡缓冲区复制到主内存，以防缓冲区溢出）。

下半部处理所有剩余的非紧迫工作。上半部在退出前会调度下半部执行。

判断工作属于哪一部分的准则：
*   如果工作对时间敏感或与硬件直接相关，放在上半部。
*   如果工作需要确保不被其他中断打断，可以放在上半部。
*   其他所有工作都应放在下半部。

以网络为例，接收数据包并复制到内存是上半部的工作；处理TCP/IP协议栈则是下半部的工作。

---

在Linux中，有多种方法可以实现下半部处理。其演进历程如下：

1.  **BH（Bottom Half）**：最古老的方法，在2.3内核前使用。只有32个预定义的BH，成为瓶颈。
2.  **任务队列（Task Queue）**：2.3内核引入，使用一系列队列，但性能仍不足。
3.  **软中断（Softirq）和 Tasklet**：2.5内核引入，是目前主要机制。
4.  **工作队列（Work Queue）**：另一种更易用的机制，将工作推送到内核线程执行。
5.  **线程化中断（Threaded IRQ）**：一种较新的方法，将整个中断处理程序作为一个内核线程运行。

以下是当前常用方法的比较（性能 vs 易用性）：
*   **软中断**：性能最高，用于高频关键任务（如网络子系统）。但实现复杂，需要处理并发。
*   **Tasklet**：基于软中断构建，性能中等，更易用。同一个Tasklet不会在多个CPU上并发运行。
*   **工作队列**：易用性最高，将工作交给内核线程执行，可以睡眠。性能相对较低。

Linux内核预定义了8种类型的软中断，例如用于定时器、网络发送/接收、块设备等。

Tasklet结构体定义如下：
```c
struct tasklet_struct {
    struct tasklet_struct *next; // 指向下一个Tasklet
    unsigned long state;         // 状态（如是否被调度）
    atomic_t count;              // 引用计数
    void (*func)(unsigned long); // 处理函数指针
    unsigned long data;          // 传递给处理函数的数据
};
```

工作队列为每个CPU创建一个“工作者线程”。待处理的工作被链接成列表，由这些线程按顺序执行。
