## 概述
在本节课中，我们将学习Minix操作系统的文件系统架构。我们将重点探讨虚拟文件系统（VFS）的概念及其在Minix中的实现方式，以及Minix文件系统（MFS）如何作为一个独立的服务器进程工作。通过理解这些核心组件，你将掌握现代操作系统如何支持多种文件系统并管理文件I/O请求。

---

## 虚拟文件系统（VFS）概念

上一节我们介绍了文件系统的一般概念。本节中，我们来看看一个在许多类Unix操作系统中使用的关键抽象层：虚拟文件系统（VFS）。

VFS是操作系统内核中的一个软件层。它允许系统中同时存在多种不同的文件系统，并为上层提供一个统一的文件访问抽象接口。

以下是VFS层的主要功能：
*   **统一接口**：VFS为所有文件系统相关的系统调用（如`open`、`read`、`write`、`close`）提供一个统一的入口点。
*   **请求路由**：当用户进程发起一个文件系统调用时，VFS层首先接收该请求。然后，VFS会判断该请求针对哪个具体的文件系统（例如，EXT4、FAT32），并将请求转发给对应的文件系统实现模块。
*   **系统扩展**：这种机制使得向操作系统内核添加新的文件系统变得非常容易。开发者只需编写符合VFS接口规范的文件系统模块即可。

在Linux等单体内核中，VFS层和各个文件系统驱动都位于内核空间。然而，Minix采用了不同的设计。

---

## Minix中的VFS：一个独立的服务器进程

与Linux不同，Minix采用微内核架构。这意味着许多传统上属于内核的功能被移到了用户空间的独立服务器进程中。VFS功能在Minix中就是由一个名为**VFS进程**的系统进程实现的。

VFS进程位于实际的用户进程和实现具体文件系统功能（如Minix文件系统）的**文件服务器进程**之间。它扮演着“交换机”或“路由器”的角色。每个文件系统（甚至是每个已挂载的分区）在Minix中都可以是一个独立的用户进程，它们通过消息传递与VFS进程进行交互。

---

## VFS进程的功能与数据流

![](img/790b5f19d8d66c4299fb6f757748717e_3.png)

VFS进程主要负责两到三类核心功能。

第一类是实现一个与POSIX兼容的系统调用接口。这包括了几乎所有文件管理相关的系统调用。

以下是VFS进程处理的部分系统调用类别：
*   **文件操作**：例如 `open()`、`close()`、`read()`、`write()`。
*   **目录操作**：例如 `mkdir()`、`rmdir()`、`getdents()`。
*   **文件属性操作**：例如 `chmod()`、`chown()`、`stat()`。
*   **文件系统挂载操作**：例如 `mount()`、`umount()`。

第二类关键功能是跟踪设备驱动程序的端点。因为所有的I/O请求最终都流经VFS进程，它需要知道系统中存在哪些字符设备驱动和块设备驱动，以便将请求正确地转发给它们。

让我们通过一个典型的I/O请求流程来理解VFS进程如何工作。

假设一个用户进程执行了一个`read()`系统调用。该请求首先被发送到VFS进程。VFS进程验证该读取操作是针对一个有效的文件，然后根据文件所在的挂载分区，将请求转发给负责该分区的特定文件服务器进程（例如，MFS进程）。文件服务器进程处理该请求，可能需要通过块设备驱动从硬盘读取数据。数据读取后，被复制回用户进程，同时一个回复消息会发送给VFS进程，告知其请求已完成。

## VFS进程的实现细节：线程与并发

VFS进程的一个独特之处在于它实现了**线程**，以处理并发的I/O请求。由于Minix本身不支持内核级线程，VFS的线程功能是通过一个名为 `pthread` 的用户级线程库实现的。

VFS采用标准的**主-从线程池架构**：
1.  一个主线程负责等待接收新的请求消息。
2.  一个静态大小的**工作线程池**负责处理具体的请求。
3.  当主线程收到请求时，它会从线程池中寻找一个空闲的工作线程，并将请求交给它处理。
4.  工作线程处理完请求后，返回线程池等待下一个任务。

需要注意的是，如果同时到达的请求数量超过了工作线程的数量，多余的请求将被排队等待。这是一种简单的静态线程池模型。

为了确保当一个线程阻塞等待文件服务器回复时，不会导致整个进程（及其所有线程）阻塞，VFS线程使用**异步I/O**方式进行通信。这样，一个线程的等待不会妨碍其他线程的执行。

VFS进程内部维护了多个关键的数据结构来管理系统状态。

以下是VFS进程中的一些核心数据结构：
*   **`fproc`**：进程文件表。为每个进程跟踪其打开的文件。
*   **`vmnt`**：挂载表。跟踪系统中所有当前已挂载的文件系统。
*   **`vnode`**：虚拟节点表。在内存中跟踪所有活跃的inode（索引节点）。
*   **`filp`**：文件位置表。为每个打开的文件跟踪其当前的读写偏移量。

由于VFS是多线程的，访问这些共享数据结构需要同步机制来避免竞态条件。

## VFS中的锁机制

VFS使用锁来保证多线程访问下数据的一致性和正确性。其设计原则借鉴了数据库ACID属性的思想，但提供的是更弱形式的保证。

VFS主要实现了三种类型的锁，类似于**读写锁**的概念：
1.  **`TL_READ`（读锁）**：允许多个线程同时以只读方式访问资源。
2.  **`TL_WRITE`（写锁）**：只允许一个线程以写入方式访问资源，此时阻塞所有其他读/写线程。
3.  **`TL_READSER`（串行读锁）**：一种特殊的读锁，用于需要将读操作序列化（升级为写锁前）的场景。

为了避免死锁，VFS强制规定了一个**锁的获取顺序**。线程必须按照固定的层次顺序（例如，先`fproc`，再`vmnt`，然后`vnode`，最后`filp`）来获取锁。线程不能在持有低顺序锁的情况下，去尝试获取高顺序的锁。遵循这个顺序可以消除循环等待的可能性。

不同的数据结构根据其访问模式使用不同类型的锁：
*   **`vmnt`（挂载表）锁**：挂载/卸载操作使用写锁；普通读操作使用并发读锁。
*   **`vnode`（inode）锁**：打开文件进行读操作使用读锁；创建、删除inode等操作使用串行锁；写入文件使用写锁。
*   **`filp`（文件位置）锁**：通常使用简单的互斥锁（mutex），其锁定隐含在`vnode`锁的顺序中。

## 崩溃恢复

VFS进程在系统组件崩溃恢复中也扮演着重要角色。它需要跟踪其他服务器进程（如文件服务器、设备驱动）的健康状态。

如果**设备驱动崩溃**，与之接口的文件服务器进程会首先尝试重启它。如果失败，VFS进程会通过重启机制尝试恢复驱动。

如果**文件服务器进程本身崩溃**，VFS进程需要进行清理工作：标记并清理所有正在访问该文件系统文件的进程状态，终止所有挂起的请求，然后尝试重启文件服务器进程并进行完整性检查。

## Minix文件系统（MFS）实现

到目前为止，我们主要讨论了VFS。现在，让我们看看Minix文件系统（MFS）本身是如何实现的。

MFS是一个完全在**用户空间**运行的独立服务器进程。它被设计成一个“网络服务器”风格的过程，通过消息传递（来自VFS进程）接收请求。这种设计的优点是，你可以修改或替换文件系统，而无需改动操作系统内核的其他部分，只要保持与VFS的接口不变即可。

MFS在磁盘分区上的布局是经典的Unix文件系统结构。

以下是Minix文件系统在磁盘分区上的布局：
1.  **引导块**：分区的第一个块。对于可引导分区，它包含一小段引导代码。
2.  **超级块**：紧接在引导块之后。包含描述整个文件系统的元数据，如inode数量、数据块数量、文件系统大小等。
3.  **inode区**：存储所有inode的连续区域。每个inode代表一个文件或目录。
4.  **数据区**：文件实际数据存储的区域，被划分为“块”或“区”。

**超级块**是文件系统的“头信息”。它存储在磁盘固定位置，并在文件系统挂载时被读入内存。超级块中的关键信息包括指向inode位图和数据区位图的指针，这些位图用于跟踪哪些inode和磁盘块是空闲的。

**inode**是文件系统的核心数据结构。它存储了文件的元数据（如所有者、权限、大小、时间戳）以及指向文件数据块的指针。

Minix的inode使用**多级索引**方案来存储数据块指针：
*   **直接指针**：前7个指针（`zone[0]` - `zone[6]`）直接指向数据块。适用于小文件。
*   **一级间接指针**：第8个指针（`zone[7]`）指向一个块，该块本身存储了更多的数据块指针。用于中等大小的文件。
*   **二级间接指针**：第9个指针（`zone[8]`）指向一个块，该块指向的块再存储数据块指针。用于大文件。
*   **三级间接指针**：预留了第10个指针（`zone[9]`）以供未来支持超大文件。

需要注意的是，**文件名并不存储在inode中**。文件名存储在目录条目里。目录本质上是一个将文件名映射到inode编号的表格。当你在目录中查找一个文件时，先找到其inode编号，然后通过该编号定位到具体的inode，从而获取文件的所有信息和数据。

![](img/790b5f19d8d66c4299fb6f757748717e_5.png)

为了提升性能，MFS（像所有现代文件系统一样）在内存中维护了一个**块缓存**（Buffer Cache）。最近访问过的磁盘块会被缓存在内存中。读操作可以直接从缓存读取，写操作通常会先修改缓存中的块（标记为“脏”），然后通过后台进程在适当时候写回磁盘（写回策略）。

## 总结
本节课中，我们一起学习了Minix操作系统的文件系统架构。我们深入探讨了两个核心概念：**虚拟文件系统（VFS）进程**和**Minix文件系统（MFS）服务器进程**。

我们了解到，VFS作为一个独立的系统进程，提供了统一的文件操作抽象，并负责将请求路由到具体的文件服务器。它通过多线程和精密的锁机制来处理并发请求。同时，MFS作为一个用户空间进程，实现了经典的文件系统布局和数据结构，如超级块、inode和多级索引。

这种微内核设计使得文件系统模块化、易于替换和扩展，是Minix操作系统灵活性的一个重要体现。
