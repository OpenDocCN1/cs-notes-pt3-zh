## 多处理器调度

上一节我们介绍了线程并发模型，本节中我们来看看如何将进程或线程调度到一台机器的多个处理器上。

![](img/77655a999fb22e9d5a1edcb7927001f2_8.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_9.png)

首先，我们需要理解多处理器系统的硬件架构。一个典型的系统包含多个处理器（或核心），每个处理器通常有自己专用的高速缓存（如L1、L2缓存），而主内存则由所有处理器共享。处理器访问缓存的速度远快于访问主内存。

基于此架构，有两种主要的调度队列设计思路：

*   **集中式队列**：所有等待调度的线程都放在一个全局共享队列中。任何空闲的处理器都可以从这个队列中选取线程执行。
    *   **优点**：负载均衡好，能充分利用所有处理器。
    *   **缺点**：共享队列本身是一个需要锁保护的数据结构。随着处理器数量增加，对队列锁的争用会成为性能瓶颈，导致处理器空闲等待。
*   **分布式队列**：为每个处理器（或每组处理器）维护一个本地队列。处理器只从自己的本地队列中选取任务。
    *   **优点**：消除了对共享数据结构的争用，调度决策快速。
    *   **缺点**：可能导致负载不均衡，某些处理器队列过长而其他处理器空闲。需要额外的机制（如工作窃取）来重新平衡队列。

![](img/77655a999fb22e9d5a1edcb7927001f2_11.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_12.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_14.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_16.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_17.png)

分布式队列还有一个关键优势：**缓存亲和性**。如果一个线程反复在同一个处理器上执行，其数据和代码很可能还保留在该处理器的缓存中，从而获得更快的执行速度。如果线程被调度到不同的处理器，就会导致缓存失效，性能下降。

## 组调度

对于并行应用程序（包含多个线程或进程），一种有效的策略是**组调度**。其核心思想是将一个应用的所有线程作为一个整体（组）进行调度，尽可能让它们同时在不同的处理器上运行。

![](img/77655a999fb22e9d5a1edcb7927001f2_27.png)

这样做的好处是减少了线程间通信的阻塞。例如，如果线程A向线程B发送消息，而线程B没有被调度执行，那么A就必须等待。如果整个组被同时调度，通信可以立即得到处理。

实现组调度时需要考虑一个问题：如果组中某个线程因I/O操作而阻塞，该如何处理？有两种常见策略：
1.  **协同调度**：一旦组中任何一个线程阻塞，就抢占整个组的所有线程，调度另一个组运行。
2.  **继续执行**：允许组内其他未阻塞的线程继续运行，直到时间片用完。

## 分布式调度（工作站网络）

![](img/77655a999fb22e9d5a1edcb7927001f2_35.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_37.png)

现在，我们将视野从单台机器扩展到多台机器构成的网络，探讨早期的分布式调度思想。这种模式通常假设环境是**工作站网络**：每个用户拥有一台桌面工作站，这些机器在用户不使用时可能处于空闲状态。

分布式调度的核心目标是：**利用网络中空闲机器的计算周期，将过载机器上的任务迁移到空闲机器上执行，从而提高整体资源利用率**。

![](img/77655a999fb22e9d5a1edcb7927001f2_39.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_41.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_43.png)

一个关键问题是：这种调度在什么情况下有益？通过直观分析可以得出：
*   **系统负载极高时**：所有机器都很忙，几乎找不到空闲机器来接收迁移的任务，因此收益很低。
*   **系统负载极低时**：大部分机器都空闲，但新任务可以直接在本地运行，无需迁移，因此收益也很低。
*   **系统负载适中时**：既存在等待运行的任务，也存在空闲的机器资源，此时分布式调度能带来显著收益。

![](img/77655a999fb22e9d5a1edcb7927001f2_45.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_47.png)

一个分布式调度器通常包含四个策略组件：
1.  **转移策略**：决定何时将进程转移到另一台机器（例如，当本地负载超过阈值时）。
2.  **选择策略**：决定转移哪个进程（通常优先选择新到达的进程，而非正在运行的进程）。
3.  **定位策略**：决定将进程转移到哪台机器（例如，随机选择、轮询或选择负载最低的机器）。
4.  **信息策略**：决定收集和维护哪些信息来做出上述决策（例如，其他机器的负载信息）。

![](img/77655a999fb22e9d5a1edcb7927001f2_49.png)

根据决策发起方的不同，主要有三种策略：
*   **发送者发起策略**：由负载高的机器主动寻找空闲机器并发送任务。
*   **接收者发起策略**：由负载低的机器主动寻找过载机器并请求任务。
*   **对称策略**：结合以上两者，设置高、低两个负载阈值。超过高阈值则成为发送者，低于低阈值则成为接收者。

历史上的一些操作系统具体实现了上述策略：

![](img/77655a999fb22e9d5a1edcb7927001f2_67.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_69.png)

*   **V系统（斯坦福大学）**：
    *   **信息策略**：采用状态变更驱动。任何机器的负载发生显著变化时，都会向全网广播其负载信息。
    *   **定位策略（发送者）**：发送者维护一个按负载排序的机器列表。当需要卸载任务时，从负载最轻的M台机器中随机选择一台发送。随机选择可以避免所有发送者都将任务集中到同一台最轻负载的机器上。

![](img/77655a999fb22e9d5a1edcb7927001f2_71.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_73.png)

*   **Sprite系统（加州大学伯克利分校）**：
    *   **核心理念**：尊重工作站所有者。用户离开时，其空闲机器可被用于运行他人任务；用户返回时，应立即恢复其对机器的完全使用权。
    *   **实现机制**：采用中央协调器收集负载信息。通过检测键盘/鼠标无活动超时（如30秒）且有空闲CPU，来判断机器可接收任务。当用户返回时，系统会**挂起**所有外来任务。为了不浪费计算成果，Sprite系统实现了复杂的**进程迁移**功能，将挂起的进程（包括内存、寄存器状态）转移到其他空闲机器继续执行。但进程迁移面临巨大挑战，如打开的本地文件、活跃的网络连接在迁移后都会断裂。

![](img/77655a999fb22e9d5a1edcb7927001f2_75.png)

*   **Condor系统（威斯康星大学）**：
    *   一个至今仍在活跃的系统，理念与Sprite类似，专注于运行**批处理作业**。它允许用户将一组机器组成集群，并利用空闲周期。

![](img/77655a999fb22e9d5a1edcb7927001f2_79.png)

## 志愿者计算

![](img/77655a999fb22e9d5a1edcb7927001f2_85.png)

志愿者计算是分布式调度思想在互联网规模上的应用。其核心是让全球用户自愿贡献个人电脑的空闲计算能力，用于大型科学项目（如寻找外星信号、药物研究）。

**工作方式**：
1.  用户从项目网站下载一个特殊的**屏幕保护程序**。
2.  当电脑空闲、屏幕保护启动时，该程序会连接项目服务器。
3.  服务器分配一小块计算任务（例如，分析一段射电望远镜数据）。
4.  屏幕保护程序完成计算并返回结果，然后获取下一个任务。
5.  当用户返回使用电脑时，屏幕保护停止，当前任务被丢弃。

![](img/77655a999fb22e9d5a1edcb7927001f2_87.png)

这种模式要求任务能够被**高度并行化**且分解成大量独立的小单元。它成功地将海量、零散的空闲计算资源汇聚起来，用于解决大规模计算问题。

## 现代集群调度

如今，硬件成本低廉，企业更倾向于构建专用的**服务器集群**。用户将作业提交到集群，由集群调度器统一分配资源。主要分为两类应用场景：

![](img/77655a999fb22e9d5a1edcb7927001f2_93.png)

![](img/77655a999fb22e9d5a1edcb7927001f2_95.png)

### 1. 交互式应用调度（如Web服务）
*   **目标**：优化请求的响应时间。
*   **架构**：通常有一个**分发器**（负载均衡器）接收用户请求，然后根据策略将请求分发给后端的多个**工作节点**（Web服务器）。
*   **负载均衡策略**：
    *   **请求级**：每个独立的HTTP请求都可能被发送到不同的服务器。
    *   **会话级**：同一用户会话（Session）的所有请求都被发送到同一台服务器。这对于需要维护会话状态（如购物车）的应用至关重要，因为状态通常存储在服务器的本地内存中。

### 2. 批处理作业调度
*   **目标**：优化系统吞吐量，在给定时间内完成尽可能多的作业。
*   **作业类型**：长时间运行的计算任务，如机器学习训练、大数据处理、科学模拟。
*   **系统示例**：SLURM（Simple Linux Utility for Resource Management），一个广泛用于超算的开源作业调度系统。
*   **高级特性**：现代集群调度器远比简单的“最少负载”策略复杂。它们支持：
    *   **多队列**：为不同用户组、项目或作业类型（短作业/长作业）设立独立队列。
    *   **配额与优先级**：为队列分配不同的资源配额和调度优先级。
    *   **策略实施**：确保资源分配符合预设的配额、优先级和公平性规则。
