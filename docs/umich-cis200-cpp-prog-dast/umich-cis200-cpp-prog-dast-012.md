## 单元测试入门

任何值得编写的代码都值得测试。测试的目的是确保代码的行为符合预期。手动检查输出容易出错，而计算机则擅长精确比较。因此，我们将通过编写代码来自动化测试过程。

以下是编写测试的基本步骤：

1.  **安排 (Arrange)**：设置测试所需的所有变量和对象。
2.  **执行 (Act)**：调用要测试的代码并获取结果。
3.  **断言 (Assert)**：验证实际结果是否与预期结果一致。

这是一种常见的测试组织方式，有助于提高代码的可读性和可维护性。

## 为强力球彩票类编写测试

我们将为 `PowerballTicket` 类的 `getWinnings` 函数编写测试。该函数根据匹配的号码计算奖金。

首先，我们需要创建一个单元测试项目。在Visual Studio中，可以添加一个“本机单元测试项目”。然后，我们需要引用包含 `PowerballTicket` 类的原始项目，以便在测试中使用它。

以下是测试 `getWinnings` 函数的一个示例：


```cpp
TEST_METHOD(GetWinnings_Jackpot)
{
    // 安排 (Arrange)
    int expectedWinnings = 1000000000; // 预期奖金：10亿
    vector<int> myNumbers = {1, 2, 3, 4, 5, 6};
    vector<int> winningNumbers = {1, 2, 3, 4, 5, 6};
    PowerballTicket ticket(myNumbers);
    PowerballTicket winningTicket(winningNumbers);

    // 执行 (Act)
    int actualWinnings = ticket.getWinnings(winningTicket);

    // 断言 (Assert)
    Assert::AreEqual(expectedWinnings, actualWinnings);
}
```


通过运行测试，我们可以得到一个清晰的通过或失败指示。如果测试失败，工具会显示预期值和实际值，帮助我们快速定位问题。

## 测试所有奖金等级

`getWinnings` 函数有多个可能的返回值（例如，匹配不同数量的白球和红球）。为了确保代码完全正确，我们应该为每个可能的奖金等级编写测试。

以下是其他一些测试用例的示例：

*   匹配5个白球（无红球）：奖金应为1,000,000美元。
*   匹配4个白球和红球：奖金应为50,000美元。
*   匹配4个白球（无红球）或3个白球和红球：奖金应为100美元。
*   仅匹配红球：奖金应为4美元。
*   无任何匹配：奖金应为0美元。

通过为所有这些情况编写测试，我们可以确保 `getWinnings` 函数的逻辑覆盖了所有边界情况。

## 代码覆盖率


代码覆盖率是衡量测试完整性的一个指标，它表示有多少比例的源代码被测试执行过。理想目标是达到100%的覆盖率，这意味着每一行代码都至少被一个测试用例执行过。

![](img/99b805e078af23e749c8dc0d4f3e22e3_16.png)

![](img/99b805e078af23e749c8dc0d4f3e22e3_17.png)

然而，在实践中，达到100%覆盖率可能需要付出巨大的努力。通常，我们会优先测试最复杂、最关键的业务逻辑。像简单的 `getter` 和 `setter` 方法，虽然也应该正确，但它们的测试优先级可能较低。

从零测试到覆盖大部分核心代码能带来最大的质量提升。追求最后的几个百分点可能需要不成比例的时间投入。

## 持续集成与部署

![](img/99b805e078af23e749c8dc0d4f3e22e3_21.png)

一旦我们拥有了自动化的测试套件，就可以将其集成到开发流程中，实现持续集成（CI）。持续集成指的是每当代码库发生变化时（例如，新的提交），就自动运行测试。

像GitHub这样的平台提供了Actions功能，可以配置在代码推送时自动运行测试。这带来了以下好处：

*   **快速反馈**：开发者无需在本地运行所有测试，节省时间。
*   **一致性**：测试在干净、标准化的环境中运行，结果更可靠。
*   **质量门禁**：只有通过所有测试的代码才能被合并到主分支。

![](img/99b805e078af23e749c8dc0d4f3e22e3_23.png)

更进一步，持续部署（CD）可以在测试通过后，自动将软件部署到生产环境。这对于Web应用尤其有用，可以实现快速迭代。但这也需要谨慎，因为错误的更新可能会影响大量用户。通常采用“金丝雀发布”策略，即先向一小部分用户发布新版本，确认无误后再全面推广。

例如，我们有一个 `Chair` 类，包含颜色和高度属性。我们可以重载 `==` 运算符来定义如何比较两把椅子是否“相等”（即颜色和高度都相同）。

```cpp
bool operator==(const Chair& lhs, const Chair& rhs) {
    return (lhs.getColor() == rhs.getColor()) &&
           (lhs.getHeightCm() == rhs.getHeightCm());
}
```
