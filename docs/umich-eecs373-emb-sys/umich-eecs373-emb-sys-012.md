# 012：SPI与I2C串行总线 🚀

![](img/348c43aaec3cb5f1066981eae67c444c_1.png)

在本节课中，我们将要学习两种在嵌入式系统中至关重要的串行通信协议：SPI（串行外设接口）和I2C（内部集成电路）。我们将了解它们的工作原理、硬件连接方式、各自的优缺点以及典型应用场景。

## 概述

串行通信协议是嵌入式系统实现芯片间通信的关键技术。由于微控制器GPIO引脚数量有限，我们需要将并行的数据转换为串行流进行传输。本节将深入探讨SPI和I2C这两种最常用的协议。

## SPI（串行外设接口）

### 基本概念与连接

![](img/348c43aaec3cb5f1066981eae67c444c_29.png)

![](img/348c43aaec3cb5f1066981eae67c444c_31.png)

![](img/348c43aaec3cb5f1066981eae67c444c_33.png)

![](img/348c43aaec3cb5f1066981eae67c444c_34.png)

SPI通常使用四根线（加上共地）进行通信：
*   **SCLK (Serial Clock)**： 由控制器产生的时钟信号。
*   **MOSI (Master Out Slave In)**： 控制器输出，从设备输入的数据线。
*   **MISO (Master In Slave Out)**： 控制器输入，从设备输出的数据线。
*   **SS/CS (Slave Select / Chip Select)**： 片选信号，由控制器控制，用于选择与哪个从设备通信。

其核心思想是两个移位寄存器（一个在控制器，一个在从设备）通过时钟同步进行数据交换。在每个时钟周期，数据同时从控制器移出到从设备，并从从设备移入到控制器。

**公式/代码描述：**
数据传输可以抽象为两个移位寄存器的循环移位操作。假设要发送的8位数据为 `data_to_send`，接收到的数据为 `data_received`，在每一个时钟边沿，操作类似于：
```
data_received[7] = MISO; // 读取从设备发来的位
MOSI = data_to_send[7]; // 向从设备发送位
// 然后所有位左移或右移一位，为下一个时钟周期准备
```

### 工作模式与时钟极性

SPI没有统一的官方标准，因此存在多种时钟配置模式，由**时钟极性(CPOL)**和**时钟相位(CPHA)**两个参数决定。

以下是四种模式的简要说明：
*   **模式0 (CPOL=0， CPHA=0)**： 时钟空闲时为低电平，数据在时钟上升沿采样。
*   **模式1 (CPOL=0， CPHA=1)**： 时钟空闲时为低电平，数据在时钟下降沿采样。
*   **模式2 (CPOL=1， CPHA=0)**： 时钟空闲时为高电平，数据在时钟下降沿采样。
*   **模式3 (CPOL=1， CPHA=1)**： 时钟空闲时为高电平，数据在时钟上升沿采样。

必须根据从设备的数据手册正确配置控制器的SPI模式，否则通信将失败。

### 典型数据帧

一个典型的SPI数据传输过程如下：
1.  控制器拉低目标从设备的片选线(CS)。
2.  控制器产生时钟信号(SCLK)。
3.  控制器通过MOSI线发送一个命令或数据字节（例如，请求读取传感器X轴数据）。
4.  同时，从设备通过MISO线返回数据（可能是对上一个命令的响应，或是默认值）。
5.  传输完预定位数（通常是8位或16位）后，控制器拉高片选线，结束本次传输。
6.  如果需要读取数据，控制器会再次发起一次传输，此时从设备将准备好的数据通过MISO线发回。

### SPI的优缺点

**优点：**
*   协议简单，易于实现。
*   全双工通信，理论数据速率高（可达数十兆比特/秒）。
*   硬件连接直观。

**缺点：**
*   需要独立的片选线，当从设备数量多时，会占用大量GPIO引脚。
*   没有硬件流控制和应答机制，错误处理需由软件实现。
*   控制器必须发起所有通信，从设备无法主动通知控制器。

上一节我们详细介绍了SPI总线，它是一种需要多根线且依赖片选进行寻址的协议。接下来，我们看看另一种只需要两根线的协议：I2C。

## I2C（内部集成电路）

I2C是一种半双工、同步、多主从的串行通信总线。它仅使用两根线（加上共地）即可连接多个设备，非常适合引脚资源紧张的系统。

![](img/348c43aaec3cb5f1066981eae67c444c_50.png)

I2C的两根线分别是：
*   **SDA (Serial Data Line)**： 双向数据线。
*   **SCL (Serial Clock Line)**： 时钟线，由主设备产生。

![](img/348c43aaec3cb5f1066981eae67c444c_52.png)

所有设备都并联在这两根总线上。每个I2C设备都有一个唯一的7位、10位或16位地址。总线通过**上拉电阻**连接到电源电压(VCC)。设备内部使用**开漏输出**驱动总线，这意味着它们只能将总线拉低（输出0），而不能主动拉高（输出1）。总线的高电平状态由上拉电阻来维持。

![](img/348c43aaec3cb5f1066981eae67c444c_54.png)

![](img/348c43aaec3cb5f1066981eae67c444c_56.png)

**公式/代码描述：**
总线上的逻辑电平可以表示为：`总线电平 = !(设备A拉低 || 设备B拉低 || ...) * VCC`。只要有一个设备输出0，总线即为低电平；所有设备都输出1（高阻态）时，总线由上拉电阻拉至高电平。

以下是通信的关键步骤：
1.  **起始条件(S)**： 当SCL为高电平时，SDA线出现一个从高到低的跳变。
2.  **地址帧**： 主设备发送7位（或10位）从设备地址，紧跟1位读写控制位（0表示写，1表示读）。
3.  **应答位(ACK/NACK)**： 地址发送后，主设备释放SDA线（输出1），并产生一个时钟脉冲。被寻址的从设备应在这个时钟周期内将SDA线拉低，作为应答(ACK)。如果地址不匹配或从设备忙，SDA线将保持高电平，即非应答(NACK)。
4.  **数据帧**： 在收到ACK后，主设备（写操作）或从设备（读操作）开始发送8位数据。每发送完8位数据，接收方必须发送一个ACK位。
5.  **停止条件(P)**： 当SCL为高电平时，SDA线出现一个从低到高的跳变。

### 总线速度与上拉电阻

I2C总线的最大速度受限于总线电容(C_bus)和上拉电阻(R_pullup)构成的RC充电时间常数。时间常数 `τ = R_pullup * C_bus`。为了在给定的时钟频率下确保信号能正确上升到逻辑高电平，必须选择合适的R_pullup值。标准模式(100 kbps)、快速模式(400 kbps)和高速模式(3.4 Mbps)都有对应的最大总线电容和推荐的上拉电阻范围。

### I2C的优缺点

![](img/348c43aaec3cb5f1066981eae67c444c_101.png)

![](img/348c43aaec3cb5f1066981eae67c444c_103.png)

**优点：**
*   只需要两根线，极大地节省了引脚和PCB空间。
*   支持多主多从（通过仲裁机制）。
*   具有硬件应答机制，通信更可靠。
*   有标准的地址分配，设备兼容性好。

![](img/348c43aaec3cb5f1066981eae67c444c_105.png)

![](img/348c43aaec3cb5f1066981eae67c444c_106.png)

![](img/348c43aaec3cb5f1066981eae67c444c_112.png)

![](img/348c43aaec3cb5f1066981eae67c444c_114.png)

**缺点：**
*   半双工通信，同一时刻只能单向传输数据。
*   速度受限于总线RC常数，通常低于SPI。
*   开漏结构和上拉电阻使得调试相对困难。
*   协议比SPI复杂。

## 总结

本节课中我们一起学习了两种核心的嵌入式串行通信协议。

*   **SPI** 以其简单、高速和全双工特性著称，适合对速度要求高、设备数量不多的点对点或星型拓扑通信。其缺点是需要较多的连线，且缺乏流控制。
*   **I2C** 以其极简的两线制和硬件寻址能力脱颖而出，非常适合连接多个低速外设的场合。它通过上拉电阻和开漏输出实现了多设备共享总线，但代价是速度受限和协议复杂度增加。

![](img/348c43aaec3cb5f1066981eae67c444c_116.png)

在实际项目中，选择SPI还是I2C取决于具体的需求：速度、引脚数量、设备数量以及系统复杂度。理解这两种协议的工作原理和特点，是设计高效、可靠嵌入式系统的基础。
