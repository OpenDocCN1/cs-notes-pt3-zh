## 为什么需要版本控制？

![](img/6664f4313c69a6e52424c50c9f7f269d_10.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_12.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_14.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_16.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_18.png)

在软件开发过程中，你可能会遇到以下常见问题：
*   不小心引入了错误，需要撤销大量更改。
*   删除了一个旧文件，但后来发现其中某些内容仍有价值。
*   在尝试新功能或工具时，担心会破坏当前可正常运行的项目。

版本控制系统（VCS）正是为解决这些问题而设计的工具。它能跟踪代码随时间的变化，创建项目的“时间线”，允许你查看历史状态，并在必要时回退到之前的稳定版本。Git是目前最流行的版本控制系统。

## 初始化Git仓库

要开始使用Git管理项目，首先需要在项目目录中初始化一个Git仓库。

![](img/6664f4313c69a6e52424c50c9f7f269d_20.png)

以下是初始化仓库的步骤：
1.  **创建项目目录**：使用 `mkdir` 命令创建一个新文件夹作为项目根目录。
2.  **进入目录**：使用 `cd` 命令切换到新创建的目录。
3.  **初始化仓库**：在该目录下运行 `git init` 命令。

执行 `git init` 后，系统会创建一个名为 `.git` 的隐藏文件夹，Git将使用这个文件夹来管理项目的所有版本历史，用户通常无需直接操作其中的内容。

## 理解Git提交（Commit）

![](img/6664f4313c69a6e52424c50c9f7f269d_25.png)

Git通过“提交”来记录项目的快照。你可以将每次提交想象成游戏中的存档点或绘图时的截图，它完整保存了项目在某个时刻的状态。

一个提交包含以下核心信息：
*   **提交ID**：一个唯一的40字符哈希值（如 `f1ac5a...`），用于标识该提交。
*   **父提交**：指向当前提交所基于的上一个提交，从而形成历史链。
*   **作者与时间戳**：记录是谁在何时创建了此提交。
*   **提交信息**：一段描述本次更改内容的文本，对于团队协作和日后回顾至关重要。
*   **变更内容**：记录自上次提交以来，哪些文件被添加、修改或删除。

## 实践：创建你的第一个提交

上一节我们介绍了提交的概念，本节中我们来看看如何实际创建一个提交。这个过程通常分为两步：将更改暂存，然后创建提交。

首先，我们需要在仓库中创建或修改一些文件。例如，可以使用 `echo` 命令和输出重定向来创建一个文本文件：
```bash
echo "Hello, Git!" > greeting.txt
```
使用 `git status` 命令可以查看仓库的当前状态，它会显示尚未被跟踪的新文件。

接下来，我们需要使用 `git add` 命令将文件更改添加到“暂存区”，为创建提交做准备。你可以添加特定文件，或使用 `.` 来添加所有更改：
```bash
git add greeting.txt
# 或
git add .
```
再次运行 `git status`，你会看到文件已被标记为“待提交”。

![](img/6664f4313c69a6e52424c50c9f7f269d_27.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_29.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_31.png)

最后，使用 `git commit` 命令并附上提交信息来创建提交：
```bash
git commit -m "Add initial greeting file"
```
命令执行后，你会看到系统生成了提交ID，并提示有多少文件被更改。至此，你的第一个提交就创建完成了。

## 查看与遍历提交历史

创建提交后，我们可以查看项目的提交历史。

使用 `git log` 命令可以列出所有提交，显示它们的ID、作者、日期和提交信息。为了获得更清晰的视图，可以使用一些参数：
```bash
git log --oneline --graph --decorate --all
```
这个命令会以单行、图形化的方式展示所有分支的提交历史。

![](img/6664f4313c69a6e52424c50c9f7f269d_33.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_35.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_36.png)

在Git中，**HEAD** 是一个特殊的指针，它指向你当前正在查看或基于其进行工作的那个提交。默认情况下，它指向最新的提交。

![](img/6664f4313c69a6e52424c50c9f7f269d_38.png)

![](img/6664f4313c69a6e52424c50c9f7f269d_40.png)

如果你想“穿越”回项目的某个历史状态，可以使用 `git checkout` 命令并指定目标提交的ID（通常只需前几位字符）：
```bash
git checkout a1b2c3d
```
执行后，HEAD会移动到指定的提交，你的工作目录也会恢复到该提交时的文件状态。这时你会处于“分离HEAD”状态。如果想回到最新的开发状态，可以切换回主分支（例如 `git checkout main`）。
