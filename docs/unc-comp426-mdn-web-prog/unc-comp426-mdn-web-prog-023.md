# 023：Vercel、持续集成、持续部署与数据分析 🚀

在本节课中，我们将学习如何将我们的Web应用部署到互联网上，并探索一些能帮助我们更专业、更高效地开发和维护项目的强大工具。我们将重点介绍Vercel平台，以及持续集成（CI）和持续部署（CD）的概念。最后，我们还会了解如何为你的应用添加数据分析功能。

## 课程概述与回顾

首先，我们来回顾一下“部署”这个概念。从本课程的第一个作业A01开始，你们就一直在使用Vercel将项目部署到网上。部署的本质，就是将你本地运行的代码放到一个服务器上，让其他人可以通过一个真实的URL来访问你的应用。

有多种工具可以实现部署，例如Netlify、GitHub Pages等。在本课程中，我们主要使用Vercel。Vercel是一个完整的云部署平台，它让部署应用变得非常简单。值得一提的是，Vercel也是我们使用的Next.js框架背后的开发团队。

Vercel主要提供三大核心功能：
1.  **部署项目到网络**：这是最基本的功能。
2.  **设置和连接域名**：管理你的网站URL，例如 `yourname.vercel.app`。你甚至可以连接自己购买的定制域名。
3.  **数据分析**：追踪用户如何与你的网站互动，例如访问量、用户来源、访问页面等。

## 理解CI/CD：持续集成与持续部署

接下来，我们引入一个在真实项目开发中非常重要的概念：**CI/CD**。这是两个相关但略有不同的术语。

*   **持续集成**：指的是在开发过程中，每当代码有变更（例如新的提交），就自动构建和测试项目，以确保新代码不会引入错误或破坏现有功能。
*   **持续部署/交付**：指的是当新功能开发完成并合并到主分支后，自动将更新部署到线上环境，让用户能够立即使用新功能。

Vercel帮助我们轻松管理CI/CD流程。它的核心机制是：**每当你的代码仓库有新的推送（push）时，Vercel都会尝试自动构建和部署你的项目**。

## Vercel的部署类型：预览与生产

Vercel会为你的项目创建和管理两种类型的部署。

*   **生产部署**：这是最终用户看到的版本。它与你设置的域名（如 `example.vercel.app`）直接关联。任何时间，只有一个生产部署是活跃的。
*   **预览部署**：每当你向仓库的**任何分支**推送新的提交时，Vercel都会尝试为这个特定版本的代码创建一个独立的部署。这个部署不会影响你的生产域名，但会生成一个独立的预览URL供开发者查看和测试。

预览部署的意义在于，它允许你在不影响线上用户的情况下，提前发现构建错误或功能问题。如果构建失败，Vercel会通知你。



### 工作流程图示



让我们通过一个Git提交历史的图示来理解这个过程。

假设你的项目主分支（`main`）目前有三个提交：添加了登录页、注册页和主页。Vercel会为最新的 `main` 分支提交创建一个**生产部署**，你的域名指向它。

现在，你想开发一个“个人资料页”新功能。最佳实践是创建一个新分支（例如 `feat/profile-page`）进行开发，而不是直接在 `main` 分支上修改，以免未完成的功能影响线上用户。

当你在 `feat/profile-page` 分支上提交代码时，Vercel会为这个提交创建一个**预览部署**。你可以通过预览URL查看这个功能的效果，并确保构建成功。此时，你的生产域名仍然指向旧版本，用户不受影响。

开发完成后，你需要创建一个GitHub拉取请求，准备将 `feat/profile-page` 分支合并回 `main` 分支。此时，Vercel会为这个拉取请求再创建一个预览部署，方便在合并前做最后检查。

当你批准并合并拉取请求后，`main` 分支就有了新的提交。Vercel会为这个新提交创建一个**新的生产部署**，并自动将你的域名切换指向它。这样，所有用户就能立刻看到包含新功能的网站了。

**思考**：在上述流程中，创建预览部署属于 **CI（持续集成）**，而合并后创建新的生产部署则属于 **CD（持续部署）**。

## 代码质量工具：Prettier与ESLint

除了部署，在开发过程中保持代码质量和风格一致也非常重要。这就是代码格式化工具（如Prettier）和代码检查工具（如ESLint）的用武之地。

*   **Prettier**：自动格式化你的代码，使其遵循统一的风格指南（如缩进、引号、括号位置等）。在本课程的开发容器中，保存文件时就会自动触发格式化。
*   **ESLint**：检查代码中潜在的错误或不符合最佳实践的写法（例如定义了未使用的变量、导入了未使用的模块等）。如果ESLint检查失败，Vercel的构建过程也会失败，从而阻止有问题的代码被部署。

**为什么需要这些工具？**
1.  **团队协作一致性**：确保团队所有成员遵循相同的代码风格，避免因个人习惯不同导致代码库混乱。
2.  **即时反馈与修正**：开发者可以按照自己习惯的方式编码，保存或提交时工具会自动修正格式或提示问题。
3.  **防止“技术债”堆积**：通过强制遵守规则，避免低质量代码（如无用变量）累积，保持代码库长期整洁和可维护性。

## 为项目添加数据分析

数据分析能帮助你了解用户如何与你的应用互动。Vercel内置了Web Analytics功能，可以轻松追踪页面访问量、用户来源、设备类型等信息。

设置Vercel Analytics非常简单：
1.  在Vercel项目仪表板的“Analytics”标签页中启用它。
2.  在你的Next.js项目中安装 `@vercel/analytics` 包。
3.  在 `app/layout.tsx`（或 `pages/_app.tsx`）文件中添加 `<Analytics />` 组件。

启用后，你可以在Vercel仪表板查看基本的访问数据。你还可以通过代码追踪自定义事件，例如用户点击了某个特定按钮、完成了某项操作等。这为深入分析用户行为提供了可能。

**请注意**：对于你们的期末项目，我们要求至少设置好基础的Vercel Analytics（追踪页面浏览量即可）。具体设置指南可参考课程幻灯片中的链接。

## 扩展概念：功能开关

功能开关是一种允许你动态开启或关闭应用特定功能的技术，而无需重新部署代码。它常用于：
*   **A/B测试**：为不同用户群体开启不同版本的UI，通过数据分析哪个版本效果更好。
*   **灰度发布**：先向小部分用户开放新功能，验证稳定后再全面开放。
*   **快速回滚**：如果新功能出现问题，可以立即关闭开关，而无需回退代码和重新部署。

虽然对于小型期末项目可能有些大材小用，但了解这个概念对未来的大型项目开发很有帮助。
