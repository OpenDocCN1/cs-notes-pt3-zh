## 块组：减少磁盘寻道时间 🔄

在基于i节点的文件系统中，文件的元数据（如目录项和i节点）通常与文件数据在磁盘上相距甚远。这会导致读取或写入文件时，磁头需要长距离移动，增加寻道时间。

伯克利快速文件系统提出的解决方案是**块组**。其核心思想是将磁盘划分为多个块组，每个块组包含自己的i节点集、空闲块位图和一部分数据区域。目标是尽量将单个文件的所有数据（包括元数据）保存在同一个块组内。

以下是块组分配的一个简化逻辑：
```c
// 根据块号计算其所属的块组
int block_group = block_number / BLOCKS_PER_GROUP;
```

这种设计是一种偏好而非强制要求。一个i节点可以指向其他块组中的块。只要大多数情况下文件数据能集中在同一块组，就能显著降低寻道时间，同时保留了分配的灵活性。

![](img/392995417771cffd50f556515d1db241_11.png)

## 片段：优化小文件存储 📦

为了提升大文件的读写效率，我们希望使用较大的块。但这会导致存储小文件时空间浪费严重，因为即使文件很小，也会占用整个块。

![](img/392995417771cffd50f556515d1db241_13.png)

伯克利快速文件系统的折中方案是引入**片段**。片段是块的子划分。对于小文件，系统可以分配片段而非整个块；对于大文件，则仍然按完整的块来分配。

这种机制的核心在于：
*   **小文件**：指向一个或多个片段。
*   **大文件**：指向一系列完整的块。

![](img/392995417771cffd50f556515d1db241_15.png)

![](img/392995417771cffd50f556515d1db241_16.png)

![](img/392995417771cffd50f556515d1db241_17.png)

这样，在不过多增加块管理开销的前提下，显著减少了对小文件的存储空间浪费。

![](img/392995417771cffd50f556515d1db241_19.png)

![](img/392995417771cffd50f556515d1db241_21.png)

## 区段：高效管理大文件 📁

![](img/392995417771cffd50f556515d1db241_23.png)

即使采用较大的块，对于数GB的大文件，其块指针列表也会非常庞大，读写这个列表本身就会成为性能瓶颈。

![](img/392995417771cffd50f556515d1db241_25.png)

现代文件系统采用**区段**来解决这个问题。区段代表磁盘上一段连续的块范围。对于大文件，系统不再记录每个单独的块号，而是记录一个或多个区段（起始块号 + 长度）。

![](img/392995417771cffd50f556515d1db241_27.png)

区段存储可以用以下结构表示：
```c
struct extent {
    uint64_t start_block; // 起始块号
    uint64_t length;      // 连续块的数量
};
```

![](img/392995417771cffd50f556515d1db241_29.png)

![](img/392995417771cffd50f556515d1db241_31.png)

理想情况下，一个大文件对应一个区段。这要求分配器更加智能，需要努力寻找并分配连续的磁盘空间，而不是随意分配离散的块。虽然增加了分配算法的复杂性，但极大地压缩了大文件的元数据大小。

![](img/392995417771cffd50f556515d1db241_33.png)

## 总结 🎯

本节课中我们一起学习了文件系统性能优化的三种关键技术：
1.  **块组**：通过将相关数据就近存放来减少磁盘寻道时间。
2.  **片段**：通过允许分配块的一部分来优化小文件的存储空间利用率。
3.  **区段**：通过记录连续块范围而非单个块指针，来高效管理大文件的元数据。

![](img/392995417771cffd50f556515d1db241_35.png)

这些优化共同作用，使得文件系统能在寻道时间、空间利用率和元数据管理开销之间取得更好的平衡。下一节，我们将探讨确保文件系统可靠性的关键技术：重做日志。
