

## 等待多个线程

最多等待 64 个对象（线程）

```
DWORD WaitForMultipleObjects(

    DWORD nCount,

    CONST HANDLE *lpHandles, // array

    BOOL fWaitAll, // wait for one or all

    DWORD dwMilliseconds)
```

等待所有：`fWaitAll==TRUE`

等待任一：`fWaitAll==FALSE`

- 返回值是找到的第一个数组索引

## 关于 WaitFor 函数的说明

- 将句柄作为参数
- 用于不同类型的对象
- 内核对象具有两种状态
  - 有信号
  - 无信号
- 行为由句柄所引用的对象定义
  - 线程：有信号表示已终止

### Hello Threads 时间线

| 时间 | main | 线程 0 | 线程 1 |
|---|---|---|---|
| T₀ | `i = 0` | --- | --- |
| T₁ | 创建(&i) | --- | --- |
| T₂ | `i++ (i == 1)` | 启动 | --- |
| T₃ | 创建(&i) | p = pArg | --- |
| T₄ | `i++ (i == 2)` | myNum = *p<br>myNum = 2 | 启动 |
| T₅ | 等待 | 打印(2) | p = pArg |
| T₆ | 等待 | 退出 | myNum = *p<br>myNum = 2 |

### 竞争条件

- 多个线程并发访问同一变量
  - 读/写冲突
  - 写/写冲突
- 并发程序中最常见的错误
- 可能并非总是显而易见
- 如何避免数据竞争？
  - 局部存储
  - 使用**临界区**控制共享访问

## Hello Thread：局部存储解决方案

```
DWORD WINAPI threadFunc(LPVOID pArg)
{
    int myNum = *((int*)pArg);
    printf( “Thread number %d\n”, myNum);
}
. . .

// from main():
for (int i = 0; i < numThreads; i++) {
    tNum[i] = i;

        CreateThread(NULL, 0, threadFunc, &tNum[i],
                     0, NULL);

```

### fork() 和 exec() 的语义

- fork() 是只复制调用线程还是复制所有线程？**都可以！**
- 如果一个线程调用了 exec()，结果会是什么？

exec() 参数中指定的程序将替换整个进程——包括所有线程。

## 线程取消

- 对于异步取消，如果目标线程拥有一些系统级资源，系统可能无法回收所有资源。
- 对于延迟取消，目标线程自行决定何时终止。回收资源不是问题。
- 大多数系统为进程（例如，使用 kill 系统调用）和线程实现异步取消。
- Pthread 支持延迟取消。

## 信号处理

- 在 UNIX 系统中，**信号**用于通知进程某个特定事件已发生。
- 所有信号都遵循相同的模式：
  - 信号由特定事件生成
  - 信号被传递给进程
  - 信号被处理
- *信号处理程序*用于处理信号
