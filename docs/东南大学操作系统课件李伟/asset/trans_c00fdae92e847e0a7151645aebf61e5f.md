

## 进程终止

- 父进程可以终止子进程的执行（abort）。
    - 子进程已超出分配的资源。
    - 分配给子进程的任务不再需要。
    - 父进程正在退出。（并非所有OS都如此， UNIX）
        - 操作系统不允许子进程在其父进程终止后继续运行。
        - 级联终止 (级联终止).

- 通信可以使用 **消息传递** 或 **共享内存** 进行。

## 共享内存系统

- 要求通信进程建立一个共享内存区域。
- 共享内存区域驻留在创建共享内存段的进程的地址空间中。
- 进程有责任确保它们不会同时写入同一位置。

## 生产者-消费者问题

- 协作进程的范式，**_生产者_** 进程产生的信息被 **_消费者_** 进程消费。
    - **_无界缓冲区_** 对缓冲区的大小没有实际限制。
    - **_有界缓冲区_** 假设缓冲区大小是固定的。

## 有界缓冲区 – 共享内存解决方案

- 共享数据

```c
#define BUFFER_SIZE 10
typedef struct {
    ...
} item;
item buffer[BUFFER_SIZE];
int in = 0;
int out = 0;
```

## 有界缓冲区 – 生产者进程

```
item nextProduced;

while (1) {
    while (((in + 1) % BUFFER_SIZE) == out)
        ; /* do nothing */
    buffer[in] = nextProduced;
    in = (in + 1) % BUFFER_SIZE;
}
```

## 有界缓冲区 – 消费者进程

```
item nextConsumed;

while (1) {
    while (in == out)
        ;/* do nothing */
    nextConsumed = buffer[out];
    out = (out + 1) % BUFFER_SIZE;
}
```

## 讨论

- 该解决方案是正确的，但只能使用 BUFFER_SIZE-1 个元素

## 消息传递系统

- **MPS 设施提供两个操作：**
    - *send(message)* – 消息大小固定或可变
    - *receive(message)*

- **如果 P 和 Q 希望通信，它们需要：**
    - 在它们之间建立一个 *通信链路*
    - 通过 send/receive 交换消息

- **通信链路的实现**
    - 物理的（例如，共享内存，硬件总线）
    - 逻辑的（例如，逻辑属性）

## 实现问题

- 链路的容量是多少？
- 链路可以容纳的消息大小是固定的还是可变的？
- 链路是单向的还是双向的？

## 间接通信

- **操作**
    - 创建一个新的邮箱
    - 通过邮箱发送和接收消息
    - 销毁一个邮箱
- **原语定义为：**
    - send(*A, message*) – 向邮箱 A 发送消息
    - receive(*A, message*) – 从邮箱 A 接收消息

## 间接通信

- **邮箱共享**
    - *P₁, P₂, 和 P₃* 共享邮箱 A。
    - *P₁* 发送；*P₂* 和 *P₃* 接收。
    - 谁获得消息？

- **解决方案**
    - 允许一个链路最多关联两个进程。
    - 允许一次只有一个进程执行接收操作。
    - 允许系统任意选择接收者。发送者会被通知接收者是谁。

## 同步

- 消息传递可以是阻塞的或非阻塞的。
- **阻塞** 被认为是同步的
- **非阻塞** 被认为是异步的
- send 和 receive 原语可以是阻塞的或非阻塞的。
