

## 抖动

- 如果进程没有“足够”的页，缺页率会非常高。
  - CPU 利用率低。
  - 操作系统认为需要提高多道程序度。
  - 于是向系统中添加另一个进程。
- **抖动** — 进程忙于在页与页之间换入换出。

![](img/0f9477f9dd9e571abf0b2ce4550a9e88_617_0.png)

- 为什么分页有效？
  - 局部性模型
    - 局部性是一组被一起活跃使用的页面。
    - 进程从一个局部性迁移到另一个局部性。
    - 局部性可能重叠。
- 为什么抖动会发生？
  - 局部性大小 > 分配的内存大小

### 工作集模型

- Δ ≡ 工作集窗口 ≡ 固定数量的页引用
- 示例：10,000 条指令
- WSSᵢ（进程 Pᵢ 的工作集）= 最近 Δ 次引用中引用的页面总数（随时间变化）
- 如果 Δ 太小，则无法涵盖整个局部性。
- 如果 Δ 太大，则会涵盖多个局部性。
- 如果 Δ = ∞ ⇒ 将涵盖整个程序。
- 工作集是程序局部性的一种近似。
- $D = \sum WSS_i \equiv$ 总需求帧数
- 如果 $D > m \Rightarrow$ 抖动 $\Rightarrow$ 挂起其中一个进程

### 缺页频率

![](img/0f9477f9dd9e571abf0b2ce4550a9e88_622_0.png)

- 建立“可接受的”缺页率。
  - 如果实际缺页率过低，进程将失去帧。
  - 如果实际缺页率过高，进程将获得帧。

## 分配内核内存

- 与用户内存的处理方式不同
- 通常从空闲内存池中分配
  - 内核为不同大小的结构请求内存
  - 某些内核内存需要连续

### 伙伴系统

- 从由物理上连续的页面组成的固定大小段中分配内存
- 使用 2 的幂次分配器分配内存
  - 以 2 的幂次大小的单位满足请求
  - 请求向上取整到下一个最高的 2 的幂次
  - 当需要的分配比可用的更小时，当前块被拆分为两个下一级 2 的幂次的伙伴块
    - 继续拆分，直到获得合适大小的块

### 板坯分配器

- 创建缓存时，用标记为空闲的对象填充
- 存储结构时，对象被标记为已使用
- 如果板坯充满已使用的对象，则从空板坯中分配下一个对象
  - 如果没有空板坯，则分配新的板坯
- 优点包括无碎片、快速满足内存请求
