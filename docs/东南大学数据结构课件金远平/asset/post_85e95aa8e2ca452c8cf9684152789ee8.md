
- $r_{ii}=0$, $w_{ii}=q_i$, $0 \le i \le n$.
- The optimal b.s.t. for $a_1, \ldots, a_n$ is $T_{0n}$. Its cost is $c_{0n}$, root $r_{0n}$.

If $T_{ij}$ is an optimal b.s.t. for $a_{i+1}, \ldots, a_j$ and $r_{ij}=k$, $i < k \le j$, then $T_{ij}$ has 2 subtrees L and R.

- L contains the identifiers $a_{i+1}, \ldots, a_{k-1}$.
- R contains the identifiers $a_{k+1}, \ldots, a_j$.

![](img/15e8d7d94d8ddf02cb6839870195a31e_753_0.png)

The cost $c_{ij}$ of $T_{ij}$ is

$$c_{ij} = p_k + \operatorname{cost}(L) + \operatorname{cost}(R) + w_{i,k-1} + w_{kj} \quad (10.2)$$

From (10.2), if $c_{ij}$ is to be minimal, then $\operatorname{cost}(L)=c_{i,k-1}$ and $\operatorname{cost}(R)=c_{kj}$, as otherwise we could replace either L or R by a subtree with a lower cost, thus generating a b.s.t. for $a_{i+1}, \ldots, a_j$ with a lower cost than $c_{ij}$. This violates the assumption that $T_{ij}$ is optimal.

Hence, Eq. (10.2) becomes

$$c_{ij} = p_k + w_{i,k-1} + w_{kj} + c_{i,k-1} + c_{kj} = w_{ij} + c_{i,k-1} + c_{kj} \quad (10.3)$$

Since $T_{ij}$ is optimal, from (10.3) we know $r_{ij}=k$ is such that

$$w_{ij}+c_{i,k-1}+c_{kj}=\min_{i<l\le j}\{w_{ij}+c_{i,l-1}+c_{lj}\}$$

or

$$c_{i,k-1}+c_{kj}=\min_{i<l\le j}\{c_{i,l-1}+c_{lj}\} \quad (10.4)$$

### Note also

$$w_{ij}=w_{i,j-1}+p_j+q_j.$$

(10.4) gives us a means of obtaining $r_{0n}$, $T_{0n}$ and $c_{0n}$, starting from $r_{ii}=0$, $T_{ii}=\varnothing$ and $c_{ii}=0$.

In general, we need to compute $c_{ij}$ for $j-i=1,2,\ldots,n$.

And for each $j-i=m$, there are $n-m+1$ $c_{ij}$'s ($c_{0m},\ldots,c_{n-m,n}$) to compute.

The computation of each $c_{ij}$ needs to find the minimum from $m$ quantities (10.4) — needs $O(m)$.

The total time for all $c_{ij}$'s with $j-i=m$ is $O((n-m)m)$.

The total time is

$$\sum_{1\le m\le n} (n-m)m = O(n^3)$$

In fact, Knuth proved that the optimal $l$ in (10.4) may be found by limiting the search to the range $r_{i,j-1} \le l \le r_{i+1,j}$. In this case, the computing time becomes $O(n^2)$. Algorithm obst uses this result.

Class BST of Chapter 5 is augmented to include obst as a private member function and to have the private data members $r$, $c$, and $w$.

Now the algorithm obst.

```cpp
template <class KeyType>
void BST<KeyType>::obst(int *p, int *q, Element<KeyType> *a, int n)
// given a1 < a2 < ... < an, and pj, 1 <= j <= n, and qi, 0 <= i <= n, compute cij
// for Tij for a_{i+1}, ..., aj. Also compute rij and wij.
{
    for (int i = 0; i < n; i++) {
        w[i][i] = q[i]; r[i][i] = c[i][i] = 0;    // initialize
        w[i][i+1] = q[i] + q[i+1] + p[i+1]; // optimal trees with one node
        r[i][i+1] = i + 1;
        c[i][i+1] = w[i][i+1];
    }
    w[n][n] = q[n]; r[n][n] = c[n][n] = 0;

    for (int m = 2; m <= n; m++) // find optimal b.s.t. with m nodes
        for (int i = 0; i <= n - m; i++) {
            int j = i + m;
            w[i][j] = w[i][j-1] + p[j] + q[j];
            int k = KnuthMin(i, j);
            // KnuthMin returns k in the range [r[i][j-1], r[i+1][j]]
            // minimizing c[i][k-1] + c[k][j]
            c[i][j] = w[i][j] + c[i][k-1] + c[k][j]; // Eq. (10.3)
            r[i][j] = k;
        }
} // end of obst
```

The actual $T_{0n}$ may be constructed from $r_{ij}$ in $O(n)$.
