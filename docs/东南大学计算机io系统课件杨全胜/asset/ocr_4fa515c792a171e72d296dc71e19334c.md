# 3.2 Principal I/O techniques

# Interrupt-Driven I/O

# How Interrupt-Driven I/O do for input, for example

+   1. The processor issues a READ command to I/O module, then goes off and does something else.
+   2. The I/O module get the data from the device and latch them in buff, then interrupt the processor to require service.
+   3. The processor saves the context of the current program and process the interrupt to read the word of data from the I/O module and stores it in memory or register.
+   4. The processor restores the context of the program it was working on and resumes execution.
