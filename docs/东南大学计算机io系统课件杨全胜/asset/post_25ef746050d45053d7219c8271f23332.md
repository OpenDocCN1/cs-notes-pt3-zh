
## 3.2 Principal I/O techniques
### Programmed I/O

I/O command that an I/O module may receive when it is addressed by a processor

- Control: Used to activate a peripheral and tell it what to do.
- Test: Used to test various status conditions associated with an I/O module and its peripherals.
- Read: Cause the I/O module to obtain an item of data from the peripheral and place it in an internal buffer. The processor can then obtain the data item by requesting that the I/O module place it on the data bus.
- Write: Cause the I/O module to take an item of data from the data bus and subsequently transmit that data item to the peripheral.

The problem with programmed I/O is:

- That the processor has to wait a long time for the I/O module of concern to be ready for either reception or transmission of data.
- The processor, while waiting, must repeatedly interrogate the status of the I/O module.
- As a result, the level of the performance of the entire system is severely degraded.

### Interrupt-Driven I/O

- Processor issue an I/O command to a module and then go on to do some other useful work.
- The I/O module will then interrupt the processor to request service when it is ready to exchange data with the processor.
- The processor then executes the data transfer, as before, and then resumes its former processing.

#### How Interrupt-Driven I/O do for input, for example

1. The processor issues a READ command to I/O module, then goes off and does something else.
2. The I/O module get the data from the device and latch them in buff, then interrupt the processor to require service.
3. The processor saves the context of the current program and process the interrupt to read the word of data from the I/O module and stores it in memory or register.
4. The processor restores the context of the program it was working on and resumes execution.

### Direct Memory Access

- When a processor wishes to read or write a block of data, it issues a command to the DMA module. Then the processor continues with other work.
- The DMA do the I/O operation to transfer the entire block of data directly to or from memory, without going through the processor.
- When the transfer is complete the DMA module send an interrupt to the processor.
- Thus, the processor is involved only at the beginning and end of the transfer or when the transfer has problem.

### I/O Channels

- The I/O module is enhanced to become an processor in its own right, with a specialized instruction set tailored for I/O. This I/O module is often referred to as an I/O channel.
- The I/O channel has the ability to execution the I/O instructions, which gives it complete control over I/O operations.
- The CPU dose not execute I/O instructions, such instructions are stored in the main memory to be executed by a special-purpose processor in the I/O channel itself.

### I/O Processor

- The I/O module has a local memory of its own and is, in fact, a computer in its own right.
- With this architecture, a large set of I/O devices can be controlled, with minimal CPU involvement.
- A common use for such an architecture has been to control communication with interactive terminals.
- The I/O processor takes care of most of the tasks involved in controlling the terminals.

## 3.3 The type of the I/O address space
### Isolated I/O

- The address for isolated I/O device, called ports address, is separate from the memory address space.
- The user can expand the memory to its full size without using any of memory space for I/O device.
- Disadvantage:
  - Data transfer between I/O and CPU must be accessed by the specialized I/O instructions.
  - Need specialized the control signal(M/IO,WR,RD)
- X86-based system used.
