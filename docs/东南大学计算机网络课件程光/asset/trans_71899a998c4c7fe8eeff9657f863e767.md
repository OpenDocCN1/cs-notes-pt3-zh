

## CSMA/CD 帧的最小长度的要求：

CSMA/CD要求整个帧的长度应不小于64字节。

目的：保证发送结点可以对发生的冲突进行有效的检测。

即：帧发送完之前，应当保证所有结点都可侦听到媒体上有信息在传输，从而暂停发送动作；

或者：若某个其他结点也启动发送过程，则结点应在发送完帧之前感知到冲突信号；

CSMA/CD要求整个帧的长度应不小于64字节。

要求：整个帧的发送时间应当不小于信号在网络中“传播距离最大”的两个结点之间传播时间的两倍：

分别对应信号到达“最远”的结点，以及冲突信号从“最远”的结点返回本结点。

## 二进制指数退避算法：

退避时间计算：信号在媒体上的往返时间 * 随机数；

随机数(r)的取值范围依赖于冲突的次数(i)； 0≤r<2^i

思路：错开等待时间，使之随失败次数增多而增加。

| 冲突次数 | 随机数（r）取值范围 |
|---|---|
| 第1次： 0, 1 （2^1-1） | |
| 第2次： 0, 1, 2, 3 （2^2-1） | |
| 第3次： 0, 1.....7 （2^3-1） | |
| ... | |
| 第i次： 0, 1, ......, 2^i-1 | |

第10次冲突后，等待时间随失败次数增多而增加，将时间错开。

第16次后，向上层报错。

## CSMA/CD的特点：

+   (1) 竞争，各节点强占对共享媒体的访问权
+   (2) 轻负载时，效率较高
+   (3) 重负载时，冲突概率加大，效率低
+   (4) 所有节点共享媒体，任何时刻只有一个节点在发信息
+   (5) 不适合实时传输

## CSMA/CD实用网络—以太网（Ethernet）

### （1） 以太网的起源

60年代末期，夏威夷大学Norman Abramson等研制ALOHA无线网络系统，实现Oahu岛上的主机和其它岛及船上的读卡机和终端通信；

出境信道+地址：主机到终端；

入境信道-终端到主机；200-1500毫秒未收应答，随机重发；70年提出ALOHA模型，争用性协议成果获IEEE Kobayashi奖。

![](img/0761188ee01704e55ea71e6a97539d38_320_0.png)

### （1）以太网的起源（续）

72年Xerox公司研制第一台PC（ALTO），Metcalfe等人阅读Abramson论文，思想用于ALTO互连，形成ALTO ALOHA网络，

73年5月22日，正式运行，命名Ethernet；

77年底，Metcalfe等人获“具有冲突检测的多点数据通信系统”专利；

79年，DEC（技术力量）、Intel（硅片）和Xerox（专利）公司共建产业标准；

80年9月，DIX V1.0—以太网：数据链路层和物理层规范；

82年，DIX V2.0—以太网标准；

凡低二层遵循DIX规范的网络的都可称为以太网。

+   - 80年，IEEE成立802委员会研究LAN国际标准；
+   - 81年6月，成立802.3分委员会，研究基于DIX成果的国际标准；
+   - 82年12月，802.3草案标准；83年802.3标准。

V2.0—以太网：数据链路层和物理层规范。

## 帧格式

| 8 | 6 | 6 | 2 | 46-1500 | 4（字节） |
|---|---|---|---|---|---|
| F | DA | SA | L/T | DATA | FCS |

F（帧起始符）：10101010 * 7 + 10101011（同步用）

DA/SA（源/宿地址）—网卡地址；

L/T（数据长度/帧类型）：高层定义，包括Ack；

Data（数据）：高层数据，用户满足长度要求；

FCS（帧校验）：CRC。

整个帧长（含起始符）为72—1526字节。

## ★ 工作过程（接收）

（类似802.3标准）

**差异：**
增加了**确认帧**（ACK帧）和等待ACK帧（9.6us），超时重发；

利用**ACK帧**来保证传输的有效性。

定义了**帧间间隔**（不能连续发数据，需等待一个时间间隔，保证ACK帧传输）。

## ★ 工作过程（发送）

```
高层有数据发送（LLC）
↓
封装MAC帧
↓
侦听媒体
↓
媒体上有无数据在传输？
├─ 有 → 按策略退避 → 退避时间是否到？
│       ├─ 未到 → 继续等待
│       └─ 已到 → 退避次数是否超过？
│                 ├─ 未超过 → 继续侦听媒体
│                 └─ 已超过 → 通知LLC网络太忙
└─ 无 → 等待9.6us仍空闲？
        ├─ 否 → 继续侦听媒体
        └─ 是 → 发送数据
                ↓
             发送数据是否冲突？
             ├─ 冲突 → 强化冲突 → 返回侦听媒体
             └─ 无冲突 → 等待Ack
                         ├─ 超时 → 超时2次？
                         │         ├─ 否 → 重新发送数据
                         │         └─ 是 → 发送失败
                         └─ 收到Ack → 发送成功
```
