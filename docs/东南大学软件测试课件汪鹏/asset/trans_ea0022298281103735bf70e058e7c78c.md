## # 挑战：测试用例规划

```
class Roots {
    // Solve ax² + bx + c = 0
    public roots(double a, double b, double c)
    { ... }

    // Result: values for x
    double root_one, root_two;
}
```

- **我们应该测试 _a_、_b_、_c_ 的哪些值？**
  - 假设 a、b、c 是 32 位整数，我们将有 (2³²)³ ≈ 10²⁸ 个合法输入
  - 即使每秒运行 1.000.000.000.000 个测试，仍然需要 25 亿年

## 随机测试

- 均匀选取可能输入值
- 避免选择偏见
- 对所有用例一视同仁

## 随机测试为什么不行

- 缺陷分布并不均匀
- 假设 Roots 应用二次方程
  $$x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}$$
  并且当 $b^2 - 4ac = 0$ 且 $a = 0$ 时失败
- 随机测试很难取到特定值

## # 黑盒测试基本概念

## ## 定义

黑盒测试：一种基于规格说明，不要求考察代码，以用户视角进行的测试

其它称谓：

功能测试、基于规格说明的测试

## # 黑盒测试基本概念

## ## ▪意义

- 1. 检查明确需求和隐含需求
- 2. 采用有效输入/输出和无效输入/输出
- 3. 包含用户视角

## # 黑盒测试基本概念

## ## ■挑战1：测试用例规划

**问题：** 可能输入/输出量常常接近无穷

**解决：** 测试用例数尽可能少，发现缺陷尽可能多
