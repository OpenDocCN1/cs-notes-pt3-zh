# 明确架构的优势

- **利益相关者沟通**
  - 架构可被用作系统利益相关者讨论的焦点。
- **系统分析**
  - 意味着可以分析系统是否能满足其非功能性需求。
- **大规模复用**
  - 架构可在一系列系统间复用

# 明确架构的优势

- **工具用于**
  - 理解
    - 系统
    - 理论限制
  - 规划
    - 资源
    - 人力
  - 沟通
    - 客户
    - 维护部门
  - 评估质量

# 影响因素

- 技术和组织因素
  - 目标领域的质量需求
  - 技术环境
- 业务因素
  - 整体业务目标
- 系统利益相关者
  - 管理层“低成本，保持人员就业”
  - 市场营销“精美功能，低成本，上市时间”
  - 终端用户“行为，性能，可靠”
  - 维护组织“可修改，可理解”
  - 客户“低成本，及时交付”
- 其他质量需求。

# 架构很早

- 架构代表最早的设计决策集合
  - 最难更改
  - 最关键要做对
- 架构是系统质量属性得到解决的第一个设计产物

# 架构与设计的区别

- 架构
  - 非功能性决策被确定之处，以及功能需求被划分之处
- 设计
  - 功能需求得以实现之处
