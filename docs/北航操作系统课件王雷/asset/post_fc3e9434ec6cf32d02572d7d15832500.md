## 比较

| Item | Multiprocessor | Multicomputer | Distributed System |
|---|---|---|---|
| Node configuration | CPU | CPU, RAM, net interface | Complete computer |
| Node peripherals | All shared | Shared exc. maybe disk | Full set per node |
| Location | Same rack | Same room | Possibly worldwide |
| Internode communication | Shared RAM | Dedicated interconnect | Traditional network |
| Operating systems | One, shared | Multiple, same | Possibly all different |
| File systems | One, shared | One, shared | Each node has own |
| Administration | One organization | One organization | Many organizations |

## 分布式进程同步

- 事件排序
  - 为每个进程建立逻辑时钟
  - 收到消息进程的逻辑时钟大于发出消息的逻辑时钟，如果收到消息的进程发现消息的逻辑时钟大于自己的逻辑时钟，则重置自己的逻辑时钟。
    - Send(m)=100, Receive(m)=90, 因此需要 Receive(m)=Send(m)+1=101
- Lamport算法

## 假设条件

- 对系统节点N进行编号，每个节点有一个进程提出请求。
- 按序传递消息。
- 消息在有限时间内送达。
- 处理器直接通信。

- 每个进程在发消息时加上自己的逻辑时钟 Ti，并保持一个请求队列

- Pi请求某个资源时，Request（Ti，i）发送到自己的队列，并发送给其他进程

- Pj收到Request（Ti，i），回复Reply（Tj，j），放入自己的队列。如果Pj收到Request（Ti，i）前已经请求过同一资源，其比较本地的邮戳时间，如果Ti＞Tj，则推迟回复。

- 允许访问
  - Pi请求处于队列的最前面
  - 收到的其他请求，晚于（Ti，i）

- 从自己的队列中去掉消息，发Release消息给其他进程

- Pj收到Pj的Release后，消去请求消息。

- 当每一个进程要访问一个共享资源时，本算法要求该进程发送3（N-1）个消息，其中（N-1）个Request消息，（N-1）个Reply消息，（N-1）个Release消息。

## 远程过程调用

![](img/861c0ad57b0249095c0356c9e5a83b26_1128_0.png)

- RPC's can be used to communicate between address spaces on different machines or the same machine
  - Services can be run wherever it’s most appropriate
  - Access to local and remote services looks the same
- Examples of modern RPC systems:
  - CORBA (Common Object Request Broker Architecture)
  - DCOM (Distributed COM)
  - RMI (Java Remote Method Invocation)
