

## 2.3.2 分析分治算法

当一个算法包含对自身的递归调用时，其运行时间通常可以用递推方程或递推关系来描述，该关系通过较小输入上的运行时间来表示规模为 n 的问题上的总体运行时间。

我们得到如下递推关系：

T(n) = { Θ(1)                     如果 n ≤ c
        a T(n / b) + D(n) + C(n)  否则 }

- D(n) 是将问题分解为子问题所需的时间。
- C(n) 是将子问题的解合并为原问题的解所需的时间。

```
MERGE-SORT(A, p, r)
1   if p < r
2     Then q ← ⌊(p + r) / 2⌋
3       MERGE-SORT(A, p, q)
4       MERGE-SORT(A, q+1, r)
5       MERGE(A, p, q, r)
```

T(n) = { Θ(1) 如果 n ≤ c
 a T(n / b) + D(n) + C(n) 否则 }

假设原问题规模是 2 的幂，递推分析可以简化。这样每一步分解都会产生两个大小恰好为 n/2 的子序列（该假设不影响递推解的增长阶）。

```
MERGE-SORT(A, p, r)
1   if p < r
2     Then q ← ⌊(p + r) / 2⌋
3       MERGE-SORT(A, p, q)
4       MERGE-SORT(A, q+1, r)
5       MERGE(A, p, q, r)
```

T(n) = { Θ(1) 如果 n ≤ c
  aT(n / b) + D(n) + C(n) 否则 }

- 如何为 T(n) 建立递推关系？T(n) 是归并排序对 n 个数排序的最坏情况运行时间。
- 如果只有一个元素 n=1，则花费常数时间。
- 当 n>1 时，
- **分解**：该步骤只是计算子数组的中间位置，一步完成。因此 D(n)=Θ(1)。
- **解决**：递归地求解两个规模为 n/2 的子问题，这为运行时间贡献 2T(n/2)。
- **合并**：MERGE 过程表明 C(n)=Θ(n)。

T(n) = { Θ(1) 如果 n = 1
  2T(n / 2) + Θ(n) 如果 n > 1 }

```
MERGE-SORT(A, p, r)
1   if p < r
2       Then q ← ⌊(p + r) / 2⌋
3           MERGE-SORT(A, p, q)
4           MERGE-SORT(A, q+1, r)
5           MERGE(A, p, q, r)
```

重写递推方程

$$T(n)=\begin{cases}\Theta(1), & \text{if } n=1\\2T(n/2)+\Theta(n), & \text{if } n>1\end{cases}$$

$$T(n)=\begin{cases}\Theta(1), & \text{if } n=1\\2T(n/2)+cn, & \text{if } n>1\end{cases}$$

求解递推方程。

![](img/09c68ab421cfce4995ddad1430ef2637_100_1.png)

![](img/09c68ab421cfce4995ddad1430ef2637_101_0.png)

将所有层次的开销相加。

共有 $\lg n+1$ 层，每层花费 $cn$，总成本为

$$cn(\lg n+1)=cn\lg n+cn=\Theta(n\lg n)$$

显然，对于足够大的输入，它在最坏情况下优于插入排序，后者运行时间为 $\Theta(n^2)$。
