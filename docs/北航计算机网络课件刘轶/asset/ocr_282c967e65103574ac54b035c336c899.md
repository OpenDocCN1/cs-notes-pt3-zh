# 3.2 错误检测和纠正

# 一、检错编码(Error detecting code)

+   - 循环冗余校验CRC原理
+   - 发送方把数据段分成k位，设每帧k个比特，在其后添加n位差错检测的n位冗余码，(k+n)比特一起发送
+   - 对接收方M计算第n位冗余码的过程：
+     - 用n位除数除2位冗余码，得到M的商，设当n位在M后面添加n个0
+     - 得到(k+n)位的数值先除选定的长度为(n+1)位的数值P，得到商为Q和余数R，余数R就是P为n位，R为n-1位
+     - R作为余数，构成生成多项式M'，最后发送元素：2*M - R
+     - 接收方收到数据后进行校验
+   - 接收方对收到的(k+n)比特计算冗余码，结果为0表示传输正确，否则表示传输错误

# 例：计算101001的3位CRC冗余码

已知：M=101001 k=6, n=3 除数P=1101 101001→Q(商) P(除数)→1101 101001000→2*M(除数) 设除数P=1101 1101 1110 1111 0111 0000 被除数：2*M=101001000 模运算的结果：商Q=110101 余数R=001 1110 1101 0110 1100 1101 001←R(余数) 发送的数据：2*M+R 即：101001001，共(k+m)位

# 二、纠错编码(Error correcting code)

+   - 检错码只能发现数据出现了错误，无法得知哪个比特出错
+   - 纠错编码通过增加冗余信息使得能够检测错误发生所在，以便于纠正，又称为向前纠错(forward error correcting)
+   - 关于数据链路层检错纠错的讨论
+     通过检错码/纠错码可以做到无差错接收，或者说“无比特差错”
+     -并不意味着可靠传输，其他的错误包括：
+       - 帧丢失、帧重复、帧失序

# 一、无限制的单工协议

+   - 假定信道
+     - 单向传输
+     - 永远不会出错
+     - 交付能力有界但无限
+     - 接收方能够及时处理所收到的数据

```
void sender(void)
{
  frame a; //待发送帧
  packet buffer; //待发送数据包
  while (1)
  {
    from_network_layer(&buffer); //从网络层获得数据包
    a.info = buffer; //把数据包装入帧
    to_physical_layer(&a); //把帧传给物理层
  }
}
```

```
void receiver(void)
{
  frame r;
  event_type event; //等待事件
  while (1)
  {
    wait_for_event(&event); //等待帧到达
    from_physical_layer(&r); //从物理层获得帧
    to_network_layer(&r.info); //把帧交给网络层
  }
}
```

# 二、单工停等(stop-and-wait)协议

按“无限能力单工协议”，如果接收方处理帧的速度不及发送方，帧可能丢失

解决办法：增加流量控制(flow control)机制，得到单工停等协议
- 接收方每收到一帧后，都要发送一个确认帧
- 发送方每发送一帧，都要等待接收方的确认，然后才发送下一帧数据

```
void sender(void)
{
  frame s;
  packet buffer;
  event_type event;
  while (1)
  {
    from_network_layer(&buffer); //从网络层获得数据包
    s.info = buffer; //把数据包装入帧
    to_physical_layer(&s); //把帧传给物理层
    wait_for_event(&event); //等待确认帧
  }
}
```

```
void receiver(void)
{
  frame r;
  event_type event;
  while (1)
  {
    wait_for_event(&event); //等待帧到达
    from_physical_layer(&r); //从物理层获得帧
    to_network_layer(&r.info); //把帧交给网络层
    to_physical_layer(&ack); //发送确认帧
  }
```

- 序号：使接收方知道收到的帧是否正确

协议实现考虑的两个主要情形
1 数据帧可能出错
  - 接收方收到错误帧，发送方收到确认后发送下一帧
2 数据帧可能丢失
  - 数据帧可能丢失，发送方超时后重传
  - 接收方收到重复帧后丢弃
3 序号出错可能丢失
  - 发送方收到确认后重传，接收方收到后，检查序号
  - 不正确时，只返回确认
