# 5.6 TCP的流量控制

+   一、利用滑动窗口实现流量控制
+   - 持续计时器(persistence timer)
+   - TCP为每一个连接设置一个特殊计时器
+   - 只要一方收到对方的零窗口通知，就启动持续计时器
+   - 若持续计时器设置的时间到，触发发送一个零窗口探测报文段(仅携带1字节的数据)，而对方在确认这个探测报文段时给出当前窗口值
+   - 若窗口仍是零，则收到这个报文段的一方就重新设置持续计时器
+   - 若窗口不是零，则死锁的僵局就可以打破了

+   - 发送方的一个计时器周期到了，这时就把当前已有的缓存数据装入报文段(但长度不能超过MSS)发送出去

# 5.7 TCP的拥塞控制

+   一、拥塞控制的一般原理
+   - 拥塞(congestion)概念和产生原因(1/2)
+   - 在某段时间，某网络中同时要求传送的数据量超过了该网络所能提供的可用部分，网络的拥塞就变得明显，从而产生拥塞，即拥塞产生的条件：
+   - 交通资源的需求 > 可资源
+   - 网络资源、链路带宽、路由器处理能力等
+   - 网络拥塞是由多种原因引起的，通过简单地增加某种资源数量往往并不能消除拥塞
+   - 例如：若网络中的存储容量太小，造成到站数据的频繁丢失，如果增加缓存容量，网络拥塞
+   - 报文在网络中拥挤，但如果路由器处理能力和输出链路带宽增加，报文就获得间隙，发送主机就提高速率则拥塞就又会产生

# 5.7 TCP的拥塞控制

+   一、拥塞控制的一般原理
+   - 拥塞(congestion)概念和产生原因(2/2)
+   - 网络拥塞的表现
+   - 网络性能下降，具体表现为网络时延下降、报文传输时延增大、丢包增多等，用用户感觉到时延长、丢包等
+   - 拥塞常常会引起恶化，即恶性循环
+   - 由 TCP 流量控制
+   - 如：一个网络由于拥塞在不显示丢弃报文段而分片，发送端主机超时重传，发送端主机超时重传导致网络中报文段数增多，从而加剧拥塞
+   - 拥塞控制(congestion control)与流量控制
+   - 拥塞控制：防止过多的数据注入到网络中，使网络的路由或链路不致过载
+   - 拥塞控制是全网络性的问题，而流量控制是点对点通信量的控制，是端到端的问题

# 5.7 TCP的拥塞控制

+   一、拥塞控制的一般原理
+   - 开环控制与闭环控制
+   - 开环控制
+   - 在设计网络时就考虑发生拥塞的因素考虑到，力求在网络工作时不产生拥塞
+   - 闭环控制：基于反馈的闭环，有以下几种措施：
+   - 监测网络系统是否出现拥塞在运行中，什么发生
+   - 将检测结果的信号传递给网络的某个地方的有关机构
+   - 调整网络系统的某些参数以消除或减轻拥塞
+   - RFC 2581中定义了四种拥塞控制方法
+   - 慢启动(slow-start)，又称拥塞开始
+   - 拥塞避免(congestion avoidance)
+   - 快重传(fast retransmit)
+   - 快恢复(fast recovery)
