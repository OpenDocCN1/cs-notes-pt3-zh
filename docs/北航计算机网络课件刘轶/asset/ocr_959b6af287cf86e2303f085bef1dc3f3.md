# 8.4 IEEE802.11的MAC层

+   - 以太网的CSMA/CD协议取得了巨大的成功
+   - WLAN与以太网同属IEEE802系列标准
+   - 无线网络的特点使WLAN不能简单照搬CSMA/CD：
+     - 无线网络的终端设备信道能量远小于节点信号强度，像CSMA/CD协议那样进行碰撞检测(发送地址所比较困难
+     - 无线信号覆盖范围有限，即使能够进行碰撞检测，也可能检测不到问题 → 隐藏站问题
+   - WLAN使用CSMA/CA协议
+     CSMA/CA: Carrier Sense Multiple Access / Collision Avoidance
+     - 由于无线网络的特点，难以像有线网络那样检测冲突，因此常于碰撞冲突
+     - 比CSMA/CD复杂得多

# 8.4 IEEE802.11的MAC层

+   - 802.11的MAC层提供两种服务
+     - 分布协调功能 DCF：各站点间用CSMA/CA协议竞争使用信道
+     - 点协调功能 PCF：集中控制方法，由AP一个轮询各站发送数据，避免了碰撞的发生
+   - 在实际应用中，DCF使用较多
+     - DCF需要考虑的因素：如何尽可能减少冲突

# 8.4 IEEE802.11的MAC层

+   - 802.11的载波监听机制
+     - 物理载波监听：检测信道是否有存在的有效信号
+     - 虚拟载波监听：802.11中的机制
+   - 虚拟载波监听(Virtual Carrier Sense)
+     - 发送站把它占用信道的时间放在发送帧中，其他站在收到该信息后，将不会在一段时间内发送数据 → 冲突的几率大大减少
+     - 该发送帧的MAC帧中“持续时间(Duration)”字段
+     - 本帧发送完毕后会显示出多长时间信道被占用，包括帧发送所需时间
+     - 虚拟载波监听的优点是，其它站收到有信号前，而是在收到发送站的通知后才知道信道被占用
+   - 网络分配向量 NAV (Network Allocation Vector)
+     - 当一个站检测到正在信道中发送的 MAC 帧都带的“持续时间”字段时，数据帧自己的网络分配向量 NAV (Network Allocation Vector)
+     - NAV 指出必须经过多长时间才能完成帧的这次传输，才能使信道转入到空闲状态

+   - 使用CSMA/CA的虚拟信道监听
+     - RTS/CTS机制与NAV配合使用，防止隐藏站在同一时间发送，减少冲突
+     ① A向B发送数据帧前，先发送一个RTS(请求发送请求)
+     ② 如果收到此请求，返回一个CTS(允许发送)
+     ③ A开始发送数据帧，并启动一个ACK计时器
+     ④ 收到数据帧后，返回一个ACK
+     - 如果ACK计时器超时而未收到ACK，则认为发生了冲突，后退后重新发送
+     - 如果A、B、D隐藏站，数据会先到RTS或CTS，由此更新自己的NAV
+     - 因此在收到时间内禁止发送
