
# 3.2 错误检测和纠正

## 一、检错编码(Error detecting code)

- 循环冗余校验CRC原理
- 发送方把数据段分成k位，设每帧k个比特，在其后添加n位差错检测的n位冗余码，(k+n)比特一起发送
- 对接收方M计算第n位冗余码的过程：
  - 用n位除数除2位冗余码，得到M的商，设当n位在M后面添加n个0
  - 得到(k+n)位的数值先除选定的长度为(n+1)位的数值P，得到商为Q和余数R，余数R就是P为n位，R为n-1位
  - R作为余数，构成生成多项式M'，最后发送元素：2*M - R
  - 接收方收到数据后进行校验
- 接收方对收到的(k+n)比特计算冗余码，结果为0表示传输正确，否则表示传输错误

## 例：计算101001的3位CRC冗余码

已知：M=101001 k=6, n=3 除数P=1101 101001→Q(商) P(除数)→1101 101001000→2*M(除数) 设除数P=1101 1101 1110 1111 0111 0000 被除数：2*M=101001000 模运算的结果：商Q=110101 余数R=001 1110 1101 0110 1100 1101 001←R(余数) 发送的数据：2*M+R 即：101001001，共(k+m)位

- 通常用生成多项式P(x)表示除数P
  例：除数P=1101的生成多项式P(x)=X^3+X^2+1
- 目前广泛使用的生成多项式
  CRC-16=X^16+X^15+X^5+1
  CRC-CCITT=X^16+X^12+X^5+1
  CRC-32=X^32+X^26+X^23+X^22+X^16+X^12+X^11+X^10+X^8+X^7+X^5+X^4+X^2+X+1
- 在网络中具体实现时，通常采用硬件电路生成CRC校验和(checksum)

## 二、纠错编码(Error correcting code)

- 检错码只能发现数据出现了错误，无法得知哪个比特出错
- 纠错编码通过增加冗余信息使得能够检测错误发生所在，以便于纠正，又称为向前纠错(forward error correcting)
- 关于数据链路层检错纠错的讨论
  通过检错码/纠错码可以做到无差错接收，或者说“无比特差错”
  - 并不意味着可靠传输，其他的错误包括：
    - 帧丢失、帧重复、帧失序

# 3.3 基本数据链路协议

## 一、无限制的单工协议

- 假定信道
  - 单向传输
  - 永远不会出错
  - 交付能力有界但无限
  - 接收方能够及时处理所收到的数据

```
void sender(void)
{
  frame a; //待发送帧
  packet buffer; //待发送数据包
  while (1)
  {
    from_network_layer(&buffer); //从网络层获得数据包
    a.info = buffer; //把数据包装入帧
    to_physical_layer(&a); //把帧传给物理层
  }
}
```

```
void receiver(void)
{
  frame r;
  event_type event; //等待事件
  while (1)
  {
    wait_for_event(&event); //等待帧到达
    from_physical_layer(&r); //从物理层获得帧
    to_network_layer(&r.info); //把帧交给网络层
  }
}
```

## 二、单工停等(stop-and-wait)协议

按“无限能力单工协议”，如果接收方处理帧的速度不及发送方，帧可能丢失

解决办法：增加流量控制(flow control)机制，得到单工停等协议
- 接收方每收到一帧后，都要发送一个确认帧
- 发送方每发送一帧，都要等待接收方的确认，然后才发送下一帧数据

```
void sender(void)
{
  frame s;
  packet buffer;
  event_type event;
  while (1)
  {
    from_network_layer(&buffer); //从网络层获得数据包
    s.info = buffer; //把数据包装入帧
    to_physical_layer(&s); //把帧传给物理层
    wait_for_event(&event); //等待确认帧
  }
}
```

```
void receiver(void)
{
  frame r;
  event_type event;
  while (1)
  {
    wait_for_event(&event); //等待帧到达
    from_physical_layer(&r); //从物理层获得帧
    to_network_layer(&r.info); //把帧交给网络层
    to_physical_layer(&ack); //发送确认帧
  }
}
```

## 三、有噪声信道的单工协议

在有噪声信道中，帧在传输过程中可能出错

解决办法——ARQ(Automatic Repeat reQuest)协议
- 校验和：使接收方能够检测是否出错
- 序号：使接收方知道收到的帧是否正确
- 序号：使接收方知道收到的帧是否正确
- 序号：使接收方知道收到的帧是否正确
- 序号：使接收方知道收到的帧是否正确

协议实现考虑的两个主要情形
1 数据帧可能出错
  - 接收方收到错误帧，发送方收到确认后发送下一帧
2 数据帧可能丢失
  - 数据帧可能丢失，发送方超时后重传
  - 接收方收到重复帧后丢弃
3 序号出错可能丢失
  - 发送方收到确认后重传，接收方收到后，检查序号
  - 不正确时，只返回确认

# 3.6 介质访问控制

**media**：介质、媒体  
**access**：访问、接入  
**media access control**：介质访问控制、媒体接入控制

## 一、局域网的数据链路层

- 局域网的主要特点  
  - 网络为一个单位所拥有，且地理范围和站点数目均有限

![](img/81d9dd756f10056160a08242a5d29d2c_13_1.png)

- 局域网要解决的重要问题：**介质访问控制技术（Media Access Control）**  
  - 问题缘由：局域网通常使用广播信道  
  - (1) 静态划分信道：频分复用、时分复用、波分复用、码分复用  
  - (2) 动态介质访问控制（多点访问）  
    - 随机访问：用户可随时发送信息，可能产生碰撞（冲突）  
    - 受控访问：如多点线路探询（polling），或令牌 → 局域网中使用较少

## 二、CSMA/CD 协议

- **Carrier Sense Multiple Access with Collision Detection** 载波监听多点访问/碰撞检测  
  - 注意：collision 又被译为“冲突”  
  - 是一种随机访问协议  
- CSMA/CD 的几个核心概念  
  - 载波监听（carrier sense）  
  - 碰撞检测（collision detection）  
  - 碰撞强化  
  - 碰撞退避

- 载波监听  
  - 站点在发送数据之前先检测一下总线上是否有其他结点正在发送数据，有则暂时不发送数据，以免发生碰撞 → “发送前先听”  
- 碰撞检测  
  - 站点边发送数据边检测信道上是否发生了碰撞（监听总线上传输的信号）→ “边发送边听”  
  - 由于线路的传播时延，单纯靠载波监听并不能完全避免碰撞 → 碰撞仍有可能发生  
  - 在发生碰撞时，两个或更多的信号在总线上相互叠加，导致无法识别

![](img/81d9dd756f10056160a08242a5d29d2c_13_2.png)

- 碰撞强化  
  - 发送方检测到碰撞后，立即停止发送，并发送32或48bit的人为干扰信号（jamming signal），以便让所有用户都知道已经发生了碰撞  
- 碰撞退避  
  - 碰撞后，结点等待一段时间，重新开始载波检测和发送操作  
  - 为避免退避后再次碰撞，冲突各方的等待时间应不相同  
  - 以太网采用截断二进制指数退避算法（truncated binary exponential backoff）  
    - 退避时间：$T = 2^k\tau$  
    - 倍数：在0, 1, ..., $2^k-1$中随机数，$k=\min(重传次数,10)$  
    - 重传次数超过16后，丢弃该帧，并向上层报告
