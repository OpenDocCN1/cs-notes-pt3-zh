# （二）可修改性战术（续）

将可修改性战术根据目标分类：

+   - 局部化修改：
+     - 目标：减少由某个变更直接影响的模块的数量
+   - 防止连锁：
+     - 目标：减少单个模块的互连：
+       有直接变更或间接变更的模块
+       （所依赖的模块和依赖它的模块）
+   - 逆向映射：
+     - 目标：
+       和某个模块紧密相关的模块，
+       所依赖者与被依赖者，必须被变更，
+       其实现必须直接影响到该模块）

# （二）可修改性战术（续）

+   - 局部化修改
+     - 目标：在设计时你为模块分配职责，以控制源的变更限制在一定的范围内。
+     - 设术：
+       - 维持语义的一致性：明确模块中职责的关系，
+         确保所有职责能够向上合并，不为实现依赖于低级模块。
+   - 预测期望的变更
+   - 泛化该模块
+   - 限制可能的选择

# （二）可修改性战术（续）

防止连锁反应
—修改所产生的一个连锁反应就是需要修改该修改或有直接影响到的模块。

—例如：如果实现了模块以完成某个独立的修改，就必须修改模块，标准依赖于模块。
