# 困难-中间件市场的多极化

对于一个企业，很难在（或根本不可能）在一种中间件体系结构上建立起自己的系统

+   - 历史遗留
+   - 部门分化
+   - 技术发展
+   - B2B

当初OMG的所有标准都是围绕CORBA定制的，但现在，要考虑一种支持所有中间件架构的开发方法，因此就提出了MDA。

# MDA的出现

OMG开始把眼光放到更远的地方：

+   - 希望在更高的层面上统一这兵荒马乱的局面
+   - 基于OMG非常成功的工作--UML，提出了MDA的概念。

MDA成功，还因为：

+   - 开发者们发现，在大部分应用程序的商业逻辑和支持这种逻辑的实现机制之间，存在者明显的分界线；不管采用何种实现技术，一些基本的规则是不变的 ==》 如何抽取和表示这些规则？
+   - 如果这些规则被绑定到某项具体的实现中，当技术改变时，事务处理的规则会被改变，常常被动的去适应技术，甚至“削足适履” ==》 呼唤二者的分离
