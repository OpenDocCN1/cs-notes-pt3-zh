# （一）可用性技术

+   - **[可用性]**：系统正常运行的时间比例。
+   
+     \[
+     a=\frac{mean\ time\ to\ failure}{mean\ time\ to\ failure+mean\ time\ to\ repair}
+     \]
+   - 系统不再提供与其规范一致的服务时，故障就发生了；系统的用户可以观察到故障。
+   - 错误（或错误的组合）可能会导致故障的发生。
+   - 恢复或修复是可用性的最后方面。

# （一）可用性技术（续）

+   - **可用性技术的目标：**
+     - 阻止错误演变成为故障，至少把错误限制在一定范围内，从而使修复成为可能。
+   - **维护可用性的方法：**
+     - 一束中类型的冗余，用来检测故障的某种类型的健康监视，以及监控检测到故障时恢复。
+   - 分别讨论错误检测、错误恢复、错误预防。

# （一）可用性技术（续）

+   - **错误检测：识别错误**
+     - 命令/响应（ping/echo）
+     - 心跳（dead man计时器）
+     - 异常
+       - 当识别到前面（可用性场景）所讨论的错误类中的某一个时，就出现了异常。
+       - 异常处理程序通常将错误在语义上转换为可以被处理的形式。

# （一）可用性技术（续）

+   - **错误恢复：包括准备恢复和修复系统两个部分**
+     - 表决
+     - 主动冗余（热启动）
+       - 所有的冗余组件都以并行的方式对事件做出响应，因此，它们处于相同的状态。
+       - 仅使用一个组件的响应（通常是被叫作响应的第一个组件），丢弃其余组件的响应。
+       - 错误发生时，使用最诚实的系统将执行时间道德最少一项，因为恢复时间就是初始时间。
+       - 运行时在库中切换后备配置（数据起降管理系统）。

# （一）可用性技术（续）

+   - 被动冗余（暖启动/双冗余/三冗余）
+     - 一个组件（主要的）对事件做出响应，并通知其它组件（备用的）的处理进行的状态更新。
+     - 当错误发生时，在继续提供服务前，系统必须确保备用状态是最新的。
+   - 条件
+     - 每个用设计平台配置用于更换各种不同的故障组件。
+     - 出现故障时，必须将其重新启动为适当的软件配置，并对其状态进行初始化。
+     - 该或其的保持事情通常是几分仲。

# （一）可用性技术（续）

有一些硬件组件在重新引入的修复模块、当冗余组件失效时，可以在纠正组件后将其再次引入。相关技术有：

+   - **Shadow操作：** 以前出现故障的组件可以在短时间内以“shadow模式”运行，这确保在恢复组件之前，核验工作组件的行为。
+   - **状态再同步：** 主动或被动冗余技术要求所恢复的组件在重新提供服务之前重新处于状态。重新同步方法有不同，取决于冗余组件、更新的规模以及更新所要保持的信息的数量。
+   - **检查点/回滚：** 检查点就是记录临时的一致状态，以定期进行。或者具体事件体出现故障，故障时，可检测到状态不一致时，通过使用上一个一致状态检测点和及时的事务日志来恢复系统。
