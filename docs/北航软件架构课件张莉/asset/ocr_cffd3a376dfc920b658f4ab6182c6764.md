# 可测试性（Testability）

+   - [定义] 指通过测试编使软件代表出缺陷的容易程度。
+     - 可观察性
+     - 可控制性

# 直接归属于系统的质量属性

+   - 不可通过观察系统运行确定的质量属性

| 质量属性 | 体系结构策略 |
|---|---|
| 可修改性 | 模块化、封装组件 |
| 可移植性 | 可移植性层 |
| 可复用性 | 减少组件的耦合 |
| 可集成性 | 可复用的交互机制；一致的组件接口； |
| 可测试性 | 使用关系允许渐进开发；模块化、封装组件；使用关系允许渐进开发 |

# 问题？

+   - 从设计师的角度看，以上对于系统质量属性的定义没有在下面阐述：
+     - 不可操作。如果某个系统是可修改的是没有意义的。
+     - 问题的讨论焦点并不在质量属性不清楚。如系统故障是可用性问题，还是安全性问题，还是易用性问题？

# 为了更好地描述质量属性

+   - 质量属性场景
+     - 刺激（Source of stimulus）
+       - 产生刺激的实体（人、物、计算机系统或其他致动器）
+     - 刺激（Stimulus）
+       - 到达系统并使其需要采取某些动作的条件
+     - 环境
+       - 刺激在某些条件下发生。当刺激发生时，系统可能处于运行、测试或其他状态
+     - 制品（Artifact）
+       - 受刺激的制品，可以是整个系统，也可以是系统的一部分
+     - 响应
+       - 系统对刺激后所采取的行动
+     - 响应度量
+       - 对响应发生时，应能够以某种方式对其进行度量，以对其结果进行测试

# 质量属性场景

+   - 区分：
+     - 一般质量属性场景：独立于系统，很可能适合任何系统的场景。
+     - 具体质量属性场景：描述适合正在考虑的某个特定系统的场景。
