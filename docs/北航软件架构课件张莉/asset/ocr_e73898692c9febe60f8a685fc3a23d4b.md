# 软件架构早期评审

# 评审时机

+   获得软件架构概要模型之后

# 评审目的

+   对系统满足功能和质量需求的潜在可能性做出评价

+   不是精确预测系统的行为和质量指标

+   识别软件架构的设计风险

+   对某些重要问题还没有做出决策

+   虽然对问题做出了决策但对决策的后果还不清楚

# 评审手段

+   基于提问的方法（Checklist、场景）

+   功能需求的满足可通过用例分析来实现

+   质量需求的满足可采用SAAM、ATAM等方法通过质量场景来验证
