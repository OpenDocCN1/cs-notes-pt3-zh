# 可修改性的一般场景生成

| 场景 | 可能的值 |
| --- | --- |
| 源 | 潜在用户、开发人员、管理员进程 |
| 刺激 | 在修改过程中触发的修改请求、错误信息、异常 |
| 制品 | 正在开发的产品、软件、其修改后与旧版本定义的功能或性能 |
| 环境 | 在运行中、维护中、测试中、设计时 |
| 响应 | 系统能够在不影响其正常运行的前提下进行修改 |
| 响应度量 | 根据修改所涉及元素的数量、修改的成本、努力、资源、该修改对其他可能被修改系统所造成影响的程度 |

# 4、安全性（Security）

+   - 安全性是衡量系统在合理合法用户正常提供服务的情形下，阻止企图非授权使用和抵制拒绝服务或攻击的能力。
+   - 可以把安全性制品看为一个提供“可信、机密性、完整性、保护、可验证性”的能力。
+   - 认证：交易（请求或信息被接受）不能被更多的任何一台设备或任何的成员，如通过Internet发送或被一个木马，或不能被确认。
+   - 机密性：未经授权的访问者可能获取敏感数据的风险。
+   - 完整性：被设计以提供交易数据的完整性。
+   - 保护：交易与各方涉及的各方人员的身份。
+   - 可用性：系统可用于合法使用的属性。
+   - 审计：系统在其它异常活动时的属性。

# 安全性的一般场景生成

| 场景 | 可能的值 |
| --- | --- |
| 源 | 企图破坏、窃取或破坏系统的个人或系统，它有自己的条件；除了对系统有破坏外，还可能对系统有破坏 |
| 刺激 | 企图破坏、窃取或破坏系统 |
| 制品 | 系统、系统中的数据 |
| 环境 | 系统在正常运行、系统在维护、系统在被攻击时 |
| 响应 | 系统能够检测到攻击并阻止攻击 |
| 响应度量 | 系统的响应时间、系统的可用性、系统的安全性 |


# 5、可测试性（Testability）

+   - 软件的可测试性：指通过测试揭示软件缺陷的容易程度。
+   - 通常：测试占40%的开发成本
+   - 一般说：系统在错误状态。
+   - 能“控制”内部状态和输入，能“观察”输出
