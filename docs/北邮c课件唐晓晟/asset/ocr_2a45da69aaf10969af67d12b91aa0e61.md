# 有基类的容器

+   - 常见做法是定义一个公共容器类型

```
class Container:public Object{
  // 公共容器接口
public:
  virtual Object* get();
  virtual void put(Object*);
  virtual Object* operator[](size_t);
}; // 派生类
class List:public Container{
public:
  Object* get();
  void put(Object*);
};
class Vector:public Container{
public:
  Object* operator[](size_t);
};
```

用于实现多态。
其中被继承的成员函数被
特化为具体类型而构成的非
类，对一个很复杂的单一
个容器来说是个大麻烦
(fat interface)

这样声明并不需要更复杂
的打开门户，添加了某些的
运行时间开销，却限制了可以
放入其中的类型范围，与
于标准库无相悖。

# 16.2.3 STL容器

+   - 标准库容器和迭代器(STL框架)可以认为是一种能够同时取得前而描述了这两种传统模型的优劣的途径，STL是一心一意追求真正高效的和通用的算法而编写的框架

+   - 考虑到效率因素，STL中推崇了采用以内联化的虚函数去实现小并使用频繁的访问函数

+   - 为了避免在大集合中，公共操作集中不包括那些无法有效存在所有集合中有效实现的操件

+   - 为每个容器提供自己的迭代器，并让这些迭代器都支持同一组标准的迭代器操作

# STL容器

+   - 标准容器不是从一个公共基类派生出来的，而是每个容器实现了完整的标准容器界面

+   - 也不存在公共的迭代器标准，这样，在使用标准容器或者迭代器时就不会涉及任何形式或隐式运行时间类型检查

+   - 最重要也是最困难的问题是如何为所有容器提供公共的服务。这个问题是通过模板参数化的分配器(allocator)处理，没有通过公共基类

+   - STL还深入的依赖模板机制，为避免大量的代码重复，通常需要变成专门化的方式，为保存指针的容器提供共享的实现
