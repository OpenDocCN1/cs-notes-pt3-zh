# 9.2 连接

+   - 在所有的编译单位中，对所有函数、类、模板、变量、名字空间、枚举和枚举符号的名字的使用必须保持一致
+   - 所有名字空间、类、函数等都应该在它们出现的各个编译单元中有适当的声明，而且所有声明都应该一致地出现在一个实体
+   - 如果一个名字可出现在其定义所在的编译单元不同的地方使用，就说它是有“外部连接”的，否则就称其为具有“内部连接”的

# 连接示例(1)

```
/*file1.c*/
int x = 1;
int f(){/*...*/}

/*file2.c*/
extern int x;
int f();
void g(){x=f();}

//ok
//file2.c使用了file1.c
//中x和f的定义

/*file1.c*/
int x = 1;
int b = 1;
extern int c;

/*file2.c*/
int x;
int g(){return f();}
extern double b;
extern int c;

//会导致错误
//定义了两次
//类型不一致
//只有声明，没有实现
```

# 连接示例(2)

```
//默认情况下
//const和typedef具有“内部连接”
//file1.c
  typedef int T;
  const int x=7;

//file2.c
  typedef void T;
  const int x=8;

//ok
//与每个const相同
//应该被放在文件中
//extern const int a = 77
//显式声明使const具有“外部连接”

//无名名字空间的效果很像“内部连接”
//file1.c
  namespace {
    class X{/*...*/};
    void f();
    int i;
  }
//file2.c
  class X{/*...*/};
  void f();
  int i;
//可以，但是有些麻烦
//无名空间static也具有“内部连接”
```

# 9.2.1 头文件

+   - 为达到在不同的编译单元中声明的一致性而使用的不完整但足够简单的方法，使用头文件
+   - `#include`机制是一种正文操作的概念，用于将源程序片段收集到一起
+   - `#include "to_be_included"`将用文件`to_be_included`的内容取代这行，该文件内容应该为源代码
