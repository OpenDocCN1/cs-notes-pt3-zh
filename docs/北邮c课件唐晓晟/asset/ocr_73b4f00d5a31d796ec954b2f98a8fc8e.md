# 处理器的顺序

```
void f() {
    try { 
        //... 
    }
    catch(...) {
        //处理任何其他异常
    }
    catch(std::exception& e){
        //处理所有标准异常
    }
    catch(std::bad_cast){
        //处理dynamic_cast失败
    }
}
```

如果次序安排的不
好，有些异常处理代
码将永远不会运行

左例中，bad_cast
部分将永远不被执
行，即使catch(...)
部分去掉也不行

# 14.4 资源管理

+   - 当函数请求了某种资源(打开文件或者分配空间)时，一个很重要的间题就是需要正确释放这些资源
+   - 但是如果程序在运行过程中产生了异常，就会导致程序的流程不是所希望那样，此时特别注意资源问题
+   - 异常产生时，实现会向上穿越堆栈”去为某个异常查找对应处理器，叫做“堆栈回退”，此时，会对所有局部对象调用析构函数

# 资源管理示例

```
void use_file(const char* fn) {
    FILE *f = fopen(fn,"r");
    //使用资源
    fclose(f);
}
//若在使用资源的过程中产生
了异常，则close(f)将不会被调
用，资源将被失败
```

```
void use_file(const char* fn) {
    FILE *f = open(fn,"r");
    try { //使用时
        ...
    }
    catch(...){
        fclose(f);
        throw;
    }
    fclose(f);
}
//一种解决办法，但是非常罗嗦
```
