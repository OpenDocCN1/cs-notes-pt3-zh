# 13.6 派生和模板

+   - 模板和派生都是从已有类型创建新类型的机制，通常被用于写出各种共性的代码
+   - 从一个具体类派生出一个模板类，这是为一组模板提供一个通用实现的办法，例如
+     ```cpp
+     template<class T> class Vector<T> :
+     private Vector<void>*{};
+     ```
+   - 从模板派生模板类也很有效，如果某个基类的成员依赖于派生类的模板参数，那么这个基类本身也必须参数化
+     ```cpp
+     template<class T> class vector{...};
+     template<class T> class Vec : public vector<T>
+     {...};
+     ```

# 13.6.1 参数化和继承

+   - 模板是将一个类型或者一个函数用其他的类进行参数化，该模板对于所有参数类型的代码实现都是相同的
+   - 抽象类定义了一个界面。抽象类的不同实现中的许多代码可以被该类层次结构所共享，同时，利用抽象类的大部分代码不依赖于它的具体实现
+   - 两者在于实现一次，然后被应用于多种不同类型而面非常相似，可用多态来描述之

# 参数化和继承

为了区分，将函数提供的东西作为运行时多态性（run-time polymorphism），而模板提供的多态性称为编译时多态性（compile-time polymorphism）或者参数式多态性（parametric polymorphism）

选择继承或者模板的依据：若所操作的一组对象之间不需要类型次序的关系，选择模板；若编译时无法得知这些对象的类型，选择抽象类；若对运行效率要求严格，选择模板可以格外操作方便地内联化

# 13.6.2 成员模板

+   - 一个类或者模板的成员也可以是模板
+   - 但是成员模板不能是 virtual

```
template<class Scalar> class complex{
Scalar re, im;
public:
template<class T> complex(const complex<T>& c) :
re(c.real()), im(c.imag()){}
};
complex<float> cf(0.0);
complex<double> cd = cf; // 允许，用 float//double 转换
class Quad{}
// 允许从 int 转换
};
complex<Quad> cq;
complex<int> ci = cq; // 错误，无从 Quad//int 转换
```
