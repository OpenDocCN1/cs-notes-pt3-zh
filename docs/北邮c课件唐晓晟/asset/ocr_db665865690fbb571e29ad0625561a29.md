# 14.3.1 重新抛出

+   □ 在捕捉到了一个异常之后，很多情况下，处理者并不能完成对这个错误的全部处理，典型的方式是：该处理者能够局部能够做的事 情，然后再一次抛出这个异常，这将使得错 误恢复动作分布在几个处理器里

+   □ 重新抛出用一个不带运算对象的throw语句

+   □ 重新抛出的异常就是当初捕捉到的那个异常，而不仅仅是异常处理器能够访问到的那个 部分

# 重新抛出示例

```
void h() {
    try { // 可能抛出Matherr的代码
    catch(Matherr){
        if(can_handle_it_completed){
            //处理Matherr
            return;
        }
        else{
            //完成这里做的事情
            throw;
        }
    }
}
```

# 14.3.2 捕捉所有异常

□ 对于函数，省略号"..."表示"任何参数"。同 样，catch(...)表示要捕捉所有异常

```
void m() {
    try {
        // 一些代码
    }
    catch(...) { // 处理所有异常
        // 报告工作
        throw;
    }
}
```

# 14.3.2.1 处理器的顺序

+   □ 派生异常可能被多于一个异常类型的处理器捕捉，因 此，在try语句时处理器的排列顺序非常 重要

```
void f0() {
    try{
        ...
    }
    catch(std::ios_base::failure){
        //处理标准I/O信息
    }
    catch(std::exception& e){
        //处理所有标准异常
    }
    catch(...){
        //处理在其他异常
    }
}
```
