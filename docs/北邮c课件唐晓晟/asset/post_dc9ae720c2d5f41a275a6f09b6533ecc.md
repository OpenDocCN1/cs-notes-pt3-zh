
## 9.2 连接

- 在所有的编译单位中，对所有函数、类、模板、变量、名字空间、枚举和枚举符号的名字的使用必须保持一致
- 所有名字空间、类、函数等都应该在它们出现的各个编译单元中有适当的声明，而且所有声明都应该一致地出现在一个实体
- 如果一个名字可出现在其定义所在的编译单元不同的地方使用，就说它是有“外部连接”的，否则就称其为具有“内部连接”的

### 连接示例(1)

```
/*file1.c*/
int x = 1;
int f(){/*...*/}

/*file2.c*/
extern int x;
int f();
void g(){x=f();}

//ok
//file2.c使用了file1.c
//中x和f的定义

/*file1.c*/
int x = 1;
int b = 1;
extern int c;

/*file2.c*/
int x;
int g(){return f();}
extern double b;
extern int c;

//会导致错误
//定义了两次
//类型不一致
//只有声明，没有实现
```

### 连接示例(2)

//默认情况下
//const和typedef具有“内部连接”
//file1.c
  typedef int T;
  const int x=7;

//file2.c
  typedef void T;
  const int x=8;

//ok
//与每个const相同
//应该被放在文件中
//extern const int a = 77
//显式声明使const具有“外部连接”

//无名名字空间的效果很像“内部连接”
//file1.c
  namespace {
    class X{/*...*/};
    void f();
    int i;
  }
//file2.c
  class X{/*...*/};
  void f();
  int i;
//可以，但是有些麻烦
//无名空间static也具有“内部连接”

## 9.2.1 头文件

- 为达到在不同的编译单元中声明的一致性而使用的不完整但足够简单的方法，使用头文件
- `#include`机制是一种正文操作的概念，用于将源程序片段收集到一起
- `#include "to_be_included"`将用文件`to_be_included`的内容取代这行，该文件内容应该为源代码

### 头文件示例

```
#include <iostream>
// 来自标准库包含其
#include "myheader.h"
// 来自当前目录
```

```
#include <iostream>
// <>或""中的空格也是
// 有意义的
```

头文件上
头文件采用后缀.h，而包含函数或数据定义的文件又用.c后缀。
其他约定：比如 .C、.cc、.cpp文件常常可以看见

// 头文件通常会，有时候
// 要避免重复包含。不让头
// 文件中重复声明，没有
// 要避免详细深入分析
// 的代码。此外，提供
// C++ 实现能够提供头文件
// 之前的预编译形式

### 头文件中可以包括

|  |  |
|---|---|
| 命名空间声明 | namespace N{...}; |
| 结构定义 | struct Point {int x,y;}; |
| 模板声明 | template <class T> class Z; |
| 模板定义 | template <class T> class V{...} |
| 函数声明 | extern int strlen(const char*); |
| 数据定义 | const int a; |
| 静态定义 | const int a = 10; |
| 名字空间 | class Matrix; |
| 包含指令 | #include <algorithm> |
| 条件编译 | #ifdef __cplusplus |
| 注释 | // check for end of file */ |
| 宏定义 | #define VERSION 12 |

### 头文件中绝对不可以包括

|  |  |
|---|---|
| 常规的函数定义 | char get(char *p){return *p++;} |
| 变量定义 | int a; |
| 聚合量(aggregate)定义 | short tbl[] = {1,2,3}; |
|  |  |
| 名字空间声明 | namespace {...} |
| 特殊的(exported)模板定义 | export template <class T> {T t(...)} |

## 9.2.2 标准库中的头文件

- 标准库的功能是通过一组标准头文件给出的
- 标准库中的头文件不需要后缀，但并不意味着这些头文件采用了某种特殊的存储方式

- 使用标准库中的头文件需要用#include <...> 而不是#include "..."

- 相对于每一个C标准库文件<X.h>，存在着一个与之对应的标准C++头文件<cX>，例如#include <stdio.h>和#include <cstdio>

### 标准库中的头文件示例

```
#ifndef __cplusplus
// 如果是 C++ 程序
namespace std {
  extern "C" {
  // 见 9.2.4
#endif
/* ...... */
int printf(const char* ...);
#endif __cplusplus
}
using namespace std;
#endif
```

左边代码每一块具体的
实际内部都是相同的，但
是有相同名字同时需要
为不同语言，以此把 C++
能与其它头文件
<stdio.h> 在起来的样子

## 9.2.3 单一定义规则

在一个程序里，任一个类、枚举和模板等都必须只定义唯一的一次。这种规则需要以一种复杂和精细的方式来描述，被称为“单一定义规则(One-Definition Rule, ODR)

- 也就是说，一个类、模板或其内联函数 的两个定义能够被接受为同一个唯一定义的实例，当且仅当
- 它们出现在不同的编译单位里
- 它拥有一个相同的对照相同
- 这些条件的意义在两个编译单位中也完全一样

### 单一定义规则(ODR)示例

```
//file1.h
struct S {int a; char b;};
void f(S*);

//file2.c
struct S {int a; char b;};
void f(S*) { /*...*/ }

// ok
// 两个不同的文件都声明了两次
// 重点是
// 堆指针 file2.c 人们不想要得到 S
// 在不同文件被声明了两次
// 或者认为可以自由地修改它
```

```
//s.h
struct S {int a; char b;};
void f(S*);

//file1.c
#include "s.h"

//file2.c
#include "s.h"
void f(S* p) { /*...*/ }
// 基于 ODR 的设计
```

### 单一定义规则的错误示例

```
//file1.h
struct S {int a; char b;};
//file1.c
struct S {int a; char b;};
// Error 重复定义

//file2.h
struct S2 {int a; char b;};
//file2.c
class Point { /*...*/ };
// Error 成员不匹配

//file1.c
typedef int X;
struct S3 {X a; char b;};
//file2.c
typedef def char X;
struct S3 {X a; char b;};
// Error X 的含义被改变了
```

//s.h
struct S {int a; char b;};
//file1.c
#define Point int
#include "s.h"
//...
//file2.c
#include "s.h"
class Point { /*...*/ };
//...
// 假如上面是正确的
// 可能会导致编译器通过
// #include 包含来同时的含义
// 导致在不同的编译单位中
// 比如，在 s.h 中定义 X Point

## 9.2.4 与非C++代码的连接

- 一个C++程序可能由多个部分组成，这些部分不一定都使用C++语言编写
- 不同语言写出的程序片段，或者是同一种语言，但是由不同的编译器编译的片段之间的协作比较困难，为了能让C++使用，可以在extern声明中给出有关其连接约定
- 这种声明能够提醒编译器应该如何去连接这片代码（例如：寄存器使用方式、参数传入的顺序、整数等内部类型的布局）

### 与非C++代码的连接示例(1)

extern "C" 提供给其他一种连接约定。非显式声明的函数，例如声明为extern "C"时函数仍遵循C++的类规则和参数传递规则，而不是C的规则

```
extern "C" char* strcpy(char*, const char*);
// 与 extern char* strcpy(char*, const char*);
// 的区别在于这里没有定义
```

```
extern "C" int f();

extern g() { return f(); } // Error f()函数没有参数
```

```
extern "C" {
    char* strcpy(char*, const char*);
    int strncmp(const char*, const char*);
} // 这对符号的连接约定为块
```

### 与非C++代码的连接示例(2)

```
extern "C" {
#include <string.h>
}

// ||extern "C"将整个文件包起来来
// 以使所有文件能被C++使用

#ifdef __cplusplus
extern "C" {
#endif
char* strcpy(char*, const char*);
int strncmp(const char*, const char*);
#ifdef __cplusplus
}
#endif
#endif // __cplusplus是一个预定义名

## 9.2.5 连接与指向函数的指针

- 当一个程序中混合使用C和C++代码片段时，有时会希望把在一个语言里定义的函数指针传递到另一个语言中定义的函数里
- 在这种情况下，注意不同语言之间的连接约定是否一致
