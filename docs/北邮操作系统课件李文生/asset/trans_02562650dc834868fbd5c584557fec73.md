## 决策模式

- **非抢占式（Nonpreemptive）**
  - 一旦进程进入运行状态，它将持续运行直到终止或自我阻塞等待I/O
- **抢占式（Preemptive）**
  - 当前运行的进程可能被操作系统中断并移入就绪状态
  - 由于任何进程都不能长期垄断（独占）处理器，因此可以提供更好的服务

## 分派器（Dispatcher）

- ▪ 分派器模块将CPU的控制权交给短期调度器选中的进程；这包括：
  - 切换上下文
  - 切换到用户模式
  - 跳转到用户程序中的适当位置，以重新启动该程序

- ▪ *分派延迟（Dispatch latency）*——分派器停止一个进程并启动另一个进程运行所需的时间。

## 调度准则的分类

- 面向用户
  - 响应时间
    - 从提交请求到产生输出之间的时间
- 面向系统
  - 处理器的有效且高效的利用
- 与性能相关
  - 定量（Quantitative）
  - 可测量，如响应时间和吞吐量
- 与性能无关
  - 定性（Qualitative）
  - 可预测性

## 补充：

## 调度准则的分类

|  | 与性能相关 | 与性能无关 |
|---|---|---|
| **面向用户** | 周转时间<br>响应时间 | 可预测性<br>截止时间 |
| **面向系统** | 吞吐量<br>CPU利用率 | 公平性<br>强制优先级<br>资源平衡 |

## 优化准则

- CPU利用率 → **最大化**
- 吞吐量 → **最大化**
- 周转时间 → **最小化**
- 等待时间 → **最小化**
- 响应时间 → **最小化**

## 5.3.1 先来先服务（FCFS）调度

- 每个进程加入就绪队列
- 当当前进程停止执行时，选择就绪队列中最早的进程
- FCFS调度算法是非抢占式的。

| 进程 | 突发时间 |
|---|---:|
| P₁ | 24 |
| P₂ | 3 |
| P₃ | 3 |

- 假设进程按顺序到达：P₁、P₂、P₃
- 调度的甘特图如下：

![](img/9321d6c42b8369e67ceb1f1d7e27b09c_323_0.png)

- P₁ 的等待时间 = 0；P₂ = 24；P₃ = 27
- 平均等待时间：(0 + 24 + 27)/3 = 17

## FCFS调度（续）

假设进程按顺序到达
\[P_2, P_3, P_1.\]

调度的甘特图如下：

| $P_2$ | $P_3$ | $P_1$ |
|---|---|---|
| 0 | 3 | 6 | 30 |

- $P_1$ 的等待时间 = 6；$P_2 = 0$；$P_3 = 3$
- 平均等待时间：$(6 + 0 + 3)/3 = 3$
- 比前一种情况好得多。
- 短进程可能需要等待非常长的时间才能执行
- 有利于CPU密集型进程
  - I/O进程必须等待CPU密集型进程完成
- **护航效应（Convoy effect）：**短进程排在长进程后面
