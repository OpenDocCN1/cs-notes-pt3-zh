

## 页面置换算法

- **置放策略**
  - 替换哪一页？
  - 被移除的页面应是近期最不可能被引用的页面
  - 大多数策略都基于过去的行为来预测未来的行为

- **希望获得最低的缺页率**

- 通过在特定的内存引用字符串（*reference string*）上运行算法并计算该字符串上的缺页次数来评估算法。

- 我们可以人工生成引用字符串（通过随机数生成器），也可以追踪给定系统并记录每次内存引用的地址。

- 在我们的所有示例中，引用字符串为
  - 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1
  - 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5

## FIFO（先进先出）算法

- 为每个页面关联该页面被调入内存的时间。
- 当必须替换页面时，选择最旧的页面。
- 示例
  - 3 个帧（每个进程一次最多可有 3 页在内存中）

![](img/9321d6c42b8369e67ceb1f1d7e27b09c_638_0.png)

- 将分配给进程的帧视为循环缓冲区
- 页面以轮询方式移除
- 这些页面可能很快又会被需要

## 最优算法

- 替换未来最长时间内不会被使用的页面。

- 3 个帧示例

![](img/9321d6c42b8369e67ceb1f1d7e27b09c_639_0.png)

- 仅有 9 次缺页

- OPT 比 FIFO 算法好得多。

## 最近最少使用（LRU）算法

- 替换最长时间未被使用的页面。
- 根据局部性原理，这应是最不可能在近期被引用的页面
- 为每个页面关联该页面的最后使用时间。这需要大量的开销。

## LRU 实现

### 计数器

- 每个页面条目都有一个计数器；每次通过该条目引用页面时，将时钟复制到计数器中。
- 当需要替换页面时，查看计数器以确定要替换哪些页面。

## LRU 实现

- 栈 – 以双向链表形式维护一个页面号栈：
  - 页面被引用：
    - 将其移至顶部
    - 需要更改 6 个指针
  - 无需搜索替换对象

- 示例：4 7 0 7 1 0 1 2 1 2 7 1 2

## LRU 近似算法

### 引用位算法

- 为每个页面关联一个位，初始为 = 0。
- 当页面被引用时，该位置为 1。
- 替换为 0 的页面（如果存在）。
- **问题：** 我们不知道顺序。

## LRU 近似算法

### 附加引用位算法

- 为内存中的每个页面在表中保留一个 8 位字节。
- 在固定间隔，定时器中断，操作系统将每个页面的引用位移入其 8 位字节的高位，将其他位右移 1 位并丢弃低位
- 这些 8 位字节包含最近 8 个时间段的页面使用历史。
- 数字最小的页面是 LRU 页面，可以被替换。
