## 标准 API 示例

- 考虑 Win32 API 中的 ReadFile() 函数——一个用于从文件读取数据的函数

```
return value
↓
BOOL  ReadFile  (HANDLE      file,
                  LPVOID      buffer,
                  DWORD       bytes To Read,
                  LPDWORD     bytes Read,
                  LPOVERLAPPED ovl);
↑
function name
parameters
```

- 对传递给 ReadFile() 的参数说明

  - HANDLE file——要读取的文件
  - LPVOID buffer——数据将被读入和写出的缓冲区
  - DWORD bytesToRead——要读入缓冲区的字节数
  - LPDWORD bytesRead——上一次读取期间读取的字节数
  - LPOVERLAPPED ovl——指示是否正在使用重叠 I/O

## 系统调用参数传递

- 通常，所需的信息不仅仅是所需系统调用的标识
  - 信息的确切类型和数量因操作系统和调用而异
- 向操作系统传递参数有三种常用方法
  - 最简单：将参数放在*寄存器*中
    - 某些情况下，参数可能比寄存器还多
  - 参数存储在内存中的*块*或表中，并将块的地址作为参数通过寄存器传递
    - 这种方法被 Linux 和 Solaris 采用
  - 参数由程序放置或*推入*到*栈*中，并由操作系统从栈中*弹出*
  - （块和栈的方法不限制所传递参数的数量或长度）

## 2.4 系统调用的类型

- 进程控制
- 文件管理
- 设备管理
- 信息维护
- 通信

## 进程控制

- 结束、中止
- 加载、执行
- 创建进程、终止进程
- 获取进程属性、设置进程属性
- 等待时间
- 等待事件、信号事件
- 分配和释放内存

## 设备管理

- 请求设备、释放设备
- 读、写、重新定位
- 获取设备属性、设置设备属性
- 逻辑上附加或分离设备

## 信息维护

- 获取时间或日期、设置时间或日期
- 获取系统数据、设置系统数据
- 获取进程、文件或设备属性
- 设置进程、文件或设备属性

## 通信

- 创建、删除通信连接
- 发送、接收消息
- 传输状态信息
- 附加或分离远程设备
- 两种常见的通信模型
  - **消息传递模型**：信息通过操作系统提供的进程间通信设施（IPC）进行交换。
  - **共享内存模型**：进程使用映射内存系统调用获取对其他进程所拥有的内存区域的访问权限。
