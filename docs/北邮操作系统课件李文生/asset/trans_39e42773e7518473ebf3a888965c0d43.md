## Effective Access Time

- 关联查找 = ε 微秒
- 假设内存周期时间为 τ 微秒
- **命中率** – 页号在关联寄存器中找到的次数百分比；比率与关联寄存器数量相关。
- 命中率 = α
- **有效访问时间 (EAT)**

  EAT = (ε + τ) α + (ε + 2τ)(1 − α)

  = 2τ + ε − τα

- ε=20ns, α=0.8, τ=100ns  EAT=140ns
- ε=20ns, α=0.98, τ=100ns  EAT=122ns

## Memory Protection

- 内存保护通过为每个帧关联保护位来实现。
- 通常这些位保存在页表中。
- **R/W** 位，可以将页面定义为读写或只读。
- *有效-无效* 位附加到页表中的每个条目：
  - “**有效**” 表示相关页面在进程的逻辑地址空间中，因此是合法页面。
  - “**无效**” 表示页面不在进程的逻辑地址空间中。

## Shared Pages

- **共享代码**
  - 一个只读 (**可重入**) 代码的副本在进程之间共享（即文本编辑器、编译器、窗口系统）。
  - 共享代码必须在所有进程的逻辑地址空间中出现在相同的位置。
- **私有代码和数据**
  - 每个进程保留代码和数据的单独副本。
  - 私有代码和数据的页面可以在逻辑地址空间中的任何位置出现。

### Hierarchical Page Tables

- 一个逻辑地址（在 32 位机器上，页面大小为 4KB）被划分为：
  - 由 20 位组成的页号。
  - 由 12 位组成的页偏移。
- 将逻辑地址空间分解为多个页表。
- 一个简单技术是两级页表。
  - 页表本身也被分页
- 由于页表被分页，页号进一步划分为：
  - 10 位页号。
  - 10 位页偏移。

### Two-Level Paging Example

因此，一个逻辑地址如下：

| page number | page offset |
| --- | --- |
| $p_1$ + $p_2$ | $d$ |
| 10 + 10 | 12 |

其中

$p_1$ 是外部页表的索引，且

$p_2$ 是外部页表页面内的位移。

### Hashed Page Tables

- 常见于地址空间 > 32 位。
- 哈希表中的每个条目包含一个链接列表，其中元素被哈希到同一位置。
- 每个元素由三个字段组成：
  - (a) 虚拟页号
  - (b) 映射页帧的值（帧号）
  - (c) 指向链接列表中下一个元素的指针
- 虚拟页号被哈希到哈希表。
- 虚拟页号与该链中字段 (a) 进行比较，搜索匹配项。如果找到匹配项，则提取相应的物理帧。
