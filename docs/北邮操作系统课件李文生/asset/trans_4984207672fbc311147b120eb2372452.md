

## 6.5 信号量

- 一种不需要忙等待的同步工具。
- 特殊变量，信号量 $S$ —— 整型变量
- 只能通过两个不可分割（原子）操作访问

```
wait (S):
    while S ≤ 0 ;    // 不执行任何操作
    S--;

signal (S):
    S++;
```

- 等待和信号操作不能被中断。
- 信号量是一个具有整数值的变量
  - 可以初始化为非负数
  - 等待操作递减信号量的值
  - 信号操作递增信号量的值

## 用法

n 个进程的临界区

- 共享数据：
  semaphore mutex; // 初始时 mutex = 1

- 进程 Pi：
  do {
    wait(mutex);
    临界区
    signal(mutex);
    剩余区
  } while (1);

```
wait (S):
  while S ≤ 0 ;
  S--;
signal (S):
  S++;
```

共享数据：
Semaphore synch; // 0

P1:
  S1;
  signal(synch);
P2:
  wait(synch);
  S2;

## 信号量的实现

- 将信号量定义为一个记录
  ```c
  typedef struct {
    int value;
    struct process *List;
  } semaphore;
  ```

- 假设两个简单的操作：
  - Block() 挂起调用它的进程。
  - wakeup(P) 恢复被阻塞进程 P 的执行。

## 信号量的临界区问题

- **单处理器环境**
  - 在执行等待和信号操作期间禁止中断。
- **多处理器环境**
  - 禁止中断不起作用。
  - 特殊的硬件指令
  - 针对临界区问题的软件解决方案，其中临界区由等待和信号过程组成。
- **忙等待问题**
  - 已经从应用程序进入临界区的部分消除了忙等待。
  - 将忙等待限制在等待和信号操作的临界区内，这些区段很短。

## 问题：死锁与饥饿

- **死锁** —— 两个或多个进程无限期等待一个只能由其中一个等待进程引发的事件。

设 S 和 Q 为两个初始化为 1 的信号量

```
P₀                 P₁
wait (S);          wait (Q);
wait (Q);          wait (S);

…                  …

signal (Q);        signal (S);
signal (S);        signal (Q);
```

```
P₀: wait (S);
P₁: wait (Q);
P₀: wait (Q);
P₁: wait (S);
```

- **饥饿** —— 无限期阻塞。一个进程可能永远无法从它被挂起的信号量队列中移除。（LIFO 队列）

## 补充：两种类型的信号量

- **二进制**信号量 —— 整数值只能在 0 和 1 之间变化；实现简单。
- **计数**信号量 —— 整数值可以在无限制的域内变化。
- 计数信号量 S 可以通过使用二进制信号量来实现。
  - 数据结构：
    binary-semaphore S1, S2;
    int C;
  - 初始化：
    S1 = 1
    S2 = 0
    C = 信号量 S 的初始值

## 补充：
### 使用二进制信号量实现 S

### Wait(S) 操作

```
wait (S1);
C--;
if (C < 0) {
    signal (S1);
    wait (S2)
}
else
    signal (S1);
```

### Signal(S) 操作

```
wait (S1);
C ++;
if (C <= 0)
    signal(S2);
signal(S1);
```

## 读者-写者问题

- 读者：只读取共享对象的内容。
- 写者：可以更新共享对象的内容。
- 写者对共享对象拥有排他访问权。
- 第一个读者-写者问题：读者优先
  - 除非写者已经获得使用共享对象的许可，否则不会让读者等待。
  - 写者可能会饥饿。
- 第二个读者-写者问题：写者优先
  - 一旦写者准备就绪，该写者将尽快执行写入操作。
  - 读者可能会饥饿。
