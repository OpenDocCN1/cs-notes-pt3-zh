

## 2.7.2 分层方法

- 操作系统被划分为若干层（级别），每一层都建立在较低层之上。最底层（第 0 层）是硬件；最高层（第 N 层）是用户界面。
- 操作系统层是对抽象对象的实现，该抽象对象是对数据的封装，以及可以操作这些数据的操作。
- 通过模块化，各层被选择为每一层仅使用较低层的功能（或操作）和服务。

### 补充：总结 — 分层系统结构

- 将系统视为一系列级别
- 每个级别执行相关的功能子集
- 每个级别依赖于下一较低级别来执行更原始的功能
- 这将问题分解为若干更易管理的子问题

## 2.7.3 微内核

- 将尽可能多的内容从内核移至“*用户*”空间。
  - 小型操作系统核心
  - 仅包含基本的操作系统功能
    - 地址空间
    - 进程间通信（IPC）
    - 基础调度
- 传统上包含在操作系统中的许多服务现在是外部子系统
  - 设备驱动程序
  - 文件系统
  - 虚拟内存管理器
  - 窗口系统
  - 安全服务

- 微内核的主要功能是为客户端程序与在用户空间运行的各种服务之间提供通信设施。
- 通信通过消息传递在用户模块之间进行。

### 微内核组织的优点

- **进程请求上的统一接口**
  - 所有服务均通过消息传递提供
- **可扩展性**
  - 允许添加新服务
- **灵活性**
  - 添加新功能
  - 可以减去现有功能
- **可移植性**
  - 将系统移植到新处理器所需的更改在微内核中进行，而非在其他服务中
- **可靠性**
  - 模块化设计
  - 小型微内核可以严格测试
- **分布式系统支持**
  - 发送消息时无需知道目标机器是什么
- **面向对象的操作系统**
  - 组件是具有明确定义接口的对象，可以相互连接形成软件
- **弊端：**
  - 用户空间到内核空间通信的性能开销

## 2.7.4 模块

- 大多数现代操作系统实现内核模块
  - 使用面向对象的方法
  - 每个核心组件都是独立的
  - 每个组件通过已知接口相互通信
  - 每个组件可根据需要在内核中加载
- 总体上与分层类似，但灵活性更高

## 2.8 虚拟机（VM）

- *虚拟机*将分层方法推向逻辑的极致。它将硬件和操作系统内核视为硬件。
- 虚拟机提供与底层裸硬件*相同*的接口。
- 操作系统创造出多个进程的幻觉，每个进程都在其自己的处理器上执行，并拥有其自己的（虚拟）内存。
  - 通过 CPU 调度
  - 通过虚拟内存
