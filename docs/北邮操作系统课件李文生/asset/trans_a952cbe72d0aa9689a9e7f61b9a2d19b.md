

## 9.2 按需分页

- 仅在需要时才将页面调入内存。
- 按需分页的好处
  - 所需 I/O 更少
  - 所需内存更少
  - 响应更快
  - 用户更多
- 需要页面 ⇒ 对其引用
  - 无效引用 ⇒ 终止
  - 不在内存中 ⇒ 将其调入内存
- 惰性交换程序 – 除非页面将被需要，否则绝不将其交换到内存中
  - 处理页面的交换程序是分页程序

## 缺页

- 如果有对页面的引用，第一次引用将陷阱到操作系统 ⇒ 缺页
- 操作系统查看另一个内部表来决定：
  - 无效引用 ⇒ 终止。
  - 只是不在内存中。
- 获取空闲帧。
- 将页面交换到帧中。
- 重置表，有效位 = 1。
- 重新启动指令

## 如果没有空闲帧会怎样？

- 页面置换 – 找到内存中某个页面，但实际上未使用，将其交换出去。
  - 算法
  - 性能 – 希望算法能导致缺页次数最少。
- 相同的页面可能被多次调入内存。

## 按需分页的性能

- 缺页率 0 ≤ p ≤ 1.0
  - 如果 p = 0，则无缺页
  - 如果 p = 1，则每次引用都是缺页

- 有效访问时间（EAT）
  EAT = (1−p) × memory access time
  + p × page fault service time
  page fault service time = page fault overhead
  + [ swap page out ]
  + swap page in
  + restart overhead

## 按需分页示例

- 内存访问时间 = 200 纳秒

- 平均缺页服务时间 ≈ 8 毫秒
  - 处理缺页中断并重新启动进程可能减少到数百条指令，每条可能需要 1 到 100 微秒。
  - 页面切换时间可能接近 8 毫秒
    - 硬盘的平均延迟为 3 毫秒；
    - 硬盘的寻道时间为 5 毫秒；
    - 传输时间为 0.05 毫秒。

## 9.3 写时复制—进程创建

- 写时复制（COW）允许父进程和子进程最初 *共享* 内存中的同一页面

如果任一进程修改了共享页面，则仅在此时才复制该页面。

- COW 允许更高效的进程创建，因为只有被修改的页面才会被复制。 （参见 P.326 Figure9.7-9.8）

- 空闲页面从 *pool* 的零页中分配。

## 基本页面置换

- **找到磁盘上所需页面的位置。**
- **找到空闲帧：**
  - 如果有空闲帧，则使用它。
  - 如果没有空闲帧，则使用页面置换算法选择一个 *victim* 帧。
  - 将受害者帧写入磁盘；相应地更改页面和帧表。
- **将所需页面读入（新）空闲帧。** 更新页面和帧表。
- **重新启动用户进程。**
