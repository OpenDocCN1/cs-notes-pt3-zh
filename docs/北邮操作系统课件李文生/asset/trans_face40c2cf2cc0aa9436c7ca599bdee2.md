## 通信模型 (2/2)

- **消息传递**在需要交换的数据量较小时很有用，因为无需避免冲突。
- 对于计算机间通信，消息传递更容易实现。
- **共享内存可以实现最大速度和通信便利性。**
  - 在计算机内部，它可以以内存速度进行。

## 3.4.1 共享内存系统

### 生产者-消费者问题

- 协作进程的一种常见范式：*生产者*进程产生信息，由*消费者*进程消费。
- 我们必须有一个缓冲区，其中的项目可以由*生产者*填充，并由*消费者*清空。
  - *生产者*可以在*消费者*消费另一个项目的同时产生一个项目。
  - *生产者*和*消费者*必须**同步**。
- 使用了两种类型的缓冲区：
  - *无界缓冲区*对缓冲区的大小没有实际限制。
  - *有界缓冲区*假定缓冲区大小固定。

## 有界缓冲区问题的共享内存解决方案

### 共享数据

```
#define BUFFER_SIZE 10
typedef struct {
...
} item;
item buffer[BUFFER_SIZE];
int in = 0;
int out = 0;
```

- **in** 指向缓冲区中下一个空闲位置；
- **out** 指向缓冲区中第一个已满位置；
- 当 **in == out** 时缓冲区为空；
- 当 **((in + 1) % BUFFER_SIZE) == out** 时缓冲区已满；
- 该解决方案是正确的，但只能使用 **BUFFER_SIZE-1** 个元素。

## 共享缓冲区——环形数组

- 当 `in == out;` 时缓冲区为空；

解决方案是正确的，但只能使用 BUFFER_SIZE-1 个元素。

### 有界缓冲区——*生产者进程*

```
item nextProduced;
while (1) {    /* produce an item in nextProduced */
              while (((in + 1) % BUFFER_SIZE) == out)
                    ; /* do nothing */
              buffer[in] = nextProduced;
              in = (in + 1) % BUFFER_SIZE;
            }
```

### 有界缓冲区——*消费者进程*

```
item nextConsumed;
while (1) {  while (in == out) ; /* do nothing */
              nextConsumed = buffer[out];
              out = (out + 1) % BUFFER_SIZE;
              /* consume the item in nextConsumed */
            }
```

## 直接通信——命名

- **进程必须显式地相互命名：**
  - `send(P, message)` – 向进程 P 发送消息
  - `receive(Q, message)` – 从进程 Q 接收消息
- **通信链路的属性**
  - 链路自动建立。
  - 一条链路恰好关联一对通信进程。
  - 每对进程之间恰好存在一条链路。
  - 链路可以是单向的，但通常是双向的。
- **缺点**
  - 所生成的进程定义的模块化程度有限

## 间接通信（1/3）

- 消息通过邮箱（也称为端口）发送和接收。
  - 每个邮箱都有唯一的 id。
  - 进程只有在共享邮箱时才能通信。
- 原语定义如下：
  - `send(A, message)` – 向邮箱 A 发送消息
  - `receive(A, message)` – 从邮箱 A 接收消息
- 通信链路的属性
  - 只有当进程共享一个公共邮箱时，才会建立链路。
  - 一条链路可以关联多个进程。
  - 每对进程可以共享多条通信链路。
  - 链路可以是单向的或双向的。
