

## Amazon SimpleDB

Amazon SimpleDB 是一种 Web 服务，提供云中数据索引和查询的核心数据库功能。

- **传统关系型数据库**
  - 需要大量的前期资本投入
  - 设计复杂
  - 通常需要大量且重复的数据库管理

- **Amazon SimpleDB**
  - 极其简单，提供简单的存储和访问 API。
  - 无需模式，自动索引您的数据。
  - 消除了数据建模、索引维护和性能调优的管理负担。

### SimpleDB 优点

- 简单
- 灵活（无模式）
- 可扩展 - 随着以下情况创建新域
  - 您的数据增长
  - 请求吞吐量增加
- 可靠
- 价格低廉

### SimpleDB 缺点

- 数据完整性无法保证。
- 不一致。
- 聚合操作需要更多编码且会慢得多。
- 复杂的报表和 *ad hoc* 查询需要 *a lot* 更多编码。
- 不支持复杂的数据模式。

### Amazon 基础设施服务的应用

- 快速构建 Web 应用的方式
  - EC2 – 应用逻辑
  - S3 – 非结构化数据存储
  - SimpleDB – 结构化数据存储
  - SQS – 消息传递

## Google Bigtable

### 动机

- Google 拥有大量（半）结构化数据
  - URL：
    - 内容、抓取元数据、链接、锚点、pagerank，...
  - 每用户数据：
    - 用户偏好设置、最近查询/搜索结果、...
  - 地理位置：
    - 物理实体（商店、餐馆等）、道路、卫星图像数据、用户注释、...
- 规模很大
  - 数十亿个 URL，每个页面多个版本（~20K/版本）
  - 数亿用户，每秒数千次查询
  - 100TB+ 卫星图像数据
  - 450,000 台机器（《纽约时报》估计，2006 年 6 月 14 日）

### 构建块

- Google 文件系统 (SOSP’03)
- MapReduce (OSDI’04)
- Chubby 锁服务 (OSDI’06)
- BigTable (OSDI’06)

### 为什么不直接使用商业数据库？

- 规模对于大多数商业数据库来说过大
- 即使不是，成本也会非常高
  - 内部构建意味着系统可以以低增量成本应用于多个项目
- 低级存储优化对性能有显著帮助
  - 在数据库层之上运行要实现起来困难得多

*为 Google 员工构建大规模系统也很有趣且具有挑战性☺*

### 数据模型：一个大地图

- <Row, Column, Timestamp> 三元组作为键 - 查找、插入和删除 API
- 按行任意“列”
  - 列族：限定符。族是重量级的，限定符是轻量级的
  - 列式物理存储 - 行是稀疏的！
- 不支持关系模型
  - 无表级完整性约束
  - 无多行事务

### API

- 元数据操作
  - 创建/删除表、列族、更改元数据
- 写入（原子）
  - Set(): 写入行中的单元格
  - DeleteCells(): 删除行中的单元格
  - DeleteRow(): 删除行中的所有单元格
- 读取
  - Scanner: 读取 Bigtable 中的任意单元格
    - 每次行读取都是原子的
    - 可以将返回的行限制为特定范围
    - 可以请求仅 1 行的数据、所有行等。
    - 可以请求所有列、仅特定列族或特定列
