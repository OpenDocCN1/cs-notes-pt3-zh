

## 4.2.3 Oracle 数据库监控实例

### 使用 V$ 表监控实例结构

DBA 可以使用许多动态性能视图显示实例的信息。这些视图对于发现当前数据库实例的状态以及与实例相关的故障问题具有很大价值。

### 1. 监控数据库的连接

所有连接到实例的用户和后台进程都可以使用 V$ 视图进行监控。

V$PROCESS 视图显示所有连接到数据库的进程信息，包括后台进程和用户进程；

V$BGPROCESS 包含所有可能的后台进程列表，以及一个附加的 PADDR 列。PADDR 列包含后台运行进程的十六进制地址；

V$SESSION 视图包括连接到数据库的用户会话信息。

V$MTS 视图包含共享服务器进程的跟踪信息。该视图包含最大连接数、服务器启动数、服务器中止数以及服务器最高水位等列。

### 2. 监控共享 SQL 区

V$SQLAREA 视图包含共享 SQL 区中的 SQL 语句信息，包括已执行 SQL 语句的文本、访问该语句的用户数、执行语句时访问的磁盘块数和内存块数，以及其他信息。在 V$SQLAREA 中，disk_reads 和 buffer_gets 列分别跟踪从磁盘读入的块数和从缓冲区读入的块数。

V$OPEN_CURSOR 视图可以找出尚未关闭的游标。

### 3. 监控系统全局区

V$SGA 视图显示每个 SGA 主要组成部分的大小（以字节为单位），包括重做日志缓冲区、数据库缓冲区高速缓存和共享池。V$SGASTAT 视图包括更多相关信息。在该视图中，可以查找系统全局区中每个独立内存结构的大小，包括为堆栈空间、PL/SQL 变量和堆预留的内存。也可以查询该视图，找出 SGA 区中可用的空闲内存总量。

### 4. 监控库缓存和字典缓存

V$LIBRARYCACHE 视图包含库缓存中每种类型对象的性能信息；V$ROWCACHE 视图包含数据字典缓存的性能信息。

### 5. 监控并行查询进程

查询 V$PQ_SYSSTAT 视图可以显示并行查询服务器的当前运行信息，例如忙碌和空闲查询服务器的数量，以及动态创建和终止服务器的统计数据。V$PQ_TQSTAT 视图包含以前使用并行查询服务器运行的查询信息。

### 6. 监控归档进程

归档进程活动信息存储在 V$ARCHIVE 视图中。可以从该视图查询由 ARCH 进程写入的归档日志信息。

## 4.3 Oracle 数据库存取管理

数据库管理员的任务是使所有运行 Oracle 数据库的系统能够高效工作。数据库管理员为每个用户提供技术支持，并且应当对 Oracle 软件中出现的所有问题都非常熟悉。除上一节介绍的 Oracle 实例设置外，Oracle 数据库的存储也会对数据库性能产生很大影响。此外，Oracle 的安全性、备份与恢复机制也将在本节中介绍。

### 4.3.1.1 管理 Oracle 数据库对象

#### 管理 Oracle 块

Oracle 服务器寻址的最小存储单元是 Oracle 块。无论段是表、索引、簇还是其他对象，块结构都是相同的。设计性能最优的数据库，应该从适当配置和管理 Oracle 块开始。

Oracle 块由三部分组成：块头、数据存储区和自由空间区。块头包含有关块的信息，例如块中存储的数据所属的段类型、哪些段在块中包含数据、块地址以及指向其中实际存储行的指针。块头由固定部分和可变部分组成，在块中通常占用 85 到 100 字节。

在 Oracle 块中，重点关注的是数据存储区和自由空间区的管理。数据区是块中实际存储行的区域。自由空间区是一个保留区域，定义为总可用空间的百分比，用于存储有关块中行未来更新的信息。

#### 理解 PCTFREE 与 PCTUSED

PCTFREE 和 PCTUSED 是应用于段的两个存储参数。当 Oracle 向数据库中写入信息时，必须首先在某个段的分配区中找到一个或多个块来存储信息。

如果块中自由空间的百分比高于 PCTFREE 参数值，则该空间可以用于存储新信息。当自由空间百分比低于 PCTFREE 时，该块就被认为是“满的”。

当块中已使用空间的百分比低于 PCTUSED 时，该块可以用于存储新信息。

应使 Oracle 保持足够的额外空间，用于行增长（修改行结构），而不必跨块存储。将行限制在单个块中，有助于使数据库以最高性能运行。

PCTFREE 和 PCTUSED 的值不能等于 100%。由数据库引擎处理引起的系统开销，可以通过在 PCTFREE 和 PCTUSED 之间至少保留 20% 的裕量来解决。默认情况下，PCTFREE 为 10，PCTUSED 为 40。

PCTFREE 和 PCTUSED 在数据库段的存储子句中指定。可以通过 DBA_TABLES、DBA_CLUSTERS 或 DBA_INDEXES 数据字典视图查询它们当前的值。

#### 索引与 PCTUSED/PCTFREE

索引使用 PCTFREE 和 PCTUSED 的方式与表不同。**这些参数仅在索引最初建立时适用。** PCTFREE 的设置应使索引结构在最初于叶块中建立时拥有足够的空间，这样就可以增加辅助关键字，而不必拆分现有叶块来为新关键字提供空间。**索引不需要设置 PCTUSED。**

当为现有表建立新索引时，如果预期表中的数据比较稳定、修改较少，可以选择较小的 PCTFREE；反之，则应选择较大的值。

#### 管理表存储区

创建表时，系统会自动在表空间中分配一个区间，构成数据段。表的空间需求等于平均行长与行数的乘积。确定表的容量应在建表前的设计阶段完成。预期增长和存储参数值等问题，应在创建表时处理。Oracle 通过以下方式为未来数据预留空间（参见 2.1 节内容）：

- 1）为表的数据段设置存储参数，控制每次分配的区间大小。
- 2）使用存储参数 PCTFREE 和 PCTUSED，控制构成数据段的区间中各个块的空间利用率。

#### 管理索引

当查询语句的 WHERE 子句表达式包含已建立索引的关键字时，Oracle 会自动启用索引。

许多应用程序员（以及 DBA）通过申请更多索引来解决数据库性能问题。但是，增加索引不仅会影响修改性能，而且在一个查询中，子句所涉及的索引也不一定都会被启用。

过多的索引并不总能提供更好的 SELECT 性能。

关于索引管理和使用的几点技巧：

- 1）组合索引是提高性能的有力工具，特别适用于只需从索引段读取、而无需从数据段读取数据的查询。
- 2）如果查询子句中包含 ‘IS NULL’ 或 ‘IS NOT NULL’，索引将不再启用。
- 3）在查询子句中涉及多个索引且没有明显优先选择的情况下，Oracle 通常根据索引类型及列的性质选择要启用的索引。当唯一性索引和非唯一性索引都可使用时，只启用唯一性索引。
- 4）对关键字执行运算可能会屏蔽定义在该列上的索引。
- 5）如果 WHERE 子句中包含不等于（‘!=’ 或 ‘NOT’）运算，Oracle 将不再启用索引，但仍可对其他列使用索引。

#### 监控回滚段

回滚段实际上是动态的，DBA 应将精力集中在确保每个回滚段及其关联的表空间都有足够的增长空间上。

关注回滚段的目的在于合理配置系统资源，提高回滚段的利用率。关键在于确定各个事务需要占用多大的存储空间，以及其活动时间有多长。

#### 管理临时表空间和段

临时段是 SELECT 语句在需要时向 Oracle 申请的存储资源，会随着 SELECT 语句结束而注销。只有当查询的直接结果与查询显示结果不同时，才会申请临时段来保存中间结果，例如 DISTINCT、ORDER BY 等操作。

默认情况下，临时段创建在系统表空间中。临时段的频繁创建和删除势必会降低系统表空间的效率，还会增加系统表空间中的“碎片”，影响存储空间的有效使用。

应该设计一个专门的表空间来存放临时段，最好将其分配在与系统表空间和数据段不同的存储器上，以减少 I/O 冲突。创建用户时，应同时为其指定用于临时段的表空间。临时段表空间的最小容量应为单个数据表信息量的两倍，同时还要考虑用户数量。
