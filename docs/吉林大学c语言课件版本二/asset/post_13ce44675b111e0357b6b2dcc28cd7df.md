
- 全局量和局部量是一个相对概念。
  - 某标识符相对于某复合语句是局部的，相对于其内层复合语句却是全局的；
  - 反之某标识符相对于内层某复合语句是全局的，但是相对于声明它本身的那个复合语句来讲却是局部的。
- 全局量在内层具有外层同样的意义
  - 在内层对全局量的操作直接反应在外层程序中

## 递归——递归程序

例8-14 编一个函数 factorial 计算阶乘 n!

按过去程序设计思想，该函数应该写成：

```c
int factorial ( int n ) {
    int i,p;
    p=1;
    for ( i=1 ; i<=n ; i=i+1 )
        p=p*i;
    return p ;
}
```

```
n! = {
```

```c
int factorial ( int n ) {

        return 1;
    else
        return n*factorial(n-1);
}
```

## 例8-16 n 次勒让德多项式

pₙ(x) = {
  1                                    当 n = 0
  x                                    当 n = 1
  ((2n-1)x pₙ₋₁(x) - (n-1) pₙ₋₂(x))/n   当 n > 1
}

```c
float r(int n,float x){
    if(n==0) return 1;
    if(n==1) return x;
    float f0=1,f1=x,f=f1;
    while(n>1){
        f=((2*n-1)*x*f1-(n-1)*f0)/n;
        f0=f1;
        f1=f;
        n--;
    }
    return f;
}
```

计算它的递归函数是：

```c
float p ( int n , float x ) {
    if ( n==0 )
        return 1 ;
    else
        if (n==1)
            return x ;
        else
            return ( (2*n-1)*x*p(n-1,x) - (n-1)*p(n-2,x) )/n ;
}
```

## 递归程序设计的思想体现在：

- 用逐步求精原则，先把一个问题分解成若干子问题
- 这些子问题中有些问题与原始问题具有相同的特征属性，至多不过是某些参数不同，规模比原来小了
- 此时，就可以对这些子问题实施与原始问题同样的分析算法，直到规模小到问题容易解决或已经解决时为止。
- 也就是说，若将整个问题的算法设计成一个函数，则解决这个子问题的算法就表现为对相应函数的递归调用。

再看 n! 的例子。该问题是：当 n>0 时，若能计算出 w=(n-1)! 则 r = n! = n*w

```c
void fact ( int n , int *r ) {
    int w ;
    if ( n==0 )
        *r = 1 ;
    else {
        fact(n-1,&w);
        *r = n*w ;
    }
}
```

若把该函数的参数 r 用函数值表示，就是前边的函数 factorial。
