
## Compile the Web Service

Create a myservice directory.

From the directory just above loanservice, run Java’s Annotation Processing Tool (APT):

```
C:\>apt -d myservice loanservice/LoanApprover.java
```

This populates a directory named myservice.
The directory holds the compiled package as well as a new directory (package) called jaxws.
The new jaxws package holds classes associated with the parameters to and from each web service method.
Use the -s switch to generate the source code.

## Publish the Service

From a directory just above myservice:

```
C:\>java -cp myservice loanservice/LoanApprover
```

To view the WSDL, visit the service with a browser at http://localhost:8080/loanapprover?wsdl

## Generate Stub Code

Make a client directory.

```
C:\>wsimport –p client –keep http://localhost:8080/loanapprover?wsdl
```

This populates the client subdirectory with .class and .java files.

- 提高业务效率和用户满意度

  - 遵循开放的标准化协议、应用于厂商多样性的环境
- 提高投资回报率
  - 服务的松耦合及平台中立降低了集成和维护成本

## SOA项目实施需求来源

- 系统整合驱动
  - 应用系统之间的数据整合
  - 功能整合
  - 流程整合
- 新系统建设驱动

- 项目实施阶段
  - 服务规划与设计
  - 服务开发
  - 服务测试
  - 服务发布
  - 服务组装运行
  - 管理流程变化

## 按建设类型来划分

- 一步到位法
  - 组织规范：建立战略机构，统一优化业务
  - 服务建模：以业务优化思想为主导；
  - 平台选择：需选择全功能且包括开发的能力的平台
- 核心扩展法
  - 组织规范：以调整核心业务的组织和规范为主
  - 服务建模：以核心业务改造为主导，逐步建立其他服务
  - 平台选择：选择适用平台
- 逐级建设法
  - 组织规范：先不涉及组织调整，后期逐步调整组织，并定规范
  - 服务建模：以公共业务重用为主导，逐步建立其他服务
  - 平台选择：选择简单平台

## 按切入点划分

- 从流程切入
  - 对于基于流程来设置组织及管理机制的用户，业务流程是最核心的，以流程为中心切入SOA将更加合适
- 从信息切入
  - 组织内部的营运管理需要大量而实时的商业信息，通过信息流需求来整合原有部门级的应用
- 从客户体验需求切入
  - 对于关注于直接客户服务的部分企业或政府用户而言，终端服务能力是推进用户信息化的重要驱动力；提升对客户的个性化及多渠道服务能力，是用户的核心关注点。

## 按实施组织类型划分

- 用户主导
  - 由用户方所建立的实施团队来主导IT总体规划及项目目标，用户业务决策层、IT信息部门及所涉及的业务部门主管来共同推动项目实施
- 厂商主导
  - 由咨询公司帮助用户梳理业务、并提出信息化及项目招标要求，由具体的集成商，选择SOA的方法及技术进行项目实施

## 按解决问题划分

- 系统集成
  - 在组织内部多个IT系统之间的互联互通需求，使SOA已逐渐成为许多用户整合项目的重要技术路线
- 新应用建设
  - 在构建新系统时，对原系统资源进行再利用，基于新功能需求进行服务化开发，从而降低成本、缩减周期
- 业务创新变革
  - 业务的调整及改变，原有多个异构系统的整合和复用，难以满足业务需求，重新规划系统，利用SOA构建新的需求，从长远角度满足业务发展及变化

## 按业务关注点划分

- 资源共享需求
  - 实现单个组织内不同部门之间或者不同组织之间的信息资源及应用资源的共享
  - 通过服务化的方式，对数据进行更灵活的共享
- 业务协同需求
  - 业务协同的核心是流程，流程中涉及到多个复杂的异构系统
  - 鉴于SOA的松耦合、标准化、灵活性等特性，基于服务的方式来实现IT系统之间的协同，已成为主流
