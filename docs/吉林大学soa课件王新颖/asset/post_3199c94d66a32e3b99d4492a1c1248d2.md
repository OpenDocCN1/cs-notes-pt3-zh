# SOA的特点

## 关注点

- SOA服务专注于业务层面的活动和互动
- 以前，只专注于技术层面的子任务

## “用户”与“开发”的调和

- 业务人员和IT人员基于SOA讨论（今天有63%的项目是由业务部门提出的）*
- 以前，业务人员与IT人员没有合适的沟通渠道和语言

## 标准

- 被广泛采用的Web Services保证了有良好定义的接口。
- 以前，私有的“标准”限制了互操作性

## 连接

- SOA服务是动态、灵活的连接
- 以前，服务之间的互操作是通过编程实现的，且与应用本身相关

## 重用性

- SOA服务能被广泛地重用，从而提高资产利用率
- 以前，重用只能在某一应用内部实现

# SOA的基本特征

1、独立的功能实体

- 企业通过Internet这样松散的环境进行控制，其结构会面临严重的稳定性问题
- SOA非常强调架构中提供服务的功能实体完全独立自主的能力，强调实体自我管理和恢复能力

2、大数据量低频率访问

- SOA采用大数据量的方式一次性进行信息交换

3、基于文本的消息传递

- 基于文本的消息本身不包含任何处理逻辑和数据类型，保证异构系统间信息的兼容性

# SOA的优劣

- SOA通过互联网发布，突破企业内网限制，实现与供应链上下游伙伴业务的紧密结合；
- SOA的平台无关性，减少了业务应用实现的限制；
- SOA具有低耦合性特点，增加和减少业务伙伴对整个业务系统的影响较低；
- SOA具有可按模块分阶段进行实施的优势；
- SOA的实施可能并不具有成本显著性。

# SOA in Five Slides (1): SOA

- 面向服务的架构（SOA）是一个范式，其目的是实现和维护跨越大部分分布式系统的业务流程
- SOA基于三个主要技术和概念
  - 服务：一项自足的业务功能，集中关注接口的业务价值，填补“业务/IT”鸿沟。
  - 企业服务总线：SOA基础设施，使得分布式系统和服务之间的高互操作性成为可能，简化了分布式业务在不同平台和技术的众多系统间的工作流程。
  - 松耦合：减少系统间的相互依赖，将个别系统的修改和故障对系统的影响降至最低。

# SOA in Five Slides (2): 政策和过程

- 分布式处理不仅仅是个技术细节，系统引入新功能，涉及多个系统和团队，必须协作。
- 构建一个SOA系统，需要清晰地定义角色、政策和过程。

# SOA in Five Slides (3): Web Service

- Web Service是实现SOA的有效技术手段之一
- Web Service自身的问题
  - 标准不够成熟，不能保证互操作性
  - 无法形成程度适当的松耦合
- 设计SOA系统，不能掉进过于Web Service化的陷阱。Web Service不会是系统集成的终极标准，因此只有当Web Service对特定的基础设施考量确实重要时，才应把它加进来发挥作用。
