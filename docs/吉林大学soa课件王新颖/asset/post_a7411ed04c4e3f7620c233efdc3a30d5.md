
## WSDL文档示例

```
<message name="getTermRequest">
    <part name="term" type="xs:string"/>
</message>

<message name="getTermResponse">
    <part name="value" type="xs:string"/>
</message>

<portType name="glossaryTerms">
    <operation name="getTerm">
        <input message="getTermRequest"/>
        <output message="getTermResponse"/>
    </operation>
</portType>
```

## WSDL操作类型

| 类型 | 定义 |
| --- | --- |
| One-way \* | 单向操作，服务访问端点接受消息，但不会返回响应 |
| Request-response \* | 请求响应操作，服务访问端点接受一个请求并会返回一个响应 |
| Solicit-response | 要求应答操作，服务访问端点发送一个请求，并会等待一个响应 |
| Notification | 通知操作，服务访问端点发送一条消息，但不会等待响应 |

## WSDL Service

服务是访问端口的集合，通过绑定指定唯一地址来定义一个访问端口（port）。

WSDL文档范围内，服务的name属性具有唯一性；访问端口的name属性也具有唯一性。

```
<wsdl:service .... > *
<wsdl:port name="nmtoken" binding="qname">*
</wsdl:port>
</wsdl:service>
```

一个<service>中可以包含一个或多个<port>。

### UDDI

## What is UDDI?

- UDDI (Universal Description, Discovery and Integration) 是一个独立于平台的框架，用于通过使用 Internet 来描述服务，发现企业，并对企业服务进行集成
- UDDI 指的是通用描述、发现与集成服务
- UDDI 是一种用于存储有关 web services 的信息的目录
- UDDI 是一种由 WSDL 描述的 web services 界面的目录
- UDDI 经由 SOAP 进行通信
- UDDI 被构建入了微软的 .NET 平台

Demo
http://www.webxml.com.cn/zh_cn/web_services.aspx

### UDDI数据模型

UDDI 实体是一个XML文档的不同元素，主要包括：

- businessEntity: 提供服务的组织的描述
- businessService: businessEntity所提供的Web服务列表
- bindingTemplate: 描述服务的技术细节。
- tModel (technical model): 一个通用的元素，可以用来存储更多的服务和技术的附加信息，如服务使用条件、认证等。
