# Multiversion Two-Phase Locking (Cont.)

+   - When an update transaction wants to read a data item:
+     - it obtains a shared lock on it, and reads the latest version.

+   - When it wants to write an item
+     - it obtains X lock on; it then creates a new version of the item and sets this version's timestamp to ∞.

+   - When update transaction Tᵢ completes, commit processing occurs:
+     - Tᵢ sets timestamp on the versions it has created to ts-counter + 1
+     - Tᵢ increments ts-counter by 1

+   - Read-only transactions that start after Tᵢ increments ts-counter will see the values updated by Tᵢ.

+   - Read-only transactions that start before Tᵢ increments the ts-counter will see the value before the updates by Tᵢ.

+   - Only serializable schedules are produced.
