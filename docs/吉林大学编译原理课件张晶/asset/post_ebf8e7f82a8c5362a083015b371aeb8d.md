
## 3.1 驱动程序的设计

- 分析的初始格局（$S\#, a_1...a_n\#$）
- 一般格局（$X_1...X_m\#, a_1...a_n\#$）

设存在格局为（$X_1...X_m\#, a_1...a_n\#$）

- 若 $X_1\in V_T$ & $X_1=a_1$，则有（$X_2...X_m\#, a_2...a_n\#$）
- 若 $X_1\in V_N$ 则查表，若 $T(X_1,a_1)=X_1\to\alpha$，格局为（$\alpha X_2...X_m\#, a_1...a_n\#$），若 $T(X_1,a_1)=Error$，则报错。
- 若格局为（$\#,\ \#$），则分析成功
- 其他情况 报错

## 3.2 驱动程序的实现

[1] 初始化： Stack := empty ; Push(#); Push(S); 即由符号栈和输入流构成的初始格局为： (#S, a₁a₂...aₙ#)

[2] 读第一个输入符： Read(a);

[3] 若当前格局是(#,#)，则成功结束；否则转下一步；

[4] 设当前格局为(.... X, a....)，则：

- 若X∈ V_T & X=a ，则：
  { Pop(1); Read(a); goto [3] }

- 若X∈ V_T & X≠ a ，则 Error;

- 若X ∈ V_N ，则：
  if T(X, a)=X→Y₁ Y₂...... Yₙ
  then { Pop(1); Push(Yₙ,...,Y₁); goto[3] }
  else Error

# 递归下降法

## 1.1 递归下降法的基本原理

- 递归下降法 (Recursive-Descent Parsing)
  
  对每个非终极符构造相应的一个子程序序列(称为语法分析子程序)，其功能是识别、分析该非终极符所能推导出的字符串。

例如：一产生式：

<While_Stm>→while <Exp> do <Stm>

则对应产生式右部的语法分析程序部分如下：

```
begin
    Match(while);
    Exp;
    Match(do);
    Stm;
end
```

```
begin Match(while); Exp; Match(do); Stm; end
```

```
while x > y do if x > y then x := y + x else y := x
```

## 1.2 对文法的要求

- 为了保证推导的唯一性，对文法的要求与LL(1)文法相同。即对于文法G中任一非终极符A，其任意两个产生式A→α和A→β，都要满足下面条件：
- Predict (A→α) ∩ Predict (A→β) = ∅

## 2. 语法分析程序的构造

- ◆ 两个标准函数
  1. ReadToken: 把输入流的头符读入变量 token中
  2. Match(a): if token=a then ReadToken else 出错

## 2. 语法分析程序的构造

当产生式形如: A→β₁|β₂|…|βₙ, 则按下面的方法编写子程序A:

```
procedure A()
begin if token∈Predict(A→β₁) then θ(β₁) else
if token∈Predict(A→β₂) then θ(β₂) else
......
if token∈Predict(A→βₙ) then θ(βₙ) else
error()
end
```

其中对βᵢ=X₁X₂…Xₙ, θ(βᵢ)=θ'(X₁);θ'(X₂);…;θ'(Xₙ);

如果X∈Vₙ, θ'(X)= X();

如果X∈Vₜ, θ'(X)= Match(X); //即if(token==X) ReadToken();

如果X= ε, θ'(ε)= skip(空语句).
