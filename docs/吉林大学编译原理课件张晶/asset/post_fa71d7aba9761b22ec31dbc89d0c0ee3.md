## 目标程序运行时内存空间

+   - **库代码区（libaray space）**：用于存放函数的目标代码，例如 Pascal 语言中用到的 sin、cos 等等，C 语言中通过 `#include` 包含进来的库代码；
+   - **目标代码区（code space）**：用以存放编译生成的目标程序。实际上一个目标程序变成可执行文件需要一个链接-装配的过程，链接装配之后存放在目标代码区。

## 目标程序运行时大

+   堆区空间
+   栈区空间
+   静态区空间
+   目标代码空间
+   库代码空间

+   - 静态区(static space)：有些数据对象所占用的空间能在编译时确定，其地址可以编译进目标代码中，这些数据对象通常存放在静态区中，如静态变量和全局变量
+   - 栈区（stack space）：存放过程活动记录，该存储区被称作一个栈，一个元素是一个过程活动记录，调用函数时压栈，函数结束时退栈

## 目标程序运行时大

+   - 堆区空间
+   - 栈区空间
+   - 静态区空间
+   - 目标代码空间
+   - 库代码空间

+   - 堆区（heap space）：堆不是一个连续分配的模式，可以进行动态分配的空间管理，主要用于存放动态申请的数据对象（如C, pascal 等语言的malloc, free, new, delete）
+   - 栈区和堆区之间没有事先划好的界线，当目标代码运行时，栈区指针和堆区指针不断地变化，并朝着对方方向不断增长。如果这两个区相交，则表示出现了内存溢出。

## 语言影响空间分配策略

+   （1）语言中是否允许函数、过程的递归调用？
+   允许递归调用，则函数的形参、局部量可能对应是一系列存储单元，不能采用静态的存储分配方式；
+   不允许有递归出现，则一个函数最多只能分配一个活动记录大小的空间。

## 语言影响空间分配策略

+   （2）当函数调用结束时局部变量是否需要保存？
+   一般来说，一个函数的局部变量在函数调用结束的时候所占用的存储空间都要被释放掉，但是有一类语言的特殊语句，允许函数中的某个局部变量保存着，下一次再调用这个函数的时候，这个局部变量是已经具有上一次语言的值。

## 语言影响空间分配策略

+   （3）是否可以访问非局部的变量？比如说外层的变量，还有其他变量是否可以被访问，不同的语言也有不同的约定。

## 语言影响空间分配策略

+   - （4）函数参数的传递方式。
+   - 常用的参数传递方式是值引用和地址引用，这就决定了地址引用型实参只能是一个变量，而不能是一个常数，形参的值引用和地址引用的空间分配的方式是不一样的

## 语言影响空间分配策略

+   - (5) 函数是否可以作为参数进行传递？
+   - (6) 函数的结果是否可以为函数？
+   - (7) 动态地申请存储块？
+   - (8) 是否显式地释放存储空间？

静态存储分配策略

## 静态存储分配

+   完全采用静态分配策略的语言必须满足以下约束条件：
+   1. 不允许有递归过程/函数。
+   2. 数据对象的长度和它在内存中位置，必须是在编译时可知。
+   3. 不允许动态建立的数据结构（如动态数组、指针等），因为没有运行时的存储分配机制。

## 动态存储分配

动态存储分配，可以分为：

+   栈式。是一种最常见的模式，在有函数调用的时候动态的分配存储空间；
若程序运行过程中需要动态进行申请和释放程序空间，就不能用栈式分配. 因为没有办法静态地在活动记录里给动态变量分配空间
+   栈堆混合式，活动记录的大小确定的存在栈区中，动态申请的空间在堆区中申请然后释放，同时增加一部分对堆区的的管理程序
