# Lower bound for the worst case

In a comparison sort, the (worst case) running time is the depth (or height) of the decision tree T(n).

Since the decision tree has n! leaves, its depth T(n) satisfies 2^{T(n)} ≥ n!. Thus, T(n) = Ω(n log n).

Are there sort algorithm with complexity O(n)?

# Counting Sort

+   - Input: A[1..n], 0 ≤ A[i] ≤ k for 1 ≤ i ≤ n
+   - Output: B[1..n]=sorted A[1..n]
+   - Idea
+     - Use C[0..k] to compute the position of each A[i]
+     - Put each A[i] for i=n to 1 into B[1..n]

![](bbox=[0.52, 0.58, 0.88, 0.78])

# Algorithm

```
for i ← 1 to k
  do C[i] ← 0;
for j ← 1 to length[A]
  do C[A[j]] ← C[A[j]] + 1;
for i ← 2 to k
  do C[i] ← C[i] + C[i-1];
for j ← length[A] downto 1
  do begin
    B[C[A[j]]] ← A[j];
    C[A[j]] ← C[A[j]] - 1;
  end
```
