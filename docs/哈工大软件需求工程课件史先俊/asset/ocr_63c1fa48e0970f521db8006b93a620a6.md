# 4 从需求到成功

+   • 把需求文档作为何时发行产品的的基础。

开发过程中，开发人员列出了与特定代码版本相对应的需求。项目的质量保证组通过对照需求来执行测试用例从而评价其对应的代码版本。根据测试标准，如果不满足需求的话就算是错误。如果不满足的需求数量超过预先给定的一个数字，或者特定的有重大影响的需求没有被满足，那么这个代码块就被拒绝了。

+   • 也不要成为需求过程的奴隶。避免陷入畸形分析的陷阱，此时，开发小组将花费大量的时间创建不必要的文档，并举行各种形式上的会议和评审，而并不编写任何软件代码，这会导致项目被取消。努力在精确的规格说明与可将产品失败的风险降至可接受程度的编码之间做出明智的选择。
