  - 指示用例 **A** 的实例也可以包含用例 **B** 指定的行为。

- 系统边界
  - 是用例周围用来指明该系统的边界。
- 约束
  - 是条件和命题的规范；为使系统有效，它必须为真。
  - 约束以花括弧（{ }）中的文本表示，可用预定义的语言编写，如对象约束语言 (**OCL**) 或自然语言等。

## 举报受理的用例说明

| 名称 | 举报受理 |
| 简述 | 本用例（use case）描述了举报案件受理的过程，根据界面提示输入或接收相关举报案件的相关资料。 |
| 参与者 | 稽查机构的工作人员 |
| 前置条件 | 略 |
| 后置条件 | 略 |
| 基本事件流 | 1. 稽查机构的工作人员进入主页面并选中案件受理后启动用例。 2. 稽查机构的工作人员将接到的举报人以书信、口头、电话或者其他形式举报的案件的，对举报人反映的偷税、逃避追缴欠税、骗税和虚开、伪造、非法提供、非法取得发票，以及其他税收违法行为，选择登记后要在《税务违法案件举报登记表》中进行登记有关内容，按提交申请请提交。 3. 还可以通过网络或文件形式接收上下级或其他部门通过本软件转来的信息，可以对原始举报材料登记。 4. 数据登记完以后点保存，确认无误后转举报案件请办。 |
| 可选事件流 | 2. 当检查机关工作人员选择“按受”案件时，直接跳到 3 |
| 非功能性需求 | 无 |
| 扩展点 | 无 |

用例模型的使用跨越从需求建模、分析、设计到实现/测试的整个阶段，将用来：

- 定义应用系统的边界
- 描述系统如何与外界交互
- 作为获取其他分析设计模型的基础
- 作为创建测试用例的基础
- 作为变更控制的基础

## 用例的详细说明

| 用例名称 | 纳税申报 |
| 简要描述 | 接受申报操作人员提交的申报材料、审核处理，在有的地方需直接进行税款征收。 |
| 事件流 | 申报操作人员提交纳税申报资料时启动用例： S1 系统读入纳税人基本信息资料 S2 基本信息资料检查 S3 系统读入纳税人申报资料 S4 审核申报资料 S5 逾期检查 S6 申报处理 S7 (征收) S8 资料归档 |
| 可选事件流 | 在输入阶段如果操作人员按“取消”将终止用例执行 |
| 扩展点 | 征收 |
| 前置条件 | 纳税人经过登记 操作人员有相应权限 |
| 后置条件 | (略) |
| 业务规则 | S2 如果纳税人识别号不存在则终止用例执行，并提示错误信息 S4 如果输入税额不正确则要求重新读入申报资料，并提示错误信息 S4 如果是申报资料已存在，则提示重复申报信息，问是否确认要重复申报 S5 如果是逾期申报则进行逾期申报处理 |

| 用例名称 | 网上申报 |

| 扩展点 | 征收 |
| 前置条件 | 纳税人经过登记 操作人员有相应权限 |
| 后置条件 | (略) |
| 业务规则 | S2 如果纳税人没有申请过网上申报则终止用例执行，并提示错误信息 S4 如果输入税额不正确则要求重新读入申报资料，并提示错误信息 S4 如果是申报资料已存在，则提示重复申报信息。问是否确认要重复申报 S5 如果是逾期申报则进行逾期申报处理 S7 只有满足条件的纳税人才能进行网上征收 |
