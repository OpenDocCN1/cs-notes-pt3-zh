
## 计算机性能的本质定义

- 计算机性能最本质的定义： “完成一个任务所需要的时间”
  - 计算机系统完成某个任务所花费的时间，称为执行时间，分为墙上时间和系统时间，在单任务情况下，两者基本一致
  - 完成一个任务的时间包括： CPU的执行时间、磁盘的访问、内存的访问、输入输出的活动和操作系统的开销等所有的时间
- CPU的执行时间（可以运行 “time ./task” 来统计）
  - 不包括等待I/O的时间或者执行其他程序的时间
  - 可以进一步用户态CPU时间（执行用户程序、动态函数调用）和系统态CPU时间（系统调用、调度和中断、同步和通讯开销）

## CPU时间的组成

- 指令数：算法、编译系统、ISA
- IPC：微结构、ISA、编译器
- 主频：微结构、工艺技术

## 影响指令数的因素

- 算法
  - 算法从根本上决定源程序执行指令的数目
- 编程语言
  - 编程语言的语句必须翻译为指令，如面向对象语言有更多的间接调用，像Java这样的语言还需要JIT和解释器的参与
- 编译系统（含相关库）
  - 如Intel的ICC编译器编出来的程序效率比GCC要高30%，能充分利用向量化指令和针对CPU结构的优化
- 指令系统架构
  - 指令系统架构的功能影响完成某个任务所需的指令数

## CPI 或IPC

- **CPI：** 平均每条指令执行花费的时钟周期数
  - IPC为CPI的倒数，表示每个时钟周期内执行的指令数
- **CPI可以表现为不同指令混合的加权平均**
  - 微结构的影响最大，IPC是体现微结构能力的最重要指标
  - 指令系统的表达能力影响CPI
  - 编译系统也影响CPI

CPU time = Cycle Time × Σ (j=1 to n) CPI_j × I_j
= Cycle Time × CPI × Instruction Count

CPI = Σ (j=1 to n) CPI_j × F_j   where F_j = I_j / Instruction Count

## CPI计算示例

- 某台机器，测量的值为：
  - 浮点指令占25%，平均CPI为4；其中FPSQR占2%，CPI为20
  - 其他指令的CPI为1.33
  - CPI = 4*25% + 1.33*75% = 2.0
- 优化设计A：把FPSQR的CPI从20 降到2
  - CPI = 2.0 − 2% *(20-2) = 1.64
  - 加速比：2.0/1.64 = 1.22
- 优化设计B：把FP指令的平均CPI降到2.5
  - CPI = 2.5*25% + 1.33*75% = 1.625
  - 加速比：2.0/1.625 = 1.23

## 时钟频率

- 时钟频率（clock rate），是指同步电路中时序电路（如触发器）每秒采样次数，量度单位为赫兹（Hz）
  - CPU的主频是评定CPU性能的重要指标，一般来说主频数值越大越好
  - 除了CPU的主频，内存及IO接口的工作频率对性能的影响也很大
- 影响CPU频率的因素
  - 工艺技术: 工艺越先进，频率越高
  - 微结构: 如流水线的划分，多发射
  - 逻辑设计: 如串行进位加法器和先行进位加法器
  - 物理设计: 如动态电路的使用，时钟树结构、降低动态压降

## 并行系统的评价指标

- 并行计算机系统包括：
  - 多核/众核处理器
  - 多处理器系统
  - 集群系统
- 并行系统的评价指标
  - 可扩展性：是指随着并行系统中机器规模的扩大，并行系统的性能随之增长的特性。
  - 加速比：加速比是同一个任务在单处理器系统和并行处理器系统中运行所耗费时间的比率，用来衡量并行系统或程序并行化的性能和效果

## 加速比

- 加速比的计算公式为： Sp = T1 / Tp
  - T1是单处理器下的运行时间，Tp是在有P个处理器并行系统中的运行时间
  - 由于通信开销，访存冲突等限制，一般Sp < p
  - 当Sp=p时，此加速比被称为线性加速比
- “超线性加速比”，即加速比比处理器数更大的情况
  - 一般由于“高速缓存效应”产生，即相同的计算数据分布到多个处理器中后，每个处理器存储的数据减少，有利于提高高速缓存命中率

## 阿姆达尔（Amdahl）定律

- **Amdahl定律：并行效果受串行部分限制**
  - 定义：系统中对某一部件采用更快执行方式所能获得的系统性能改进程度，取决于这种执行方式被使用的频率，或所占总执行时间的比例
  - 例如：浮点功能单元执行性能提高2倍；但是仅有10%的浮点指令，则加速比为Speedup_overall = 1 ÷ 0.95 = 1.053
- **Amdahl定律的局限性：只假定并行系统处理固定规模问题**
  - 如果把问题规模随机器规模一起变大，加速比仍然可以变大

ExTime_new = ExTime_old × [(1 − Fraction_enhanced) + Fraction_enhanced / Speedup_enhanced]

Speedup_overall = ExTime_old / ExTime_new = 1 / [(1 − Fraction_enhanced) + Fraction_enhanced / Speedup_enhanced]
