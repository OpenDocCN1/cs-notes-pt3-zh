

## §2.4 继承

### 1. 单重继承

子类仅从一个父类继承属性和方法

子类可以覆盖父类的部分属性和方法

### 2. 多重继承

子类可从多个父类继承属性和方法

### 3. 继承机制的意义

- 避免冗余，简化类或对象之间的接口
- 支持软件重用

## §2.5 多态

### 1. 重载 (Overloading)

相同的函数名称，属于不同的类 或 由不同的参数类型，而导致不同的功能或行为

### 2. 重设 (Overriding)

子类覆盖父类的方法

### 3. 多态 (Polymorphism)

相同的消息由同一(父)类的不同对象接收时，导致不同的行为

由编译器决定函数名与函数体的联编 (Binding)

在运行时刻动态决定函数名与函数体的联编

## §3.3 需求建模

- 建模是刻画、分析和解决问题的有效途径
- 需求模型详细、准确地描述用户对目标软件系统在功能、行为等方面的要求
- 建模有助于分析人员全面、系统地了解用户需求；
- 有助于发现用户需求描述中的不一致性和模糊性
- 有助于确保需求规格说明书的准确、一致、全面性

## §3.4 问题抽象、问题分解和多视点分析

### 1 问题抽象

- 在某个层次上认识和表示事物，抽取事物的某些特性和行为
- 抽象有助于控制问题的复杂度
- 抽象有助于获取和分析问题本身所固有的一般——特殊关系

### 2 问题分解

- 高内聚，低耦合原则；自然性原则
- 分解有助于获取和分析问题本身所固有的部分——整体关系

### 3 多视点分析

- 从多角度、多视点对问题进行理解、分析
- 然后综合成为全面的需求模型

## §3.5 支持需求分析的原型技术

- 快速生成一个简单、初步的需求模型
- 快速设计（主要关心目标软件系统的总体结构、用户界面和核心数据结构）
- 实现原型（不考虑效率问题）
- 将原型提交给用户评审，征询改进意见
- 重复以上过程，直至需求模型一致化、完全化

## §3.6 需求规格说明与评审

### §3.6.1 需求规格说明

#### 1. 内容

- 功能与行为需求描述：需求模型及附加的文字描述
- 非行为需求描述：设计约束，效率，可靠性，安全性，可移植性等

#### 2. 格式

- 采用标准格式

#### 3. 目标

- 便于用户、分析人员和软件设计人员进行理解和交流
- 支持目标软件系统的确认
- 控制系统的进化过程

### §3.6.2 评审

用户、需求分析人员和设计人员共同参与

评审的内容和标准：

- 正确性，无歧义性，完整性，一致性
- 可理解性，可修改性，可验证性，可追踪性

## §4.1 OOA 的语言

1. 从 OO 观点出发，OOA 模型描述：

   - 问题域中对象及它们之间的结构关系
   - 问题域中对象之间的通信与协调

2. OOA 模型的内容：

   - 对象--类层：问题域中概念及实体的抽象
   - 属性层：对象的属性及对象之间的实例连接
   - 服务层：对象的服务及对象之间的消息连接
   - 结构层：问题域中的结构关系（继承与聚集）
   - 主题层：问题分解，分而治之

## §4.2 OOA 的方法

### §4.2.1 发现和识别对象

#### 1. 采用自然语言处理技术标识问题域中的概念及其相互关系

- 采用自然语言分析技术 获得 概念集合
- 采用矩阵分析技术 获得 概念之间的相互关联
- 将上述结果表示成 OOA 工作表格

| 条目 (0) | (1) | (2) | (3) | (4) | (5) | 注释 |
|---|---|---|---|---|---|---|
| | | | | | | |
| | | | | | | |

(0) 忽略 (1) 可能的对象/类 (2) 可能的继承关系

(3) 可能的聚集关系 (4) 可能的对象/类的属性

(5) 可能的对象/类的外部服务

对象在用户需求的正文描述中可能呈以下形式：

- (1) 与目标系统交互信息的外部实体。例如，物理设备，操作人员或用户，其他有关的子系统。
- (2) 现实问题信息域中的概念实体。例如信号、报表、显示信息。
- (3) 目标系统运行过程中可能出现并需要系统记忆的事件。例如核电站运转时的意外事故。
- (4) 与目标系统发生交互作用的人员所扮演的各种角色。例如管理人员，工程师，销售人员。
- (5) 作为系统环境或问题上下文的场所、位置。例如卫星地面接收站的安装位置（经度、维度、海拔高度）。
- (6) 有关的组织机构。例如，单位、小组。
- (7) 表示一组成分对象的聚集对象。例如物理设备。

#### 2. 根据 DFD，ER 和状态转换图进一步标识有用的对象/类

顶级 DFD 中：

- 外部实体可构成潜在的对象
- 输入/输出数据流应在 OOA 模型得到适当的接收和处理

DFD 子图中的函数/过程可构成潜在的外部服务

ER 图中：

- 实体可构成潜在对象
- 实体的属性可构成潜在的对象属性
- 数量对应关系可构成 OOA 模型中的实例连接

状态转换图：系统必须处理的外部事件以及系统在处理这些事件时发生的状态变迁

- 事件的接收、响应过程有助于对象标识
- 状态信息有助于标识对象的属性
