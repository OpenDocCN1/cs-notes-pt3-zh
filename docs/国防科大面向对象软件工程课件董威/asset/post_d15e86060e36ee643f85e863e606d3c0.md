
## §4.2 OOA的方法

### §4.2.2 标识结构

#### 1. 标识继承关系

- 1.1 标识已有类之间的继承关系：是否自然？
- 1.2 从已有类出发寻找子类：
  - 对象的特殊化是否位于问题域中？是否自然？
  - 对象的特殊化可否使用额外的属性或外部服务进行刻画？
- 1.3 从已有类出发寻找公共父类：
  - 是否可以抽象出多个父类的公共属性或外部服务以简化OOA模型？

#### 2. 标识部分—整体关系

- 2.1 标识已有类之间的部分—整体关系：是否自然？
- 2.2 从已有类出发寻找部件类：
  - 是否可以提取多个类的公共部件类以简化OOA模型？
  - 提取的部件类是否自然？
- 2.3 从已有类出发寻找整体类：
  - 是否可以将已有类组装成为新的整体类？
  - 新得到的整体类是否位于问题域中？
  - 是否自然？
- 2.4 标识部分—整体关系中的重复度与参与度
  - 一个整体类的实例，可能含有多个部件类的实例？
  - 一个部件类的实例，可能出现在多个整体类的实例中？
  - 一个整体类的实例，是否必须包含某个部件类的实例？
  - 一个部件类的实例，是否必须出现在某个整体类的实例中？（是否可以独立出现？）

### §4.2.3 标识主题词

- 1. 根据问题空间中系统/子系统、问题/子问题的自然分解关系初步确定主题词
- 2. 主题词可以具有层次结构
- 3. 根据主题词将要求分析任务划分至各分析小组
- 4. 随分析的不断深入对主题词的内涵和划分进行必要调整

### §4.2.4 标识属性及实例关系

#### 1. 标识属性

- 1.1 在ER图中，实体的属性可能构成OOA模型的属性
- 1.2 哪些属性在问题空间中完全刻画了被标识的每个对象？

#### 规则

- 1.3 属性必须适应于类的所有实例，否则应考虑继承关系的可能性
- 1.4 导出属性和外部不可见属性应略去

#### 2. 标识实例关系

- 2.1 利用自然语言处理方法自动收集对象之间的关系
- 2.2 实例关系应反映自然域中的限制或事务规则
- 2.3 导出关系可以省略

### §4.2.5 标识服务和消息：分析对象之间的动态关联

- 1. 在自然语言处理过程中，考虑相关的动词可否构成外部服务
- 2. 考虑对象的生命周期（创建、删除、维护）
- 3. 结合数据流图考虑对象的计算性行为
- 4. 基于状态—事件—响应图提取对象之间的消息传递
- 5. 通过运行走查细化外部服务的定义

#### 规则

- 1. 任一对象的所有外部服务均由传入该对象的消息引发
- 2. 属性必须与某外部服务相关联，否则可删去
- 3. 消息连接必须与实例关系相一致

## §4.3 实例分析

### 电梯控制系统（ECS）

在M层的建筑内安装了N部电梯。电梯问题是指这些电梯的逻辑控制问题。

- 1. 每个电梯有一些按钮，每个按钮对应一个楼层。当按下按钮后，按钮灯亮，并指出电梯开往相应楼层。当电梯到达该楼层后，按钮灯熄灭。
- 2. 除底层和顶层只有一个按钮外，每个楼层有两个按钮，分别指示上楼和下楼请求。当按下后，按钮灯亮。如果电梯已经到达该楼层，或者遇到有冲突的请求时，按钮灯熄灭。在后一种情况下，如果两个楼层同时发出请求，则只能取消其中一个请求。决定服务优先次序的算法应尽量减少两个请求的等待时间。
- 3. 当没有服务请求时，电梯保持在最后一个目的楼层，电梯门关闭。
- 4. 系统以事件驱动的方式响应楼层对电梯的请求。所有楼层的优先级是相同的。
- 5. 系统以事件驱动的方式响应电梯内部到达楼层的要求，并按照电梯运动的方向依次完成这些要求。
- 6. 每个电梯都有一个紧急按钮，按下后向管理人员发出报警信号，然后电梯被置为“不可用”状态。每个电梯都有取消“不可用”状态的机制。

- 建筑物
