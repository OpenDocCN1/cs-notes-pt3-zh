# 4.2 UML 的表示方法

UML 的表示方法定义了 UML 的符号表示，为开发者或开发工具提供使用这种图形表
示方法为系统建模。这些符号或文字表述是应用级的模型，在语义上是 UML 元模型的实例。
UML1.1 标准提供了共五类九种视图来完成这种语义表达。在我们学习的 Rational Rose
98 中用到了其中的七种。

# 4.2.1 用例图(Use Case Diagram)

use case 图从用户的角度描述系统功能的使用者和主要的系统操作流程。这种图通常在
需求描述时使用，并在系统的分析过程中随着对系统的认识加深而不断改进。

# 4.2.2 静态图(Static Diagram)

静态图描述系统的静态特征和结构（系统不也是一个对象吗？）并表述系统的主要组
成部分。通常分为：

# A 类图(Class Diagram)

描述系统中类的静态结构，不仅定义系统中的类，还表示了系统中类之间的关系，如
关联(association)、依赖(dependency)、聚集(aggregation)等。也表示类的内部结构（属性和操
作）。类图描述的是一种静态关系，在系统的整个生命周期中都是有效的。

# B 对象图(Object Diagram)

既然对象是类的实例，对象图肯定也是类图的实例了。它们使用几乎完全相同的标识，
不同点在于对象图是表示类的多个实例，而不是实际的类。由于对象存在生命周期，因此对
象图仅在系统的某一阶段中存在。

# C 包图(Package Diagram)

包是指把功能或者用途相同的一个或多个类或对象用一个符号来表示，并代表所有这
些类或对象的静态、动态特征。主要是为简化复杂系统的视图而设计的。可以把几个类放在一
个包里，由包来和其它对象或类发生联系，并把消息传递给所属的类或对象。
