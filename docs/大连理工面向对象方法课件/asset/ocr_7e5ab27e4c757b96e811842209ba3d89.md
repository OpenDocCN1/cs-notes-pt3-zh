```
push 1 //1入栈

push si//this指针（指向brass object）入栈

mov bx,word ptr [si] //this所指内容（即vptr）进入bx

call word ptr [bx+4]//调用具体函数

add sp,4//恢复堆栈
```

C++函数调用的参数与C 函数调用一样，是从右向左进栈的。（这个顺序是为了支持C 的变量参数表），所以参数1 首先压栈。在这个函数的这个地方，寄存器si存放i 的首地址。因为它是被递中对的象的首地址，它也被压进栈。请大家记住：这个首地址对应于this的值。正因为调用每个成员函数时this都必须作为参数压进栈，所以成员函数知道它工作在哪个特殊对象上。这样，我们总能看到，在成员函数调用之前压栈的次数等于参数个数加一（except static成员函数，它没有this）。

如何实现实际的虚函数调用？首先，必须产生VPTR，使得能找到VTABLE。由于VPTR在对象的开头，所以this的内容对应于VPTR。所以mov bx, word ptr[si]取出si（即this）所指的字，它就是VPTR。将这个VPTR放入寄存器bx中。放在bx中的这个VPTR指向这个VTABLE的首地址，但被调用的函数在VTABLE中不是第0个位置，而是第2个位置（因为它是这个表中的第三个函数）。对于这种内存模式，设每个函数指针是两个字节长，所以编译器对VPTR加4，计算相应的函数地址所存在的地方，注意，这是编译时建立的常值。所以我们只要保证在第二个位置上的指针恰好指向adjust()。幸好编译器仔细处理，并保证在VTABLE中的所有函数指针都与相同的次序出现。

一旦在VTABLE中相应函数指针的地址被计算出来，就调用这个函数。所以取出这个地址并马上在这个句子中调用：

call word ptr [bx+4]

最后，栈指针移回去，以清除在调用之前压入栈的参数。在C++的汇编代码中，我们将常常看到调用者清除这些参数。但这依处理器和编译器的实现而有所变化。
