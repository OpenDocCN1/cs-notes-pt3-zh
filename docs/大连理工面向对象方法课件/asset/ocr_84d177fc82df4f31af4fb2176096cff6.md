（续）、private和protected，它们的作用我们将在下面作说明，**base-class**是基类的类名。

与指定类中的成员的访问权限相仿，我们可以使用访问限定关键字指定派生类对基类成员的访问权限。

**注意：对于使用不同继承方式（public、private和protected）派生的类，对于基类中以不同方式（public、private和protected）定义的成员的访问限制是不同的。**有关内容见表所示。

表 不同派生方式得到的派生类对基类成员的访问权限

| 基类成员所使用的关键字 | 派生类对基类的继承方式 | 派生类对基类成员访问权限 |
|---|---|---|
| public（公有成员） | public | 相当于使用了public关键字 |
| public（公有成员） | protected | 相当于使用了protected关键字 |
| public（公有成员） | private | 相当于使用了private关键字 |
| protected（受保护成员） | public | 相当于使用了protected关键字 |
| protected（受保护成员） | protected | 相当于使用了protected关键字 |
| protected（受保护成员） | private | 相当于使用了private关键字 |
| private（私有成员） | public | 不可访问 |
| private（私有成员） | protected | 不可访问 |
| private（私有成员） | private | 不可访问 |

# 结论：

从表可以看出，无论使用哪种方式生成的派生类，其成员函数都可以访问基类中除了private方式生成的派生类以外的其它成员。

如果希望基类成员能够被派生类所访问，而同时又不希望被类外部的其它函数直接访问，那么应该使用的基类成员限定符是protected，而不是private。

# 小结：

+   1. 对于以public方式生成的派生类，在基类中使用public和protected关键字限定的成员，在派生类中仍相当于使用了public和protected关键字；
+   2. 对于以protected方式生成的派生类，在基类中使用public和protected关键字限定的成员，在派生类中都相当于使用了protected关键字；
+   3. 而对于以private方式生成的派生类，它们都相当于使用了private关键字。
