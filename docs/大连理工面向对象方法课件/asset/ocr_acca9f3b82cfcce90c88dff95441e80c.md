1) 它分离了具体的类：
一个工厂封装了创建产品对象的责任和过程，它将客户与类的实现分离。客户通过它们的抽象接口操纵实例。产品的类名也在具体工厂的实现中被分离；它们不出现在客户代码中。

2) 它有利于产品的一致性：
当一个系列中的产品对象被设计成一起工作时，一个应用一次只能使用同一个系列中的对象，这一点很重要。而AbstractFactory很容易实现这一点。

3) 难以支持新种类的产品，难以扩展抽象工厂以生产新种类的产品：
因为AbstractFactory接口确定了可以被创建的产品集合。支持新种类的产品（增加新的产品等级结构）需要扩展该工厂接口，这将涉及AbstractFactory类及其所有子类的改变。

# 二. 工厂方法

# 1. 意图

定义一个用于创建对象的接口，让子类决定实例化哪一个类。Factory Method使一个类的实例化延迟到其子类。

# 2. 适用性

在以下情况发生时可以考虑使用工厂方法模式：
● 有继承关系，需要创建多个子类的对象时；
● 类无法预计出必须创建哪个类的对象，也就是当一个类希望由它的子类来指定它所创建的对象的时候；
● 当类将创建对象的职责委托给多个子类中的某一个，类要使用其子类制定出所要创建的对象。
