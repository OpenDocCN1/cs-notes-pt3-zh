一个对象象一个软件构造块，它包含了数据结构和提供相关的行为。对象本身可
为用户提供一系列的服务——可以改变对象状态、测试、传递消息等，用户无需知道
服务的任何实现细节，操作完全是封闭的，也就是说对用户是透明的。

抽象数据类型是面向对象程序设计的中心概念之一。
在大多数面向对象程序设计语言中，类的定义描述以抽象数据类型为基础的对象
行为，抽象数据类型定义了能以类为基础执行所有操作的接口。类定义也指定了实现细节
或类型的数据结构。通常这些实现细节仅在该类范围内存取，称这种类型为私有类型
（Private）；当数据类型的全部或部分在该类范围外存取时，称之为公共（Public）类
型。

为一个类定义的所有操作称为方法（Method），这相当于面向过程编程方法中
独立定义的过程或函数。
一个对象（Object）是被一个特定类说明的变量，它通过包含在类内的所有域的拷贝
（Private 或 Public 两部分）来封装。通过访问一个或几个在类上定义的方法，可以对该对象
实现各种操作。
每个类变量或对象表示该类的一个实例（Instance）。

面向对象方法通过子类提供类型的等级层次。一个子类（Subclass）定义一个对象
集合的行为，该对象继承父类（Parent）的各种特征。借助建立子类的方法，可使软件开发
的周期缩短，从而降低开发复杂性和费用。

# （二）面向对象软件系统的特点

面向对象软件系统的结构建立在一系列类上，这些类刻画了系统中所有要处理
的基本数据类型的行为。面向对象程序设计集中在对数据操作而不是对过程操
纵。

比如，在我们编写的任意整数排序的程序中，不用类的方法就是面向过程的设计方法，
而用类的方法就是面向对象的方法。
在前者中，我们定义了数据结构后，以后的精力都集中在了函数或过程的设计、
处理中，需求变化后，不仅数据结构需要修改，而且相应的过程也要修改；
在后者中，对数据的操纵一直和数据密切相关，类的定义同时就包含了数据结
构和相应操作的定义，而不是分开来独立进行的。
定义一个面向对象软件系统的结构框架和一个高层体系结构，最终只表现为一
系列类（子类）及它们的定义和对象，用方法接口描述每个类的行为特征。
类中定义的方法的接口可以和实现细节的定义分开，这就导致了概念（与方法接口
有关的类定义）和它的实现（实现这个类的数据结构和算法的代码）的分离，这一点在
面向对象的程序设计中非常重要，因为它可以提高系统的可重用性、控制维护花费。
