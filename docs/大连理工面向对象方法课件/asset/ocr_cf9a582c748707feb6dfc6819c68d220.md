# ## (4) 安装vpointer(即vptr)

a. 因为VPTR决定了对象的虚函数的行为，所以我们会看到VPTR总是指向相应的VTABLE是多么重要。在VPTR适当初始化之前，我们绝对不能对虚函数调用。
b. 记住：能保证vptr初始化的地点是在：构造函数中。
c. 但是，在前面的WINd例子中没有一个是有构造函数的。
d. 这样，缺省构造函数的创建是很关键的。在WINd例子中，编译器创建了一个缺省构造函数，它只做初始化VPTR的工作。所以，调用虚函数是安全的。

# ## (5) 对象与（指针和引用）是不同的

记住：向上映射仅处理地址。这是非常重要的。
如果编译器有一个它知道确切类型的对象，那么（在C++中）对任何函数的调用将不再用晚绑排，或至少编译器不必须用晚绑排。因为编译器知道对象的类型，为了提高效率，当调用这些对象的虚函数时，很多编译器使用早绑排。下面是一个例子：

```
```cpp
//: C15:Early.cpp
// Early binding & virtuals
#include <iostream>
using namespace std;

class Base {
public:
	virtual int f() const {
		return 1;
	}
};

class Derived : public Base {
public:
	int f() const {
		return 2;
	}
};
