可重用性使得用户无需关心类内部的方法是如何实现的，也就是说，从用户观点来说，方法实现被包含在隐藏细节的“黑盒”中。可维护性也很重要，因为改变数据结构和算法（即实现类的代码）仅局限于实现这个类或类的一部分的代码区域内，这给维护提高了极大方便。

面向对象的程序设计中，把密切相关的数据与过程定义为一个整体（即对象），而且一旦作为一个整体定义了之后，就可以使用它而无需了解其中的实现细节。面向对象软件系统的构造不仅被用于对象的内部结构，而仅依赖于能在对象内部数据上实行操作的方法。

封装和数据隐藏使软件设计者避免了许多维护问题，一旦数据（类型）结构修改了，仅对实行模型的代码局部区域作适当变化，软件系统其余部分原则不动。

用户在使用时，只需定义一个相关类的对象，通过调用其中的方法如有储来实现相应的操作，而不必关心存储这一方法在类中是如何定义及实现的。改变数据结构和算法时，只需修改类的定义部分，而不涉及整个软件系统。

再比如在我们的排序程序中，当数据结构变化时，仅需修改类 sort 的定义部分（一般不提倡，也不应该），而其他部分不用修改。而在非面向对象的设计中，我们需要修改的还包括实现排序的过程或函数。
在面向对象程序设计中，对象而不是函数或过程代表问题解的真正环节。

面向对象的程序的最根本的目的是使程序员更好的理解和管理庞大而复杂的程序，它在面向过程程序设计的基础上完成进一步的抽象。这种在设计方法上更高层次的抽象正是为了适应目前软件开发的特点。

+   特点：
+   （1）自然、直观；
+   （2）继承为复用提供了有效手段；
+   （3）类与对象成为基本的模块；
+   （4）多态性增强了操作的透明性、可理解性和可维护性；
+   （5）吸取了结构化程序设计的优点，追求的目标是将现实世界的问题求解尽可能简单化；
+   （6）将数据和对数据的操作放在一起，作为一个不可分割的整体来处理，它采用抽象和信息隐藏技术。将对象及对象的操作抽象成一种新的数据类型——类，并且考虑了不同对象之间的联系和对类类的重用性。
