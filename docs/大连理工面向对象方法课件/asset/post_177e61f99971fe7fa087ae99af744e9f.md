**解决方法：** 将基类析构函数声明为虚析构函数，这样就会使所有派生类的析构函数自动成为虚析构函数（即使他们与基类析构函数名不同）。这时，如果像上面那样使用 `delete`，系统也会调用相应的析构函数。

### 一、引用参数

引用(reference)就是给变量起一别名（&）。（注意：引用和指针的区别）

- 引用参数的说明一般要立即初始化（引用创建时初始化，指针就不同）。

```cpp
int value;

int& value1 = value; // 变量value1引用了value，或者说value1是对一个整形变量value的引用。
```

- 一个引用变量还可以被另一个变量再引用。例如：

```cpp
int a;
int & r1 = a;
int & r2 = r1;
r2 = 10;
// 或者 r2++;
```

// 相当于修改原始变量。（但是 r1, r2 不能再是其他变量的别名，对别名的所有操作实际上都是对原始变量本身的操作。编译器并不为别名保留空间）。

要点：任何引用必须和存储单元联系，访问引用，就是访问那个存储单元。

- 简单变量的引用称为独立引用。
- 函数参数和返回类型亦可为引用类型（这才是引用的主要用场。这两种引用方式可以解决给函数传递对象和从函数中返回值的问题）。常用的方法中，采用引用可以具有传递指针的效率。

## 二、操作符 new 和 delete

### 1. new

**语法：** `<指针变量> = new <类型>[参数]`（能返回所需分配类型的指针）

**语义：** 按 new 后面的类型及其参数分配适当大小（sizeof（<类型>[参数]）的内存。

例：

```cpp
int *p = new int;

int *p1 = new int(8);  // 将初始数据 8 装入所分配的空间

int *p2 = new char[10];  // 在堆区分配含有 10 个元素的字符型空间
```

### 2. delete

**语法：** `delete [参数] <指针变量>;`

**语义：** 释放指针变量所指的内存空间。

例：

```cpp
delete p;

delete p1;

delete [10] p2;  // 或 delete [] p2;  注意释放形式
```

**注意：** 用 new 分配的空间，使用结束后应该用也只能用 delete 显式地释放，否则这部分空间将不能回收而变成死空间。

## 三、void 型指针

- void 型作为指针的类型时，这种指针就是一种通用型指针。
- 当指针为通用型指针时，是指它可以接受任何类型指针的赋值，但对已获得的 void 型指针，对它再进行处理（如输出/传递指针值时），则必须再进行显式类型转换，否则将出错。

例3：

```cpp
void *p;

int i = 100;

p = &i;

cout << *p;  // 错误
```

```cpp
cout << *(int*)p; // 正确

char *c = "abc" ;

p = c; // c=p 则不可以

cout << p; // 错误

cout << (char*)p; // 正确

void **pp;

pp = p; // 正确

char *cc;

cc = p; // 错误
```

## 四、常量类型 const

- 一般情况下，const 和 define 在定义符号常量时功能几乎是一样的。

例：const float pi = 3.14; // 限定 pi 为 float 型的常量；
const int SIZE = 100; // 限定 SIZE 为 int 型的常量；

- 但在定义指针变量时，const 却有不同的地方。例如：

- (1) const char *pc = " abcd" ;// 指向串常量的指针

// 限定指针 pc 只能指向一个串常量，一旦赋值，它所指的值不能再修改。

但是可以把 pc 指向其他内存单元。即 pc 是一个可以用来读取值而不能用来修改值的指针（只读指针）。

- (2) char *const pc = " abcd" ;// 指向串的常量指针，pc 指向的值可以被修改，但是不能把 pc 指向其他内存单元。

- (3) const char *const pc = " abcd" //（1）、（2）的综合

- (4) 另外：赋值时注意：

pc[1] = ' s' // 错

pc = " xyz" // 正确

## FACADE（外观，门面）—对象结构型模式

### 1. 意图

为子系统中的一组接口提供一个一致的界面，Facade 模式定义了一个高层接口，这个接口使得这一子系统更加容易使用。

### 2. 动机

将一个系统划分成为若干个子系统有利于降低系统的复杂性。一个常见的设计目标是使子系统间的通信和相互依赖关系达到最小。这可以通过引入一个外观（Facade）对象，它为子系统中较一般的设施提供了一个单一而简单的界面。

![](img/3b4669cf00b2833fe526284506f3f342_111_0.png)

例如有一个编程环境，它允许应用程序访问它的编译子系统。这个编译子系统包含了若干个类，如 Scanner、Parser、ProgramNode、BytecodeStream 和 ProgramNodeBuilder，用于实现这一编译器。

- （1）有些特殊应用程序需要直接访问这些类；
- （2）但是大多数编译器的用户（不需要直接访问这些类）并不关心语法分析和代码生成这样的细节；他们只是希望编译一些代码。

对于这些用户，编译子系统中那些功能强大但是又较低级的接口会使他们的任务复杂化。

为了提供一个高层的接口并且对客户屏蔽这些类，编译子系统还包括一个 Compiler 类。

这个类定义了一个编译器功能的统一接口。Compiler 类是一个外观，它给用户提供了一个单一而简单的编译子系统接口。它无需完全隐藏或实现编译功能的那些类，即可将它们结合在一起。编译器的外观可方便大多数程序员使用，同时对少数懂得如何使用底层功能的人，它并不隐藏这些功能，如下图所示。
