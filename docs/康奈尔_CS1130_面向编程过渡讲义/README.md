

# 模块 1.1 结构化与算法化方面

#### 概述

编程语言有两个主要方面：

-   1. 算法化或过程化方面。
-   2. 结构化或组织化方面。

你可以将其类比为烹饪书。每个菜谱都是按顺序进行的一系列指令，用于烹饪某种食物。这就是算法化方面。

菜谱可以按章节进行组织 - 开胃菜、主菜、甜点、面包等。每个章节可以进一步细分为小节。这就是组织化方面。

在编程语言中，算法化方面主要涉及赋值语句、条件语句、循环和过程/函数调用的序列。

当编程语言首次发明 - 从20世纪50年代的Fortran开始，到20世纪60年代的Algol、Lisp和Cobol - 主要的组织工具是子程序（今天称为函数、过程或方法），它对应于烹饪书中的菜谱。要给程序添加更多功能，只需添加更多的子程序，每个子程序都有自己的功能。这种相对平面的结构无法很好地扩展！由数百甚至数千个子程序组成的软件系统很难管理和维护。然而，子程序继续是流行编程语言中的主要结构机制，一直延续到20世纪80年代。

还开发了各种其他组织方法。其中许多是围绕模块进行组织的，模块可以包含子程序和其他内容。但最成功的组织方法是面向对象，或称为OO。

## OO的基础知识

下面是一个类比，可以了解OO的基本思想。一个典型的办公室有文件柜。每个抽屉里都有一堆信封。一个抽屉里的文件夹包含完全相同类型的信息。它们包含数据（例如人的姓名和地址，他们欠的金额）。此外，对于OO，它们还包含指令（称为方法）来执行对数据的操作-更改数据，检查数据，进行计算。因为指令已经放在每个信封中，办公室的任何人都可以做任何工作。

在OO中，每个文件柜称为一个类，文件柜中的每个信封称为该类的对象。

此外：

-   1. 可以编写一个类定义，该类定义了类的文件夹的格式 - 每个文件夹包含哪些数据和指令。
-   2. 文件抽屉（类）SC的类定义可以说，嘿，让我的文件夹包含与类C定义的相同类型的数据和指令，还可以定义更多的数据和指令。SC继承自C的所有内容。例如，康奈尔大学本科生的文件夹将包含康奈尔学生类的所有信息和指令，以及仅适用于本科生的任何信息和指令。
-   3. 有一种简单的方法可以创建一个新的文件夹（对象）放入文件抽屉（类）中。

现在你了解了面向对象的一些基本特性。这门课程CS1130将向你展示这些特性如何在Java编程语言中实现。

## 面向对象的历史

面向对象的起源可以追溯到20世纪60年代末开发的Simula 67语言。但是当时尝试的东西并没有完全被理解，它的思想没有得到普及。这在科学和工程中经常发生。以下是其他例子。查尔斯·巴贝奇在19世纪50年代构思了计算机，并设计并试图建造一些计算机。他当时没有电！但是第一台工作的计算机直到20世纪40年代才被制造出来。

SmallTalk-71是为了尝试Simula 67中的"消息传递"思想而开发的，并且在整个1970年代在施乐帕洛阿尔托研究中心（PARC）进行了进一步的探索。在20世纪80年代初，SmallTalk-80向世界展示了，对面向对象的兴趣增加，导致面向对象被纳入其他语言中。例如，C++语言是C语言的面向对象版本。

如今，面向对象在许多语言中以某种形式出现，例如Eiffel、C++和当然还有Java，只是举几个例子。不要期望所有面向对象语言的外观完全相同，但基本思想是相同的。

在Windows机器上，我们有时会遇到一个错误，系统找不到一个名为tools.jar的文件。如果发生这种情况，你需要选择该文件的正确位置。它通常在一个类似于以下位置的文件夹中

```
C:\ProgramFiles\Java\jdk1.6.0_29\lib ools.jar
```

然而，确切的文件夹可能因您的Java版本而异。您还可以使用桌面工具在计算机上搜索此文件。

```
编辑 / 首选项 / 资源位置 / Tools.jar 位置
```

然后输入或浏览到正确的位置。

## 类型和int类型

类型是一组值，以及对它们的（原始的）操作。记住这个定义！在处理Java时，这个术语会一次又一次地被使用。

-   整数类型在数学、科学和工程中经常使用：

-   整数类型：
    值：整数集合 {...,-3,-2,-1,0,1,2,3,...}
    操作：否定，或一元减号 -b
    加法b + c，
    减法b - c，
    乘法b * c，
    除法 /。

整数必须存储在计算机的内存位置上，而计算机的内存容量是有限的。因此，Java，与大多数编程语言不同，不使用类型 *integer*。相反，它有一个类型 **int**，其中的值限制在范围-2<sup>31</sup>到2<sup>31</sup>-1之间。选择这个范围是因为今天的计算机中的数字是以32位或4字节的序列方式存储的。你不需要确切地知道值是如何存储在4个字节中的。

## 类型int的操作

-   类型 **int**的操作与类型*integer*的操作相同，只是增加了一个新的操作，余数%。
    我们将在一分钟内讨论这些操作。但在我们讨论之前，我们提到了Java设计者们决定的一个重要原则：

    原则：每个类型 **int**的基本操作必须产生一个 **int**。
    我们使用这个原则来帮助回答关于类型 **int**及其操作的问题。

-   我们现在使用DrJava的交互面板来研究一些int类型的属性。首先，一元减法、加法、减法和乘法的运算结果与预期相同。

但是除法呢？根据int运算必须产生int的原则，6 / 4不能得到1.5。对于6 / 4的值，有两种可能的选择：要么截断为1，要么四舍五入为2。Java设计者选择了向零截断，所以6 / 4 = 1，-6 / 4 = -1。

百分号%用于求余操作，6 % 4是6除以4的余数。所以，6 % 4 = 2，6 % 3 = 0。

## int类型的最小值和最大值的名称

-   Java为int类型的最小值和最大值定义了名称：

    ```
    Integer.MIN_VALUE      和      Integer.MAX_VALUE
    ```

    稍后，我们将看到为什么它们具有这些奇怪的名称，其中包含一个句点。现在，只需使用它们。

-   由于Integer.MAX_VALUE是int类型的最大值，你认为将1添加到Integer.MAX_VALUE会产生什么结果？有几种可能性，Java的设计者必须选择一种。你认为应该是什么？请注意，没有“错误”的答案。每个选择都有原因，设计者只是选择了其中之一。

    一种选择是使Integer.MAX_VALUE + 1的计算产生错误并停止执行，以便程序员或用户知道发生了错误。另一种可能是返回Integer.MAX_VALUE本身，甚至可以说是0。Java选择了另一个答案；Integer.MAX_VALUE + 1产生了int类型的最小值-值“环绕”。要知道为什么选择了这个值，就必须了解计算机中实现算术的一些知识，而我们在这里不涉及这个。

    在这门课程中，你编写的程序将展示出这种环绕效应，你不需要担心这种“溢出”现象。

## char类型

#### 概述
char类型的值是您可以在键盘上输入的字符，还有很多其他字符。

char类型的字面值用单引号括起来表示。下面的最后一个例子是空格字符，您可以通过键盘上的空格键输入。

`'a'      'Z'      '<'      ' '`

尝试在DrJava交互窗格中输入`''`，您会有一个惊喜。它会产生一个错误消息。问题在于第二个单引号是模棱两可的——它是字面值的结束还是表示单引号字符？为了解决这种歧义，Java和许多其他语言使用转义字符 `\` 来表示像单引号这样的字符，就像这样：

## 双精度类型
#### 概述
双精度类型的值是对实数的近似值。例如：

`1.8  3.0  0.000005`

在本课程中，我们不会大量使用双精度类型，并且在这里只提供基本概述。 有关更多信息，请参阅 Gries/Gries 的第 1.1.2 节（第 18 页）。 此外，还可以使用 Gries/Gries 的第 6.4 节，第 221-224 页和课程实时 CD 上的第 6-3 和 6-4 页作为双精度类型的参考。

双精度类型的值是对实数的近似值，因为实数具有无限数量的小数位，而每个双精度数占用固定数量的位。 实数有无限多个值，而双精度数只有有限个值。

例如：
在DrJava交互窗格中计算 `0.1111111111111111111111111111111` 结果为 `0.111111111111111`。

而且，令人惊讶的是：
在交互窗格中，`1.0/9.0` 的计算结果为 `0.11111111111111111`
在交互窗格中，`0.1/0.9` 的计算结果为 `0.11111111111111112`。

在数学中，我们使用科学计数法，例如 `3.1*10⁷`，表示3.1乘以10,000,000。在Java中，这个数可以写作 `3.1E7`。在这种表示法中，E左边的数字称为尾数，右边的数字称为指数。尾数被截断为大约16-17位小数。

使用以下方法获取最大和最小的正值：
- `Double.MIN_VALUE`: `4.9E-324`
- `Double.MAX_VALUE`: `1.7976931348623157E308`

下表列出了 double 类型的操作。它们的表现如预期，但由于 double 数的有限性，会出现"舍入误差"。

| 操作 | 名称 | 示例 |
| :--- | :--- | :--- |
| 一元 - | 否定 | `-3.8` |
| 一元 + | 无操作 | `+7.13E11` |
| + | 加法 | `1.3E7 + 2.4E8` |
| - | 减法 | `3.14 - 2.73` |
| * | 乘法 | `8.0 * 2.5` |
| / | 除法 | `1.0 / 9.0` |
| % | 余数 | `5.1 % 2.0` |

如果一元减号、`-`、`+`、`*`、`/`、`%` 的操作数是 `int` 类型，则该操作是一个 `int` 操作。如果至少有一个操作数是 `double`，则该操作是一个 `double` 操作，并且如果需要，其他操作数首先转换为 `double` 类型。

## 布尔类型
在某些编程语言中，例如Matlab和C，整数用于表示逻辑值 **true** 和 **false**。通常，0用于 **false**，任何其他整数都可以用于 **true**。

Java处理布尔值的方式不同。有一个（原始）类型 **boolean**，其值为 **true** 和 **false**（仅此而已）。该类型有五个操作，其操作数为布尔值：
- 类型 **boolean** 值： **true**， **false**
- 操作： **!** （非）、 **&&** （与，或合取）、 **||** （或，或析取）、 **==** （等于，或等价）、 **!=** （不等于，或不等价）

下面是定义这五个操作的表格。

| **b** | **c** | **!b** | **b && c** | **b || c** | **b == c** | **b != c** |
|---|---|---|---|---|---|---|
| **false** | **false** | **true** | **false** | **false** | **true** | **false** |
| **false** | **true** | **true** | **false** | **true** | **false** | **true** |
| **true** | **false** | **false** | **false** | **true** | **false** | **true** |
| **true** | **true** | **false** | **true** | **true** | **true** | **false** |

我们在交互窗格中评估了一些表达式，并讨论了这些操作。

- `!` ，读作“非”，是一元逻辑否定。! **false** 是 **true**，而 ! **true** 是 **false**。
- `&&` 读作与，因为 `b && c` 当且仅当 b 和 c 都为真时为真。
- `||` 读作或，因为 `b || c` 当且仅当 b 或 c（或两者都）为真时为真。
- `==` 用于判断相等： `b == c` 当且仅当 b 和 c 具有相同的值时为真。
- `!=` 用于不等式： `b != c` 当且仅当 b 和 c 具有不同的值时为真。

## 关系
六个关系操作数用于生成布尔值。

- **b == c**, **b != c**, **b < c**, **b <= c**, **b > c**, **b >= c**

你可能在其他编程语言中见过这些关系，所以我们不会在这里详细介绍。唯一奇怪的地方是使用 **==** 表示相等，而不是 **=**。以下是示例。

- **5 < 6** 为真
- **5 >= 6** 为假
- **5 < true** 是非法的，因为一个操作数是 **int** 而另一个是 **boolean**。

这些关系运算符适用于所有数字类型 — **int, double, char** 等。例如，我们可以测试 **5 < 6.2** 是否为真，或者 **6.0 == 7** 是否为真。如果两个操作数的类型不同，其中一个会被转换为另一个类型，以便进行操作。更多关于这种转换的内容稍后介绍。

#### 短路评估
评估表达式：
```
5/0 == 3 && false
```
由于除以0而导致错误，这是可以预料的。但是反转操作数后对相同表达式的评估不会产生错误消息 - 它产生了值 **false**。

同样地，`true || c` 是 `true` 无论 c 的值是什么，所以在这种情况下不会对 c 进行求值。表达式 `b || c` 等同于：
如果 b 为真则返回 `true`，否则返回 c，或者在 Java 表达式中为 `b ? true : c`。

正如你将在几个作业中看到的，短路求值是编写布尔表达式的有用工具。

## 字符串类型
类型 `String` 与原始类型 `int` 和 `double` 不同。`String` 是一个类类型。我们将在稍后解释这意味着什么，之后我们将解释什么是类。

每个 `String` 类型的值都是一个字符序列。我们通过将字符序列括在双引号 `"` 中来表示一个值。你可以在DrJava的交互窗格中看到这些字面量会求值为它们自身。第二个例子包含一个大写字母和三个空格，或者空白字符，它是一个字符。最后一个例子展示了空字符串，即不包含任何字符的字符串。

`"第一个"  "价格是$25.00。"  "5 <= 20"  ""`

使用换行符 `"\n"` 表示跳转到新行。例如，注意 `"1234\n"` 的评估显示在两行上。换行符以所谓的转义字符反斜杠开头。使用转义字符来写入反斜杠本身，以及双引号字符。例如，注意字符串字面值 `"1\\2\"3"` 的评估结果是包含字符1、\、2、"和3的字符串。在文本第6章中查找使用转义字符编写的其他字符。

#### 连接 (String +)
类型 `String` 的一个操作：连接（或拼接），用于将一个字符串附加到另一个字符串。表达式 `"将此存储" + "在s中。"` 的结果是值 `"将此存储在s中。"`

这是一个有用的规则：
如果 `+` 的一个操作数是一个字符串，那么另一个操作数会被转换为字符串并执行连接操作。

我们来看一些使用这个规则的例子。首先，观察常量1如何被转换为一个字符串。其次，观察两个数字首先相加，因为有括号，然后结果被转换为一个字符串以便进行连接操作。如果去掉括号，`+` 操作将从左到右执行，所以两个 `+` 都是连接操作：
```
"three" + 1 // 得到"three1"
"three" + (1+2) // 得到"three3"
"three" + 1 + 2 // 得到"three12"
```

这是一个有用的技巧：使用空字符串进行连接，将任何表达式的值转换为一个字符串。
```
"" + (945 - 3/2.0) 得到 "943.5"
```

#### 有用的函数
类型字符串提供了许多函数。我们解释其中四个。

**长度**。对于一个字符串 s，`s.length()` 返回 s 中的字符数。在我们介绍类之后，这种带有点的有趣表示法将变得有意义。
```
"love".length() // 返回 4
```
你可以获取任何字符串表达式的长度，而不仅仅是字面值。在这里，连接首先执行以产生一个字符串值，然后获取它的长度。
```
("non" + "violence").length()
```

## 字符串类型
#### 字符的位置或索引
有两个函数用于获取字符串的子部分，要理解这些函数，你必须知道一个字符串的第一个字符位于位置0，第二个字符位于位置1，依此类推。因此，字符的编号从0开始，而不是从1开始！位置更常被称为字符的索引。

**charAt**。对于一个字符串 s，`s.charAt(i)` 给出了在位置 i 处的字符 s。以下是一些例子。
```
"Truth".charAt(0)    // 得到 'T'
"Truth".charAt(4)    // 得到 'h'
```
对于 `charAt(i)` 合法，i 必须是一个有效的位置编号或索引。否则，执行将中止并显示错误消息。例如，`"T".charAt(2)` 会导致 `StringIndexOutOfBoundsException`，表示无效的索引。所以要小心。无论何时你写一个函数调用 `charAt(i)`，请确保 i 在适当的范围内。

**substring**。函数 `substring` 提取字符串的子串。例如，
```
"0123456".substring(1,4);
```
提取由位置 1、2 和 3 处的字符组成的字符串，但不包括位置 4 处的字符。第一个参数指定开始位置。第二个参数指定要提取的最后一个字符之后的索引。

如果省略第二个参数，结果将包含从第一个参数到字符串末尾的每个字符:
```
"harmony".substring(2);    // 得到 "rmony"
```
如果子字符串调用的参数相等，则返回空字符串 `""`。
```
"harmony".substring(2,2) 是 ""
```
甚至可以请求一个空字符串的子字符串:
```
"".substring(0,0) 得到 "".
```

**相等性**。请不要使用 `s1 == s2` 来测试字符串 s1 和 s2 是否相同，因为它不会按照你的想法工作——因为 `String` 是一个类类型。再次，你必须等到我们讨论类才能理解这一点。这是一个例子，用来说明 `==` 不起作用:
```
"abc" == "ab" + "c" // 是false
```
测试字符串相等的正确方法是使用函数 `equals`:
```
"abc".equals("ab" + "c") // 是true
```

#### 函数调用
你从高中开始就见过函数调用，像：
```
sqrt(25)       // 25的平方根. 它的值是 5.0.
abs(-7)        // -7的绝对值. 它的值是 7.
cos(0)         // 角度为0的余弦. 它的值是 1.0.
min(5, 7)      // 5和7的最小值. 它的值是 5.
```
你将在以后学习如何在Java中编写函数。这里我们只看一下如何调用函数。

函数调用的形式为：
```
<函数名> (<参数>)
```
其中 `<参数>` 是由逗号分隔的表达式列表。你在这里看到的前三个函数调用有一个参数。最后一个函数调用有两个参数——表达式5和7——它们之间用逗号分隔。你甚至见过一个没有参数的函数：函数 `length`（还记得关于类型 `String` 的讲座吗）。

请记住函数调用的术语参数。你可能会看到它被称为实际参数。我们不使用这个术语，因为它很容易引起混淆，当我们讨论编写函数本身时，你会明白的。

函数调用是一个表达式，你可以在任何可以放置表达式的地方放置一个函数调用，就像你可以在这个表达式中看到的一样：
```
1 + min(5, 7) * 2
```
其次，由于函数调用是一个表达式，它可以被计算出来以产生一个结果。表达式 `min(5,7)` 的值是5，所以上述表达式的值是11。

由于Java是强类型的，函数调用的参数必须具有特定的类型。例如，你不能要求一个布尔值的平方根。函数调用的值也有一个特定的已知类型。

Java有成千上万个内置函数供你使用。在这里，我们告诉你一些数学函数。它们的名称以“Math.”开头——这个原因以后会变得清楚。

Math.sqrt(double)        // 返回一个 double。
Math.sqrt(25.0)     // 25.0的平方根。它的值是 5.0。
Math.sqrt(5.0)      // 5.0的平方根。它的值是2.23606797749979。
Math.sqrt(25)       // 25.0的平方根。它的值是 5.0。
Math.sqrt(5)        // 5.0的平方根。它的值是2.23606797749979。
```

```
Math.abs(int)          // 返回一个 int 值。
Math.abs(5)       // 绝对值为 5的值是 5。
Math.abs(-5)      // 绝对值为 -5的值是 5。
```
实际上，有几个绝对值函数，取决于参数类型。例如，
```
Math.abs(double)        // 返回一个 double。
Math.abs(5.0)     // 绝对值为 5.0的值是 5.0。它的值是5.0。
Math.abs(-5.0)    // 绝对值为 -5.0的值是 5.0。

```
Math.min(int, int)      // 返回一个 int。

## 运算符的优先级

你知道乘法 * 的优先级高于加法 +。 也就是说，表达式 5 + 4 * 3 的计算结果就好像它被括号括起来一样：5 + (4 * 3)。

数学中有关运算符优先级的约定，以减少在编写复杂表达式时所需的括号数量。 其中一些约定在全世界范围内都是标准的，比如 * 优于 +。其他的则不是。

下面是 Java 运算符的优先级表。 如果你忘记了优先级，可以参考这个表格，或者 Gries/Gries 的第 227 页上的表格。

#### 运算符优先级表

| 顺序 | 运算符 | 示例 |
| :--- | :--- | :--- |
| 最高 | 一元运算符： | + - ++ -- ! |
| | 二元算术运算符：* / % | |
| | 二元算术运算符：+ - | |
| | 算术关系运算符： | < > <= >= |
| | 相等关系运算符： | == != |
| | 逻辑与运算符： | && |
| 最低 | 逻辑或运算符： | || |

例如，表达式

```
    (n != 0) && (10/n > 2)
```

可以很容易地重写为

```
    n != 0 && 10/n > 2
```

因为关系运算符优先于 &&。

#### 一些准则

##### 尽量减少冗余的括号（但不要牺牲清晰度）

你在编写表达式时的目标应该是使它们尽可能清晰简洁，这通常可以通过消除冗余表达式来实现——但你可以通过在优先级较低的运算符周围添加更多的空格来帮助读者。 例如，下面显示的两个赋值语句具有相同的含义，但第二个更容易阅读：

```
b= ((x<=y)||(x<=z));
b= x <= y || x <= z;
```

尽量减少冗余的括号。例如，在函数体内的返回语句中不需要它们（稍后你将学习有关返回语句的内容）。下面的两个语句是等价的，但第二个更容易阅读：

```
return (x >= -10 && x <= 10);
return x >= -10 && x <= 10;
```

##### 为了清晰起见，使用AND和OR时要加括号

### 赋值语句

赋值语句用于将一个值存储在变量中。与大多数编程语言一样，赋值语句的形式如下：

```
<变量> = <表达式>;
```

例如，一旦我们有一个 `int` 变量 `j`，我们可以将其赋值为表达式 `4 + 6`：

```
int j;
j = 4+6;
```

按照惯例，我们总是在 = 符号后面加一个空格，但在它之前不加。你不必遵循这个惯例。我们对此的原因在 Gries/Gries 的第 27 页上有解释。

一旦我们有了带有值的变量，我们可以在表达式中使用这些变量。例如，我们可以计算只包含 `j` 的表达式，或者计算 `2 * j` 的表达式，并且我们可以将表达式 `j + 1` 的值存储在另一个变量 `k` 中：

```
j
2*j
int k;
k = j + 1;
k
```

你必须记住赋值语句是如何执行的。如果被问到，你应该说：评估 <表达式> 并将其值存储在 <变量> 中。

请记住如何执行赋值语句的定义。为了确保你理解它，我们执行一系列的赋值操作，展示变量如何变化。

```

```

当我们执行赋值操作时，我们改变变量的值。我们不再绘制变量。只有一个变量 `j`，每当 `j` 被赋予新值时，它的值就会改变。

重要的是要意识到这只是一个声明和赋值的组合。对于同一个变量，写两个这样的初始化声明是行不通的，因为每个变量只允许有一个声明。

#### 变量和表达式的类型必须匹配

在 Java 的赋值语句中，变量和表达式的类型必须匹配。例如，如果一个是 `boolean`，那么另一个也必须是，如果一个是 `String`，那么另一个必须是 `String`。这是强类型原则的结果。

对于数值类型，有更多的灵活性。你知道有 `byte`、`short`、`int` 和 `long` 这些类型，它们有越来越大的值集合，还有两种浮点数类型，即实数类型，`float` 和 `double`。这些类型从所谓的最窄类型 `byte` 到最宽类型 `double`。

对于一个表达式是数字的赋值，规则是变量的类型必须至少与表达式的类型一样宽。

例如，如果我们有一个 byte 变量 b 和一个 int 变量 i，它们都包含0，将 b 赋值给 i 是合法的，但将 i 赋值给 b 是非法的。

```
byte b= 0;
int i= 0;
i= b;
b= i;   //非法
```

规则的原因应该很清楚。将更宽的类型值赋给更窄的类型变量可能会丢失信息或导致溢出。例如，如何将6000存储在一个 byte 变量中？

你可能会认为 Java 允许将一个 int 赋给一个 byte，但如果 int 值太大，它会在运行时报错。然而，这将违反 Java 中设计的强类型原则。

### 类型转换和混合原始类型

将一种类型的数据转换为另一种类型必须遵循类型转换的规则。 如果转换导致精度丢失，例如将 int 值转换为 short，则编译器将发出错误消息，除非进行显式转换。

要将类型 A 的数据转换为类型 B 的数据，在类型 A 的数据前面加上类型 B 的名称的括号：

```
A a = aData;
B b = (B)a; // 将类型 A 转换为类型 B
```

例如，将整数数据转换为浮点数：

```
int i=0;
float f;
f=(float)i; // 将 int 转换为 float
```

表达式可以自动提升为更宽的类型，无需显式转换：

```
int i=1;
long j=3L; // 字面值是 int 类型，因此需要 L 后缀
j=i;           // 正确
```

但是，不能将值分配给更窄的类型而不进行显式转换：

```
i=j;           // 将 long 赋值给 int 时出错
i=(int)j; // 正常
```

因此，具有较低精度（较少位）的数据类型可以转换为具有较高精度的类型，而无需显式转换。 然而，要将较高精度的类型转换为较低精度，需要显式转换，否则编译器将报错。

请注意，当将宽类型的值转换为更窄的类型时，例如将 `int` 值转换为 `byte` 变量时，高位字节将被截断。 也就是说，`int` 值中的最低位字节将被复制到 `byte` 值中。

#### 原始类型转换表

下面是一个表格，指示可以将给定的原始数据类型转换为其他原始类型之一。 符号 **C** 表示需要显式转换，因为精度在降低。 符号 **A** 表示精度在增加，因此可以自动转换而无需显式转换。 **N** 表示不允许转换。

| 类型 \ 转换为 | int | long | float | double | char | byte | short | boolean |
|---------------|-----|------|-------|--------|------|------|-------|---------|
| int  | -   | A  | A*     | A      | C    | C    | C  | N       |
| long   | C   | -  | A*     | A*     | C    | C    | C  | N       |
| float | C | C | - | A | C | C | C | N |
| double | C | C | C | - | C | C | C | N |
| char | A | A | A | A | - | C | C | N |
| byte | A | A | A | A | C | - | A | N |
| short | A | A | A | A | C | C | - | N |
| boolean | N | N | N | N | N | N | N | - |

星号 *表示在转换过程中可能会丢失最低有效位数，即使目标类型允许更大的数字。 例如，一个使用了所有32位的 int 类型值中的大值，在转换为 float 时会丢失一些较低的位数，因为指数使用了32位中的8位来表示 float 值。

#### 表达式中的混合类型

如果一个表达式包含了不同类型的操作数，较低精度或较窄的值操作数会被转换为较高精度或较宽的类型。 然后，如果结果要赋给较低精度的类型，必须进行强制类型转换：

```
float x, y=3;
int j, i=3;
x= i*y;          // OK, 因为 i 会被提升为 float
j= i*y;          // 错误, 因为结果是一个浮点数
j= (int) (i*y); // OK
```

将一个值转换为更宽或更高精度的整数或浮点数类型的过程称为"数值提升"。 Java 虚拟机规范对于表达式中的两个操作数的提升有以下规则，例如 x+i:

* 如果任一操作数的类型为 double，则另一个操作数将转换为 double。
* 否则，如果任一操作数的类型为 float，则另一个操作数将转换为 float。
* 否则，如果任一操作数的类型为 long，则另一个操作数将转换为 long。
* 否则，两个操作数将转换为 int。

### 条件表达式

条件表达式的目的是根据第三个布尔表达式选择两个表达式中的一个。 条件表达式的格式为

```
<布尔表达式> ? <表达式-1> : <表达式-2>
```

如果 <布尔表达式> 的值为真，则条件表达式的值为 <表达式-1> 的值；如果为假，则条件表达式的值为 <表达式-2> 的值。

一个重要的点是，在计算条件表达式时，只有 <表达式-1> 和 <表达式-2> 中的一个会被计算。例如，下面的表达式中的除以零不会引发错误，因为它不会被计算：

```
true ? 7 : 7/0
```

表达式 <表达式-1> 和 <表达式-2> 可以是任何表达式，只要它们具有相同的类型（如果一个比另一个宽，则较窄的将自动提升为较宽的类型）。

条件表达式被称为三元操作，因为它有三个操作数。

#### 使用示例

您可以在任何可以使用更传统表达式的地方使用条件表达式。 以下示例使用条件表达式将 c 设置为 a 和 b 中较大的值：

```
c = a > b ? a : b;
```

要小心。 条件运算符 ? 和 : 是所有运算符中优先级最低的。 在复杂情况下，使用括号来包围条件表达式是有帮助的。

下面是一个示例，创建一个指示 a 和 b 中较大值的字符串：

```
"a 和 b 中较大的是" + (a > b ? "a: " + a : "b: " + b)
```

尝试在交互面板中编写几个条件表达式，以便熟悉它们。 例如，编写一个表达式，找到三个值中的最小值 b, c, 和 d。

#### 谨慎使用条件表达式

如果滥用条件表达式，可能会导致代码难以阅读。 然而，在某些情况下，使用条件表达式可以使代码更短更简单。 例如，考虑将一个变量 s 设置为两个字符串的连接：(1) 如果 b 为真或假，则为”华氏度”或”摄氏度”，(2) 如果 c 为正数，则为“热”，否则为“冷”。我们可以写成：

```
s= (b ? "华氏度" : "摄氏度") + (c > 0 ? "热" : "冷");
```

如果不使用条件表达式来编写此赋值语句，您将需要一系列语句，并且可能至少使用两个条件语句 if (…) … else…。

### 强类型与弱类型

#### 安全性

编程语言中有时会寻求的一个特性是安全性。对于安全性的定义存在一些混淆，但以下是一个在2000年由一个临时委员会使用的定义，该委员会建议高级放置（AP）编程考试基于Java编程语言：

> 安全性：任何对数据的错误解释在编译时被捕获或在运行时生成一个明确定义的错误。

C和C++是不安全的。在这些语言中，数组索引操作 `b[k]` 可能被允许，即使 `k` 超出了数组的范围。也没有内置的保护机制来防止使用指针操作访问几乎任何内存部分。许多计算机病毒利用“缓冲区溢出”——类似于在数组边界之外写入——进行攻击。当然，程序员可以显式检查溢出，但语言不要求这样做。

在专业人士手中，“不安全”的特性可以被利用起来。但对于大多数程序员来说，提供安全性的语言具有巨大的价值。特别是对于初学者，安全性非常有帮助。

#### 强类型

安全性的大部分（但不是全部）是通过强类型来实施的——这个术语也没有很好地定义，所以让我们在这里解释一下。首先，每个变量和表达式的类型是一个语法属性——通过查看程序而不是执行它来确定的。其次，变量只能以符合其类型的方式使用——例如，不可能对 int 值执行 double 操作（int 值必须首先转换为 double 格式），或者将布尔值用作整数。因此，在语法上，不可能忽略操作数的类型，将一个值解释为它不是的东西。

#### 运行时安全特性

Java 的强类型支持对运行时行为的强保证，目标是确保没有值可以被解释为它不是的东西。对于 String 值，不可能索引不存在的字符。例如 `s.charAt(i)`，如果 i 不在范围 `0..s.length()-1` 内，将引发异常。同样，数组下标必须在数组的范围内。此外，在 Java 中不可能进行“指针算术”，就像在 C 和 C++ 中可以做的那样。在 Java 中，指针是我们称之为对象的“名称”，并且没有对这些名称进行任何操作。

#### 安全性和强类型的好处

一些错误是由于缺乏理解而产生的；另一些是由于思考和设计不足而导致的逻辑错误；还有一些只是拼写错误。 在所有情况下，编译时尽早发现错误可以节省大量时间。 安全性和强类型使得许多错误能够在早期被检测出来。

初学者会比专业程序员从安全性和强类型中获益更多，仅仅因为初学者倾向于犯更多类型的错误。 但是专业程序员也会从安全性和强类型的语言中受益。 当一个程序由数百个文件组成时，很容易混淆和犯错，而我们对程序进行的检查越多，我们就越好。

最后，对于像Java这样的语言，其程序可以通过编写小应用程序在网页上访问，安全性和强类型也有助于用户，因为这些特性使得恶意人员更难通过这些小应用程序侵入系统。

最后，我们在主体中放置了一个赋值语句，将参数 `n`分配给字段 `number`。然后编译。现在，在交互面板中展示，我们可以使用设置程序将一个值分配给字段，然后使用一个获取函数来检索该值。

现在让我们给出构造函数的规则。首先，构造函数是一种新的方法。它有一个目的，你应该记住:

> > 构造函数的目的: 在评估新表达式期间初始化新创建对象的一些或所有字段。

接下来，构造函数定义包括:

+   1. 一个访问修饰符 - 通常是 public，以便可以从任何地方调用构造函数。
2. 构造函数的名称，与类的名称相同! 注意，在构造函数定义中既没有类型也没有关键字 void。

+   3. 为每个在新表达式中要给出值的字段声明一个参数。

构造函数是第三种类型的方法。它与函数或过程不同，因为它没有返回类型或关键字void，并且它的名称是类的名称。现在，让我们看看如何调用它。

#### 函数 toString

#### 类 Chapter 的函数 toString

在 DrJava 的右上窗格中，你可以看到类 Chapter，有三个字段：章节编号、章节标题和上一章节。还有两个构造函数和 getter/setter 方法。我们经常希望能够获取这样一个类的对象的描述——我们希望以漂亮的格式显示字段的值，以清楚地表明哪个值是哪个。

获取一个类的对象描述的 Java 约定是在类中编写一个函数 toString。这是一个标准的规范，尽管在某些情况下可能会更详细。它是公共的，返回一个 String，它的名称是 toString，没有参数。我们插入了一个返回语句，以便可以编译并运行该类。

```java
/** = 本章的表示方式 —— 对于上一章，给出了章节标题。 */
public String toString() {
    return "";
}
```

现在让我们写真正的返回语句。让我们从单词章节开始；将章节编号、一个句点和一个空格连接到它上面；然后将标题和另一个句点和空格连接到它上面。对于上一章，我们必须小心。我们编写一个条件表达式；如果上一章的标题为空，我们附加“没有上一章”，如果不为空，我们附加上一章的标题，根据规范要求。

```java
return "章节 " + number + ". " + title + ". " +
    (prev == null ? "没有上一章"
        : "上一章标题： " + prev.title);
```

现在让我们来检查一下。我们创建两个章节类的对象——确保其中一个具有非空的上一章字段——并调用它们的 toString 函数。看看？

```java

Chapter c2 = new Chapter(2, "真相", c1);
```

这就是编写函数 toString 的全部内容。通常，结果包含所有字段，但有时候这会太多，一个不完整的 toString 函数就足够了。

我们为类 Point 编写了一个函数 toString，其中的实例包含一个点 (x, y) 在平面上——x 是水平坐标，y 是垂直坐标。我们有两个字段，x 和 y，并且有一个构造函数，允许在新表达式中初始化这两个字段。我们没有编写其他方法，因为它们对于这个演示不需要。

```java
/** = 表示这个点的 "(x, y)" */
public String toString() {

我们写出真正的返回语句。我们从开括号开始；将字段连接到它上面；连接一个逗号和空格；然后是字段 y，最后是闭括号。

#### Object类中的toString函数

由于Object是类层次结构的根，所以它的toString函数被每个类继承，因此该函数出现在每个对象中。

然而，如果您在一个类中定义了toString函数，您的定义将覆盖继承的函数。 因此，在之前的网络讲座中，我们在Point类中编写的toString函数覆盖了从Object类继承的toString函数。 因此，调用p.toString () 将调用覆盖的函数。

稍后，在第2个模块中，你将看到你仍然可以调用继承的函数。

#### 函数在类对象中相等

现在让我们转向对函数 equals的讨论，它也在类 Object中定义 ——就像这样：

（即，由于对象名称是唯一的，它们命名相同的对象）”。*/
public boolean equals(Object ob) {

}

我们已经在对象中展示了整个方法，以确保你理解它确实存在。 你以前可能没有看到过关键字 this的用法。 它指的是它所出现的对象的名称，在这种情况下，它指的是 a0本身。 因此，对该方法的调用测试了ob是否包含名称 a0。

### 方法的规范

你知道第一个函数 `mini` 的作用，因为它的规范在前面的注释中告诉了你。你不需要函数体——我们现在向你展示它。

你不知道第二个函数的作用，因为它的规范没有给出。要理解它的作用，你需要看它的函数体：`Integer.signum`。

方法的规范定义了对方法的调用会做什么。规范应该是精确的、完整的，并且尽可能清晰。这样你就不必查看方法体了。

事实上，每个方法都应该有一个规范，当编写对方法的调用时，你不应该查看方法体。方法体指示了任务的执行方式。当编写对方法的调用时，我们不想知道具体的执行方式，我们想知道任务是什么。规范应该告诉我们。

#### 编写过程规范

我们将方法规范写成紧接在方法之前的Javadoc注释。Javadoc注释以 `/**` 开始，以 `*/` 结束。下一节课将解释为什么我们使用Javadoc注释。

让我们开始讨论过程的规范。这里有两点要说明。

```
/** 将标题设置为t */
public void setTitle(String title){...}
```

1.规范中提到了每个参数的名称，并以解释参数用途的方式进行说明。如果规范没有提到某个参数，读者可能不理解该参数的用途，规范就是不完整的。

2.这个规范是一个命令去做某事。我们不说，“这个过程将标题设置为t”，或者类似的东西。我们说，“将标题设置为t。”这是因为我们使用它如下。假设我们调用了过程 `setTitle`：`setTitle("我想要和平")`；。弄清楚它的意思的方法是用规范替换它，但用参数替换参数：

将标题设置为“我想要和平”。

由于过程调用是一个命令去做某事，所以规范也应该是一个命令。

#### 编写函数规范

由于函数返回一个值，规范应该是对该值的描述。实际上，它应该说明函数调用的结果是什么。例如，函数`areAscending`的规范就是这样的。它说明了调用`areAscending(a, b, c)`的结果等于真假句子“a， b和 c按升序排列。”

```
/** = "a、b和c按升序排列"。 */
public static boolean areAscending(int a, int b, int c){...}
```

由于函数会计算出一个值，我们通常以等号开头来编写它们的规范。你可能会看到这样的规范：“如果a、b和c按升序排列，则返回true。”这种规范有一种操作性的感觉，我们不太希望有这种感觉。在数学中，如果有人问“sin(0)等于多少”，我们不会说“返回sin 0的值”，而是简单地说“它等于sin 0。”对于任何函数调用也是一样。

#### 编写构造函数的规范

下面是我们如何为构造函数编写规范。单词“构造函数”表示这是一个构造函数。它解释了新实例的属性——每个字段包含什么。请注意，规范中说明了前一章将是什么，即使没有参数。还请注意，所有参数都有解释：

```
/** 构造函数：一个新的实例，具有章节编号 n，章节标题 t，和前一章节 null。 */
public Chapter(int n, String t) {...}
```

### 良好的规范## 方法的规范

养成在编写方法体之前编写方法规范的习惯。有两个原因。首先，你不会忘记编写规范。其次，规范将帮助你作为程序员，在编写方法体时。你可以在编写方法体时参考规范。你不必记住规范的所有内容。

确保你的规范准确和完整。它必须与方法体一致。任何方面有错误的规范可能比没有规范更糟糕，因为依赖规范在调用方法时的程序员很可能会引入错误到他们的程序中。

最后，在调用时明确包含任何前置条件 —— 也就是，调用者必须满足的约束条件。例如，计算 r 的平方根的函数的规范应包括以下语句：

前置条件：r >= 0。

这样的前置条件不需要在函数中进行检查；只有在前置条件为真时，调用者才能调用该函数。

如果你意识到需要更改方法的功能，请先更改规范，然后再更改方法体。在这样做时要有纪律性，这样你就会减少错误。

## 测试

错误是程序中的一个错误。测试是分析和执行程序以确定是否存在错误的过程。我们在测试中的主要工具是测试用例：一组输入和预期输出。

- 调试是一个独立的过程。在检测到程序存在错误后，我们需要找出是什么导致了错误并将其删除。这个过程被称为调试。

#### 创建测试用例的原则

- 在本讲座中，我们专注于测试用例-如何开发它们，何时开发它们以及为什么开发它们。在作业中要求您编写一堆测试用例可能会感觉像是浪费时间。但是，如果您正确地完成这个任务，您会发现您的生产力会提高。

开发良好的测试用例很重要。一些公司有质量保证（QA）团队，他们只做软件测试 - 其他人，而不是原始程序员，在程序员认为他们的产品已经完成后进行测试。

- 在编写和测试方法时，要确切了解方法应该做什么。这意味着在方法体之前应编写方法规范。有些人主张在编写方法体之前，还要编写一组测试用例，因为这有助于我们理解方法应该做什么。当从其他人给我们的规范编写方法时，这可能很有用。

尽早且经常进行测试。越早测试方法，越早发现和修复错误。事实上，一旦编写了方法规范，就应该编写一个调用该方法的示例，这样即使在编写方法体之前，也会考虑到方法可能如何使用。

- 考虑整个输入集。不总是可行测试每个输入值，因为输入集可以是无限大的，比如整数集，所以我们需要一种策略来确保尽管我们的测试用例不包括所有输入，但它们足以保证我们的程序正常工作。

我们将给出一个整数有序对 (x, y) 的示例来说明这个原则。

- 首先，我们将把有序对 (x, y) 视为一个正方形。这个正方形中大约有 2^{64} 个点。测试所有这些点将会浪费时间，所以我们需要找到这个正方形中有兴趣区域的一组点。在这种情况下，我们可能想先测试所有四个象限中的一些点，例如 (15, 17), (-10, 20), (-100, -200) 或者 (134, -27)。然后，我们可能想尝试一些极端值或者边界情况，例如 -2^{31}（最小整数），或者 2^{31} - 1（最大整数），或者 0。还有一些我们可能会忽略的有趣值，例如 1 或者 -1。我们也可以将这个思想应用到不同的输入集合上。例如，如果我们的输入集合是一个 class，那么极端值将会是 null。

开发提供测试覆盖率的测试用例。如果执行这些测试用例将导致程序的每个部分至少执行一次，则一组测试用例提供测试覆盖。

一次只测试一件事。如果一次测试多个事物并且测试失败，你将更难弄清楚原因。此外，很容易迷失在你正在测试的内容中，并且更难确保你已经覆盖了所有情况。

在完成每个方法时彻底测试它。一旦测试了一个方法并且其正确性得到保证（尽可能），你就可以相当确定任何出现的错误不在该方法中。它存在于其他地方。这在开发测试用例、测试和调试时，很大程度上减少了需要调查的程序区域。

- 验证文档。在测试时，问自己一些在编写代码时通常不会考虑的问题。确保文档回答这些问题。

#### 创建测试用例的方法

- 穷举测试。对所有可能的输入进行测试，听起来很好，但对于大多数程序来说通常是不可行的，因为可能的测试用例太多。

- 黑盒测试，或功能测试。在制定测试用例时，只看程序的规范（而不是程序本身），决定要尝试哪些测试用例。程序是一个黑盒，你无法看到里面。

### JUnit 测试

DrJava 内置了一个机制，通过点击按钮，可以轻松创建一个类来维护一套测试用例，并在适当的时候运行所有测试用例。 这个机制在许多交互式开发环境中都被称为 JUnit。

现在我们展示如何使用 JUnit 测试器构建测试用例。

#### Panda 类

在 DrJava 中，我们有一个类 Panda，每个实例都维护有关熊猫的信息。 为了保持简单，这个类只维护熊猫的名字和父亲（如果已知）。 在实际情况中，会维护更多的信息。 有一个构造函数，两个 getter 方法和两个 setter 方法。 它们都必须进行测试，我们使用一个保存所有测试用例的 JUnit 测试类来完成这个任务。

#### 创建一个 JUnit 测试类

要创建一个 JUnit 类，请选择菜单文件项新建 JUnit 测试用例...。 在提示符处，输入一个类名作为此测试器。 我们建议测试的类名后面加上“Tester”一词。 点击按钮确定。

新类已创建。 将其保存在与类 Panda 相同的文件夹中。

导入语句表示类 TestCase 出现在包 junit.framework 中，类 PandaTester 扩展了 TestCase。 从类 TestCase 继承了几个方法。 稍后我们将展示其中一个的使用方法。

类 PandaTester 带有一个过程 TestX。 正如其注释所说，我们可以将 x 替换为我们自己的名称，并将其替换为 ConstructorGetters。

我们可以拥有任意数量的测试过程。 我们添加第二个用于测试设置方法的过程。

#### 编写一个测试方法

现在让我们编写过程的主体来测试构造函数和获取器方法。 首先，我们需要创建一些熊猫对象；让我们使用这两个赋值：

```
Panda p1 = new Panda("双", null);
Panda p2 = new Panda("林", p1);
```

请注意，我们创建了一个没有父亲的对象和一个有父亲的对象，以测试这两种不同的情况。

为了测试对象 p1 是否被正确创建，我们需要检查 p1 的每个字段是否具有正确的值。 可以使用继承的过程 assertEquals 来实现这个目的。 该过程测试其两个参数是否相等。 第一个参数是预期值，第二个参数是被测试方法产生的值。

在这里，我们编写了两个对 assertEquals 的调用，测试对象 p1 的获取器方法是否产生了正确的值：

```
assertEquals("双", p1.getName());
assertEquals(null, p1.getFather());
```

以相同的方式，我们插入语句来测试 p2 的 getter 方法：

```
assertEquals("林", p2.getName());
assertEquals(p1, p2.getFather());
```

为了展示出现错误时会发生什么，让我们改变第一个 assertEquals 调用的预期值，再次编译并点击按钮 Test。 现在，测试过程的名称变为红色，表示检测到错误，并且 assertEquals 的错误调用被突出显示。

我们以相同的方式测试设置方法，在过程 testSetters 中放置测试用例-在 assertEquals 调用中实现。我们编写代码创建一个熊猫。然后我们编写代码调用每个设置器方法，并检查它是否正确设置了字段。请注意，我们让熊猫 p1 成为自己的父亲。没关系，这只是为了测试目的。

#### 一些评论

有几点评论需要说明。

1. 首先，这些测试过程不需要放置规范，只要过程的名称能够说明正在测试的内容即可。
2. 其次，以 test 开头的每个方法都将在点击按钮测试时被调用。
3. 第三，注意有很多 assertEquals 过程，每个原始类型和每个类类型都有一个。你不需要考虑你调用的是哪一个；只需写出调用即可。
4. 第四，在调用 assertEquals 时，期望值是第一个参数，计算值（应该等于期望值）是第二个参数。
5. 第五，你需要编写多少个不同的测试过程取决于你。为每个要测试的方法编写一个测试过程将是太多的工作。不要这样做！另一方面，将所有测试用例放在一个测试过程中可能会使该测试方法过长且难以处理。不要这样做！

相反，尝试找到一个适当的平衡，将要测试的方法放入逻辑组中，例如，getter 方法、setter 方法，并为每个组编写一个测试过程，以便没有一个测试过程过长且易于维护。

## 调试

### 介绍

测试是运行程序与测试用例以尝试发现错误的过程。调试是寻找错误原因并修复错误的过程——一旦找到错误原因。通常错误原因与错误表现的地方相距甚远。

有些人讨厌调试，认为它是一项漫长、艰苦和令人沮丧的任务，就像在干草堆中寻找针一样。其他人喜欢调试，认为它是一项需要侦探技巧的问题解决活动，需要寻找证据并筛选，试图找出谁犯了罪。

有两种基本方法来追踪错误：

1. 使用 IDE 的调试功能。 在大多数 IDE 中，你可以打开“调试器”，它允许你逐步执行程序，观察变量值的变化。你还可以设置“断点”，然后让程序执行，当达到断点时它会停下来，让你调查变量的值。
2. 在程序的适当位置插入打印语句。然后执行程序并分析输出。

在本课程中，我们专注于第二种方法，即插入打印语句。下一个项目要求您观看 CD Program Live 上的几个讲座。这些讲座将逐步介绍调试程序的过程。程序的某个部分调用了一个函数 `anglicize`，将一个整数翻译成其英文等价物，例如 123 被翻译成“一百二十三”。函数 `anglicize` 似乎无法正常工作，需要进行调试以找出原因。

### 调试原则

ProgramLive 以及文本 Gries/Gries 提供了四个有助于追踪错误的原则。由于它们非常重要，我们在这里再次声明一次：

- 调试原则 1。在似乎有错误的方法的开头和结尾处放置打印语句，以检查其前置条件是否满足，并检查其是否返回正确的值。
- 调试最大化 2。从每个练习和测试用例中尽可能获取更多信息。
- 调试最大化 3。在适当的位置插入打印语句，以检查变量的值。
- 调试最大化 4。小心处理接口，因为它们是许多错误的源头。

### 自动装箱

在Java的4.0版本之前，像这样的赋值是非法的

```
Integer b;
b= 25;

int i;
i= b;
```

因为变量和表达式的类型不匹配——一个是 int，另一个是Integer类，所以这是非法的。

在Java的5.0版本中，引入了自动装箱，使得这样的赋值合法。在第一个赋值语句中，b= 25; 整数25会自动包装成一个新的 Integer实例；就好像程序员写了

```
b= new Integer(25);
```

在第二个赋值语句中，i=b; 由于需要一个 int值，所以从Integer中自动提取出int值；就好像程序员写了

```
i= b.intValue();
```

自动装箱是程序员的便利，使他们能够缩短代码。

自动装箱使用所有原始类型及其对应的包装类。例如，这是字符的自动装箱：

```
Character c= 'g';
```

此外，自动装箱可以在赋值以外的地方进行。

我们给出了int类型的自动装箱规则，并留给您写其他原始类型的规则。

int类型的自动装箱规则：如果一个类型为int的表达式e出现在期望（或可能）是Integer类的对象的位置上，表达式new Integer(e)将被用来替代e。以下是使用此规则的示例。函数isFive的参数是五，

```
/** = "obj is 5". */
public static boolean isFive(Integer obj) {
    return obj.equals(new Integer(5));
}
```

是整数类型。然而，在调用时，我们可以放入一个整数类型的值 int.

```
AutoboxDemo.isFive(5)
```

还有一个拆箱规则 - 从包装类对象中提取值的规则。这是class Integer 的规则; 你可以自己推广到其他包装类。

Integer 的自动拆箱规则: 如果一个类型为 Integer 的表达式 e 出现在期望类型为 int 的位置上，则使用表达式e.intValue()代替 e。以下是使用该规则的示例。函数 isFour 的参数,

```
/** = "c是4". */
public static boolean isFour(int c) {
    return c == 4;
}
```

我们可以使用调用 AutoboxDemo.isFour(new Integer(4))来调用 isFour，并且从参数表达式中提取出 int值。

### 方法的规范

你知道第一个函数 `mini` 的作用，因为它的规范在前面的注释中告诉了你。你不需要函数体——我们现在向你展示它。

方法的规范告诉我们对方法的调用会做什么。规范应该是精确的、完整的，并且尽可能清晰。这样你就不必查看方法体了。

实际上，每个方法都应该有一个规范，当编写方法调用时，你不应该查看方法的主体。方法主体表示任务的执行方式。当编写方法调用时，我们不想知道这个，我们想知道任务是什么。规范应该告诉我们。

#### 编写过程规范

我们将方法规范写成紧接在方法之前的 Javadoc 注释。Javadoc 注释以 `/**` 开始，以 `*/` 结束。下一节课将解释为什么我们使用 Javadoc 注释。

让我们开始讨论过程的规范。这里有两点要说明。

```
/** 将标题设置为t */
public void setTitle(String title){...}
```

1. 规范中提到了每个参数的名称，并以解释参数用途的方式进行说明。如果规范没有提到某个参数，读者可能不理解该参数的用途，规范就是不完整的。

2. 这个规范是一个命令去做某事。我们不说，“这个过程将标题设置为t”，或者类似的东西。我们说，“将标题设置为t。”这是因为我们使用它如下。假设我们调用了过程 `setTitle`：`setTitle(“我想要和平”)`；。弄清楚它的意思的方法是用规范替换它，但用参数替换参数：

将标题设置为“我想要和平”。

由于过程调用是一个命令去做某事，所以规范也应该是一个命令。

#### 编写函数规范

由于函数返回一个值，规范应该是对该值的描述。实际上，它应该说明函数调用的结果是什么。例如，函数 `areAscending` 的规范就是这样的。它说明了调用 `areAscending(a, b, c)` 的结果等于真假句子“a，b 和 c 按升序排列。”

```
/** = "a、b和c按升序排列"。 */
public static boolean areAscending(int a, int b, int c){...}
```

由于函数会计算出一个值，我们通常以等号开头来编写它们的规范。你可能会看到这样的规范：“如果a、b和c按升序排列，则返回true。”这种规范有一种操作性的感觉，我们不太希望有这种感觉。在数学中，如果有人问“sin(0)等于多少”，我们不会说“返回sin 0的值”，而是简单地说“它等于sin 0。”对于任何函数调用也是一样。

#### 编写构造函数的规范

下面是我们如何为构造函数编写规范。单词“构造函数”表示这是一个构造函数。它解释了新实例的属性——每个字段包含什么。请注意，规范中说明了前一章将是什么，即使没有参数。还请注意，所有参数都有解释：

```
/** 构造函数：一个新的实例，具有章节编号 n，章节标题 t，和前一章节 null。 */
public Chapter(int n, String t) {...}
```

### 方法的规范

养成在编写方法体之前编写方法规范的习惯。有两个原因。首先，你不会忘记编写规范。其次，规范将帮助你作为程序员，在编写方法体时。你可以在编写方法体时参考规范。你不必记住规范的所有内容。

最后，在调用时明确包含任何前置条件 —— 也就是，调用者必须满足的约束条件。例如，计算r的平方根的函数的规范应包括以下语句：

### 方法头

### 介绍

我们总结方法头，定义方法的签名，并讨论其用法。这些内容在课程教材Gries/Gries中有更详细的介绍。

方法声明由规范（作为注释）、方法头和主体组成。下面是一个方法声明：

```
/** = ”x在1到50的范围内”。 */
public boolean isLess(int x) {
    return x >= 1 && x <= 50;
}
```

这个课程中我们使用的方法头格式如下，用于Java中的三种方法类型，提供了关于每种方法调用的信息，并附有一些注释：

| 方法类型 | 头部格式 | 方法调用： |
|----------|----------|------------|
| procedure | `public void <name>(<参数列表>);` | 是一个语句。 |
| 函数 | `public <返回类型> <名称>(<参数列表>)` | 是一个表达式，返回一个值。 |
| 构造函数 | `public <类名>(<参数列表>)` | 出现在new表达式中或构造函数的第一个语句中。 |

#### 注释

- 关键字 `public` 可以被 `private` 替换，如果你希望该方法只能在声明它的类中访问。
- `<名称>` 可以是任何Java标识符。下面介绍了一些约定。
- `<返回类型>` 是函数返回的值的 `<类型>`。它可以是基本类型或类类型。
- `<参数列表>` 包含方法的参数声明。它是一个（可能为空的）由逗号分隔的声明序列。每个声明的形式为 `<类型>` `<变量名>`。
- `<类名>` 是声明构造函数的类的名称。
- 如果包含此方法头的类是抽象类，则关键字 `abstract` 可能出现在访问修饰符（`public` 或 `private`）之后。这在另一节中有解释。
- 对于函数或过程，如果方法不直接引用类的实例变量或实例方法，则在访问修饰符之后放置关键字 `static`。然后，方法只有一个副本，并且它将放置在类的文件抽屉中。

#### 方法名称

方法名称通常写为一个或多个单词的序列，如 `toString`、`setName` 和 `isLess`。除了第一个字母外，每个单词的首字母都大写。

过程名称通常是执行某些操作的命令，例如 `setName`, `printArea`, `fixName`。

函数名称通常是以下之一：

- 描述返回值的名词短语，例如 `sin`, `sqrt`, `smallestName`；
- 算法的名称，例如 `quicksort`, `selectionSort`, `binarySearch`；
- 布尔函数的真假短语，表示其值，例如 `isLess`, `areRed`；
- getter方法的名称是字段前面加上 `get`，例如 `getTitle`。

### 方法签名

方法的签名由其名称和参数类型组成（用括号括起来，用逗号分隔）。例如，此网页开头附近声明的方法的签名是

```
isLess(int)
```

在Java中，类中的方法必须具有不同的签名。这意味着，例如，不能同时有名为 `isLess` 且带有 `int` 参数的过程和函数。Java以这种方式限制方法，以便在任何方法调用时，不会产生歧义，可以确定调用的是哪个方法。

### 函数和过程调用

函数调用的形式为

```
<函数名> ( <参数> ) // 这是一个表达式
```

过程调用的形式为

```
<过程名> ( <参数> ); // 这是一个语句
```

其中 `<参数>` 是由逗号分隔的表达式序列。

方法调用可能需要在之前加上一个表达式，以指示方法所在的位置。例如，

- `Math.sqrt(7)` 调用类 `Math` 中的静态函数 `sqrt`。
- `s.length()` 调用对象名为 `s` 的对象的函数 `length`。
- `s.substring(3, 5).length()` 首先调用对象名为 `s` 的对象的两个参数函数 `substring`，生成第二个 `String` 对象，然后调用该对象的函数 `length`。

参数的数量必须与被调用方法的参数数量相等，并且每个参数的类型必须与相应的参数类型相同或更窄。

方法调用的执行过程如下——这将在后面的讲座中详细解释：

1.  创建被调用方法的参数和局部变量。
2.  将参数的值赋给相应的参数。
3.  执行方法体。
4.  擦除参数和局部变量——如果这是一个函数，则返回终止方法体的返回语句的表达式的值。

从上面可以看出，参数只会被评估一次，并且它们的值存储在参数中。在方法体中，将值存储在参数中不会对相应的参数产生影响。

### 局部变量

局部变量是在方法体内声明的变量。你看到的程序有两个不同的局部变量，都名为temp。

局部变量声明的语法如下：

```

初始化声明允许我们编写一系列语句来交换两个变量，如下所示：

```

```

我们将我们对局部变量的评论限制在您的监视器上看到的三个问题上：

1.  当创建和销毁局部变量时。
2.  局部变量的作用域。
3.  命名局部变量。

#### 当创建和销毁局部变量时

这是对方法 m的调用，带有三个参数。在执行此调用时，所有局部变量都在方法体执行之前创建。请注意，变量 temp有两个声明，它们是不同的变量，这就是为什么您看到两个具有相同名称的变量。其次，局部变量在方法体执行期间一直存在。第三，在方法体执行结束时销毁。

局部变量的作用域是可以引用它的位置。这包括在其声明之后的语句开始的块中的所有语句，并延伸到块的末尾。

#### 命名局部变量的准则

现在让我们谈谈局部变量和参数的命名。通常，面向对象编程中的方法通常很短。实际上，它们通常不超过一页，几乎总是不超过两页。

方法的简洁意味着在阅读方法体时，参数声明以及方法的规范（描述每个参数的用途）始终可见。因此，不需要使用长参数名。

有时会看到像这样的方法，参数名很长 - 程序员试图将参数的含义放入它们的名称中。但是，这种变化并没有澄清和简化问题，反而使问题更加复杂。程序变得更难阅读！看起来很尴尬吧？而且没有必要增加复杂性；短名称没有含义，因为规范和其他注释提供了所有的含义，并且它们很容易看到，因为方法很短。

同样，如果局部变量在注释中有足够的描述，并且方法体很短，则应优先选择短名称作为局部变量。

我们讨论本地变量声明的放置。一般来说，声明应该放在它们在逻辑上属于的位置，并且通常意味着尽可能靠近它们首次使用的位置。让我们看一个说明这一点的例子。

这是一个使用名为选择排序的算法对数组段 b[0..n] 进行排序的过程。在这门课程中我们还没有讨论过数组，但你在另一种编程语言中见过它们。在第一个参数声明中，你可以看到如何声明 b 为一个一维数组。

在 temp 和 j 的声明之后是一个注释，说明主循环的不变式——这只是一个在每次循环迭代之前和之后都保持的图像，并且我们将信息显示为下面的图像。这个图像表示段 b[0..k-1] 是已排序的，并且它的所有元素都不超过第二个段中的元素，这就是我们所说的 <= 和 >= 符号的含义。

看一下外循环的重复部分。它将 j 设置为 b[k..n] 中最小值的索引，并且交换 b[j] 和 b[k]，这样 b[k] 就包含了第二段 b[k..n] 中的最小值。由于 b[k] 是该段中最小的值，并且至少大于第一段中的所有元素，在该段中递增 k 保持了这个情况的真实性。

现在，为什么要在开头声明 temp 和 j？它们的意义是什么？当你第一次阅读过程体时，你会感到困惑吗？实际上，在这一点上，这些变量没有意义，它们在体的开头出现是逻辑上不正确的。它们在开头的出现给人一种它们在迭代中有意义的印象，但实际上它们没有。这些声明不应该在开头。

考虑变量 temp。它只在交换 b[j] 和 b[k] 时使用，所以 temp 可以在第一个赋值语句中声明。

考虑变量 j。它在哪里被使用？只在外部循环的重复部分中使用：它将包含 b[k..n] 的最小索引，并参与交换。因此，我们可以在其第一次赋值时声明 j。

请注意，temp 在语句注释“交换 b[j] 和 b[k]”中声明，因为它在那里被使用，那是它所属的地方。而且，声明尽可能靠近其第一次使用。

类似地，j 在其所属的外部循环的重复部分中声明，它是一个局部变量，并且尽可能靠近其第一次使用。

你担心声明会使过程变得不那么高效，因为声明被“处理”多次吗？不用担心。记住，局部变量在方法体执行之前只创建一次。所以我们没有使过程变得不那么高效。此外，该过程更容易理解。

### 条件语句和循环

### 介绍

每个过程式编程语言都有条件语句（if语句）和迭代语句（循环）。除非你之前的编程语言是纯函数式语言，否则你应该熟悉这些概念。因此，我们的目的是总结这些语句的Java版本，并指导你在文本和CDProgramLive中找到更详细的讨论。

1.  代码块。
2.  if语句。
3.  if-else语句。
4.  while循环。
5.  for循环。

#### 代码块

代码块的形式为

```
{ <一系列语句和局部变量声明> }
```

它的目的是将一系列语句和声明聚合（收集在一起）成一个单独的语句。它在编写条件语句和循环时使用。

更多信息，请参见Gries/Gries，第69页，和ProgramLive，第1-4页。

#### if语句

if语句的形式为

```
if ( <条件> ) <语句>
```

`<条件>`是一个布尔表达式。通常我们将`<语句>`设为一个块。

下面的例子展示了本课程中用于缩进和放置`<语句>`的约定。

```
if (x < y) {
    // 交换 x 和 y
    int temp = x;
    x = y;
    y = temp;
}
```

要执行if语句，首先评估`<条件>`，如果为真，则执行`<语句>`。

更多信息请参见 Gries/Gries 第 69 页和 ProgramLive 第 1-4 页。

#### if-else 语句

if-else 语句的形式为

```
if ( <条件> ) <语句1> else <语句2>
```

`<条件>`是一个布尔表达式。通常我们将 `<语句1>` 和 `<语句2>` 设为块。

以下示例展示了本课程中用于缩进和语句的开括号放置的约定。

```
// 将x和y中较小的值放入z
if (x <= y) {
    z = x;
} else {
    z = y;
}
```

或

```
// 将x和y中较小的值放入z
if (x <= y) {
    z = x;
}
else {
    z = y;
}
```

要执行if-else语句，首先评估`<条件>`；如果为真，则执行`<语句1>`；如果为假，则执行`<语句2>`。

有关更多信息，请参见Gries/Gries，第69页和ProgramLive，第1-4页。

#### while循环

while循环的形式为

```
while ( <条件> ) <重复体>
```

其中`<条件>`是布尔表达式，`<重复体>`是任意语句。 (重复体表示要重复的内容。)

通常我们将`<重复体>`作为一个块。

下面的例子展示了本课程中用于缩进和`<重复体>`的开括号放置的约定。

```
// 前提条件：n >= 1
// 将x设置为最大的2的幂，不超过n
x=1;
// 不变式：x是2的幂且x <= n
while (x <= n) {
    x=2*x;
}
```

要执行while循环，请执行以下操作：

1.  评估`<条件>`；如果为假，则终止循环的执行。
2.  执行`<重复体>`；然后，从步骤1开始重复。

`<重复体>`的第一次执行称为迭代0；第二次称为迭代1；依此类推。

有关更多信息，请参见Gries/Gries，第233页，和ProgramLive，第7-1页。

#### for循环

我们不会描述关于for循环的所有内容，只是描述它与一个单独的'控制变量'一起使用的方式，该变量在开始时初始化，并在每次for循环迭代时递增。(迭代是重复执行的一次执行 - 请参见下文。)for循环的形式为

```
for ( <初始化> ; <条件> ; <递增> ) <重复体>
```

`<初始化>`是一个赋值或初始化声明，`<条件>`是一个布尔表达式，`<递增>`是一个赋值，`<重复体>`是任何语句。(重复体是要重复的事物。)

通常我们将`<重复体>`作为一个块。

下面的示例展示了本课程中用于缩进和`<重复体>`的开括号放置的约定。注意，范围m..m只有一个值，即m。但是范围m..m-1没有值，因此其总和为0。最后，如果在此示例中m=n+1，则循环不执行任何迭代(重复体的执行)。

```
// 前提条件：m <= n+1
// 将x设置为范围m..n中值的总和
x=0;
// 不变式：x是范围m..k-1中值的总和
for (int k=m; k<=n; k=k+1) {
    x=x+k;
}
```

for循环的执行等同于以下转换为while循环的执行，只有一个例外。如果初始化是一个初始化声明，则控制变量的作用域是for循环本身，并且控制变量不能在循环后的语句中引用。但在while循环版本中，作用域包括循环后的语句。

```
<初始化> ;
while ( <条件> ) {
    <重复体>
    <递增> ;
}
```

更多信息，请参阅Gries/Gries，第78页（快速介绍）和第253页，以及ProgramLive，第7-4页。

## 数组

### 介绍

Java，像大多数编程语言一样，有数组 - 一定类型元素的列表，在创建数组时列表的大小是固定的。 在Java中，数组是对象。

我们提供了一维和二维数组的非常简要的摘要。请参阅Gries / Gries的第8章，第271-297页，以获取有关一维数组的完整讨论。阅读第9章，第301-311页，了解如何将二维数组处理为数组的数组。

### 声明一维数组变量

使用

数组索引从0开始；例如，数组b的元素可以通过b[0], b[1], ..., b[b.length-1]来引用。 以下赋值将b[k]增加1：

以下过程调用设置了 j[3]的标题:

## 返回语句

### 介绍

执行返回语句会终止方法体的执行，因此也终止了方法调用的执行。函数体中的返回语句与过程或构造函数中的返回语句有所不同。请参见下文。

### 过程和构造函数体

当调用过程或构造函数时，其体中的语句按照出现的顺序逐个执行。在执行过程中，执行以下语句：

```
return;
```

终止体的执行，从而终止过程或构造函数的调用 - 一旦执行了return语句，体中的任何其他语句都不会执行。过程或构造函数的体中不一定需要包含return语句，但有时使用return语句可以更容易编写体。

### 函数体

函数调用会产生一个值。因此，函数体的执行必须通过执行形式为`return <expression>;`的return语句来终止。其中`<expression>`的类型与函数结果的类型相同或更窄。

执行这样的return语句会终止函数体和函数调用，并将`<expression>`的值作为调用的结果。

由于函数体的执行必须以return语句的执行结束，函数体的最后一条语句通常是return语句。然而，return语句也可以出现在其他位置。

### 自内向外规则

#### 关于尊重隐私的注意事项

我们向您展示了一条确定与变量引用相关联的变量声明的通用规则。这个问题与变量引用是否合法无关。例如，在本节对象的方法 `m` 中，对变量 `title` 的引用与从超类 `Chapter` 继承的字段 `title` 相关联。但是，如果字段 `title` 被声明为访问修饰符 `private`，则引用是非法的，可能应该调用函数 `getTitle`。

#### 变量的自内向外规则

程序中的每个变量名都引用了程序中某个地方声明的变量。大多数编程语言使用某种形式的自内向外规则来确定变量名引用的声明。

- 例如，变量可能在循环体中声明，其中包含变量引用；如果不在那里，在周围的if语句中；如果不在那里，在方法体中；如果不在那里，它可能是一个参数；如果不在那里，它可能是方法所在对象的字段；最后，如果不在那里，它可能是一个静态变量，因此在文件包中。
- 因此，搜索是在内部范围中进行的，并扩展到越来越大的周围范围。也就是说，
- 内外规则：要找到与变量使用对应的声明，请从内部到外部查找，直到找到为止。

在DrJava中，我们看到了一个说明这一点的类。你可以看到在循环体、条件语句的 `then` 部分和方法体中声明的局部变量。你可以看到一个参数声明。你可以看到一个字段。而且你可以看到一个静态变量。

这个内外规则，是确定变量声明的基本机制，一个变量引用引用的变量。这很简单。

#### 方法调用的内外规则

方法调用的内外规则是相似的。有两个不同之处。首先，方法只出现在对象和文件包中，所以搜索变得简化了。

对于对象中的方法，只需要在该对象中查找，然后在周围的文件包中查找。例如，对象 `a0` 中的方法 `toString` 调用了 `getTitle`；它的声明在对象 `a0` 中找到。方法 `toString` 还使用一个 `int` 参数调用了 `m`。该方法不在 `a0` 中，但是在封闭的文件包中找到。

对于在文件包中的静态方法，只需要在文件包中查找，因为没有封闭的作用域。例如，具有 `bool` 参数的方法 `m` 调用了具有 `int` 参数的方法 `m`，而该方法 `m` 也在文件包中。

这是搜索变量和搜索方法之间的另一个区别。当搜索方法时，需要的是具有正确签名的方法，即名称和参数类型一起。因此，在寻找调用 `m(number)` 的方法声明时，会搜索一个具有单个参数且类型至少与 `int` 一样宽的方法。

#### 查看文件夹或文件包

这里有两个文件包，一个用于类 `Chapter`，另一个用于类 `C`。根据内外规则，从方法 `toString` 的主体中，可以引用 `a0` 的所有方法和字段，以及文件包中的静态方法和变量。从两个方法 `m` 的主体中，可以引用文件包 `Chapter` 中的静态方法和变量，但不能引用对象 `a0` 的组件。内外规则不允许向内查看，只能向外查看。

从方法 `p` 在对象 `a1` 中，不能直接引用 `Chapter` 的文件包中的任何项。

然而，在方法 `p` 内部，我们可以引用字段 `c1`，其中包含名称 `a0`。因此，可以使用类似的引用来引用 `a0` 中的所有组件，以及 `Chapter` 文件包中的静态组件：

```
c1.title   c1.getTitle()   c1.m(3)   c1.m(true)
```

因此，对象的名称不仅可以访问对象的组件，而且还可以通过内部-外部规则访问文件包中的静态组件。

就像对象的名称用作访问该对象的入口一样，类的名称用作访问类文件包中的静态组件的入口。例如，在类C的方法p的主体中，我们可以通过在调用之前加上类的名称Chapter来调用Chapter文件包中的方法m: Chapter.m(n)

类的静态组件可以通过在引用前加上类的名称（当然后面要加上一个句点）来从任何地方引用。

请注意，在方法p中，我们可以使用c1.m(n)或Chapter.m(n)来调用第一个方法m。首选使用Chapter的名称。

#### 类不变量

### 表面类和真实类

任何术语的目的都是为了促进问题的讨论和概念的澄清。 没有这个术语，讨论可能会变得冗长、费力和混乱。 有了这个术语，问题和概念应该在更短的时间内得到解释和讨论。 在这个讲座中，我们介绍了两个新词：变量或表达式的表面类和真实类。 请确保你理解这个新术语。

#### 变量的显式类

这里是三个变量的基本声明： `ob`, `sp`, 和 `ci`.

```java
Object ob;
Shape sp;
Circle ci;
```

这里是变量本身。 我们已经用它们的类型进行了注释。 它们都包含相同对象的名称，属于 `Circle` 类。

![](img/00e683c7c66775b90e383a24260c76e8_90_0.png)

在这种情况下，我们说 `ob`的显式类是 `Object`， `sp`的显式类是 `Shape`， `ci`的显式类是 `Circle`：

定义：变量的显式类是其声明的类。

为什么我们使用这个名称？ 显式意味着清楚地看到或理解，表现出可能不是真实的特定品质或属性。 显然，变量包含给定类的对象。

显式类是一个语法属性。 你可以从程序本身中判断出变量的显式类，而显式类决定了可以和不可以引用的内容。

在这里显示的情况下，由于 `ob`的显式类是 `Object`，只能使用在类 `Object`中定义的字段和方法来引用 `ob`。 那些无法引用的已被灰掉。由于 `sp`的显式类型是 `Shape`，只能使用在类 `Shape`中定义或继承的字段和方法来引用 `sp`。 那些无法引用的已被灰掉。而且，由于 `ci`的显式类是 `Circle`，只能使用在类 `Circle`中定义或继承的字段和方法来引用 `ci`。

总结一下，规则是：

> 规则：对于某个类类型 `C`的变量 `x`，形式为 `x.variable`或 `x.method-call`的合法引用是指在类 `C`中定义或继承的变量和方法。

#### 变量的真实类别

表面类别是变量中对象的声明所显示的类别；真实类别是变量中对象的实际类别。目前，`ob`的表面类别是`Object`，但`ob`的真实类别是`Circle`，因为`ob`包含了一个属于`Circle`类的对象的名称。

这个真实的类在执行过程中可以改变，只要变量被赋值就会执行。

真实的类决定了实际调用的方法。 例如，在这里给出的情况下，`ob.toString()`是合法的，因为 `toString`在类 `Object`中被定义。 然而，它调用了在类 `Circle`中声明的重写的`toString`函数——这是根据在对象中找到变量或方法对应的声明的自底向上规则的结果。

重写的 `toString`函数被调用可能一开始看起来很奇怪。 但这是面向对象编程的一个重要方面。 下面是如何理解它有意义的。 当调用`ob.toString()`时，我们希望尽可能多地了解对象的信息。 如果调用 `Object`分区中的 `toString`函数，我们只会得到对象的名称！ 但是，由于调用了分区`Circle`中的 `toString`函数，我们得到了最大量的信息。

### 类 Object 中的 equals

正如你所知，函数 equals，在类 object 中定义，用于测试两个对象是否确实是同一个对象。它可以写成如下形式：

```java
/** = "这个对象和对象 ob是同一个对象"。 */
public boolean equals(Object ob) {
    return this == ob;
}
```

例如，对于这里看到的两个变量 c1 和 c2，c1.equals(c1)为真，而c1.equals(c2)为假。

每个类 C（假设）都可以重写函数 equals。这是它的一般规范：

```java
/** =“对象 ob 是类 C 的对象且与该对象相等 */
public boolean equals(Object ob)
```

这里有两个重要的要点需要注意。首先，为了重写函数 equals，参数必须具有类型 Object。其次，规范指出 ob是类 C 的对象，因此在方法体中必须检查这个属性。例如，假设 c1包含一个类 C 的对象。那么，调用c1.equals(new Integer(5))

必须返回 false，因为参数的类不是C。

### equals函数应该是一个等价关系

现在，equals函数的编写者可以决定“对象 obequals this object”是什么意思。约定是这是一个真正的等价关系 —— 假设 c1、c2和 c3是同一类的对象，那么有三个属性成立：

- 自反性 : c1.equals(c1) 为真。
- 对称性 : c1.equals(c2) 和 c2.equals(c1) 产生相同的值。
- 传递性：如果c1.equals(c2)和c2.equals(c3)为真，则c1.equals(c3)也为真。

现在，如果你还没有被告知等价关系具有这些属性，不用担心。你不必检查这些属性是否适用于你的equals函数。如果你只是根据常识定义equals函数，那么它应该具有这些属性。

函数 equals通常检查两个对象的某些或所有字段的相等性，但它应该以抽象的方式来指定，即以类的含义为基础，而不是以字段的实现为基础。例如，对于 String对象，相等性是由以下方式定义的

对象中包含的两个字符串（字符序列）是相等的

我们不知道类 String中使用了哪些字段；我们只知道每个实例以某种方式包含一个字符序列，并且在函数equals中测试了这些序列的相等性。

因此，将规范写成类的含义而不是字段的形式。

### 遵循规范的编程风格的原因

你的计算机程序应该是可读的，因为如果它不可读，它正确的机会很小。 此外，如果你的程序不可读，找到并纠正其中的错误将会很困难且耗时。因此，

**使用规范的编程风格的主要原因是在阅读或调试程序时能够节省时间。**

你的程序应该不仅仅对你自己可读，还应该对其他人可读。 考虑一下你将在本课程中编写的程序。 一个有困难理解它的评分人不太可能给你一个好成绩。 你的程序越易理解，对于评分人来说，它就越简单，他们就越愿意给你一个好成绩。

在这门课程之外，使程序对他人可读变得更加重要。大多数程序存在很长时间，并需要"维护"--即根据新的和不同的需求进行更改，升级其他软件，新硬件等。此外，当需要进行维护时，程序的作者很可能已经不在了；其他人必须阅读程序并足够理解以成功更新它。

即使是为自己编写的程序也应该可读性强；如果不是这样，在完成后的四周内，你将不会记得足够多以进行简单的更改。

因此，出于你自己和他人的利益，开发具有可读性、可理解性和正确性的编程习惯是有意义的。

这些习惯的一部分涉及简单的语法措施，如正确缩进程序部分和使用一些变量、方法等的命名约定。更重要的部分涉及在注释中记录足够的信息，以便读者理解程序的设计和原因。

计算机程序是许多设计决策的结果。 这些决策 - 为什么引入这个变量，那个函数做什么等等 - 通常不会在最终的Java代码中反映出来，而Java代码由低级别的详细声明和语句组成。 然而，如果程序员要成功修改程序，就必须理解更高级别的设计。 试图理解在代码中没有记录的决策是乏味、容易出错和令人恼火的 - 但这种情况太常见了。

因此，从一开始就养成一些纪律性的编程习惯对你有利，例如：

- 在声明变量时，写一个精确的定义（在注释中）。
- 当你决定改变变量的含义时，更新变量的定义（注释）。
- 在编写方法的标题时，写一个精确的规范（说明它做什么）。
  不要等到方法完全编写或程序调试之后再做。
- 每当对方法的主体进行违反规范的更改时，更改规范。

在程序完成后准备所有注释对于三个原因来说都是不好的：

1. 在开发和调试程序时，注释对你没有用处，所以你花费了比必要的时间更多的时间。
2. 在程序完成后编写注释更加困难，因为很难记住所有变量和方法的含义。
3. 很可能，你不会编写注释--即使是最有诚意的程序员在事后填写注释时也不会花费太多时间，因为还有太多其他有趣的事情要做。

你会发现，在编写程序时，编写良好的注释将有助于澄清你的思路，并更早地编写出更好、正确的代码。 如果你能清楚地写下你的程序正在做什么，你就更有可能对问题有很好的理解，并且你的程序更有可能是正确的。

在仔细思考和编写上花费的时间，在测试和调试过程中节省的时间将远远超过这些时间。大多数人不喜欢对语句注释的子语句进行缩进，而是依靠空行来分隔语句注释的子语句的结束。

### 命名约定

良好的命名约定可以帮助你和程序的任何读者轻松理解程序；糟糕的命名约定或者没有命名约定可能导致混淆和误解。有些人主张使用非常长的名称来定义被命名的实体（方法、字段、局部变量等）所代表的内容。然而，总的来说，这是不可行的。一个实体的良好定义可能需要三行或更多的解释---你怎么可能有这么长的名称呢？另一方面，极短的名称--只有一两个字符--一点也不有帮助。因此，必须采取一些中间措施。在某些情况下，短名称是最好的选择，在其他情况下，较长的名称是最好的选择。

记住，一个名称很少能够用来给出实体的完整、精确的定义，应该在定义实体的地方始终给出完整的定义。

开发Java程序的人们已经制定了一些标识符的约定，这些约定在一定程度上帮助人们看出标识符代表的是什么。你可以通过查看java.awt（抽象窗口工具包）中的类来看到这些约定的运作。下面，我们列出这些约定，并添加了一些补充。

#### 包名

示例：animalstory，java.awt

包是一组被分组在一起的类。包的名称通常是用来标识其内容的。一般来说，包名应该全部小写，以区分其内部类的名称。即使包名是一个复合词，这个规则仍然适用。

在Java API中，你可能会注意到包名之间用句点分隔。在包名中使用句点是一个高级主题，超出了本课程的范围；我们建议你避免使用这种方式命名包。句点具有特殊含义，不仅仅是用来分隔复合词的方式。特别是，句点前面的单词是一个前缀，用于将多个包分组在一起；例如，包"java.awt"和"java.lang"都是在前缀"java"下分组的（它本身是一个元包）。

#### 类名

示例：FilterInputStream，LivingMammals

由于一个类代表一组可能的对象，每个对象都是该类的实例，一个类名通常应该是一个名词短语，用于标识可能的对象。 一个类名应该以大写字母开头，类名中的所有后续单词都应该大写。

#### 方法名称

示例： drawOval, fillOval, length, toString

一个表示执行某些操作的方法应该使用一个动词短语来命名，该动词短语应该提供一些关于方法功能的指示（但是这个名字不应该成为不注释方法的借口！）。另一方面，一个实现某个功能的方法（例如返回一个值）应该是一个描述该值的名词短语。

最后，一个既执行某个任务又返回一个值的方法，你应该根据自己的判断来创建它的名字。

一个方法名应该以小写字母开头，但是方法名中的所有后续单词都应该大写。

#### (方法) 参数名称

示例： x, y

参数的确切含义以及任何限制应在方法标题的注释中给出。 因此，特别是如果方法相对较短，给参数取短名称是明智的。

对于更详细的示例，请考虑下面给出的两个方法标题。 第一个方法更好，因为它更短且更容易理解。 此外，第一个方法的方法体也会更短且更容易理解和操作。

```
// 绘制一个椭圆，该椭圆恰好适合于以(x， y)为左上角，宽度为w，高度为h的矩形内。使用当前颜色绘制椭圆。
void drawOval(int x, int y, int w, int h) {
```

```
// 绘制一个椭圆，该椭圆恰好适合于以(xCoordinate， yCoordinate)为左上角，宽度为width，高度为height的矩形内。使用当前颜色绘制椭圆。
void drawOval(int xCoordinate, int yCoordinate,
               int width, int height)
```

像"theLoopCounter"或"firstNumber"这样的名称，而不是"k"或"x"，会导致混乱。

用作标志的参数应该根据标志所代表的含义进行命名，例如noMorePizza，而不仅仅是 flag。 此外，你应该避免使用泛泛的名称，如"count"和"value"；而是描述被计数的项目或参数中存储的值。

#### 字段名称

示例：size, xCoordinate, noLines

字段名称，有时也称为实例变量，包含有助于描述其所在对象状态的信息。因此，字段名称应该是一个描述字段所包含信息的名词短语（但是，字段仍然需要一个更精确的注释来描述它）。字段名称中的所有单词，除了第一个单词外，都应该大写。

#### 局部变量名称

示例：size, xCoordinate, noLines

方法的局部变量包含有助于描述其执行过程中状态的信息。局部变量应该是一个描述其所包含信息的名词短语（然而，局部变量仍然需要一个更精确的注释来描述它）。局部变量名称中的所有单词，除了第一个单词外，都应该大写。

如果方法的主体很短，或者局部变量的使用位置相对较短，则可以使用一个或两个字母的短名称作为局部变量（还可以参考参数名称的约定）。像"theLoopCounter"或"firstNumber"这样的名称，而不是"kk"或"x"，会导致混乱。如果局部变量仅在一个短上下文中使用，并且在声明的位置适当地定义了一个注释，则可以使用短名称。

用作标志的变量应该以标志所代表的内容命名，例如noMorePizza，而不仅仅是flag。此外，应该避免使用通用名称，如"count"和"value"；而应该描述被计数的项或存储在变量中的值。

#### 访问器名称

示例：getTextLength, setTextLength

字段的访问器方法要么返回字段中的值，要么将值存储在字段中。在课堂上，我们将这些称为"getter"和"setter"，因为这是标准的Java约定。Getter用于引用字段，而setter用于存储值。

这些方法的命名来自命名约定本身。Getter将字段的第一个字母大写，并添加"get"前缀；setter将字段的第一个字母大写，并添加"Set"前缀。

我们通过一个例子来说明命名约定。假设我们有一个名为"textLength"的字段。要引用该字段，我们使用方法"getTextLength()"。要将值存储在字段中，我们使用方法"setTextLength()"。

#### 常量名称

示例：PI, Y, E, WINDOW_SIZE

在Java中，常量只是一个已声明为final的类字段；这意味着它永远不会改变。 为了区分常量和实例变量或局部变量，我们只使用大写字母来命名常量。 如果一个常量是一个复合词，用下划线分隔相邻的单词来命名常量。

### 缩进

缩进用于使程序的结构清晰可见。 基本规则如下：

**语句或声明的子语句应该缩进。**

例如，方法的主体，条件语句的if部分和then部分，以及方法的主体应该缩进。

有几种放置用于界定语句的花括号的方法；没有人喜欢它们全部，而且每种方法都有人不喜欢 。 花括号对于条件语句和方法主体都很重要。

    y = 0;

### 语句注释

就像一篇文章的句子被分组成段落一样，方法体中的语句序列应该被分组成逻辑单元。通常，通过在逻辑单元之前加上解释其功能的注释，可以增强程序的清晰度。这个注释作为逻辑单元的规范，应该准确地说明逻辑单元的功能。

这样的逻辑单元的注释被称为"语句注释"。这个注释应该被写成一个执行某些操作的命令。以下是一个例子。

```
// 如果需要，通过交换x和y来使x >= y成立。
if (x < y) {
    int tmp = x;
    x = y;
    y = tmp;
}
```

注释应该解释一组语句的功能，而不是如何实现它。因此，它与方法的规范具有相同的目的：允许跳过逻辑单元的语句，只阅读注释。通过适当的在方法体中的语句注释中，可以以几个"抽象级别"阅读方法，这有助于快速扫描程序以找到当前感兴趣的部分，就像在文章或书籍中扫描节和子节标题一样。但是，只有当语句注释准确无误时，才能实现这个目的。

语句注释应该是完整的。 例如，下面的注释是不充分的：

`// 测试有效输入`

如果输入有效会发生什么？ 如果输入无效，是写入错误消息还是设置某个标志？ 没有这些信息，就必须阅读这个语句注释所规定的语句，而语句注释的整个目的就丧失了。

### 方法规范

每个方法都应该在前面加上一个注释，给出其规范。这个规范连同方法的标题一起，给出参数的数量和类型（类）以及结果的类型（类），应该提供使用方法所需的所有信息--而不多。它应该描述参数的任何限制以及方法的功能，而不是它是如何实现的。人们不应该需要查看方法的主体来理解如何使用它。

规范注释还应描述方法的参数。规范通常可以用几句话来写。这里是一个例子：

```
/** 在t[0..c-1]中打印出出现频率最高的温度如果有多个可能性，请打印出最低温度。
 */
void findCommon (Temperature [] t, int c)
```

不幸的是，更典型的是找到有人写下如下的注释（如果有的话提供任何注释）。

```
// 找到最常见的温度
void findCommon (Temperature [] t, int c) {
```

这个规范没有说明在查找最常见的温度时应包含数组t的哪个部分。它还没有说明在有多个可能性的情况下应该在哪里打印，这将是一个问题。用户唯一的办法是查看方法的主体（如果有的话），这是不必要的。

这是我们建议您使用多行注释而不是单行注释来进行规范的原因之一。 它鼓励您提供更好的细节，而不是在行末省略信息。

话虽如此，长段落和代码一样难以阅读。 当你写注释时，它们应该尽可能简短明了。对于一个函数（即返回一个值的方法），最简单的方式通常是简单描述返回的值，使用"yield"这个词：

```
/** 计算点 (x1, y1) 和 (x2, y2) 之间的距离 */
double dist (int x1, int y1, int x2, int y2) {
```

另一个好的经验法则来自于《风格的要素》，这是一本由康奈尔大学教授W. Strunk, Jr.和E.B. White所写的著名小书。尽可能使用主动语态，以保持信息简短直接。例如，不要写成“该函数在列表x中搜索值y...” 或者 “函数isIn在列表x中搜索值y...”。这样的规范太啰嗦，不是命令而是描述。相反，它们应该如下所述：

```
/** 返回"y在列表x中"的结果 */
boolean isIn(int y, List x) {
```

### 变量定义

每个重要的变量和数据结构都需要精确完整的定义，提供了理解变量所需的所有信息。最有用的信息通常是数据的不变性属性：即始终为真的事实，除非可能在更新多个相关变量时短暂地发生变化。

重要提示：在首次使用变量时编写变量的定义，并在输入变量声明时将定义作为注释输入到程序中。 如果您以后决定更改在更改使用变量的语句之前，先更改变量的定义之前你更改使用变量的语句。

这是两个变量"i"和"currentItem"的定义示例；请注意它们在单个注释中定义，因为它们是相关的。

```
// 0 <= i <= currentItem < numberItems，且i是最小的值
// 使得item i的价格至多等于item currentItem的价格。
```

布尔变量的定义通常最好以某个英语（或数学）语句的值来呈现。例如，以下两个定义是等价的，但第一个更短。

```
boolean b; // = “用户选择的菜单项 文件 | 退出”
boolean b; // 如果用户选择的菜单项是 文件 | 退出，则为真；否则为假
```

定义越精确，越好。像"循环标志"或"索引到 b"这样的注释是无用的；它们只说明了变量的用途，而不是它的含义。

相关的变量应该一起声明和描述。例如，表的定义不仅应该描述保存数据的数组，还应该描述包含当前表项数量的整数变量。在下面的示例中，为了最大的清晰度，使用制表符来对齐标识符名称和注释。

```
final int maxTemp= 150; // 温度读数的最大值.
        int nTemp= 0      // 温度读数在
                          // temp[0..nTemp-1]，其中
        double temp= new double[maxTemp]; // 0 <= nTemp < maxTemp
```

如果注释太长无法很好地放在右边，那么将其放在声明之上并缩进声明：

```
// 温度读数在 temp[0..nTemp-1]，其中
// 0 <= nTemp <= maxTemp，maxTemp 是最大的
// 温度读数
final int maxTemp = 150;
        int nTemp     = 0;
        double temp= new double[maxTemp];
```

### 理解流

“流”是一系列数据值，从开始到结束进行处理，可以进行读取或写入。当数据被读取或输入时，流被称为“输入流”；当数据被写入或输出时，流被称为“输出流”。

**在Java中，使用java.io包中的类来进行流的输入/输出。在下面的交互窗格中尝试任何操作时，请记得导入这个包。**

创建文件输入流的基本方法是通过创建类的实例FileReader：

```
FileReader fr= new FileReader(描述要读取的文件的参数);
```

使用FileReader fr标准的读取方式是逐个字符读取，使用函数

```
fr.read()
```

这对我们来说太底层了。我们希望能够一次读取一行而不是一个字符。为此，我们使用类BufferedReader。不要使用上面的方法，使用这个方法：

```
FileReader fr= new FileReader(描述要读取的文件的参数);
BufferedReader br= new BufferedReader(fr);
```

然后，执行

```
String line = br.readLine();
```

读取文件的下一行并将其存储在变量line中——如果没有更多行可读，则将null存储在line中。我们将在后面看到如何使用这个。

### 使用JFileChooser对话框

为了读取一个文件，你必须指定要读取的文件。最简单的方法是使用对话框窗口导航到适当的目录并选择文件。为此，我们使用javax.swing包中的JFileChooser类的实例。在交互窗格中执行以下操作：

```
br= Reading.getReader(null);
```

一个对话框会打开。它的标题是“选择输入文件”。它允许你随意导航然后选择一个文件。进行一些导航并选择一个文件。然后看一下getReader(String)函数。它的功能如下：

1.  声明局部变量jd，类型为JFileChooser。
2.  将一个JFileChooser类的新实例存储在jd中。在新表达式new JFileChooser()中，你无法控制对话框窗口中最初出现的目录。在新表达式new JFileChooser(p)中，字符串p应该是你计算机上要打开的目录的路径。这个选择可以省去很多导航的步骤。
3.  将jd的标题设置为"选择输入文件"。
4.  执行jd.showOpenDialog(null);会导致对话框窗口在您的监视器上打开，并且程序暂停，直到您关闭它。在您选择文件（或取消交互）之前，不会发生任何事情。
5.  使用您选择的文件（其名称为jd.getSelectedFile()）作为参数创建一个新的FileReader，并将其名称存储在fr中。
6.  创建并返回一个附加到fr的BufferedReader。

从BufferedReader br中获取下一行的函数是：

```
br.readLine() // = BufferedReader br的下一行 —如果没有更多行，则为null
```

在交互窗格中，您可以继续评估br.readLine()。每次执行时，都会打印出您选择的文件的下一行。试试看。

### 处理文件的行

类Lab10中的函数lines演示了处理给定的BufferedReader的文件行的基本方法。在交互窗格中，调用此方法并让它读取某个文件——您将看到文件中有多少行。

学习这个方法。你编写的任何处理文件的循环都应该类似于这个——每行的"处理"会改变，但处理的循环的基本结构不会。请注意，这个方法包含一个while循环。以下是重要的要点：

1.  在while循环之前读取第一行并存储在变量lin中。如果文件为空，则lin将为null。
2.  当lin为null时，循环停止，表示文件中没有更多的行。
3.  重复部分首先处理变量lin给出的行，然后将下一行读入lin。

该方法的头部包含一个新的构造：`throws IOException`。这是必需的，因为函数`br.readLine()`可能会产生某种I/O（输入/输出）错误，而这就是我们处理它的方式。我们在课程中之前讨论过异常。
