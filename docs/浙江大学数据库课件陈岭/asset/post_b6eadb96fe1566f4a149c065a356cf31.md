

## Closure of Functional Dependencies (Cont.)

### Armstrong 公理的补充定律：

We can further simplify manual computation of **F+** by using the following additional rules.

- If \(\alpha \rightarrow \beta\) **and** \(\alpha \rightarrow \gamma\) holds, then \(\alpha \rightarrow \beta\gamma\) holds (union, 合并律)

- If \(\alpha \rightarrow \beta\gamma\) holds, then \(\alpha \rightarrow \beta\) **and** \(\alpha \rightarrow \gamma\) holds (decomposition, 分解律)

- If \(\alpha \rightarrow \beta\) **and** \(\gamma\beta \rightarrow \delta\) holds, then \(\alpha\gamma \rightarrow \delta\) holds (pseudotransitivity, 伪传递律)

The above rules can be inferred from Armstrong's axioms.

> Prov: Rule1: \(\beta\gamma \rightarrow \beta\), \(\beta\gamma \rightarrow \gamma\), given \(\alpha \rightarrow \beta\gamma\), by Rule3, then \(\alpha \rightarrow \beta\) and \(\alpha \rightarrow \gamma\)

## (3) Closure of Attribute Sets (cont)

- ▪ **Algorithm to compute** α⁺, **the closure of** α **under** F

```
result := α;
while (changes to result) do
    for each β → γ in F do
    begin
        if β ⊆ result then result := result ∪ γ
    end;
α⁺ := result
```

避免了找 F⁺（反复使用公理）的麻烦

## Uses of Attribute Closure

There are 3 kind uses of the attribute closure algorithm:

1. **Testing for superkey** --- (α → R ?)
   
   To test if α is a superkey, we compute α⁺, and check if α⁺ contains all attributes of R, i.e. check if R ⊆ α⁺

2. **Testing functional dependencies** --- (α → β ?)
   
   To check if a functional dependency α → β holds (or, in other words, is in F⁺), just check if β ⊆ α⁺.
   
   It’s a simple and cheap test, and very useful

3. **Computing closure of F** --- (F⁺ = ?)
   
   For each γ ⊆ R, we find the closure γ⁺, and for each S ⊆ γ⁺, we output a functional dependency γ → S. All γ → S form F⁺

## (4) Canonical Cover (正则覆盖)

DBMS should always check to ensure not violate any FD in F. If the F is too big, the check is costly. Then we need simplify the set of FDs.

Intuitively, a canonical cover of F (denoted Fc) is a “minimal” set of FDs equivalent to F :

1. Having no redundant FDs and no redundant parts of FDs, i.e. no functional dependency in Fc contains an extraneous attribute.

2. Each left side is unique.

E.g. α1→β1 , α1 →β2 , ⇒ α1→β1β2
